# 1. Overview

Route redistribution is the process of exchanging routes between different routing protocols or between different routing sources. It allows networks running multiple routing protocols to share reachability information.

Because different protocols use different metrics and administrative distances, redistribution must be carefully controlled using tools such as **route-maps, prefix-lists, and metric manipulation** to prevent routing loops and unwanted route advertisements.

---

# 2. Why Route Redistribution Is Needed

Example enterprise network:

```
             OSPF Network

                 |

              Router

                 |

             EIGRP Network

```

Problem:

OSPF routers do not know EIGRP routes.

Solution:

```
Redistribution

OSPF ↔ EIGRP
```

# 4. Redistribution Direction

Redistribution is configured **into a protocol**.

Example:

```
EIGRP routes

      ↓

OSPF process

```

Means:

OSPF learns EIGRP routes.

Configuration:

```bash
router ospf 1

redistribute eigrp 100
```

# 6. Redistribution Metric Problem

Different protocols use different metrics.

Example:

OSPF:

```
Cost
```

EIGRP:

```
Bandwidth + Delay
```

When redistributing:

The receiving protocol needs a metric.

# 8. Default Redistribution Metric

If no metric is defined:

- Assign default metric
- Create unreachable routes

Redistribution should not blindly advertise every route.

- Routing loops

Solution:

```
Prefix-list
```

# 11. Prefix Lists

## Definition

Prefix-lists filter routes based on network prefixes.

They are faster and more flexible than access-lists for route filtering.

---

Syntax:

```bash
ip prefix-list NAME permit PREFIX/LENGTH
```

---

Example:

Allow:

```
10.0.0.0/8
```

Command:

```bash
ip prefix-list INTERNAL permit 10.0.0.0/8
```

---

# 12. Prefix Length Matching

Example:

```bash
ip prefix-list TEST permit 10.0.0.0/8 le 24
```

Meaning:

Allow:

```
10.0.0.0/8

through

10.0.0.0/24
```

---

Operators:

| Keyword | Meaning |
|---|---|
| ge | Greater than or equal |
| le | Less than or equal |

---

Example:

```bash
10.0.0.0/8 ge 16 le 24
```

Allows:

```
10.x.x.x/16

to

10.x.x.x/24
```

---

# 13. Prefix List Example

Allow only internal networks:

```bash
ip prefix-list INTERNAL permit 10.10.0.0/16
ip prefix-list INTERNAL permit 10.20.0.0/16
```

---

Deny everything else:

```bash
ip prefix-list INTERNAL deny 0.0.0.0/0 le 32
```

# 14. Route Maps

## Definition

Route-maps are policy tools used to:

- Match routes
- Modify routes
- Filter routes

---

Structure:

```
Route-map

 |

Match

 |

Set Action

```

---

Example:

```
If route = 10.0.0.0/8

Then:

Allow

Set metric 100
```

---

# 15. Route Map Components

## Match Statements

Select routes.

Examples:

```
match ip address

match ip prefix-list
```

---

## Set Statements

Modify routes.

Examples:

```
set metric

set local-preference

set tag
```

---

# 16. Route Map Example

Create prefix-list:

```bash
ip prefix-list LAN permit 10.10.0.0/16
```

Create route-map:

```bash
route-map OSPF-IN permit 10

match ip address prefix-list LAN

set metric 50
```

---

Apply:

```bash
router ospf 1

redistribute eigrp 100 route-map OSPF-IN
```

---

# 17. Redistribution Filtering Example

Goal:

Redistribute only:

```
10.0.0.0/8
```

into OSPF.

---

Prefix-list:

```bash
ip prefix-list REDIST permit 10.0.0.0/8
```

---

Route-map:

```bash
route-map FILTER permit 10

match ip address prefix-list REDIST
```

---

Apply:

```bash
router ospf 1

redistribute eigrp 100 route-map FILTER
```

# 18. Route Tags

## Purpose

Prevent redistribution loops.

---

Problem:

```
OSPF

 ↓

EIGRP

 ↓

OSPF again

```

Routes return back.

---

Solution:

Add a tag.

Example:

```
EIGRP route

tag 100
```

When redistributing back:

```
Reject tag 100
```

---

# 19. Route Tag Example

Set tag:

```bash
route-map EIGRP-TO-OSPF permit 10

set tag 100
```

---

Block tagged routes:

```bash
route-map OSPF-TO-EIGRP deny 10

match tag 100
```

# 25. Route Redistribution Best Practices

| Practice | Reason |
|---|---|
| Redistribute only required routes | Reduce complexity |
| Use prefix-lists | Precise filtering |
| Use route-maps | Policy control |
| Tag redistributed routes | Prevent loops |
| Define metrics | Avoid unpredictable routing |
| Document policies | Easier troubleshooting |

---

# 26. Prefix List vs Access List

| Feature | Prefix List | Access List |
|-|-|-|
| Purpose | Route filtering | Traffic filtering |
| Matches | Networks/prefixes | Packets |
| Used in routing | Yes | Sometimes |
| Performance | Faster | Slower |

---

# 27. Route Map vs Prefix List

| Feature | Prefix List | Route Map |
|-|-|-|
| Filtering | Yes | Yes |
| Modify attributes | No | Yes |
| Set metrics | No | Yes |
| Set tags | No | Yes |
| Policy control | Basic | Advanced |

# CCNP Exam Traps

- Redistribution happens into the receiving protocol.
- Different protocols require metric conversion.
- Route-maps control redistribution policies.
- Prefix-lists filter routes by network and prefix length.
- Route tags help prevent redistribution loops.
- Two-way redistribution can cause routing loops.
- Always control redistribution scope.
- OSPF external routes are created by redistribution.
- EIGRP requires a seed metric when redistributing.
