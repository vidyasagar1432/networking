# 1. Overview

Policy-Based Routing (PBR) is a routing technique that allows network administrators to forward packets based on **custom policies instead of the normal routing table lookup**.

Traditional routing uses the destination IP address to make forwarding decisions. PBR allows decisions based on additional parameters such as source IP, protocol, application, packet size, or access lists.

Example:

```
Normal Routing:

Destination IP
      |
      |
Routing Table
      |
      |
Next Hop

```

PBR:

```
Packet

 |

Policy Rules

 |

Selected Path

```

---

# 2. Why Use PBR?

Traditional routing answers:

> "Where is the destination network?"

PBR answers:

> "Which path should this traffic use based on policy?"

---

Common uses:

| Use Case | Example |
|---|---|
| Traffic engineering | Send voice traffic through MPLS |
| Multiple ISP connections | Certain users use ISP-A |
| Security policies | Send unknown traffic through firewall |
| QoS integration | Prioritize specific traffic |
| Application routing | Video through high-bandwidth link |

# 7. PBR Configuration Steps

## Step 1: Create ACL

Identify traffic.

Example:

```
Source network:

10.10.10.0/24
```

Command:

```bash
access-list 10 permit 10.10.10.0 0.0.0.255
```

---

# Step 2: Create Route-map

Example:

```bash
route-map PBR_POLICY permit 10
```

---

Match ACL:

```bash
match ip address 10
```

---

Set next hop:

```bash
set ip next-hop 192.168.1.1
```

---

# Step 3: Apply to Interface

Example:

```bash
interface GigabitEthernet0/0

ip policy route-map PBR_POLICY
```

# 8. Complete PBR Example

## Scenario

Network:

```

 |

 |

 |              |

```

Requirement:

```

```

```

```

---

## ACL

```bash
access-list 10 permit 10.10.10.0 0.0.0.255
```

---

## Route-map

```bash
route-map FINANCE_POLICY permit 10

match ip address 10

set ip next-hop 203.0.113.1
```

---

## Apply

```bash
interface GigabitEthernet0/1

ip policy route-map FINANCE_POLICY
```

---

Result:

```
Finance Traffic

↓

ISP-A

```

# 15. PBR and Route Maps

PBR uses the same route-map concept used for:

- Redistribution
- BGP policies
- Filtering

Difference:

| Feature | Redistribution | PBR |
|-|-|-|
| Controls | Routes | Packets |
| Uses | Route-map | Route-map |
| Match | Prefixes | Traffic |
| Set | Metrics/tags | Next hop |

---

# 16. PBR vs Static Routing

| Feature | Static Route | PBR |
|-|-|-|
| Decision | Destination | Policy |
| Configuration | Simple | Advanced |
| Source awareness | No | Yes |
| Application control | No | Yes |

---

# 17. PBR vs Dynamic Routing

| Feature | Dynamic Routing | PBR |
|-|-|-|
| Learns paths | Yes | No |
| Based on | Destination | Policy |
| Automatic adaptation | Yes | Limited |
| Traffic control | Limited | High |

# 18. PBR Limitations

| Limitation | Explanation |
|---|---|
| CPU usage | Extra packet processing |
| Asymmetric routing | Can create return path issues |
| Complexity | Harder troubleshooting |
| Failure handling | Needs tracking |

# CCNP Exam Traps

- PBR overrides normal routing table decisions.
- PBR uses route-maps.
- ACLs identify traffic.
- Match statements classify packets.
- Set statements define forwarding behavior.
- PBR is applied to incoming interfaces.
- PBR is not a replacement for dynamic routing.
- Route tracking improves PBR reliability.
- PBR can create asymmetric routing.
- The routing table is checked only when PBR does not provide a match.
