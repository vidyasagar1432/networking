# 1. Overview

TCP flow control prevents a fast sender from overwhelming a slow receiver by using a sliding window mechanism. TCP retransmission provides reliability by detecting lost segments and resending missing data using acknowledgments, timers, and sequence numbers.

---

# 2. Core Concepts

# TCP Reliability Mechanisms

| Mechanism | Purpose |
|---|---|
| Sequence numbers | Track segment order |
| Acknowledgments (ACK) | Confirm received data |
| Sliding window | Control transmission rate |
| Retransmission | Recover lost segments |
| Checksum | Detect corrupted data |
| Flow control | Protect receiver |
| Congestion control | Protect network |

---

# Flow Control Definition

Flow control:

```
A TCP mechanism that controls how much data
a sender can transmit before receiving acknowledgment.
```

Purpose:

```
Prevent receiver buffer overflow
```

---

# Flow Control Problem

Without flow control:

```
Fast Sender
     |
     |
     v
Slow Receiver

Receiver buffer fills
       |
       v
Packets dropped
```

---

# TCP Window Concept

TCP uses:

```
Receive Window (RWND)
```

The receiver advertises how much data it can accept.

---

# Receive Window (RWND)

Definition:

```
Amount of data a receiver can accept
without acknowledgment.
```

Example:

```
Receiver window = 5000 bytes
```

Sender can send:

```
5000 bytes
```

before waiting.

---

# TCP Sliding Window

Definition:

```
A mechanism that allows multiple TCP segments
to be sent before waiting for ACKs.
```

---

# Stop-and-Wait vs Sliding Window

| Feature | Stop-and-Wait | Sliding Window |
|---|---|---|
| Segments sent | One | Multiple |
| Efficiency | Low | High |
| Waiting | After every packet | After window full |
| TCP usage | No | Yes |

---

# Sliding Window Example

Window size:

```
4000 bytes
```

Sender sends:

```
Segment 1 = 1000 bytes
Segment 2 = 1000 bytes
Segment 3 = 1000 bytes
Segment 4 = 1000 bytes
```

No ACK required yet.

After ACK:

```
Window moves forward
```

New data can be sent.

---

# Window Movement

Before ACK:

```
[1][2][3][4] | [5][6][7]
 SEND WINDOW
```

After ACK:

```
[1][2][3][4]
 ACKED

        [5][6][7]
        NEW WINDOW
```

The window slides forward.

---

# TCP Window Size Field

TCP header contains:

```
Window Size
```

Size:

```
16 bits
```

Range:

```
0 - 65,535 bytes
```

---

# Window Scaling

Problem:

High-speed networks require larger windows.

Solution:

```
TCP Window Scaling Option
```

Allows windows larger than:

```
65,535 bytes
```

---

# Flow Control vs Congestion Control

| Feature | Flow Control | Congestion Control |
|---|---|---|
| Protects | Receiver | Network |
| Controlled by | Receiver | Sender |
| Uses | Receive window | Congestion window |
| Problem solved | Buffer overflow | Network congestion |

---

# TCP Congestion Window (CWND)

Sender maintains:

```
Congestion Window
```

Purpose:

```
Avoid overwhelming the network.
```

Effective sending window:

```
Minimum(RWND, CWND)
```

---

# TCP Acknowledgments

TCP uses:

```
Cumulative ACK
```

Example:

Receiver gets:

```
Segment 1
Segment 2
Segment 3
```

Sends:

```
ACK 4
```

Meaning:

```
Received everything before byte 4.
Send byte 4 next.
```

---

# TCP Retransmission

Definition:

```
Resending data when TCP detects loss.
```

---

# Causes of Retransmission

| Cause | Description |
|---|---|
| Missing ACK | Receiver did not confirm |
| Timeout | ACK took too long |
| Duplicate ACKs | Missing segment detected |
| Corruption | Checksum failure |

---

# Retransmission Timer (RTO)

TCP uses:

```
Retransmission Timeout (RTO)
```

Process:

```
Send segment
      |
      v
Wait for ACK
      |
      |
ACK received?
      |
 No
      |
      v
Retransmit
```

---

# Timeout-Based Retransmission

Example:

Sender:

```
Segment 1
```

Receiver:

```
No ACK
```

Timer expires:

```
Resend Segment 1
```

---

# Fast Retransmit

TCP can retransmit before timeout.

Triggered by:

```
3 duplicate ACKs
```

Example:

Receiver receives:

```
1
2
4
5
```

Missing:

```
3
```

Receiver sends:

```
ACK 3
ACK 3
ACK 3
```

Sender detects:

```
Missing segment 3
```

Immediately retransmits.

---

# Duplicate ACK

Meaning:

```
A segment is missing.
```

Example:

Expected:

```
Segment 5
```

Received:

```
Segment 6
```

Receiver sends:

```
Duplicate ACK 5
```

---

# TCP Segment Loss Example

Normal:

```
Sender              Receiver

Segment 1 -------->

Segment 2 -------->

Segment 3 -------->

ACK 4 <-------------
```

---

Loss:

```
Sender              Receiver

Segment 1 -------->

Segment 2 ----X

Segment 3 -------->

ACK 2 <-------------
ACK 2 <-------------
ACK 2 <-------------
```

Sender:

```
Fast retransmit Segment 2
```

---

# TCP Retransmission vs UDP

| Feature | TCP | UDP |
|---|---|---|
| Detect loss | Yes | Limited |
| Retransmit | Yes | No |
| Order packets | Yes | No |
| ACK | Yes | No |

---

# TCP Performance Factors

| Factor | Effect |
|---|---|
| Small window | Lower throughput |
| Packet loss | More retransmissions |
| High latency | Slower ACK return |
| Large window | Higher throughput |

---

# Bandwidth Delay Product (BDP)

Formula:

```
BDP = Bandwidth × Delay
```

Purpose:

Determines required TCP window size for high-speed links.

Example:

```
1 Gbps link
100 ms latency
```

Requires large TCP window.

# 5. Exam Traps

- Flow control protects the receiver, not the network.
- Congestion control protects the network.
- TCP uses sliding windows, not stop-and-wait.
- Window size determines how much data can be sent before ACK.
- TCP retransmits lost segments.
- UDP does not retransmit.
- Sequence numbers identify missing data.
- Three duplicate ACKs trigger fast retransmit.
- ACK numbers indicate the next expected byte.
- Large window size improves throughput on high-latency links.
- Packet loss reduces TCP performance.
- TCP reliability occurs at Layer 4.

# 7. Practice Questions

## Question 1

What is the purpose of TCP flow control?

A. Encrypt packets  
B. Prevent receiver overload  
C. Select routes  
D. Assign IP addresses  

### Answer: B

Explanation:

Flow control controls sender speed based on receiver capacity.

---

## Question 2

Which TCP mechanism allows multiple segments to be sent before receiving ACKs?

A. VLAN  
B. Sliding window  
C. ARP  
D. NAT  

### Answer: B

Explanation:

Sliding window improves TCP efficiency.

---

## Question 3

What triggers TCP fast retransmit?

A. One ACK  
B. Three duplicate ACKs  
C. DNS failure  
D. SYN packet  

### Answer: B

Explanation:

Three duplicate ACKs indicate a missing segment.

---

## Question 4

Which mechanism protects the network from congestion?

A. Receive window  
B. Flow control  
C. Congestion window  
D. ARP cache  

### Answer: C

Explanation:

CWND controls sender transmission rate based on network conditions.

---

## Question 5

A TCP sender transmits data but receives no ACK before the timer expires. What happens?

A. Connection closes immediately  
B. Data is retransmitted  
C. UDP is used  
D. Routing changes  

### Answer: B

Explanation:

TCP retransmits missing data after timeout.
