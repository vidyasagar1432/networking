# 1. Overview

TCP uses a three-way handshake to establish a reliable connection between two endpoints before data transmission begins. TCP uses a four-way termination process to gracefully close a session and ensure both sides finish sending data.

# TCP Three-Way Handshake

## Purpose

Establish a TCP connection between:

```
Client
   |
   |
Server
```

Before:

```
No connection
```

After:

```
Reliable TCP session established
```

---

# Three-Way Handshake Steps

```
Client                         Server

  SYN  -------------------->

       <-------------------- SYN + ACK

  ACK  -------------------->

        Connection Established
```

---

# Step 1: SYN

Client sends:

```
SYN
```

Meaning:

```
I want to start a TCP session.
```

Contains:

- Initial Sequence Number (ISN)
- TCP options

Client state:

```
SYN-SENT
```

---

# Step 2: SYN-ACK

Server responds:

```
SYN + ACK
```

Meaning:

```
I received your request.
I agree to establish a session.
```

Contains:

- Server ISN
- Acknowledgment of client ISN

Server state:

```
SYN-RECEIVED
```

---

# Step 3: ACK

Client sends:

```
ACK
```

Meaning:

```
I received your response.
Connection is ready.
```

Both sides enter:

```
ESTABLISHED
```

---

# Sequence Number Example

Client sends:

```
SYN
Seq = 100
```

---

Server replies:

```
SYN ACK

Seq = 500
Ack = 101
```

Meaning:

```
Received sequence 100.
Expected next byte = 101
```

---

Client sends:

```
ACK

Ack = 501
```

Meaning:

```
Received server sequence 500.
```

# TCP Connection States

| State | Meaning |
|---|---|
| CLOSED | No connection |
| LISTEN | Waiting for connection |
| SYN-SENT | SYN sent |
| SYN-RECEIVED | SYN received |
| ESTABLISHED | Data transfer |
| FIN-WAIT | Closing process |
| TIME-WAIT | Waiting before final close |

---

# TCP Four-Way Termination

## Purpose

Gracefully close a TCP connection.

Why four steps?

Because TCP is full-duplex:

```
Client → Server
Server → Client
```

Each direction closes separately.

---

# Four-Way Termination Process

```
Client                         Server

 FIN  -------------------->

       <-------------------- ACK


       <-------------------- FIN

 ACK  -------------------->


Connection Closed
```

---

# Step 1: FIN

Client sends:

```
FIN
```

Meaning:

```
I have finished sending data.
```

Client state:

```
FIN-WAIT-1
```

---

# Step 2: ACK

Server responds:

```
ACK
```

Meaning:

```
I received your FIN.
```

Server can still send data.

Server state:

```
CLOSE-WAIT
```

---

# Step 3: FIN

Server sends:

```
FIN
```

Meaning:

```
I have finished sending data.
```

Server state:

```
LAST-ACK
```

---

# Step 4: ACK

Client sends:

```
ACK
```

Meaning:

```
I received your FIN.
```

Client enters:

```
TIME-WAIT
```

Connection closes.

---

# Why TIME-WAIT Exists

Purpose:

1. Allow delayed packets to expire.
2. Ensure final ACK can be retransmitted.

Typical duration:

```
2 × Maximum Segment Lifetime (MSL)
```

---

# TCP Handshake vs Termination

| Feature | Handshake | Termination |
|---|---|---|
| Purpose | Create connection | Close connection |
| Steps | 3 | 4 |
| Main flag | SYN | FIN |
| Result | ESTABLISHED | CLOSED |

---

# TCP States During Handshake

| Device | State |
|---|---|
| Client sends SYN | SYN-SENT |
| Server receives SYN | SYN-RECEIVED |
| Both after ACK | ESTABLISHED |

---

# TCP States During Termination

| Step | State |
|---|---|
| Client sends FIN | FIN-WAIT-1 |
| Server ACKs FIN | CLOSE-WAIT |
| Server sends FIN | LAST-ACK |
| Client ACKs FIN | TIME-WAIT |

# TCP Reset (RST)

RST is used for:

- Immediate termination
- Refusing connection
- Invalid session

Example:

Connecting to closed port:

```
Client ---> Server

SYN

<--- RST
```

Meaning:

```
No service available.
```

# 5. Exam Traps

- TCP uses a three-way handshake to establish connections.
- TCP termination uses four steps because communication is full duplex.
- SYN starts a connection.
- ACK confirms received data.
- FIN gracefully closes a connection.
- RST immediately closes/refuses a connection.
- TCP does not use a two-way handshake.
- UDP does not perform a handshake.
- The final ACK in termination causes TIME-WAIT.
- Sequence numbers provide ordering.
- ACK numbers indicate the next expected byte.
- Established state means TCP session is ready.

# 7. Practice Questions

## Question 1

Which TCP flag starts a connection?

A. FIN  
B. ACK  
C. SYN  
D. RST  

### Answer: C

Explanation:

SYN synchronizes sequence numbers and begins TCP setup.

---

## Question 2

What is the correct TCP handshake order?

A. ACK → SYN → FIN  
B. SYN → SYN/ACK → ACK  
C. FIN → ACK → SYN  
D. SYN → FIN → ACK  

### Answer: B

Explanation:

TCP uses SYN, SYN/ACK, ACK.

---

## Question 3

Why does TCP use four-way termination?

A. Faster routing  
B. Both directions close independently  
C. Encryption process  
D. Reduce packet size  

### Answer: B

Explanation:

TCP is full-duplex, so each direction closes separately.

---

## Question 4

Which TCP flag immediately resets a connection?

A. SYN  
B. ACK  
C. FIN  
D. RST  

### Answer: D

Explanation:

RST forcibly terminates a TCP session.

---

## Question 5

Which TCP state indicates an active connection?

A. LISTEN  
B. SYN-SENT  
C. ESTABLISHED  
D. CLOSED  

### Answer: C

Explanation:

ESTABLISHED means the handshake completed successfully.
