# 1. Overview

Public cloud providers such as **Amazon Web Services (AWS)** and **Microsoft Azure** allow organizations to build private virtual networks inside the cloud.

Instead of buying physical routers, switches, firewalls, and cables, cloud providers create these networking components virtually.

AWS calls this:

```
VPC

Virtual Private Cloud
```

Microsoft Azure calls it:

```
VNet

Virtual Network
```

Although the names differ, they provide similar functionality.

# 3. What is an AWS VPC?

A **Virtual Private Cloud (VPC)** is a logically isolated virtual network within AWS.

It allows you to:

- Launch virtual machines (EC2)
- Create subnets
- Configure routing
- Apply security rules
- Connect to on-premises networks

Think of a VPC as your own private data center inside AWS.

---

# 4. What is an Azure VNet?

An **Azure Virtual Network (VNet)** is Azure's virtual networking service.

It provides:

- IP addressing
- Subnets
- Routing
- Security
- Hybrid connectivity
- Internet access

A VNet is conceptually similar to an AWS VPC.

# 10. Public vs Private Subnets

## Public Subnet

Has direct Internet connectivity.

Common workloads:

- Web servers
- Bastion hosts
- Load balancers
- VPN gateways

---

## Private Subnet

No direct Internet access.

Common workloads:

- Databases
- Internal applications
- Domain controllers
- Backend APIs

# 14. NAT Gateway

Private servers often need outbound Internet access for:

- Software updates
- Package downloads
- API calls

A **NAT Gateway** provides outbound Internet access without allowing inbound connections.

```

↓

↓
```

# 17. Security Groups (AWS)

A **Security Group** is a virtual firewall attached to an instance.

Characteristics:

- Stateful
- Allow rules only
- Applied to EC2 instances

Example:

```
Allow

TCP 80

TCP 443

TCP 22
```

---

# 18. Network ACLs (AWS)

Network ACLs operate at the subnet level.

Characteristics:

- Stateless
- Allow and deny rules
- Applied to subnets

---

# 19. Security Group vs Network ACL

| Feature | Security Group | Network ACL |
|----------|---------------|-------------|
| Level | Instance | Subnet |
| Stateful | Yes | No |
| Deny Rules | No | Yes |
| Typical Use | Instance protection | Subnet filtering |

# 33. Best Practices

- Use private subnets for databases.
- Place Internet-facing resources in public subnets.
- Follow the principle of least privilege with Security Groups/NSGs.
- Use NAT Gateways instead of exposing private servers.
- Deploy workloads across multiple Availability Zones.
- Use VPC/VNet peering for private cloud-to-cloud communication.
- Use Direct Connect or ExpressRoute for high-performance hybrid connectivity.

# 34. Troubleshooting

## VM Cannot Reach Internet

Check:

- Route table
- Internet Gateway
- NAT Gateway
- Public IP
- Security Group / NSG
- Network ACL

---

## VM Cannot Reach Another Subnet

Verify:

- Routing
- Security rules
- Subnet association
- VPC/VNet peering

---

## Hybrid VPN Down

Check:

- IPsec parameters
- Shared keys
- BGP (if used)
- Tunnel status
- Firewall policies

# CCNP Exam Traps

- A **VPC** (AWS) and a **VNet** (Azure) are logically isolated virtual networks.
- A **public subnet** has a route to an **Internet Gateway**; a **private subnet** does not.
- A **NAT Gateway** allows **outbound** Internet access from private subnets without permitting inbound connections.
- AWS **Security Groups** are **stateful** and applied to instances.
- AWS **Network ACLs** are **stateless** and applied to subnets.
- Azure **NSGs** are stateful and can be associated with subnets or network interfaces.
- **VPC/VNet Peering** provides private communication between virtual networks.
- **AWS Direct Connect** and **Azure ExpressRoute** provide dedicated private connectivity to the cloud.
