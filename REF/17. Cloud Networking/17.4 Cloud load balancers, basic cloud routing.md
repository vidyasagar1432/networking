# Cloud Load Balancers and Basic Cloud Routing

## CCNP Enterprise (ENCOR 350-401) & Cloud Networking Fundamentals

**CCNA Relevance: Basic understanding of cloud networking.**  
**CCNP ENCOR Relevance: High — Cloud load balancing, routing, high availability, and traffic distribution are essential hybrid networking concepts.**  
**Cloud Certifications (AWS SAA, Azure AZ-104, AZ-700): Core networking topic.**

---

# 1. Overview

Cloud applications must remain:

- Highly available
- Scalable
- Fault tolerant
- Resilient

Cloud providers achieve this using:

- Virtual Load Balancers
- Route Tables
- Internet Gateways
- NAT Gateways
- Multiple Availability Zones
- Dynamic Routing

Instead of relying on a single server or router, traffic is intelligently distributed across multiple resources.

# 3. What Is a Cloud Load Balancer?

A **Cloud Load Balancer** distributes incoming client traffic across multiple backend servers.

Goals:

- High Availability
- Fault Tolerance
- Scalability
- Better Performance

---

# 4. Basic Load Balancing

Without Load Balancer:

```
Users

↓

Single Server

↓

Failure

↓

Application Down
```

---

With Load Balancer:

```
Users

↓

Load Balancer

↓

Server A

Server B

Server C
```

Traffic continues even if one server fails.

# 10. Load Balancing Algorithms

Common algorithms:

| Algorithm | Description |
|-----------|-------------|
| Round Robin | Even distribution |
| Least Connections | Server with fewest active sessions |
| Weighted | Based on server capacity |
| Hash-Based | Client/IP affinity |

---

# 11. Round Robin

```
Request 1

↓

Server A

Request 2

↓

Server B

Request 3

↓

Server C

Request 4

↓

Server A
```

Each server receives requests in turn.

---

# 12. Least Connections

```
Server A

5 Sessions

Server B

2 Sessions

↓

New Request

↓

Server B
```

Useful for long-lived sessions.

---

# 13. Session Persistence (Sticky Sessions)

Sometimes users must continue using the same backend server.

```

↓

LB

↓

Server 2

↓

Future Requests

↓

Server 2
```

Useful for applications that store session state locally.

# 14. Layer 4 vs Layer 7 Load Balancing

## Layer 4 (Transport)

Uses:

- IP address
- TCP/UDP ports

Fast and efficient.

---

## Layer 7 (Application)

Uses:

- URL
- HTTP headers
- Cookies
- Host names

Allows advanced content-based routing.

---

# 15. Layer 7 Example

```
example.com/images

↓

Image Server

-------------------

example.com/api

↓

API Server
```

Different requests are routed based on URL paths.

---

# 16. AWS Load Balancers

AWS Elastic Load Balancing (ELB) includes:

| Type | OSI Layer | Purpose |
|------|-----------|----------|
| Application Load Balancer (ALB) | Layer 7 | HTTP/HTTPS applications |
| Network Load Balancer (NLB) | Layer 4 | TCP, UDP, TLS |
| Gateway Load Balancer (GWLB) | Layer 3/4 | Third-party virtual appliances |

*(Classic Load Balancer exists for legacy workloads but is generally superseded by ALB and NLB.)*

# 23. Cloud Routing Overview

Routing determines where packets are forwarded inside cloud networks.

Each subnet has:

- Route Table
- Destination
- Next Hop

---

# 24. Route Tables

Example:

| Destination | Next Hop |
|-------------|----------|
| 10.0.0.0/16 | Local |
| 0.0.0.0/0 | Internet Gateway |

Every packet is matched against the route table.

---

# 25. Longest Prefix Match

```

Most Specific Route

↓
```

# 36. Best Practices

- Deploy load balancers across multiple Availability Zones.
- Configure health probes.
- Use HTTPS whenever possible.
- Separate public and private workloads.
- Use least-privilege security rules.
- Implement autoscaling for dynamic workloads.
- Monitor latency and backend health.
- Use Layer 7 load balancing when application-aware routing is required.

# 37. Troubleshooting

## Server Not Receiving Traffic

Check:

- Health probe status
- Backend pool membership
- Security Groups / NSGs
- Route tables
- Firewall rules

---

## Client Cannot Reach Application

Verify:

- Public IP
- DNS records
- Listener configuration
- SSL/TLS certificates
- Backend health

---

## Routing Problems

Check:

- Route table associations
- Default route
- NAT Gateway
- Internet Gateway
- Transit Gateway / Virtual WAN
- Longest-prefix-match behavior

# CCNP Exam Traps

- Cloud load balancers distribute traffic across **multiple backend instances** to improve availability and scalability.
- **Health probes** determine whether a backend is eligible to receive traffic.
- **Layer 4** load balancers make decisions using **IP addresses and TCP/UDP ports**.
- **Layer 7** load balancers make decisions using **HTTP/HTTPS information**, such as URLs, host headers, and cookies.
- **AWS Application Load Balancer (ALB)** operates at **Layer 7**.
- **AWS Network Load Balancer (NLB)** operates primarily at **Layer 4**.
- **Azure Application Gateway** is Azure's **Layer 7** load balancer with optional **Web Application Firewall (WAF)** capabilities.
- Cloud route tables use the **longest-prefix-match** rule, just like traditional routers.
- **AWS Transit Gateway** and **Azure Virtual WAN** centralize routing between multiple networks.
