# Wireless LAN Controller (WLC) Configuration: AP Join Process & WLAN Profiles

## CCNP Enterprise (ENCOR 350-401) Wireless Networking

**CCNA Relevance:** WLC architecture, CAPWAP, AP join process, WLAN creation.  
**CCNP ENCOR Relevance:** High — Understanding Cisco Wireless LAN Controllers (WLCs), AP discovery and join, WLAN profiles, policy profiles, and enterprise wireless deployment is essential.

---

# 1. Overview

In enterprise wireless networks, **Wireless LAN Controllers (WLCs)** centrally manage lightweight Access Points (APs).

Instead of configuring every AP individually:

```
Administrator

↓

Wireless LAN Controller

↓

Hundreds of APs
```

The controller manages:

- AP configuration
- SSIDs (WLANs)
- Security policies
- RF management
- Roaming
- Firmware updates
- Client authentication
- QoS

# 6. AP Join Process Overview

The AP Join Process consists of several stages:

```
1. Boot

↓

2. Get IP

↓

3. Discover Controller

↓

4. Select Controller

↓

5. Join

↓

6. Download Configuration

↓

7. Operational
```

---

# 7. Step 1 — Obtain Power

The AP receives power through:

- PoE (Power over Ethernet)
- Power Adapter

PoE is the preferred enterprise deployment method.

---

# 8. Step 2 — Obtain an IP Address

The AP requires:

- IP Address
- Default Gateway
- DNS Server (optional but common)
- WLC discovery information (depending on the discovery method)

Typically assigned using **DHCP**.

---

# 9. Step 3 — Discover the WLC

The AP can discover a controller using several methods.

### Discovery Methods

- Layer 2 Broadcast (same VLAN only)
- DHCP Option 43
- DNS lookup (e.g., `cisco-capwap-controller`)
- Previously stored controller information
- Manual configuration
- CAPWAP broadcast (limited scenarios)

---

# 10. DHCP Option 43

DHCP Option 43 returns the WLC IP address.

```
AP

↓

DHCP Discover

↓

DHCP Server

↓

Option 43

↓

WLC Address
```

Useful when the WLC resides in a different subnet.

---

# 11. DNS Discovery

The AP can query DNS.

```
DNS Query

↓

cisco-capwap-controller

↓

WLC IP
```

If a matching DNS record exists, the AP learns the controller address.

---

# 12. Step 4 — CAPWAP Discovery

After learning one or more WLC addresses:

```
AP

↓

CAPWAP Discovery Request

↓

Controller

↓

Discovery Response
```

The AP builds a list of candidate controllers.

---

# 13. Step 5 — Controller Selection

If multiple controllers respond, the AP selects one based on factors such as:

- Primary/Secondary/Tertiary controller assignments
- Controller availability
- Join capacity
- Controller preference

---

# 14. Step 6 — Join Request

The AP sends:

```
Join Request

↓

Controller

↓

Join Response
```

The controller authenticates the AP before allowing it to join.

---

# 15. AP Authentication

The WLC validates the AP using:

- Manufacturer Installed Certificate (MIC)
- Self-Signed Certificate (SSC) (legacy/specific scenarios)
- Public Key Infrastructure (PKI)

Only trusted APs are allowed to join.

---

# 16. Step 7 — Configuration Download

After joining:

```
Controller

↓

Downloads

↓

AP Configuration
```

Typical configuration includes:

- RF parameters
- WLAN assignments
- QoS settings
- Security policies
- Firmware (if required)

---

# 17. Step 8 — Operational State

The AP begins:

- Advertising SSIDs
- Accepting wireless clients
- Exchanging CAPWAP control traffic
- Forwarding client traffic according to its configured mode

---

# 18. CAPWAP Channels

CAPWAP uses separate channels.

### Control Plane

Carries:

- AP management
- Configuration
- Keepalives

---

### Data Plane

Carries:

- Client traffic

Depending on the AP mode (e.g., Local vs FlexConnect), client traffic may be tunneled to the WLC or switched locally.

# 30. Best Practices

- Use PoE for AP deployment.
- Use DHCP Option 43 or DNS for large deployments.
- Configure Primary/Secondary WLC assignments.
- Use WPA3 where supported.
- Separate Guest and Corporate WLANs.
- Apply QoS to voice traffic.
- Keep controller and AP software versions compatible.
- Monitor AP join failures and CAPWAP status.

# 31. Troubleshooting AP Join

## AP Does Not Get an IP Address

Check:

- DHCP server
- VLAN assignment
- Trunk configuration
- DHCP scope
- IP helper address

---

## AP Cannot Find the WLC

Verify:

- DHCP Option 43
- DNS record (`cisco-capwap-controller`)
- Routing
- CAPWAP reachability
- Firewall ACLs

---

## AP Join Failure

Check:

- AP certificates
- Software compatibility
- Controller capacity
- Time synchronization (certificate validation)
- Licensing (platform dependent)

---

## Clients Cannot Connect

Verify:

- WLAN enabled
- Security configuration
- VLAN mapping
- RADIUS server
- DHCP
- ACLs

# CCNP Exam Traps

- Lightweight APs communicate with the WLC using **CAPWAP**.
- The AP join sequence is: **Boot → IP Address → WLC Discovery → Controller Selection → Join → Configuration Download → Operational**.
- WLC discovery methods include **DHCP Option 43**, **DNS (`cisco-capwap-controller`)**, previously known controllers, and manual configuration.
- **CAPWAP control traffic** is always tunneled to the WLC, while **client data traffic** depends on the AP mode (e.g., Local vs FlexConnect).
- On **Cisco Catalyst 9800 WLCs**, the configuration model separates **WLAN Profiles**, **Policy Profiles**, **RF Profiles**, and **Policy Tags**.
- A **WLAN Profile** defines the **SSID and security**, while a **Policy Profile** defines operational behavior such as VLANs and QoS.
