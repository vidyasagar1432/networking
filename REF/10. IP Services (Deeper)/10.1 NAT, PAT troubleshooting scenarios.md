# 1. Overview

NAT/PAT troubleshooting requires understanding how private addresses are translated into public addresses and how packets move through NAT-enabled routers. CCNA tests identifying configuration mistakes, verifying translations, checking ACLs, and troubleshooting inside/outside interface issues.

# 2. NAT/PAT Troubleshooting Fundamentals

# NAT Traffic Flow

```
Inside Host

Private IP
192.168.1.10

      |

Inside Interface

      |

NAT Router

      |

Outside Interface

      |

Internet

Public IP
203.0.113.5
```

---

# NAT Troubleshooting Checklist

Check:

| Item | Question |
|---|---|
| Interfaces | Are inside/outside correctly configured? |
| ACL | Is traffic permitted for NAT? |
| NAT rule | Does translation exist? |
| Routing | Is there a route to destination? |
| Public IP | Is address available? |
| Overload | Is PAT configured correctly? |
| Firewall | Is traffic blocked? |

# 3. Common NAT/PAT Problems

---

# Scenario 1: No Internet Access

## Problem

Users cannot access the Internet.

Example:

```
PC

192.168.1.10

     X

Internet
```

---

# Troubleshooting Steps

## Step 1: Check NAT Configuration

Command:

```bash
show running-config | include ip nat
```

Expected:

```
ip nat inside source list 1 interface g0/0 overload
```

---

## Step 2: Check NAT Interfaces

Inside:

```bash
interface g0/1
 ip nat inside
```

Outside:

```bash
interface g0/0
 ip nat outside
```

---

# Common Cause

Missing:

```bash
ip nat inside
```

or:

```bash
ip nat outside
```

---

# Solution

Configure interfaces correctly:

```bash
interface g0/1
 ip nat inside

interface g0/0
 ip nat outside
```

---

# Scenario 2: NAT Translation Not Appearing

## Problem

User traffic reaches router, but no translation is created.

Command:

```bash
show ip nat translations
```

Output:

```
(empty)
```

---

# Possible Causes

| Cause | Explanation |
|---|---|
| Wrong ACL | Traffic not matched |
| Missing NAT rule | No translation configured |
| Interface issue | NAT not applied |
| No traffic | Translation created only after traffic |

---

# Check ACL

```bash
show access-lists
```

Example:

Incorrect:

```
permit 192.168.2.0
```

Actual network:

```
192.168.1.0
```

---

# Solution

Correct ACL:

```bash
access-list 1 permit 192.168.1.0 0.0.0.255
```

---

# Scenario 3: Wrong Inside/Outside Interface

## Problem

NAT is configured but does not work.

Configuration:

```
LAN Interface

ip nat outside
```

Incorrect.

---

# Correct Configuration

LAN:

```bash
interface g0/1
 ip nat inside
```

Internet:

```bash
interface g0/0
 ip nat outside
```

---

# Verification

```bash
show ip nat statistics
```

Expected:

```
Inside interfaces:
GigabitEthernet0/1

Outside interfaces:
GigabitEthernet0/0
```

# Scenario 4: PAT Allows Only One Device

## Problem

One computer works, others fail.

Example:

```
PC1 ✓

PC2 ✗

PC3 ✗
```

---

# Possible Causes

Missing:

```
overload
```

---

Incorrect:

```bash
ip nat inside source list 1 interface g0/0
```

---

Correct:

```bash
ip nat inside source list 1 interface g0/0 overload
```

---

# Explanation

Without overload:

```
One private IP
=
One public IP
```

With overload:

```
Many private IPs
=
One public IP
+
different ports
```

# Scenario 5: Static NAT Server Not Reachable

## Problem

Internet users cannot access internal web server.

Topology:

```
Internet

   |

Public IP

   |

NAT

   |

Web Server
192.168.1.100
```

---

# Check Static NAT

Command:

```bash
show running-config | include static
```

Expected:

```bash
ip nat inside source static 192.168.1.100 203.0.113.100
```

---

# Common Causes

| Problem | Fix |
|---|---|
| Missing static NAT | Configure mapping |
| Wrong inside interface | Correct NAT role |
| Firewall blocking | Allow traffic |
| Server gateway wrong | Fix default gateway |

## Problem

Outgoing traffic works:

```
LAN → Internet ✓
```

Return traffic fails:

```
Internet → LAN ✗
```

---

# Possible Causes

## Missing Route

NAT router needs:

```
Default route to ISP
```

Check:

```bash
show ip route
```

---

## Firewall Blocking

Check:

- ACL
- Firewall rules

# Scenario 7: NAT Pool Exhaustion

## Problem

Users cannot access Internet during busy periods.

---

# Dynamic NAT Example

Pool:

```
203.0.113.10-20
```

Available:

```
11 addresses
```

Users:

```
500 devices
```

---

# Cause

Not enough public addresses.

---

# Solution

Options:

- Increase NAT pool
- Use PAT overload

# Scenario 8: ACL Blocking NAT Traffic

## Problem

NAT configured correctly but no translations appear.

---

# Check ACL

Command:

```bash
show access-lists
```

Example:

ACL:

```
deny 192.168.1.0
```

Result:

```
Traffic not translated
```

---

# Fix

Allow inside network:

```bash
access-list 10 permit 192.168.1.0 0.0.0.255
```

# Scenario 9: Wrong Default Route

## Problem

NAT translation exists:

```
Inside local → Inside global
```

---

```bash

```

```

```

```bash

# Scenario 10: NAT Hairpinning Issue

## Problem

Internal users cannot access internal server using public IP.

Example:

```
User

192.168.1.20

   |

Public IP

203.0.113.100

   |

---

# Cause

NAT loopback/hairpin NAT not configured.

# 5. NAT Troubleshooting Decision Table

| Symptom | Likely Cause |
|---|---|
| No translations | ACL/NAT rule issue |
| No Internet | Missing route/NAT |
| One user works | Missing overload |
| Server unreachable | Static NAT/firewall issue |
| Translations exist but fail | Routing/firewall |
| Pool empty | NAT exhaustion |
| Internal access fails | Hairpin NAT |

---

# 6. Exam Traps

- NAT translations appear only after traffic passes through the router.
- PAT requires the `overload` keyword.
- NAT requires inside and outside interfaces.
- ACLs identify traffic to translate.
- NAT does not provide security filtering.
- A default route is required for Internet access.
- Static NAT allows inbound connections.
- Dynamic NAT requires a public IP pool.
- PAT uses TCP/UDP port numbers.
- `show ip nat translations` is the primary troubleshooting command.
