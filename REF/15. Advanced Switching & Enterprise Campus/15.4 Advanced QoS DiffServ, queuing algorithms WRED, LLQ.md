# Advanced QoS: DiffServ, Queuing Algorithms, WRED, and LLQ

# 1. Overview

Quality of Service (QoS) is a collection of techniques used to **manage network traffic**, ensuring that important applications receive the bandwidth, latency, and reliability they require.

Without QoS:

- Voice packets compete equally with file transfers.
- Video calls may become choppy.
- Critical business applications may experience delays.

QoS allows administrators to prioritize traffic based on business requirements.

---

# 2. Why QoS Is Needed

Modern networks carry many traffic types simultaneously:

- Voice over IP (VoIP)
- Video conferencing
- Web browsing
- File transfers
- Database traffic
- Cloud applications
- Backups

Each application has different performance requirements.

Example:

```
                WAN Link

        +----------------------+

Voice
Video
Email
Backups
Web

        ↓

Only 100 Mbps Available
```

QoS determines **which packets should be sent first**.

# 6. QoS Models

Two primary architectures:

| Model | Description |
|---------|-------------|
| IntServ | Per-flow reservation (RSVP) |
| DiffServ | Class-based QoS |

Modern enterprise networks almost always use **DiffServ**.

---

# 7. IntServ (Integrated Services)

Characteristics:

- Resource reservation
- RSVP protocol
- Per-flow state
- High overhead
- Poor scalability

Mostly of historical interest.

---

# 8. DiffServ (Differentiated Services)

## Definition

DiffServ classifies traffic into **service classes** instead of reserving resources for individual flows.

Packets are marked once and then treated according to their marking throughout the network.

---

Architecture:

```
Packet

↓

Classification

↓

Mark DSCP

↓

Forward According To Class
```

---

# 9. DSCP (Differentiated Services Code Point)

DSCP is a **6-bit field** in the IPv4 ToS byte (or IPv6 Traffic Class field).

```
IPv4 Header

+-------------------------+

DSCP (6 bits)

ECN (2 bits)

+-------------------------+
```

---

# 10. Common DSCP Values

| DSCP | Decimal | Use |
|-------|---------|-----|
| BE (Best Effort) | 0 | Default traffic |
| EF (Expedited Forwarding) | 46 | Voice |
| AF11 | 10 | Low-priority data |
| AF21 | 18 | Business applications |
| AF31 | 26 | Critical applications |
| AF41 | 34 | Video |
| CS6 | 48 | Routing protocols |
| CS7 | 56 | Network control |

# 19. Queuing Algorithms

Major algorithms:

| Algorithm | Purpose |
|------------|----------|

---

# 20. FIFO (First-In, First-Out)

```
Packet1

↓

Packet2

↓

Packet3
```

First packet in is the first packet out.

Advantages:

- Simple
- Low overhead

Disadvantages:

- No prioritization

---

# 21. Priority Queuing (PQ)

Multiple queues:

```
High

Medium

Normal

Low
```

Scheduler always services:

```
High

↓

Medium

↓

Normal

↓

Low
```

Problem:

Low-priority traffic can starve.

---

# 22. Custom Queuing (CQ)

Each queue receives a configured number of bytes per cycle.

Example:

```
Voice

50%

Data

30%

Backup

20%
```

---

# 23. Weighted Fair Queuing (WFQ)

Automatically allocates bandwidth.

Small interactive flows receive better service.

Advantages:

- Fair
- Automatic

Disadvantages:

- Limited scalability
- Less control

---

# 24. Class-Based WFQ (CBWFQ)

Administrator defines classes.

Example:

```
Voice

↓

30%

Video

↓

40%

Data

↓

20%

Backup

↓

10%
```

Provides guaranteed bandwidth.

---

# 25. Low Latency Queuing (LLQ)

LLQ =

```
CBWFQ

+

Priority Queue
```

Voice receives:

```
Strict Priority

```

Other traffic uses CBWFQ.

---

# 26. LLQ Operation

```
Voice Queue

↓

Always First

↓

Other Queues

↓

CBWFQ Scheduling
```

Ideal for:

- VoIP
- Video conferencing

---

# 28. Congestion Avoidance

Instead of waiting until queues are full:

QoS may begin dropping packets early.

Purpose:

Prevent TCP global synchronization.

---

# 29. Tail Drop

Default behavior.

```
Queue

↓

Full

↓

Drop New Packets
```

Problems:

- Global synchronization
- TCP burst recovery
- High latency

---

# 30. WRED (Weighted Random Early Detection)

## Definition

WRED proactively drops packets **before** the queue becomes full.

Packets are dropped based on:

- Queue depth
- Traffic class
- DSCP value

---

# 31. WRED Operation

```
Queue

↓

Growing

↓

Random Drops Begin

↓

TCP Slows Down

↓

Queue Stabilizes
```

---

# 32. WRED Advantages

- Prevents queue overflow
- Reduces packet bursts
- Improves TCP performance
- Avoids global synchronization

---

# 33. WRED Priority

Higher-priority packets:

```
Lower Drop Probability
```

Lower-priority packets:

```
Higher Drop Probability
```

Example:

```
Voice

Rarely Dropped

↓

Best Effort

Dropped Earlier
```

---

# 34. RED vs WRED

| Feature | RED | WRED |
|----------|-----|------|
| Random Drops | Yes | Yes |
| QoS Awareness | No | Yes |
| DSCP Awareness | No | Yes |
| Enterprise Use | Rare | Common |

---

# 35. Traffic Policing

Policing:

```
Traffic Exceeds Limit

↓

Drop

or

Remark
```

Characteristics:

- Immediate enforcement
- Drops excess traffic
- Used at network edges

---

# 36. Traffic Shaping

Shaping:

```
Traffic Exceeds Limit

↓

Buffer

↓

Transmit Later
```

Characteristics:

- Smooths bursts
- Reduces drops
- Common on WAN links

---

# 37. Policing vs Shaping

| Feature | Policing | Shaping |
|----------|----------|----------|
| Drops Packets | Yes | No (normally) |
| Buffers Traffic | No | Yes |
| Controls Bursts | Limited | Excellent |
| WAN Use | Less Common | Very Common |

# 41. Best Practices

- Use **DiffServ** in enterprise networks.
- Mark traffic as close to the source as possible.
- Trust markings only from trusted devices.
- Use **LLQ** for delay-sensitive traffic like VoIP.
- Use **CBWFQ** for business applications.
- Use **WRED** for TCP-based best-effort traffic.
- Avoid excessive priority bandwidth that could starve other classes.
- Monitor QoS counters regularly with `show policy-map interface`.

# CCNP Exam Traps

- **DiffServ** is the dominant enterprise QoS architecture.
- **DSCP** uses **6 bits**.
- **EF (DSCP 46)** is commonly used for voice.
- **LLQ = CBWFQ + Strict Priority Queue**.
- **WRED** begins dropping packets **before** the queue is full.
- **Tail Drop** drops packets only after the queue is completely full.
- **Policing** drops or remarks excess traffic; **Shaping** buffers excess traffic.
- **Class-map** identifies traffic; **Policy-map** defines actions.
- QoS policies are applied to interfaces using `service-policy`.
