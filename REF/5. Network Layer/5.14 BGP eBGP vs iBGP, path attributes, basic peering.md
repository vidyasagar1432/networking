# 1. Overview

Border Gateway Protocol (BGP) is a path-vector routing protocol used to exchange routing information between autonomous systems. CCNA tests BGP fundamentals, eBGP vs iBGP differences, autonomous systems, neighbor relationships, and basic path attribute concepts.

---

# 2. Core Concepts

# BGP Definition

BGP:

```
Border Gateway Protocol
```

Type:

```
Path Vector Routing Protocol
```

Primary use:

```
Internet routing
```

---

# BGP Characteristics

| Feature | Value |
|---|---|
| Protocol type | Path Vector |
| Transport protocol | TCP |
| TCP port | 179 |
| Administrative Distance (eBGP) | 20 |
| Administrative Distance (iBGP) | 200 |
| Metric concept | Path attributes |
| Main use | Inter-AS routing |

---

# Autonomous System (AS)

## Definition

An Autonomous System is a collection of networks managed by a single organization.

Example:

```
ISP A
AS 65001

ISP B
AS 65002
```

Each AS has a unique:

```
ASN (Autonomous System Number)
```

---

# ASN Types

| Type | Range |
|---|---|
| Traditional ASN | 1 - 65535 |
| Private ASN | 64512 - 65534 |
| Extended ASN | 4-byte ASN |

Example:

```
AS 65001
```

---

# BGP Operation

Basic process:

```
Establish TCP session
          |
          v
Exchange routes
          |
          v
Apply policies
          |
          v
Select best path
```

---

# BGP Neighbor Relationship

BGP routers form:

```
BGP Peering Session
```

using:

```
TCP port 179
```

---

# BGP Neighbor Requirements

| Requirement | Must Match |
|---|---|
| IP connectivity | Yes |
| AS number | Depends on eBGP/iBGP |
| TCP 179 reachable | Yes |
| Authentication (optional) | Yes |
| Router ID | Unique |

---

# BGP Peering Types

Two major types:

| Type | Meaning |
|---|---|
| eBGP | External BGP |
| iBGP | Internal BGP |

---

# eBGP (External BGP)

## Definition

BGP session between routers in different autonomous systems.

Example:

```
AS 65001
Router A
      |
      |
      |
Router B
AS 65002
```

---

# eBGP Characteristics

| Feature | Value |
|---|---|
| AS relationship | Different AS |
| Common use | ISP connections |
| AD | 20 |
| TTL default | 1 |
| Updates | Between organizations |

---

# iBGP (Internal BGP)

## Definition

BGP session between routers inside the same autonomous system.

Example:

```
AS 65001

R1 -------- R2
```

---

# iBGP Characteristics

| Feature | Value |
|---|---|
| AS relationship | Same AS |
| Common use | ISP internal routing |
| AD | 200 |
| TTL default | 255 |
| Requires full mesh | Traditionally |

---

# eBGP vs iBGP

| Feature | eBGP | iBGP |
|---|---|---|
| AS number | Different | Same |
| AD | 20 | 200 |
| Location | Between organizations | Within organization |
| TTL | 1 | 255 |
| Common use | ISP peering | ISP backbone |

---

# BGP Path Selection

BGP does not use:

```
Hop count
```

or:

```
Bandwidth
```

It uses:

```
Path Attributes
```

---

# Important BGP Path Attributes

| Attribute | Purpose |
|---|---|
| Weight | Cisco-specific preference |
| Local Preference | Outbound path selection |
| AS Path | Number of AS hops |
| Origin | How route entered BGP |
| MED | Influence inbound path |
| Next Hop | Next router address |
| Community | Route grouping/policy |

---

# BGP Best Path Selection Order

Common Cisco order:

| Order | Attribute |
|---|---|
| 1 | Highest Weight |
| 2 | Highest Local Preference |
| 3 | Locally originated route |
| 4 | Shortest AS Path |
| 5 | Lowest Origin type |
| 6 | Lowest MED |
| 7 | eBGP over iBGP |
| 8 | Lowest IGP metric to next hop |
| 9 | Lowest Router ID |

---

# Weight

## Definition

Cisco-specific attribute.

Range:

```
0 - 65535
```

Default:

```
0
```

Higher is preferred.

Example:

```
Route A Weight = 500
Route B Weight = 100
```

Winner:

```
Route A
```

---

# Local Preference

## Definition

Controls outbound traffic from an AS.

Higher value preferred.

Default:

```
100
```

Example:

```
Path A Local Pref = 200
Path B Local Pref = 100
```

Winner:

```
Path A
```

---

# AS Path

## Definition

List of AS numbers a route has traveled through.

Example:

```
AS 65001 → AS 65002 → AS 65003
```

AS Path:

```
65002 65003
```

Shorter path is preferred.

---

# Origin Attribute

Shows how BGP learned the route.

Values:

| Code | Meaning |
|---|---|
| IGP | Network command |
| EGP | Old EGP protocol |
| Incomplete | Redistribution |

Preference:

```
IGP < EGP < Incomplete
```

---

# MED (Multi Exit Discriminator)

Purpose:

Influences inbound traffic from neighboring AS.

Lower MED preferred.

Example:

```
Path A MED = 50
Path B MED = 100
```

Winner:

```
Path A
```

---

# Next-Hop Attribute

Identifies:

```
Router to reach destination
```

Example:

```
Network:
10.10.0.0/16

Next hop:
192.168.1.1
```

---

# Community Attribute

Groups routes for applying policies.

Example:

```
Community:
65001:100
```

Used by ISPs.

---

# BGP Tables

| Table | Purpose |
|---|---|
| Neighbor table | BGP peers |
| BGP table | All learned BGP routes |
| Routing table | Best routes installed |

---

# BGP Neighbor States

| State | Meaning |
|---|---|
| Idle | Initial state |
| Connect | TCP connection attempt |
| Active | Waiting/retrying |
| OpenSent | OPEN message sent |
| OpenConfirm | Waiting for confirmation |
| Established | Neighbor relationship formed |

---

# Established State

Successful BGP session:

```
Established
```

Means:

- TCP connection works
- BGP messages exchanged
- Routes can be advertised

---

# BGP Messages

| Message | Purpose |
|---|---|
| OPEN | Establish session |
| UPDATE | Advertise routes |
| KEEPALIVE | Maintain session |
| NOTIFICATION | Report errors |

---

# Basic BGP Peering Example

Topology:

```
R1                 R2

AS 65001        AS 65002
```

R1 configures R2 as eBGP neighbor.

# Cisco Commands

## Enable BGP

```bash
router bgp 65001
```

Starts BGP process.

```
65001 = local ASN
```

---

## Configure Neighbor

```bash
neighbor 10.0.0.2 remote-as 65002
```

Defines BGP peer.

Meaning:

```
Neighbor IP:
10.0.0.2

Remote AS:
65002
```

---

## Advertise Network

```bash
network 192.168.1.0 mask 255.255.255.0
```

Advertises network into BGP.

---

## Verify BGP Neighbors

```bash
show ip bgp summary
```

Displays:

- Neighbor status
- AS number
- State

---

## View BGP Routes

```bash
show ip bgp
```

Displays BGP routing table.

---

## View Specific BGP Route

```bash
show ip bgp 192.168.1.0
```

Shows path attributes.

# 5. Exam Traps

- BGP is a path-vector protocol.
- BGP uses TCP port 179.
- eBGP uses different AS numbers.
- iBGP uses the same AS number.
- eBGP AD = 20.
- iBGP AD = 200.
- Shortest AS path is preferred.
- Higher Local Preference is preferred.
- Lower MED is preferred.
- Weight is Cisco-specific.
- BGP does not use hop count as metric.
- BGP neighbor state must reach Established.
- BGP is mainly used between autonomous systems.
- TCP connection must exist before BGP exchange.
- Router ID is still required in BGP.

# 7. Practice Questions

## Question 1

What protocol does BGP use?

A. UDP  
B. TCP  
C. ICMP  
D. RTP  

### Answer: B. TCP

Explanation:

BGP uses TCP port 179.

---

## Question 2

Two routers in different autonomous systems use:

A. iBGP  
B. eBGP  
C. OSPF  
D. RIP  

### Answer: B. eBGP

Explanation:

eBGP operates between different AS numbers.

---

## Question 3

Which BGP attribute prefers a shorter path through autonomous systems?

A. Weight  
B. Local Preference  
C. AS Path  
D. MED  

### Answer: C. AS Path

Explanation:

Shortest AS path is preferred.

---

## Question 4

What is the default iBGP administrative distance?

A. 20  
B. 90  
C. 110  
D. 200  

### Answer: D. 200

Explanation:

iBGP routes have AD 200.

---

## Question 5

Which BGP state indicates a successful neighbor relationship?

A. Active  
B. OpenSent  
C. Established  
D. Idle  

### Answer: C. Established

Explanation:

Established means BGP peering is operational.
