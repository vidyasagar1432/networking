# 1. Overview

Network threats are malicious activities that attempt to disrupt services, steal information, gain unauthorized access, or compromise network resources. CCNA tests common attack concepts such as DoS/DDoS, spoofing, Man-in-the-Middle attacks, and social engineering techniques.

---

# 2. Core Concepts

# Security Threat Categories

| Category | Goal |
|---|---|
| Availability attacks | Make services unavailable |
| Confidentiality attacks | Steal information |
| Integrity attacks | Modify data |
| Authentication attacks | Gain unauthorized access |

---

# CIA Security Triad

Network security focuses on:

| Principle | Meaning |
|---|---|
| Confidentiality | Prevent unauthorized access to data |
| Integrity | Prevent unauthorized modification |
| Availability | Keep services accessible |

# 1. DoS (Denial of Service)

## Definition

DoS is an attack that attempts to make a service unavailable by overwhelming a system with traffic or requests.

---

# DoS Goal

```
Consume resources

↓

Service becomes unavailable
```

---

# DoS Targets

Attackers may target:

- Web servers
- Routers
- Firewalls
- Applications
- Network bandwidth

---

# DoS Examples

## Traffic Flooding

Attacker sends:

```
Large amount of traffic
```

Result:

```
Bandwidth exhaustion
```

---

## Resource Exhaustion

Attacker consumes:

- CPU
- Memory
- Connections

---

# Common DoS Attacks

| Attack | Description |
|---|---|
| SYN Flood | Overwhelms TCP connection requests |
| Ping Flood | Sends excessive ICMP traffic |
| HTTP Flood | Overloads web servers |

---

# SYN Flood Attack

Normal TCP:

```
Client

SYN

  →

Server

SYN-ACK

  →

Client

ACK
```

---

Attack:

```
Attacker

Many SYN requests

        ↓

Server waits for responses

        ↓

Resources exhausted
```

---

# DoS Characteristics

| Feature | DoS |
|---|---|
| Attack source | Single system |
| Target | Service availability |
| Result | Service slowdown/outage |

---

# 2. DDoS (Distributed Denial of Service)

## Definition

DDoS is a DoS attack launched from multiple compromised systems.

---

# DDoS Architecture

```
          Attacker

             |

        Botnet Control

             |

 ---------------------

 |        |        |

PC1      PC2      PC3

             |

          Target

```

---

# Botnet

Botnet:

```
Network of infected devices controlled by attacker
```

Examples:

- Compromised computers
- IoT devices
- Servers

---

# DoS vs DDoS

| Feature | DoS | DDoS |
|---|---|---|
| Attack sources | One | Many |
| Difficulty | Lower | Higher |
| Detection | Easier | Harder |
| Scale | Limited | Large |

---

# DDoS Mitigation

Methods:

| Method | Purpose |
|---|---|
| Rate limiting | Limit traffic |
| Traffic filtering | Block malicious sources |
| CDN | Distribute traffic |
| DDoS protection service | Absorb attacks |
| Firewalls | Filter traffic |

---

# 3. Spoofing

## Definition

Spoofing is an attack where an attacker pretends to be a trusted entity.

---

# Spoofing Goal

```
Fake identity

↓

Gain trust/access
```

---

# Types of Spoofing

| Type | Fake Information |
|---|---|
| IP spoofing | Source IP address |
| MAC spoofing | MAC address |
| Email spoofing | Sender identity |
| DNS spoofing | DNS responses |
| ARP spoofing | IP-to-MAC mapping |

---

# IP Spoofing

Attacker changes:

```
Source IP address
```

Example:

Actual:

```
10.1.1.50
```

Fake:

```
192.168.1.1
```

---

# ARP Spoofing

Normal ARP:

```
IP Address

↓

MAC Address
```

---

Attack:

Attacker sends false ARP information.

Example:

```
Gateway IP

is mapped to

Attacker MAC
```

Result:

Traffic can be redirected.

---

# Spoofing Prevention

| Method | Purpose |
|---|---|
| DHCP Snooping | Build trusted bindings |
| Dynamic ARP Inspection | Prevent ARP attacks |
| IP Source Guard | Block invalid IP/MAC pairs |
| Authentication | Verify identity |

---

# 4. MITM (Man-in-the-Middle)

## Definition

A MITM attack occurs when an attacker secretly places themselves between two communicating parties.

---

# Normal Communication

```
User

     |

Server
```

---

# MITM Communication

```
User

     |

Attacker

     |

Server
```

---

# MITM Goals

Attacker may:

- Read traffic
- Modify data
- Steal credentials
- Redirect communication

---

# MITM Examples

| Attack | Description |
|---|---|
| ARP poisoning | Redirect LAN traffic |
| Rogue Wi-Fi AP | Fake wireless network |
| DNS manipulation | Redirect websites |
| SSL stripping | Downgrade encryption |

---

# MITM Attack Process

Example:

1. Attacker tricks client.
2. Traffic passes through attacker.
3. Attacker captures/modifies data.
4. Communication continues unnoticed.

---

# MITM Prevention

| Method | Purpose |
|---|---|
| Encryption | Protect data |
| HTTPS/TLS | Secure communication |
| VPN | Encrypted tunnel |
| Certificate validation | Verify identity |
| Secure Wi-Fi | Prevent rogue access |

---

# 5. Social Engineering

## Definition

Social engineering attacks exploit human behavior instead of technical vulnerabilities.

---

# Social Engineering Goal

```
Trick people

↓

Reveal information

↓

Gain access
```

---

# Common Social Engineering Attacks

| Attack | Description |
|---|---|
| Phishing | Fake messages/emails |
| Spear phishing | Targeted phishing |
| Vishing | Voice phishing |
| Smishing | SMS phishing |
| Tailgating | Following authorized users |
| Pretexting | Fake scenario |
| Baiting | Fake reward/device |

---

# Phishing Example

Attacker sends:

```
Fake banking email
```

Victim enters:

```
Username + Password
```

Attacker steals credentials.

---

# Spear Phishing

Difference:

| Phishing | Spear Phishing |
|---|---|
| Generic | Targeted |
| Many victims | Specific person |
| Less personalized | Highly customized |

---

# Social Engineering Prevention

| Method | Purpose |
|---|---|
| User training | Recognize attacks |
| MFA | Reduce password risk |
| Verification procedures | Confirm identity |
| Security awareness | Improve behavior |

---

# 3. Worked Examples

## Example 1: Identify Attack

Scenario:

```
Thousands of computers send traffic to a website causing outage.
```

Answer:

```
DDoS
```

Reason:

Multiple systems are involved.

---

# Example 2: Identify MITM

Scenario:

```
Attacker redirects LAN traffic through their laptop and captures passwords.
```

Answer:

```
MITM attack
```

Reason:

Attacker is positioned between communication endpoints.

# 4. Exam Traps

- DoS uses one attacker; DDoS uses many.
- DDoS commonly uses botnets.
- Spoofing means pretending to be another identity.
- ARP spoofing targets IP-to-MAC mappings.
- MITM intercepts communication between two parties.
- Encryption helps prevent MITM data theft.
- Social engineering targets people, not devices.
- Phishing is a social engineering attack.
- Firewalls do not stop every attack.
- Security requires multiple layers of protection.
