# 1. Overview

Trunking allows a single physical link to carry traffic from multiple VLANs between network devices. CCNA tests IEEE 802.1Q tagging, trunk port behavior, native VLAN operation, allowed VLANs, and troubleshooting issues such as native VLAN mismatches.

---

# 2. Core Concepts

# What is VLAN Trunking?

## Definition

A trunk is a Layer 2 link that carries traffic for multiple VLANs between network devices.

Common connections:

- Switch-to-switch
- Switch-to-router (Router-on-a-stick)
- Switch-to-Access Point

Example:

```
Switch A                    Switch B

VLAN 10  ----\
VLAN 20 ----- Trunk ------- VLAN 10
VLAN 30  ----/              VLAN 20
                            VLAN 30
```

---

# Access Port vs Trunk Port

| Feature | Access Port | Trunk Port |
|---|---|---|
| VLANs carried | One VLAN | Multiple VLANs |
| Connected devices | PCs, printers | Switches, routers |
| Frame tagging | No | Yes (802.1Q) |
| Default mode | Access | Depends on configuration |

---

# Trunk Characteristics

| Feature | Description |
|---|---|
| Layer | Layer 2 |
| Carries | Multiple VLANs |
| Standard | IEEE 802.1Q |
| Tagging | Adds VLAN information |
| Used between | Network devices |

---

# IEEE 802.1Q

## Definition

802.1Q is the IEEE standard used to identify VLAN membership by adding a VLAN tag inside an Ethernet frame.

---

# 802.1Q Frame Format

Original Ethernet frame:

```
+------------+
| Dest MAC   |
+------------+
| Source MAC |
+------------+
| Type       |
+------------+
| Data       |
+------------+
| FCS        |
+------------+
```

After tagging:

```
+------------+
| Dest MAC   |
+------------+
| Source MAC |
+------------+
| 802.1Q Tag |
+------------+
| Type       |
+------------+
| Data       |
+------------+
| FCS        |
+------------+
```

---

# 802.1Q Tag Location

The VLAN tag is inserted between:

```
Source MAC
      |
      v
802.1Q Tag
      |
      v
EtherType
```

---

# 802.1Q Tag Fields

| Field | Size | Purpose |
|---|---:|---|
| TPID | 16 bits | Identifies 802.1Q frame |
| PCP | 3 bits | Priority (QoS) |
| DEI | 1 bit | Drop eligibility |
| VLAN ID | 12 bits | VLAN identification |

---

# VLAN ID Field

Size:

```
12 bits
```

Calculation:

```
2^12 = 4096 VLAN IDs
```

Usable VLAN range:

```
1 - 4094
```

---

# Tagged vs Untagged Frames

| Frame Type | VLAN Tag |
|---|---|
| Normal trunk VLAN traffic | Tagged |
| Native VLAN traffic | Untagged |
| Access port traffic | Untagged |

---

# Native VLAN

## Definition

The native VLAN is the VLAN that carries untagged frames across an 802.1Q trunk.

Example:

```
Switch A ===== Trunk ===== Switch B

Untagged traffic = Native VLAN
```

---

# Default Native VLAN

Cisco default:

```
VLAN 1
```

---

# Native VLAN Rules

| Rule | Explanation |
|---|---|
| Must match on both trunk ends | Prevents traffic issues |
| Frames are untagged | Default behavior |
| Exists only on trunks | Not an access concept |

---

# Native VLAN Mismatch

## Definition

A native VLAN mismatch occurs when two trunk ports have different native VLAN configurations.

Example:

Switch A:

```
Native VLAN 10
```

Switch B:

```
Native VLAN 20
```

---

# Native VLAN Mismatch Result

```
Switch A
Native VLAN 10

      |
      |
    Trunk

      |
      |

Switch B
Native VLAN 20
```

Problem:

- Untagged frames are assigned to different VLANs.
- Traffic may enter the wrong VLAN.
- Connectivity issues occur.

---

# Native VLAN Mismatch Symptoms

| Symptom | Cause |
|---|---|
| CDP warning messages | Different native VLANs |
| Unexpected VLAN traffic | Frames mapped incorrectly |
| Connectivity problems | VLAN assignment mismatch |

---

# Cisco Native VLAN Warning

Example message:

```
%CDP-4-NATIVE_VLAN_MISMATCH:
Native VLAN mismatch discovered
```

Meaning:

The two connected trunk interfaces have different native VLAN settings.

---

# Allowed VLANs on Trunk

A trunk does not always carry every VLAN.

Example:

Allowed VLANs:

```
10,20,30
```

Traffic from:

```
VLAN 40
```

will not pass.

---

# VLAN Pruning

## Definition

Removing unnecessary VLAN traffic from trunks to reduce bandwidth usage.

Example:

```
VLAN 50 not needed on Switch B

Remove from trunk
```

---

# Trunk Negotiation

Cisco switches can use:

```
DTP (Dynamic Trunking Protocol)
```

to negotiate trunk links.

---

# DTP Modes

| Mode | Behavior |
|---|---|
| Access | Always access |
| Trunk | Always trunk |
| Dynamic desirable | Actively tries to form trunk |
| Dynamic auto | Waits for trunk request |

---

# DTP Compatibility

| Side A | Side B | Result |
|---|---|---|
| Trunk | Trunk | Trunk |
| Trunk | Access | Access |
| Desirable | Auto | Trunk |
| Auto | Auto | No trunk |

---

# Recommended Enterprise Practice

Use:

```
switchport mode trunk
```

Disable negotiation:

```
switchport nonegotiate
```

Reasons:

- Better security
- Predictable configuration

# 3. Worked Examples

## Example 1: Identify Native VLAN Problem

### Scenario

Two switches are connected using a trunk.

Switch A:

```
Native VLAN 99
```

Switch B:

```
Native VLAN 1
```

What problem exists?

---

### Solution

Step 1:

Compare native VLAN values.

```
99 ≠ 1
```

Step 2:

Native VLAN must match on both sides.

Step 3:

Problem:

```
Native VLAN mismatch
```

Fix:

Configure:

```
Native VLAN 99
```

on both switches.

---

## Example 2: Determine VLAN Tagging

### Scenario

A trunk carries:

- VLAN 10
- VLAN 20
- VLAN 99 (native)

Which frames are tagged?

---

### Solution

Step 1:

Normal VLAN traffic is tagged.

```
VLAN 10 → Tagged
VLAN 20 → Tagged
```

Step 2:

Native VLAN traffic is untagged.

```
VLAN 99 → Untagged
```

Answer:

```
Tagged: VLAN 10, VLAN 20
Untagged: VLAN 99
```

# 5. Exam Traps

- 802.1Q is the standard VLAN tagging protocol.
- Native VLAN frames are untagged.
- Normal trunk VLAN traffic is tagged.
- Default native VLAN is VLAN 1.
- Native VLAN must match on both trunk sides.
- Access ports do not tag frames.
- Trunks carry multiple VLANs.
- VLANs not allowed on a trunk cannot pass traffic.
- DTP is Cisco proprietary.
- Two ports in dynamic auto mode do not form a trunk.
- A native VLAN mismatch does not disable the trunk; it causes traffic problems.

# 7. Practice Questions

## Question 1

Which protocol adds VLAN information to Ethernet frames?

A. STP  
B. 802.1Q  
C. ARP  
D. CDP  

### Answer: B. 802.1Q

Explanation:

IEEE 802.1Q inserts VLAN tags into Ethernet frames.

---

## Question 2

What happens to native VLAN frames on an 802.1Q trunk?

A. They are encrypted  
B. They are dropped  
C. They are untagged  
D. They are routed  

### Answer: C. They are untagged

Explanation:

Native VLAN traffic does not receive an 802.1Q tag.

---

## Question 3

Two trunk ports have different native VLANs. What issue occurs?

A. Speed mismatch  
B. Native VLAN mismatch  
C. Duplex mismatch  
D. IP conflict  

### Answer: B. Native VLAN mismatch

Explanation:

Both ends of a trunk must use the same native VLAN.

---

## Question 4

Which command displays trunk information?

A. show interfaces trunk  
B. show ip route  
C. show arp  
D. show spanning-tree  

### Answer: A. show interfaces trunk

Explanation:

This command shows trunk status, VLANs, and native VLAN.

---

## Question 5

Which VLAN traffic is normally untagged on an 802.1Q trunk?

A. Data VLAN  
B. Voice VLAN  
C. Native VLAN  
D. Management VLAN  

### Answer: C. Native VLAN

Explanation:

The native VLAN is specifically used for untagged trunk frames.
