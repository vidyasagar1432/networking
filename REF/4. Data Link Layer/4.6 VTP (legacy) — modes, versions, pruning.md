**CCNP ENCOR Relevance: Yes — VTP knowledge is useful for enterprise switching troubleshooting, but modern enterprise networks commonly avoid VTP due to operational risks.**

# 1. Overview

VTP (VLAN Trunking Protocol) is a Cisco proprietary Layer 2 protocol used to distribute VLAN database information between switches over trunk links. CCNA tests VTP modes, versions, pruning behavior, and why VTP is often disabled in modern networks.

---

# 2. Core Concepts

# What is VTP?

## Definition

VTP allows Cisco switches to synchronize VLAN information from one switch to other switches in the same VTP domain.

Example:

```
              Trunk

Switch A  =================  Switch B

Create VLAN 10
        |
        v
VLAN 10 learned by Switch B
```

---

# VTP Purpose

| Purpose | Description |
|---|---|
| VLAN database synchronization | Shares VLAN information |
| Centralized VLAN management | Reduces manual configuration |
| Reduces configuration errors | Automatic VLAN distribution |

---

# VTP Characteristics

| Feature | Value |
|---|---|
| Vendor | Cisco proprietary |
| Layer | Layer 2 |
| Protocol | Ethernet frames |
| Transport | Trunk links |
| Uses | VLAN database synchronization |
| Requires | Same VTP domain |

---

# VTP Requirements

For switches to exchange VTP information:

| Requirement | Description |
|---|---|
| Same VTP domain name | Required |
| Trunk connection | Required |
| Compatible VTP version | Required |
| VTP password | Must match if configured |

---

# VTP Domain

## Definition

A VTP domain is a group of Cisco switches sharing VLAN information.

Example:

```
VTP Domain: COMPANY

Switch A
Switch B
Switch C
```

All switches belong to:

```
COMPANY
```

---

# VTP Advertisement

VTP uses advertisements to distribute VLAN changes.

Example:

Administrator creates:

```
VLAN 50
```

Server sends update:

```
VTP Advertisement
        |
        v
Other switches update VLAN database
```

---

# VTP Advertisement Types

| Type | Purpose |
|---|---|
| Summary Advertisement | Sends VLAN database summary |
| Subset Advertisement | Sends VLAN changes |
| Advertisement Request | Requests VLAN information |

---

# VTP Revision Number

## Definition

A revision number tracks VLAN database changes.

Higher revision number:

```
Newer VLAN database
```

---

# VTP Revision Number Risk

Example:

```
New switch added

Revision number:
500

Existing network:
Revision number:
10
```

Result:

```
New switch database may overwrite existing VLAN database
```

---

# VTP Modes

Cisco supports three main VTP modes:

| Mode | Function |
|---|---|
| Server | Creates and modifies VLANs |
| Client | Receives VLAN updates |
| Transparent | Does not synchronize VLAN database |

---

# VTP Server Mode

## Definition

Default VTP mode on many Cisco switches.

Capabilities:

| Feature | Supported |
|---|---|
| Create VLANs | Yes |
| Delete VLANs | Yes |
| Modify VLANs | Yes |
| Send advertisements | Yes |
| Receive advertisements | Yes |
| Save VLAN database | Yes |

---

# VTP Client Mode

## Definition

A switch that receives VLAN information from a VTP server.

Capabilities:

| Feature | Supported |
|---|---|
| Create VLANs | No |
| Delete VLANs | No |
| Modify VLANs | No |
| Receive updates | Yes |
| Send updates | Yes |

---

# VTP Transparent Mode

## Definition

A switch that maintains its own VLAN database and does not synchronize VLAN information.

Capabilities:

| Feature | Supported |
|---|---|
| Create VLANs | Yes |
| Modify VLANs | Yes |
| Receive advertisements | No |
| Forward VTP advertisements | Yes |

---

# VTP Modes Comparison

| Feature | Server | Client | Transparent |
|---|---|---|---|
| Create VLAN | Yes | No | Yes |
| Store VLAN database | Yes | Yes | Yes |
| Send advertisements | Yes | Yes | Forwards only |
| Learn VLANs | Yes | Yes | No |
| Independent VLAN config | No | No | Yes |

---

# VTP Mode Behavior

Example:

```
        VLAN 10 created

             |
             v

      VTP Server Switch

             |
          Trunk

             |
             v

      VTP Client Switch

        VLAN 10 appears
```

Modern VTP version.

# VTP Pruning

## Definition

VTP pruning prevents unnecessary broadcast and unknown unicast traffic from traveling across trunks where the VLAN does not exist.

---

# Without VTP Pruning

Example:

```
VLAN 10 exists only on Switch A

Broadcast
    |
    |
Trunk
    |
    |
Switch B

(No VLAN 10 users)
```

Traffic is unnecessary.

---

# With VTP Pruning

```
VLAN 10 broadcast

Switch A
    |
    X
    |
Switch B

Blocked because VLAN 10 not needed
```

---

# VTP Pruning Benefits

| Benefit | Description |
|---|---|
| Saves bandwidth | Removes unnecessary traffic |
| Reduces broadcasts | Limits flooding |
| Improves scalability | Better large networks |

---

# VTP Pruning Rules

| Rule | Description |
|---|---|
| Works on trunks | Yes |
| Affects access ports | No |
| Applies to VLAN traffic | Yes |
| Default status | Disabled |

---

# VTP Pruning Example

Network:

```
Switch A
 VLAN 10 users

        |
      Trunk

        |

Switch B
 No VLAN 10 users
```

Without pruning:

```
Broadcast forwarded
```

With pruning:

```
Broadcast blocked
```

---

# VTP Security Issues

## VLAN Database Overwrite

Problem:

```
New switch
VTP Server mode
High revision number
```

Can overwrite VLAN database.

---

# VTP Best Practices

| Practice | Reason |
|---|---|
| Use transparent mode | Avoid unwanted changes |
| Disable VTP if not required | Reduce risk |
| Reset revision number before adding switches | Prevent overwrite |
| Use VTP v3 if required | Better security |

# 3. Worked Examples

## Example 1: Identify VTP Mode

### Scenario

A switch:

- Receives VLAN updates
- Cannot create VLANs locally

What VTP mode is it?

---

### Solution

Step 1:

Cannot create VLANs:

```
Not Server
Not Transparent
```

Step 2:

Receives VLAN updates:

```
Client behavior
```

Answer:

```
VTP Client mode
```

---

## Example 2: VTP Revision Problem

### Scenario

A new switch is connected to the network.

New switch:

```
Revision number: 200
```

Existing network:

```
Revision number: 20
```

What can happen?

---

### Solution

Step 1:

VTP trusts higher revision numbers.

Step 2:

New switch has newer revision.

Step 3:

It may overwrite the VLAN database.

Answer:

```
VTP revision number mismatch problem
```

Fix:

Reset VTP information before connecting.

# 5. Exam Traps

- VTP is Cisco proprietary.
- VTP advertisements travel over trunk links.
- VTP server creates VLANs.
- VTP client cannot create VLANs.
- Transparent mode does not learn VLAN information.
- VTP pruning reduces unnecessary broadcast traffic.
- VTP revision number determines database updates.
- A higher revision number can overwrite VLAN information.
- VTP v3 supports extended VLANs.
- Modern networks often use transparent mode or disable VTP.
- VTP does not carry user traffic; it carries VLAN information.

# 7. Practice Questions

## Question 1

Which VTP mode can create VLANs locally?

A. Client  
B. Server  
C. Disabled  
D. None  

### Answer: B. Server

Explanation:

VTP servers create and modify VLAN databases.

---

## Question 2

Which VTP mode does not synchronize VLAN information?

A. Server  
B. Client  
C. Transparent  
D. Primary  

### Answer: C. Transparent

Explanation:

Transparent switches maintain their own VLAN database.

---

## Question 3

What does VTP pruning reduce?

A. VLAN creation  
B. Broadcast traffic over trunks  
C. MAC learning  
D. IP routing  

### Answer: B. Broadcast traffic over trunks

Explanation:

Pruning removes unnecessary VLAN traffic from trunks.

---

## Question 4

Which command displays VTP status?

A. show vlan  
B. show vtp status  
C. show trunk  
D. show mac table  

### Answer: B. show vtp status

Explanation:

This command shows VTP mode, version, and revision.

---

## Question 5

Which VTP version supports extended VLANs?

A. VTP v1  
B. VTP v2  
C. VTP v3  
D. None  

### Answer: C. VTP v3

Explanation:

VTP v3 supports VLANs 1006-4094 and improves security.
