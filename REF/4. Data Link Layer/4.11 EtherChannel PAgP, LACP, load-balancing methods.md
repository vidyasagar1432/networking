# 1. Overview

EtherChannel combines multiple physical Ethernet links into one logical link to increase bandwidth and provide redundancy between switches. CCNA tests EtherChannel protocols (PAgP and LACP), negotiation modes, configuration requirements, and traffic load-balancing methods.

---

# 2. Core Concepts

# What is EtherChannel?

## Definition

EtherChannel bundles multiple physical interfaces into a single logical interface called a Port-Channel.

Example:

```
Before:

Switch A                 Switch B

Gi0/1 ------------------ Gi0/1
Gi0/2 ------------------ Gi0/2
Gi0/3 ------------------ Gi0/3


After:

Switch A                 Switch B

       Port-Channel 1
=========================
  Gi0/1
  Gi0/2
  Gi0/3
```

---

# EtherChannel Benefits

| Benefit | Description |
|---|---|
| Increased bandwidth | Combines multiple links |
| Redundancy | Link failure does not stop traffic |
| STP improvement | STP sees one logical link |
| Simplified management | Configure one logical interface |

---

# EtherChannel Characteristics

| Feature | Value |
|---|---|
| Layer | Layer 2 or Layer 3 |
| Logical interface | Port-Channel |

| STP view | One logical link |

# EtherChannel Protocols

Two negotiation protocols:

| Protocol | Vendor | Standard |
|---|---|---|
| PAgP | Cisco proprietary | No |
| LACP | IEEE 802.3ad | Yes |

---

# PAgP (Port Aggregation Protocol)

## Definition

PAgP is Cisco proprietary protocol used to automatically form EtherChannel links.

---

# PAgP Modes

| Mode | Behavior |
|---|---|
| Desirable | Actively negotiates |
| Auto | Passively waits |

---

# PAgP Negotiation

| Side A | Side B | Result |
|---|---|---|
| Desirable | Desirable | Forms EtherChannel |
| Desirable | Auto | Forms EtherChannel |
| Auto | Auto | Does not form |

---

# LACP (Link Aggregation Control Protocol)

## Definition

LACP is an IEEE standard protocol used to create EtherChannel.

Standard:

```
IEEE 802.3ad
```

---

# LACP Modes

| Mode | Behavior |
|---|---|
| Active | Actively negotiates |
| Passive | Waits for negotiation |

---

# LACP Negotiation

| Side A | Side B | Result |
|---|---|---|
| Active | Active | Forms EtherChannel |
| Active | Passive | Forms EtherChannel |
| Passive | Passive | Does not form |

---

# PAgP vs LACP

| Feature | PAgP | LACP |
|---|---|---|
| Vendor | Cisco | IEEE |
| Standard | No | Yes |
| Modes | Auto/Desirable | Active/Passive |
| Multi-vendor | No | Yes |
| Common modern use | Less | More |

---

# EtherChannel Mode Comparison

| Protocol | Active Mode | Passive Mode |
|---|---|---|
| PAgP | Desirable | Auto |
| LACP | Active | Passive |

# Port-Channel Interface

After creating EtherChannel:

Physical ports:

```
Gi0/1
Gi0/2
Gi0/3
```

Become:

```
Po1
```

Configuration should normally be applied to:

```
interface port-channel 1
```

---

# EtherChannel Load Balancing

## Definition

EtherChannel distributes traffic across member links using a hashing algorithm.

Important:

It does NOT send packets randomly.

---

# Load-Balancing Methods

Traffic selection can use:

| Method | Based On |
|---|---|
| Source MAC | Source MAC address |
| Destination MAC | Destination MAC address |
| Source + Destination MAC | Both MACs |
| Source IP | Source IP address |
| Destination IP | Destination IP address |
| Source + Destination IP | Both IPs |
| Port numbers | TCP/UDP ports |

---

# Cisco Default Load Balance

Typical Cisco switches:

```
Source MAC address
```

---

# Load Balancing Example

Topology:

```
PC-A
 |
Switch
 |
EtherChannel
 |
Server
```

Hash:

```
Source MAC
```

PC-A traffic always selects:

```
One member link
```

---

# Important Load Balancing Rule

A single flow usually uses one physical link.

Example:

```
File transfer A
       |
       v
Link 1
```

Another flow:

```
File transfer B
       |
       v
Link 2
```

---

# EtherChannel and STP

Without EtherChannel:

```
Link 1
Link 2
Link 3
```

STP may block two links.

---

With EtherChannel:

```
Port-Channel 1

Link 1
Link 2
Link 3
```

STP sees:

```
One logical link
```

All links can forward traffic.

# EtherChannel Configuration

## LACP Configuration Example

Create EtherChannel:

```bash
interface range gigabitEthernet 0/1 - 2
```

```bash

```

# 3. Worked Examples

## Example 1: LACP Negotiation

### Scenario

Two switches are configured:

Switch A:

```
LACP active
```

Switch B:

```
LACP passive
```

Will EtherChannel form?

---

### Solution

Step 1:

Check modes.

```
Active + Passive
```

Step 2:

LACP allows one side to actively negotiate.

Step 3:

Result:

```
EtherChannel forms
```

Answer:

```
Yes, LACP EtherChannel is created.
```

---

## Example 2: PAgP Negotiation

### Scenario

Two switches:

Switch A:

```
PAgP auto
```

Switch B:

```
PAgP auto
```

Will EtherChannel form?

---

### Solution

Step 1:

Both sides are passive.

```
Auto + Auto
```

Step 2:

No side starts negotiation.

Step 3:

Result:

```
No EtherChannel
```

Fix:

Change one side:

```
desirable
```

# 5. Exam Traps

- EtherChannel combines links into one logical interface.
- STP sees EtherChannel as one link.
- LACP is IEEE standard.
- PAgP is Cisco proprietary.
- LACP active + passive works.
- LACP passive + passive does not work.
- PAgP desirable + auto works.
- PAgP auto + auto does not work.
- Member interfaces must have identical configurations.
- Load balancing is based on hashing, not round-robin.
- One conversation usually uses one physical link.
- Configure settings on the Port-Channel interface.

# 7. Practice Questions

## Question 1

Which protocol is an IEEE standard for EtherChannel?

A. PAgP  
B. LACP  
C. DTP  
D. VTP  

### Answer: B. LACP

Explanation:

LACP is IEEE 802.3ad standard.

---

## Question 2

Which combination forms a PAgP EtherChannel?

A. Auto + Auto  
B. Desirable + Auto  
C. Passive + Passive  
D. Active + Passive  

### Answer: B. Desirable + Auto

Explanation:

PAgP requires at least one side in desirable mode.

---

## Question 3

What does STP see when EtherChannel is configured?

A. Multiple links  
B. One logical link  
C. No link  
D. Blocked links only  

### Answer: B. One logical link

Explanation:

The Port-Channel appears as a single STP interface.

---

## Question 4

Which command verifies EtherChannel status?

A. show vlan  
B. show etherchannel summary  
C. show spanning-tree  
D. show cdp neighbor  

### Answer: B. show etherchannel summary

Explanation:

It shows channel groups and member ports.

---

## Question 5

How does EtherChannel distribute traffic?

A. Random selection  
B. Round robin  
C. Hash algorithm  
D. Broadcast forwarding  

### Answer: C. Hash algorithm

Explanation:

Cisco uses hashing based on MAC/IP/port information.
