# NAT Policy Configuration on Firewalls

## CCNP Enterprise (ENCOR 350-401) Security & Enterprise Networking

**CCNA Relevance:** NAT/PAT fundamentals and firewall NAT basics.  
**CCNP ENCOR Relevance:** High — Understanding firewall NAT policies, processing order, bidirectional traffic flow, NAT troubleshooting, and enterprise NAT design is essential.

---

# 1. Overview

Most enterprise firewalls perform **Network Address Translation (NAT)** in addition to filtering traffic.

NAT allows:

- Private IP addresses to communicate with the Internet
- Public services to be published securely
- Address conservation
- Overlapping network support
- Hybrid cloud connectivity

Unlike routers, firewalls integrate NAT with:

- Security policies
- Session tracking
- Zones
- VPNs
- Routing

---

# 2. Why NAT on Firewalls?

Instead of deploying a separate router for NAT, enterprise firewalls combine:

```
Internet

      |

 Firewall

+------------+

| NAT        |

| Security   |

| VPN        |

| IPS        |

+------------+

      |

 Internal LAN
```

This simplifies security and policy enforcement.

---

# 3. Basic NAT Flow

```
PC

10.1.1.10

↓

Firewall

↓

NAT

↓

203.0.113.5

↓

Internet
```

The firewall replaces the source IP before forwarding the packet.

---

# 4. NAT Terminology

| Term | Description |
|------|-------------|
| Inside Local | Private IP address |
| Inside Global | Public IP after NAT |
| Outside Local | Remote address as seen internally |
| Outside Global | Actual public destination |

Example:

```
Inside Local

10.1.1.10

↓

NAT

↓

Inside Global

203.0.113.5
```

---

# 5. Types of NAT

Enterprise firewalls commonly support:

- Static NAT
- Dynamic NAT
- Dynamic PAT (Overload)
- Policy NAT
- Twice NAT (platform dependent)
- Identity NAT (NAT Exemption)

---

# 6. Static NAT

One private address maps to one public address.

```
10.1.1.20

↓

203.0.113.20
```

Commonly used for:

- Web servers
- Mail servers
- VPN gateways

---

# 7. Static NAT Example

```
Internet

↓

203.0.113.20

↓

Firewall

↓

10.1.1.20

↓

Web Server
```

External users connect to the public address.

---

# 8. Dynamic NAT

Dynamic NAT uses a pool of public addresses.

```
Private Hosts

↓

NAT Pool

↓

203.0.113.10

203.0.113.11

203.0.113.12
```

Each session receives an available public IP.

---

# 9. Dynamic PAT (Overload)

PAT allows multiple hosts to share one public IP by translating source ports.

```
10.1.1.10:52344

↓

203.0.113.5:40001

--------------------

10.1.1.11:52345

↓

203.0.113.5:40002
```

This is the most common Internet access method.

---

# 10. Static vs Dynamic vs PAT

| Feature | Static NAT | Dynamic NAT | PAT |
|----------|------------|-------------|-----|
| One-to-One | Yes | Temporary | No |
| Uses Port Translation | No | No | Yes |
| Conserves Public IPs | No | Limited | Yes |
| Internet Access | Yes | Yes | Yes |
| Public Servers | Yes | Possible | Usually No |

---

# 11. Policy NAT

Policy NAT translates traffic only when specified conditions match.

Conditions may include:

- Source zone
- Destination zone
- Source subnet
- Destination subnet
- Service
- Interface

Example:

```
Only

HR

↓

Internet

↓

Translate
```

---

# 12. Example Policy NAT

```
Source

10.10.0.0/16

↓

Destination

Internet

↓

Translate

-------------------

Destination

VPN

↓

Do Not Translate
```

Different destinations result in different NAT actions.

---

# 13. Identity NAT (NAT Exemption)

Identity NAT leaves the IP address unchanged.

```
10.1.1.10

↓

Identity NAT

↓

10.1.1.10
```

Commonly used for:

- VPN traffic
- Internal routing
- Hybrid cloud connections

---

# 14. Why Identity NAT?

Without NAT exemption:

```
VPN Traffic

↓

Translated

↓

Tunnel Fails
```

With Identity NAT:

```
VPN Traffic

↓

Original Address

↓

Tunnel Works
```

---

# 15. Twice NAT (Policy-Based NAT)

Some firewalls (such as Cisco ASA/FTD) support **Twice NAT**, allowing translation of:

- Source
- Destination
- Both

Example:

```
Source

10.1.1.10

↓

203.0.113.5

Destination

172.16.1.20

↓

198.51.100.20
```

Useful for overlapping address spaces and advanced policy requirements.

---

# 16. Destination NAT (DNAT)

Destination NAT changes the destination IP address.

```
Internet

↓

203.0.113.20

↓

Firewall

↓

10.1.1.20

↓

Web Server
```

Used to publish internal services.

---

# 17. Source NAT (SNAT)

Source NAT changes the source IP.

```
Client

↓

Firewall

↓

203.0.113.5

↓

Internet
```

Common for outbound Internet access.

---

# 18. Port Forwarding

A form of destination NAT.

```
203.0.113.5:443

↓

10.1.1.20:443
```

External users access the internal server through the firewall.

---

# 19. NAT Table

Example:

| Private | Public | Protocol |
|----------|--------|----------|
|10.1.1.10|203.0.113.5|TCP|
|10.1.1.11|203.0.113.5|TCP|
|10.1.1.12|203.0.113.5|UDP|

The firewall tracks translations for each session.

---

# 20. Session Table

```
Client

↓

Session Created

↓

NAT Applied

↓

Return Traffic

↓

Reverse Translation

↓

Client
```

Stateful firewalls use both the session table and NAT table.

---

# 21. NAT with Security Policies

Typical processing:

```
Packet

↓

Routing Lookup

↓

NAT Evaluation

↓

Security Policy

↓

Forward
```

> **Important:** The exact order of routing, NAT, and policy evaluation varies by firewall platform (Cisco ASA, Cisco FTD, Palo Alto, etc.) and software version.

---

# 22. Cisco ASA NAT

Cisco ASA supports:

- Auto NAT (Object NAT)
- Manual NAT (Twice NAT)
- Identity NAT
- Static NAT
- Dynamic NAT
- PAT

Manual (Twice) NAT provides the greatest flexibility and is evaluated before Auto NAT in ASA's NAT processing order.

---

# 23. Cisco FTD NAT

Cisco FTD provides:

- Auto NAT
- Manual NAT
- Dynamic PAT
- Static NAT
- Identity NAT

Policies are managed through **Cisco Secure Firewall Management Center (FMC)** or **Firewall Device Manager (FDM)**.

---

# 24. Palo Alto NAT

Palo Alto uses **NAT Policies**.

Policies match on:

- Source Zone
- Destination Zone
- Source Address
- Destination Address
- Service

Actions include:

- Source NAT
- Destination NAT
- No NAT

---

# 25. Cloud NAT

Cloud environments also use NAT.

Examples:

AWS:

```
Private Subnet

↓

NAT Gateway

↓

Internet
```

Azure:

```
Private Subnet

↓

NAT Gateway

↓

Internet
```

These services primarily provide outbound Internet connectivity for private resources.

---

# 26. NAT and VPN

Enterprise VPNs usually require:

```
VPN Traffic

↓

Identity NAT

↓

Tunnel
```

If traffic is translated unexpectedly, the VPN may fail.

---

# 27. Overlapping Networks

Example:

```
Branch A

10.1.1.0/24

Branch B

10.1.1.0/24
```

Policy NAT or Twice NAT can translate one side to avoid conflicts.

# 28. NAT Troubleshooting

## No Internet Access

Check:

- NAT policy
- Default route
- Security policy
- Public IP availability
- Interface status

---

## Public Server Unreachable

Verify:

- Static NAT
- Destination NAT
- Security policy
- Public DNS
- Firewall logs

---

## VPN Fails

Check:

- Identity NAT
- Crypto ACL / Traffic Selectors
- Route lookup
- Tunnel status

---

## Wrong Address Translation

Verify:

- NAT rule order
- Source zone
- Destination zone
- Matching conditions
- Route selection

---

# 29. Best Practices

- Use **PAT** for general outbound Internet access.
- Use **Static NAT** for publicly accessible servers.
- Configure **Identity NAT** for VPN traffic when required.
- Keep NAT policies simple and well documented.
- Place specific NAT rules before general rules.
- Monitor NAT translation tables and logs.
- Remove unused NAT entries.
- Test changes in maintenance windows.

---

# CCNP Exam Traps

- **Static NAT** provides a permanent **1:1** mapping.
- **Dynamic NAT** uses a **pool** of public addresses.
- **PAT (Overload)** allows many private hosts to share one public IP by translating source ports.
- **Identity NAT** (NAT Exemption) is commonly used for **VPN traffic**.
- **Destination NAT (DNAT)** publishes internal services by changing the destination address.
- **Source NAT (SNAT)** changes the source address for outbound traffic.
- **Twice NAT** can translate both **source** and **destination** addresses.
- The order of **NAT**, **routing**, and **security policy** evaluation is **platform-dependent**—know the behavior of the specific firewall you're configuring.
