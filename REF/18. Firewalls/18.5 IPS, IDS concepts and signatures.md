# Intrusion Detection Systems (IDS), Intrusion Prevention Systems (IPS), and Signatures

## CCNP Enterprise (ENCOR 350-401) Security Fundamentals

**CCNA Relevance:** Basic IDS/IPS concepts.  
**CCNP ENCOR Relevance:** High — Understanding IDS/IPS architecture, detection methods, signatures, threat prevention, deployment models, and tuning is essential for enterprise security.

---

# 1. Overview

Firewalls primarily control **who can communicate**.

An **IDS (Intrusion Detection System)** and **IPS (Intrusion Prevention System)** determine **whether the traffic itself is malicious**.

They analyze packets, sessions, and application data to detect or stop attacks.

---

# 2. Why IDS/IPS?

Even if a firewall allows traffic, it may contain:

- Malware
- Exploits
- Viruses
- Worms
- Ransomware
- SQL Injection
- Cross-Site Scripting (XSS)
- Command-and-Control (C2) traffic

IDS/IPS provide deeper inspection beyond simple access control.

---

# 3. Firewall vs IDS vs IPS

```
Internet

        |

    Firewall

        |

      IDS

        |

      IPS

        |

Internal Network
```

In many modern deployments, IPS functionality is integrated into a **Next-Generation Firewall (NGFW)**.

---

# 4. What Is an IDS?

An **Intrusion Detection System (IDS)** monitors network traffic and generates alerts when suspicious activity is detected.

It **does not block** traffic.

```
Traffic

↓

IDS

↓

Threat Detected

↓

Alert
```

---

# 5. IDS Characteristics

| Feature | Value |
|----------|-------|
| Monitors Traffic | Yes |
| Blocks Traffic | No |
| Generates Alerts | Yes |
| Passive | Yes |
| Network Impact | Low |

---

# 6. What Is an IPS?

An **Intrusion Prevention System (IPS)** monitors traffic and can actively stop malicious activity.

```
Traffic

↓

IPS

↓

Threat Detected

↓

Drop Packet

or

Reset Session

or

Alert
```

---

# 7. IPS Characteristics

| Feature | Value |
|----------|-------|
| Monitors Traffic | Yes |
| Blocks Traffic | Yes |
| Generates Alerts | Yes |
| Inline Device | Yes |
| Active Protection | Yes |

---

# 8. IDS vs IPS

| Feature | IDS | IPS |
|----------|-----|-----|
| Detects Attacks | Yes | Yes |
| Blocks Attacks | No | Yes |
| Inline | No | Yes |
| Generates Alerts | Yes | Yes |
| Can Drop Packets | No | Yes |
| Risk of Blocking Legitimate Traffic | Low | Higher (if poorly tuned) |

# 10. Detection Methods

IDS/IPS can use:

- Signature-Based Detection
- Anomaly-Based Detection
- Behavior-Based Detection
- Reputation-Based Detection

Many enterprise solutions combine multiple techniques.

---

# 11. Signature-Based Detection

A **signature** is a known pattern that identifies malicious traffic.

```
Packet

↓

Compare

↓

Known Signature?

↓

Yes

↓

Alert / Block
```

---

# 12. Example Signature

Known attack:

```
SQL Injection

OR 1=1
```

If traffic matches the signature:

```
↓

Threat

↓

Blocked
```

---

# 13. Signature Database

The IPS maintains a database of known attack patterns.

```
IPS

↓

Signature Database

↓

Threat Match

↓

Action
```

Regular updates are essential to detect newly discovered threats.

---

# 14. Signature Update Process

```
Vendor

↓

Threat Intelligence

↓

Updated Signatures

↓

Firewall / IPS
```

Keeping signatures current is a critical security practice.

---

# 15. Anomaly-Based Detection

Instead of matching known signatures:

```
Normal Traffic

↓

Baseline

↓

Abnormal Activity

↓

Alert
```

Useful for detecting unknown or zero-day attacks, but may generate more false positives.

---

# 16. Behavior-Based Detection

Monitors long-term behavior.

Example:

```
Normal User

↓

100 DNS Queries

----------------

Compromised Host

↓

20,000 DNS Queries

↓

Alert
```

---

# 17. Reputation-Based Detection

Traffic is compared against threat intelligence.

```
Connection

↓

Known Malicious IP?

↓

Yes

↓

Block
```

---

---

# 21. False Positives

A **False Positive** occurs when:

```
Normal Traffic

↓

Detected As Attack
```

Example:

A legitimate application triggers a generic SQL Injection signature.

---

# 22. False Negatives

A **False Negative** occurs when:

```
Actual Attack

↓

Not Detected
```

Usually caused by:

- Missing signatures
- Encrypted traffic (without decryption)
- Misconfiguration
- New or unknown attack techniques

---

# 23. IDS/IPS Tuning

Administrators often:

- Disable unnecessary signatures
- Adjust sensitivity
- Create exceptions
- Reduce false positives
- Add custom signatures (where supported)

Proper tuning improves accuracy and performance.

---

# 24. Deep Packet Inspection (DPI)

IPS analyzes:

```
Packet Header

+

Payload
```

This allows inspection beyond Layer 3 and Layer 4.

---

# 25. SSL/TLS Inspection

Encrypted traffic cannot be fully inspected unless decrypted.

```
HTTPS

↓

Decrypt

↓

Inspect

↓

Encrypt

↓

Forward
```

Without decryption, inspection is limited to visible metadata.

# 26. Cisco IPS

Modern Cisco Secure Firewall (FTD) includes integrated IPS capabilities.

- Snort Inspection Engine
- Threat Intelligence

# 27. Snort

**Snort** is one of the world's most widely used intrusion detection and prevention engines.

Capabilities:

- Signature-based detection
- Protocol analysis
- Packet logging
- Custom rule support

It is the inspection engine used in Cisco Secure Firewall.

Palo Alto integrates:

- URL Filtering

These features work together to inspect traffic.

# 30. Logging

IPS events commonly include:

- Timestamp
- Source IP
- Destination IP
- Signature Name
- Severity
- Action Taken
- Interface
- User (if known)

Logs are often forwarded to SIEM platforms.

---

# 31. Best Practices

- Keep signatures up to date.
- Enable IPS on Internet-facing traffic.
- Tune signatures to reduce false positives.
- Monitor logs regularly.
- Inspect encrypted traffic where appropriate and compliant.
- Integrate with SIEM for centralized monitoring.
- Test policy changes before production deployment.

# CCNP Exam Traps

- **IDS** is **passive**—it detects and alerts but does **not** block traffic.
- **IPS** is **inline**—it can detect and actively prevent attacks.
- **Signature-based detection** identifies **known attacks** using predefined patterns.
- **Anomaly-based detection** compares traffic against a baseline to identify unusual behavior.
- **Behavior-based detection** looks for suspicious activity over time.
- **Reputation-based detection** uses threat intelligence to identify known malicious sources.
- **False positives** incorrectly identify legitimate traffic as malicious.
- **False negatives** fail to detect actual attacks.
- Encrypted traffic often requires **SSL/TLS inspection** for full IPS analysis.
