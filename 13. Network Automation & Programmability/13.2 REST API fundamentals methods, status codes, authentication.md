# 1. Overview

REST API (Representational State Transfer Application Programming Interface) allows software applications to communicate with network devices, controllers, and services using standard HTTP methods. Modern Cisco platforms such as Cisco DNA Center, Meraki, and SD-WAN controllers use REST APIs for network automation and management.

REST APIs commonly exchange data using JSON or XML formats.

# 6. HTTP Methods (CRUD Operations)

REST APIs commonly use CRUD operations.

| Operation | HTTP Method | Purpose |
|---|---|---|
| Create | POST | Create new object |
| Read | GET | Retrieve information |
| Update | PUT | Replace existing object |
| Modify | PATCH | Partial update |
| Delete | DELETE | Remove object |

---

# 7. GET Method

## Purpose

Retrieve information.

---

Example:

Request:

```
GET /devices
```

Response:

```json
{
 "device": "R1",
 "status": "online"
}
```

---

Used for:

- Viewing devices
- Reading configurations
- Checking status

---

# 8. POST Method

## Purpose

Create new resources.

---

Example:

```
POST /interfaces
```

Body:

```json
{
 "name":"Gig0/1",
 "description":"LAN Interface"
}
```

---

Used for:

- Creating VLANs
- Adding users
- Deploying configurations

---

# 9. PUT Method

## Purpose

Replace an existing resource.

Example:

```
PUT /device/R1
```

Body:

```json
{
 "hostname":"Router-New"
}
```

---

Difference:

PUT:

```
Replace complete object
```

---

# 10. PATCH Method

## Purpose

Modify part of an object.

Example:

Current:

```json
{
 "hostname":"R1",
 "location":"Delhi"
}
```

PATCH:

```json
{
 "location":"Hyderabad"
}
```

Only location changes.

---

# 11. DELETE Method

## Purpose

Remove a resource.

Example:

```
DELETE /vlan/20
```

Removes:

```
VLAN 20
```

# 13. HTTP Status Codes

HTTP responses contain status codes indicating success or failure.

---

# Status Code Categories

| Range | Meaning |
|---|---|
| 1xx | Information |
| 2xx | Success |
| 3xx | Redirection |
| 4xx | Client error |
| 5xx | Server error |

---

# 14. Common 2xx Success Codes

| Code | Meaning |
|---|---|
| 200 OK | Request successful |
| 201 Created | Resource created |
| 202 Accepted | Request accepted |
| 204 No Content | Successful, no response data |

---

Example:

Create VLAN:

```
POST /vlans

201 Created
```

| Method | Description |

Uses:

```
Username + Password
```

Example:

HTTP Header:

```
Authorization: Basic <encoded-data>
```

---

Security:

Low unless used with:

```
HTTPS
```

# 19. API Key Authentication

Client sends:

```

```

---

Used for:

- Cloud services

# 20. Token Authentication

```

↓

Receive Token

↓

Use Token in Requests
```

---

Example:

Header:

```

```

# 21. OAuth Authentication

OAuth provides delegated authorization.

Used by:

- Cloud platforms
- Enterprise applications

Flow:

```

↓

Authorization Server

↓

Access Token

↓

API Request
```

- User permissions

- URL

# CCNA Exam Traps

- REST APIs commonly use HTTP/HTTPS.
- GET retrieves information.
- POST creates resources.
- PUT replaces resources.
- PATCH modifies part of a resource.
- DELETE removes resources.
- JSON is the most common REST data format.
- 200 means successful request.
- 201 means resource created.
- 401 means authentication failure.
- 403 means authorization failure.
- 404 means resource not found.
- HTTPS should be used to protect API communication.
