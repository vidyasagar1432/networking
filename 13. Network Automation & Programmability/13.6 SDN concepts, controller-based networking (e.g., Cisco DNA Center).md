# 1. Overview

Software-Defined Networking (SDN) is a networking architecture that separates the **control plane** from the **data plane**, allowing centralized software controllers to manage network devices. Instead of configuring each router and switch individually, administrators define policies that the controller automatically applies across the network.

Controller-based networking, such as Cisco DNA Center, enables intent-based networking (IBN), automation, analytics, and centralized network management.

---

# 2. Traditional Networking vs SDN

## Traditional Network Model

Each device operates independently.

```
Administrator

    |

    |

Router ---- Switch ---- Firewall

(Device-by-device configuration)
```

Characteristics:

- Distributed control
- Manual CLI configuration
- Device-by-device management
- Limited visibility

---

# SDN Model

Centralized controller manages devices.

```
              SDN Controller

                    |

        -------------------------

        |          |            |

     Router     Switch       Firewall

```

Characteristics:

- Centralized control
- Automation
- Policy-based management
- Network-wide visibility

---

# 3. Control Plane vs Data Plane

## Data Plane

Responsible for forwarding traffic.

Example:

```
Receive packet

↓

Check forwarding table

↓

Send packet
```

Functions:

- Packet forwarding
- Switching
- Routing decisions already learned

---

## Control Plane

Responsible for making decisions.

Functions:

- Routing protocol operation
- Building routing tables
- Network intelligence

Examples:

- OSPF
- BGP
- STP

---

# Traditional Device

```
+----------------+
| Control Plane  |
|                |
+----------------+
| Data Plane     |
|                |
+----------------+
```

Control and forwarding exist on the same device.

---

# SDN Device

```
        Controller

       Control Plane

            |

            |

        Network Device

         Data Plane
```

Control logic moves to controller.

SDN commonly has three layers:

```

        |

```

# 5. Application Layer

Contains applications that define network requirements.

Examples:

- Security policies
- QoS policies
- Traffic engineering
- Monitoring applications

---

Example:

Application says:

```
Video traffic needs priority
```

Controller translates this into device configurations.

---

# 6. Control Layer

Contains the SDN controller.

Responsibilities:

- Network intelligence
- Policy decisions
- Device management
- Automation

Examples:

- Cisco DNA Center
- OpenDaylight
- VMware NSX Controller

---

# 7. Infrastructure Layer

Contains physical and virtual devices.

Examples:

- Routers
- Switches
- Firewalls
- Access points

Responsible for:

```
Packet forwarding
```

# 8. SDN Communication Interfaces

SDN uses APIs for communication.

---

# Northbound APIs

Communication:

```
Application

        ↓

Controller
```

Used by:

- Applications
- Automation systems

Examples:

- REST API
- RESTCONF

---

# Southbound APIs

Communication:

```
Controller

        ↓

Network Devices
```

Used for device control.

Examples:

| Protocol | Purpose |
|---|---|
| NETCONF | Configuration |
| RESTCONF | API-based configuration |
| OpenFlow | Flow control |
| SNMP | Monitoring |

---

# Northbound vs Southbound

| Feature | Northbound | Southbound |
|---|---|---|
| Direction | Application → Controller | Controller → Device |
| Purpose | Policy/application communication | Device management |
| Example | REST API | NETCONF |

# 12. Intent-Based Networking (IBN)

## Definition

Intent-based networking allows administrators to describe what they want instead of manually configuring how to achieve it.

---

Traditional:

```
Configure VLAN

Configure ACL

Configure QoS

Configure Routing
```

---

Intent-based:

```
"Employees should access internal applications"

↓

Controller creates required configuration
```
