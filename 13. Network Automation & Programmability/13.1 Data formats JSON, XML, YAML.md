# 1. Overview

Data formats define how information is structured and exchanged between applications, devices, and APIs. Modern network automation relies heavily on structured data formats such as JSON, XML, and YAML for configuration, API communication, and automation workflows.

Cisco platforms, REST APIs, SDN controllers, and automation tools commonly use these formats.

---

# 2. What is Structured Data?

Structured data organizes information in a predictable format.

Example:

Human-readable:

```
Device Name: Router1
IP Address: 192.168.1.1
```

Structured format:

```json
{
  "device": "Router1",
  "ip": "192.168.1.1"
}
```

|---|---|---|
| JSON | JavaScript Object Notation | REST APIs, automation |
| XML | Extensible Markup Language | APIs, older systems, NETCONF |
| YAML | YAML Ain't Markup Language | Configuration files, automation |

# 4. JSON (JavaScript Object Notation)

## Definition

JSON is a lightweight text-based format used for storing and exchanging structured data.

Commonly used with:

- REST APIs
- Python automation
- Cisco DNA Center APIs
- Network controllers

---

# JSON Structure

Uses:

- Objects
- Key-value pairs
- Arrays

---

Example:

```json
{
  "hostname": "R1",
  "ip_address": "192.168.1.1",
  "interface": "GigabitEthernet0/0"
}
```

---

# JSON Components

| Component | Description |
|---|---|
| Object | Collection of key-value pairs |
| Key | Name/value identifier |
| Value | Data |
| Array | List of values |

---

# JSON Object

Example:

```json
{
  "vendor": "Cisco",
  "model": "C9300"
}
```

---

# JSON Array

Example:

```json
{
  "interfaces": [
    "Gig0/0",
    "Gig0/1",
    "Gig0/2"
  ]
}
```

---

# JSON Data Types

| Type | Example |
|---|---|
| String | `"Cisco"` |
| Number | `100` |
| Boolean | `true` |
| Null | `null` |
| Object | `{}` |
| Array | `[]` |

---

# JSON Rules

- Keys must use double quotes
- Data separated by commas
- Objects use `{ }`
- Arrays use `[ ]`

---

Valid:

```json
{
 "port": 443
}
```

---

Invalid:

```json
{
 port: 443
}
```

---

# JSON in Network Automation

Example API response:

```json
{
 "interface": "GigabitEthernet0/1",
 "status": "up",
 "speed": 1000
}
```

Automation script can read:

```
interface
status
speed
```

and configure devices automatically.

# 5. XML (Extensible Markup Language)

## Definition

XML is a markup-based data format that uses tags to represent information.

Common uses:

- NETCONF
- SOAP APIs
- Older management systems

---

# XML Structure

Example:

```xml
<router>
    <hostname>R1</hostname>
    <ip>192.168.1.1</ip>
</router>
```

---

# XML Components

| Component | Description |
|---|---|
| Tag | Defines data |
| Element | Complete data unit |
| Attribute | Additional information |

---

# XML Tags

Example:

```xml
<hostname>R1</hostname>
```

Parts:

```
<hostname>

Opening tag


R1

Value


</hostname>

Closing tag
```

---

# XML Attributes

Example:

```xml
<interface type="ethernet">
GigabitEthernet0/1
</interface>
```

Attribute:

```
type="ethernet"
```

---

# XML Characteristics

| Feature | Description |
|---|---|
| Human readable | Yes |
| Uses tags | Yes |
| More verbose | Yes |
| Supports hierarchy | Yes |

---

# XML Example: Network Configuration

```xml
<interface>
    <name>GigabitEthernet0/0</name>
    <ip-address>192.168.1.1</ip-address>
    <status>up</status>
</interface>
```

# 6. YAML (YAML Ain't Markup Language)

## Definition

YAML is a human-friendly data format commonly used for configuration files and automation tools.

Used in:

- Ansible
- Docker Compose
- Kubernetes
- CI/CD systems

---

# YAML Structure

Uses:

- Indentation
- Key-value pairs

Example:

```yaml
hostname: R1
ip_address: 192.168.1.1
interface: GigabitEthernet0/0
```

---

# YAML Rules

Important:

- Indentation matters
- Uses spaces, not tabs
- No brackets required
- Easy for humans to read

---

# YAML List Example

```yaml
interfaces:
  - GigabitEthernet0/0
  - GigabitEthernet0/1
```

---

# YAML Nested Data

Example:

```yaml
router:
  hostname: R1
  interfaces:
    - Gig0/0
    - Gig0/1
```

---

# 7. JSON vs XML vs YAML Comparison

| Feature | JSON | XML | YAML |
|---|---|---|---|
| Format type | Data format | Markup language | Data serialization |
| Readability | High | Medium | Very high |
| File size | Small | Large | Small |
| Syntax | Brackets | Tags | Indentation |
| Human friendly | Yes | Less | Yes |
| API usage | Very common | Common | Less common |
| Automation | Excellent | Good | Excellent |

# 12. Data Validation

Structured data must follow expected format.

Example:

Expected:

```json
{
 "interface": "Gig0/1"
}
```

Incorrect:

```json
{
 "interface_name": "Gig0/1"
}
```

Application may reject it.

---

# 13. Common Errors

## JSON Errors

Missing comma:

Incorrect:

```json
{
"name":"R1"
"ip":"10.0.0.1"
}
```

Correct:

```json
{
"name":"R1",
"ip":"10.0.0.1"
}
```

---

## YAML Errors

Wrong indentation:

Incorrect:

```yaml
router:
hostname: R1
```

Correct:

```yaml
router:
  hostname: R1
```
