# Multicast Basics: IGMP, PIM Dense Mode, and Sparse Mode

## CCNP Enterprise (ENCOR 350-401) Level

**CCNA Relevance: Basic multicast concepts and IGMP awareness are helpful.**  
**CCNP ENCOR Relevance: High — Multicast forwarding, IGMP, PIM modes, Rendezvous Points (RP), Reverse Path Forwarding (RPF), and multicast design are important enterprise topics.**

---

# 1. Overview

Traditional IP communication uses either:

- **Unicast** (one-to-one)
- **Broadcast** (one-to-all)

However, many applications need **one-to-many** communication without sending multiple copies of the same data. This is where **multicast** is used.

Multicast sends **one copy** of a packet from the sender, and the network duplicates it **only where necessary**, making it efficient for streaming and group communications.

---

# 2. Communication Types

| Type | Communication | Example |
|--------|--------------|----------|
| Unicast | One → One | Web browsing |
| Broadcast | One → All | ARP |
| Multicast | One → Many (Interested Receivers Only) | IPTV, Live Video |
| Anycast | One → Nearest | DNS Servers |

```

   |

```
              Sender

                 |

```

```

# 13. IGMP (Internet Group Management Protocol)

## Definition

IGMP is used between **hosts and routers** to manage multicast group membership.

Important:

IGMP **does not route multicast traffic**.

Its job is only to tell routers:

> "I want to receive multicast group X."

---

# 14. IGMP Operation

```
Host

↓

IGMP Join

↓

Router

↓

Adds Host

↓

Multicast Forwarding Begins
```

# 17. IGMP Leave

When a host no longer wants multicast traffic:

```
Host

↓

Leave Message

↓

Router

Stops Forwarding
```

---

# 18. IGMP Query

Routers periodically ask:

```
"Who still wants this group?"
```

Hosts reply if still interested.

# 19. IGMP Roles

| Device | Role |
|----------|------|

# 20. IGMP Snooping

Without IGMP Snooping:

```
Switch

↓

Floods Multicast

↓

Every Port
```

---

With IGMP Snooping:

```
Switch Learns

↓

Interested Ports

↓

Forward Only There
```

Benefits:

- Reduces flooding
- Conserves bandwidth
- Improves efficiency

---

# 21. Multicast Routing

Once hosts join a group:

Routers must transport multicast traffic.

This is done using:

```
PIM

Protocol Independent Multicast
```

---

# 22. PIM (Protocol Independent Multicast)

## Definition

PIM is the multicast routing protocol used between routers.

It is called "Protocol Independent" because it can work with any unicast routing protocol (OSPF, EIGRP, IS-IS, BGP, static routes, etc.).

PIM relies on the existing unicast routing table to make forwarding decisions.

---

# 23. Reverse Path Forwarding (RPF)

Before forwarding multicast traffic:

Router checks:

```
"Did this packet arrive on the correct interface toward the source?"
```

If:

```
Yes

↓

Forward
```

Otherwise:

```
Drop
```

This prevents routing loops.

---

# 24. RPF Example

```
Source

   |

 R1

   |

 R2

   |

 R3
```

If traffic reaches R3 through R2 (best path):

```
Passes RPF Check
```

If it arrives from another interface:

```
Fails RPF

↓

Dropped
```

# 26. PIM Dense Mode (PIM-DM)

## Concept

Dense Mode assumes:

> "Everyone wants multicast traffic."

Process:

```
Flood

↓

Prune

↓

Re-Flood

```

---

# 27. Dense Mode Operation

```
Source

↓

Flood

↓

Every Router Receives

↓

Routers Without Receivers

↓

Send Prune Messages
```

---

Example:

```
Source

 |

R1

/ \

R2 R3

 |

Receiver
```

Initially:

```
Traffic Everywhere
```

Later:

```
Unused Branches Pruned
```

---

# 28. Advantages of Dense Mode

- Simple
- No RP required
- Automatic flooding

---

Disadvantages:

- Wastes bandwidth
- Poor scalability
- Frequent flooding

---

Used only in:

- Small networks
- Lab environments

---

# 29. PIM Sparse Mode (PIM-SM)

## Concept

Sparse Mode assumes:

> "Nobody wants multicast unless they explicitly ask."

Routers receive traffic only after joining the multicast distribution tree.

---

# 30. Rendezvous Point (RP)

Sparse Mode introduces the:

```
RP

(Rendezvous Point)
```

The RP acts as a meeting point between:

- Source
- Receivers

---

# 31. Sparse Mode Architecture

```
Source

   |

   RP

  /  \

 R1  R2

 |    |

Host Host
```

---

Receivers send:

```
Join

↓

RP

↓

Traffic Starts
```

---

# 32. Sparse Mode Operation

Step 1

Receiver joins group.

↓

Step 2

Router sends PIM Join to RP.

↓

Step 3

Source registers with RP.

↓

Step 4

Traffic flows.

---

# 33. Shared Tree

Initially:

```
Source

↓

RP

↓

Receivers
```

Called:

```
Shared Tree

(*,G)
```

---

# 34. Shortest Path Tree (SPT)

Later:

Router may optimize traffic.

```
Receiver

↓

Direct Path

↓

Source
```

This is:

```
Shortest Path Tree

(S,G)
```

Benefits:

- Lower latency
- Better bandwidth utilization

---

# 35. Dense vs Sparse Mode

| Feature | Dense Mode | Sparse Mode |
|-----------|------------|-------------|
| Initial Action | Flood | Join |
| RP Required | No | Yes |
| Scalability | Poor | Excellent |
| Bandwidth Usage | High | Low |
| Enterprise Use | Rare | Common |

# 36. PIM Neighbor Discovery

Routers exchange:

```
Hello Messages
```

Used to:

- Discover neighbors
- Elect Designated Router (DR) on LANs
- Maintain adjacencies

---

# 37. Designated Router (DR)

On multi-access networks:

One router becomes the DR.

Responsibilities:

- IGMP processing
- Register source with RP
- Forward multicast traffic

---

# 38. Source-Specific Multicast (SSM)

Modern multicast deployment.

Instead of joining:

```
(*,G)
```

Receivers specify:

```
(S,G)
```

Example:

```
Source:

192.168.1.100

Group:

232.1.1.1
```

Advantages:

- No RP required
- Better security
- Better scalability

Uses:

```
IGMPv3
```

# 41. Best Practices

- Use **PIM Sparse Mode** in enterprise networks.
- Deploy redundant RPs for high availability.
- Enable **IGMP Snooping** on Layer 2 switches.
- Use **SSM (232.0.0.0/8)** for new multicast deployments.
- Monitor RPF failures.
- Avoid Dense Mode except for labs or very small networks.

---

# CCNP Exam Traps

- **IGMP** manages host membership; it does **not** route multicast traffic.
- **PIM** performs multicast routing between routers.
- PIM relies on the **unicast routing table** for RPF decisions.
- Dense Mode uses **Flood-and-Prune**.
- Sparse Mode uses **Explicit Joins** and an **RP**.
- The **RP** is required only for PIM Sparse Mode (not for Dense Mode or SSM).
- **RPF checks** prevent multicast loops.
- **IGMP Snooping** is a Layer 2 switch feature.
- **SSM** uses **IGMPv3** and eliminates the need for an RP.
