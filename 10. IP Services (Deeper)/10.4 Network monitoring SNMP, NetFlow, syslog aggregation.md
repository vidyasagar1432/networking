# 1. Overview

Network monitoring is the process of collecting, analyzing, and responding to information about network devices, traffic, and events. SNMP provides device health monitoring, NetFlow provides traffic visibility, and syslog aggregation collects centralized event logs for troubleshooting and security analysis.

# 3. SNMP (Simple Network Management Protocol)

## Definition

SNMP is a protocol used to monitor and manage network devices.

---

# SNMP Components

```
                SNMP Manager

                    |

                    |

              Network Device

              (SNMP Agent)
```

---

# Components

| Component | Function |
|---|---|
| SNMP Manager | Monitoring server |
| SNMP Agent | Software on device |
| MIB | Database of information |
| OID | Identifier for objects |

---

# SNMP Manager

Examples:

- Network monitoring server
- NMS (Network Management System)

Functions:

- Collect data
- Display graphs
- Generate alerts

---

# SNMP Agent

Runs on:

- Router
- Switch
- Firewall
- Server

Collects:

- CPU usage
- Memory
- Interface status
- Traffic counters

---

# MIB (Management Information Base)

## Definition

A database containing information that can be monitored.

---

Example MIB objects:

| Object | Information |
|---|---|
| Interface status | Up/down |
| CPU usage | Processor load |
| Memory | RAM usage |
| Bandwidth | Traffic counters |

---

# OID (Object Identifier)

## Definition

A unique identifier for a MIB object.

Example:

```
1.3.6.1.2.1.2.2
```

Represents:

```
Interface information
```

---

# SNMP Versions

| Version | Security |
|---|---|
| SNMPv1 | Community string only |
| SNMPv2c | Improved but still community string |
| SNMPv3 | Authentication + encryption |

---

# SNMPv1

Uses:

```
Community string
```

Example:

```
public
```

Problem:

Sent in plain text.

---

# SNMPv2c

Features:

- Better performance
- Bulk retrieval

Still uses:

```
Community strings
```

---

# SNMPv3

Provides:

```
Authentication

+

Encryption
```

---

# SNMPv3 Security Levels

| Level | Authentication | Encryption |
|---|---|---|
| noAuthNoPriv | No | No |
| authNoPriv | Yes | No |
| authPriv | Yes | Yes |

---

# SNMP Communication Methods

## 1. Polling

Manager requests information.

Example:

```
Manager

"What is CPU usage?"

      |

Device

"40%"
```

---

## 2. Trap

Device sends alert automatically.

Example:

```
Interface down

↓

SNMP Trap

↓

Manager
```

---

## 3. Inform

Similar to trap but requires acknowledgement.

---

# SNMP Ports

| Function | Protocol | Port |
|---|---|---|
| SNMP queries | UDP | 161 |
| SNMP traps | UDP | 162 |

---

# Cisco SNMP Configuration Example

Enable SNMP community:

```bash
snmp-server community public RO
```

Meaning:

```
Read-only access
```

---

Enable SNMP trap:

```bash
snmp-server enable traps
```

---

Configure SNMP host:

```bash
snmp-server host 192.168.1.50 public
```

---

# Verify SNMP

```bash
show snmp
```

# 4. NetFlow

## Definition

NetFlow collects information about network traffic flows.

---

# What NetFlow Answers

Examples:

- Who is using bandwidth?
- Which application consumes traffic?
- Where is traffic going?
- When did traffic occur?

---

# NetFlow Flow Definition

A flow is identified by:

```
Source IP

Destination IP

Source Port

Destination Port

Protocol
```

---

# NetFlow Example

Traffic:

```
PC

192.168.1.10

↓

YouTube

8.8.8.8

TCP 443
```

NetFlow records:

```
Source:
192.168.1.10

Destination:
8.8.8.8

Port:
443

Bytes:
500 MB
```

---

# NetFlow Components

```
Network Device

(NetFlow Exporter)

        |

        |

Collector

        |

        |

Analyzer
```

---

# Components

| Component | Function |
|---|---|
| Exporter | Creates flow records |
| Collector | Stores records |
| Analyzer | Displays reports |

---

# NetFlow Versions

| Version | Description |
|---|---|
| v5 | Traditional fixed fields |
| v9 | Flexible templates |
| IPFIX | Standardized NetFlow |

---

# NetFlow vs SNMP

| Feature | SNMP | NetFlow |
|---|---|---|
| Focus | Device health | Traffic details |
| Data | CPU/interface | Flows |
| Answers | Is device healthy? | Who uses bandwidth? |
| Collection | Polling | Flow export |

---

# NetFlow Configuration Concept

Enable flow monitoring:

```bash
ip flow ingress
```

Export:

```bash
ip flow-export destination 192.168.1.100 9996
```

# 5. Syslog

## Definition

Syslog is a protocol used to send device event messages to a centralized logging server.

---

# Syslog Architecture

```
Network Devices

Router
Switch
Firewall

      |

      |

 Syslog Server

      |

      |

 Administrator
```

---

# Syslog Message Format

Contains:

| Field | Meaning |
|---|---|
| Timestamp | When event occurred |
| Device | Source |
| Facility | Service generating message |
| Severity | Importance |
| Message | Event details |

---

# Syslog Severity Levels

Levels:

```
0 - Emergency

1 - Alert

2 - Critical

3 - Error

4 - Warning

5 - Notification

6 - Informational

7 - Debugging
```

---

# Severity Table

| Level | Name | Meaning |
|---|---|---|
| 0 | Emergency | System unusable |
| 1 | Alert | Immediate action |
| 2 | Critical | Critical condition |
| 3 | Error | Error condition |
| 4 | Warning | Warning |
| 5 | Notice | Normal but important |
| 6 | Informational | Information |
| 7 | Debugging | Debug messages |

---

# Remember

Lower number:

```
Higher severity
```

Example:

```
Level 0 > Level 7
```

---

# Syslog Destinations

| Destination | Description |
|---|---|
| Console | Terminal display |
| Buffer | Device memory |
| VTY | Remote sessions |
| Syslog server | Central storage |

---

# Cisco Syslog Configuration

Enable buffered logging:

```bash
logging buffered 16384
```

---

Send logs to server:

```bash
logging host 192.168.1.100
```

---

Set severity:

```bash
logging trap warnings
```

---

# Verify Syslog

```bash
show logging
```

# 6. Syslog Aggregation

## Definition

Syslog aggregation collects logs from multiple devices into one centralized location.

---

# Without Aggregation

```
Router 1 → Local logs

Router 2 → Local logs

Switch 1 → Local logs
```

Problem:

Hard to investigate.

---

# With Aggregation

```
Router 1

Router 2

Switch 1

Firewall

    |

    |

Syslog Server
```

---

# Benefits

| Benefit | Description |
|---|---|
| Central visibility | One location |
| Faster troubleshooting | Search all events |
| Security analysis | Detect attacks |
| Compliance | Keep records |

# 9. Comparison Table

| Feature | SNMP | NetFlow | Syslog |
|---|---|---|---|
| Purpose | Monitoring | Traffic analysis | Event logging |
| Data type | Metrics | Flow records | Messages |
| Direction | Polling/traps | Export | Push logs |
| Port | UDP 161/162 | UDP/custom | UDP 514 |
| Security | SNMPv3 | Depends | TLS options |

# 10. CCNA Exam Traps

- SNMP monitors device health.
- NetFlow analyzes traffic patterns.
- Syslog stores event messages.
- SNMPv3 provides authentication and encryption.
- SNMP uses UDP 161.
- SNMP traps use UDP 162.
- Syslog default port is UDP 514.
- Lower syslog severity numbers are more serious.
- NetFlow identifies conversations, not packet contents.
- Syslog aggregation improves troubleshooting.
