# 1. Overview

Simple Network Management Protocol (SNMP) is an application-layer protocol used to monitor and manage network devices. CCNA tests SNMP components (manager, agent, MIB), SNMP versions, community strings, polling, and traps.

---

# 2. Core Concepts

# SNMP Definition

SNMP:

```
Simple Network Management Protocol
```

Used for:

- Network monitoring
- Device health checks
- Performance measurement
- Fault detection

---

# SNMP Protocol Details

| Feature | Value |
|---|---|
| OSI Layer | Layer 7 (Application) |
| Transport | UDP |
| Manager Port | UDP 162 |

| Protocol | SNMP |

# SNMP Architecture

SNMP uses three main components:

```
SNMP Manager
        |
        |
        v

        |
        |
        v

```

---

# SNMP Components

| Component | Function |
|---|---|
| SNMP Manager | Monitoring system that collects information |
| SNMP Agent | Software running on managed device |
| Managed Device | Router, switch, server, firewall |
| MIB | Database of managed objects |

---

# SNMP Manager

Also called:

```
Network Management System (NMS)
```

Examples:

- SolarWinds
- Cisco DNA Center
- PRTG
- Nagios

Functions:

- Sends queries
- Receives responses
- Displays monitoring data

---

# SNMP Agent

Software running on:

- Routers
- Switches
- Firewalls
- Servers

Functions:

- Collects device information
- Responds to manager requests
- Generates notifications

---

# MIB (Management Information Base)

A MIB is:

```
A structured database containing information
about managed network objects.
```

Examples:

- Interface status
- CPU usage
- Memory usage
- Traffic counters

---

# MIB Structure

MIB uses:

```
Hierarchical Object Identifiers (OIDs)
```

Example:

```
1.3.6.1.2.1.2.2
```

Represents:

```
Interface table
```

---

# Object Identifier (OID)

OID:

```
Unique identifier for an SNMP object.
```

Example:


# SNMP Communication Methods

SNMP uses:

## Polling

Manager asks:

```
"What is your status?"
```

Flow:

```
Manager → Agent
        GET

Agent → Manager
        RESPONSE
```

---

## Traps

Agent sends:

```
Unsolicited notification
```

Example:

```
Interface down
```

Flow:

```
Agent → Manager
        TRAP
```

---

# Polling vs Traps

| Feature | Polling | Trap |
|---|---|---|
| Initiator | Manager | Agent |
| Direction | Manager requests | Agent sends |
| Frequency | Regular intervals | Event-based |
| Traffic | Higher | Lower |
| Example | CPU check | Link failure |

---

# SNMP Messages

| Message | Purpose |
|---|---|
| GET | Retrieve information |
| GET-NEXT | Retrieve next object |
| GET-BULK | Retrieve large amount of data |
| SET | Modify values |
| RESPONSE | Reply to request |
| TRAP | Notification |
| INFORM | Acknowledged notification |

---

# SNMP Operations

## GET

Manager requests data.

Example:

```
What is interface status?
```

---

## SET

Manager changes configuration.

Example:

```
Change device value
```

(Note: Often disabled for security.)

---

## TRAP

Agent reports event.

Example:

```
Interface Gi0/1 down
```

# SNMP Versions

SNMP has three major versions:

| Version | Security | Features |
|---|---|---|
| SNMPv1 | None | Basic monitoring |
| SNMPv2c | Community string | Improved performance |
| SNMPv3 | Strong security | Authentication + encryption |

---

# SNMPv1

Characteristics:

- First version
- Simple
- Uses community strings
- No encryption

Security:

```
Weak
```

---

# SNMPv2c

Characteristics:

- Uses community strings
- Adds GET-BULK
- Improved performance

Security:

```
Still insecure
```

---

# SNMPv3

Provides:

- Authentication
- Encryption
- Message integrity

Security:

```
Recommended
```

---

# SNMP Version Comparison

| Feature | v1 | v2c | v3 |
|---|---|---|---|
| Authentication | No | Community string | Yes |
| Encryption | No | No | Yes |
| Community string | Yes | Yes | Optional |
| Security | Low | Low | High |
| GET-BULK | No | Yes | Yes |

# Cisco SNMP Configuration

## Enable SNMP Read-Only Community

```bash
snmp-server community public ro
```

Explanation:

| Command | Function |
|---|---|
| snmp-server community | Creates SNMP community |
| public | Community string |
| ro | Read-only access |

---

## Enable SNMP Read-Write Community

```bash
snmp-server community private rw
```

Allows modification.

---

## Configure SNMP Trap Receiver

```bash
snmp-server host 192.168.1.100 version 2c public
```

Sends traps to:

```
192.168.1.100
```

---

## Enable Traps

```bash
snmp-server enable traps
```

Enables SNMP notifications.

---

# 5. Exam Traps

- SNMP operates at Layer 7.
- SNMP uses UDP, not TCP.
- SNMP agent listens on UDP 161.
- SNMP traps are sent to UDP 162.
- MIB stores information about managed objects.
- OIDs identify specific MIB objects.
- SNMPv1 and SNMPv2c use community strings.
- Community strings are not encryption.
- SNMPv3 provides authentication and encryption.
- Polling is initiated by the manager.
- Traps are initiated by the agent.
- GET retrieves information.
- SET modifies information.
- SNMP is used for monitoring, not routing.
