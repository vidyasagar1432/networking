# Site-to-Site and Remote-Access VPN Configuration

## CCNP Enterprise (ENCOR 350-401) Security & VPN Technologies

**CCNA Relevance:** VPN fundamentals, IPsec basics, remote access concepts.  
**CCNP ENCOR Relevance:** High — Enterprise VPN design, IPsec configuration, IKE, tunnel negotiation, remote-access VPNs, high availability, and troubleshooting.

---

# 1. Overview

A **Virtual Private Network (VPN)** creates a secure, encrypted tunnel over an untrusted network (usually the Internet).

VPNs provide:

- Confidentiality (Encryption)
- Integrity (Hashing)
- Authentication
- Anti-Replay Protection

Enterprise VPNs mainly fall into two categories:

- **Site-to-Site VPN**
- **Remote-Access VPN**

---

# 2. Why Use VPNs?

VPNs allow organizations to:

- Connect branch offices securely
- Enable remote employees to work securely
- Extend corporate networks to cloud environments
- Reduce leased-line costs
- Protect data over the Internet

# 4. Site-to-Site VPN

A Site-to-Site VPN permanently connects two or more networks.

```
Headquarters

        |

Firewall / Router

        |

======== Internet ========

        |

Firewall / Router

        |

Branch Office
```

Users work normally without manually connecting to the VPN.

---

# 5. Site-to-Site VPN Characteristics

- Always available
- Gateway-to-gateway tunnel
- No VPN client required
- Transparent to users
- Commonly uses IPsec

---

# 6. Site-to-Site VPN Example

```
HQ LAN

10.1.0.0/16

↓

VPN Gateway

↓

Internet

↓

VPN Gateway

↓

Branch LAN

10.2.0.0/16
```

Hosts communicate securely across the tunnel.

---

# 7. Remote-Access VPN

A Remote-Access VPN connects an individual user to the corporate network.

```
Remote User

↓

VPN Client

↓

Internet

↓

VPN Gateway

↓

Corporate LAN
```

Commonly used by:

- Employees
- Contractors
- Administrators

---

# 8. Remote-Access VPN Characteristics

- User initiates the connection
- Requires user authentication
- May require a VPN client (depending on the solution)
- Supports mobile users
- Can use IPsec or SSL/TLS

---

# 9. VPN Components

| Component | Purpose |
|----------|---------|
| VPN Client | Initiates remote connection |
| VPN Gateway | Terminates VPN tunnel |
| Authentication Server | Verifies users |
| Certificate Authority (Optional) | Issues certificates |
| Internal Network | Destination resources |

# 10. IPsec Overview

IPsec is the most common VPN technology for Site-to-Site VPNs.

Provides:

- Encryption
- Authentication
- Integrity
- Anti-Replay Protection

---

# 12. IKE Phases (Conceptual)

```
IKE Phase 1

↓

Secure Management Tunnel
```

# 14. VPN Authentication Methods

Common methods:

- Pre-Shared Key (PSK)
- Digital Certificates
- EAP (Remote Access)

Certificates are preferred for large enterprise deployments due to improved scalability and security.

---

# 15. Encryption Algorithms

Common algorithms:

| Algorithm | Status |
|-----------|--------|
| DES | Obsolete |
| 3DES | Legacy |
| AES-128 | Common |
| AES-192 | Common |
| AES-256 | Enterprise Standard |

AES is recommended for modern deployments.

---

# 16. Integrity Algorithms

Provide packet integrity.

Examples:

- SHA-256
- SHA-384
- SHA-512

Older algorithms such as MD5 and SHA-1 are considered legacy and are generally avoided in new deployments.

---

# 17. Diffie-Hellman (DH)

Diffie-Hellman securely exchanges cryptographic keys.

```
Peer A

↓

DH Exchange

↓

Peer B

↓

Shared Secret
```

Stronger DH groups provide better security.

---

# 18. Security Associations (SA)

An SA defines the parameters for a secure connection.

Includes:

- Encryption algorithm
- Integrity algorithm
- Lifetime
- Keys
- Peer information

Each VPN tunnel has one or more SAs.

---

# 19. Interesting Traffic

Only specified traffic enters the VPN.

Example:

```
10.1.0.0/16

↓

10.2.0.0/16

↓

Encrypt
```

Internet-bound traffic is usually not encrypted unless configured for full-tunnel operation.

# 32. Best Practices

- Use **IKEv2** where supported.
- Use **AES-256** (or other approved modern ciphers) for encryption.
- Use strong integrity algorithms (e.g., SHA-256 or stronger).
- Prefer certificates for large deployments.
- Enable **Perfect Forward Secrecy (PFS)** where appropriate.
- Configure Identity NAT for VPN traffic when required.
- Enable logging and monitoring.
- Use MFA for remote-access VPNs.
- Build redundant VPN gateways for high availability.

---

# 33. Troubleshooting

## Tunnel Does Not Establish

Check:

- Peer IP
- IKE policy
- Pre-shared key or certificates
- Reachability
- Firewall rules

---

## Tunnel Established but No Traffic

Verify:

- Interesting traffic definitions
- NAT exemption / Identity NAT
- Security policies
- Routing
- Tunnel selectors

---

## Authentication Failure

Check:

- Username
- Password
- RADIUS/LDAP server
- Certificates
- MFA configuration

---

## Slow VPN

Verify:

- Internet bandwidth
- CPU utilization
- Encryption overhead
- MTU/MSS settings
- Packet fragmentation

# CCNP Exam Traps

- **Site-to-Site VPNs** connect **networks**, while **Remote-Access VPNs** connect **individual users**.
- **IPsec** provides **encryption, authentication, integrity, and anti-replay protection**.
- **IKE** negotiates the secure parameters used by IPsec.
- **Identity NAT (NAT exemption)** is commonly required so VPN traffic is **not translated**.
- **Split tunneling** sends only corporate traffic through the VPN, while **full tunneling** sends all traffic through the VPN gateway.
- **GRE over IPsec** is commonly used when routing protocols or multicast traffic must traverse the tunnel.
- Modern enterprise deployments typically prefer **IKEv2**, **AES**, **SHA-256 (or stronger)**, and **MFA** for remote users.

Which VPN type permanently connects two corporate networks?

A. Remote-Access VPN  
B. Clientless SSL VPN  
C. Site-to-Site VPN  
D. PPTP VPN  

### Answer: C

## Question 2

What is the primary role of IKE in an IPsec VPN?

A. Perform DNS resolution  
B. Assign IP addresses  
C. Negotiate security parameters and establish secure associations for the VPN  
D. Compress traffic only  

### Answer: C

Why is Identity NAT commonly configured for Site-to-Site VPNs?

A. To encrypt packets  
B. To prevent VPN traffic from being translated by NAT  
C. To improve Wi-Fi coverage  
D. To assign public IP addresses automatically  

### Answer: B

Which option best describes a split-tunnel VPN?

B. Only corporate-destined traffic traverses the VPN, while other Internet traffic goes directly to the Internet.
