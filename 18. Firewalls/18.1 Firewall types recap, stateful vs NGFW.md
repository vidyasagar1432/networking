# Firewall Types Recap: Stateful Firewall vs Next-Generation Firewall (NGFW)

## CCNA & CCNP Enterprise (ENCOR 350-401)

**CCNA Relevance: Core security topic.**  
**CCNP ENCOR Relevance: High — Understanding firewall architectures, traffic inspection, application awareness, IPS, and policy enforcement is essential for enterprise networks.**

---

# 1. Overview

A **firewall** is a network security device that monitors, filters, and controls traffic between networks based on security policies.

Its primary objectives are to:

- Prevent unauthorized access
- Protect internal resources
- Allow legitimate traffic
- Block malicious activity
- Enforce security policies

Modern enterprise environments typically use:

- Packet-Filtering Firewalls
- Stateful Firewalls
- Next-Generation Firewalls (NGFWs)

---

# 2. Evolution of Firewalls

```
Packet Filtering

        ↓

Stateful Firewall

        ↓

Next-Generation Firewall (NGFW)

        ↓

Cloud Firewalls / SASE
```

Each generation adds more visibility and security capabilities.

---

# 3. Packet-Filtering Firewall (1st Generation)

A packet-filtering firewall examines individual packets based on:

- Source IP
- Destination IP
- Source Port
- Destination Port
- Protocol

It does **not** track the state of a connection.

```
Packet

↓

ACL Rules

↓

Allow / Deny
```

---

# 4. Packet Filtering Example

```
Allow

TCP

Port 80

↓

Web Traffic
```

Every packet is evaluated independently.

---

# 5. Limitations of Packet Filtering

- No connection tracking
- No application awareness
- Cannot detect attacks inside allowed sessions
- Vulnerable to spoofing and certain evasion techniques

---

# 6. Stateful Firewall (2nd Generation)

A **stateful firewall** keeps track of active connections.

Instead of evaluating every packet independently, it remembers session information in a **state table**.

```
Packet

↓

State Table

↓

Existing Session?

↓

Yes

↓

Allow

↓

No

↓

Evaluate Rules
```

---

# 7. Stateful Inspection

When a client initiates a connection:

```
Client

↓

SYN

↓

Firewall

↓

Server

↓

SYN-ACK

↓

Firewall

↓

Client
```

The firewall records the session and automatically permits the corresponding return traffic.

---

# 8. Stateful Firewall Characteristics

| Feature | Supported |
|----------|-----------|
| Connection Tracking | Yes |
| Session Table | Yes |
| Layer 3 Filtering | Yes |
| Layer 4 Filtering | Yes |
| Return Traffic | Automatically Allowed |
| Application Awareness | Limited |

---

# 9. Stateful Session Table

Example:

| Source | Destination | Port | State |
|----------|-------------|------|-------|
|10.1.1.10|172.16.1.20|443|Established|
|10.1.1.15|8.8.8.8|53|Established|

The firewall uses this table to make forwarding decisions.

---

# 10. Advantages of Stateful Firewalls

- More secure than packet filtering
- Tracks active sessions
- Reduces unnecessary rule processing
- Automatically handles return traffic
- Better protection against certain attacks

---

# 11. Limitations of Stateful Firewalls

Stateful firewalls generally cannot identify:

- Applications using non-standard ports
- Malware hidden in encrypted traffic (without SSL/TLS inspection)
- User identity
- Advanced threats
- Zero-day attacks

This led to the development of **Next-Generation Firewalls**.

---

# 12. What Is a Next-Generation Firewall (NGFW)?

A **Next-Generation Firewall (NGFW)** combines traditional stateful inspection with advanced security capabilities such as:

- Application awareness
- Intrusion Prevention System (IPS)
- User identity integration
- URL filtering
- Malware detection
- SSL/TLS inspection (where enabled)
- Threat intelligence

---

# 13. NGFW Architecture

```
Packet

↓

Stateful Inspection

↓

Application Identification

↓

IPS

↓

URL Filtering

↓

Threat Detection

↓

Allow / Block
```

Traffic passes through multiple inspection stages.

---

# 14. Application Awareness

NGFWs identify applications regardless of port number.

Example:

Instead of:

```
TCP 443
```

The firewall can recognize:

- YouTube
- Microsoft Teams
- Zoom
- Dropbox
- Facebook
- Salesforce

This enables policies based on the actual application.

---

# 15. Traditional vs Application-Based Rules

Traditional Firewall:

```
Allow TCP 443
```

NGFW:

```
Allow

Microsoft Teams

Block

YouTube

Allow

Salesforce
```

---

# 16. Deep Packet Inspection (DPI)

NGFWs inspect packet payloads in addition to headers.

```
Packet

↓

Header

↓

Payload

↓

Inspection
```

This enables detection of application traffic and malicious content.

---

# 17. Intrusion Prevention System (IPS)

An NGFW often includes an **Intrusion Prevention System (IPS)**.

Functions:

- Detect attacks
- Block exploits
- Prevent malware
- Identify protocol anomalies
- Inspect known attack signatures

---

# 18. URL Filtering

Policies can restrict web access.

Example:

Allow:

- Company websites
- Business tools

Block:

- Gambling
- Malware sites
- Phishing pages
- Adult content

---

# 19. SSL/TLS Inspection

Much Internet traffic is encrypted.

Without decryption:

```
HTTPS

↓

Firewall

↓

Encrypted

↓

Cannot Inspect Payload
```

With SSL/TLS inspection enabled:

```
HTTPS

↓

Decrypt

↓

Inspect

↓

Encrypt

↓

Forward
```

This requires careful planning due to privacy, compliance, and performance considerations.

---

# 20. User Identity Integration

NGFWs can integrate with identity services such as:

- Active Directory
- LDAP
- RADIUS

Policies can then be based on users or groups rather than only IP addresses.

Example:

```
Engineering

↓

GitHub Allowed

Sales

↓

CRM Allowed
```

---

# 21. Threat Intelligence

Many NGFWs receive continuous updates containing:

- Malicious IP addresses
- Domain reputation
- File hashes
- Emerging attack indicators

This helps block known threats quickly.

# 28. Best Practices

- Follow the **principle of least privilege**.
- Enable IPS for critical networks.
- Restrict applications rather than only ports.
- Keep threat signatures and software up to date.
- Log and monitor firewall events.
- Segment internal networks.
- Review firewall policies regularly.
- Enable SSL/TLS inspection only where appropriate and compliant with organizational policies.

# CCNP Exam Traps

- **Packet-filtering firewalls** inspect packets individually and do **not** track connection state.
- **Stateful firewalls** maintain a **session table** and automatically allow return traffic for established sessions.
- **NGFWs** include **stateful inspection** plus advanced features such as application awareness, IPS, URL filtering, user identity integration, and threat intelligence.
- **Application-aware policies** identify applications regardless of the TCP/UDP port they use.
- **SSL/TLS inspection** allows encrypted traffic to be analyzed but increases processing requirements and has privacy considerations.
- **IPS** is designed to **detect and block** malicious traffic, whereas a traditional stateful firewall primarily enforces access policies.

What is the primary advantage of a stateful firewall over a packet-filtering firewall?

A. It supports VLANs.  
B. It tracks active network sessions and automatically permits return traffic.  
C. It replaces routing protocols.  
D. It performs DNS resolution.  

### Answer: B

A. IPv4 support

### Answer: C

Which firewall feature allows security policies such as "allow Microsoft Teams but block YouTube"?

A. NAT  
B. Port forwarding  
C. Application awareness  
D. Static routing

A. Increase Wi-Fi coverage  
B. Assign IP addresses
