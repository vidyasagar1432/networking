# Cisco ASA, Cisco Secure Firewall (FTD), and Palo Alto Firewalls: Zones and Security Policies

## CCNP Enterprise (ENCOR 350-401) Security Fundamentals

**CCNA Relevance:** Basic firewall and zone concepts.  
**CCNP ENCOR Relevance:** High — Understanding Cisco ASA, Cisco Secure Firewall Threat Defense (FTD), Palo Alto Networks firewalls, security zones, policy evaluation, NAT, and inspection is essential for enterprise networks.

---

# 1. Overview

Enterprise firewalls do much more than simply allow or block traffic.

Modern firewalls perform:

- Stateful inspection
- Application identification
- Intrusion Prevention (IPS)
- Malware detection
- SSL/TLS inspection
- URL filtering
- User-based policies
- Network Address Translation (NAT)
- VPN termination

The most common enterprise firewalls include:

- **Cisco ASA**
- **Cisco Secure Firewall Threat Defense (FTD)**
- **Palo Alto Networks NGFW**

# 3. Cisco ASA Overview

Cisco ASA (Adaptive Security Appliance) is a **stateful firewall**.

Main features:

- Stateful inspection
- NAT/PAT
- VPN
- ACLs
- High Availability
- Basic application inspection

ASA is widely deployed in enterprise networks.

---

# 4. Cisco Secure Firewall Threat Defense (FTD)

FTD combines:

```
Cisco ASA

+

Firepower Services

=

Cisco Secure Firewall
```

Additional capabilities include:

- Application Awareness
- Intrusion Prevention (IPS)
- URL Filtering
- Malware Protection
- Threat Intelligence
- Advanced Logging

---

# 5. Palo Alto Networks Firewall

Palo Alto is a **Next-Generation Firewall (NGFW)**.

Key technologies include:

- App-ID
- User-ID
- Content-ID
- SSL/TLS Decryption
- Threat Prevention
- URL Filtering
- WildFire Malware Analysis

# 6. What Is a Security Zone?

A **security zone** is a logical grouping of interfaces that share the same trust level and security policies.

Examples:

```
Inside

Outside

DMZ

Guest

Management

VPN
```

Policies are applied **between zones**, not individual interfaces.

---

# 7. Zone-Based Design

```
Internet

↓

Outside Zone

↓

Firewall

↓

Inside Zone

↓

Users
```

Traffic crossing zone boundaries is inspected.

# 11. Security Policy

A **security policy** defines whether traffic between zones is permitted or denied.

Policies are based on:

- Source zone
- Destination zone
- Source IP
- Destination IP
- Application
- User
- Service/Port
- Schedule
- Action

# 15. Cisco ASA Security Levels

ASA traditionally uses **security levels** (0–100).

Example:

| Interface | Security Level |
|-----------|----------------|
| Inside | 100 |
| DMZ | 50 |
| Outside | 0 |

By default:

- Higher → Lower: Allowed
- Lower → Higher: Denied

ACLs are commonly used to refine or override this behavior.

# 31. Best Practices

- Use **least privilege**.
- Segment networks into security zones.
- Block all unnecessary inbound traffic.
- Allow only required applications.
- Enable IPS for Internet-facing services.
- Log both allowed and denied traffic where appropriate.
- Regularly review and remove unused rules.
- Place more specific rules before general rules.

# CCNP Exam Traps

- **Cisco ASA** is primarily a **stateful firewall**, while **Cisco FTD** and **Palo Alto** are **Next-Generation Firewalls (NGFWs)**.
- **Security zones** group interfaces with similar trust levels, and policies are applied **between zones**.
- **Cisco ASA** traditionally uses **security levels (0–100)**, whereas **FTD** and **Palo Alto** rely primarily on **zone-based security policies**.
- NGFWs evaluate traffic based on **applications**, **users**, **content**, and **state**, not just IP addresses and ports.
- Security policies are generally processed **top to bottom**, with the **first matching rule** applied.
- Application identification (App-ID on Palo Alto) allows policies such as "allow Microsoft Teams, block BitTorrent" regardless of the transport port.
