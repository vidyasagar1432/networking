# High Availability (HA): Active/Standby Firewall Pairs

## CCNP Enterprise (ENCOR 350-401) Security & High Availability

**CCNA Relevance:** Basic redundancy concepts.  
**CCNP ENCOR Relevance:** High — Firewall High Availability (HA), failover mechanisms, state synchronization, redundancy, and enterprise resiliency are essential topics.

---

# 1. Overview

A firewall is a **critical point of failure**.

If a single firewall fails:

- Internet access stops
- VPN tunnels disconnect
- Branch offices lose connectivity
- Users cannot access applications

To eliminate this single point of failure, organizations deploy **High Availability (HA)**.

---

# 2. What Is High Availability?

High Availability (HA) is the deployment of two or more firewalls so that network services continue even if one firewall fails.

Goals:

- Minimize downtime
- Increase reliability
- Improve fault tolerance
- Maintain user sessions (where supported)

---

# 3. HA Architecture

```
                 Internet

                     |

          ---------------------

          |                   |

      Firewall A         Firewall B

       (Active)         (Standby)

          |                   |

          ---------------------

                     |

                 Core Switch

                     |

                Internal LAN
```

Only one firewall forwards traffic at a time in an **Active/Standby** design.

---

# 4. Active/Standby Mode

```
Firewall A

↓

Processing Traffic

-------------------------

Firewall B

↓

Waiting

↓

Ready To Take Over
```

The standby firewall continuously monitors the active firewall.

---

# 5. Active/Active Mode

Some firewall platforms also support **Active/Active** operation.

```
Firewall A

↓

Handles Some Traffic

-------------------------

Firewall B

↓

Handles Other Traffic
```

Active/Active is generally more complex and often used in larger environments. Availability depends on the firewall platform and deployment model.

---

# 6. HA Components

A firewall HA solution typically includes:

- Active Firewall
- Standby Firewall
- HA/Failover Link
- State Synchronization
- Configuration Synchronization
- Heartbeat Messages

---

# 7. Heartbeat

Firewalls periodically exchange heartbeat packets.

```
Active

↓

Heartbeat

↓

Standby

↓

Alive
```

If heartbeats stop, failover is triggered.

---

# 8. Failover Link

A dedicated interface carries HA traffic.

```
Firewall A

======= HA Link =======

Firewall B
```

The HA link synchronizes:

- State table
- Configuration
- Health information

---

# 9. State Synchronization

Without synchronization:

```
User

↓

Connected

↓

Firewall Fails

↓

Session Lost
```

With synchronization:

```
Firewall A

↓

Session Table

↓

Sync

↓

Firewall B
```

Existing sessions can continue after failover, depending on the protocol and platform.

---

# 10. Session Table Synchronization

Example:

| Source | Destination | Port | State |
|----------|-------------|------|-------|
|10.1.1.10|8.8.8.8|443|Established|
|10.1.1.11|172.16.1.20|22|Established|

The standby firewall maintains a synchronized copy.

---

# 11. Configuration Synchronization

Configuration changes on the active firewall are replicated to the standby firewall.

Examples:

- NAT policies
- Security rules
- VPN configuration
- Interfaces
- Routing configuration (platform dependent)

This helps keep both firewalls consistent.

---

# 12. Failover Process

```
Active Firewall

↓

Failure

↓

Heartbeat Lost

↓

Standby Detects Failure

↓

Standby Becomes Active

↓

Traffic Resumes
```

---

# 13. Failover Triggers

Failover can occur due to:

- Power failure
- Hardware failure
- Software crash
- Interface failure
- Link failure
- Administrator-initiated failover
- Health monitoring failure

---

# 14. Interface Monitoring

Firewalls monitor critical interfaces.

```
Outside Interface

↓

Down

↓

Failover
```

Monitoring prevents a firewall with failed connectivity from remaining active.

---

# 15. Gateway Monitoring

Some platforms monitor upstream devices.

Example:

```
Firewall

↓

Ping

↓

Router

↓

No Response

↓

Failover
```

This detects failures beyond the local interfaces.

---

# 16. Virtual IP Address (VIP)

Clients normally communicate with a shared **Virtual IP (VIP)**.

```
Users

↓

203.0.113.1

↓

Active Firewall
```

The VIP moves to the standby firewall after failover, allowing clients to continue using the same gateway or service address.

---

# 17. Virtual MAC Address

Some HA implementations use a **Virtual MAC Address**.

```
VIP

↓

Virtual MAC

↓

Moves During Failover
```

This reduces the need for neighboring devices to relearn MAC addresses.

---

# 21. VPN and HA

Modern HA firewalls synchronize VPN information where supported.

```
VPN Tunnel

↓

Firewall A

↓

Sync

↓

Firewall B
```

This minimizes VPN disruption during failover.

---

# 22. NAT Synchronization

NAT translation tables may also be synchronized.

```
Client

↓

PAT Entry

↓

Sync

↓

Standby
```

This helps preserve existing NAT sessions after failover.

---

# 23. Routing During Failover

After failover:

```
Firewall B

↓

Becomes Gateway

↓

Routing Continues
```

Dynamic routing adjacencies may need to reconverge unless optimized by the platform or design.

# 25. Split-Brain Problem

A **split-brain** condition occurs when both firewalls believe they should be active.

```
Firewall A

↓

Active

-------------------

Firewall B

↓

Also Active
```

This can cause:

- Duplicate IP addresses
- Routing issues
- Session failures

Reliable HA communication and quorum mechanisms help prevent this.

---

# 26. Maintenance Mode

Administrators can manually switch roles.

```
Firewall A

↓

Standby

↓

Firewall B

↓

Active
```

Useful for:

- Software upgrades
- Hardware replacement
- Planned maintenance

---

# 27. Best Practices

- Use dedicated HA links.
- Synchronize configuration and state.
- Monitor critical interfaces and upstream paths.
- Test failover regularly.
- Keep software versions consistent.
- Use redundant switches and uplinks.
- Document failover procedures.
- Perform upgrades during maintenance windows.

---

# 28. Troubleshooting

## Failover Does Not Occur

Check:

- HA link
- Heartbeat status
- Interface monitoring
- Configuration mismatch
- Licensing (if applicable)

---

## Sessions Drop After Failover

Verify:

- Stateful synchronization
- NAT synchronization
- VPN synchronization
- Session timeout values
- Platform capabilities

---

## Frequent Failovers

Check:

- Flapping interfaces
- CPU utilization
- Memory usage
- Link stability
- Health monitoring thresholds

# CCNP Exam Traps

- **Active/Standby** means **one firewall actively forwards traffic** while the other waits to take over.
- **Heartbeats** detect the health of the active firewall.
- **State synchronization** helps preserve active sessions during failover.
- **Configuration synchronization** keeps firewall policies and settings consistent.
- **Interface monitoring** and **path/gateway monitoring** can both trigger failover.
- **Split-brain** occurs when both firewalls incorrectly believe they are active.
- **Cisco ASA** supports Active/Standby and Active/Active (in multiple-context mode).
- **Cisco FTD** commonly uses Active/Standby HA.
- **Palo Alto** supports both Active/Passive and Active/Active deployments.
