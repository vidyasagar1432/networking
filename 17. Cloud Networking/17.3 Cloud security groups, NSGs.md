# Cloud Security Groups and Network Security Groups (NSGs)

## CCNP Enterprise (ENCOR 350-401) & Cloud Networking Fundamentals

**CCNA Relevance: Basic cloud security awareness.**  
**CCNP ENCOR Relevance: High — Understanding cloud firewalls, Security Groups, NSGs, routing, and layered security is essential for hybrid and cloud networking.**  
**Cloud Certifications (AWS SAA, Azure AZ-104, AZ-700): Core networking and security topic.**

---

# 1. Overview

In traditional networks, traffic is controlled by **physical firewalls** and **Access Control Lists (ACLs)**.

In cloud environments, security is primarily enforced using **virtual firewalls**.

The most common are:

- **AWS Security Groups (SGs)**
- **AWS Network ACLs (NACLs)**
- **Azure Network Security Groups (NSGs)**

These technologies control which traffic is allowed to reach cloud resources.

# 5. AWS Security Groups

A **Security Group (SG)** is a **virtual stateful firewall** attached to AWS resources such as:

- EC2 instances
- Elastic Network Interfaces (ENIs)
- Some load balancers
- Other supported services

It controls:

- Inbound traffic
- Outbound traffic

---

# 6. Security Group Characteristics

| Feature | Value |
|----------|-------|
| Stateful | Yes |
| Applied To | Instance / ENI |
| Deny Rules | No |
| Default Action | Implicit Deny |
| Direction | Inbound and Outbound |

Security Groups are **stateful**.

Example:

```

↓

TCP 443

↓

Web Server

↓

Response

↓

Automatically Allowed
```

Return traffic does not require a separate outbound rule.

Each rule contains:

- Protocol
- Port

Default behavior:

Inbound:

```
No Access
```

Outbound:

```
Allow All
```

(Outbound behavior can be modified.)

# 13. Security Group Referencing

Security Groups can reference other Security Groups instead of IP addresses.

Example:

```

↓

App SG

↓

```

This simplifies security management.

---

# 14. AWS Network ACL (NACL)

A **Network ACL** is another AWS firewall.

Unlike Security Groups:

- Applied to subnets
- Stateless
- Supports allow and deny rules

---

# 15. NACL Characteristics

| Feature | Value |
|----------|-------|
| Stateful | No |
| Applied To | Subnet |
| Deny Rules | Yes |
| Rule Order | Evaluated in numerical order |
| Direction | Inbound and Outbound |

---

# 16. Security Group vs NACL

| Feature | Security Group | Network ACL |
|----------|---------------|-------------|
| Scope | Instance/ENI | Subnet |
| Stateful | Yes | No |
| Allow Rules | Yes | Yes |
| Deny Rules | No | Yes |
| Rule Processing | All rules evaluated | Lowest rule number first |
| Default | Implicit deny inbound | Default NACL allows all (modifiable) |

---

# 17. Azure Network Security Group (NSG)

Azure uses **Network Security Groups (NSGs)**.

An NSG filters traffic to:

- Virtual Machines
- Network Interfaces (NICs)
- Subnets

It performs a role similar to an AWS Security Group.

---

# 18. NSG Characteristics

| Feature | Value |
|----------|-------|
| Stateful | Yes |
| Applied To | NIC or Subnet |
| Allow Rules | Yes |
| Deny Rules | Yes |
| Default Rules | Built-in |
| Priority-Based | Yes |

---

# 19. Azure NSG Example

```
Internet

↓

NSG

↓

Azure VM
```

Rules:

Allow:

```
TCP 443

TCP 3389

TCP 22
```

---

# 20. NSG Rule Components

Each rule contains:

- Priority
- Direction
- Protocol
- Source
- Destination
- Port
- Action (Allow or Deny)

---

# 21. NSG Priority

Lower numbers have **higher priority**.

Example:

| Priority | Rule |
|----------|------|
| 100 | Allow HTTPS |
| 200 | Allow SSH |
| 300 | Deny All |

The first matching rule is applied.

---

# 22. Default NSG Rules

Azure automatically creates default rules.

Examples:

- Allow VNet traffic
- Allow Azure load balancer traffic
- Deny all other inbound traffic

These defaults can usually be overridden by creating higher-priority custom rules.

---

# 23. NSG Example

```
Priority 100

Allow TCP 443

↓

Priority 200

Allow TCP 22

↓

Priority 300

Deny All
```

# 34. Best Practices

- Follow the **principle of least privilege**.
- Avoid exposing management ports (SSH/RDP) directly to the Internet.
- Use bastion hosts or managed access services.
- Restrict inbound rules to trusted IP ranges.
- Remove unused rules regularly.
- Use descriptive rule names and documentation.
- Monitor security logs and traffic.
- Combine Security Groups/NSGs with host-based firewalls and identity controls for layered security.

# CCNP Exam Traps

- **AWS Security Groups** are **stateful** and are attached to **instances/ENIs**.
- **AWS Network ACLs** are **stateless**, applied to **subnets**, and support **allow and deny** rules.
- **Azure NSGs** are **stateful** and can be associated with **NICs** or **subnets**.
- Security Groups **do not have explicit deny rules**—only allow rules; all other traffic is implicitly denied.
- **NACLs** evaluate rules in numerical order and stop at the first match.
- **NSGs** evaluate rules by **priority**, with lower numbers processed first.
- Security Groups and NSGs complement, rather than replace, other security controls such as firewalls, VPNs, IAM, and host-based security.
