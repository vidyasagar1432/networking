# 1. Overview

ARP (Address Resolution Protocol) maps an IPv4 address to a MAC address so devices can communicate on a local network. CCNA tests ARP request/reply operation, ARP tables, broadcast behavior, gratuitous ARP, and ARP-related security issues.

---

# 2. Core Concepts

# ARP Definition

ARP resolves:

```
IPv4 Address
        |
        v
MAC Address
```

Example:

Device knows:

```
Destination IP:
192.168.1.20
```

Needs:

```
Destination MAC:
AA:BB:CC:DD:EE:FF
```

ARP provides the mapping.

---

# Why ARP Is Needed

Ethernet communication requires:

```
Destination MAC Address
```

IP communication requires:

```
Destination IP Address
```

ARP connects:

```
Layer 3 IP Address
        |
        v
Layer 2 MAC Address
```

---

# ARP Position in TCP/IP Model

| Layer | Protocol |
|---|---|
| Internet Layer | IPv4 |
| Network Access Layer | Ethernet |
| ARP | Between Layer 2 and Layer 3 |

ARP is commonly called:

```
Layer 2.5 protocol
```

---

# ARP Message Types

| Message | Purpose |
|---|---|
| ARP Request | Find MAC address |
| ARP Reply | Provide MAC address |
| Gratuitous ARP | Announce own IP/MAC mapping |

---

# Normal ARP Process

Example:

PC-A:

```
IP: 192.168.1.10
MAC: AA-AA-AA-AA-AA-AA
```

PC-B:

```
IP: 192.168.1.20
MAC: BB-BB-BB-BB-BB-BB
```

---

## Step 1: ARP Request

PC-A sends:

```
Who has 192.168.1.20?
Tell 192.168.1.10
```

Destination MAC:

```
FF:FF:FF:FF:FF:FF
```

Broadcast frame.

---

## Step 2: ARP Reply

PC-B responds:

```
192.168.1.20 is at BB-BB-BB-BB-BB-BB
```

Destination:

```
AA-AA-AA-AA-AA-AA
```

Unicast frame.

---

## Step 3: ARP Cache Update

PC-A stores:

```
192.168.1.20
        |
        v
BB-BB-BB-BB-BB-BB
```

---

# ARP Communication Flow

```
PC-A
 |
 | ARP Request
 | Broadcast
 v

Switch

 |
 | ARP Reply
 | Unicast
 v

PC-B
```

---

# ARP Table

Devices store ARP mappings in an ARP cache.

Example:

| IP Address | MAC Address | Type |
|---|---|---|
| 192.168.1.1 | 00:11:22:33:44:55 | Dynamic |
| 192.168.1.20 | AA:BB:CC:DD:EE:FF | Dynamic |

---

# ARP Table Entry Types

| Type | Description |
|---|---|
| Dynamic | Learned automatically |
| Static | Manually configured |

---

# Dynamic ARP Aging

Dynamic ARP entries expire after a timeout.

Purpose:

- Remove outdated mappings
- Allow MAC changes

---

# ARP Request Characteristics

| Feature | Value |
|---|---|
| Destination MAC | Broadcast |
| MAC address | FF:FF:FF:FF:FF:FF |
| Destination IP | Target device |
| Sent by | Requesting host |

---

# ARP Reply Characteristics

| Feature | Value |
|---|---|
| Destination MAC | Requester MAC |
| Type | Unicast |
| Contains | IP-to-MAC mapping |

---

# ARP and Routers

Routers maintain ARP tables for directly connected networks.

Example:

```
PC ---- Router ---- Internet
```

PC does not ARP for Internet servers.

Instead:

PC ARPs for:

```
Default Gateway MAC
```

---

# Default Gateway ARP Example

PC:

```
IP: 192.168.1.10
Gateway: 192.168.1.1
```

Before sending traffic outside LAN:

PC asks:

```
Who has 192.168.1.1?
```

Router replies with:

```
Gateway MAC address
```

---

# Proxy ARP

## Definition

Proxy ARP allows a router to answer ARP requests on behalf of another device.

Example:

```
Host A ---- Router ---- Host B
```

Router replies:

```
I have Host B's MAC
```

---

# Proxy ARP Usage

| Feature | Description |
|---|---|
| Enabled by default on many Cisco routers | Yes |
| Responds for other hosts | Yes |
| Used today | Less common |

---

# Gratuitous ARP (GARP)

## Definition

A device sends an ARP message without receiving a request.

Purpose:

Announce:

```
My IP address = My MAC address
```

---

# Gratuitous ARP Operation

Example:

Device:

```
IP:
192.168.1.10

MAC:
AA:AA:AA:AA:AA:AA
```

Sends:

```
192.168.1.10 is at AA:AA:AA:AA:AA:AA
```

---

# Gratuitous ARP Uses

| Use Case | Explanation |
|---|---|
| Duplicate IP detection | Detect IP conflicts |
| Update ARP caches | Inform devices of MAC changes |
| High availability | Used with FHRP |
| NIC changes | Update mappings |

---

# Gratuitous ARP in FHRP

Used by:

- HSRP
- VRRP
- GLBP

Example:

Before failover:

```
Router A
Virtual IP → MAC A
```

After failover:

```
Router B
Virtual IP → MAC B
```

GARP updates switches and hosts.

---

# ARP Security Issues

## ARP Spoofing

Attacker sends fake ARP messages.

Example:

Attacker claims:

```
Gateway IP = Attacker MAC
```

Result:

Traffic interception.

---

# ARP Poisoning

Definition:

Corrupting ARP caches with false mappings.

Example:

Normal:

```
192.168.1.1 → Router MAC
```

Attack:

```
192.168.1.1 → Attacker MAC
```

---

# ARP Protection Methods

| Feature | Protection |
|---|---|
| Dynamic ARP Inspection | Validates ARP packets |
| DHCP Snooping | Provides trusted IP-MAC bindings |
| Static ARP | Manual mapping |
| Port Security | Limits devices |

---

# ARP vs IPv6 Neighbor Discovery

| Feature | ARP | IPv6 ND |
|---|---|---|
| Protocol | ARP | ICMPv6 |
| Addressing | IPv4 | IPv6 |
| Broadcast | Uses broadcast | Uses multicast |
| Mapping | IP → MAC | IPv6 → MAC |

# 3. Worked Examples

## Example 1: ARP Resolution

### Scenario

PC-A wants to communicate with:

```
192.168.1.20
```

PC-A knows:

```
Destination IP
```

but not:

```
Destination MAC
```

---

### Solution

Step 1:

PC checks ARP cache.

Result:

```
No entry found
```

---

Step 2:

PC sends ARP Request:

```
Who has 192.168.1.20?
```

Destination:

```
FF:FF:FF:FF:FF:FF
```

---

Step 3:

Destination replies:

```
192.168.1.20 is at MAC address
```

---

Step 4:

PC stores:

```
IP → MAC
```

Communication begins.

---

## Example 2: Gratuitous ARP After Failover

### Scenario

HSRP failover occurs.

Before:

```
Router A
Virtual IP:
192.168.1.1

MAC:
AAAA
```

After:

```
Router B becomes active
```

---

### Solution

Step 1:

Router B takes ownership.

---

Step 2:

Router B sends Gratuitous ARP:

```
192.168.1.1 is at BBBB
```

---

Step 3:

Switches update MAC tables.

---

Step 4:

Traffic moves to Router B.

# 5. Exam Traps

- ARP resolves IPv4 addresses to MAC addresses.
- ARP request is broadcast.
- ARP reply is normally unicast.
- ARP works only on local Layer 2 networks.
- Hosts ARP for the default gateway MAC, not remote hosts.
- Routers do not forward ARP broadcasts.
- Gratuitous ARP is unsolicited.
- Gratuitous ARP can detect duplicate IP addresses.
- ARP does not use TCP or UDP ports.
- ARP spoofing is prevented using Dynamic ARP Inspection.
- ARP cache stores IP-to-MAC mappings.
- Proxy ARP allows routers to answer ARP requests for other devices.

# 7. Practice Questions

## Question 1

What does ARP resolve?

A. MAC address to IP address  
B. IPv4 address to MAC address  
C. Port number to IP address  
D. Hostname to IP address  

### Answer: B. IPv4 address to MAC address

Explanation:

ARP maps Layer 3 IPv4 addresses to Layer 2 MAC addresses.

---

## Question 2

An ARP request is sent using which destination MAC address?

A. Router MAC  
B. Broadcast MAC  
C. Source MAC  
D. Multicast MAC  

### Answer: B. Broadcast MAC

Explanation:

ARP requests use:

```
FF:FF:FF:FF:FF:FF
```

---

## Question 3

Which feature validates ARP packets against trusted bindings?

A. STP  
B. PortFast  
C. Dynamic ARP Inspection  
D. EtherChannel  

### Answer: C. Dynamic ARP Inspection

Explanation:

DAI prevents ARP spoofing.

---

## Question 4

What is the purpose of gratuitous ARP?

A. Discover remote networks  
B. Announce IP-to-MAC mapping  
C. Assign IP addresses  
D. Encrypt traffic  

### Answer: B. Announce IP-to-MAC mapping

Explanation:

GARP informs devices about the sender's own IP/MAC relationship.

---

## Question 5

A PC wants to send traffic to the Internet. Which MAC address does it need?

A. Internet server MAC  
B. DNS server MAC  
C. Default gateway MAC  
D. ISP router MAC  

### Answer: C. Default gateway MAC

Explanation:

MAC addresses are only used on the local network segment.
