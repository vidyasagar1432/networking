# 1. Overview

A Virtual Private Network (VPN) creates a secure logical connection across an untrusted network such as the Internet. VPNs are commonly used over WAN links to securely connect branch offices, remote users, cloud environments, and enterprise networks.

VPNs provide:

- Confidentiality (encryption)
- Integrity (data protection)
- Authentication (identity verification)
- Secure communication over public networks

---

# 2. Why VPNs Are Needed

## Problem Without VPN

Example:

```
Branch Office

      |

  Internet

      |

Head Office
```

Traffic travels over:

```
Public network
```

Risks:

- Data interception
- Modification
- Unauthorized access

---

## Solution

Create encrypted tunnel:

```
Branch Office

      |

Encrypted VPN Tunnel

      |

Head Office
```

Connects two or more networks using VPN gateways.

# 8. IPsec VPN Fundamentals

## Definition

IPsec:

```
Internet Protocol Security
```

A framework of protocols that secures IP communication.

---

# IPsec Provides

| Feature | Purpose |
|---|---|
| Encryption | Hide data |
| Authentication | Verify sender |
| Integrity | Prevent modification |
| Anti-replay | Prevent packet reuse |

---

# 9. IPsec Components

## Authentication Header (AH)

Provides:

- Authentication
- Integrity

Does NOT provide:

- Encryption

Protocol:

```
IP Protocol 51
```

---

## Encapsulating Security Payload (ESP)

Provides:

- Encryption
- Authentication
- Integrity

Protocol:

```
IP Protocol 50
```

---

# AH vs ESP

| Feature | AH | ESP |
|---|---|---|
| Encryption | No | Yes |
| Authentication | Yes | Yes |
| Integrity | Yes | Yes |
| Common usage | Rare | Common |

---

# 10. IPsec Modes

## Transport Mode

Encrypts:

```
Payload only
```

Used mainly:

- Host-to-host communication

---

## Tunnel Mode

Encrypts:

```
Entire original IP packet
```

Used mainly:

- Site-to-site VPNs

---

# Transport vs Tunnel

| Feature | Transport | Tunnel |
|---|---|---|
| Encryption | Payload | Entire packet |
| Use case | Host VPN | Site VPN |
| New IP header | No | Yes |

---

# 11. IPsec VPN Operation

Basic process:

```
1. Peer authentication

        ↓

2. Secure tunnel creation

        ↓

3. Encryption keys exchange

        ↓

4. Data transmission
```

# 15. GRE Over VPN

## GRE

```
Generic Routing Encapsulation
```

Creates tunnels between routers.

---

# GRE Provides

- Multicast support
- Routing protocol support
- Multiple protocol transport

---

# GRE Does NOT Provide

- Encryption
- Authentication

---

# GRE + IPsec

Common design:

```
Routing Protocol

      |

GRE Tunnel

      |

IPsec Encryption

      |

Internet
```

---

# GRE vs IPsec

| Feature | GRE | IPsec |
|---|---|---|
| Encryption | No | Yes |
| Routing protocols | Yes | Limited |
| Security | Low | High |
| Common use | Tunnel transport | Secure tunnel |

```

```
Private tunnel address

# 18. VPN Troubleshooting

## Problem 1: Tunnel Not Establishing

Check:

- Peer reachability
- Authentication
- Encryption settings
- Firewall rules

---

Commands:

```bash
show crypto isakmp sa
```

(IKEv1)

---

```bash
show crypto ikev2 sa
```

(IKEv2)

---

Check IPsec:

```bash
show crypto ipsec sa
```

---

# Problem 2: Tunnel Up but No Traffic

Possible causes:

- Routing issue
- ACL mismatch
- NAT issue
- Incorrect interesting traffic

---

# Problem 3: VPN Slow Performance

Check:

- Encryption overhead
- Bandwidth
- Latency
- Packet loss

# CCNA Exam Traps

- VPN creates secure tunnels over untrusted networks.
- IPsec ESP provides encryption.
- AH does not encrypt traffic.
- Site-to-site VPN connects networks.
- Remote access VPN connects users.
- GRE does not encrypt.
- GRE over IPsec provides routing support plus security.
- Tunnel mode is commonly used for site-to-site VPNs.
- IKE negotiates IPsec parameters.
- IPsec uses protocol number 50 (ESP).
- AH uses protocol number 51.
