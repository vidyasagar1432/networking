# 1. Overview

Cisco network devices store configuration files that control device operation. Network administrators must regularly back up configurations, restore devices after failures, and transfer IOS files or configuration files between devices and servers. Cisco IOS supports file transfers using protocols such as TFTP and SCP.

---

# 2. Cisco Configuration Files

Cisco IOS uses two main configuration files:

| Configuration | Location | Purpose |
|---|---|---|
| Running-config | RAM | Active configuration |
| Startup-config | NVRAM | Saved configuration used after reboot |

---

# Running Configuration

Command:

```bash
show running-config
```

or:

```bash
show run
```

Characteristics:

- Stored in RAM
- Current active settings
- Lost after power failure if not saved

---

# Startup Configuration

Command:

```bash
show startup-config
```

Characteristics:

- Stored in NVRAM
- Loaded during boot
- Persistent after reboot

---

# 3. Saving Configuration

## Copy Running Configuration to Startup

Command:

```bash
copy running-config startup-config
```

Shortcut:

```bash
copy run start
```

or:

```bash
write memory
```

---

Process:

```
Running-config (RAM)

        |

        |

        ↓

Startup-config (NVRAM)
```

---

# 4. Erasing Configuration

Remove saved configuration:

```bash
erase startup-config
```

or:

```bash

```

---

Reload device:

```bash

```

```

```

# 6. TFTP Fundamentals

## Definition

TFTP:

```
Trivial File Transfer Protocol
```

A simple file transfer protocol commonly used for Cisco configuration backups and IOS images.

---

# TFTP Characteristics

| Feature | Description |
|---|---|
| Transport | UDP |
| Port | 69 |
| Encryption | None |
| Authentication | None |
| Security | Low |

---

# TFTP Operation

```
Cisco Router

      |

      |

TFTP Server

```

The router sends or receives files from the TFTP server.

# 10. TFTP Limitations

| Limitation | Reason |
|---|---|
| No encryption | Data sent in clear text |
| No authentication | Anyone can access |
| UDP based | Less reliable |
| Not suitable for sensitive data | Security risk |

---

# 11. SCP Fundamentals

## Definition

SCP:

```
Secure Copy Protocol
```

Uses SSH to securely transfer files.

---

# SCP Characteristics

| Feature | Description |
|---|---|
| Transport | TCP |
| Port | 22 |
| Encryption | Yes |
| Authentication | SSH credentials |
| Security | High |

---

# SCP Advantages

- Encrypted transfer
- User authentication
- Secure backup method
- Suitable for production networks

---

# 15. TFTP vs SCP Comparison

| Feature | TFTP | SCP |
|---|---|---|
| Protocol | TFTP | SSH |
| Transport | UDP | TCP |
| Port | 69 | 22 |
| Encryption | No | Yes |
| Authentication | No | Yes |
| Security | Low | High |
| Usage | Legacy backups | Modern secure transfers |

# CCNA Exam Traps

- Running-config is stored in RAM.
- Startup-config is stored in NVRAM.
- `copy run start` saves configuration.
- TFTP uses UDP port 69.
- SCP uses SSH and TCP port 22.
- SCP is encrypted; TFTP is not.
- `copy running-config tftp:` backs up active configuration.
- `copy startup-config tftp:` backs up saved configuration.
- `copy tftp: running-config` merges configuration into RAM.
- `erase startup-config` removes saved configuration.
