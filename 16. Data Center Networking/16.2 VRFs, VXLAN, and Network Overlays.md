# VRFs, VXLAN, and Network Overlays

## CCNP Enterprise (ENCOR 350-401) & CCNP Data Center (DCCOR) Level

**CCNA Relevance: Limited (basic VRF awareness only).**  
**CCNP ENCOR Relevance: High — VRFs, overlays, VXLAN concepts, and network virtualization are important enterprise topics.**  
**CCNP Data Center Relevance: Very High — VXLAN EVPN and network overlays are foundational technologies in modern data centers.**

---

# 1. Overview

Modern enterprise and cloud networks must support:

- Multi-tenancy
- Workload mobility
- Large-scale Layer 2 domains
- Cloud connectivity
- Data center virtualization
- Software-defined networking (SDN)

Traditional VLANs alone cannot meet these requirements. Technologies such as **VRFs**, **VXLAN**, and **network overlays** provide scalable network virtualization.

---

# 2. Traditional Network Limitations

Consider a large enterprise:

```
        Data Center

           |

     +-------------+

     | Core Switch |

     +-------------+

      |         |

  VLAN10     VLAN20

```

Problems:

- VLAN limit (4094 VLANs)
- STP blocking
- Difficult workload mobility
- Large Layer 2 domains
- Complex multi-tenant designs

---

# 3. Network Virtualization

Network virtualization creates multiple **logical networks** on top of the same physical infrastructure.

Example:

```
        Physical Network

+------------------------------+

      Tenant A

      Tenant B

      Tenant C

+------------------------------+
```

Each tenant behaves as if it owns its own network.

---

# 4. Underlay vs Overlay

Modern fabrics consist of two independent networks.

```
Application

        |

 Overlay Network

        |

 Underlay Network

        |

 Physical Links
```

---

# 5. Underlay Network

The **underlay** is the physical IP network.

Responsibilities:

- Physical connectivity
- IP routing
- ECMP
- Fast convergence
- Transport for overlays

Typical routing protocols:

- OSPF
- IS-IS
- eBGP

---

# 6. Overlay Network

The **overlay** is a logical network built on top of the underlay.

Responsibilities:

- Virtual Layer 2 segments
- Tenant isolation
- Workload mobility
- Encapsulation

Common overlay technologies:

- VXLAN
- GRE
- Geneve

---

# 7. Underlay vs Overlay

| Feature | Underlay | Overlay |
|----------|----------|----------|
| Type | Physical | Logical |
| Routing | IP | Encapsulated |
| Devices | Routers/Switches | Virtual Networks |
| Visibility | Physical | Tenant/Application |

---

# 8. What is a VRF?

## VRF = Virtual Routing and Forwarding

A VRF creates **multiple independent routing tables** on a single router or Layer 3 switch.

Think of a VRF as creating several "virtual routers" inside one physical device.

---

# 9. Why Use VRFs?

Without VRFs:

```
Router

↓

One Routing Table

↓

All Networks Together
```

With VRFs:

```
Router

|

+--------+

VRF A

|

Routing Table A

+--------+

VRF B

|

Routing Table B

```

Traffic is isolated between VRFs.

---

# 10. VRF Example

Company hosts two customers:

```
Customer A

10.0.0.0/24

Customer B

10.0.0.0/24
```

Normally impossible because of overlapping addresses.

Using VRFs:

```
VRF A

10.0.0.0/24

↓

Independent

VRF B

10.0.0.0/24
```

Both networks coexist on the same router.

---

# 11. VRF Components

Each VRF has:

- Routing table
- Forwarding table (FIB)
- Interfaces
- Static routes
- Dynamic routing instances

---

# 12. VRF Configuration (Basic Example)

Create a VRF:

```bash
vrf definition CUSTOMER_A
```

Assign an interface:

```bash
interface GigabitEthernet0/0

 vrf forwarding CUSTOMER_A

 ip address 10.1.1.1 255.255.255.0
```

---

# 13. Verifying VRFs

Show VRFs:

```bash
show vrf
```

Routing table for a VRF:

```bash
show ip route vrf CUSTOMER_A
```

# 15. VXLAN Overview

## VXLAN = Virtual Extensible LAN

VXLAN is an overlay protocol that extends Layer 2 networks across a Layer 3 infrastructure.

Instead of relying on VLANs, VXLAN encapsulates Ethernet frames inside UDP packets.

---

# 16. Why VXLAN?

Traditional VLANs have limitations:

```
Maximum VLANs

4094
```

Large cloud providers require:

```
Millions of Virtual Networks
```

VXLAN supports:

```
16 Million+

Segments
```

---

# 17. VXLAN Architecture

```
VM

↓

Leaf Switch

↓

IP Network

↓

Leaf Switch

↓

VM
```

The underlay only sees IP packets.

The virtual Layer 2 network exists in the overlay.

---

# 18. VXLAN Encapsulation

Original Ethernet frame:

```
Ethernet

IP

TCP

Data
```

VXLAN adds headers:

```
Outer Ethernet

Outer IP

UDP

VXLAN Header

Original Ethernet Frame

```

---

# 19. VXLAN Header

The VXLAN header contains a **VXLAN Network Identifier (VNI)**.

```
VXLAN Header

↓

24-bit VNI
```

---

# 20. VLAN vs VNI

| Feature | VLAN | VXLAN |
|----------|------|--------|
| Identifier | 12-bit VLAN ID | 24-bit VNI |
| Maximum | 4094 | ~16.7 Million |
| Scope | Local | Data Center/Cloud |
| Transport | Layer 2 | UDP over Layer 3 |

---

# 21. VNI (VXLAN Network Identifier)

Each VXLAN segment has a unique VNI.

Example:

| Tenant | VNI |
|----------|-----|
| HR | 10010 |
| Finance | 10020 |
| Engineering | 10030 |

VNI functions similarly to a VLAN but at a much larger scale.

---

# 22. VTEP (VXLAN Tunnel Endpoint)

A **VTEP** is the device responsible for:

- Encapsulating Ethernet frames into VXLAN packets
- Decapsulating VXLAN packets back into Ethernet frames

Usually implemented on:

- Leaf switches
- Hypervisors
- Software switches

---

```
VXLAN Tunnel

↓

Leaf (VTEP)

↓

Host B
```

The intermediate IP network only forwards IP packets.

# 25. EVPN (Ethernet VPN)

Modern VXLAN deployments use **EVPN** as the control plane.

EVPN distributes:

- MAC addresses
- IP addresses
- VNI information
- Host reachability

Control protocol:

```
MP-BGP
```

---

# 26. VXLAN + EVPN

```
Control Plane

↓

EVPN

↓

MP-BGP

-------------------

Data Plane

↓

VXLAN
```

---

# 27. Benefits of EVPN

- No flood-and-learn behavior
- Better scalability
- Faster convergence
- Multi-homing support
- Efficient MAC learning

# 34. Troubleshooting

## VXLAN Connectivity Issues

Check:

- Underlay routing
- VTEP reachability
- MTU consistency
- VNI mapping
- EVPN neighbors

---

## VRF Issues

Verify:

- Interface assignment
- Routing table
- VRF membership
- Route leaking (if required)

---

## Overlay Failure

Check:

- VXLAN tunnels
- BGP EVPN sessions
- Underlay IP reachability
- Encapsulation configuration

---

# 35. Best Practices

- Keep the underlay simple (often eBGP or IS-IS).
- Use **VXLAN EVPN** for modern data center fabrics.
- Deploy **VRFs** for tenant or department isolation.
- Assign unique VNIs for each VXLAN segment.
- Monitor MTU to prevent fragmentation.
- Use ECMP in the underlay for redundancy and load balancing.
- Document VRF-to-VNI mappings clearly.

# CCNP Exam Traps

- **VRF** creates multiple independent routing tables on one device.
- VRFs allow **overlapping IP address spaces**.
- **VXLAN** encapsulates Layer 2 frames inside **UDP** over an IP underlay.
- VXLAN uses a **24-bit VNI**, supporting approximately **16.7 million** segments.
- **VTEPs** encapsulate and decapsulate VXLAN traffic.
- **EVPN** provides the control plane for VXLAN, commonly using **MP-BGP**.
- The **underlay** provides IP connectivity; the **overlay** provides virtual networking.
- VXLAN overcomes the traditional VLAN limit of **4094 VLAN IDs**.
