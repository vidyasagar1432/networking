# Spine-Leaf Architecture

## CCNP Enterprise (ENCOR 350-401) & CCNP Data Center (DCCOR) Level

**CCNA Relevance: Basic awareness only.**  
**CCNP ENCOR Relevance: Medium — Understanding modern campus/data center architectures and SDN evolution is important.**  
**CCNP Data Center Relevance: Very High — Spine-Leaf is the standard architecture for modern data centers.**

---

# 1. Overview

**Spine-Leaf** is a modern **data center network architecture** designed to provide:

- High bandwidth
- Low latency
- High availability
- Predictable performance
- Horizontal scalability

Unlike the traditional **three-tier architecture** (Core, Distribution, Access), Spine-Leaf creates a **non-blocking fabric** where every Leaf switch connects to every Spine switch.

This design minimizes bottlenecks and ensures consistent latency between servers.

---

# 2. Evolution of Data Center Networks

## Traditional Three-Tier Architecture

```
                Core

                 |

      ---------------------

      |                   |

 Distribution        Distribution

      |                   |

   --------           --------

   |      |           |      |

 Access Access     Access Access

   |      |           |      |

 Servers Servers   Servers Servers
```

Problems:

- Multiple hops
- STP blocking
- Oversubscription
- Bottlenecks
- Limited scalability

---

## Modern Spine-Leaf Architecture

```
          Spine1      Spine2

             | \      / |

             |  \    /  |

             |   \  /   |

             |    \/    |

             |    /\    |

             |   /  \   |

             |  /    \  |

             | /      \ |

        Leaf1 Leaf2 Leaf3 Leaf4

          |      |      |      |

       Servers Servers Servers Servers
```

Every Leaf connects to every Spine.

---

# 3. Why Spine-Leaf?

Modern applications generate significant **East-West traffic** (server-to-server communication) rather than **North-South traffic** (client-to-server).

Examples:

- Kubernetes
- VMware clusters
- Storage replication
- AI workloads
- Microservices
- Distributed databases

Traditional networks struggle with this traffic pattern.

---

    |

```

```

```

# 5. Spine Layer

The Spine layer acts as the **high-speed backbone**.

Responsibilities:

- Connect all Leaf switches
- Forward traffic
- High-speed routing
- Low latency
- High availability

Characteristics:

- No servers connect directly
- Usually identical hardware
- Full-mesh with Leafs

---

# 6. Leaf Layer

Leaf switches connect:

- Servers
- Storage
- Firewalls
- Load balancers
- Hypervisors

Each Leaf connects to **every Spine**.

---

# 7. Basic Topology

```
          Spine A

        /   |   \

Leaf1 Leaf2 Leaf3

   |     |     |

Servers Servers Servers
```

Add another Spine:

```
      Spine1   Spine2

        |\     /|

        | \   / |

        |  \ /  |

        |  / \  |

        | /   \ |

Leaf1 Leaf2 Leaf3
```

Every Leaf has a connection to every Spine.

---

# 8. Packet Forwarding

Example:

```
Server A

↓

Leaf1

↓

Spine2

↓

Leaf3

↓

Server B
```

Every server-to-server path is:

```
Leaf

↓

Spine

↓

Leaf
```

Only **two Layer 3 hops** regardless of server location.

---

# 9. Equal-Cost Multipath (ECMP)

Since multiple Spine switches exist:

```
Leaf1

↓

Spine1

↓

Leaf2

OR

Leaf1

↓

Spine2

↓

Leaf2

OR

Leaf1

↓

Spine3

↓

Leaf2
```

All paths have equal cost.

---

Benefits:

- Load balancing
- Redundancy
- Better bandwidth
- Fast failover

---

# 10. ECMP Example

Leaf1             Leaf2

          Spine2
```

Traffic may use:

```
Leaf1

↓

Spine1

↓

Leaf2
```

or

```
Leaf1

↓

Spine2

↓

Leaf2
```

# 11. Routing Protocols

Common routing protocols:

| Protocol | Usage |
|----------|-------|
| OSPF | Enterprise fabrics |
| IS-IS | Large-scale fabrics |
| eBGP | Modern Clos fabrics (most common) |

Many modern data centers prefer **eBGP** because of its scalability and simplicity.

---

# 12. Why eBGP?

Advantages:

- Fast convergence
- Easy policy control
- Scalable
- Vendor-neutral
- Excellent ECMP support

Many hyperscale data centers run **eBGP between every Leaf and Spine**.

---

# 13. Underlay Network

The **underlay** is the physical IP network.

Responsibilities:

- IP connectivity
- Routing
- ECMP
- Fast convergence

Example:

```
Leaf

↓

IP Link

↓

Spine
```

---

# 14. Overlay Network

The **overlay** is a virtual network built on top of the underlay.

Common technologies:

- VXLAN
- EVPN
- Geneve

Provides:

- Layer 2 extension
- Tenant isolation
- Virtual networking

---

# 15. Underlay vs Overlay

| Feature | Underlay | Overlay |
|----------|----------|----------|
| Purpose | Physical connectivity | Virtual networks |
| Routing | IP | VXLAN/EVPN |
| Visibility | Physical | Logical |
| Technology | OSPF, IS-IS, eBGP | VXLAN, EVPN |

---

# 16. Clos Network

Spine-Leaf is based on the **Clos Network**, invented by Charles Clos.

Characteristics:

- Multiple equal paths
- Non-blocking
- Highly scalable
- Fault tolerant

Modern cloud providers use Clos fabrics extensively.

# 27. Troubleshooting

## Unequal Traffic Distribution

Check:

- ECMP enabled
- Routing protocol
- Hash algorithm

---

## Spine Failure

Verify:

```bash
show ip route
```

Ensure alternate paths exist.

---

## Overlay Issues

Check:

- VXLAN tunnels
- EVPN neighbors
- Underlay routing
- MTU consistency

---

# 28. Best Practices

- Use Layer 3 links between Leafs and Spines.
- Deploy ECMP for load balancing.
- Use eBGP or IS-IS for the underlay.
- Use VXLAN EVPN for overlays.
- Keep Spine switches stateless (no direct server connections).
- Use identical Spine hardware where possible.
- Design for horizontal scaling from the start.

---

# CCNP Exam Traps

- Every **Leaf connects to every Spine**.
- **Spines never connect directly to end hosts**.
- Typical server-to-server traffic traverses **Leaf → Spine → Leaf**.
- **ECMP** provides load balancing and redundancy.
- Modern data centers favor **Layer 3 fabrics** over large Layer 2 domains.
- **eBGP** is increasingly common as the underlay routing protocol.
- **VXLAN EVPN** is the most common overlay technology in modern data centers.
- Adding a **Leaf** increases port capacity; adding a **Spine** increases fabric bandwidth.
- Spine-Leaf is based on the **Clos network** architecture.
