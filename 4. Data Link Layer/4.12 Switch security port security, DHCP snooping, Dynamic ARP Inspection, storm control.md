**CCNP ENCOR Relevance: Yes — Layer 2 security mechanisms are important enterprise switching concepts, especially access-layer protection and troubleshooting.**

# 1. Overview

Switch security features protect Layer 2 networks from attacks such as MAC flooding, rogue DHCP servers, ARP spoofing, and broadcast storms. CCNA tests port security, DHCP snooping, Dynamic ARP Inspection (DAI), and storm control configuration and behavior.

---

# 2. Core Concepts

# Layer 2 Security Threats

| Attack | Description | Protection |
|---|---|---|
| MAC flooding | Attacker fills CAM table with fake MAC addresses | Port Security |
| Rogue DHCP server | Unauthorized DHCP server provides wrong settings | DHCP Snooping |
| DHCP starvation | Exhausts DHCP address pool | DHCP Snooping |
| ARP spoofing | Fake ARP replies redirect traffic | Dynamic ARP Inspection |
| Broadcast storm | Excessive broadcast traffic | Storm Control |

---

# Port Security

## Definition

Port Security limits which MAC addresses can connect to a switch port.

Usually configured on access ports.

Example:

```
PC
 |
Switch Access Port
```

---

# Port Security Functions

| Function | Description |
|---|---|
| Limit MAC addresses | Controls devices per port |
| Learn MAC addresses | Static or dynamic |
| Block violations | Protects network access |

---

# Port Security MAC Address Types

| Type | Description |
|---|---|
| Static secure MAC | Manually configured |
| Dynamic secure MAC | Learned automatically |
| Sticky secure MAC | Dynamically learned and saved |

---

# Sticky MAC Address

Definition:

Sticky learning converts dynamically learned MAC addresses into configuration entries.

Example:

Before:

```
Dynamic MAC learning
```

After:

```
Secure sticky MAC
```

Stored in running configuration.

---

# Port Security Maximum

Example:

```
Maximum MAC addresses = 1
```

Only one device can connect.

---

# Port Security Violation Modes

| Mode | Action |
|---|---|
| Shutdown | Default; disables port |
| Restrict | Drops frames and logs violation |
| Protect | Drops frames silently |

---

# Violation Mode Comparison

| Feature | Shutdown | Restrict | Protect |
|---|---|---|---|
| Drops traffic | Yes | Yes | Yes |
| Logs violation | Yes | Yes | No |
| Sends SNMP alert | Yes | Yes | No |
| Port state | Err-disabled | Active | Active |

---

# DHCP Snooping

## Definition

DHCP Snooping is a Layer 2 security feature that prevents rogue DHCP servers and builds a trusted DHCP binding table.

---

# DHCP Snooping Trust Model

Ports are divided into:

| Port Type | Description |
|---|---|
| Trusted port | DHCP server/uplink |
| Untrusted port | User access ports |

---

# DHCP Snooping Example

Normal:

```
             DHCP Server
                  |
             Trusted Port
                  |
              Switch
                  |
          ----------------
          |              |
        PC1            PC2
     Untrusted     Untrusted
```

---

# DHCP Snooping Behavior

Trusted port:

Allows:

```
DHCP OFFER
DHCP ACK
```

Untrusted port:

Blocks:

```
DHCP Server Messages
```

---

# DHCP Snooping Binding Table

Stores:

| Field | Example |
|---|---|
| MAC Address | AA:BB:CC:DD:EE:FF |
| IP Address | 192.168.1.10 |
| VLAN | 10 |
| Interface | Gi0/1 |
| Lease Time | Remaining time |

---

# DHCP Snooping Protection

Prevents:

| Attack | Result |
|---|---|
| Rogue DHCP server | Blocked |
| DHCP starvation | Reduced |
| Fake DHCP replies | Blocked |

---

# Dynamic ARP Inspection (DAI)

## Definition

DAI validates ARP packets against the DHCP Snooping binding database to prevent ARP spoofing.

---

# ARP Spoofing Attack

Normal:

```
PC ---- ARP Request ---- Gateway
```

Attack:

```
Attacker sends:

"I am the gateway"
```

Result:

Traffic redirected.

---

# DAI Operation

Process:

```
ARP Packet
     |
     v
DAI checks binding table
     |
     v
Valid?
 |
 +---- Yes ---> Forward
 |
 +---- No ----> Drop
```

---

# DAI Requirements

| Requirement | Needed |
|---|---|
| DHCP Snooping | Yes |
| Trusted ports configured | Yes |
| VLAN enabled for DAI | Yes |

---

# DAI Trusted Ports

Example:

```
Switch ---- Router
```

Router uplink:

```
Trusted
```

User ports:

```
Untrusted
```

---

# Storm Control

## Definition

Storm Control limits excessive broadcast, multicast, and unknown unicast traffic.

---

# Traffic Types Protected

| Traffic Type | Example |
|---|---|
| Broadcast | ARP, DHCP |
| Multicast | Streaming traffic |
| Unknown unicast | Unknown destination MAC |

---

# Storm Control Operation

Example:

Limit:

```
Broadcast traffic > 20%
```

Action:

```
Drop excessive traffic
```

---

# Storm Control Actions

| Action | Description |
|---|---|
| Shutdown | Disable interface |
| Trap | Send notification |
| Drop | Discard traffic |

---

# Security Feature Comparison

| Feature | Protects Against | Works With |
|---|---|---|
| Port Security | MAC attacks | MAC addresses |
| DHCP Snooping | Rogue DHCP | DHCP messages |
| DAI | ARP spoofing | DHCP database |
| Storm Control | Traffic storms | Broadcast/multicast |

# 3. Worked Examples

## Example 1: Port Security Violation

### Scenario

A switch port allows:

```
Maximum MAC addresses = 1
```

Current device:

```
PC-A
MAC: AA-AA-AA-AA-AA-AA
```

A new device connects:

```
PC-B
MAC: BB-BB-BB-BB-BB-BB
```

Violation mode:

```
Shutdown
```

---

### Solution

Step 1:

Switch sees second MAC address.

Step 2:

Maximum limit exceeded.

Step 3:

Violation occurs.

Result:

```
Interface enters err-disabled state
```

---

## Example 2: DHCP Snooping + DAI

### Scenario

An attacker sends:

```
ARP:
"I am the default gateway"
```

Switch has:

```
DHCP Snooping enabled
DAI enabled
```

---

### Solution

Step 1:

DAI receives ARP packet.

Step 2:

Checks DHCP Snooping binding table.

Step 3:

MAC/IP mapping does not match.

Step 4:

ARP packet is dropped.

Result:

```
ARP spoofing prevented
```

# 5. Exam Traps

- Port security works mainly on access ports.
- Default port-security violation mode is shutdown.
- Sticky MAC addresses are dynamically learned but saved.
- DHCP Snooping trusts DHCP server ports, not user ports.
- DAI depends on DHCP Snooping binding information.
- DAI checks ARP IP-to-MAC mappings.
- Storm Control does not prevent all attacks; it limits traffic volume.
- DHCP Snooping blocks rogue DHCP servers.
- BPDU Guard protects against rogue switches, not DHCP attacks.
- Port Security limits MAC addresses, not IP addresses.
- Trusted ports should be configured toward infrastructure devices.

# 7. Practice Questions

## Question 1

Which feature prevents unauthorized devices from using a switch port?

A. DHCP Snooping  
B. Port Security  
C. DAI  
D. Storm Control  

### Answer: B. Port Security

Explanation:

Port Security limits allowed MAC addresses.

---

## Question 2

Which feature prevents rogue DHCP servers?

A. Port Security  
B. DHCP Snooping  
C. DAI  
D. STP  

### Answer: B. DHCP Snooping

Explanation:

DHCP Snooping blocks DHCP server messages from untrusted ports.

---

## Question 3

DAI protects against which attack?

A. VLAN hopping  
B. ARP spoofing  
C. MAC flooding  
D. Broadcast storm  

### Answer: B. ARP spoofing

Explanation:

DAI validates ARP packets against trusted information.

---

## Question 4

What happens when a port-security violation occurs in shutdown mode?

A. Traffic is slowed  
B. Port becomes err-disabled  
C. VLAN is deleted  
D. MAC table clears  

### Answer: B. Port becomes err-disabled

Explanation:

Shutdown mode disables the interface.

---

## Question 5

Which feature limits excessive broadcast traffic?

A. DAI  
B. DHCP Snooping  
C. Storm Control  
D. PortFast  

### Answer: C. Storm Control

Explanation:

Storm Control limits broadcast, multicast, and unknown unicast traffic.
