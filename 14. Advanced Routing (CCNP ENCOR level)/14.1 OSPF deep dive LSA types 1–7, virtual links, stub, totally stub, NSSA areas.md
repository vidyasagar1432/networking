# 1. Overview

OSPF (Open Shortest Path First) is a link-state interior gateway protocol (IGP) that uses the **SPF (Shortest Path First) algorithm** to calculate the best path through an IP network. At CCNP level, engineers must understand how OSPF builds its topology database, how LSAs propagate between areas, and how different area types reduce routing table size and LSA flooding.

OSPF uses a hierarchical design based on **areas**, with **Area 0 (backbone area)** being the central connection point.

# 2. OSPF Review

## OSPF Characteristics

| Feature | Value |
|---|---|
| Protocol | Link-state IGP |
| Algorithm | Dijkstra SPF |
| Administrative Distance | 110 |
| Multicast Address | 224.0.0.5 / 224.0.0.6 |
| IP Protocol Number | 89 |
| Metric | Cost |
| Standard | RFC 2328 (OSPFv2) |
| IPv6 Version | OSPFv3 |

# 3. OSPF Router Roles

| Router Type | Function |
|---|---|
| Internal Router | All interfaces in same area |
| Backbone Router | Connected to Area 0 |
| ABR | Connects multiple areas |
| ASBR | Connects OSPF to external networks |

# 4. OSPF Hierarchical Design

Example:

```
             Area 1

               |

              ABR

               |

            Area 0

               |

              ABR

               |

             Area 2
```

---

Benefits:

- Smaller LSDB
- Faster SPF calculations
- Reduced LSA flooding
- Better scalability

# 5. OSPF Database Components

## Link-State Database (LSDB)

Contains:

- Router information
- Network information
- External routes
- Area information

All routers in the same area should have an identical LSDB.

---

# 6. OSPF LSA Overview

LSA:

```
Link-State Advertisement
```

LSAs describe network topology information.

They are stored in:

```
OSPF LSDB
```

---

# LSA Types Summary

| Type | Name | Generated By | Purpose |
|---|---|---|---|
| 1 | Router LSA | Every OSPF router | Router links |
| 2 | Network LSA | DR | Multi-access network |
| 3 | Summary LSA | ABR | Inter-area routes |
| 4 | ASBR Summary LSA | ABR | Reach ASBR |
| 5 | External LSA | ASBR | External routes |
| 6 | Group Membership LSA | MOSPF | Multicast routing |
| 7 | NSSA External LSA | NSSA ASBR | External routes inside NSSA |

---

# 7. LSA Type 1 — Router LSA

## Generated By

Every OSPF router.

---

## Purpose

Describes:

- Router ID
- Connected links
- Interface states
- OSPF cost

---

Example:

```
Router R1

Links:

G0/0
Cost 10

G0/1
Cost 20
```

---

## Flooding Scope

Within:

```
Same Area
```

---

Command:

```bash
show ip ospf database router
```


# 10. LSA Type 4 — ASBR Summary LSA

## Generated By

ABR

---

## Purpose

Provides a path to an ASBR.

Example:

```
External Network

      |

     ASBR

      |

    Area 0

```

Other areas need to know:

```
How to reach ASBR
```

---

# 11. LSA Type 5 — External LSA

## Generated By

ASBR

---

## Purpose

Advertises external routes.

Examples:

- Static routes
- BGP routes
- Another IGP

---

Example:

```
Internet

   |

 ASBR

   |

OSPF

```

---

Routes appear as:

```
O E1
O E2
```

---

## Type 5 Not Allowed In:

- Stub areas
- Totally stub areas
- NSSA areas (uses Type 7)

# 17. Stub Area

## Purpose

Reduce LSDB size.

Restrictions:

Blocks:

```
Type 5 LSA
```

---

Instead:

ABR advertises:

```
Default Route

0.0.0.0/0
```

---

Allows:

| LSA | Allowed |
|-|-|
| Type 1 | Yes |
| Type 2 | Yes |
| Type 3 | Yes |
| Type 4 | Yes |
| Type 5 | No |

---

Configuration:

```bash
router ospf 1

area 1 stub
```

---

# 18. Totally Stubby Area

Cisco proprietary.

## Blocks:

- Type 3
- Type 4
- Type 5

Only allows:

- Type 1
- Type 2

---

ABR sends:

```
Default route only
```

---

Benefits:

- Smallest LSDB
- Less SPF calculation

---

Configuration:

ABR:

```bash
area 1 stub no-summary
```

---

# 19. NSSA (Not-So-Stubby Area)

Problem:

Stub areas cannot have ASBRs.

NSSA allows:

```
External routes inside stub-like area
```

---

Allows:

- Type 1
- Type 2
- Type 3
- Type 7

Blocks:

- Type 5

---

Example:

```
NSSA Area

Router

 |

ASBR

 |

Internet
```

---

Configuration:

```bash
router ospf 1

area 1 nssa
```

---

# 20. Totally NSSA

Combination of:

```
NSSA + Totally Stubby
```

- Type 3
- Type 4
- Type 5

Allows:

- Type 1
- Type 2
- Type 7

```
Default Route
```


# 22. Virtual Links

## Definition

A virtual link creates a logical connection through a non-backbone area to connect an area to Area 0.

---

# OSPF Rule

Every area must connect to:

```
Area 0
```

---

Problem:

```
Area 0

 |

Area 1

 |

Area 2
```

Area 2 has no direct connection.

---

Solution:

```
Virtual Link
```

---

# 23. Virtual Link Example

Before:

```
Area 0

 |

Area 1

 |

Area 2
```

After:

```
Area 0

 |

Area 1

========

Virtual Link

========

Area 2
```

---

# 24. Virtual Link Configuration

Example:

Router connected through Area 1:

```bash
router ospf 1

area 1 virtual-link 2.2.2.2
```

Where:

```
2.2.2.2 = Remote Router ID
```

---

# 25. Virtual Link Requirements

Both routers must:

- Be ABRs
- Share transit area
- Know each other's Router ID

# CCNP Design Guidelines

## Use Stub Areas When:

- Branch offices
- No external routes needed

---

## Use Totally Stub Areas When:

- Small remote sites
- Default route is enough

---

## Use NSSA When:

- Area needs local ASBR
- External routes must enter

---

## Avoid Virtual Links When:

- Designing new networks

They are mainly for:

- Migration
- Temporary fixes
