# 1. Overview

EIGRP (Enhanced Interior Gateway Routing Protocol) is an advanced distance-vector routing protocol developed by Cisco. It uses the **DUAL (Diffusing Update Algorithm)** to provide fast convergence while maintaining loop-free routing.

At CCNP level, engineers must understand advanced EIGRP features such as **named mode configuration**, **wide metrics**, **topology tables**, and **unequal-cost load balancing using variance**.

---

# 2. EIGRP Characteristics

| Feature | Value |
|---|---|
| Protocol Type | Advanced distance vector / Hybrid |
| Algorithm | DUAL |
| Administrative Distance | 90 (Internal), 170 (External) |
| Metric | Composite metric |
| Multicast Address | 224.0.0.10 |
| IP Protocol | 88 |
| Transport | Reliable Transport Protocol (RTP) |
| Neighbor Discovery | Hello packets |

---

# 3. EIGRP Components

EIGRP uses three major tables:

| Table | Purpose |
|---|---|
| Neighbor Table | Stores EIGRP neighbors |
| Topology Table | Stores all learned paths |
| Routing Table | Stores best paths |

---

# 4. DUAL Algorithm Review

DUAL provides:

- Loop-free routing
- Fast convergence
- Backup path selection

---

Important terms:

| Term | Meaning |
|---|---|
| Successor | Best route |
| Feasible Successor | Backup loop-free route |
| Feasible Distance (FD) | Metric of best path |
| Reported Distance (RD) | Neighbor's metric to destination |

---

# 5. Feasibility Condition

A route becomes a feasible successor when:

```
Reported Distance < Feasible Distance
```

Meaning:

The neighbor must be closer to the destination than the current router.

---

Example:

```
Router A

Best path FD = 100

Backup path RD = 80

```

Because:

```
80 < 100
```

The route qualifies as a feasible successor.

---

# 6. EIGRP Metric

Traditional EIGRP metric:

```
Metric =
Bandwidth + Delay
```

Default:

```
K1 = 1
K3 = 1
K2 = 0
K4 = 0
K5 = 0
```

Only:

- Bandwidth
- Delay

are used.

# 7. EIGRP Named Mode

## Definition

Named mode is the modern EIGRP configuration style introduced in IOS.

It replaces the older:

```
router eigrp AS-number
```

configuration.

---

Traditional mode:

```bash
router eigrp 100

network 10.0.0.0
```

---

Named mode:

```bash
router eigrp EIGRP-NETWORK
```

---

# 8. Named Mode Structure

Named mode has a hierarchy:

```
router eigrp NAME

        |

 address-family

        |

 autonomous-system

        |

 topology

        |

 interface
```

---

Example:

```
router eigrp CAMPUS

 address-family ipv4 unicast autonomous-system 100

  topology base

  network 10.0.0.0

```

---

# 9. Named Mode Advantages

| Advantage | Description |
|---|---|
| Organized configuration | Hierarchical structure |
| Supports IPv4/IPv6 | Single process |
| Easier troubleshooting | Clear separation |
| Supports advanced features | Modern IOS features |
| Supports wide metrics | Better scalability |

---

# 10. Named Mode Configuration Example

Enable EIGRP:

```bash
router eigrp CAMPUS
```

Configure IPv4 address family:

```bash
address-family ipv4 unicast autonomous-system 100
```

Add network:

```bash
network 10.1.0.0 0.0.0.255
```

---

Enable interface:

```bash
interface GigabitEthernet0/0

 ip eigrp CAMPUS
```

# 12. Unequal-Cost Load Balancing

## Definition

EIGRP can distribute traffic across multiple paths even when their metrics are different.

This is called:

```
Unequal-Cost Load Balancing
```

---

Example:

Normal routing:

```
Path A
Metric 100

Path B
Metric 200

Only Path A used
```

---

With EIGRP variance:

```
Path A
Metric 100

Path B
Metric 200

Both used
```

---

# 13. Equal-Cost vs Unequal-Cost Load Balancing

| Feature | Equal Cost | Unequal Cost |
|---|---|---|
| Metrics | Same | Different |
| Protocols | Most routing protocols | EIGRP |
| Configuration | Default | variance required |
| Traffic sharing | Automatic | Controlled |

---

# 14. Variance Command

The variance command controls how much higher a backup route metric can be compared to the best route.

Syntax:

```bash
variance multiplier
```

Range:

```
1 - 128
```

---

Default:

```
variance 1
```

Meaning:

Only equal-cost paths.

---

# 15. Variance Calculation

Formula:

```
Maximum Allowed Metric =
Best Metric × Variance
```

---

Example:

Best path:

```
FD = 100
```

Variance:

```
2
```

Calculation:

```
100 × 2 = 200
```

Any feasible path with metric:

```
≤ 200
```

can participate.

---

# 16. Unequal Load Balancing Requirements

A path must satisfy:

## Requirement 1

Must be a feasible successor.

Meaning:

```
RD < FD
```

---

## Requirement 2

Metric must be within variance.

Example:

```
Path Metric ≤ FD × Variance
```

---

# 17. Unequal Load Balancing Example

Topology:

```
          R2
        /    \
       /      \
      R1       R3

```

Routes:

| Path | Metric |
|-|-|
| R1-R2 | 100 |
| R1-R3 | 150 |

Configure:

```bash
router eigrp 100

variance 2
```

Calculation:

```
100 × 2 = 200
```

Both paths qualify.

Traffic:

```
R1

↓

R2 + R3
```

---

# 18. Traffic Sharing Method

EIGRP supports:

## Per-Destination Load Balancing

Default.

Example:

```
Flow 1 → Path A

Flow 2 → Path B
```

---

## Per-Packet Load Balancing

Every packet can use different paths.

Configured:

```bash
ip load-sharing per-packet
```

Usually avoided because packets may arrive out of order.

# 21. EIGRP Troubleshooting

## Neighbor Not Forming

Check:

```bash
show ip eigrp neighbors
```

Possible causes:

- Wrong AS number
- Wrong K-values
- Authentication mismatch
- Interface passive
- Network mismatch

---

## Unequal Load Balancing Not Working

Check:

1. Feasible successor exists

```bash
show ip eigrp topology
```

2. Variance configured

```bash
show running-config
```

3. Route metric qualifies

# 22. EIGRP Design Recommendations

Use:

- Named mode for new deployments
- Route summarization at boundaries
- Stub routing for branches
- Authentication for security
- Unequal load balancing carefully
