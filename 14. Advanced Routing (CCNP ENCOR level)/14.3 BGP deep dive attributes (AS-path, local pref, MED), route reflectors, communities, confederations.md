# 1. Overview

BGP (Border Gateway Protocol) is the Internet's primary **Exterior Gateway Protocol (EGP)** used for exchanging routing information between autonomous systems (AS). Unlike OSPF and EIGRP, which focus on finding the shortest path, BGP uses **path attributes and policies** to select the best route.

At CCNP level, engineers must understand BGP path selection, important attributes, iBGP scaling challenges, and solutions such as route reflectors and confederations.

# 3. Autonomous System (AS)

## Definition

An Autonomous System is a group of networks controlled by a single organization with a common routing policy.

Examples:

- ISP network
- Enterprise network
- Cloud provider

---

Example:

```
AS 65001

Enterprise Network

        |

      BGP

        |

AS 65002

ISP Network
```

# 4. eBGP vs iBGP

| Feature | eBGP | iBGP |
|---|---|---|
| Purpose | Between different AS | Within same AS |
| AS Number | Different | Same |
| AD | 20 | 200 |
| TTL | 1 by default | 255 |
| Next-Hop Handling | Changes next hop | Usually preserves next hop |

# 7. BGP Path Attributes

BGP chooses routes using attributes.

Major attributes:

| Attribute | Purpose |
|---|---|
| Weight | Cisco-specific preference |
| Local Preference | Internal AS preference |
| AS Path | Path length |
| Origin | Route source |
| MED | External preference |
| Next Hop | Next-hop router |
| Community | Route tagging |

---

# 8. BGP Best Path Selection Order (Cisco)

Simplified order:

```
1. Highest Weight

2. Highest Local Preference

3. Locally originated route

4. Shortest AS Path

5. Lowest Origin Type

6. Lowest MED

7. eBGP over iBGP

8. Lowest IGP metric to next hop

9. Oldest route

10. Lowest Router ID
```

---

# 9. Weight Attribute

## Definition

Cisco-specific attribute used to prefer routes locally.

Range:

```
0 - 65535
```

Default:

```
0
```

Local router originated:

```
32768
```

---

Higher weight wins.

Example:

```
Path A Weight = 500

Path B Weight = 200

Winner:

Path A
```

---

Configuration:

```bash
neighbor 10.1.1.1 weight 500
```

---

# 10. Local Preference

## Definition

Local Preference controls outbound traffic from an AS.

Used inside:

```
iBGP
```

---

Rule:

```
Higher Local Preference wins
```

---

Default:

```
100
```

---

Example:

```
          ISP-A
            |
            |
          AS65000
            |
            |
          ISP-B

```

Want traffic leaving through ISP-A:

```
Set higher local preference toward ISP-A
```

---

Configuration:

```bash
router bgp 65000

bgp default local-preference 200
```

---

# 11. AS Path Attribute

## Definition

Lists the autonomous systems a route has passed through.

Example:

```
65010 65020 65030
```

Meaning:

```
Current AS

↓

65010

↓

65020

↓

65030
```

---

Rule:

```
Shortest AS Path wins
```

---

Example:

Path A:

```
65010 65020
```

Length:

```
2
```

Path B:

```
65030 65040 65050
```

Length:

```
3
```

Winner:

```
Path A
```

---

# 12. AS Path Prepending

Used to make a path less preferred.

Adds fake AS numbers.

Example:

Before:

```
65000
```

After:

```
65000 65000 65000
```

Result:

Longer path → less preferred.

# 13. MED (Multi-Exit Discriminator)

## Definition

MED tells external neighbors which entry point to use.

Used between:

```
Different AS
```

---

Rule:

```
Lower MED wins
```

---

Example:

ISP receives:

```
Link A MED = 50

Link B MED = 100
```

ISP prefers:

```
Link A
```

---

# 14. MED vs Local Preference

| Feature | Local Preference | MED |
|-|-|-|
| Direction | Outbound traffic | Inbound traffic |
| Scope | Inside AS | Between AS |
| Winner | Higher | Lower |
| Attribute Type | Well-known | Optional |

---

# 15. Origin Attribute

Shows how route entered BGP.

Values:

| Value | Meaning |
|-|-|
| IGP (i) | Network command |
| EGP (e) | Old protocol |
| Incomplete (?) | Redistribution |

Preference:

```
IGP > EGP > Incomplete
```

# 16. Community Attribute

## Definition

BGP communities are tags attached to routes to apply policies.

Instead of managing individual prefixes:

```
Tag routes

↓

Apply policy
```

---

Example:

```
Community:

65000:100
```

Meaning:

```
Customer routes
```

---

# 17. Common BGP Communities

| Community | Meaning |
|---|---|
| no-export | Do not advertise outside AS |
| no-advertise | Do not advertise anywhere |
| internet | Advertise normally |
| local-AS | Keep within local AS |

---

# 18. Community Configuration Example

Create route-map:

```bash
route-map CUSTOMER permit 10

set community 65000:100
```

Apply:

```bash
neighbor 10.1.1.1 route-map CUSTOMER out
```

# 19. Route Reflectors

## Problem: iBGP Full Mesh

Rule:

iBGP routers do not advertise routes learned from one iBGP neighbor to another iBGP neighbor.

---

Example:

```
       R1

      /  \

    R2----R3

```

Need:

```
Every router peers with every router
```

Problem:

Large networks become difficult.

---

# 20. Route Reflector Solution

A route reflector allows one iBGP router to advertise routes learned from another iBGP neighbor.

---

Topology:

```
        RR

      / | \

    R1 R2 R3

```

RR:

```
Reflects routes
```

---

# 21. Route Reflector Terminology

| Term | Meaning |
|-|-|
| Route Reflector | Central iBGP router |
| Client | Router using RR |
| Non-client | Normal iBGP peer |

---

Configuration:

```bash
router bgp 65000

neighbor 10.1.1.1 route-reflector-client
```

---

# 22. Route Reflector Benefits

| Benefit | Description |
|-|-|
| Reduces sessions | Less peering |
| Improves scalability | Large networks |
| Simplifies design | Easier management |

---

# 23. BGP Confederations

## Definition

Confederations divide one large AS into multiple smaller internal AS numbers.

---

Example:

External view:

```
AS 65000
```

Internal:

```
65001
65002
65003
```

---

# 24. Confederation Purpose

Solves:

- Large iBGP scalability
- Full mesh requirement

---

Topology:

```
        AS65000

   ----------------

   AS65001

   AS65002

   AS65003

```

Externally:

```
Looks like one AS
```

---

# 25. Route Reflector vs Confederation

| Feature | Route Reflector | Confederation |
|-|-|-|
| Method | Reflect routes | Divide AS |
| Complexity | Lower | Higher |
| Scalability | High | High |
| External visibility | Same AS | Appears as one AS |

Check:

```bash
show ip bgp summary
```

- Authentication mismatch

Check:

# 29. BGP Design Guidelines

Use:

- Local preference for outbound path selection
- AS path prepending for inbound control
- MED for multi-link connections
- Communities for scalable policies
- Route reflectors for large iBGP networks
