# 1. Overview

Device hardening is the process of securing network devices by reducing vulnerabilities, limiting unnecessary access, and applying security best practices. CCNA tests basic hardening techniques such as disabling unused services, securing management protocols, using strong authentication, and controlling administrative access.

---

# 2. Core Concepts

# Device Hardening Definition

Device hardening:

```
The process of reducing the attack surface of a network device.
```

---

# Attack Surface

Attack surface includes:

- Open ports
- Enabled services
- Weak passwords
- Insecure protocols
- Unused interfaces
- Poor access controls

---

# Device Hardening Goals

| Goal | Purpose |
|---|---|
| Reduce attack surface | Remove unnecessary features |
| Protect management access | Secure administration |
| Prevent unauthorized access | Control users |
| Improve monitoring | Detect threats |
| Maintain secure configuration | Reduce risks |

---

# Basic Hardening Checklist

| Area | Action |
|---|---|
| Passwords | Use strong passwords |

| Services | Disable unused services |

| Updates | Apply security patches |

# 1. Disable Unused Ports

## Purpose

Unused switch ports can be exploited by attackers.

Example:

```
Unused port

↓

Attacker connects laptop

↓

Unauthorized network access
```

---

# Port Shutdown

Cisco command:

```bash
interface g0/10
shutdown
```

---

# Verify Interface Status

```bash
show interfaces status
```

---

# Best Practice

Unused ports should be:

```
Administratively disabled
```

---

# Assign Unused Ports to Unused VLAN

Example:

```
VLAN 999

Unused Ports
```

Configuration:

```bash
interface range g0/1-10
 switchport access vlan 999
 shutdown
```

---

# 2. Disable Unnecessary Services

## Purpose

Every running service creates a possible security risk.

---

# Common Insecure Services

| Service | Risk |
|---|---|
| Telnet | Sends data in clear text |
| HTTP management | No encryption |
| CDP | Reveals network information |
| Unused routing protocols | Unnecessary exposure |
| Small services | Legacy vulnerabilities |

---

# Disable Telnet

Telnet:

```
Clear-text protocol
```

Replace with:

```
SSH
```

---

# Disable HTTP Server

Command:

```bash
no ip http server
```

---

# Disable HTTPS Server (if unused)

```bash
no ip http secure-server
```

---

# Disable CDP Globally

```bash
no cdp run
```

---

# Disable CDP on Interface

```bash
interface g0/1
 no cdp enable
```

# 4. Exam Traps

- SSH is secure; Telnet is not.
- Device hardening reduces attack surface.
- Unused ports should be disabled.
- `shutdown` disables an interface administratively.
- `enable secret` is more secure than `enable password`.
- AAA provides centralized access control.
- SNMPv3 provides authentication and encryption.
- Logging requires accurate time synchronization.
- Password encryption does not replace strong passwords.
- ACLs control access but do not replace firewalls.
- Security is a layered approach.
