**CCNP ENCOR Relevance: Yes — ACL design, traffic filtering, placement strategy, troubleshooting, and advanced policy control are important CCNP Enterprise concepts.**

---

# 1. Overview

Access Control Lists (ACLs) are rule-based filters used on Cisco devices to control network traffic. CCNA tests ACL types, rule processing, wildcard masks, placement rules, numbered vs named ACLs, and standard vs extended ACL capabilities.

---

# 2. Core Concepts

# ACL Definition

ACL:

```
Access Control List
```

A list of rules that:

- Permit traffic
- Deny traffic
- Control access to network resources

---

# ACL Purpose

ACLs are used for:

| Purpose | Example |
|---|---|
| Traffic filtering | Block unwanted traffic |
| Security | Restrict access |
| Route filtering | Control advertisements |
| NAT control | Select traffic |
| QoS classification | Identify traffic |

---

# ACL Operation

ACL works:

```
Packet arrives

       |

ACL checks rules

       |

Match found?

       |

Permit or Deny
```

---

# ACL Processing Rules

## 1. Top-to-Bottom Processing

ACL entries are checked:

```
First rule → Last rule
```

---

## 2. First Match Wins

Example:

```
deny host 192.168.1.10
permit ip any any
```

Traffic from:

```
192.168.1.10
```

is denied.

---

## 3. Implicit Deny

Every ACL has:

```
deny any
```

at the end automatically.

Example:

Configured:

```
permit 192.168.1.0/24
```

Actually:

```
permit 192.168.1.0/24

deny any
```

---

# ACL Types Overview

| Type | Purpose |
|---|---|
| Standard ACL | Filters based only on source IP |
| Extended ACL | Filters source, destination, protocol, ports |
| Named ACL | Uses descriptive names |
| Numbered ACL | Uses numeric identifiers |

---

# Standard ACL

## Definition

Standard ACLs filter traffic using:

```
Source IPv4 address only
```

---

# Standard ACL Checks

| Field | Supported |
|---|---|
| Source IP | Yes |
| Destination IP | No |
| Protocol | No |
| Port number | No |

---

# Standard ACL Example

Requirement:

```
Block host 192.168.1.10
```

Configuration:

```bash
access-list 10 deny host 192.168.1.10
access-list 10 permit any
```

---

# Standard ACL Number Range

IPv4 standard ACL:

```
1-99
```

Extended standard range:

```
1300-1999
```

---

# Standard ACL Placement

Best practice:

```
Place close to destination
```

Reason:

Standard ACL cannot identify destination.

---

Example:

```
PC

 |

Router

 |

Server
```

Place ACL near:

```
Server network
```

---

# Extended ACL

## Definition

Extended ACLs filter using:

- Source IP
- Destination IP
- Protocol
- Port numbers

---

# Extended ACL Checks

| Field | Supported |
|---|---|
| Source IP | Yes |
| Destination IP | Yes |
| Protocol | Yes |
| TCP/UDP ports | Yes |

---

# Extended ACL Protocol Examples

| Protocol | Keyword |
|---|---|
| TCP | tcp |
| UDP | udp |
| ICMP | icmp |
| IP | ip |

---

# Extended ACL Example

Requirement:

Allow HTTP traffic to server:

```
10.1.1.10
```

Configuration:

```bash
access-list 100 permit tcp any host 10.1.1.10 eq 80
```

---

# Extended ACL Number Range

IPv4 extended ACL:

```
100-199
```

Additional:

```
2000-2699
```

---

# Extended ACL Placement

Best practice:

```
Place close to source
```

Reason:

Prevents unwanted traffic early.

---

# Standard vs Extended ACL

| Feature | Standard ACL | Extended ACL |
|---|---|---|
| Filtering | Source only | Source + destination |
| Protocol filtering | No | Yes |
| Port filtering | No | Yes |
| Number range | 1-99 | 100-199 |
| Placement | Near destination | Near source |
| Complexity | Simple | Advanced |

---

# Numbered ACL

## Definition

ACL identified by a number.

Example:

```bash
access-list 10 permit 192.168.1.0 0.0.0.255
```

---

# Numbered ACL Advantages

- Simple
- Supported on all IOS versions
- Easy for small rules

---

# Numbered ACL Disadvantages

- Hard to remember purpose
- Difficult editing
- Less readable

---

# Named ACL

## Definition

ACL identified by a text name.

Example:

```bash
ip access-list standard BLOCK_USERS
```

---

# Named ACL Advantages

| Advantage | Explanation |
|---|---|
| Readable | Meaningful names |
| Easier editing | Add/remove entries |
| Better management | Large networks |

---

# Named Standard ACL Example

```bash
ip access-list standard BLOCK_USERS
 deny host 192.168.1.10
 permit any
```

---

# Named Extended ACL Example

```bash
ip access-list extended WEB_ACCESS
 permit tcp any host 10.1.1.10 eq 80
 deny ip any any
```

---

# Named vs Numbered ACL

| Feature | Numbered | Named |
|---|---|---|
| Identifier | Number | Name |
| Readability | Lower | Higher |
| Editing | Limited | Easier |
| Enterprise use | Less | More |

---

# Wildcard Masks

ACLs use:

```
Wildcard masks
```

to identify matching addresses.

---

# Wildcard Mask Rules

| Value | Meaning |
|---|---|
| 0 | Must match |
| 1 | Ignore |

---

# Common Wildcard Masks

| Network | Wildcard |
|---|---|
| Single host | 0.0.0.0 |
| /24 network | 0.0.0.255 |
| /16 network | 0.0.255.255 |
| Any address | 255.255.255.255 |

---

# Host Keyword

Instead of:

```
192.168.1.10 0.0.0.0
```

Use:

```bash
host 192.168.1.10
```

---

# Any Keyword

Instead of:

```
0.0.0.0 255.255.255.255
```

Use:

```bash
any
```

---

# ACL Direction

ACLs are applied:

## Inbound

Traffic entering interface.

```
Source

 |

Interface IN

 |

Router
```

---

## Outbound

Traffic leaving interface.

```
Router

 |

Interface OUT

 |

Destination
```

---

# Inbound vs Outbound

| Feature | Inbound | Outbound |
|---|---|---|
| Applied before routing | Yes | No |
| Applied after routing | No | Yes |
| Saves resources | Usually | Less |

1. Create ACL.
2. Apply ACL to interface.

Syntax:

```bash

```

```bash

```

```bash

```

```bash

```

# ACL Counters

```

```

Shows:

```
Number of packets matching rule
```

---

# ACL Troubleshooting

| Problem | Cause |
|---|---|
| Traffic blocked | Missing permit rule |
| Rule not working | Wrong order |
| ACL too broad | Incorrect wildcard |
| No matches | Applied wrong interface |

---

# ACL Design Best Practices

- Place specific rules first.
- End with explicit permit/deny.
- Use named ACLs for large networks.
- Document ACL purpose.
- Test before deployment.
- Use least privilege approach.

# 5. Exam Traps

- ACLs are processed top to bottom.
- First matching rule wins.
- Every ACL has an implicit deny any.
- Standard ACL only checks source IP.
- Extended ACL checks source, destination, protocol, and ports.
- Standard ACLs are placed near destination.
- Extended ACLs are placed near source.
- Wildcard mask 0 means must match.
- Wildcard mask 1 means ignore.
- Named ACLs are easier to modify.
- ACLs do not filter traffic without being applied to an interface.
- `permit ip any any` allows all IPv4 traffic.
- Missing permit statements can block all traffic.

# 7. Practice Questions

## Question 1

Which ACL type can filter TCP port numbers?

A. Standard ACL  
B. Extended ACL  
C. MAC ACL  
D. VTY ACL  

### Answer: B

Explanation:

Extended ACLs can match protocols and ports.

---

## Question 2

What does the wildcard bit value 0 mean?

A. Ignore address bit  
B. Match address bit exactly  
C. Block traffic  
D. Permit traffic  

### Answer: B

Explanation:

0 means the bit must match.

---

## Question 3

Where should an extended ACL usually be placed?

A. Near destination  
B. Near source  
C. On switch only  
D. On DNS server  

### Answer: B

Explanation:

Extended ACLs are placed close to the source.

---

## Question 4

What happens if no ACL rule matches?

A. Permit all  
B. Drop packet  
C. Forward normally  
D. Send to router CPU  

### Answer: B

Explanation:

Implicit deny any blocks unmatched traffic.

---

## Question 5

Which ACL type uses a descriptive name?

A. Numbered ACL  
B. Named ACL  
C. Standard ACL only  
D. Dynamic ACL only  

### Answer: B

Explanation:

Named ACLs use text identifiers.
