# MP-BGP (Multiprotocol BGP)

> **Level 20 · MPLS** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**MP-BGP** carries **VPN routes** between PE routers in an MPLS network. Using
**address families** and the **RD + RT** model, it makes overlapping customer prefixes
unique and filters who receives them. The **VPNv4** address family (64-byte: 8 RD + 32
IPv4) is how the control plane builds L3VPNs.

---

## 2. Core Concepts

### 2.1 Address families

| AF | What it carries |
|----|-----------------|
| ipv4 unicast | normal BGP |
| ipv4 multicast | multicast NLRI |
| **vpnv4** | VRF routes + label |
| ipv6 unicast | IPv6 |
| vpnv6 | IPv6 VPN routes |

- Each **AF** has its own NLRI and policy.

### 2.2 The VPNv4 route

| Field | Meaning |
|-------|---------|
| RD | makes prefix unique |
| IPv4 prefix | customer route |
| Label | VPN service label |
| Next-hop | egress PE |
| RT | membership |

- **RD + prefix** = globally unique; label = the VPN FEC.

### 2.3 RD (distinguisher)

| Format | Example |
|--------|---------|
| ASN:NN | 65000:100 |
| IP:NN | 10.0.0.1:100 |

- The RD **must be unique** per VRF on the PE.
- Two customers can use the **same IPv4 space** — RD disambiguates.

### 2.4 RT (route target)

| RT | Meaning |
|----|---------|
| export | tag routes leaving the VRF |
| import | which routes enter the VRF |
| policy | controls VPN membership |

- A PE imports only routes whose RT matches its **import list**.
- The RT creates the **VPN topology** (full-mesh/extranet/hub-spoke).

### 2.5 Configuration

```text
router bgp 65000
 neighbor 192.0.2.2 remote-as 65000
 !
 address-family vpnv4
  neighbor 192.0.2.2 activate
  neighbor 192.0.2.2 send-community extended
 exit-address-family
!
ip vrf CUST1
 rd 65000:100
 route-target export 65000:100
 route-target import 65000:100
```

| Command | Purpose |
|---------|---------|
| `address-family vpnv4` | VPNv4 session |
| `activate` | enable per neighbor |
| `send-community extended` | carry RTs |
| `rd` / `route-target` | VRF identity |

- **Extended communities (RTs)** must be sent between PEs.

### 2.6 Verification

```text
show bgp vpnv4 unicast all
show bgp vpnv4 unicast vrf CUST1
show ip vrf
show ip route vrf CUST1
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No VPN routes | AF not activated | show bgp vpnv4 |
| Missing RTs | extended comms off | send-community |
| Overlap confusion | RD duplicated | rd |
| Wrong import | RT mismatch | route-target |
| No label | no label in NLRI | vpnv4 detail |

---

## 5. Exam Traps

- MP-BGP = **AF + RD/RT** model.
- **VPNv4** NLRI = RD(8) + IPv4(32) + label.
- **RD = uniqueness; RT = membership policy**.
- RTs ride as **extended communities**.
- `show bgp vpnv4 unicast vrf X` is the key check.
