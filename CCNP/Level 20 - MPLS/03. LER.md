# LER (Label Edge Router)

> **Level 20 · MPLS** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **LER** (also **PE** in VPN terms) sits at the **edge** of the MPLS domain. It does
the IP → label transition: **pushing** a label on ingress and **popping** it on egress.
It runs the full IP routing stack (IGP + MP-BGP for VPNs) so it can classify packets
into FECs and build the right label stack.

---

## 2. Core Concepts

### 2.1 Edge responsibilities

| Direction | Action |
|-----------|--------|
| Ingress | classify → push label |
| Egress | pop label → deliver IP |
| Core side | faces MPLS (LSP) |
| CE side | faces customer |

- Ingress LER = the **push** point; egress LER = the **pop** point.

### 2.2 Ingress behavior

| Step | Detail |
|------|--------|
| 1 | receive IP from CE |
| 2 | CEF lookup → FEC |
| 3 | push transport label (+ service label) |
| 4 | forward into core |

- The push is decided by the **FEC** (note 06).

### 2.3 Egress behavior

| Step | Detail |
|------|--------|
| 1 | receive label from core |
| 2 | pop (after PHP) |
| 3 | route / deliver to CE |
| 4 | VRFs separate customers |

- With **PHP**, the egress often receives an **explicit null** to keep Exp.

### 2.4 LER in a VPN (PE)

| Role | Job |
|------|-----|
| VRF | per-customer routing table |
| MP-BGP | exchange VPNv4 routes |
| LDP | core label |
| CE-facing | PE–CE routing |

- The PE is an LER that also runs **VRF + MP-BGP** (notes 07/08).

### 2.5 Configuration sketch

```text
interface Gi0/0          ! core facing
 mpls ip
!
interface Gi0/1          ! CE facing
 ip vrf forwarding CUST1
 ip address 10.10.0.1 255.255.255.0
```

- Core interface gets `mpls ip`; CE interface goes **into a VRF**.

### 2.6 Verification

```text
show ip cef
show mpls forwarding-table
show ip vrf
show ip vrf detail
show ip route vrf CUST1
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No label push | CEF/FEC | show ip cef |
| CE unreachable | VRF missing | show ip vrf |
| Wrong path | label binding | forwarding-table |
| VPN no route | MP-BGP | show bgp vpnv4 |
| Edge asymmetry | push/pop mismatch | CEF |

---

## 5. Exam Traps

- LER = **edge** (PE): push on ingress, pop on egress.
- Core-facing interfaces get `mpls ip`; CE interfaces go **into VRFs**.
- VPN edge = LER + **VRF + MP-BGP**.
- Ingress classifies into **FECs** to choose labels.
- PHP means egress usually receives explicit/implicit null.
