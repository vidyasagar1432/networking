# RIB (Routing Information Base)

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **Routing Information Base (RIB)**, commonly called the **routing table**, is the
**control-plane** database holding the **best route per prefix** — selected by
Administrative Distance (note 02) then metric (note 03). The RIB is the authoritative
place where route selection happens; from it the CEF/FIB is built (note 05/07) for
hardware forwarding.

---

## 2. Core Concepts

### 2.1 Who feeds the RIB

| Source | Entry code | Note |
|--------|-----------|------|
| Directly connected | C | interface up/up |
| Local /32 | L | interface address |
| Static | S | configured AD 1 (unless floating) |
| OSPF | O | 110 |
| EIGRP | D | 90 internal / 170 external |
| BGP | B | 20 eBGP / 200 iBGP |

### 2.2 Route selection in the RIB

1. Gather **all** candidate routes for a prefix from all sources.
2. Drop to the **lowest AD** source (only one source wins).
3. Within that source, **lowest metric** wins.
4. Metric tie → **ECMP** (all next hops kept, load-shared).

### 2.3 The RIB vs the FIB (recap of the split)

| | RIB | FIB/CEF |
|--|-----|---------|
| Plane | control | data |
| Content | prefix + next hop + AD/metric | prefix + adjacency |
| Resolution done here | yes (recursion, note 04) | consumes its result |
| Command | `show ip route` | `show ip cef` |

### 2.4 Memory & scale (RIB tables)

| Design concern | Fix |
|----------------|-----|
| Huge internet tables | BGP route filtering, communities |
| RIB churn/flap | dampening (BGP), summarization |
| Memory pressure | summarize at boundaries (note 11) |
| Per-VRF isolation | separate RIB per VRF |

### 2.5 RIB update & convergence

- Protocol events (topology change, neighbor flap) trigger **RIB recalculation**; new
  winners are pushed to the FIB.
- Watch for **route flapping** (route installed, withdrawn, reinstalled) — a classic
  instability symptom seen in `show ip route` timestamps.

## 3. Configuration / Commands

```text
show ip route                      ! full RIB
show ip route 10.1.1.0             ! one prefix detail
show ip route summary              ! totals per protocol
show ip protocols                  ! AD + network statements
show ip route vrf X                ! per-VRF RIB
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Prefix in protocol but not RIB | lower AD source present, or filter | `show ip route prefix` \\| origin |
| RIB flap timestamps | route flapping via unstable neighbor | `show ip route` age, log changes |
| Wrong source wins | AD override / distance config | `show ip protocols` distances |
| Missing after failover | convergence delay (protocol timers) | protocol state, hold timers |
| Max RIB size | too many prefixes (no BGP filter/aggregate) | `show ip route summary` |

---

## 5. Exam Traps

- **RIB = routing table = control plane.** Forwarding is done by FIB/CEF — "router uses
  the routing table to forward" is wrong on modern IOS.
- **RIB holds only winners** — losers (same prefix other source) are not installed.
- **AD picks the source, metric picks the path** — entirely inside the RIB logic.
- **Recursive lookup is RIB-computed**; the FIB gets the resolved adjacency (note 04).
- `show ip route summary` tells you protocol totals — great scale/debug exam tool.
