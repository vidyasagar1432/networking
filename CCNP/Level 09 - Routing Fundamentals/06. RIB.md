# RIB (Routing Information Base)

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **Routing Information Base (RIB)** is the router's **control-plane routing database**, commonly viewed through the Cisco routing table.

The RIB receives candidate routes from **connected interfaces, static configuration, and dynamic routing protocols**. It determines which route or routes should be installed for each destination prefix based on **Administrative Distance (AD)** and the routing protocol's **metric/path-selection rules**.

The resulting forwarding information is then used by **Cisco Express Forwarding (CEF)** to build the **FIB** and associated forwarding information for packet forwarding.

> **RIB = route selection**  
> **FIB = packet forwarding**

---

## 2. Core Concepts

### 2.1 Who Feeds the RIB

Common IPv4 route sources shown by `show ip route` include:

|Source|Code|Typical Cisco AD|Description|
|---|--:|--:|---|
|Connected|`C`|0|Directly connected network|
|Local|`L`|0|Local interface address, usually `/32`|
|Static|`S`|1|Manually configured route|
|OSPF|`O`|110|OSPF-learned route|
|EIGRP Internal|`D`|90|Internal EIGRP route|
|EIGRP External|`D EX`|170|External EIGRP route|
|BGP eBGP|`B`|20|External BGP route|
|BGP iBGP|`B`|200|Internal BGP route|

> **Important:** These are typical Cisco IOS/IOS XE administrative distances. They can be changed with configuration, and some route types have additional rules.

## 3. Route Selection in the RIB

Route selection should be understood in **two stages**.

### Stage 1 — Select the Routing Source

If multiple routing protocols provide the **same destination prefix**, Cisco compares their **Administrative Distance**.

```text
Lower AD = preferred routing source
```

Example:

```text
OSPF      10.10.10.0/24    AD 110
EIGRP     10.10.10.0/24    AD 90
```

EIGRP wins because:

```text
90 < 110
```

The OSPF route is therefore not the active route for that prefix.

---

### Stage 2 — Select the Best Path Within the Protocol

Once a routing source is selected, that protocol uses its own **metric/path-selection algorithm** to select the best path.

Example:

```text
OSPF
 ├── Path A → metric 20
 └── Path B → metric 40
```

OSPF selects:

```text
Path A → metric 20
```

> **Exam rule:**  
> **AD chooses between routing sources.**  
> **Metric chooses the best path within a routing protocol.**

Do not simplify this to:

> "AD then metric globally."

Each routing protocol performs its own path-selection process before the resulting route competes in the RIB.

---

## 4. ECMP

If multiple paths are considered equal by the routing protocol and the platform supports them, the router can install **multiple equal-cost paths**.

This is called:

**ECMP — Equal-Cost Multi-Path**

Example:

```text
10.20.0.0/16

     ┌──→ Next hop A
RIB ─┤
     └──→ Next hop B
```

The RIB can therefore contain multiple valid paths for the same prefix when they are equal-cost paths.

CEF/FIB can then use those paths for forwarding and load sharing.

> **Important:** ECMP is not simply "metric tie = always install everything." The routing protocol and platform determine whether paths qualify as equal-cost and how many can be installed.

---

## 5. RIB vs FIB

The RIB and FIB have different responsibilities.

|Feature|RIB|FIB / CEF|
|---|---|---|
|Plane|Control plane|Data plane|
|Main purpose|Route selection|Packet forwarding|
|Receives information from|Routing protocols, connected, static|RIB|
|Main question|**Which route should be used?**|**How should the packet be forwarded?**|
|Contains|Routing information and selected routes|Forwarding information|
|Command|`show ip route`|`show ip cef`|
|Used for|Routing decisions|Packet forwarding|

### Simplified relationship

```text
Connected / Static / Routing Protocols
                  ↓
                 RIB
          "Which route wins?"
                  ↓
                 CEF
            ↙          ↘
          FIB      Adjacency Info
           ↓             ↓
     L3 forwarding    L2 rewrite
            └──────┬──────┘
                   ↓
             Packet Forwarding
```

> **Exam point:** The RIB is the control-plane routing database. CEF/FIB is used for normal packet forwarding.

## 6. Recursive Next-Hop Resolution

A route can specify a next-hop IP address that is **not directly connected**.

Example:

```text
10.10.10.0/24
    via 192.168.100.2
```

If `192.168.100.2` is not directly connected, the router must determine how to reach that next hop.

It performs a **recursive lookup**:

```text
10.10.10.0/24
      ↓
Next hop: 192.168.100.2
      ↓
Lookup 192.168.100.2
      ↓
192.168.100.0/24 via Gi0/1
      ↓
Next hop is reachable
```

The resulting forwarding information is then used by CEF to construct the appropriate FIB/adjacency information.

> **Exam point:** Recursive resolution is part of determining how a route's next hop is reachable. CEF uses the resolved forwarding information rather than performing a complete recursive route lookup for every packet.

## 7. RIB Updates and Convergence

The RIB changes when routing information changes.

Typical triggers include:

- Interface going up or down
    
- Routing-protocol neighbor failure
    
- Topology changes
    
- Route advertisements or withdrawals
    
- Static-route changes
    
- Administrative-distance changes
    
- Metric/path-selection changes
    

A simplified convergence process is:

```text
Topology / Routing Change
          ↓
Routing Protocol
          ↓
New Route Information
          ↓
RIB Recalculation
          ↓
New Best Route
          ↓
CEF/FIB Update
          ↓
Forwarding Uses New Path
```

During convergence, the router may temporarily have:

- A route removed
    
- A replacement route selected
    
- A different next hop installed
    
- A temporary period without a usable route
    

---

## 8. Route Flapping

**Route flapping** occurs when a route repeatedly changes state, for example:

```text
Installed
   ↓
Withdrawn
   ↓
Reinstalled
   ↓
Withdrawn
   ↓
Reinstalled
```

Possible causes include:

- Unstable physical links
    
- Routing-protocol neighbor instability
    
- Interface errors
    
- Misconfiguration
    
- Unstable paths
    
- External routing changes
    

Route flapping can cause repeated RIB and FIB updates and increase control-plane processing.

For troubleshooting, use protocol-specific neighbor/status commands, logs, and route information rather than relying only on route timestamps.

## 9. Memory, Scale, and VRFs

The RIB consumes memory because the router must maintain routing information and associated state.

### Large Routing Tables

Common techniques to control routing-table scale include:

- Route filtering
    
- Route summarization
    
- BGP communities and policy
    
- Prefix limits
    
- Appropriate route redistribution
    
- Careful use of default routes
    

### Route Flapping

Possible mitigation depends on the protocol and design:

- Fix the underlying instability
    
- Use route filtering/policy
    
- Use BGP route dampening where appropriate
    
- Use summarization to reduce propagation of instability
    

### VRFs

Each **VRF** maintains its own routing context and routing table.

Example:

```text
Global RIB
 ├── Internet routes
 └── Infrastructure routes

VRF CUSTOMER-A
 └── Customer-A routes

VRF CUSTOMER-B
 └── Customer-B routes
```

Routes in one VRF are normally isolated from routes in another VRF unless explicit mechanisms are configured to exchange them.

## 11. Troubleshooting

|Symptom|Possible Cause|What to Check|
|---|---|---|
|Prefix exists in a routing protocol but not in the RIB|Another route has a better AD, route is unusable, or policy/filtering prevents installation|`show ip route`, protocol-specific route output|
|Wrong routing source wins|Administrative Distance|`show ip route`, `show ip protocols`|
|Wrong path within a protocol wins|Protocol-specific metric/path-selection rules|Protocol-specific commands|
|Route disappears during failover|Neighbor/interface failure or convergence|Interface state, neighbor state, protocol timers/logs|
|Route repeatedly appears/disappears|Route flapping|Logs, interface state, protocol neighbors|
|Expected route missing|Filtering, redistribution, summarization, policy, or protocol failure|Protocol configuration and route database|
|Too many routes|Large routing domain or insufficient filtering/summarization|`show ip route summary`|
|RIB route exists but traffic still fails|FIB/adjacency, Layer-2, ACL, or other forwarding problem|`show ip cef`, ARP/ND, interfaces, ACLs|

## 12. Exam Traps

### Trap 1 — RIB = FIB

**Incorrect.**

```text
RIB → control plane → route selection
FIB → data plane → packet forwarding
```

---

### Trap 2 — Lowest AD always means lowest metric

**Incorrect.**

AD compares **different routing sources**.

The routing protocol's metric determines the best path **within that protocol**.

```text
Different protocols → AD
Same protocol      → protocol-specific metric/path selection
```

---

### Trap 3 — RIB contains only one route for every prefix

**Too simplistic.**

The active routing table installs the preferred route or routes, but routing processes can maintain alternative candidate information, and ECMP can result in multiple installed paths.

---

### Trap 4 — The RIB forwards every packet

**Incorrect for normal modern Cisco CEF forwarding.**

The RIB is primarily a **control-plane route-selection database**. CEF/FIB provides the normal forwarding path.

---

### Trap 5 — Recursive lookup happens for every packet

**Incorrect.**

Recursive next-hop resolution is performed when determining forwarding information. CEF then uses the resolved forwarding information for efficient packet forwarding.

---

### Trap 6 — `show ip route` shows every route learned by every protocol

**Incorrect.**

`show ip route` primarily shows the **active routing table**.

Alternative routes may still exist in the routing protocol's own database but not be installed as the active route.

---

### Trap 7 — BGP AD determines BGP's best path

**Incorrect.**

BGP first performs its own **BGP path-selection process**.

Only after BGP selects its candidate route does that route compete with routes from other routing sources using Administrative Distance.

## 13. RIB → FIB Relationship

The complete process can be remembered as:

```text
          ROUTING INFORMATION
                  ↓
     ┌─────────────────────────┐
     │           RIB           │
     │   Control Plane         │
     │                         │
     │ Route Selection         │
     │ AD + Protocol Rules     │
     └────────────┬────────────┘
                  ↓
                CEF
                  ↓
     ┌─────────────────────────┐
     │           FIB           │
     │    Data Plane           │
     │                         │
     │ Forwarding Decision     │
     └────────────┬────────────┘
                  ↓
        Adjacency / L2 Rewrite
                  ↓
             Packet Out
```

### Simple Mental Model

> **RIB asks: "Which route should I use?"**

> **FIB asks: "How do I forward this packet?"**

## 15. One-Line Exam Definition

> **The RIB is the control-plane routing database that collects candidate routes, selects the preferred route or equal-cost paths for each destination, and provides the routing information from which CEF builds the forwarding information used by the data plane.**
