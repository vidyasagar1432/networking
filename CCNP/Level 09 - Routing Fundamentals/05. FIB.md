# FIB (Forwarding Information Base)

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **Forwarding Information Base (FIB)** is the **data-plane** copy of the best routes.
On Cisco IOS, it's the **CEF table** (note 07). It contains everything the router needs to
forward a packet at wire speed: the destination prefix + the **resolved adjacency**
(egress interface + next-hop MAC). The FIB is what actually makes forwarding fast; the RIB
is the control-plane source it mirrors.

---

## 2. Core Concepts

### 2.1 FIB vs RIB — the two tables

| | RIB (note 06) | FIB |
|--|---------------|-----|
| Plane | control | data |
| Source of truth | all protocols + selection | winner per prefix |
| Content | prefix + next hop + AD/metric | prefix + adjacency |
| Speed | software decision | hardware / ASIC lookup |
| Example | `show ip route` | `show ip cef` |

### 2.2 How the FIB is built

1. Routing protocols / statics feed the **RIB** (control plane).
2. The **CEF/FIB process** resolves each route's next hop to an **adjacency**
   (output interface + L2 next-hop MAC via ARP/ND).
3. FIB entries are pushed to the **hardware (ASIC/TCAM)** for line-rate lookups.

### 2.3 Entry structure

```
Prefix/len        Adjacency
10.1.1.0/24       via GigabitEthernet0/1 (MAC aaaa.bbbb.cccc)
```

- For **recursive next hops** (note 04), the FIB stores the already-resolved adjacency —
  no per-packet recursion at forwarding time.

### 2.4 Paths in the FIB (CEF types)

| FIB type | Use |
|----------|-----|
| Receive | packet to the router itself (its own IPs) |
| Attached/receive | directly connected subnet (ARP for next hop) |
| Next-hop | forwarded to the adjacency's MAC |
| Drop | discard (null0 / unresolved) |
| Glean | subnet route — send ARP request for that host |

- The **glean** and **attach** entries are why `show ip cef` looks different from
  `show ip route` — the FIB contains L2 details the RIB doesn't.

### 2.5 Default (lookup miss) behavior

- If no FIB entry matches a destination → falls to the **default route** (0.0.0.0/0 if
  present) — see note 10. Otherwise packet is dropped.

### 2.6 FIB with ECMP

- ECMP prefixes get **multiple adjacencies**; hardware load-shares on the **hash**
  (per-flow, note 07). FIB keeps all equal-cost paths.

## 3. Configuration / Commands

```text
show ip cef                        ! full FIB
show ip cef 10.1.1.0               ! entry + adjacency
show ip cef detail                 ! with L2 info
show adjacency                     ! MAC/interface pairs
show ip route same-prefix          ! RIB side to compare
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Route in RIB, traffic dropped | FIB/CEF entry missing or unresolved | `show ip cef prefix` |
| Rice gibberish in cef | adjacency unresolved (ARP fail) | `show adjacency`, `show arp` |
| FIB covered by "next hop" but no path | recursive next hop black-holed | check whole chain (note 04) |
| CEF "no route" | max BGP scale / hardware full | `show ip cef summary` |
| Hardware full | TCAM exhausted | `show ip cef summary`, reduce prefixes |

---

## 5. Exam Traps

- **FIB = data plane; RIB = control plane** — the #1 trap pairing.
- **CEF keeps the resolved adjacency** — data plane does not re-lookup next hop.
- **`show ip cef` ≠ `show ip route`** — FIB shows glean/attach/drop entries too.
- **Recursion resolved at FIB build time**, not per packet (note 04).
- Hard/TCAM **exhaustion** drops traffic even though RIB looks healthy.
