# FIB (Forwarding Information Base)

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **Forwarding Information Base (FIB)** is the **data-plane forwarding table** derived from the routing table (**RIB**). It contains the Layer-3 information required to make a forwarding decision for a destination prefix.

On Cisco IOS, the FIB is part of **Cisco Express Forwarding (CEF)**. CEF uses the **FIB together with the adjacency table** to forward packets efficiently.

The key relationship is:

> **RIB decides the best route → FIB provides the Layer-3 forwarding decision → adjacency provides the Layer-2 rewrite → packet is forwarded.**

---

## 2. Core Concepts

### 2.1 RIB vs FIB

|Feature|RIB|FIB|
|---|---|---|
|Plane|Control plane|Data plane|
|Purpose|Selects the best route|Forwards packets|
|Built from|Connected, static, and routing-protocol routes|Best routes from the RIB|
|Contains|Prefix, next hop, AD, metric, source|Forwarding information and references to adjacency information|
|Main command|`show ip route`|`show ip cef`|
|Decision|Which route should be used?|Where/how should the packet be forwarded?|

### 2.2 How the FIB Is Built

The forwarding process can be simplified as:

```text
Connected / Static / Routing Protocols
                  ↓
                 RIB
          (best route selected)
                  ↓
                 CEF
             ↙          ↘
           FIB      Adjacency Table
            ↓             ↓
      L3 forwarding    L2 rewrite
            └──────┬──────┘
                   ↓
              Packet Forwarding
```

1. Connected routes, static routes, and routing protocols provide information to the **RIB**.
    
2. The RIB selects the **best route** for each destination prefix.
    
3. CEF builds the corresponding **FIB entries**.
    
4. CEF resolves the required next-hop information through the **adjacency table**.
    
5. On platforms that support hardware forwarding, forwarding information can be programmed into the appropriate hardware forwarding resources.
    
6. Packets are then forwarded without performing a full routing-protocol decision for every packet.

## 3. FIB and Adjacency Table

The FIB and adjacency table are related but **not the same thing**.

### FIB

The FIB primarily answers:

> **Which forwarding path should be used for this destination prefix?**

Example:

```text
10.1.1.0/24 → GigabitEthernet0/1 → next-hop 192.168.1.2
```

### Adjacency Table

The adjacency table provides the **Layer-2 forwarding information** needed to rewrite the outgoing frame.

Example:

```text
Next hop: 192.168.1.2
Interface: GigabitEthernet0/1
Destination MAC: aaaa.bbbb.cccc
```

ARP for IPv4 or Neighbor Discovery (ND) for IPv6 is commonly used to resolve the Layer-2 address of a directly reachable next hop.

> **Exam point:** Do not think of the FIB as simply a table containing `prefix + MAC`. The FIB provides the Layer-3 forwarding decision and works with adjacency information to perform the actual Layer-2 rewrite.

---

## 4. Entry Structure

A simplified forwarding entry can be represented as:

```text
Destination Prefix     Forwarding Information
10.1.1.0/24            via 192.168.1.2, Gi0/1
```

The corresponding adjacency may contain:

```text
Next Hop               192.168.1.2
Outgoing Interface     Gi0/1
Destination MAC        aaaa.bbbb.cccc
```

For a **recursive next hop**, the routing process must resolve the next hop through another route before the forwarding information can be fully resolved.

The important exam concept is:

> **The router does not perform a complete recursive routing lookup for every packet. CEF resolves the forwarding information ahead of packet forwarding.**

---

## 5. CEF Forwarding Entry Types

`show ip cef` can display different types of forwarding entries/adjacencies.

|Type|Purpose|
|---|---|
|**Receive**|Traffic destined to an address owned by the router|
|**Connected / Attached**|Represents a directly connected network|
|**Glean**|Connected subnet where the specific host adjacency has not yet been resolved|
|**Next-hop**|Forward traffic toward a resolved next hop|
|**Drop**|Explicitly discard traffic|
|**Null**|Forward traffic to a null interface, commonly used for intentional discards/summarization|

### Glean

A **glean adjacency** commonly appears for a connected subnet when the router knows the destination belongs to that subnet but does not yet have a specific Layer-2 adjacency for the host.

For IPv4, the router can use **ARP** to resolve the host's MAC address.

For IPv6, **Neighbor Discovery (ND)** performs the equivalent neighbor-resolution function.

> **Exam shortcut:**  
> **Glean = connected subnet + specific host adjacency not yet resolved.**

## 6. Longest-Prefix Match Still Applies

The FIB follows the same fundamental forwarding rule:

> **The most specific matching prefix wins.**

Example:

```text
10.0.0.0/8
10.10.0.0/16
10.10.10.0/24
```

For destination:

```text
10.10.10.50
```

The FIB selects:

```text
10.10.10.0/24
```

because `/24` is more specific than `/16` or `/8`.

---

## 7. Default Route and Lookup Miss

If no more-specific FIB entry matches a destination, the router can use the **default route**:

```text
0.0.0.0/0
```

The simplified logic is:

```text
Destination
    ↓
Longest-prefix match
    ↓
Specific route?
 ┌──Yes──→ Forward
 │
 No
 ↓
Default route?
 ┌──Yes──→ Forward
 │
 No
 ↓
Drop
```

> The default route is **not automatically used simply because a more-specific route is absent**. It must exist in the forwarding table as a usable route.

---

## 8. FIB and ECMP

**ECMP (Equal-Cost Multi-Path)** allows multiple equal-cost paths to the same destination.

Example:

```text
10.20.0.0/16
 ├── via 192.168.1.2
 └── via 192.168.2.2
```

The FIB can maintain multiple forwarding paths for the prefix.

Cisco platforms commonly use a **hashing mechanism** to distribute traffic across available paths.

Typical behavior is **per-flow**, helping packets belonging to the same flow remain on the same path and reducing packet reordering.

> **Exam point:** ECMP does not mean every individual packet must alternate between paths. The exact load-sharing behavior is platform-dependent.

## 9. Configuration / Verification Commands

### View the FIB

```text
show ip cef
```

### View a specific FIB entry

```text
show ip cef 10.1.1.0
```

### Display detailed CEF information

```text
show ip cef detail
```

### View adjacency information

```text
show adjacency
```

### View the RIB

```text
show ip route
```

### Compare a specific route

```text
show ip route 10.1.1.0
```

### Check ARP resolution

```text
show ip arp
```

> **Note:** Hardware forwarding, TCAM, and platform-capacity troubleshooting commands vary by Cisco platform. Do not assume `show ip cef summary` alone diagnoses every hardware-resource problem.

## 10. Troubleshooting

|Symptom|Possible Cause|What to Check|
|---|---|---|
|Route exists in RIB but forwarding fails|FIB/adjacency problem or another forwarding issue|`show ip route`, `show ip cef`|
|Next hop unresolved|ARP/ND or Layer-2 connectivity problem|`show ip arp`, `show adjacency`|
|FIB points toward an unreachable next hop|Recursive resolution/problem in the next-hop path|Check the entire recursive chain|
|Connected network shows glean|Host-specific adjacency has not been resolved|ARP/ND and Layer-2 connectivity|
|Traffic unexpectedly discarded|Drop/null forwarding entry or other forwarding condition|`show ip cef`|
|ECMP traffic not balanced as expected|Hashing/platform behavior|Check platform-specific CEF/load-sharing behavior|
|Hardware forwarding capacity exhausted|Platform-specific forwarding-resource limitation|Use platform-specific hardware/TCAM commands|

## 11. Common Misconceptions

### Misconception 1: FIB and RIB are the same

**Incorrect.**

```text
RIB → control-plane routing information
FIB → data-plane forwarding information
```

The RIB determines the best route; the FIB is used to forward packets.

---

### Misconception 2: The FIB contains only destination MAC addresses

**Incorrect.**

The FIB contains Layer-3 forwarding information and works with the **adjacency table** for the Layer-2 rewrite.

---

### Misconception 3: CEF performs recursive routing for every packet

**Incorrect.**

CEF resolves forwarding information before packet forwarding so that packets do not require a full recursive route lookup every time.

---

### Misconception 4: Every FIB lookup is always performed by an ASIC/TCAM

**Incorrect.**

Cisco forwarding architecture is **platform-dependent**. CEF provides efficient forwarding, while the exact hardware/software implementation varies by platform.

---

### Misconception 5: Glean means the route is missing

**Incorrect.**

A glean entry generally indicates that the router knows the destination is on a directly connected subnet but does not yet have the specific host's Layer-2 adjacency.

## 12. FIB vs RIB vs Adjacency

|Component|Main Question|Example|
|---|---|---|
|**Routing Protocol**|How can I reach the network?|OSPF, EIGRP, BGP|
|**RIB**|Which route is the best?|`show ip route`|
|**FIB**|How should I forward toward the destination?|`show ip cef`|
|**Adjacency Table**|What Layer-2 rewrite is required?|Next-hop MAC/interface|

### Mental Model

```text
Routing Protocols
       ↓
      RIB
"Which route wins?"
       ↓
      FIB
"Where do I forward?"
       ↓
 Adjacency Table
"What L2 rewrite do I use?"
       ↓
   Packet Forwarding
```

## 13. Exam Traps

- **RIB = control plane; FIB = data plane.**
    
- The **RIB selects the best route**; the FIB is used for forwarding.
    
- **CEF is the forwarding architecture**, not simply another name for the RIB.
    
- The **FIB and adjacency table are separate but work together**.
    
- `show ip route` shows the **RIB**; `show ip cef` shows **CEF/FIB information**.
    
- **Glean** indicates that a connected subnet is known but a specific host adjacency is not yet resolved.
    
- **Receive** is associated with traffic destined to addresses owned by the router.
    
- Recursive next-hop resolution is performed **before normal packet forwarding**, not as a complete routing lookup for every packet.
    
- **Longest-prefix match** still determines the destination prefix selected for forwarding.
    
- ECMP can install **multiple equal-cost forwarding paths**.
    
- Hardware forwarding implementation and capacity are **platform-dependent**.
    
- A healthy RIB does not automatically guarantee successful packet forwarding; **FIB, adjacency, Layer-2 resolution, and hardware resources** can still be involved.
