# Routing Table

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **routing table** (also **RIB**, Routing Information Base) is the control-plane database
of **known networks and their best next hops**. It is where all routing sources — directly
connected, static, and dynamic protocols — converge. The router picks **one best route per
prefix** and feeds that winner into CEF (note 07) for hardware fast-forwarding. The table
itself does not forward packets; it feeds the data-plane tables.

---

## 2. Core Concepts

### 2.1 What goes into the table

| Source | How it enters | Code in `show ip route` |
|--------|--------------|---------------------------|
| Directly connected | interface up/up | C (connected) |
| Local address (IOS) | self address | L (local) |
| Static | configured | S |
| OSPF | LSAs computed | O / O IA / O E1 / O E2 |
| EIGRP | DUAL | D / D EX |
| BGP | NLRI | B |

### 2.2 Anatomy of a route entry

```
O    10.1.1.0/24 [110/20] via 192.0.2.1, 00:12:34, GigabitEthernet0/1
```

| Field | Measures | Meaning |
|-------|----------|---------|
| `O` | protocol code | which routing source produced it |
| `10.1.1.0/24` | prefix/length | the destination network |
| `[110/20]` | **AD/weighted metric** | admin distance `110`; protocol metric `20` |
| `via 192.0.2.1` | next hop | where to send the packet |
| `00:12:34` | age | time since route learned/reinstalled |
| `GigabitEthernet0/1` | egress | outgoing interface (direct/static) |

### 2.3 Route selection: AD first, metric second

1. Compare **Administrative Distance** — trustworthiness of the *source* (note 02).
2. If ADs tie (two routes from the same protocol), compare **metric** — cost of the *path*
   (note 03).
3. Winner is installed in the RIB; losers stay with the protocol but are not installed.

### 2.4 One best route per prefix

- IOS installs **one best route** per destination prefix in the RIB.
- A tie in metric can produce **equal-cost multipath (ECMP)** — multiple next hops
  installed and load-shared (up to protocol limit, e.g., 4–32 paths).
- Switch-Router (e.g., with CEF) even balances per-flow across ECMP next hops.

### 2.5 Connected + local prefix note

- With IPv4 on IOS you normally see **both** `C` (connected, the subnet) and `L` (local,
  the interface's own IP/32). The `L` is what the routing protocol advertises to peers.
- Interface directly connected is only in the table while the interface is **up/up**.

### 2.6 The routing table's three planes reminder

| Plane | Artifact | Purpose |
|-------|----------|---------|
| Control | RIB / routing table | computing best paths |
| Data | FIB / CEF (note 05/07) | hardware forwarding |
| Management | CLI/SNMP/NetFlow | operator/admin access |

## 3. Configuration / Commands

```text
show ip route                      ! full routing table
show ip route 10.1.1.0             ! specific prefix + source detail
show ip route connected            ! only connected entries
show ip route static               ! only static entries
show ip route ospf                 ! only OSPF-learned
show ip route summary              ! table totals (routes per protocol)
show ip route vrf X                ! per-VRF table
show ip cef                        ! the FIB view (note 07)
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Prefix missing from table | protocol not converged / denied filter | `show ip protocol`, neighbor state |
| WRONG next hop installed | AD tie or lower metric from other source | `show ip route prefix` origin |
| ECMP not load-sharing | hash polarization / max-paths default | verify both next hops in `via` list |
| Connected expected but absent | interface down / IP not assigned | `show ip interface brief` |
| Table massive / slow review | no summarization (note 11) | aggregate at boundaries |

## 5. Exam Traps

- **Routing table = RIB = control plane**, forwarding happens in **CEF/FIB** — "the router
  forwards using the routing table" is a classic wrong statement on modern IOS.
- **AD decides between protocols; metric decides within a protocol.**
- **One best route per prefix**, unless ECMP ties.
- `C` (`connected`) vs `L` (`local`) are different — the local/32 is what's advertised.
- Codes are case-sensitive: `O` OSPF, `o` OSPF on NSSA — read both.
