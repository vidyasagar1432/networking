# Routing Table

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **routing table**, also called the **RIB (Routing Information Base)**, is the control-plane  
database containing the **best routes** to known destination prefixes.

Routes can come from directly connected networks, static configuration, or dynamic routing  
protocols. The router evaluates candidate routes and installs the best route(s) into the RIB.  
The **FIB (Forwarding Information Base)** is then derived from the RIB for data-plane packet  
forwarding.

> **Key idea:** The RIB decides **where traffic should go**; the FIB/CEF is used to **forward  traffic**.

---

## 2. Core Concepts

### 2.1 What Goes into the Routing Table

|Source|How it enters|Code in `show ip route`|
|---|---|---|
|Directly connected|Interface is up/up with an IP address|`C`|
|Local address (IOS)|Router's own interface address|`L`|
|Static|Manually configured|`S`|
|OSPF|SPF calculation from LSDB/LSAs|`O`, `O IA`, `O E1`, `O E2`, `O N1`, `O N2`|
|EIGRP|DUAL calculation|`D`, `D EX`|
|BGP|BGP NLRI and best-path selection|`B`|

> **Exam note:** The exact route codes displayed by IOS can vary by route type and  
> configuration.

---

### 2.2 Anatomy of a Route Entry

```text
O    10.1.1.0/24 [110/20] via 192.0.2.1, 00:12:34, GigabitEthernet0/1
```

|Field|Meaning|
|---|---|
|`O`|Routing protocol/source code — OSPF|
|`10.1.1.0/24`|Destination prefix and prefix length|
|`[110/20]`|Administrative Distance / protocol metric|
|`110`|OSPF administrative distance|
|`20`|OSPF path metric (cost)|
|`via 192.0.2.1`|Next-hop IP address|
|`00:12:34`|Route age|
|`GigabitEthernet0/1`|Outgoing interface|

### Important

The value inside brackets follows:

```text
[Administrative Distance / Metric]
```

For example:

```text
[110/20]
  │  │
  │  └── OSPF metric
  └───── Administrative Distance
```

## 2.3 Route Selection: AD First, Metric Second

When multiple routing sources provide a route to the **same destination prefix**:

1. Compare **Administrative Distance (AD)**.
    
2. The route with the **lowest AD** wins between different routing sources.
    
3. Once the routing protocol is selected, that protocol uses its own **metric** to choose  
    the best path.
    
4. The resulting best route(s) are installed in the RIB.
    

### Example

```text
OSPF route: 10.1.1.0/24 [110/20]
EIGRP route: 10.1.1.0/24 [90/30]
```

EIGRP wins because:

```text
90 < 110
```

The metric values `20` and `30` are **not compared** because the routes came from  
different routing protocols.

> **Exam rule:**  
> **AD compares routing sources. Metric compares paths within a routing protocol.**

---

## 2.4 One Best Route Per Prefix — With ECMP

A router normally installs the **best route(s)** for a destination prefix into the RIB.

If multiple paths have the same qualifying cost, the router can install multiple  
**equal-cost paths**, known as **ECMP (Equal-Cost Multipath)**.

Example:

```text
10.1.1.0/24
   ├── via 192.0.2.1
   └── via 192.0.2.5
```

The exact number of supported ECMP paths depends on the **platform, routing protocol,  
software version, and configuration**.

With CEF, traffic is normally load-balanced using a **hash-based method**, typically  
keeping packets from the same flow on the same path to avoid packet reordering.

---

## 2.5 Connected and Local Routes

When an IPv4 interface is configured and operational, Cisco IOS normally installs two  
related routes:

```text
C    192.168.1.0/24 is directly connected, GigabitEthernet0/0
L    192.168.1.1/32 is directly connected, GigabitEthernet0/0
```

### `C` — Connected

Represents the **directly connected subnet**.

```text
C 192.168.1.0/24
```

### `L` — Local

Represents the router's **own interface address** as a host route.

```text
L 192.168.1.1/32
```

### Important distinction

The `L` route is **not itself what routing protocols advertise**.

A routing protocol may advertise the connected network, depending on protocol configuration,  
but the local `/32` is primarily used by the router to recognize traffic destined for its  
own interface address.

> **Exam trap:**  
> `C` = connected subnet  
> `L` = local interface address `/32`

If the interface is not operational, the corresponding connected/local routes may disappear  
from the routing table.

## 2.6 Routing Table vs FIB vs CEF

|Component|Plane|Purpose|
|---|---|---|
|**RIB**|Control plane|Stores and selects best routes|
|**FIB**|Data plane|Contains forwarding information derived from the RIB|
|**CEF**|Data-plane forwarding architecture|Cisco mechanism used to perform efficient packet forwarding|

Conceptually:

```text
Routing Protocols
      │
      ▼
 Candidate Routes
      │
      ▼
     RIB
   (Routing
   decision)
      │
      ▼
     FIB
 (Forwarding
 information)
      │
      ▼
    CEF / ASIC
      │
      ▼
   Packet Forwarding
```

> **Key distinction:**  
> **RIB = routing decision**  
> **FIB/CEF = forwarding decision**

## 3. Configuration / Verification Commands

```text
show ip route
```

Display the complete IPv4 routing table.

```text
show ip route 10.1.1.0
```

Display routing information for a specific destination/prefix.

```text
show ip route connected
```

Display connected routes.

```text
show ip route static
```

Display static routes.

```text
show ip route ospf
```

Display OSPF-learned routes.

```text
show ip route summary
```

Display routing-table statistics and route counts.

```text
show ip route vrf X
```

Display the routing table for VRF `X`.

```text
show ip cef
```

Display the IPv4 CEF/FIB view.

Useful additional commands:

```text
show ip protocols
show ip route <prefix>
show ip route <prefix> longer-prefixes
show ip interface brief
```

## 4. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Prefix missing from RIB|Protocol not converged, interface problem, filtering, redistribution issue|`show ip protocols`, neighbor state, `show ip route`|
|Unexpected route installed|Another source has a lower AD or protocol selected a better metric|`show ip route <prefix>`|
|ECMP not present|Paths are not equal-cost, maximum-paths/configuration limits, or protocol rules|Verify metrics and `show ip route <prefix>`|
|Connected route missing|Interface down/down, IP not configured, or interface not operational|`show ip interface brief`|
|Static route missing|Next hop/interface unavailable or route not installed|`show ip route static`|
|OSPF route missing|Adjacency/LSDB/SPF/filtering issue|`show ip ospf neighbor`, `show ip ospf database`|
|Routing table very large|Excessive prefixes or lack of summarization|`show ip route summary`|

## 5. Exam Traps

### Trap 1 — RIB vs FIB

**Wrong:**

> "The router forwards packets directly using the routing table."

**Correct:**

> The **RIB** is the control-plane routing database. The **FIB**, populated from the RIB,  
> is used for data-plane forwarding.

---

### Trap 2 — AD vs Metric

Remember:

```text
Different routing protocols
        ↓
Administrative Distance
        ↓
Choose routing source

Same routing protocol
        ↓
Metric
        ↓
Choose best path
```

---

### Trap 3 — Connected vs Local

```text
C 192.168.1.0/24
L 192.168.1.1/32
```

- `C` = directly connected network
    
- `L` = router's own interface IP
    

Do **not** say that the `L` route itself is what routing protocols advertise.

---

### Trap 4 — ECMP

A prefix can have **multiple installed next hops** when qualifying paths are equal-cost.

Therefore, "one route per prefix" is an oversimplification.

Better:

> The RIB installs the best route or qualifying equal-cost paths for a prefix.

---

### Trap 5 — OSPF Route Codes

Common OSPF codes include:

```text
O      OSPF intra-area
O IA   OSPF inter-area
O E1   OSPF external Type 1
O E2   OSPF external Type 2
O N1   OSPF NSSA external Type 1
O N2   OSPF NSSA external Type 2
```

Do **not** confuse lowercase `o` with NSSA.
