# Static Routing

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Static routes** are manually configured routes used to reach remote networks. They have a  
default **administrative distance (AD) of 1**, while connected routes have AD 0.

Static routes provide **predictability, low overhead, and precise control**, but they do not  
automatically discover alternate paths or dynamically reconverge when the topology changes.

Common uses include **stub networks, default routing, backup paths, hub-and-spoke designs,  
and summary-route loop prevention**.

---

## 2. Core Concepts

### 2.1 Static Route Forms

|Form|Syntax|Key Point|
|---|---|---|
|**Next-hop**|`ip route PREFIX MASK <next-hop>`|Router resolves the next hop recursively|
|**Exit-interface**|`ip route PREFIX MASK <interface>`|Uses the specified outgoing interface|
|**Fully specified**|`ip route PREFIX MASK <interface> <next-hop>`|Specifies both the outgoing interface and next hop|

### Next-hop static

```cisco
ip route 10.1.1.0 255.255.255.0 192.0.2.1
```

The router must determine how to reach `192.0.2.1`. If that next hop is not directly  
connected, the router performs a **recursive lookup**.

### Exit-interface static

```cisco
ip route 10.1.1.0 255.255.255.0 GigabitEthernet0/1
```

The route specifies only the outgoing interface. Behavior depends on the interface type;  
on Ethernet/broadcast interfaces, interface-only statics can cause unnecessary ARP  
resolution and are generally less desirable than specifying a next hop.

### Fully specified static

```cisco
ip route 10.1.1.0 255.255.255.0 GigabitEthernet0/1 192.0.2.1
```

Both the outgoing interface and next-hop address are explicitly specified. This removes  
ambiguity about the forwarding path and is useful when both pieces of information are known.

> **Exam tip:** For a typical Ethernet topology, a **next-hop static** or  
> **fully specified static** is generally preferred.

---

## 2.2 Administrative Distance

The default AD of a static route is:

```text
Static route = AD 1
Connected    = AD 0
```

Common comparisons:

|Route Source|Default AD|
|---|--:|
|Connected|0|
|Static|1|
|EIGRP|90|
|OSPF|110|
|RIP|120|

A static route therefore normally wins over dynamic routes **when competing routes have  
the same destination prefix**.

> **Important:** **Longest-prefix match is considered before AD.**  
> A more-specific route can beat a static route with a lower AD.

Example:

```text
10.10.0.0/16      Static AD 1
10.10.10.0/24     OSPF   AD 110
```

Traffic destined for `10.10.10.5` uses the `/24` because it is more specific.

---

## 2.3 Floating Static Routes

A **floating static route** is a static route configured with a higher AD so that it acts  
as a backup.

```cisco
! Primary static
ip route 10.1.1.0 255.255.255.0 192.0.2.1

! Backup static
ip route 10.1.1.0 255.255.255.0 198.51.100.1 200
```

The second route has AD 200, so it normally remains inactive while a better route exists.

When the preferred route disappears from the RIB, the floating static can become active.

> **Key idea:** Higher AD = lower preference.

---

## 2.4 Static Routes and Recursive Lookup

Consider:

```cisco
ip route 10.1.1.0 255.255.255.0 192.0.2.1
```

If `192.0.2.1` is not directly connected, the router must determine how to reach it.

Conceptually:

```text
Destination
   ↓
10.1.1.0/24
   ↓
Next hop: 192.0.2.1
   ↓
Lookup 192.0.2.1
   ↓
Find route to 192.0.2.1
   ↓
Outgoing interface / adjacency
```

This is called **recursive next-hop resolution**.

A change in the routing table can therefore change how the static route's next hop is  
resolved.

---

## 2.5 Static Route Tracking

Static routes can be tied to a tracking object.

Example:

```cisco
track 1 ip sla 100 reachability

ip route 10.1.1.0 255.255.255.0 192.0.2.1 track 1
```

When the tracked condition becomes down, the static route can be removed from the RIB.

Tracking is commonly combined with **IP SLA** to detect reachability beyond simply checking  
whether an interface is operational.

Conceptually:

```text
IP SLA
  ↓
Track Object
  ↓
Static Route
  ↓
RIB installation/removal
```

> **Exam tip:** Interface-up status does not necessarily mean the remote destination is  
> reachable. IP SLA + tracking can provide a more meaningful reachability test.

---

## 2.6 Multiple Static Routes and ECMP

Multiple static routes to the same destination can provide **equal-cost paths** when they  
meet the requirements for equal-cost installation.

Example:

```cisco
ip route 10.1.1.0 255.255.255.0 192.0.2.1
ip route 10.1.1.0 255.255.255.0 198.51.100.1
```

If both routes are eligible and have the same preference, Cisco can install multiple paths  
subject to the platform's **maximum-paths** configuration.

```cisco
show ip route 10.1.1.0
```

> Do not confuse **ECMP** with a floating static.  
> Equal AD/preference can provide multiple active paths; a higher AD static is normally a  
> backup.

---

## 2.7 Null0 Static Routes

A static route can point to the **Null0** interface:

```cisco
ip route 10.1.1.0 255.255.255.0 Null0
```

Matching packets are discarded.

Common uses:

- Summary-route loop prevention
    
- Intentional traffic blackholing
    
- Providing a discard path for an aggregate prefix
    

Example:

```cisco
ip route 10.0.0.0 255.0.0.0 Null0
```

If more-specific routes are absent, traffic matching the summary can be discarded.

> **Important:** Null0 is a routing discard mechanism, not a replacement for a firewall  
> or security policy.

---

## 2.8 Static Default Route

A static default route matches destinations for which no more-specific route exists.

```cisco
ip route 0.0.0.0 0.0.0.0 192.0.2.1
```

The default route is represented as:

```text
0.0.0.0/0
```

It is commonly used on:

- Stub routers
    
- Branch routers
    
- Internet-edge routers
    
- Routers with a single upstream path
    

A configured default route can become the router's **gateway of last resort** when it is  
installed in the routing table.

Verify with:

```cisco
show ip route
```

## 5. Troubleshooting

|Symptom|Possible Cause|Check|
|---|---|---|
|Static route missing from RIB|Next hop unresolved, interface down, invalid configuration, or route preference|`show ip route`, `show ip interface brief`|
|Static route exists but traffic fails|Next-hop/adjacency problem, ACL, or downstream failure|`show ip route`, `show ip cef`, ping/traceroute|
|Unexpected path|More-specific route exists|`show ip route <destination>`|
|Floating static not active|Primary route still installed|`show ip route <destination>`|
|Backup does not work|Backup AD not higher than primary or next hop unavailable|Verify AD and reachability|
|Interface-only static behaves unexpectedly|Broadcast/Ethernet interface resolution or ARP behavior|Check interface, ARP, and CEF|
|Traffic disappears into Null0|Destination matches discard route|`show ip route <destination>`|
|Tracking route disappears|Tracked object is down|`show track`|

## 6. Design Use Cases

|Use Case|Why Use Static Routing|
|---|---|
|**Stub network**|Simple topology with one upstream path|
|**Default route**|Send unknown destinations toward an upstream router|
|**Backup path**|Floating static with higher AD|
|**Small fixed topology**|Minimal routing overhead|
|**Hub-and-spoke**|Predictable paths|
|**Summary loop prevention**|Null0 discard route|
|**Controlled routing**|Administrator explicitly defines the path|

## 7. Exam Traps

### Trap 1 — Static AD is 1

```text
Connected = 0
Static    = 1
```

Static routes normally beat dynamic routes **for the same prefix**.

---

### Trap 2 — Longest Prefix Comes First

Do not say:

> "AD 1 always beats AD 110."

The correct process is:

```text
1. Longest-prefix match
2. Route preference / AD among competing routes
3. Metric where applicable
```

A more-specific prefix can therefore beat a less-specific static route even when the  
less-specific route has a lower AD.

---

### Trap 3 — Higher AD Means Backup

```cisco
ip route 10.1.1.0 255.255.255.0 192.0.2.1 200
```

AD 200 makes the route less preferred than normal static AD 1.

This is the basis of a **floating static route**.

---

### Trap 4 — Static Routes Do Not Automatically Discover Paths

Static routes are manually configured.

They do not participate in an IGP's automatic neighbor discovery or topology exchange.

Failover requires mechanisms such as:

- Floating static routes
    
- Object tracking
    
- IP SLA
    
- Multiple equal-cost static routes
    

---

### Trap 5 — Fully Specified Does Not Mean "Magic"

A fully specified static route provides both:

```text
Exit interface + next hop
```

It removes ambiguity, but the next hop still must be usable for forwarding.

---

### Trap 6 — Interface-Only Statics Are Context-Dependent

An interface-only static is not universally equivalent to:

> "The interface is up, therefore the remote network is reachable."

On Ethernet/broadcast interfaces, the router may need ARP/adjacency resolution for the  
destination or next hop.

For typical Ethernet designs, specifying a next hop is usually clearer.

---

### Trap 7 — Null0 Drops Traffic

A route to Null0 intentionally discards matching traffic.

```cisco
ip route 10.0.0.0 255.0.0.0 Null0
```

It is commonly used with summarization to prevent traffic for nonexistent destinations  
from being forwarded incorrectly or causing routing loops.

---

### Trap 8 — Static Routes Are Not Advertised Automatically

A static route exists locally.

It is **not automatically advertised** to other routers.

To make it part of a dynamic routing domain, it must be redistributed or otherwise  
introduced according to the routing protocol's configuration.

---

## 8. Static Routing Decision Model

A useful mental model is:

```text
Packet arrives
      ↓
Destination IP
      ↓
Longest-prefix match
      ↓
Select best route
      ↓
Resolve next hop / adjacency
      ↓
CEF forwarding
      ↓
Outgoing interface
```

For static routes, the route itself is manually defined, but the router still performs  
normal route selection and forwarding resolution.

**CCNP takeaway:** Static routing gives the administrator deterministic control, but that  
control comes at the cost of manual configuration. Know the difference between **next-hop,  
interface, and fully specified statics**, understand **recursive resolution**, and be able  
to distinguish **normal static, floating static, tracked static, ECMP static, default, and  
Null0 routes**.
