# Administrative Distance

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Administrative Distance (AD)** is a 0–255 **trust value** that ranks routing *sources*
(directly connected, static, OSPF, EIGRP, BGP, ...). When the **same prefix** is learned
from multiple protocols, the router installs the source with the **lowest AD** into the
RIB. AD is about *who* told you, not how good the path is — that job belongs to metrics.

---

## 2. Core Concepts

### 2.1 The decision split

| Stage | Uses | Question answered |
|-------|------|-------------------|
| 1. Source selection | **AD** | which protocol do I trust more? |
| 2. Path selection | **Metric** | which route from that protocol is best? |

- AD never compares paths across protocols; it only picks the source.

### 2.2 Default AD values (exam table — memorize)

| Source | AD |
|--------|-----|
| Connected interface | 0 |
| Static | 1 |
| EIGRP summary route | 5 |
| External BGP (eBGP) | 20 |
| EIGRP (internal) | 90 |
| IGRP | 100 |
| OSPF | 110 |
| IS-IS | 115 |
| RIP | 120 |
| EIGRP (external) | 170 |
| Internal BGP (iBGP) | 200 |
| Unknown/unreachable | 255 |

- **Lower AD wins.** A prefix present in multiple protocols → only the lowest-AD one is
  installed into the RIB.

### 2.3 Tuning AD per source and per prefix

```text
router eigrp 100
 distance 80 10.0.0.0 0.0.0.255   ! AD toward specific source
router ospf 1
 distance 150                    ! global AD for OSPF routes
ip route 10.1.1.0 255.255.255.0 192.0.2.1 10   ! static AD 10 (see note 09)
```

- Lowering OSPF AD below a static's AD makes OSPF win — a common design tool
  (prefer dynamic over static) and an equally common troubleshooting gotcha.

### 2.4 AD vs route redistribution interaction

- When you **redistribute** (Level 13/14), routes keep their *source protocol's AD* on the
  receiving router — that is why an OSPF-learned EIGRP route still shows up based on the
  AD configured for OSPF only if you also set `distance` appropriately.
- Redistribution does **not** convert AD — it converts metric; AD belongs to the
  receiving protocol.

### 2.5 AD and the routing table output

```
O    10.1.1.0/24 [110/20] via 192.0.2.1
                  ^^^
              110  = OSPF's AD   20 = OSPF metric
```

- Always read `[AD/metric]` as two numbers — the exam loves swapping them in trap answers.

## 3. Configuration / Commands

```text
show ip route                     ! [AD/metric] per entry
show ip route 10.1.1.0            ! shows AD + metric + source detail
show ip protocols                 ! per-protocol AD settings
show ip route summary
router ospf 1
 distance 130                     ! override OSPF default AD
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Static route never used | dynamic route has lower AD | compare `[AD/...]` in RIB |
| OSPF route missing | static AD 1 beats it | reduce OSPF `distance` or remove static |
| BGP route wins unexpectedly | eBGP AD 20 < OSPF 110 | verify protocol preference, set distance |
| Floating static never active | its AD still < primary protocol AD | raise the floating AD (note 09) |

---

## 5. Exam Traps

- **Lower AD wins** — the classic reversal trap.
- **AD ranks sources; metric ranks paths** — never merge them.
- **Connected AD = 0** — nothing beats connected except nothing.
- **eBGP 20 vs iBGP 200** — the two BGP values are different.
- **EIGRP internal 90 vs external 170** — reinstalled external routes jump AD.
- **Static default AD = 1** — a "static route wins over everything dynamic" trap.
