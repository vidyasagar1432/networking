# Administrative Distance

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Administrative Distance (AD)** is a Cisco value from **0–255** that represents the relative  
trustworthiness of a **routing source**.

When the same destination prefix is learned from multiple routing sources, the router uses  
AD to choose which source should be installed in the **RIB**.

> **Lower AD = more preferred routing source.**

AD answers:

> **"Which routing source should I trust?"**

The routing protocol's **metric** answers a different question:

> **"Which path is best within that routing protocol?"**

---

## 2. Core Concepts

### 2.1 AD vs Metric

|Decision Stage|Uses|Question|
|---|---|---|
|Source selection|**Administrative Distance**|Which routing source should I trust?|
|Path selection|**Protocol metric**|Which path from that routing protocol is best?|

### Example

Suppose a router learns:

```text
OSPF:   10.1.1.0/24 [110/20]
EIGRP:  10.1.1.0/24 [90/100]
```

The router compares:

```text
OSPF AD   = 110
EIGRP AD  = 90
```

EIGRP wins because:

```text
90 < 110
```

The OSPF metric `20` and EIGRP metric `100` are **not compared** because they belong  
to different routing protocols.

> **Exam rule:**  
> **AD compares routing sources. Metric compares paths within a routing protocol.**

---

## 2.2 Default Administrative Distance Values

These are the important Cisco default values to memorize for CCNP:

|Routing Source|Default AD|
|---|--:|
|Connected|**0**|
|Static|**1**|
|EIGRP summary|**5**|
|eBGP|**20**|
|EIGRP internal|**90**|
|IGRP|**100**|
|OSPF|**110**|
|IS-IS|**115**|
|RIP|**120**|
|EIGRP external|**170**|
|iBGP|**200**|
|Unknown / unusable|**255**|

### Memory order

```text
0    Connected
1    Static
5    EIGRP Summary
20   eBGP
90   EIGRP Internal
100  IGRP
110  OSPF
115  IS-IS
120  RIP
170  EIGRP External
200  iBGP
255  Unknown
```

> **Lower is better.**

---

## 2.3 AD Is Used for Source Selection

Consider:

```text
10.1.1.0/24
    │
    ├── Static     AD 1
    ├── EIGRP      AD 90
    └── OSPF       AD 110
```

The router prefers:

```text
Static AD 1
```

because:

```text
1 < 90 < 110
```

The EIGRP and OSPF routes can still exist as **candidate routes** in their respective  
routing-protocol databases, but they are not selected as the active RIB route while the  
lower-AD route is available.

---

## 2.4 AD Does Not Compare Metrics Between Protocols

This is a common exam trap.

```text
OSPF:
AD = 110
Metric = 10

EIGRP:
AD = 90
Metric = 1000
```

EIGRP still wins:

```text
90 < 110
```

The EIGRP metric of `1000` is irrelevant when comparing it against the OSPF route.

The metric only becomes relevant when selecting between candidate paths **inside the same  
routing protocol**.

---

## 2.5 Administrative Distance in `show ip route`

A Cisco route entry commonly looks like:

```text
O    10.1.1.0/24 [110/20] via 192.0.2.1
```

The brackets contain:

```text
[AD / Metric]
```

Therefore:

```text
[110/20]
   │  │
   │  └── OSPF metric
   └───── OSPF administrative distance
```

### Another example

```text
D    10.1.1.0/24 [90/30720] via 192.0.2.1
```

Means:

```text
90      = EIGRP AD
30720   = EIGRP metric
```

> **Exam trap:** Do not reverse `[AD/metric]`.

---

## 2.6 Changing Administrative Distance

Cisco IOS allows AD to be modified for different routing sources.

### OSPF — change the distance globally

```text
router ospf 1
 distance 150
```

This changes the AD used for OSPF routes on that router.

### EIGRP — change distance

```text
router eigrp 100
 distance 80
```

You can also use a more selective EIGRP distance configuration:

```text
router eigrp 100
 distance 80 10.0.0.1 0.0.0.0
```

The exact syntax and supported options depend on the IOS/IOS XE routing protocol and  
software version.

### Static route — set a custom AD

```text
ip route 10.1.1.0 255.255.255.0 192.0.2.1 10
```

Here:

```text
10 = Administrative Distance
```

The default AD for a static route is `1`.

---

## 2.7 Floating Static Routes

A **floating static route** is a static route configured with a higher AD than the  
primary route.

Example:

```text
Primary OSPF route:
AD = 110

Floating static route:
AD = 200
```

The static route is not preferred while OSPF is available:

```text
110 < 200
```

If the OSPF route disappears, the static route can become active.

Example:

```text
ip route 10.1.1.0 255.255.255.0 192.0.2.5 200
```

> **Key idea:** A floating static route is a **backup route created by giving a static  
> route a higher AD**.

---

## 2.8 AD and Redistribution

**Administrative Distance does not get carried inside a route as an attribute.**

When a route is redistributed from one routing protocol into another, the receiving router  
evaluates the resulting route according to the **receiving routing protocol/source** and its  
local AD rules.

For example:

```text
OSPF route
    │
    │ redistribution
    ▼
EIGRP
```

The original OSPF AD of `110` is **not preserved as a property of the redistributed route**.

Instead, EIGRP's local route-selection behavior and AD apply to the resulting EIGRP route.

> **Important distinction:**  
> **Metric can be translated/set during redistribution. AD is a local route-selection value  
> on the receiving router; it is not redistributed with the route.**

## 4. Troubleshooting

|Symptom|Likely Cause|What to Check|
|---|---|---|
|Static route not installed|Another source has lower AD|Compare `[AD/metric]`|
|OSPF route missing|Static route with AD 1 is preferred|Check `show ip route`|
|EIGRP route not selected|Another source has lower AD|Compare candidate sources|
|BGP route unexpectedly loses|Another source has lower AD|Check eBGP/iBGP AD|
|Floating static is active too early|Its AD is not higher than the primary route|Increase static AD|
|Expected backup route is absent|Primary route still exists or static next hop is unreachable|Check primary route and next-hop reachability|
|Route source preference changed unexpectedly|AD was manually modified|`show ip protocols`, configuration|

## 5. Exam Traps

### Trap 1 — Lower AD Wins

```text
AD 90
AD 110
```

The route with **AD 90** wins.

> **Lower is better.**

---

### Trap 2 — AD Is Not the Metric

```text
[110/20]
```

means:

```text
110 = AD
20  = metric
```

---

### Trap 3 — AD Compares Sources

AD is used when choosing between routes from different routing sources.

```text
EIGRP AD 90
OSPF  AD 110
```

EIGRP is preferred.

---

### Trap 4 — Metric Selects the Best Path Within a Protocol

If OSPF has multiple candidate paths, OSPF uses its own metric:

```text
OSPF path A = cost 20
OSPF path B = cost 40
```

The lower-cost OSPF path is preferred.

---

### Trap 5 — eBGP vs iBGP

Memorize:

```text
eBGP = 20
iBGP = 200
```

These are significantly different values.

---

### Trap 6 — EIGRP Internal vs External

```text
EIGRP Internal = 90
EIGRP External = 170
```

Do not confuse the two.

---

### Trap 7 — Static Usually Beats Dynamic Routing

Default static AD:

```text
1
```

Therefore, a normal static route is preferred over:

```text
EIGRP 90
OSPF  110
RIP   120
```

unless its AD is manually increased.

---

### Trap 8 — Connected Has AD 0

Connected routes have:

```text
AD = 0
```

They are therefore preferred over static and dynamic routes for the same prefix.

---

### Trap 9 — AD Is Local

AD is **not a route attribute that gets advertised between routers**.

Changing AD on one router changes that router's local route-source preference; it does not  
change the AD value used by another router.

## 7. Connections

- **01 · Routing Table** — AD helps determine which candidate route enters the RIB.
    
- **03 · Metrics** — metrics select the best path within a routing protocol.
    
- **08 · Static Routes** — static routes normally have AD `1`.
    
- **09 · Floating Static Routes** — use a higher AD to create a backup path.
    
- **10 · Default Routes** — default routes can also have different AD values.
