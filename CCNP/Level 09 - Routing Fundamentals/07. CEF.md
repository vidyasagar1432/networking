# CEF (Cisco Express Forwarding)

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Cisco Express Forwarding (CEF)** is Cisco's **default data-plane forwarding engine**.
It builds the **FIB** (prefix → next hop) plus **adjacency tables** (next hop → MAC/egress)
ahead of traffic and pushes them to hardware, giving **line-rate, per-flow load-balanced**
forwarding with no per-packet CPU lookups. CEF = FIB + adjacency, built from the RIB.

---

## 2. Core Concepts

### 2.1 The two CEF tables

| Table | Content | Built from |
|-------|---------|-----------|
| **FIB** | destination prefix → next hop | RIB winners (note 05) |
| **Adjacency** | next hop → L2 rewrite (MAC + egress) | ARP / ND |

- Data plane does a single **LPM (longest-prefix-match)** lookup in the FIB, then uses
  the adjacency for L2 rewrite. No route-process involvement per packet.

### 2.2 Adjacency types

| Type | When | Behavior |
|------|------|----------|
| **Glean** | attached subnet | ARP for unknown hosts |
| **Receive** | router's own address | punt to control plane |
| **Drop** | null0 / unresolved | discard silently |
| **Normal** | resolved next hop | rewrite & forward |

### 2.3 CEF load balancing (per-flow, not per-packet)

```
hash = (src IP, dst IP [, src port, dst port]) → chooses one member path
```

- Hash is **deterministic per flow** → no reordering, ECMP shares across links.
- **Hash polarization** on multi-stage ECMP networks: use different hash inputs per layer
  to avoid all flows choosing the same link. Mitigated with `cef load-balancing algorithm`.

### 2.4 Control vs data plane (whole picture)

| Component | Plane | Role |
|-----------|-------|------|
| RIB | control | route selection (note 06) |
| FIB | data | prefix lookup |
| Adjacency | data | L2 rewrite |
| CEF | both | FIB + adjacency engine |

- Modifications to RIB (new best route) **reprogram CEF/FIB**; recursive resolution
  (note 04) happens at that update time.

### 2.5 CEF failure behavior

| Condition | Result |
|-----------|--------|
| FIB entry missing prefix | no match → fall to default route / drop |
| Adjacency unresolved | packet punted to CPU for ARP |
| Hardware (TCAM) full | new routes not installed → drops |
| CEF disabled (rare) | fallback slow-path routing |

## 3. Configuration / Commands

```text
show ip cef                        ! FIB view
show ip cef 10.1.1.0
show ip cef summary                ! counts + memory
show adjacency                     ! L2 rewrite table
show adjacency max-current         ! adjacency stats
show ip interface Gi0/1            ! "CEF is enabled" line

! hash tuning
cef load-balancing algorithm include-ports
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Traffic dropped but RIB fine | FIB/CEF not updated / TCAM full | `show ip cef summary` |
| Slow path / high CPU | adjacencies unresolved (ARP storms) | `show adjacency`, ARP count |
| Uneven ECMP links | hash polarization, same hash inputs | tune `cef load-balancing algorithm` |
| Packets punted | receive/glean type entries | `show ip cef` type column |
| Hardware lookup miss | scale limit hit | reduce prefixes / summarize |

---

## 5. Exam Traps

- **CEF is enabled by default** on modern IOS/IOS-XE — no config required.
- **CEF = FIB + adjacency** — two tables, not one.
- **Load balancing is per-flow (hash), not per-packet** — avoids reordering.
- **Recursion is resolved when FIB updates** — not per packet (note 04).
- **"Routing table lookup per packet" is outdated** — modern = CEF LPM in FIB.
- **Hash polarization** — the classic multi-tier ECMP gotcha.
