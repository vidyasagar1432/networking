# CEF (Cisco Express Forwarding)

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Cisco Express Forwarding (CEF)** is Cisco's high-performance **IP forwarding architecture**. It uses a **Forwarding Information Base (FIB)** and an **adjacency table** to make packet-forwarding decisions efficiently without requiring a full routing-table lookup for every packet.

CEF derives its Layer-3 forwarding information from the **RIB** and uses adjacency information to perform the required **Layer-2 rewrite**.

A useful exam model is:

> **RIB → CEF → FIB + Adjacency → Packet Forwarding**

CEF can use hardware forwarding on platforms that support it, while the exact hardware implementation is platform-dependent.

---

## 2. Core Concepts

### 2.1 CEF's Two Main Forwarding Structures

CEF primarily works with two related structures:

|Structure|Contains|Built/Resolved From|
|---|---|---|
|**FIB**|Destination prefix → forwarding information|RIB|
|**Adjacency Table**|Next-hop/interface → Layer-2 rewrite information|ARP / IPv6 ND and interface information|

### FIB

The FIB answers:

> **Which forwarding path should be used for this destination?**

Example:

```text
10.1.1.0/24
    ↓
via 192.168.1.2
Gi0/1
```

### Adjacency Table

The adjacency table provides the Layer-2 information required to send the packet on the selected interface.

Example:

```text
Next hop:       192.168.1.2
Interface:      Gi0/1
Destination MAC: aaaa.bbbb.cccc
```

For IPv4, **ARP** commonly resolves the next-hop MAC address.

For IPv6, **Neighbor Discovery (ND)** performs neighbor resolution.

> **Exam shortcut:**  
> **FIB = Layer-3 forwarding decision**  
> **Adjacency = Layer-2 rewrite information**

---

## 3. Packet Forwarding with CEF

A simplified forwarding process is:

```text
Incoming Packet
      ↓
Destination IP
      ↓
FIB Lookup
      ↓
Longest-Prefix Match
      ↓
Forwarding Entry
      ↓
Adjacency Lookup
      ↓
L2 Rewrite
      ↓
Outgoing Interface
      ↓
Packet Forwarded
```

The router does **not normally perform a complete RIB route-selection process for every packet**.

Instead:

1. The RIB determines the active route.
    
2. CEF builds/updates the FIB.
    
3. CEF resolves the required adjacency information.
    
4. Incoming packets use the FIB and adjacency information for forwarding.
    

> **Exam point:**  
> **RIB = control-plane route selection.**  
> **CEF/FIB = normal data-plane forwarding.**

---

## 4. Longest-Prefix Match

CEF uses **Longest-Prefix Match (LPM)** when selecting the destination prefix in the FIB.

Example:

```text
10.0.0.0/8
10.10.0.0/16
10.10.10.0/24
```

For:

```text
Destination = 10.10.10.50
```

The `/24` entry wins:

```text
10.10.10.0/24
```

because it is the most specific matching prefix.

---

## 5. CEF Adjacency Types

CEF can display different types of adjacency/forwarding entries.

|Type|Meaning|Typical Behavior|
|---|---|---|
|**Normal**|Next hop has been resolved|Perform L2 rewrite and forward|
|**Glean**|Host is on a connected subnet but specific host adjacency is not resolved|ARP/ND can be used to resolve the host|
|**Receive**|Destination address belongs to the router|Packet is handled locally|
|**Drop**|Packet should be discarded|Packet is dropped|
|**Null**|Forwarding toward a null interface|Packet is intentionally discarded|

### Glean

Suppose the router has:

```text
10.10.10.0/24 → Gi0/1
```

but does not yet know the MAC address of:

```text
10.10.10.50
```

The connected subnet can have a **glean** entry.

The router can then use ARP for IPv4 or ND for IPv6 to resolve the specific host adjacency.

> **Exam shortcut:**  
> **Glean = connected subnet known, specific host adjacency unresolved.**

---

## 6. CEF and Recursive Next-Hop Resolution

Consider:

```text
10.20.20.0/24
      ↓
next hop 192.168.100.2
```

If `192.168.100.2` is not directly connected, the router must recursively determine how to reach it.

Example:

```text
10.20.20.0/24
      ↓
192.168.100.2
      ↓
192.168.100.0/24
      ↓
Gi0/1
```

CEF uses the resulting forwarding information to build the appropriate FIB/adjacency relationship.

The packet-forwarding path does not perform the entire recursive RIB lookup for every packet.

> **Exam point:**  
> **Recursive resolution is performed when forwarding information is built or updated, not as a complete recursive routing lookup for every packet.**

---

## 7. CEF Load Balancing

CEF can support **ECMP (Equal-Cost Multi-Path)** forwarding.

When multiple equal-cost paths exist:

```text
10.20.0.0/16
      │
 ┌────┴────┐
 ↓         ↓
Path A    Path B
```

CEF can use a **hash-based load-sharing algorithm** to select a path.

A simplified conceptual model is:

```text
Flow attributes
      ↓
   Hashing
      ↓
Select ECMP path
```

Depending on the platform and configuration, the hash can use fields such as:

- Source IP
    
- Destination IP
    
- Source port
    
- Destination port
    
- Protocol
    

> **Important:** Exact hash inputs and load-balancing behavior are **platform-dependent**.

### Per-Flow vs Per-Packet

CEF commonly performs **per-flow/per-destination load sharing**, rather than blindly alternating every packet between paths.

This helps keep packets belonging to the same flow on a consistent path and reduces packet reordering.

> **Exam shortcut:**  
> **ECMP + CEF → hash-based load sharing.**

---

## 8. Hash Polarization

**Hash polarization** can occur in a multi-stage ECMP topology when different devices use similar hashing inputs and repeatedly select corresponding paths.

Example:

```text
          Router A
         /        \
        /          \
      Path 1      Path 2
        \          /
         \        /
          Router B
         /        \
        /          \
      Path 1      Path 2
```

If both routers use the same effective hash behavior, traffic can become concentrated on particular links instead of being evenly distributed.

Possible mitigation depends on the platform and can include:

- Different hashing inputs
    
- Platform-specific load-balancing options
    
- Topology/design changes
    

> **Exam point:** Hash polarization is a **multi-stage ECMP load-balancing issue**, not a routing-table selection problem.

## 9. CEF and Control/Data Plane Relationship

|Component|Plane|Main Role|
|---|---|---|
|**Routing Protocol**|Control|Learns routes and selects protocol-specific paths|
|**RIB**|Control|Determines active routing information|
|**CEF**|Forwarding architecture|Builds/uses forwarding structures|
|**FIB**|Data|Destination-prefix forwarding lookup|
|**Adjacency Table**|Data|Layer-2 rewrite information|
|**Hardware Forwarding**|Data|Platform-dependent packet forwarding|

### Complete Picture

```text
Routing Protocols / Static / Connected
                  ↓
                 RIB
            Route Selection
                  ↓
                 CEF
             ↙          ↘
           FIB       Adjacency
            ↓             ↓
       L3 Decision     L2 Rewrite
             └──────┬──────┘
                    ↓
              Packet Forwarding
```

## 10. CEF Updates

When the RIB changes, CEF forwarding information must be updated.

Typical events include:

- New route learned
    
- Better route selected
    
- Route withdrawn
    
- Interface state change
    
- Next-hop reachability change
    
- ARP/ND adjacency change
    
- ECMP path change
    

Simplified process:

```text
Routing Change
      ↓
RIB Changes
      ↓
CEF/FIB Update
      ↓
Adjacency Update if Required
      ↓
New Forwarding Behavior
```

This allows the data plane to adapt to control-plane changes without requiring every packet to consult the routing process.

## 11. CEF Failure and Exceptional Conditions

CEF forwarding can encounter conditions that require special handling.

|Condition|Possible Result|
|---|---|
|No matching FIB entry|Default route if available; otherwise drop|
|Unresolved adjacency|Adjacency resolution/exception handling may occur|
|Receive entry|Packet handled locally|
|Drop entry|Packet discarded|
|Hardware forwarding resource limit|Platform-specific forwarding limitations|
|CEF disabled|Different/slower forwarding path depending on platform/software|

### Important

Do **not** memorize:

> "Unresolved adjacency always means the packet is punted to the CPU."

The exact behavior is **platform- and software-dependent**.

Similarly, do not assume:

> "TCAM full always means all new routes immediately drop."

Hardware forwarding-resource behavior varies by Cisco platform and feature set.


```text
show ip cef 10.1.1.0
```

### View detailed CEF information

```text
show ip cef detail
```

### View CEF summary

```text
show ip cef summary
```

### View adjacency information

```text

```

### View routing table for comparison

```text
show ip route
```

### Check ARP resolution

```text
show ip arp
```

### Check interface CEF status

```text
show ip interface GigabitEthernet0/1
```

> The exact CEF commands and output vary between Cisco IOS, IOS XE, and hardware platforms.

## 13. CEF Load-Balancing Configuration

Some Cisco platforms provide commands for modifying CEF load-balancing behavior.

For example, platform/software versions may support:

```text
cef load-balancing algorithm include-ports
```

This should **not** be memorized as a universal command.

> **Exam focus:** Understand the concept of **hash-based ECMP load sharing** and **hash polarization**. Exact configuration syntax is platform-dependent.

## 14. Troubleshooting

|Symptom|Possible Cause|What to Check|
|---|---|---|
|RIB has route but traffic fails|FIB/adjacency or another forwarding issue|`show ip route`, `show ip cef`|
|Next hop unresolved|ARP/ND or Layer-2 problem|`show ip arp`, `show adjacency`|
|Connected subnet shows glean|Host adjacency not yet resolved|ARP/ND and Layer-2 connectivity|
|Unexpected drop|Drop/null entry or another forwarding condition|`show ip cef`|
|ECMP links uneven|Hashing behavior or polarization|Platform-specific CEF load-sharing information|
|Forwarding-resource limitation|Hardware scale/capacity issue|Platform-specific hardware/TCAM commands|
|CPU unexpectedly high|Exception/punt traffic or another control-plane issue|Platform-specific punt/CPU diagnostics|

## 15. Exam Traps

### Trap 1 — CEF = RIB

**Incorrect.**

```text
RIB  → control plane → route selection
CEF  → forwarding architecture
FIB  → data-plane forwarding information
```

---

### Trap 2 — CEF is just the FIB

**Incorrect.**

A useful exam model is:

```text
CEF
 ├── FIB
 └── Adjacency information
```

CEF uses these structures together to perform efficient forwarding.

---

### Trap 3 — CEF performs a routing-table lookup for every packet

**Incorrect.**

Normal CEF forwarding uses the FIB and adjacency information rather than invoking the full routing process for every packet.

---

### Trap 4 — CEF always means ASIC/TCAM forwarding

**Incorrect.**

CEF is a forwarding architecture. The exact hardware/software implementation is **platform-dependent**.

---

### Trap 5 — Per-packet load balancing is the default CEF behavior

**Incorrect.**

CEF commonly uses **hash-based load sharing**, typically keeping packets of a flow on a consistent path.

---

### Trap 6 — All CEF hash inputs are universal

**Incorrect.**

The exact fields used by the hashing algorithm vary by Cisco platform, software, and configuration.

---

### Trap 7 — Glean means the route is missing

**Incorrect.**

Glean generally means the router knows the destination belongs to a connected subnet but does not yet have the specific host's resolved adjacency.

---

### Trap 8 — Receive means normal forwarding

**Incorrect.**

A **receive** entry represents traffic destined for an address owned by the router and is handled locally.

## 16. RIB → CEF → FIB → Adjacency

The complete exam mental model:

```text
             ROUTING INFORMATION
                     ↓
                    RIB
              "Which route?"
                     ↓
                    CEF
          ┌──────────┴──────────┐
          ↓                     ↓
         FIB               Adjacency
    "Which path?"          "Which L2 rewrite?"
          └──────────┬──────────┘
                     ↓
              Packet Forwarding
```

### One-Sentence Memory Rule

> **RIB selects the route → CEF builds/uses forwarding information → FIB performs the Layer-3 lookup → adjacency provides the Layer-2 rewrite.**
