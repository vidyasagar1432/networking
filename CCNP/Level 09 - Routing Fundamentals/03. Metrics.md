# Routing Metrics

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **routing metric** is a value used by a routing protocol to measure the relative  
**cost or preference of a path** to a destination.

When multiple routes to the same prefix come from the **same routing protocol**, the  
protocol uses its metric to select the best path.

When routes come from **different routing sources**, the router first uses  
**Administrative Distance (AD)** to choose the preferred source.

> **AD answers:** "Which routing source do I trust?"  
> **Metric answers:** "Which path from that source is best?"

Each routing protocol has its own metric calculation and units. Therefore, **metrics  
from different protocols cannot be directly compared**.

---

## 2. Core Concepts

### 2.1 Metric by Protocol

|Protocol / Route Source|Metric|What It Measures|
|---|---|---|
|Static|No routing-protocol metric|Static route selection primarily uses AD|
|Connected|No routing-protocol metric|Directly connected network|
|OSPF|Cost|Reference bandwidth ÷ interface bandwidth|
|EIGRP|Composite metric|Primarily bandwidth + delay by default|
|RIP|Hop count|Number of routers/hops|
|IS-IS|Cost|Configured per-interface/path cost|

> **Exam rule:**  
> **Same protocol → metric**  
> **Different protocols → AD**

---

## 2.2 OSPF Metric — Cost

OSPF calls its metric **cost**.

The basic calculation is:

```text
OSPF cost = Reference bandwidth / Interface bandwidth
```

Cisco IOS/IOS XE represents the resulting cost as an integer.

### Example with 100-Mbps reference bandwidth

|Interface Bandwidth|OSPF Cost|
|--:|--:|
|10 Mbps|10|
|100 Mbps|1|
|1 Gbps|1|
|10 Gbps|1|

This creates an important problem with modern high-speed interfaces:

```text
100 Mbps → cost 1
1 Gbps   → cost 1
10 Gbps  → cost 1
```

Therefore, OSPF may treat these interfaces as equal-cost unless the reference bandwidth  
is increased or costs are manually configured.

### Example with 1-Gbps reference bandwidth

|Interface Bandwidth|OSPF Cost|
|--:|--:|
|10 Mbps|100|
|100 Mbps|10|
|1 Gbps|1|
|10 Gbps|1|

### Important

The OSPF **path cost** is the sum of the OSPF interface costs along the path toward  
the destination.

```text
R1 ──10── R2 ──10── R3
```

Total path cost:

```text
10 + 10 = 20
```

Lower OSPF cost is preferred.

---

## 2.3 OSPF Reference Bandwidth

The reference bandwidth can be changed so that modern high-speed links receive  
meaningfully different costs.

```text
router ospf 1
 auto-cost reference-bandwidth 1000
```

The value is specified in **Mbps**.

For example:

```text
1000 Mbps = 1 Gbps
```

With a 1-Gbps reference:

```text
10 Mbps  → 100
100 Mbps → 10
1 Gbps   → 1
10 Gbps  → 1
```

> **Important:** The reference bandwidth must be configured consistently across the  
> OSPF domain when you intend predictable cost calculations.

---

## 2.4 Manually Setting OSPF Cost

An interface's OSPF cost can be manually configured:

```text
interface GigabitEthernet0/1
 ip ospf cost 25
```

This provides explicit control over path selection.

A manually configured OSPF cost takes precedence over the automatically calculated  
interface cost.

### Traffic engineering

To influence OSPF path selection:

```text
Increase cost → make path less preferred
Decrease cost → make path more preferred
```

Example:

```text
Path A = cost 10
Path B = cost 50
```

OSPF prefers:

```text
Path A
```

---

## 2.5 EIGRP Composite Metric

EIGRP uses a **composite metric**.

The classic EIGRP metric uses:

- Bandwidth
    
- Delay
    
- Load
    
- Reliability
    
- K values
    

The general formula is:

```text
Metric =
256 × [
    K1 × BW
    + (K2 × BW)/(256 − Load)
    + K3 × Delay
] ×
[K5/(Reliability + K4)]
```

The bandwidth and delay terms are scaled values.

### Default EIGRP K values

Cisco's default K values are:

```text
K1 = 1
K2 = 0
K3 = 1
K4 = 0
K5 = 0
```

Therefore, the effective default calculation uses:

```text
Bandwidth + Delay
```

More specifically, the commonly used simplified calculation is:

```text
256 × (
    10^7 / minimum bandwidth
    + cumulative delay / 10
)
```

where:

- Bandwidth is based on the **minimum bandwidth** along the path.
    
- Delay is the **cumulative delay** along the path.
    

> **Exam focus:** EIGRP's default metric is primarily **bandwidth + delay**.

---

## 2.6 EIGRP Bandwidth and Delay

Bandwidth can influence the EIGRP metric:

```text
interface GigabitEthernet0/1
 bandwidth 1000000
```

The bandwidth command uses **Kbps**.

For example:

```text
1000000 Kbps = 1 Gbps
```

Delay can also be configured:

```text
interface GigabitEthernet0/1
 delay 100
```

The IOS delay value is expressed in **tens of microseconds**.

Therefore:

```text
delay 100
```

represents:

```text
100 × 10 microseconds
= 1000 microseconds
= 1 millisecond
```

> **Important:** The `bandwidth` command changes the interface's **routing metric  
> attribute**; it does not change the physical link speed.

---

## 2.7 EIGRP K Values

EIGRP neighbors must agree on the K values used for metric calculation.

If incompatible K values are configured between neighbors, EIGRP adjacency formation  
can fail.

For normal Cisco EIGRP operation, the default values are:

```text
K1 = 1
K2 = 0
K3 = 1
K4 = 0
K5 = 0
```

This means load and reliability are not included in the default EIGRP metric.

> **Exam trap:** Don't include load or reliability in a normal EIGRP metric calculation  
> unless the question explicitly changes the K values.

---

## 2.8 RIP Metric — Hop Count

RIP uses **hop count** as its metric.

```text
R1 ─ R2 ─ R3 ─ R4
```

From R1 to R4:

```text
3 hops
```

RIP prefers the path with the **lowest hop count**.

### RIP limit

```text
1–15 hops = reachable
16 hops    = infinity / unreachable
```

Therefore:

> **15 is the maximum reachable RIP hop count.**

RIP does **not** consider:

- Bandwidth
    
- Delay
    
- Link speed
    
- Congestion
    

This creates a classic routing-design problem:

```text
Fast path = 5 hops
Slow path = 2 hops
```

RIP may choose:

```text
Slow 2-hop path
```

because hop count is its metric.

---

## 2.9 IS-IS Metric — Cost

IS-IS uses a **cost** metric.

The cost is associated with interfaces/links and contributes to the total path cost.

For a path:

```text
R1 ──10── R2 ──20── R3
```

Total path cost:

```text
10 + 20 = 30
```

Lower total cost is preferred.

Cisco implementations commonly use a default interface metric of `10`, but the exact  
default and metric behavior should be verified against the platform and IS-IS configuration.

---

## 2.10 Same Protocol vs Different Protocol

### Same protocol

Metric determines the preferred path.

```text
OSPF Path A = cost 10
OSPF Path B = cost 30
```

OSPF chooses:

```text
Path A
```

---

### Different protocols

AD determines the preferred routing source.

```text
OSPF:
AD = 110
Metric = 10

EIGRP:
AD = 90
Metric = 1000
```

EIGRP wins because:

```text
90 < 110
```

The OSPF cost `10` and EIGRP metric `1000` are **not compared**.

---

## 2.11 Equal-Cost Paths and ECMP

If a routing protocol finds multiple paths with the same qualifying metric, it may install  
multiple paths using **ECMP (Equal-Cost Multipath)**.

Example:

```text
OSPF:

10.1.1.0/24
 ├── Path A → cost 20
 └── Path B → cost 20
```

Both paths can be installed if the protocol and platform allow it.

The exact number of supported paths depends on the **routing protocol, platform,  
software, and configuration**.

## 3. Configuration / Verification Commands

### OSPF

```text
router ospf 1
 auto-cost reference-bandwidth 1000
```

Set the OSPF reference bandwidth to 1 Gbps.

```text
interface GigabitEthernet0/1
 ip ospf cost 25
```

Manually set OSPF interface cost.

```text
show ip ospf interface brief
```

View OSPF-enabled interfaces and their costs.

```text
show ip ospf interface GigabitEthernet0/1
```

View detailed OSPF interface information, including cost.

---

### EIGRP

```text
interface GigabitEthernet0/1
 bandwidth 1000000
 delay 100
```

Modify interface values used by EIGRP's metric calculation.

```text
show ip eigrp topology
```

View EIGRP topology and successor/feasible-successor information.

```text
show ip eigrp neighbors
```

Verify EIGRP neighbor relationships.

---

### RIP

```text
router rip
 maximum-paths 4
```

Configure the maximum number of equal-cost RIP paths that can be installed.

> `maximum-paths` controls ECMP; it does **not** change the RIP hop-count metric.

---

### General

```text
show ip route
```

View routes and their:

```text
[AD/metric]
```

For example:

```text
O 10.1.1.0/24 [110/20] via 192.0.2.1
```

Here:

```text
110 = AD
20  = OSPF metric
```

## 4. Troubleshooting

|Symptom|Likely Cause|Check / Fix|
|---|---|---|
|1-Gbps and 10-Gbps OSPF links have same cost|Reference bandwidth too low|Increase OSPF reference bandwidth|
|OSPF chooses unexpected path|Interface cost incorrect|`show ip ospf interface`|
|Traffic uses slow RIP path|RIP only considers hop count|Use a more appropriate metric-aware protocol|
|EIGRP path appears unexpected|Bandwidth/delay affects metric|Check interface `bandwidth` and `delay`|
|EIGRP adjacency fails after metric tuning|K values do not match|Verify EIGRP K values|
|Two paths are installed|Equal-cost paths exist|Check ECMP/max-paths|
|OSPF and EIGRP metrics appear different|Metrics are protocol-specific|Compare AD, not metric|
|Static route preferred over dynamic route|Static route has lower default AD|Check `[AD/metric]`|

## 5. Exam Traps

### Trap 1 — AD vs Metric

```text
Different routing sources → AD
Same routing protocol     → Metric
```

Never compare:

```text
OSPF cost 20
EIGRP metric 5000
```

The numbers have different meanings.

---

### Trap 2 — Lower Metric Usually Wins

For the protocols covered here:

```text
OSPF  → lower cost
EIGRP → lower composite metric
RIP   → lower hop count
IS-IS → lower cost
```

---

### Trap 3 — OSPF Reference Bandwidth

With the classic 100-Mbps reference:

```text
100 Mbps → 1
1 Gbps   → 1
10 Gbps  → 1
```

This is why modern networks often increase the reference bandwidth.

---

### Trap 4 — OSPF Path Cost Is Cumulative

Do not use only the destination interface cost.

```text
R1 ──10── R2 ──20── R3
```

Total:

```text
10 + 20 = 30
```

---

### Trap 5 — EIGRP Default Metric

Default EIGRP K values:

```text
K1=1
K2=0
K3=1
K4=0
K5=0
```

Therefore:

```text
Default EIGRP metric → bandwidth + delay
```

Load and reliability are not normally part of the default calculation.

---

### Trap 6 — EIGRP Minimum Bandwidth

EIGRP's bandwidth component uses the **minimum bandwidth along the path**, not the  
average or total bandwidth.

---

### Trap 7 — RIP 15/16 Rule

```text
15 = maximum reachable
16 = infinity / unreachable
```

---

### Trap 8 — `maximum-paths` Is Not Metric Tuning

```text
maximum-paths
```

controls how many equal-cost paths can be installed.

It does not change the underlying routing metric.

---

### Trap 9 — Static Routes

A normal static route does not participate in a routing protocol's metric calculation.

Its default AD is:

```text
1
```

A floating static route uses a **higher AD** to act as a backup.

---

### Trap 10 — EIGRP K Values Must Match

Changing K values is not simply a local metric-tuning operation.

If neighboring EIGRP routers have incompatible K values, adjacency formation can fail.

## 8. Connections

- **01 · Routing Table** — selected routes and their `[AD/metric]` values appear in the RIB.
    
- **02 · Administrative Distance** — selects between different routing sources.
    
- **08 · Static Routes** — static routes normally use AD `1`.
    
- **09 · Floating Static Routes** — higher AD creates a backup route.
    
- **11 · Route Summarization** — affects how prefixes are represented in routing tables.
    
- **OSPF topics** — OSPF cost and reference bandwidth are central to SPF path selection.
    
- **EIGRP topics** — composite metric, bandwidth, delay, and K values determine path selection.
