# Route Summarization (Aggregation)

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Route summarization** replaces many consecutive prefixes with **one less-specific
prefix** (e.g., `10.1.1.0/24 … 10.1.7.0/24` → `10.1.0.0/21`). Aggregation shrinks the RIB,
reduces CPU/BGP churn, improves convergence, and hides instability. Its cost: you may route
traffic for **sub-ranges you don't have** — handled with a **Null0 "discard" route** to
avoid loops.

---

## 2. Core Concepts

### 2.1 The win table

| Benefit | Detail |
|---------|--------|
| Table size | fewer prefixes in RIB/FIB (TCAM efficiency up) |
| Convergence | fewer updates → faster, less flap |
| Stability | internal flaps don't propagate (BGP/OSPF filtering) |
| Determinism | aggregate = one next hop at the boundary |
| TRAM / CPU | less control-plane work |

### 2.2 Auto vs manual summarization by protocol

| Protocol | Auto-summarization | Manual |
|----------|--------------------|--------|
| RIP v1 | classful (always) | — |
| RIP v2 | default off; `auto-summary` | `ip summary-address rip` |
| EIGRP | `auto-summary` old default (off later) | `ip summary-address eigrp N` |
| OSPF | **none** (LSAs always exact) | **area boundary** ABR aggregates |
| BGP | none | `ip prefix-list` + `aggregate-address` |

- **OSPF cannot summarize inside an area** — only at **ABR (between areas)** (Level 11).
- `summary-address` is used for **external** routes redistributed into OSPF.

### 2.3 Summarization points & math

- **Classful**: summarize to a class boundary (e.g., /8, /16, /24).
- **CIDR**: arbitrary length, best-fit block.
- Pick the smallest block that covers the whole range — the exam gives you ranges and
  asks for the aggregate: align on the **common prefix bits**.

### 2.4 Null0 "discard" companion (loop prevention)

```
EIGRP: ip summary-address eigrp 100 10.1.0.0 255.255.255.0 … creates a
       Null0 route for that summary on the router.
```

- A router advertising an aggregate must **drop traffic to ranges it doesn't actually have**
  — a **Null0 route** for the aggregate stops loops ("this summary exists, but only these
  specifics exist elsewhere → don't re-send back").

### 2.5 Trade-offs & the exam's real question

| Trade-off | Explanation |
|-----------|-------------|
| Sub-optimal routing | all packets of the aggregate take one path |
| Loss of granularity | troubleshooting hides underlying specifics |
| Loops if no Null0 | aggregate forwarded back to its origin |

- The answer to "why summarize?" → table size, stability, convergence. The answer to
  "why a Null0?" → loop prevention for the synthesized aggregate.

## 3. Configuration / Commands

```text
! EIGRP interface summary
interface Gi0/1
 ip summary-address eigrp 100 10.1.0.0 255.255.0.0

! OSPF ABR area summary (on ABR)
router ospf 1
 area 1 range 10.1.0.0 255.255.0.0

! OSPF external summary
router ospf 1
 summary-address 10.2.0.0 255.255.0.0

! BGP aggregate (with Null0 discard via route-map / next-hop)
router bgp 65000
 network 10.1.0.0 mask 255.255.0.0
 aggregate-address 10.1.0.0 255.255.0.0 summary-only

! Static aggregate + Null0 (belt and braces)
ip route 10.1.0.0 255.255.0.0 192.0.2.1
ip route 10.1.0.0 255.255.0.0 Null0 250

show ip route | include "10.1.0.0/16"
show ip protocols | include "Summarization"
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Traffic to some sub-range blackholed | aggregate without Null0 / missing specifics | `show ip route` for sub-prefix |
| OSPF not summarizing | not on ABR / wrong area | `show ip ospf ... area range` |
| EIGRP summary flap | summary interface wrong/short mask | verify summary prefix coverage |
| BGP origin confusing | aggregate without `network` statement | confirm `network` + `aggregate-address` |
| Loop through aggregate | no Null0 discard | add Null0 for the aggregate |

---

## 5. Exam Traps

- **Find the summary**: longest common prefix of the given ranges — the "block" the exam
  expects. (Align on shared bits; ensure it covers ALL listed networks.)
- **OSPF aggregates only at ABR (between areas)** — not inside an area.
- **BGP aggregate does not inject specifics** — `summary-only` suppresses more specific
  advertisement; redistributed specifics still need handling.
- **Null0 is the loop-prevention partner** of any synthesized aggregate.
- **Auto-summarization is classful and usually turned off** in modern designs.
