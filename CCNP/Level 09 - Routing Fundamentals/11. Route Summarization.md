# Route Summarization (Aggregation)

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Route summarization** represents multiple more-specific routes with **one less-specific  
aggregate prefix**.

Example:

```text
10.1.0.0/24
10.1.1.0/24
10.1.2.0/24
10.1.3.0/24
10.1.4.0/24
10.1.5.0/24
10.1.6.0/24
10.1.7.0/24
        ↓
10.1.0.0/21
```

Summarization reduces the number of prefixes advertised and maintained, which can reduce  
control-plane processing, routing-table size, update traffic, and the propagation of  
instability.

The trade-off is **loss of routing granularity**: a summary may represent address space  
for which no specific route actually exists. A discard route such as **Null0** is commonly  
used with manually originated summaries so that traffic for nonexistent destinations does  
not follow an unintended less-specific path and create a routing loop.

---

## 2. Core Concepts

### 2.1 Benefits of Summarization

|Benefit|Explanation|
|---|---|
|Smaller routing tables|Multiple specific prefixes are represented by fewer aggregate prefixes|
|Less control-plane work|Fewer routing updates and fewer prefixes to process|
|Faster convergence|Fewer prefixes may need to be recalculated or updated|
|Stability|Internal route changes can be hidden beyond the summarization boundary|
|Reduced update propagation|A specific route change does not necessarily need to propagate outside the summary|
|Scalability|Large networks can be represented with fewer routing entries|

> **Important:** Summarization does not automatically guarantee a single physical forwarding  
> path or a single next hop. Forwarding behavior depends on the routing protocol and the  
> resulting RIB/FIB.

---

## 3. Summarization by Routing Protocol

|Protocol|Summarization Method|Key Point|
|---|---|---|
|RIP v1|Classful behavior|No VLSM/CIDR advertisements|
|RIP v2|`auto-summary` or manual summary|`auto-summary` performs classful summarization when enabled|
|EIGRP|`auto-summary` or interface summary|Manual summary uses `ip summary-address eigrp`|
|OSPF|ABR `area range`|Summarizes inter-area routes at an ABR|
|OSPF External|`summary-address`|Summarizes external routes originated by an ASBR|
|BGP|`aggregate-address`|Creates an aggregate from contributing BGP routes|

### Important OSPF distinction

OSPF has **two different summarization mechanisms**:

- **ABR summarization:** `area range`
    
    - Summarizes routes between OSPF areas.
        
    - Performed by an **ABR**.
        
    - OSPF does **not** summarize routes within the same area.
        
- **External-route summarization:** `summary-address`
    
    - Summarizes external routes being introduced into OSPF.
        
    - Performed by an **ASBR**.

## 4. Summarization and Prefix Math

### 4.1 Longest Common Prefix

To find a summary route:

1. Convert the relevant network addresses to binary.
    
2. Compare the addresses from left to right.
    
3. Find the longest sequence of identical bits.
    
4. Those common bits become the summary prefix.
    
5. Set all remaining host bits to `0`.
    
6. Verify that the resulting aggregate covers **every required subnet**.
    

### Example

Summarize:

```text
10.1.0.0/24
10.1.1.0/24
10.1.2.0/24
10.1.3.0/24
```

The four `/24` networks can be represented by:

```text
10.1.0.0/22
```

Because:

```text
/22 = 4 × /24 networks
```

The block is:

```text
10.1.0.0/22
├── 10.1.0.0/24
├── 10.1.1.0/24
├── 10.1.2.0/24
└── 10.1.3.0/24
```

### 4.2 Block Alignment

A valid summary must be **properly aligned**.

For example:

```text
10.1.4.0/24
10.1.5.0/24
10.1.6.0/24
10.1.7.0/24
```

summarize to:

```text
10.1.4.0/22
```

not:

```text
10.1.5.0/22   ← invalid network boundary for /22
```

> **Exam rule:** Find the **smallest correctly aligned prefix** that covers all required  
> networks without accidentally including unwanted address space.

## 5. EIGRP Summarization

EIGRP supports manual summarization on an interface.

```cisco
interface GigabitEthernet0/1
 ip summary-address eigrp 100 10.1.0.0 255.255.0.0
```

This advertises the summary instead of the individual routes through that interface.

### EIGRP Null0 Behavior

When an EIGRP interface summary is configured, Cisco IOS installs a **summary route to  
Null0** on the summarizing router.

Conceptually:

```text
10.1.0.0/16 → Null0
```

This prevents traffic destined for an address inside the summary but not covered by an  
actual more-specific route from being forwarded indefinitely toward another router.

### Important

The Null0 route is normally **less preferred than more-specific routes**, so valid  
specific destinations continue to use their specific routes because of longest-prefix  
match.

---

## 6. OSPF Summarization

### 6.1 ABR Summarization

OSPF summarizes inter-area routes at an **ABR** using:

```cisco
router ospf 1
 area 1 range 10.1.0.0 255.255.0.0
```

Conceptually:

```text
Area 1
 ├── 10.1.0.0/24
 ├── 10.1.1.0/24
 ├── 10.1.2.0/24
 └── ...
        ↓
      ABR
        ↓
10.1.0.0/16
```

### Key Rule

> **OSPF does not summarize routes inside an area.**

Summarization occurs at the **area boundary**.

### 6.2 OSPF External Summarization

For external routes being redistributed into OSPF, an ASBR can use:

```cisco
router ospf 1
 summary-address 10.2.0.0 255.255.0.0
```

This is different from `area range`.

|Command|Purpose|Device|
|---|---|---|
|`area range`|Summarizes inter-area routes|ABR|
|`summary-address`|Summarizes external routes|ASBR|

## 7. BGP Summarization

BGP supports aggregation using:

```cisco
router bgp 65000
 aggregate-address 10.1.0.0 255.255.0.0
```

The aggregate is generated based on contributing routes in the BGP table.

### `summary-only`

```cisco
router bgp 65000
 aggregate-address 10.1.0.0 255.255.0.0 summary-only
```

`summary-only` suppresses advertisement of the more-specific contributing routes to  
BGP peers while advertising the aggregate.

Conceptually:

```text
10.1.0.0/24
10.1.1.0/24
10.1.2.0/24
        ↓
   BGP aggregation
        ↓
10.1.0.0/16
```

> **Important:** `aggregate-address` does not require a `network` statement for the exact  
> aggregate. `network` and `aggregate-address` are separate BGP mechanisms.

### BGP and Null0

BGP aggregation should **not** be described as automatically creating a Null0 route in  
the same way as an EIGRP interface summary.

A common design for a manually originated aggregate is:

```cisco
ip route 10.1.0.0 255.255.0.0 Null0
!
router bgp 65000
 network 10.1.0.0 mask 255.255.0.0
```

The static Null0 route provides a local discard path for destinations inside the aggregate  
that do not have a more-specific route.

> **Key distinction:** A Null0 route is a deliberate routing design technique for handling  
> traffic to nonexistent destinations within an aggregate; it is not a universal automatic  
> property of every BGP `aggregate-address` configuration.

---

## 8. Null0 and Loop Prevention

Suppose a router advertises:

```text
10.1.0.0/16
```

but actually owns only:

```text
10.1.1.0/24
10.1.2.0/24
```

Traffic destined for:

```text
10.1.200.0/24
```

matches the `/16` summary even though the destination does not actually exist.

A local Null0 route can safely discard that traffic:

```text
10.1.200.0/24
      ↓
10.1.0.0/16
      ↓
    Null0
      ↓
   discard
```

Meanwhile, valid more-specific routes win by longest-prefix match:

```text
10.1.1.0/24  → actual path
       ↑
more specific than
       ↓
10.1.0.0/16 → summary
```

### Why Null0 Matters

Without an appropriate discard route, traffic matching only the summary could potentially  
be forwarded toward another less-specific route, depending on the routing topology. That  
can contribute to routing loops.

> **Exam idea:** The Null0 route provides a safe termination point for traffic that matches  
> the summary but does not match any valid more-specific route.

## 10. Troubleshooting

|Symptom|Possible Cause|Check|
|---|---|---|
|Expected summary is missing|Incorrect summary configuration or no contributing routes|`show ip route`, `show ip protocols`, `show ip bgp`|
|OSPF summary missing|`area range` configured on wrong router/area|Verify the router is an ABR and check OSPF configuration|
|OSPF external summary missing|`summary-address` configured incorrectly|Verify ASBR and redistributed external routes|
|EIGRP summary not advertised|Summary configured on wrong interface or incorrect prefix|Check interface configuration and `show ip protocols`|
|BGP aggregate missing|Required contributing BGP routes are absent|`show ip bgp`|
|Specific route unexpectedly hidden from BGP peers|`summary-only` suppressing specifics|Check `aggregate-address ... summary-only`|
|Traffic to nonexistent address follows another path|No appropriate discard route/design|Check the routing table for the aggregate and Null0|
|Valid specific traffic is discarded|Summary/Null0 design is incorrect or specific route is missing|Check longest-prefix routes with `show ip route`|

## 11. Exam Traps

### Trap 1 — Summarization is not simply "combine any networks"

The networks must form a **valid, aligned CIDR block**.

```text
10.1.0.0/24
10.1.1.0/24
10.1.2.0/24
10.1.3.0/24
        ↓
10.1.0.0/22
```

---

### Trap 2 — OSPF cannot summarize inside an area

Remember:

```text
ABR
 ↓
area range
```

and:

```text
ASBR
 ↓
summary-address
```

---

### Trap 3 — `area range` and `summary-address` are different

```text
area range
    ↓
Inter-area routes
    ↓
ABR
```

```text
summary-address
    ↓
External routes
    ↓
ASBR
```

---

### Trap 4 — EIGRP creates a summary Null0 route

An EIGRP interface summary normally creates a corresponding **Null0 discard route**.

---

### Trap 5 — BGP `aggregate-address` does not mean "automatic Null0"

Do not memorize:

```text
BGP aggregate = automatic Null0
```

Instead remember:

```text
BGP aggregate
    ↓
aggregate-address
    ↓
BGP aggregation behavior

Manual aggregate design
    ↓
may use Null0
```

---

### Trap 6 — `summary-only` suppresses specifics

```cisco
aggregate-address 10.1.0.0 255.255.0.0 summary-only
```

means the aggregate is advertised while the contributing more-specific routes are  
suppressed from advertisement to the relevant BGP peers.

---

### Trap 7 — Longest Prefix Match still wins

If both exist:

```text
10.1.0.0/16 → Null0
10.1.1.0/24 → Gi0/1
```

traffic for `10.1.1.10` uses:

```text
10.1.1.0/24
```

because `/24` is more specific than `/16`.

## 12. Quick Review

|Item|Key Point|
|---|---|
|Summarization|Represents multiple specific routes with a less-specific prefix|
|Main benefit|Smaller routing tables and less control-plane/update overhead|
|Main trade-off|Loss of routing granularity|
|Prefix calculation|Find the longest common prefix and correct block alignment|
|RIP v1|Classful behavior|
|RIP v2|Supports classful `auto-summary` when enabled|
|EIGRP|`ip summary-address eigrp`|
|EIGRP Null0|Interface summaries normally install a Null0 summary route|
|OSPF internal|`area range` on an ABR|
|OSPF external|`summary-address` on an ASBR|
|OSPF within an area|No route summarization|
|BGP|`aggregate-address`|
|BGP `summary-only`|Suppresses contributing specifics from advertisement|
|BGP Null0|Not automatically implied by `aggregate-address`; may be used in manual aggregate designs|
|Null0 purpose|Safely discards traffic matching only the aggregate|
|LPM|More-specific routes beat the aggregate|
|Exam focus|Common prefix + correct alignment + protocol-specific summarization behavior|

> **CCNP takeaway:**  
> **Summarization = fewer prefixes.**  
> **Find the longest common prefix.**  
> **OSPF summarizes at boundaries, not inside an area.**  
> **EIGRP interface summaries create a Null0 summary route.**  
> **BGP uses `aggregate-address`; Null0 is a separate design consideration.**  
> **Longest-prefix match always prefers a valid more-specific route.**
