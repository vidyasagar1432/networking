# Recursive Lookup

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Recursive lookup** is the process of resolving a route's **next-hop address** when that  
next hop is not directly connected.

The router first finds the route to the **destination prefix**. If that route specifies a  
next-hop IP address, the router then looks up that next-hop address in the routing table to  
determine how to reach it.

The process can continue through multiple routing-table lookups until the next hop is  
resolved to a usable **egress interface and adjacency**.

> **Key idea:**  
> Recursive lookup resolves **where the next hop is reachable**, not the original  
> destination itself.

---

## 2. Core Concepts

### 2.1 The Problem It Solves

Consider:

```text
Destination:
192.168.100.0/24
        │
        ▼
Next hop:
10.0.0.1
        │
        ▼
10.0.0.0/24 is directly connected
GigabitEthernet0/1
```

The router knows:

```text
192.168.100.0/24 → via 10.0.0.1
10.0.0.0/24      → directly connected Gi0/1
```

Therefore:

```text
192.168.100.0/24
        ↓
next hop 10.0.0.1
        ↓
10.0.0.0/24
        ↓
Gi0/1
```

The router can forward traffic toward `10.0.0.1` even though `10.0.0.1` is not the  
destination.

---

## 2.2 How Recursive Lookup Works

Conceptually:

### Step 1 — Look up the destination

The router receives a packet for:

```text
192.168.100.10
```

It performs a routing lookup and finds:

```text
192.168.100.0/24
    via 10.0.0.1
```

### Step 2 — Resolve the next hop

The next hop is:

```text
10.0.0.1
```

The router performs another routing lookup for `10.0.0.1`.

It finds:

```text
10.0.0.0/24 is directly connected
GigabitEthernet0/1
```

### Step 3 — Resolve forwarding information

The router now knows:

```text
Destination → 192.168.100.10
Next hop    → 10.0.0.1
Interface   → Gi0/1
```

CEF/FIB can use the resolved forwarding information for packet forwarding.

---

## 2.3 Multiple Levels of Recursion

The next-hop route does not necessarily have to be directly connected.

Example:

```text
192.168.100.0/24
        │
        ▼
via 10.0.0.1
        │
        ▼
10.0.0.0/24
via 172.16.0.1
        │
        ▼
172.16.0.0/24
directly connected Gi0/1
```

Conceptually:

```text
Destination
    ↓
Next hop 10.0.0.1
    ↓
Next hop 172.16.0.1
    ↓
Directly connected network
    ↓
Egress interface
```

This is **recursive next-hop resolution**.

> In practical routing systems, the forwarding architecture resolves this information  
> into usable forwarding state rather than performing an entire recursive chain for  
> every packet.

---

## 2.4 When Recursive Lookup Is Used

|Situation|Why Recursion May Be Required|
|---|---|
|iBGP route|BGP next hop is often several hops away|
|eBGP with loopbacks|Next hop may not be directly connected|
|eBGP multihop|Peer can be multiple hops away|
|Next-hop static route|Next-hop IP must be resolved|
|Dynamic routing route|Protocol may provide a next-hop address that is not directly connected|
|Route through another router|Next hop must be resolved through the RIB|

### Important BGP distinction

Normal eBGP peers are commonly directly connected, so eBGP does **not inherently require  
recursive lookup**.

However, recursion can be required when using:

- Loopback-based peering
    
- `ebgp-multihop`
    
- Non-directly-connected next hops
    
- Certain provider/customer or transit designs
    

**iBGP commonly requires recursive next-hop resolution** because the BGP next hop can  
be reachable through the IGP.

---

## 2.5 Static Routes and Next-Hop Resolution

### Next-hop-only static route

```text
ip route 192.168.100.0 255.255.255.0 10.0.0.1
```

The router must determine how to reach:

```text
10.0.0.1
```

Therefore, the next hop must itself be resolvable through the routing table.

Example:

```text
192.168.100.0/24 → 10.0.0.1
10.0.0.0/24      → Gi0/1
```

The first route depends on the second route for next-hop resolution.

---

## 2.6 Static Route Types

### A. Next-hop-only static route

```text
ip route 192.168.100.0 255.255.255.0 10.0.0.1
```

The router knows the next-hop IP but must resolve how to reach it.

```text
Destination → Next hop → Egress
```

---

### B. Exit-interface static route

```text
ip route 192.168.100.0 255.255.255.0 GigabitEthernet0/1
```

The route specifies only the outgoing interface.

There is no separate next-hop IP to recursively resolve.

However, behavior differs depending on the interface type.

On a point-to-point interface, this is generally straightforward.

On a multiaccess Ethernet interface, an interface-only static route can cause the router  
to treat the destination as directly reachable on that segment and potentially ARP for  
the destination itself.

> **Design rule:** On Ethernet/multiaccess networks, specifying a next-hop address is  
> generally preferable to an interface-only static route.

---

### C. Fully specified static route

```text
ip route 192.168.100.0 255.255.255.0 GigabitEthernet0/1 10.0.0.1
```

This specifies both:

```text
Outgoing interface = GigabitEthernet0/1
Next hop            = 10.0.0.1
```

This removes ambiguity and provides both pieces of forwarding information explicitly.

> **Exam idea:** A fully specified static route supplies both the exit interface and  
> next-hop address.

---

## 2.7 Recursive vs Fully Specified

|Static Route Type|Example|Next-Hop Resolution|
|---|---|---|
|Next-hop only|`ip route ... 10.0.0.1`|Yes|
|Exit interface only|`ip route ... Gi0/1`|No separate next-hop recursion|
|Fully specified|`ip route ... Gi0/1 10.0.0.1`|Both interface and next hop explicitly specified|

---

## 2.8 Recursive Lookup and the RIB/FIB/CEF

Recursive next-hop resolution is primarily a **control-plane process** used to build  
usable forwarding information.

Conceptually:

```text
Routing Information
        │
        ▼
       RIB
        │
        │ resolve next hop
        ▼
Resolved forwarding information
        │
        ▼
       FIB
        │
        ▼
      CEF / ASIC
        │
        ▼
Packet forwarding
```

The data plane does not normally repeat the entire recursive chain for every packet.

Instead, the forwarding architecture uses the **resolved FIB/CEF information**.

> **Remember:**  
> Recursive lookup happens as part of route/forwarding resolution; CEF provides the  
> efficient data-plane forwarding result.

---

## 2.9 Recursive Lookup vs Longest Prefix Match

These are different concepts.

### Longest Prefix Match

Answers:

> **Which route best matches the packet's destination?**

Example:

```text
10.0.0.0/8
10.1.0.0/16
10.1.1.0/24
```

Destination:

```text
10.1.1.50
```

The `/24` route wins because it is the most specific match.

---

### Recursive Lookup

Answers:

> **How do I reach the next-hop address of the selected route?**

Example:

```text
10.1.1.0/24 → via 192.0.2.1
```

The router must resolve:

```text
192.0.2.1
```

before it can use that next hop.

> **Exam distinction:**  
> **Longest-prefix match selects the destination route.**  
> **Recursive lookup resolves the selected route's next hop.**

---

## 2.10 What Happens When the Next Hop Cannot Be Resolved?

Suppose:

```text
192.168.100.0/24 → via 10.0.0.1
```

but there is no usable route to:

```text
10.0.0.1
```

The route cannot be properly resolved for forwarding.

The route may therefore not be installed in the usable forwarding table, depending on  
the platform and route type.

Traffic may then:

- Follow another available route
    
- Match a default route
    
- Or be dropped if no usable route exists
    

> **Important:** A configured route and an installed/usable route are not always the same  
> thing.

---

## 2.11 Circular or Recursive Routing Problems

A routing configuration can create an invalid or circular resolution.

Conceptually:

```text
Route A
  ↓
next hop B

Route B
  ↓
next hop A
```

or:

```text
Destination → next hop
                 ↓
              another route
                 ↓
              same lookup
```

This prevents a valid forwarding resolution.

When troubleshooting recursive problems, verify the entire next-hop resolution chain.

## 3. Configuration / Verification Commands

### View a route

```text
show ip route 192.168.100.0
```

Check the selected route and next hop.

---

### Check the next-hop route

```text
show ip route 10.0.0.1
```

This answers:

> How does the router reach the next-hop address?

---

### Check CEF

```text
show ip cef 192.168.100.0
```

View the forwarding entry for the destination.

---

### Check CEF detail

```text
show ip cef 192.168.100.0 detail
```

Useful when investigating recursive resolution and forwarding details.

---

### Check interface state

```text
show ip interface brief
```

Verify that the expected interface is operational.

---

### Verify static routes

```text
show running-config | include ^ip route
```

Useful for checking configured static routes.

## 4. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Static route configured but not usable|Next hop cannot be resolved|`show ip route <next-hop>`|
|BGP route missing|BGP next hop is unreachable|Check BGP route and IGP reachability|
|BGP route exists but forwarding fails|Next-hop resolution/CEF problem|`show ip cef <prefix>`|
|Interface-only static behaves unexpectedly|Multiaccess interface and destination treated as directly reachable|Prefer next-hop or fully specified route|
|Recursive chain fails|Intermediate route missing|Check every next hop|
|Route points back toward itself|Circular recursion|Trace the resolution chain|
|Expected route not in RIB|Unresolved next hop, AD, tracking, interface, or protocol issue|Check `show ip route`, protocol state, and next hop|

## 5. Exam Traps

### Trap 1 — Recursion Resolves the Next Hop

Wrong:

> "Recursive lookup finds the best destination route."

Correct:

> The initial routing lookup selects the destination route; recursive lookup resolves  
> that route's next-hop address when necessary.

---

### Trap 2 — iBGP Commonly Uses Recursive Resolution

An iBGP route can look like:

```text
B    10.10.10.0/24 [200/0] via 192.0.2.1
```

If `192.0.2.1` is reachable through the IGP:

```text
192.0.2.1
    ↓
OSPF/IS-IS/EIGRP route
    ↓
Egress interface
```

The IGP provides reachability to the BGP next hop.

---

### Trap 3 — eBGP Does Not Always Require Recursion

Normal eBGP peers are commonly directly connected.

Recursion may still be required with:

```text
Loopback peering
ebgp-multihop
Non-direct next hops
```

---

### Trap 4 — Next-Hop-Only Static Routes Need Resolution

```text
ip route 10.1.1.0 255.255.255.0 192.0.2.1
```

The router must know how to reach:

```text
192.0.2.1
```

---

### Trap 5 — Fully Specified Static Routes

```text
ip route 10.1.1.0 255.255.255.0 Gi0/1 192.0.2.1
```

This explicitly specifies:

```text
Interface + Next hop
```

It avoids ambiguity and provides the required forwarding information directly.

---

### Trap 6 — Interface-Only Static Routes

```text
ip route 10.1.1.0 255.255.255.0 Gi0/1
```

This does not perform separate next-hop recursion.

On Ethernet, however, the router may need to ARP for the destination itself, so an  
interface-only static route is generally less desirable than specifying a next hop.

---

### Trap 7 — Recursion Is Not Per-Packet Table Walking

The router does not normally perform:

```text
destination lookup
→ next-hop lookup
→ next-hop lookup
```

for every packet.

The control plane resolves the forwarding information, and the FIB/CEF is used by  
the data plane.

---

### Trap 8 — Recursive Lookup vs Longest Prefix Match

```text
Longest Prefix Match
→ selects the destination route

Recursive Lookup
→ resolves that route's next hop
```

Do not confuse these two operations.

## 7. One-Minute Mental Model

```text
                 Packet
                   │
                   ▼
          Destination Lookup
                   │
                   ▼
          Best Route Selected
                   │
                   ▼
          Is next hop directly
             reachable?
              /       \
            Yes        No
             │          │
             │          ▼
             │     Lookup next hop
             │          │
             │          ▼
             │     Another route
             │          │
             │          ▼
             │     Repeat if needed
             │          │
             └──────┬───┘
                    ▼
             Egress Interface
                    │
                    ▼
             FIB / CEF Entry
                    │
                    ▼
              Packet Forwarding
```

> **Remember:**  
> **LPM selects the destination route.**  
> **Recursive lookup resolves its next hop.**  
> **FIB/CEF uses the resolved forwarding information to forward packets.**
