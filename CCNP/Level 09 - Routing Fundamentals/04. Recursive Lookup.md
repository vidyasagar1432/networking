# Recursive Lookup

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Recursive lookup** is how a router resolves a route whose **next hop is itself not
directly connected**. The router looks up the next-hop address in the RIB to find an
*intermediate* route — often a connected subnet or another route — until it reaches a
directly connected egress. This is why routes with a next hop but no directly attached
interface still work: the router "walks" the table.

---

## 2. Core Concepts

### 2.1 The problem it solves

```
192.0.2.1/32 → next hop 10.0.0.1        (BGP route, next hop far away)
10.0.0.0/24 →  directly connected Gi0/1 (recursive resolution)

Result: send to 192.0.2.1 via Gi0/1 toward 10.0.0.1
```

- With recursive lookup the destination is reachable even though the BGP next hop is
  multiple hops away — the router chains lookups.

### 2.2 How it works step by step

1. Look up the **destination prefix** in the RIB → first route found.
2. Its next hop may be non-connected → look up that next-hop address.
3. Repeat until the resolution ends in a **directly connected interface**.
4. If it ends in a default route fine too — that provides the egress.

### 2.3 When recursion is needed

| Case | Why recursion |
|------|---------------|
| BGP route | eBGP next hop often multi-hop / iBGP always needs recursion |
| Static route given only as next hop | e.g., `ip route 10.1.1.0 255.255.255.0 192.0.2.1` |
| Summary route learned via dynamic protocol | next hop is an upstream router, not local link |

### 2.4 Static routes: next-hop vs interface

| Config | Behavior |
|--------|----------|
| `ip route PREFIX MASK <next-hop>` | requires the routable **next hop** in RIB → may need recursion |
| `ip route PREFIX MASK <interface>` | **linked route**, no recursion — next hop is "out the interface" |
| `ip route PREFIX MASK <int> <next-hop>` | fully specified, least ambiguity |

- A route pointing *only* at interface is installed even if the interface is up but the
  remote end is unreachable — **a trap** (unreachable "attached" path). Preferred: use a
  next-hop so RIB validation applies.

### 2.5 Where recursion resolves (RIB vs CEF)

- **Recursive resolution happens in the RIB** during FIB construction (control plane).
- The **FIB/CEF** stores the already-resolved adjacency, so the data plane sends the
  packet with no repeated lookup (note 05/07).

### 2.6 Failure behavior — black hole vs drop

If the recursive next hop is **unreachable** (no route), the original route is not
installed in the RIB — traffic to it is dropped (or matches a default). Watch for:

```
show ip cef <prefix>          ! if unresolved, displays "no route"
show ip route <next-hop>      ! confirms whether intermediate route exists
```

## 3. Configuration / Commands

```text
! Static that requires recursion (next hop not directly connected)
ip route 10.1.1.0 255.255.255.0 192.0.2.1

! Avoid recursion / pin to an interface
ip route 10.1.1.0 255.255.255.0 GigabitEthernet0/1 192.0.2.1

show ip cef 10.1.1.0              ! resolved or "no route"
show ip route 192.0.2.1           ! what the next hop resolves to
show ip cef detail | include recv | recursive
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Route installed but traffic dropped | recursive next hop unreachable → route absent from FIB | `show ip cef prefix`, `show ip route nh` |
| Static looks fine but not working | next hop only reachable via itself (circular) | diagnosis of recursive chain |
| BGP route missing | iBGP next hop not reachable | `show bgp ...`, igp route to next hop |
| Interface-only route forwards into void | link route no next-hop validation | use next-hop syntax |

---

## 5. Exam Traps

- **Recursion resolves next hops**, not destinations.
- **A next-hop-only static still needs a connected route** to the next hop (or recursion).
- **Fully specified route (interface + next hop) avoids recursion** — safest for statics.
- **Recursive resolution is control-plane (RIB/FIB)** — data plane already has adjacency.
- **Interface-only static** passes because interface is up — packets can still be black-holed.
- Route absent from RIB but present as config → usually unresolved next hop.
