# Floating Static

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **floating static route** is a static route given an **AD deliberately higher** than a
dynamic protocol's, so it stands **idle as a backup** and activates only if the primary
dynamic route disappears. It "floats" in and out of the RIB as the primary fails/recovers —
manual failover made automatic, with operator-controlled trust.

---

## 2. Core Concepts

### 2.1 The trick: gear the AD

```
Static default AD = 1   (too eager — would beat everything)
Floating example AD     = 150   (> OSPF 110)  → backup to OSPF
                         or 200 (> EIGRP 90)   → backup to EIGRP
```

- The floating AD must be **higher than the primary protocol's AD** (but still < 255).
- **Only one route for the prefix in the RIB** at a time — the AD ensures no competition.

### 2.2 Choice of AD target

| Primary protocol | Primary AD | Choose floating AD |
|------------------|------------|-------------------|
| OSPF | 110 | e.g., **130–200** |
| EIGRP (internal) | 90 | e.g., **110–200** |
| RIP | 120 | e.g., **130–200** |
| (Any static still 1) | 1 | — |

- Keep floating below 255 so it *can* be installed; keep it above the primary so it waits.

### 2.3 How failover behaves

| Event | Routing table |
|-------|---------------|
| Primary route present | only primary installed; floating absent |
| Primary lost (converged) | floating static is installed → traffic uses backup |
| Primary returns | floating static removed again |

- The backup path is usually a second ISP link, a DDR dial, or an alternate WAN.

### 2.4 Enhancing with tracking (IP SLA)

```text
track 1 ip sla 100 reachability
ip route 0.0.0.0 0.0.0.0 192.0.2.1 track 1
ip route 0.0.0.0 0.0.0.0 198.51.100.1 200
```

- Without tracking, the floating route only appears when the primary *prefix disappears*.
- With `track`, the primary is pulled even if it's still in the RIB but the next hop is
  blackholing (reachability probe fails) — much faster, true failover.

### 2.5 Floating statics vs full redundancy approaches

| Approach | Overhead | Failover speed |
|----------|----------|----------------|
| Floating static only | none (static) | protocol-convergence-gated |
| + IP SLA tracking | small (probe) | fast — detects next-hop loss |
| Dynamic protocol (BGP/OSPF) | protocol state | protocol-recalculated |

- Exam-design answers often want **floating static + IP SLA** for a WAN backup path.

## 3. Configuration / Commands

```text
! Primary dynamic protocol (OSPF) already running
! Backup static with higher AD than the dynamic route
ip route 10.1.1.0 255.255.255.0 198.51.100.1 150

! Optional tracking for faster failover
ip sla 100
 icmp-echo 203.0.113.1 source-interface Gi0/1
 frequency 10
ip sla schedule 100 life forever start-time now
track 1 ip sla 100 reachability
ip route 10.1.1.0 255.255.255.0 198.51.100.1 150 track 1

show ip route 10.1.1.0
show track 1
show ip route static
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Floating static never installs | its AD still lower than primary | confirm AD > primary protocol |
| Floating activates when it shouldn't | primary lost / filtered | `show ip route prefix` source |
| No failover on link down | no tracking; prefix still in RIB via other means | add IP SLA track |
| Backup flap | AD too close to primary | give clear margin (e.g., +40) |

---

## 5. Exam Traps

- **Floating static only works if AD > primary's AD** — the constant gotcha.
- **AD suffix on a static = floating; suffix < primary = it would take over immediately.**
- **No automatic failover from a *prefix-less* disappearance** without `track`.
- **The floating static is still a static** — it won't advertise itself (redistribution needed).
- AD values are per-source, so a `150` static is still "trusted" once installed — operators
  must size it > primary deliberately.
