# Floating Static Routes

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **floating static route** is a static route configured with an **administrative distance (AD)  
higher than the preferred route** so that it normally remains out of the RIB and acts as a  
**backup path**.

When the preferred route is no longer installed or selected, the floating static can become  
the best available route and enter the RIB.

It provides **simple, predictable backup routing** without requiring a dynamic routing  
protocol on the backup path.

> **Core idea:**  
> **Normal static AD = 1 → Floating static = higher AD → backup route**

---

## 2. Core Concepts

### 2.1 The AD Trick

A normal static route has:

```text
Static route AD = 1
```

To make it a backup, configure a higher AD:

```cisco
ip route 10.1.1.0 255.255.255.0 198.51.100.1 150
```

The final `150` is the route's administrative distance.

If another route to the same destination has a lower AD, that route is preferred.

Example:

```text
OSPF route      AD 110
Floating static AD 150
```

Result:

```text
OSPF route → preferred
Static AD 150 → backup
```

When the OSPF route is no longer installed, the static route can become active.

---

## 2.2 Choosing the Floating AD

The floating static's AD must be **higher than the route source you want it to back up**.

|Primary Route|Default AD|Example Floating AD|
|---|--:|--:|
|Connected|0|1+|
|Static|1|2+|
|EIGRP Internal|90|100+|
|OSPF|110|120+|
|RIP|120|130+|

Common practical values include:

```text
OSPF  → floating static AD 150
EIGRP → floating static AD 150
RIP   → floating static AD 200
```

There is no special requirement to use a particular value such as 150 or 200. The important  
rule is:

> **Floating AD > AD of the preferred route**

### AD 255

Do not configure a floating static with AD 255 expecting it to become active.

```text
AD 255 = route considered unreachable
```

Therefore, use an AD **greater than the primary route but less than 255**.

---

## 2.3 How Route Selection Works

A floating static does not automatically "turn on" simply because a link goes down.

The router evaluates available routes using normal route-selection rules.

A simplified model is:

```text
Destination
    ↓
Longest-prefix match
    ↓
Compare competing routes for that prefix
    ↓
Administrative distance
    ↓
Best route installed in RIB
    ↓
CEF forwarding
```

Example:

```text
OSPF route:
10.1.1.0/24 → AD 110

Floating static:
10.1.1.0/24 → AD 150
```

While the OSPF route is installed:

```text
OSPF AD 110     → selected
Static AD 150   → not selected
```

If the OSPF route disappears:

```text
OSPF AD 110     → unavailable
Static AD 150   → selected
```

---

## 2.4 Floating Static Does Not Need to Be a Specific Route

A floating static can protect either a specific destination or a default route.

### Specific destination

```cisco
ip route 10.1.1.0 255.255.255.0 198.51.100.1 150
```

### Floating default route

```cisco
ip route 0.0.0.0 0.0.0.0 198.51.100.1 200
```

A floating default route is common when a router has a primary and backup WAN/Internet  
connection.

---

## 2.5 Basic Failover Behavior

|Event|Result|
|---|---|
|Primary route installed|Floating static remains unselected|
|Primary route removed|Floating static can become active|
|Primary route returns|Primary becomes preferred again|
|Primary route flaps|Traffic can move between primary and backup|

Example:

```text
Primary:
OSPF → 10.1.1.0/24 → AD 110

Backup:
Static → 10.1.1.0/24 → AD 150
```

Normal state:

```text
RIB
└── OSPF route AD 110
```

After OSPF loses the route:

```text
RIB
└── Floating static AD 150
```

When OSPF reconverges and reinstalls the route:

```text
RIB
└── OSPF route AD 110
```

## 2.6 Floating Static + IP SLA Tracking

A floating static can be combined with **object tracking** and **IP SLA** when simply  
watching the routing table is not sufficient.

Example:

```cisco
ip sla 100
 icmp-echo 203.0.113.1 source-interface GigabitEthernet0/1
 frequency 10
ip sla schedule 100 life forever start-time now

track 1 ip sla 100 reachability

ip route 10.1.1.0 255.255.255.0 192.0.2.1 track 1
ip route 10.1.1.0 255.255.255.0 198.51.100.1 200
```

Conceptually:

```text
                 ┌── IP SLA probe ──→ Destination
                 │
                 ↓
             Track Object
                 │
        ┌────────┴────────┐
        │                 │
      UP                  DOWN
        │                 │
 Primary static       Primary static
 remains installed    withdrawn
                          │
                          ↓
                   Floating static
                     becomes active
```

### Why tracking matters

Without tracking, a primary static route can remain in the RIB even when the path beyond  
its next hop is unusable.

For example:

```text
Router
  ↓
Primary next hop
  ↓
Broken upstream path
  ↓
Remote network unreachable
```

The router may still consider the primary static route valid because its configured  
forwarding information remains available.

With IP SLA + tracking:

```text
Probe fails
    ↓
Track object DOWN
    ↓
Tracked primary static removed
    ↓
Floating static becomes preferred
```

> **Important:** IP SLA tracking provides a reachability test; it does not make static  
> routing a dynamic routing protocol.

Failover timing depends on the IP SLA probe interval, timeout, tracking configuration, and  
route-processing/convergence behavior.

## 2.7 Floating Static vs Tracked Static

These are related but not identical concepts.

### Floating static

The backup route has a higher AD:

```cisco
ip route 10.1.1.0 255.255.255.0 198.51.100.1 150
```

Its role is determined by route preference.

### Tracked static

A static route is tied to a tracking object:

```cisco
ip route 10.1.1.0 255.255.255.0 192.0.2.1 track 1
```

The tracking state determines whether the route remains eligible for installation.

### Combined design

```text
Primary static + tracking
          ↓
     Track fails
          ↓
Primary removed
          ↓
Floating static
          ↓
Backup path
```

This is a common design for WAN failover.

### 3.3 Primary Static + Floating Static

```cisco
! Primary static
ip route 10.1.1.0 255.255.255.0 192.0.2.1

! Backup static
ip route 10.1.1.0 255.255.255.0 198.51.100.1 200
```

Result:

```text
Primary static → AD 1
Backup static  → AD 200
```

The AD 200 route is used only when the AD 1 route is no longer selected/installed.

---

### 3.4 Primary Default + Floating Default

```cisco

ip route 0.0.0.0 0.0.0.0 192.0.2.1

! Backup default route
ip route 0.0.0.0 0.0.0.0 198.51.100.1 200
```

This is a common dual-WAN design.

## 5. Troubleshooting

|Symptom|Possible Cause|Check|
|---|---|---|
|Floating route never becomes active|Primary route is still preferred|`show ip route <prefix>`|
|Backup route activates immediately|AD is lower than or equal to the intended primary preference|Verify AD values|
|Backup route does not work|Backup next hop/interface is unreachable|`show ip route`, `show ip cef`|
|Primary remains active despite remote failure|No tracking/reachability mechanism|Use IP SLA + tracking|
|Tracking route disappears|Track object is DOWN|`show track`|
|IP SLA reports failure|Probe target/source/path problem|`show ip sla statistics`|
|Route flaps between primary and backup|Primary or tracking condition is unstable|Check SLA/tracking and interface stability|
|AD 255 route never activates|AD 255 makes the route unusable|Use AD < 255|

## 6. Exam Traps

### Trap 1 — Higher AD Makes It Float

```text
Primary OSPF       AD 110
Floating static    AD 150
```

The static remains less preferred while OSPF is available.

---

### Trap 2 — AD Must Be Higher Than the Intended Primary

For OSPF:

```text
OSPF = 110
Floating static > 110
```

For EIGRP internal:

```text
EIGRP = 90
Floating static > 90
```

For RIP:

```text
RIP = 120
Floating static > 120
```

---

### Trap 3 — AD 255 Is Not a Normal Backup Value

```text
AD 254 → potentially installable
AD 255 → considered unreachable
```

Therefore:

> **Use an AD greater than the primary but less than 255.**

---

### Trap 4 — Floating Does Not Mean "Link Down = Backup"

A physical interface going down is one way the primary route may disappear, but floating  
static routing is based on **route availability and preference**, not simply on detecting  
a cable/link failure.

For failures beyond the directly connected next hop, use **tracking/IP SLA** when  
appropriate.

---

### Trap 5 — IP SLA Does Not Automatically Mean Floating Static

IP SLA measures reachability.

Object tracking connects that result to a route or other tracked action.

A common chain is:

```text
IP SLA
  ↓
Track Object
  ↓
Tracked Static Route
  ↓
Route withdrawn when tracking fails
  ↓
Floating Static becomes preferred
```

---

### Trap 6 — Floating Static Is Still Static

A floating static:

- Does not automatically discover neighbors
    
- Does not exchange topology information
    
- Does not automatically advertise itself
    
- Requires manual configuration
    

If it needs to be advertised through a routing protocol, redistribution or another  
appropriate mechanism must be configured.

---

### Trap 7 — AD Is Not Checked Before Longest Prefix

Suppose:

```text
Static 10.0.0.0/8      AD 1
OSPF   10.10.10.0/24   AD 110
```

Traffic to:

```text
10.10.10.5
```

uses the `/24` because it is **more specific**.

Do not memorize:

> "Lower AD always wins."

Instead remember:

```text
Longest prefix first
        ↓
Route preference / AD
        ↓
Best route
```

---

### Trap 8 — No Arbitrary AD Margin Is Required

There is no rule saying:

```text
"AD must be primary + 40"
```

Any appropriate value can work as long as the floating route has a **higher AD than the  
route it is intended to back up** and remains below 255.

---

## 7. Floating Static Decision Model

```text
             Destination
                  ↓
        Longest-prefix match
                  ↓
       Multiple routes available?
                  ↓
       Compare route preference
                  ↓
        ┌─────────┴─────────┐
        ↓                   ↓
 Primary available     Primary unavailable
        ↓                   ↓
 Primary selected       Floating static
                            ↓
                       Backup selected
```

With tracking:

```text
IP SLA
  ↓
Reachability test
  ↓
Track Object
  ↓
Primary static eligible?
  │
  ├── YES → Primary remains installed
  │
  └── NO  → Primary withdrawn
               ↓
         Floating static
               ↓
          Backup path
```

### CCNP Takeaway

> **A floating static route is simply a static route configured with a higher AD so that  another route is preferred under normal conditions. 
> When the preferred route is no longer available, the floating static can become active. 
> For failures that do not remove the primary route from the RIB, combine static routing with IP SLA and object tracking to make the primary route conditional on actual reachability.**
