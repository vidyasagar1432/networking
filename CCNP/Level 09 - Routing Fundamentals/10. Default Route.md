# Default Route

> **Level 09 · Routing Fundamentals** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **default route** is the least-specific route used when no more-specific route matches  
the destination.

For IPv4:

```text
0.0.0.0/0
```

For IPv6:

```text
::/0
```

A default route is commonly used to send unknown destinations toward an upstream router,  
such as an ISP.

> **Core idea:**  
> **More-specific route → preferred by longest-prefix match**  
> **No more-specific match → default route**

A default route can be **static or dynamically learned/advertised**.

---

## 2. Core Concepts

### 2.1 Longest-Prefix Match

The default route is the **least-specific route** possible.

Example:

```text
10.10.10.0/24
10.10.0.0/16
10.0.0.0/8
0.0.0.0/0
```

For a packet destined to `10.10.10.5`:

```text
10.10.10.0/24  → longest match → selected
10.10.0.0/16   → less specific
10.0.0.0/8     → less specific
0.0.0.0/0      → least specific
```

If no more-specific route exists:

```text
Packet
  ↓
No specific route
  ↓
0.0.0.0/0
  ↓
Default next hop
```

If there is **no matching route and no default route**, the router normally drops the  
packet.

> **Exam rule:** The default route does not "beat" other routes because of AD. It is  
> normally selected because it is the **least-specific matching prefix**.

---

## 2.2 Static Default Route

A common Cisco IOS IPv4 static default route is:

```cisco
ip route 0.0.0.0 0.0.0.0 192.0.2.1
```

This means:

```text
Destination: 0.0.0.0/0
Next hop:    192.0.2.1
```

Any destination without a more-specific matching route can be forwarded toward  
`192.0.2.1`.

### Exit-interface form

```cisco
ip route 0.0.0.0 0.0.0.0 GigabitEthernet0/1
```

### Fully specified form

```cisco
ip route 0.0.0.0 0.0.0.0 GigabitEthernet0/1 192.0.2.1
```

---

## 2.3 IPv6 Default Route

The IPv6 equivalent is:

```text
::/0
```

Example:

```cisco
ipv6 route ::/0 2001:db8:1::1
```

The same fundamental concept applies:

> **Use the default route when no more-specific IPv6 route matches.**

---

## 2.4 Static Default Route AD

A normal static route has a default administrative distance of:

```text
AD = 1
```

Therefore, a static default route normally has:

```text
0.0.0.0/0 → AD 1
```

If a dynamic routing protocol also provides a default route, route preference is considered  
when competing routes have the same prefix.

Example:

```text
Static default   AD 1
OSPF default     AD 110
```

The static default is normally preferred.

> **Important:** AD is considered after determining the matching prefix.  
> Do not confuse **longest-prefix match** with **administrative distance**.

---

## 2.5 Floating Default Route

A default route can also be configured as a **floating static route** for backup connectivity.

```cisco
! Primary default
ip route 0.0.0.0 0.0.0.0 192.0.2.1

! Backup default
ip route 0.0.0.0 0.0.0.0 198.51.100.1 200
```

Result:

```text
Primary default → AD 1   → preferred
Backup default  → AD 200 → standby
```

The backup becomes eligible when the preferred default is no longer installed/selected.

Common use:

```text
Primary ISP
    ↓
Primary default

Backup ISP
    ↓
Floating default
```

---

## 2.6 Default Route and Gateway of Last Resort

When a default route is installed in the IPv4 routing table, Cisco IOS can identify the  
corresponding path as the **gateway of last resort**.

Example:

```cisco
ip route 0.0.0.0 0.0.0.0 192.0.2.1
```

Then:

```text
Unknown destination
       ↓
No more-specific route
       ↓
Gateway of last resort
       ↓
192.0.2.1
```

Check with:

```cisco
show ip route
```

You may see:

```text
Gateway of last resort is 192.0.2.1 to network 0.0.0.0
```

> **Important distinction:**  
> **Default route** = routing-table entry for unknown destinations.  
> **Gateway of last resort** = the router's fallback forwarding path associated with the  
> default route.

---

## 2.7 Default Route vs Default Gateway

These terms are related but apply at different levels.

|Concept|Device|Meaning|
|---|---|---|
|**Default route**|Router|Route used when no more-specific route exists|
|**Default gateway**|Host|Local router address used to reach remote networks|
|**Gateway of last resort**|Router|Fallback path associated with a default route|

Example:

```text
PC
10.10.10.10/24
Default gateway: 10.10.10.1
        ↓
Router
        ↓
Default route: 0.0.0.0/0
        ↓
ISP
```

The PC uses its **default gateway**.

The router uses its **default route**.

---

## 2.8 OSPF Default Route Origination

OSPF can advertise a default route into an OSPF domain using:

```cisco
router ospf 1
 default-information originate
```

Normally, the router must already have a default route in its routing table.

For example:

```text
Router
  ↓
Has 0.0.0.0/0
  ↓
default-information originate
  ↓
OSPF advertises default
  ↓
Other OSPF routers learn a default
```

### Force OSPF to originate a default

The `always` keyword allows the router to originate the default even if it does not  
currently have a default route in its routing table:

```cisco
router ospf 1
 default-information originate always
```

> **Exam trap:** `default-information originate` does not create the router's local  
> default route. It controls **OSPF default-route advertisement**.

---

## 2.9 Dynamic Default Routes

A default route does not have to be statically configured.

It can be learned or advertised through routing protocols such as:

- OSPF
    
- EIGRP
    
- BGP
    
- IS-IS
    

The exact method depends on the protocol and network design.

Conceptually:

```text
Upstream router
      ↓
Advertises default
      ↓
Downstream router
      ↓
Installs 0.0.0.0/0
```

For example, OSPF can originate a default with:

```cisco
router ospf 1
 default-information originate
```

BGP and other protocols have their own mechanisms for carrying or originating default  
routes.

> **Exam tip:** Do not memorize "default route = static."  
> **Default route describes the prefix/function, not how the route was learned.**

---

## 2.10 `ip default-network`

Cisco IOS also supports the legacy:

```cisco
ip default-network
```

This is an older mechanism for identifying a candidate default network.

For modern CCNP designs, prefer understanding and using explicit default routes and  
protocol-specific default-route mechanisms.

> **Exam note:** Know that `ip default-network` exists, but do not confuse it with the  
> standard `ip route 0.0.0.0 0.0.0.0 ...` static default route.

---

## 2.11 Default Route and CEF

Once installed in the routing table, a default route can also be represented in the  
forwarding information used by CEF.

Conceptually:

```text
Packet destination
       ↓
CEF lookup
       ↓
More-specific entry?
   ┌───┴───┐
  Yes      No
   ↓        ↓
Forward   0.0.0.0/0
             ↓
       Default adjacency
             ↓
        Next hop/interface
```

A useful verification command is:

```cisco
show ip cef <destination>
```

For example:

```cisco
show ip cef 8.8.8.8
```

This is often more useful than checking only the `0.0.0.0/0` CEF entry because it shows  
the actual forwarding decision for a destination.

## 5. Troubleshooting

|Symptom|Possible Cause|Check|
|---|---|---|
|Internet unreachable|No default route|`show ip route`|
|Default route missing|Bad configuration or unresolved next hop|`show ip route 0.0.0.0`|
|Default exists but traffic fails|Next hop/adjacency/path problem|`show ip route`, `show ip cef <destination>`|
|More-specific route unexpectedly used|LPM selected a longer prefix|`show ip route <destination>`|
|OSPF neighbors don't learn default|Default not being originated|Check `default-information originate`|
|OSPF default not originated|Router has no local default|Check `show ip route 0.0.0.0`|
|OSPF default required regardless of local default|Missing `always`|`default-information originate always`|
|Hosts cannot reach remote networks|Incorrect/missing host default gateway|Check host IP configuration|
|Backup default never activates|Primary default still preferred|Check route AD and RIB|
|Traffic intentionally discarded|Default points to Null0|Verify route configuration|

## 6. Design Use Cases

|Use Case|Purpose|
|---|---|
|**Stub router**|Send all unknown traffic to one upstream router|
|**Internet edge**|Forward Internet-bound traffic toward ISP|
|**Branch network**|Avoid maintaining full external routing information|
|**Dual ISP**|Primary + floating backup default|
|**OSPF domain**|Advertise one exit path to other routers|
|**Small networks**|Simple routing with minimal configuration|
|**Controlled egress**|Centralize outbound traffic through a known router|

## 7. Exam Traps

### Trap 1 — Default Route Is Not "Always Used"

A default route is used only when there is no **more-specific matching route**.

```text
10.0.0.0/8
10.10.0.0/16
10.10.10.0/24
0.0.0.0/0
```

For `10.10.10.5`:

```text
10.10.10.0/24 wins
```

The default route is ignored because a more-specific route exists.

---

### Trap 2 — Default Route ≠ Default Gateway

```text
Host
  ↓
Default gateway
  ↓
Router
  ↓
Default route
  ↓
ISP
```

A host normally has a **default gateway**.

A router has a **default route**.

---

### Trap 3 — AD Is Different from Prefix Length

Do not say:

> "The default route has the lowest AD."

The default route is the **least-specific prefix**.

AD is a separate route-selection attribute.

Correct mental model:

```text
Longest-prefix match
        ↓
Best route among applicable candidates
        ↓
Administrative distance
        ↓
Metric / protocol-specific selection
```

---

### Trap 4 — Static Default AD = 1

A normal static default route has:

```text
AD = 1
```

Therefore:

```text
Static default → normally preferred
OSPF default   → AD 110
```

when both provide the same `0.0.0.0/0` prefix.

---

### Trap 5 — `default-information originate` Does Not Create a Local Default

This:

```cisco
router ospf 1
 default-information originate
```

means:

> Advertise a default route through OSPF, assuming the normal prerequisite is met.

It does **not** mean:

> Create `0.0.0.0/0` locally.

To create a local static default:

```cisco
ip route 0.0.0.0 0.0.0.0 192.0.2.1
```

---

### Trap 6 — `always` Changes OSPF Default Origination Behavior

Normal:

```cisco
router ospf 1
 default-information originate
```

Requires a local default route.

Forced:

```cisco
router ospf 1
 default-information originate always
```

Allows OSPF to originate the default even without a local default route.

---

### Trap 7 — Floating Default Uses Higher AD

Example:

```cisco
! Primary
ip route 0.0.0.0 0.0.0.0 192.0.2.1

! Backup
ip route 0.0.0.0 0.0.0.0 198.51.100.1 200
```

```text
AD 1   → primary
AD 200 → backup
```

---

### Trap 8 — No Default Route Means No Catch-All

If a packet has no matching route and there is no default route:

```text
No route
   ↓
Packet dropped
```

The router does not automatically send unknown traffic somewhere.

---

## 8. Default Route Decision Model

```text
                 Packet
                   ↓
            Destination IP
                   ↓
          Routing table / CEF
                   ↓
        Is there a matching route?
             ┌─────┴─────┐
            Yes           No
             ↓             ↓
     Longest-prefix      Default
        selection        route?
                         ┌──┴──┐
                        Yes    No
                         ↓      ↓
                    Forward   Drop
```

A more specific route always beats `0.0.0.0/0` when both match the destination.

### CCNP Takeaway

> **A default route is the least-specific route and acts as the router's catch-all path.  
> It is used only when no more-specific route matches. A default route can be static or  
> dynamically learned/advertised. For IPv4, it is `0.0.0.0/0`; for IPv6, `::/0`. Know the  
> distinction between a default route, default gateway, and gateway of last resort, and  
> remember that OSPF's `default-information originate` advertises a default rather than  
> creating the router's local default route.**
