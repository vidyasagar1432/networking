# PIM Sparse Mode (PIM-SM)

> **Level 19 · Multicast** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PIM-SM** is the **production default** for IP multicast. It assumes receivers are
**sparse** — nobody gets traffic until they **explicitly join** (pull model). Joins go
through a **Rendezvous Point (RP)** which builds a shared `(*,G)` tree; after a
threshold the router may switch to a source-based `(S,G)` SPT. Efficient, scalable, and
the design you must know cold.

---

## 2. Core Concepts

### 2.1 Pull model

| Step | Who | Action |
|------|-----|--------|
| 1 | receiver | IGMP report |
| 2 | DR | joins `(*,G)` toward RP |
| 3 | RP | shared tree built |
| 4 | source | registers to RP |
| 5 | last-hop | SPT switchover |

- Traffic flows only to **those who asked**.

### 2.2 Tree types

| Tree | Entry | Path | Use |
|------|-------|------|-----|
| Shared | `(*,G)` | via RP | initial |
| Shortest-path | `(S,G)` | source-direct | after switchover |

- **Shared tree** → **SPT switchover** after `ip pim spt-threshold 0`.

### 2.3 Key roles

| Role | Who |
|------|-----|
| RP | core of shared tree |
| DR | first-hop for source / last-hop for receiver |
| FHR | source's DR |
| LHR | receiver's DR |

- **RP**: where the source registers and receivers join.

### 2.4 Configuration

```text
ip multicast-routing
ip pim rp-address 192.168.10.10
interface Gi0/1
 ip pim sparse-mode
```

| Command | Purpose |
|---------|---------|
| `ip pim rp-address` | static RP |
| `ip pim sparse-mode` | enable SM per interface |
| `ip pim spt-threshold 0` | immediate SPT switchover |

- **Auto-RP / BSR** (note 04) remove static RP mapping.

### 2.5 Register process

| Step | Packet | Destination |
|------|--------|-------------|
| 1 | source → FHR | multicast |
| 2 | FHR → RP | **register** (unicast) |
| 3 | RP → FHR | register-stop |
| 4 | RP forwards | down shared tree |

- The register message **encapsulates** the multicast packet in unicast.

### 2.6 SPT switchover

```text
ip pim spt-threshold 0
```

| Item | Detail |
|------|--------|
| Default | 0 kbps (immediate) |
| After switch | LHR builds (S,G) |
| Result | shortest path, best latency |

- With threshold 0 the LHR switches **immediately** to the SPT.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No traffic | RP unreachable | show ip pim rp mapping |
| Shared only | spt-threshold | show ip mroute |
| Register failing | FHR/RP | debug ip pim |
| No joins | pim not enabled | show ip pim interface |
| RP mismatch | static vs auto | rp mapping |

---

## 5. Exam Traps

- PIM-SM = **pull/join** model via an **RP**.
- Trees: `(*,G)` shared then `(S,G)` SPT.
- **Register** carries the first packet unicast to the RP.
- `spt-threshold 0` = immediate SPT switchover.
- `ip pim sparse-mode` per interface.
