# Multicast Routing

> **Level 19 · Multicast** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

Multicast routing forwards copies of a packet **away from the source** along a **tree**,
and the core rule is **RPF** (Reverse Path Forwarding): a multicast packet is forwarded
only if it arrived on the interface the unicast table would use toward the source. The
lesson: multicast forwarding is **source- and RPF-driven**, using **MBGP** or **RPF
alternates** for inter-domain delivery.

---

## 2. Core Concepts

### 2.1 RPF check — the heart of multicast

| Rule | Detail |
|------|--------|
| Accept | packet from the RPF interface |
| Drop | wrong interface (RPF failure) |
| Basis | unicast route toward source |
| Result | loop-free distribution tree |

- If the source's route points out interface A but the packet arrived on B → **RPF
  failure** (dropped).

### 2.2 Why multicast uses unicast routing

| Aspect | Unicast | Multicast |
|--------|---------|-----------|
| Destination | host address | group address |
| Decision | toward destination | away from source |
| Routing basis | destination | RPF (source) |
| Protocol | unicast IGP | PIM + unicast |

- PIM uses the **existing unicast RIB** for RPF — no separate multicast topology.

### 2.3 mroute entries

| Entry | Meaning |
|-------|---------|
| `(*,G)` | any source, group (shared) |
| `(S,G)` | source, group (SPT) |
| OIL | outgoing interface list |
| Flags | RPF check result |

```text
show ip mroute
```

- Correct (S,G) with proper **OIL** = the tree is being built.

### 2.4 MBGP (multicast BGP)

| Item | Detail |
|------|--------|
| What | BGP carrying **NLRIs for multicast** |
| SAFI | 1 = unicast, 2 = multicast |
| Use | separate multicast RPF path |
| Benefit | RPF may differ from unicast path |

- **MBGP** lets multicast use a **different route** than unicast for RPF.

### 2.5 Inter-domain multicast

| Tool | Role |
|------|------|
| MBGP | multicast reachability |
| MSDP | RP peering / source discovery |
| PIM | forwarding between domains |
| SSM | simplifies inter-domain (v3 + source) |

- SSM (IGMPv3 + PIM-SM) avoids RP/register complexity for inter-domain.

### 2.6 Design points

| Concern | Mitigation |
|---------|------------|
| RPF asymmetry | MBGP / default route |
| Peering | PIM neighbors per link |
| Scope | TTL / boundary |
| Loop risk | always RPF |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| RPF drops | wrong inbound interface | show ip rpf |
| No mroute | PIM/RP issue | show ip mroute |
| Multicast path wrong | unicast asym | MBGP |
| No forwarding | OIL empty | mroute count |
| Inter-domain no flow | no MSDP/SSM | peering |

---

## 5. Exam Traps

- **RPF check** = forward only from the source-facing interface.
- RPF uses the **unicast RIB** — multicast rides unicast routing.
- **MBGP** = separate multicast NLRI (SAFI 2).
- `(*,G)` shared vs `(S,G)` SPT.
- SSM removes the RP/register model for simple inter-domain.
