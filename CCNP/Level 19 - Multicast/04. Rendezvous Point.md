# Rendezvous Point (RP)

> **Level 19 · Multicast** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **RP (Rendezvous Point)** is the router where receivers' `(*,G)` joins meet the
source's register traffic — the **hub of PIM-SM** (note 03). Every PIM-SM router must
know the **group → RP mapping**; that mapping can be **static**, learned via **Auto-RP**,
or via **BSR**. The exam tests mapping methods and RP placement/anycast.

---

## 2. Core Concepts

### 2.1 What the RP does

| Task | Detail |
|------|--------|
| Join target | receivers join `(*,G)` to RP |
| Register target | source FHR registers to RP |
| Forwarding | shared tree flows through RP |
| Mapping | routers need group→RP |

- No RP → **no shared tree**, no PIM-SM operation.

### 2.2 RP discovery methods

| Method | Mechanism | Pros | Cons |
|--------|-----------|------|------|
| Static | manual rp-address | simple | manual per site |
| Auto-RP | Cisco proprietary | dynamic | legacy |
| BSR | PIM draft standard | vendor-neutral | config |

- **Static** is the easiest to reason about and the exam favorite.
- Auto-RP/BSR give **dynamic** mapping and redundancy.

### 2.3 Auto-RP

| Role | Detail |
|------|--------|
| RP-announce | candidate RPs announce |
| RP-discovery | maps and distributes |
| Mapping agent | picks winner |
| Elections | by IP / weight |

- Auto-RP uses **Cisco-specific group 224.0.1.39/40**.
- Highest RP IP typically wins ties.

### 2.4 BSR (bootstrap router)

| Item | Detail |
|------|--------|
| BSR | elected bootstrap router |
| Candidate-RP | announces capabilities |
| Mapping | BSR floods to all PIM routers |
| Election | highest priority/IP |

- BSR is **PIM draft standard** — interoperable.

### 2.5 Configuration

```text
! static RP
ip pim rp-address 192.168.10.10
!
! Auto-RP candidate (on RP)
ip pim send-rp-announce Loopback0 scope 32
ip pim send-rp-discovery Loopback0 scope 32
!
! BSR candidate
ip pim bsr-candidate Loopback0 0
ip pim rp-candidate Loopback0
```

| Command | Method |
|---------|--------|
| `ip pim rp-address` | static |
| `send-rp-announce` | Auto-RP |
| `bsr-candidate` / `rp-candidate` | BSR |

### 2.6 RP placement & redundancy

| Strategy | Benefit |
|----------|---------|
| Central RP | simple, single point |
| Anycast RP (MSDP) | redundancy, shared load |
| Per-group RP | scale control |

- **Anycast RP** uses a shared loopback + **MSDP** for redundancy.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No mapping | static/auto not learned | show ip pim rp mapping |
| RP unreachable | routing to RP | ping RP |
| Auto-RP empty | announce/discovery missing | show ip pim rp mapping |
| BSR issues | scope/priority | debug ip pim |
| Traffic via wrong RP | mapping conflict | rp hash |

---

## 5. Exam Traps

- Every PIM-SM router needs the **group→RP mapping**.
- **Static**, **Auto-RP**, **BSR** — know all three.
- Auto-RP groups: **224.0.1.39/40** (Cisco proprietary).
- BSR is the **PIM draft standard**.
- **Anycast RP** = shared loopback + **MSDP**.
