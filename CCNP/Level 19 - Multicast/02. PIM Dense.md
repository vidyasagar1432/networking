# PIM Dense Mode (PIM-DM)

> **Level 19 · Multicast** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PIM-DM** assumes **almost every LAN has a receiver** — it **floods** multicast into the
network (push model) and then **prunes** branches with no members. It builds a
**source-based (S,G) tree** directly from the source. Simple, but inefficient for sparse
groups — hence PIM-SM (note 03) is the production default.

---

## 2. Core Concepts

### 2.1 Flood-and-prune model

| Step | Action |
|------|--------|
| 1 | source sends |
| 2 | flood to all PIM neighbors |
| 3 | leaf routers without members **prune** |
| 4 | state timeout → re-flood (every 3 min) |

- The tree is a **shortest-path tree (SPT)** rooted at the source.

### 2.2 State model

| State | Entry | Meaning |
|-------|-------|---------|
| (S,G) | source, group | per-source tree |
| (*,G) | any source | not used in DM |
| Prune state | branch cut | no receivers |

- PIM-DM uses only **(S,G)** states.

### 2.3 Traffic direction

| Item | Detail |
|------|--------|
| Flood | pushes toward everyone |
| Prune | cuts no-member branches |
| Graft | restores a pruned branch |
| Source | starts the flow |

- **Graft** = fast re-join after a new member appears below a prune.

### 2.4 Configuration

```text
ip multicast-routing
interface Gi0/1
 ip pim dense-mode
```

| Command | Purpose |
|---------|---------|
| `ip pim dense-mode` | enable DM per interface |
| `ip multicast-routing` | global multicast |

- No RP needed — **RP-less** design.

### 2.5 Dense vs Sparse at a glance

| Aspect | Dense | Sparse |
|--------|-------|--------|
| Assumption | members everywhere | members are sparse |
| Flow | push/flood | pull/join |
| State | (S,G) only | (*,G) + (S,G) |
| RP | not needed | required |
| Efficiency | low for sparse | high |
| Default | no | **yes** |

- Production networks use **PIM-SM**; DM is a lab/legacy topic.

### 2.6 When DM is acceptable

- Small, fully-meshed groups with dense receivers (e.g., LAN audio).

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No tree | pim not enabled | show ip mroute |
| Flapping prune | no members | receivers |
| Graft storms | flapping member | stability |
| Neighbor missing | interface mode | show ip pim neighbor |
| Traffic loops | RP confusion | none (RP-less) |

---

## 5. Exam Traps

- PIM-DM = **flood-and-prune**, source-based **(S,G)** SPT.
- **No RP** required in dense mode.
- **Graft** restores pruned branches.
- Inefficient → **PIM-SM is the production default**.
- `ip pim dense-mode` per interface.
