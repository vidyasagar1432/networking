# SD-WAN

> **Level 30 · Labs** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **SD-WAN lab** brings up the **control plane** (vManage/vSmart/vBond), **onboards
vEdge/cEdge**, and verifies **transport tunnels, BFD, and policy**. It modernizes WAN
design with centralized control.

---

## 2. Core Concepts

### 2.1 Components

| Node | Role |
|------|------|
| vManage | dashboard |
| vSmart | policy |
| vBond | orchestrator |
| vEdge/cEdge | router |
| vAnalytics | reporting |

- **Control plane first; data plane follows.**

### 2.2 Onboarding flow

| Step | Action |
|------|--------|
| 1 | DNA/port |
| 2 | vBond discovery |
| 3 | upload to vManage |
| 4 | vSmart contact |
| 5 | tunnels form |

- vEdge **finds vBond, then registers** to vManage.

### 2.3 Verification commands

| Check | Command |
|-------|---------|
| Control | show sdwan control connections |
| Local | show sdwan control local-properties |
| Tunnel | show sdwan tunnel |
| Interface | show sdwan interface |
| Policy | show sdwan policy |

- **Control + tunnel** tables = core health.

### 2.4 BFD / SLA

| Item | Detail |
|------|--------|
| BFD | liveness |
| SLA | class metrics |
| Path | preference |
| Fallback | backup |
| vSmart | apples policy |

- **BFD/SLA drive path selection + failover.**

### 2.5 Policy

| Type | Scope |
|------|-------|
| Centralized | vSmart |
| Data | match/action |
| Control | routing |
| Localized | device |
| App-aware | priority |

- Policy = **vSmart-applied match/action rules**.

### 2.6 Lab flow

| Step | Action |
|------|--------|
| 1 | deploy controllers |
| 2 | onboard edge |
| 3 | check control |
| 4 | tunnels |
| 5 | policy |
| 6 | verify |

- **Deploy → onboard → control → tunnels → policy.**
