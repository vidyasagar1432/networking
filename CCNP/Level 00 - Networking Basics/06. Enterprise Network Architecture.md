# Enterprise Network Architecture

> **Level 00 · Level 00 - Networking Basics** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

Enterprise architecture is the structured way of organizing network devices into
functional modules so the network is **predictable, scalable, secure, and manageable**.
The classic Cisco architecture (Cisco Enterprise Architecture model) splits the network
into layers/modules; modern variants (SD-Access fabric, Cisco DNA) preserve the same
design goals with automation on top.

---

## 2. Core Concepts

### 2.1 Hierarchical (three-tier) model — the foundation

| Layer | Role | Devices | Notes |
|-------|------|---------|-------|
| **Core** | High-speed backbone, fast convergence, no policy | Routers/L3 spine switches | Always-uplink; never apply policy here |
| **Distribution** | Routing between VLANs, policy, aggregation of access | L3 switches (routers) | QoS marking, ACLs, first-hop redundancy falls here (chassis HA) |
| **Access** | Endpoint connectivity, ports, PoE, VLAN assignment | L2/L3 switches, APs | Keep it simple: ports + VLANs (+ 802.1X/port security) |

Two-tier collapsed core merges core+distribution for smaller sites; three-tier is for
large sites, especially with a separate server block or WAN edge.

### 2.2 Cisco modular model (functional blocks)
- **Campus core / distribution / access** — user connectivity (as above).
- **Server farm (data center) module** — servers, storage, firewalls/load balancers
  between campus and DC (west-east flows).
- **WAN module (WAN edge)** — MPLS, Internet, SD-WAN; connects to branch/remote sites.
- **Branch office module** — smaller campus replicating access→distribution→WAN edge;
  destination of VPN/DMVPN tunnels from HQ.
- **Remote Access / VPN module** — terminates user VPNs (SSL/IPsec), placed in DMZ.
- **Internet edge / DMZ** — firewalls, web/email DMZ tiers, Internet router.
- **Teleworker / home office** — connectivity over broadband/cellular.

### 2.3 Design choices within each module
- **Redundancy & HA:** two core switches, dual uplinks from every access switch
  (L2/L3 trunks), HSRP/VRRP for default gateways, redundant SUP (Level 27).
- **Loop prevention:** spanning-tree on L2 (Level 08), routed design where possible.
- **Segmentation:** VLANs per functional area (users, servers, management, voice, guest),
  later replaced/expanded by VXLAN/VRF/SD-Access segmentation (Level 24).

### 2.4 Modern architecture — SD-Access (fabric) summary
- Centralized **DNA Center** controller + fabric underlay (IS-IS), overlay using
  **VXLAN** over LISP, per-group segmentation (SGT/SCA) instead of static VLANs.
- Keeps the same modules but moves from box-by-box config to intent-based automation.
- (Deep dive: Level 24 SDN & Automation.)

### 2.5 Traffic-flow terminology
- **North-south** — client→server (to DC/WAN), crosses the hierarchy.
- **East-west** — server-to-server within a data center (high volume, very low latency),
  shapes DC spine-leaf design (Level 02 Two-Tier / spine-leaf).

## 3. Configuration / Commands

```text
# Collapsed-core concept at distribution switch (first-hop gateway)
interface Vlan10
 ip address 10.1.10.1 255.255.255.0
standby 10 ip 10.1.10.254
standby 10 priority 110          # active first-hop redundancy (HSRP)

# Access switch: port to a server/PC
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast

# Trunk uplink to distribution
interface GigabitEthernet0/24
 switchport trunk encapsulation dot1q
 switchport mode trunk
 channel-group 1 mode active       # EtherChannel to dist
```

## 4. Exam Traps

- **Don't put policy in the core** — core = fast and clean; distribution owns policy/QoS.
- **"Collapsed core" = distribution+core merged** — common small-site answer, not a mistake.
- **VLAN design:** management VLAN should be separated from user VLANs (often one dedicated
  and untagged once; avoid spanning-tree root changes).
- **Fabric vs classic:** VXLAN + LISP + DNA Center is the modern, but classic 3-tier is
  still the answer for traditional enterprise topology questions.
- **Server farm placement:** east-west fencing (firewalls along DC boundary) is a modern
  security pattern; expect a question about segmenting the DC from campus.
- **DMZ is not "just an extra VLAN"** — it's a zone between outside and inside, own
  firewall policy, one-arm or two-arm placement.

## 5. Quick Review Table

| Module | Purpose | Devices | Policy? |
|--------|---------|---------|---------|
| Campus core | High-speed backbone | Core switches/routers | No |
| Distribution | Routing, policy, aggregation | L3 switches | Yes |
| Access | Endpoints, ports, PoE | Switches, APs | Light |
| Server farm (DC) | Compute/storage | ToR/EoR, firewalls, LB | Yes (segmentation) |
| WAN edge | MPLS/Internet/SD-WAN | Routers, vEdge | Yes |
| Internet edge/DMZ | External services | Firewalls, DMZ tiers | Yes, strict |
| Remote access | User VPN | SSL/IPsec concentrators | Yes |
| Branch | Small campus replica | Access+dist+WAN edge | Assigned centrally |
| Teleworker | Home users | Broadband/cellular, VPN | Via VPN |
