# Docker

> **Level 25 · Virtualization & Cloud** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Docker** is the most common **container runtime/platform**: build images from a
**Dockerfile**, share them in a **registry**, and run them anywhere. Core concepts —
**image, container, volume, network, compose** — underpin cloud-native networking (CNF,
CI/CD). The exam tests the object model and key commands.

---

## 2. Core Concepts

### 2.1 Object model

| Object | Meaning |
|--------|---------|
| Image | read-only template |
| Container | running image |
| Volume | persistent data |
| Network | connectivity |
| Compose | multi-container |

- **Image → container**; volumes persist; compose orchestrates locally.

### 2.2 Dockerfile

```dockerfile
FROM ubuntu
RUN apt-get update
COPY app.py /app.py
EXPOSE 80
CMD ["python3", "/app.py"]
```

| Instruction | Meaning |
|-------------|---------|
| FROM | base image |
| RUN | build step |
| COPY | add file |
| EXPOSE | port |
| CMD | runtime command |

- A Dockerfile **builds images declaratively**.

### 2.3 Key commands

| Command | Meaning |
|---------|---------|
| `docker build` | create image |
| `docker pull/push` | registry |
| `docker run` | start container |
| `docker ps` | list running |
| `docker exec` | run inside |
| `docker stop/rm` | manage |

- **pull → run → exec → stop** = the lifecycle.

### 2.4 Networking

| Mode | Detail |
|------|--------|
| bridge | default NAT |
| host | shared net |
| none | isolated |
| custom | user networks |

- Containers default to a **bridge/NAT** network.
- `-p` publishes host→container ports.

### 2.5 Docker vs VM mindset

| Aspect | Docker |
|--------|--------|
| Kernel | shared |
| Process | per container |
| Startup | milliseconds |
| Isolation | namespaces |

- Docker = **process-level virtualization**.

### 2.6 Docker in networking

| Use | Detail |
|-----|--------|
| CNF | containerized NFs |
| Lab | test topologies |
| CI/CD | automated |
| Orchestration | K8s (note 05) |

- Docker runs **network functions/testbeds**; K8s scales them.

## 3. Configuration / Commands

```bash
docker build -t myapp .
docker run -d -p 8080:80 myapp
docker ps
docker logs <id>
docker exec -it <id> /bin/bash
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Port conflict | -p | docker ps |
| Image pull fail | registry/network | pull |
| Container exits | CMD | logs |
| No network | bridge | networks |
| Data lost | no volume | volumes |

## 5. Exam Traps

- Docker objects: **image, container, volume, network**.
- Dockerfile: **FROM/RUN/COPY/EXPOSE/CMD**.
- Default network = **bridge/NAT**.
- `docker ps/run/exec/build` — know the verbs.
- Docker = process isolation; **K8s = orchestration**.
