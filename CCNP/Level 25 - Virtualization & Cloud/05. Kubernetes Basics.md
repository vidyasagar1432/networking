# Kubernetes Basics

> **Level 25 · Virtualization & Cloud** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Kubernetes (K8s)** is the **container orchestrator** — it schedules, scales, and
heals container workloads across a **cluster**. Core objects: **nodes, pods,
deployments, services, namespaces**. For networking, K8s services and **CNI/Ingress**
are the key concepts to remember.

---

## 2. Core Concepts

### 2.1 Cluster structure

| Component | Role |
|-----------|------|
| Control plane | brain (API server) |
| Worker nodes | run pods |
| kubelet | node agent |
| etcd | state store |

- **Control plane decides; workers run** the workload.

### 2.2 Core objects

| Object | Meaning |
|--------|---------|
| Node | a worker machine |
| Pod | smallest unit (1+ containers) |
| Deployment | desired replicas |
| Service | stable network endpoint |
| Namespace | logical partition |

- **Pods run apps; services expose them; deployments maintain count.**

### 2.3 Pod vs Service

| Item | Detail |
|------|--------|
| Pod | ephemeral, own IP |
| Service | stable VIP/clusterIP |
| Selector | labels to match pods |
| Result | apps don't chase IPs |

- **Services decouple clients from pod churn.**

### 2.4 Networking model

| Layer | Detail |
|-------|--------|
| Pod network | full mesh, CNI |
| Service | clusterIP |
| Ingress | external L7 |
| NodePort/LB | external access |

- **CNI** provides pod networking; **Ingress** exposes services.

### 2.5 Scaling & self-healing

| Behavior | Detail |
|----------|--------|
| Desired state | declarative |
| Replicas | auto scale |
| Health | liveness probes |
| Restart | crashed pods re-created |

- K8s **reconciles** current → desired state continuously.

### 2.6 Key commands

```bash
kubectl get nodes
kubectl get pods -A
kubectl get services
kubectl apply -f deployment.yaml
kubectl scale deploy app --replicas=5
```

| Command | Meaning |
|---------|---------|
| get | list resources |
| apply | declarative apply |
| scale | change replicas |

## 3. Configuration / Commands

```bash
kubectl get nodes/pods/services/namespaces
kubectl apply -f manifest.yaml
kubectl describe pod <name>
kubectl logs <pod>
kubectl scale deployment --replicas=N
```

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Pod pending | resources | describe |
| CrashLoop | app | logs |
| No service | selector | services |
| Node not ready | kubelet | get nodes |
| Image pull | registry | events |

## 5. Exam Traps

- K8s = **orchestration; Docker = runtime**.
- **Pod = unit; Service = stable endpoint; Deployment = replicas**.
- Control plane vs worker nodes.
- Networking: **CNI (pods), Service (clusterIP), Ingress (L7)**.
- Declarative desired state + **self-healing**.
