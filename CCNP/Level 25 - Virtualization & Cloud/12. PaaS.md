# PaaS

> **Level 25 · Virtualization & Cloud** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PaaS** provides a **managed platform** — runtime, DB, middleware — where developers
deploy code without managing servers/OS. The provider handles **infra + platform**;
you manage **app + data**. Examples: **Azure App Service, AWS Elastic Beanstalk,
container services**. It sits **between IaaS and SaaS** in control.

---

## 2. Core Concepts

### 2.1 What PaaS is

| Item | Detail |
|------|--------|
| Deliverable | platform/runtime |
| Provider | infra + OS + runtime |
| Customer | app + data |
| Access | deploy your code |

- PaaS = **rent the platform, bring the app**.

### 2.2 Examples

| Service | Use |
|---------|-----|
| Azure App Service | web apps |
| AWS Beanstalk | deploy |
| Google App Engine | scale |
| Managed DB | PaaS data |

- **Managed DBs and app runtimes** are classic PaaS.

### 2.3 Responsibility split

| Layer | Provider | Customer |
|-------|----------|----------|
| Infra | yes | no |
| OS | yes | no |
| Runtime/middleware | yes | no |
| App + data | no | yes |

- Provider owns the **platform**; you own the **app**.

### 2.4 PaaS vs IaaS vs SaaS

| Model | You manage |
|-------|-----------|
| IaaS | OS + app + data |
| PaaS | app + data |
| SaaS | data + users |

- **PaaS is mid-control**: less than IaaS, more than SaaS.

### 2.5 Networking angle

| Item | Detail |
|------|--------|
| Public endpoint | provider LB |
| VNet/VPC | still isolated |
| APIs | app integration |
| Security | app-level |

- App **APIs + cloud network** still matter to network teams.

### 2.6 Pros/cons

| Pro | Con |
|-----|-----|
| No infra mgmt | platform limits |
| Fast dev | lock-in |
| Auto scale | cost control |
| Managed DB | data residency |

- PaaS = **developer velocity** at some flexibility cost.
