# Three-Tier (Hierarchical)

> **Level 02 · Network Topologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **three-tier / hierarchical** model layers the LAN as **Core → Distribution →
Access**. This is Cisco's classic campus framework: each layer has distinct roles,
making the network scalable, predictable, and easy to tune. Used for large campuses,
multi-building sites, and enterprise cores where a two-tier "collapsed core" is too big.

---

## 2. Core Concepts

### 2.1 The three layers and their jobs

| Layer | Role | What runs there |
|-------|------|-----------------|
| **Access** | Endpoint connectivity | Ports, VLAN assignment, PoE, port security/802.1X, QoS trust on endpoints |
| **Distribution** | Policy, routing, aggregation | Inter-VLAN routing, ACLs/firewalling, QoS marking, default gateways (HSRP/VRRP), summarization |
| **Core** | Fast transport backbone | Pure L3 forwarding; *no policy*; maximum speed & redundancy |

Rules that make it work:
- **Core = fast and dumb** — never attach users or policy to the core.
- **Distribution = the smart layer** — aggregation + policy point (the "routing brain").
- **Access = simple and cheap** — keep it shallow, let the distribution hold logic.

### 2.2 Typical traffic-flow logic
- North-south flows traverse access→distribution→core (e.g., to servers/WAN).
- Distribution performs **summarization** (VLANs → summary routes) toward the core,
  keeping core tables small and convergence fast.
- Redundancy everywhere: dual uplinks (access→both dists), dist pair → core pair.

### 2.3 Variants and scaling
- Small: collapsed core (2-tier) — see [[07. Two-Tier]].
- Large: **split distribution** per building, each pair owning its VLANs/subnets,
  core interconnects them.
- Modern: **spine-leaf** replaces the rigid 3-tier in DCs, but the conceptual
  access/dist/core logic still underpins design questions.

### 2.4 Failure & STP interplay
- L2 loops from dual uplinks are handled by **MST/RPVST+** (see Level 08);
- Distribution pairs run **first-hop redundancy (HSRP/VRRP)** so hosts always have a gateway;
- Core failure → routing protocols converge; distribution-to-core is usually routed.

## 3. Configuration / Commands

```text
# Distribution switch: inter-VLAN router + gateway
interface Vlan10
 ip address 10.1.10.1 255.255.255.0
standby 10 ip 10.1.10.254
standby 10 priority 120          # active/backup pair

# Summarization toward core
router ospf 1
 summary-address 10.1.0.0 255.255.252.0   # summarize VLANs

# Core: pure L3, no VLANs/policy — just routes
interface TenGigabitEthernet1/1
 ip address 10.0.0.1 255.255.255.252
```

---

## 4. Exam Traps

- **No policy in the core** is the #1 three-tier trap; the answer is "core = transport, distribution = policy."
- **Best place for default gateway**: distribution, not access or core.
- **Access switches may be L2** (common) — don't insist they must route.
- **Spanning Tree belongs to L2 access/dist; routed core has none.**
- **The exam synonym mapping**: "**collapsed core**" = two-tier; "**hierarchical**" = three-tier.

| Layer | Responsibility | Watch-list |
