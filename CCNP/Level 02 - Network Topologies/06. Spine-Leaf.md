# Spine-Leaf (Clos)

> **Level 02 · Network Topologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Spine-leaf** is the modern data-center/enterprise switching architecture: every
**leaf** (ToR) switch connects to every **spine** switch, and no leaf connects to another
leaf. It is a Clos network delivering **predictable east-west performance**, low
latency, and easy scaling.

---

## 2. Core Concepts

### 2.1 Why replace the tree
- A traditional 3-tier tree concentrates **north-south** traffic and gets bottlenecked;
  east-west (server↔server) traffic had to traverse many hops.
- Spine-leaf keeps **any-to-any in ≤ N hops** (leaf→spine→leaf) regardless of size.

### 2.2 Structure and rules

| Element | Role | Rules |
|---------|------|-------|
| Spines | Aggregation/backbone | No spine↔spine links; all traffic passes through a spine |
| Leaves (ToR/EoR) | Connect servers/storage + gateways | Every leaf to every spine; no leaf↔leaf |
| Uplinks | Equal-cost paths | All links are used (ECMP) — no STP blocking |
| Overlay/underlay | Often VXLAN + BGP/IS-IS | Address scaling; anycast gateways |

### 2.3 Characteristics
- **Predictable latency**: 3-4 hops for any flow; each member of ECMP has equal cost.
- **Scalability**: add a spine → all leaves gain 1 more path (linear for leaves with N spines).
- **No loops by design**: at L2-with-fabric, or fully L3 (routed) — avoids STP blocking
  (you can run ECMP).
- **Load balance with ECMP / VXLAN hashing** — flows distributed across every spine.

### 2.4 Spine-leaf modernization details (ENCOR-relevant)
- **Overlay**: **VXLAN** provides L2 segments over the L3 underlay (Level 24);
  **anycast VTEP gateways** enable seamless VM migration.
- **Control plane**: BGP EVPN (or MP-BGP) exchanges MAC/IP reachability;
  IS-IS or OSPF on the underlay.
- **Physical connectivity**: 40/100G uplinks; QSFP/MPO (see Level 01 Transceivers).
- Small vs large: **2-spine + 4-leaf** classroom; production is 4-8+ spines, many leaves.

### 2.5 Spine-leaf vs traditional (comparison snapshot)

| | Traditional tree | Spine-leaf |
|--|------------------|------------|
| Hop count | Variable, grows | Fixed ≤3-4 |
| Link utilization | Core bottleneck | All uplinks ECMP |
| East-west | Slow | Fast, predictable |
| Loop control | STP blocking | ECMP / routed fabric |
| Scaling | Redesign at core | Add spines/leaves |

## 3. Configuration / Commands

```text
# Example: underlay IGP on a leaf (each link equal cost)
interface Ethernet1/1
 description to SPINE-1
 ip address 10.10.0.1/31
interface Ethernet1/2
 description to SPINE-2
 ip address 10.10.1.1/31
router ospf 1
 network 10.10.0.0/16 area 0 # leaves+spines all area 0 (or BGP underlay)

# Verify ECMP
show ip route | include "via Two"
show ip cef 1.1.1.1 internal     # multiple FIB next-hops
```

## 4. Exam Traps

- **No leaf-leaf links, no spine-spine links** — that's the definition; any config
  showing that = wrong.
- **ECMP everywhere**: in leaf-spine, ALL parallel links are active — do not say
  "STP blocks one" (that's old-tree thinking).
- **Hop count reasoning**: "3 hops" for leaf-to-leaf with 2 spines.
- **Scaling answer**: to increase capacity per leaf, add spines (spine count = capacity);
  to add capacity total, add leaves.
- **Underlay vs overlay** distinction; VXLAN is overlay L2 — the topological question is
  about the interconnected fabric below it.

|------|----------|------|
