# Mesh Topology

> **Level 02 · Network Topologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

In a **mesh** topology, nodes are interconnected with direct links — **full mesh**
(every node to every other) or **partial mesh** (only some pairs). Mesh provides the
most redundancy and the best path diversity; its cost (links) is the trade-off.

---

## 2. Core Concepts

### 2.1 Full vs partial

| Model | Links needed | When used |
|-------|-------------|-----------|
| **Full mesh** (N nodes) | `N(N−1)/2` links | Small core / key hub HA; cost dominates beyond ~5-6 nodes |
| **Partial mesh** | Subset (a hub-and-spoke with extras) | WAN cores, ISP backbones, data centers |

### 2.2 Why mesh exists — path redundancy + lower latency
- **Multiple paths** → if a link fails, traffic uses another (fault tolerance).
- **No single point of failure** for a meshed node.
- **Lower hop count / lower latency** — near-complete connectivity.
- **Load-balancing** possibilities (equal-cost multipath).

### 2.3 Mechanisms that make mesh possible (switching/routing)
- **L2**: The redundancy creates loops — **Spanning Tree (STP)** puts redundant links
  in Blocking to prevent broadcast storms; EtherChannel bundles two links into one
  logical (Level 08).
- **L3**: routing protocols (OSPF/BGP) learn multiple equal paths and offload —
  **ECMP** balances across parallel links; **fast convergence** when a path disappears (Level 09/10/12).
- **Spine-leaf** (Level 06) = a disciplined partial/full mesh: every leaf ↔ every spine.

### 2.4 Real-world mesh examples
- **WAN partial mesh** — backup circuits between major sites (2 sites↔HQ circuit).
- **ISP backbone** — national meshes enable sub-50 ms convergence on fiber cut.
- **Data center spine-leaf** — full-mesh underlay between spines/leaves.
- **Wireless mesh** — APs relay to each other to extend coverage without cabling
  (and here mesh is a radio-forwarding topology).

## 3. Configuration / Commands

```text
# ECMP example (two equal-cost static/default routes) — router balances
ip route 0.0.0.0 0.0.0.0 10.0.0.1
ip route 0.0.0.0 0.0.0.0 10.0.0.2
# show ip route will list both with same AD/metric → load-balanced (CEF)

# L2 pairwise links in a mesh — invert STP behavior per link? Actually:
# leave STP on; redundant paths will block one (RSTP/MST). For two links between
# the same pair of switches use EtherChannel:
interface Port-channel1
 channel-group 1 mode active          # LACP
interface GigabitEthernet0/1
 channel-group 1 mode active
```

## 4. Exam Traps

- **Full-mesh link count formula `N(N-1)/2`** — an easy calculation question (4 nodes → 6 links).
- **Mesh at L2 without STP/EtherChannel = loop risk** — the design must control redundancy.
- **Mesh is NOT default for small networks** — full mesh for 20 routers is absurd; partial mesh / hub-spoke is typical.
- **ECMP** is how routing realizes mesh benefit — AD and metric both equal.
- **Wireless mesh** relays degrade with hops (half throughput per hop in some techs) — a trap in RF questions.

## 5. Quick Review Table

| Aspect | Full mesh | Partial mesh |
|--------|-----------|--------------|
| Links | N(N-1)/2 | Selected subset |
| Redundancy | Every pair | Some pairs |
| Cost | Grows fast | Moderate |
| Fault | Best per-node | Depends on the kept links |
| Loading | ECMP easy | Paths for hot spots |
| Typical | Small cores, spines | WAN/ISP backbones |
| L2 caveat | STP/EtherChannel required | Loops controlled |
