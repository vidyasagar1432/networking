# NAT64

> **Level 15 · NAT** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**NAT64** lets **IPv6-only** hosts reach **IPv4-only** destinations by translating at the
network edge. It pairs a **stateful IPv6→IPv4 translator** with a **DNS64** resolver that
synthesizes `AAAA` records. It's the coexistence tool when you can't run dual-stack
everywhere — IPv6 clients talk "IPv6", the NAT64 box rewrites to IPv4, and replies come
back through the same state.

---

## 2. Core Concepts

### 2.1 The NAT64 translation model

| Side | Address | Role |
|------|---------|------|
| IPv6 client | 2001:db8::/32 etc. | source |
| Well-known prefix | 64:ff9b::/96 | embedded IPv4 |
| Translator | NAT64 gateway | rewrites 6↔4 |
| IPv4 server | 192.0.2.10 | destination |

- The **64:ff9b::/96 well-known prefix** encodes the IPv4 destination inside an IPv6
  address.

### 2.2 DNS64 role

- IPv6 client asks for a domain; the IPv4 DNS answer only has A records.
- **DNS64 synthesizes an AAAA**: `64:ff9b::<IPv4>` so the client can address it over IPv6.
- The NAT64 gateway then maps that synthetic address to the real IPv4 host.

### 2.3 Stateful vs stateless NAT64

| Type | State table | Port translation |
|------|-------------|------------------|
| Stateful | yes | yes (PAT-like) |
| Stateless | no | no (1:1 via IPv4-translatable) |

- Stateful NAT64 is the common deployment; stateless needs 1:1 v6/v4 address mapping.

### 2.4 Configuration overview (IOS XE)

```text
interface Vlan10
 ipv6 address 2001:db8:10::1/64
 ipv6 enable

nat64 enable
nat64 prefix stateful 64:ff9b::/96
nat64 v4 pool NAT64-POOL 192.0.2.1 192.0.2.20
interface Vlan20
 ipv4 address 192.0.2.254 255.255.255.0
 nat64 enable
```

- The **well-known prefix** `64:ff9b::/96` is the default stateful NAT64 prefix.
- IPv4 pool provides the translated addresses for outbound sessions.

### 2.5 Deployment modes

| Mode | Use |
|------|-----|
| NAT64 + DNS64 | host access to IPv4 (exam classic) |
| 464XLAT | mobile carriers (CLAT + PLAT) |
| Prefix 64:ff9b::/96 | standard embedding |

- DNS64 must be reachable by the IPv6 clients; it's the "first hop" of the solution.

### 2.6 Considerations

| Concern | Note |
|---------|------|
| ALG | FTP/SIP need inspection |
| Fragmentation | MTU handling required |
| State scale | translator must track flows |
| Inbound IPv4→IPv6 | needs explicit statics (not automatic) |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No translation | prefix / v4 pool missing | show nat64 stats |
| DNS fails | no DNS64 | AAAA synthesis |
| Unreachable | prefix wrong | well-known prefix |
| Return dies | state expired / asymmetry | bidirectional flows |
| Fragmentation | MTU small | adjust |

---

## 5. Exam Traps

- **64:ff9b::/96** = the well-known NAT64 prefix.
- NAT64 is **stateful + port translation** (unlike simple NAT-PT).
- **DNS64** synthesizes AAAA from A — the pair that enables IPv6-only clients.
- NAT64 solves **IPv6→IPv4**; IPv4→IPv6 needs explicit statics.
- It's the transition answer when dual-stack isn't an option.
