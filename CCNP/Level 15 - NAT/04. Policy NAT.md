# Policy-Based NAT

> **Level 15 · NAT** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Policy NAT** applies translation **conditionally** — matching an ACL and/or specifying
**source+destination** pairs, rather than blanket "all inside traffic" rules. It lets
different flows (by source, destination, or port) use **different public addresses or
pools**, enabling traffic steering, asymmetric return paths, and multi-ISP designs.

---

## 2. Core Concepts

### 2.1 The generalized NAT syntax

```text
ip nat inside source [list ACL | interface INTF | static ...]
```

- Plain ACL NAT matches on **source only**.
- **Policy NAT** adds a **destination ACL** to refine the trigger.

### 2.2 Matched pairs (source + destination)

```text
access-list SRC permit 10.0.0.0 0.0.255.255
access-list DST permit 198.51.100.0 0.0.0.255

ip nat pool WEB-GLOBAL 203.0.113.1 203.0.113.2 netmask 255.255.255.0
ip nat inside source list SRC pool WEB-GLOBAL match-in-vrf
```

- Cisco IOS policy NAT uses **`match ip address in-list` + `out-list`** forms:

```text
ip nat inside source list 1 pool POOL-A
ip nat inside source list 1 match ... 
```

### 2.3 The route-map / match form (IOS XE modern)

```text
route-map NAT-POLICY permit 10
 match ip address SRC
 match ip address DST
 set ip next-hop 10.255.255.1
```

- Route-map NAT applies translation **only when the route-map permits** — closest to
  "policy NAT".

### 2.4 Use cases

| Use | Behavior |
|-----|----------|
| Multi-ISP | source-per-ISP pools |
| Traffic steering | shift VOIP to separate global IP |
| Asymmetric routing | return path pinned |
| Security segmentation | NAT only for untrusted nets |

- PAT interfaces per link + policy = dual-uplink translation.

### 2.5 Outside-policy NAT

```text
ip nat outside source static 203.0.113.99 198.51.100.99
```

- Rewrites the **outside source** — used when remote ranges overlap internal ones
  (NAT for overlapping address domains).

### 2.6 Policy NAT vs ACL NAT (the boundary)

| Aspect | ACL NAT | Policy NAT |
|--------|---------|------------|
| Trigger | source ACL | source + destination / ports |
| Selectivity | coarse | fine-grained |
| Multiple pools | static mapping | conditional by flow |
| Typical use | general sharing | multi-ISP, steering |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Not translated | ACL too narrow | match lists |
| Wrong public IP | policy picks wrong pool | policy-to-pool binding |
| Return fails | outside-policy asymmetric | both directions |
| Overlap VPN returns | missing outside NAT | outside source maps |
| Policy ignored | route-map order | route-map permit |

---

## 5. Exam Traps

- Policy NAT = **conditional** translation (destination/port aware).
- Outside-policy NAT fixes **overlapping address** domains.
- Source-only ACL NAT is NOT policy NAT — the destination filter is the difference.
- Route-map NAT matches and translates only permitted flows.
- Multi-ISP NAT is the flagship policy-NAT use case.
