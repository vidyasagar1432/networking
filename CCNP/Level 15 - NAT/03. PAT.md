# PAT (Port Address Translation / NAT Overload)

> **Level 15 · NAT** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PAT (Port Address Translation)**, also called **NAT overload**, allows multiple inside hosts to share one or more public IP addresses.

Unlike traditional dynamic NAT, PAT uses **Layer-4 identifiers** such as TCP/UDP source ports to maintain unique translations.

Example:

```text
Inside host
10.0.0.5:12345
      │
      │ PAT
      ▼
203.0.113.1:12345
      │
      ▼
Internet
```

If another inside host uses the same source port:

```text
10.0.0.6:12345
      │
      │ PAT
      ▼
203.0.113.1:20001
```

The router maintains a translation table so return traffic can be mapped to the correct inside host.

> **Key idea:** PAT allows many inside-local addresses to share an inside-global address by using Layer-4 identifiers to distinguish simultaneous flows.

---

## 2. NAT Terminology

|Term|Meaning|
|---|---|
|**Inside Local**|Address assigned to the inside host, normally private|
|**Inside Global**|Address representing the inside host to the outside network|
|**Outside Global**|Address of the external destination as known on the outside network|
|**Outside Local**|Address of the external destination as represented to the inside network|

Example:

```text
Inside host                         Internet server
10.0.0.5:12345                      198.51.100.10:443
     │                                      │
     │            PAT Router                │
     └──────────────┬───────────────────────┘
                    │
                    ▼
             203.0.113.1:12345
```

---

## 3. How PAT Works

### 3.1 Outbound translation

Suppose:

```text
Inside host:
10.0.0.5:12345

Destination:
198.51.100.10:443
```

The router may create:

```text
10.0.0.5:12345
        ↓
203.0.113.1:12345
```

If that source port cannot be used for the required translation, IOS can allocate another source port:

```text
10.0.0.5:12345
        ↓
203.0.113.1:23456
```

The important requirement is that the resulting translation is **unique enough for the router to identify the correct return flow**.

---

### 3.2 Return traffic

The Internet server responds to:

```text
203.0.113.1:23456
```

The NAT router looks up the translation:

```text
203.0.113.1:23456
        ↓
10.0.0.5:12345
```

The packet is then forwarded to the original inside host.

---

## 4. PAT Translation Keys

PAT primarily uses Layer-4 information to distinguish simultaneous flows.

|Protocol|Identifier|
|---|---|
|TCP|TCP source port|
|UDP|UDP source port|
|ICMP Echo|ICMP Identifier|
|Other protocols|Behavior depends on protocol and IOS NAT support|

TCP and UDP have separate port spaces, so the same numeric port can exist simultaneously for TCP and UDP.

> **Important:** PAT does not mean that every packet must have its source port numerically changed. IOS may preserve the original source port when the translation remains unique; a different port can be allocated when required.

---

## 5. PAT Configuration

### 5.1 PAT using an address pool

```cisco
access-list 1 permit 10.0.0.0 0.0.255.255

ip nat pool PUBLIC 203.0.113.1 203.0.113.10 netmask 255.255.255.0

ip nat inside source list 1 pool PUBLIC overload
```

The keyword:

```cisco
overload
```

causes multiple inside hosts to share the addresses in the NAT pool using PAT.

---

### 5.2 PAT using the outside interface address

The most common configuration is to overload the router's outside interface address:

```cisco
access-list 1 permit 10.0.0.0 0.0.255.255

ip nat inside source list 1 interface GigabitEthernet0/1 overload
```

This means:

```text
Inside hosts
10.0.0.0/16
     │
     │ PAT
     ▼
Gi0/1 interface address
203.0.113.1
```

---

## 6. Required Interface Configuration

The router must identify which interface is connected to the inside and which is connected to the outside.

```cisco
interface GigabitEthernet0/0
 ip address 10.0.0.1 255.255.255.0
 ip nat inside

interface GigabitEthernet0/1
 ip address 203.0.113.1 255.255.255.0
 ip nat outside
```

The NAT rule and interface roles work together:

```text
Inside interface
      │
      │  ip nat inside
      ▼
   NAT Router
      │
      │  ip nat outside
      ▼
Outside interface
```

## 7. PAT vs Dynamic NAT

|Feature|Dynamic NAT|PAT / NAT Overload|
|---|---|---|
|Address mapping|IP → IP|IP:port → IP:port|
|Public addresses|Usually multiple|One or a few|
|Port translation|Not required|Used to distinguish flows|
|Scalability|Limited by address pool|Much higher|
|Return traffic|Existing translations|Existing translations|
|Unsolicited inbound|Not normally supported|Not normally supported|
|Cisco keyword|`pool`|`overload`|

### Key distinction

```text
Dynamic NAT:

10.0.0.5  → 203.0.113.5


PAT:

10.0.0.5:12345 → 203.0.113.1:23456
```

---

## 8. PAT and Inbound Traffic

PAT does **not** normally provide unsolicited inbound access to an inside host.

For example:

```text
Internet
   │
   │ unsolicited connection
   ▼
203.0.113.1:443
```

There is no existing PAT translation telling the router which inside host should receive the connection.

### Static PAT / Port Forwarding

A static PAT entry can create a predictable inbound mapping:

```cisco
ip nat inside source static tcp 10.0.0.10 8080 interface GigabitEthernet0/1 80
```

This creates a mapping similar to:

```text
203.0.113.1:80
       ↕
10.0.0.10:8080
```

Therefore, an Internet client connecting to:

```text
203.0.113.1:80
```

can be translated to:

```text
10.0.0.10:8080
```

> **Important:** PAT return traffic for an existing outbound translation is allowed. The limitation applies to **unsolicited inbound connections** without an appropriate static mapping.

---

## 9. Static NAT vs Static PAT

### Static NAT

```text
10.0.0.10
    ↕
203.0.113.10
```

The entire IP address is mapped.

### Static PAT

```text
10.0.0.10:8080
      ↕
203.0.113.1:80
```

Only a specific Layer-4 port is mapped.

Static PAT is commonly used when multiple internal services must share one public IP:

```text
203.0.113.1:80   → 10.0.0.10:80
203.0.113.1:443  → 10.0.0.20:443
203.0.113.1:25   → 10.0.0.30:25
```

---

## 10. PAT Port Allocation

A public IP address has a finite Layer-4 port space.

For TCP and UDP:

```text
0–65535
```

However, not all values are necessarily available for PAT because some ports may be reserved, restricted, or already in use.

Also:

- TCP and UDP have separate port spaces.
    
- NAT implementations may impose additional limits.
    
- The practical number of simultaneous translations depends on the platform and configuration.
    
- PAT capacity should therefore **not** be reduced to simply saying "64,000 sessions per IP."
    

> **Exam concept:** PAT dramatically increases scalability compared with one-to-one dynamic NAT, but it is still constrained by available translation resources.

---

## 11. PAT Translation Table

Example:

```text
Pro Inside global      Inside local       Outside local       Outside global
tcp 203.0.113.1:23456  10.0.0.5:12345    198.51.100.10:443   198.51.100.10:443
tcp 203.0.113.1:23457  10.0.0.6:12345    198.51.100.10:443   198.51.100.10:443
```

Notice that two inside hosts can use the same source port:

```text
10.0.0.5:12345
10.0.0.6:12345
```

The router can distinguish them using different translated mappings:

```text
203.0.113.1:23456
203.0.113.1:23457
```

## 13. Troubleshooting

|Symptom|Possible Cause|Check|
|---|---|---|
|No translation created|ACL does not match inside source|`show access-lists`|
|No translation created|NAT interfaces incorrectly configured|`show ip nat statistics`|
|No Internet access|Missing/incorrect default route|`show ip route`|
|PAT appears not to work|Incorrect NAT rule|`show running-config \| include ip nat`|
|Return traffic fails|Translation not created or routing issue|`show ip nat translations`|
|Inbound connection fails|No static PAT/NAT mapping|Check static NAT configuration|
|PAT resource exhaustion|Too many simultaneous translations|NAT translations/statistics|
|FTP-related problems|FTP connection handling / NAT inspection issue|Verify FTP mode and NAT behavior|
|VPN problems|Some VPN protocols/traffic are not compatible with traditional NAT|Verify NAT traversal/design|
|Wrong addresses translated|ACL matches unintended sources|`show access-lists`|

## 14. PAT Troubleshooting Workflow

Use a structured approach:

### Step 1 — Verify interfaces

```cisco
show ip interface brief
```

Confirm:

```text
Inside interface → ip nat inside
Outside interface → ip nat outside
```

### Step 2 — Verify the NAT configuration

```cisco
show running-config | include ip nat
```

### Step 3 — Verify the ACL

```cisco
show access-lists
```

Make sure the ACL matches the intended inside-local addresses.

### Step 4 — Verify routing

```cisco
show ip route
```

The router must know how to reach the outside network.

### Step 5 — Generate traffic

From an inside host:

```text
ping <destination>
```

or generate TCP/UDP traffic.

### Step 6 — Check translations

```cisco
show ip nat translations
```

### Step 7 — Check statistics

```cisco
show ip nat statistics
```

### Step 8 — Use debugging only when necessary

```cisco
debug ip nat
```

Then disable it:

```cisco
undebug all
```

## 15. Common CCNP Exam Traps

### Trap 1 — PAT requires `overload`

```cisco
ip nat inside source list 1 interface GigabitEthernet0/1 overload
```

The keyword:

```text
overload
```

enables PAT behavior.

---

### Trap 2 — Interface overload uses the interface IP

```cisco
ip nat inside source list 1 interface Gi0/1 overload
```

The public/inside-global address is taken from the specified interface.

---

### Trap 3 — PAT does not automatically publish inside servers

PAT allows return traffic for existing translations, but unsolicited inbound connections require an appropriate static NAT/static PAT mapping.

---

### Trap 4 — PAT is not limited to TCP

PAT can operate with TCP and UDP and can also handle protocols such as ICMP using protocol-specific identifiers.

---

### Trap 5 — Port translation is not necessarily visible as a changed port

The router may preserve the original source port when possible.

Therefore:

```text
PAT ≠ "the router must always change the port number"
```

Instead:

```text
PAT = using Layer-4 identifiers to allow multiple translations
```

---

### Trap 6 — Dynamic NAT and PAT are different

```text
Dynamic NAT:
10.0.0.5 → 203.0.113.5

PAT:
10.0.0.5:12345 → 203.0.113.1:23456
```

Dynamic NAT primarily consumes public **IP addresses**.

PAT allows multiple hosts to share public IP addresses by using Layer-4 information.

## 18. One-Minute Mental Model

```text
                 INSIDE
                   │
        10.0.0.5:12345
        10.0.0.6:12345
        10.0.0.7:54321
                   │
                   ▼
             ┌───────────┐
             │ NAT/PAT   │
             │  Router   │
             └─────┬─────┘
                   │
                   │
        203.0.113.1:20001
        203.0.113.1:20002
        203.0.113.1:54321
                   │
                   ▼
                INTERNET
```

**Remember:**

> **Dynamic NAT = address translation.**  
> **PAT = address translation + Layer-4 flow identification.**  
> **`overload` = Cisco command keyword for PAT.**  
> **Existing outbound translations allow return traffic.**  
> **Unsolicited inbound access requires static NAT/static PAT.**
