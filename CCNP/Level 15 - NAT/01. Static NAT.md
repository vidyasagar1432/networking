# Static NAT

> **Level 15 · NAT** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Static NAT** creates a **permanent one-to-one mapping** between an inside local address and an inside global address.

```text
Inside Local                 Inside Global
10.0.0.10        <------>    203.0.113.10
(private IP)                 (public/global IP)
```

This allows an inside host, such as a server, to have a predictable address representation on the outside network.

Static NAT is **bidirectional**:

- Inside → Outside: `10.0.0.10` is translated to `203.0.113.10`
    
- Outside → Inside: traffic destined for `203.0.113.10` is translated to `10.0.0.10`
    

The static mapping exists even when there is no active traffic.

### Important

Static NAT does **not** automatically make a server reachable.

Inbound connectivity still requires:

1. The NAT router to have a route to the inside host.
    
2. The outside network to be able to reach the inside-global address.
    
3. The server to have a valid return path, normally through the NAT router.
    
4. Appropriate ACL/firewall/security policies to permit the traffic.
    

> **NAT changes addresses; NAT does not repair routing or override security policy.**

# 2. Core Concepts

## 2.1 NAT Terminology

Cisco NAT uses four address terms:

|Term|Meaning|
|---|---|
|**Inside Local**|Address assigned to the inside host, as represented on the inside/local network|
|**Inside Global**|Address that represents the inside host to the outside network|
|**Outside Global**|Address assigned to the outside host by its owner, as represented on the outside|
|**Outside Local**|Address that represents the outside host from the inside network's perspective|

### Mental Model

- **Inside / Outside** identifies which side of the NAT boundary the host belongs to.
    
- **Local / Global** describes how that address is represented in the NAT context.
    

For a normal Internet NAT configuration where the outside host is not translated:

```text
Outside Local = Outside Global
```

### Example

PC1:

```text
Inside Local:  10.0.0.10
Inside Global: 203.0.113.10
```

Remote server:

```text
Outside Local: 198.51.100.7
Outside Global: 198.51.100.7
```

|Address|Value|Represents|
|---|---|---|
|Inside Local|`10.0.0.10`|Inside host's internal address|
|Inside Global|`203.0.113.10`|Inside host's externally represented address|
|Outside Local|`198.51.100.7`|Outside host as represented from inside|
|Outside Global|`198.51.100.7`|Outside host's actual/global address|

---

## 2.2 Static NAT One-to-One Behavior

Configuration:

```cisco
ip nat inside source static 10.0.0.10 203.0.113.10
```

### Outbound

```text
Source:
10.0.0.10 → 203.0.113.10

Destination:
198.51.100.7
```

The source address is translated:

```text
10.0.0.10 → 203.0.113.10
```

### Inbound

```text
Source:
198.51.100.7

Destination:
203.0.113.10
```

The destination is translated:

```text
203.0.113.10 → 10.0.0.10
```

The mapping is permanent and can support connections initiated from either direction, provided routing and security policies allow the traffic.

### Important

Network-level static NAT translates the **IP address**. It does not inherently translate TCP/UDP ports.

For example:

```text
10.0.0.10:443
        ↓
203.0.113.10:443
```

The port remains `443`.

# 3. NAT Inside/Outside Boundary

The router needs to know which interfaces belong to the inside and outside of the NAT domain.

```cisco
interface GigabitEthernet0/0
 ip nat inside

interface GigabitEthernet0/1
 ip nat outside
```

These commands define the NAT boundary.

Typical topology:

```text
        Inside Network                    Outside Network
              
      10.0.0.0/24
           |
         Server
      10.0.0.10
           |
       Gi0/0
     ip nat inside
          R1
       Gi0/1
     ip nat outside
           |
       Internet
```

NAT processing depends on traffic crossing an interface configured as `ip nat inside` and an interface configured as `ip nat outside`.

# 4. Static NAT Configuration

## 4.1 Basic Static NAT

```cisco
ip nat inside source static 10.0.0.10 203.0.113.10
```

Interface configuration:

```cisco
interface GigabitEthernet0/0
 ip address 10.0.0.1 255.255.255.0
 ip nat inside

interface GigabitEthernet0/1
 ip address 203.0.113.1 255.255.255.0
 ip nat outside
```

The resulting mapping is:

```text
10.0.0.10 ↔ 203.0.113.10
```

Remove it with:

```cisco
no ip nat inside source static 10.0.0.10 203.0.113.10
```

---

## 4.2 Does Static NAT Require an ACL?

**No.**

The static mapping itself does not require an ACL to define which inside address is translated.

For example:

```cisco
ip nat inside source static 10.0.0.10 203.0.113.10
```

is sufficient to create the mapping.

However:

> **ACLs can still be used independently to permit or deny traffic.**

ACLs are commonly used with dynamic NAT/PAT to classify which inside traffic should be translated, but an ACL is not required merely to create a static NAT mapping.

# 5. Routing Requirements

Static NAT does not replace routing.

For inbound connectivity, verify:

### 1. NAT router knows the inside network

```cisco
show ip route
```

Example:

```text
C 10.0.0.0/24 is directly connected
```

### 2. Server has a return path

Normally:

```text
Server default gateway = 10.0.0.1
```

where `10.0.0.1` is the NAT router's inside address.

### 3. Outside network can reach the inside-global address

Example:

```text
203.0.113.10
```

must be reachable from the outside network.

### 4. Security policy permits the traffic

Check ACLs/firewalls:

```cisco
show access-lists
```

### Key troubleshooting principle

```text
NAT translation exists
        ↓
Does the router know where to send the translated packet?
        ↓
Does the server know where to send the reply?
        ↓
Are ACL/firewall policies permitting the traffic?
```

# 6. Static PAT / Port Forwarding

Static PAT maps a specific protocol and port instead of an entire IP address.

Example:

```cisco
ip nat inside source static tcp 10.0.0.10 80 203.0.113.10 8080
```

Mapping:

```text
203.0.113.10:8080
        ↓
10.0.0.10:80
```

An outside client connects to:

```text
203.0.113.10:8080
```

and the NAT router forwards it to:

```text
10.0.0.10:80
```

### Multiple Services Using One Public IP

For example:

```cisco
ip nat inside source static tcp 10.0.0.10 80 203.0.113.10 8080
ip nat inside source static tcp 10.0.0.20 443 203.0.113.10 8443
```

Result:

```text
203.0.113.10:8080 → 10.0.0.10:80
203.0.113.10:8443 → 10.0.0.20:443
```

This allows multiple internal services to share one global IP by using different ports.

### Static NAT vs Static PAT

|Feature|Static NAT|Static PAT|
|---|---|---|
|Mapping|Entire IP address|Specific protocol/port|
|Example|`10.0.0.10 ↔ 203.0.113.10`|`10.0.0.10:80 ↔ 203.0.113.10:8080`|
|Ports|Not changed by the address mapping|Explicitly mapped|
|Inbound access|Address-level mapping|Only mapped service/port|
|Typical use|Public-facing server|Port forwarding|

---

# 7. Static NAT vs Dynamic NAT vs PAT

|Type|Mapping|Inbound initiation|
|---|---|---|
|**Static NAT**|Fixed 1:1|Yes, predictable mapping|
|**Dynamic NAT**|Inside local ↔ temporary pool address|Not normally available before a translation exists|
|**PAT**|Many inside hosts ↔ shared global address/ports|Requires an existing translation or explicit static PAT|
|**Static PAT**|Fixed protocol/port mapping|Yes, for the mapped service|

### Exam Point

Static NAT and static PAT create **predictable mappings that can support externally initiated traffic**.

Do not memorize the oversimplification:

> “Static NAT is the only NAT that allows inbound traffic.”

Instead remember:

> **Externally initiated traffic requires a predictable translation/mapping and appropriate routing/security.**

# 8. NAT Translation Table

Verify translations with:

```cisco
show ip nat translations
```

Example:

```text
Pro Inside global      Inside local       Outside local      Outside global
--- 203.0.113.10       10.0.0.10          ---                ---
```

For a port-based translation:

```text
Pro Inside global       Inside local      Outside local  Outside global
tcp 203.0.113.10:8080   10.0.0.10:80      ---            ---
```

A static address translation can appear in the table even when there is no active session.

# 10. Clearing NAT Translations

```cisco
clear ip nat translation *
```

This clears **dynamic/active translation entries**, but it does **not remove configured static NAT mappings**.

To remove a static mapping:

```cisco
no ip nat inside source static 10.0.0.10 203.0.113.10
```

### Exam Trap

```text
clear ip nat translation *
        ≠
remove static NAT configuration
```

# 11. Troubleshooting

|Symptom|Possible Cause|Check|Fix|
|---|---|---|---|
|No translation|NAT interfaces not configured|`show running-config`|Add `ip nat inside/outside`|
|Static mapping missing|Static NAT command incorrect/missing|`show running-config \| section ip nat`|Correct configuration|
|Inbound traffic fails|No route to inside network|`show ip route`|Add/fix route|
|Server receives packet but reply fails|Incorrect server gateway/return route|Server routing|Fix default gateway/route|
|Inbound traffic fails|Traffic entering wrong interface|Interface configuration|Mark correct outside interface|
|NAT exists but application fails|ACL/firewall blocks traffic|`show access-lists`|Permit required traffic|
|Static PAT fails|Wrong protocol/port|`show ip nat translations`|Correct port mapping|
|Port conflict|Same global address/port already used|NAT configuration/table|Use another global port|
|Old static mapping remains|`clear ip nat translation *` was used|`show ip nat translations`|Remove with `no ip nat ... static`|
|Public IP reachable but service fails|Service not listening / wrong port|Server/application|Fix service or mapping|

# 12. Troubleshooting Workflow

When static NAT is not working, use this order:

```text
1. Check physical/interface status
        ↓
2. Verify ip nat inside / ip nat outside
        ↓
3. Verify static NAT configuration
        ↓
4. Check routing to the inside host
        ↓
5. Check server default gateway/return route
        ↓
6. Check ACL/firewall policies
        ↓
7. Check NAT translation table
        ↓
8. Test the actual application/port
        ↓
9. Use debugging only when necessary
```

Useful commands:

```cisco
show ip interface brief
show ip route
show ip nat translations
show ip nat statistics
show access-lists
show running-config | section ip nat
```

# 14. NAT and ACL Interaction

Static NAT itself does not require an ACL.

However, NAT and security filtering are separate functions.

Example:

```text
Internet
   |
   | 203.0.113.10:443
   ↓
NAT Router
   |
   | translated to 10.0.0.10:443
   ↓
Server
```

Even if NAT translates the packet correctly, an ACL can still deny it.

Therefore:

> **NAT answers “what address should this packet use?”**

while:

> **ACLs/firewalls answer “is this traffic permitted?”**

Do not confuse NAT with security.

---

# 15. NAT and Routing Interaction

NAT and routing perform different jobs.

```text
NAT:
Changes the address representation.

Routing:
Determines where the packet should go.
```

For inbound traffic:

```text
Outside client
      |
      ↓
203.0.113.10
      |
      ↓
NAT translation
      |
      ↓
10.0.0.10
      |
      ↓
Routing decision
      |
      ↓
Inside server
```

The NAT router must still know how to reach `10.0.0.10`.

Likewise, the server must know how to return traffic toward the NAT router.

# 16. NAT and DNS

NAT and DNS can interact in scenarios where internal hosts access services using names that resolve to translated addresses.

Cisco platforms may provide DNS-related NAT/ALG functionality depending on the IOS/IOS XE release, platform, and configuration.

Do **not** assume that every Cisco NAT deployment automatically rewrites DNS responses.

For enterprise designs, **split-horizon DNS** is often used when internal clients should receive an internal address while external clients receive a public address.

Example:

```text
Internal DNS:
server.example.com → 10.0.0.10

External DNS:
server.example.com → 203.0.113.10
```

This avoids depending on NAT hairpin/U-turn behavior for internal clients.

---

# 17. NAT Hairpinning / U-Turn NAT

Hairpin NAT occurs when an inside host accesses another inside host using that host's **inside-global/public address**.

Example:

```text
PC1
10.0.0.20
   |
   | connects to
   ↓
203.0.113.10
   |
   ↓
10.0.0.10
Server
```

This is sometimes called:

- Hairpin NAT
    
- NAT loopback
    
- U-turn NAT
    

Support and behavior can vary by platform, IOS/IOS XE release, and configuration.

For production designs, **split-horizon DNS** is often preferred when internal clients can use the internal address directly.

> **CCNP lab rule:** If your lab depends on hairpin NAT, verify the behavior on the exact IOS/IOS XE image being used.

# 18. Static NAT and `extendable`

Example:

```cisco
ip nat inside source static 10.0.0.10 203.0.113.10 extendable
```

The `extendable` keyword allows Cisco IOS to distinguish otherwise conflicting static translations by making the translation entry more specific.

It is particularly relevant when multiple static translations could otherwise conflict on the same global address, such as mappings involving different protocols or ports.

Do not think of `extendable` simply as:

> “Static NAT becomes PAT.”

That is misleading.

Instead:

> **`extendable` allows additional static translation entries to coexist when the complete translation tuple can distinguish them.**

# 19. `inside source` vs `outside source`

A very important CCNP concept is that Cisco NAT has different source-translation directions.

### Inside Source

```cisco
ip nat inside source static 10.0.0.10 203.0.113.10
```

This is the normal configuration for translating an **inside host's address**.

Conceptually:

```text
Inside Local
    ↓
Inside Global
```

### Outside Source

```cisco
ip nat outside source static ...
```

This is used when the **outside host's address** needs to be translated.

It can be useful in situations such as:

- Overlapping address spaces
    
- Translating external addresses into an internal representation
    

### Exam Trap

Do not interpret:

```text
inside source
```

as simply meaning:

> “traffic coming from inside.”

It identifies the **NAT address being translated**.

---

# 20. Security Considerations

Static NAT is **not a security feature**.

Creating:

```cisco
ip nat inside source static 10.0.0.10 203.0.113.10
```

does not automatically mean the server is protected.

With network-level static NAT, the global address can represent the inside host for many types of traffic, subject to:

- ACLs
    
- Firewall policies
    
- Interface access rules
    
- Application behavior
    
- Routing
    
- Protocol support
    

For a public server, explicitly control which services should be reachable.

For example, if only HTTPS should be exposed, use appropriate security controls rather than relying on NAT itself.

# 22. Common Exam Traps

### Trap 1 — Static NAT is not dynamic NAT

Static NAT:

```text
Fixed mapping
```

Dynamic NAT:

```text
Temporary mapping from a pool
```

---

### Trap 2 — Static NAT mappings do not time out

The configured mapping remains until the configuration is removed.

```cisco
no ip nat inside source static 10.0.0.10 203.0.113.10
```

---

### Trap 3 — `clear ip nat translation *` does not remove static configuration

```cisco
clear ip nat translation *
```

does not replace:

```cisco
no ip nat inside source static ...
```

---

### Trap 4 — NAT is not a firewall

A NAT mapping does not replace ACLs or firewall policies.

---

### Trap 5 — NAT does not fix routing

If the NAT router cannot route to the inside server, translation alone cannot make the connection work.

---

### Trap 6 — The server needs a return path

If the server sends replies through another router instead of the NAT router, reverse NAT may never occur correctly.

---

### Trap 7 — Static NAT and Static PAT are different

```text
Static NAT:
10.0.0.10 ↔ 203.0.113.10

Static PAT:
10.0.0.10:80 ↔ 203.0.113.10:8080
```

---

### Trap 8 — Interface roles matter

You normally need:

```cisco
ip nat inside
```

and:

```cisco
ip nat outside
```

on the appropriate interfaces.

---

### Trap 9 — `inside source` does not mean simply “inside traffic”

It identifies the source address/host that NAT is translating.

---

### Trap 10 — DNS behavior is not universal

Do not assume every Cisco NAT configuration automatically rewrites DNS responses. DNS behavior depends on platform, software, and configuration.

# 23. Complete Example

## Topology

```text
                Internet
                    |
             198.51.100.1
                    |
                 Gi0/1
                R1-NAT
                 Gi0/0
              10.0.0.1/24
                    |
              10.0.0.10
               Web Server
```

Required public address:

```text
203.0.113.10
```

### Configuration

```cisco
R1(config)# ip nat inside source static 10.0.0.10 203.0.113.10

R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip address 10.0.0.1 255.255.255.0
R1(config-if)# ip nat inside
R1(config-if)# no shutdown

R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip address 198.51.100.1 255.255.255.0
R1(config-if)# ip nat outside
R1(config-if)# no shutdown
```

Server:

```text
IP address:       10.0.0.10
Subnet mask:      255.255.255.0
Default gateway:  10.0.0.1
```

### Result

Inside:

```text
10.0.0.10
```

Outside representation:

```text
203.0.113.10
```

Inbound:

```text
Client
  |
  | Destination 203.0.113.10
  ↓
R1
  |
  | Destination translated to 10.0.0.10
  ↓
Server
```

Outbound:

```text
Server
  |
  | Source 10.0.0.10
  ↓
R1
  |
  | Source translated to 203.0.113.10
  ↓
Internet
```

# 26. CCNP Mental Model

Remember Static NAT as:

```text
STATIC NAT
│
├── Fixed 1:1 mapping
│     └── Inside Local ↔ Inside Global
│
├── Permanent configuration
│     └── Does not behave like a dynamic pool entry
│
├── Bidirectional
│     ├── Inside → Outside
│     └── Outside → Inside
│
├── Requires NAT boundary
│     ├── ip nat inside
│     └── ip nat outside
│
├── Does NOT replace routing
│     ├── Route to server
│     └── Return route from server
│
├── Does NOT replace security
│     └── ACL/firewall can still deny traffic
│
├── Static PAT
│     └── Protocol + port mapping
│
└── Verification
      ├── show ip nat translations
      └── show ip nat statistics
```

> **Exam takeaway:**  
> **Static NAT = permanent, predictable 1:1 address mapping.**  
> **Static PAT = permanent, predictable protocol/port mapping.**  
> **NAT translates addresses; routing determines where packets go; ACLs/firewalls determine whether traffic is permitted.**
