# Dynamic NAT

> **Level 15 · NAT** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Dynamic NAT** creates **temporary one-to-one mappings** between inside local addresses and addresses from a configured NAT pool.

Unlike Static NAT, the mapping is created **when eligible traffic requires translation** and is removed when the translation ages out.

```text
Inside Local                 Inside Global
10.0.0.10        <------>    203.0.113.10
10.0.0.11        <------>    203.0.113.11
```

The mapping is normally **1:1**:

- One inside host consumes one pool address while it has an active translation.
    
- Multiple inside hosts can use the pool at different times.
    
- The pool address is returned to the pool when the translation expires.
    
- Dynamic NAT **does not translate TCP/UDP ports**.
    

### Important

Dynamic NAT is primarily designed for **inside-initiated connections**.

An outside host cannot normally initiate a new connection to an inside host through a dynamic NAT mapping because there is no permanent mapping telling NAT which inside host should receive the traffic.

> **Dynamic NAT provides temporary address mappings; it does not provide a permanent public address for an inside host.**

---

# 2. Core Concepts

## 2.1 How Dynamic NAT Works

Assume:

```text
Inside Network:
10.0.0.0/24

NAT Pool:
203.0.113.10 – 203.0.113.20
```

PC1:

```text
10.0.0.10
```

When PC1 starts an outbound connection:

```text
PC1
10.0.0.10
   |
   ↓
NAT Router
   |
   | Allocates 203.0.113.10
   ↓
Internet
```

The router creates:

```text
10.0.0.10 ↔ 203.0.113.10
```

The translation remains active while the corresponding NAT translation is active.

When the translation ages out:

```text
203.0.113.10
      ↓
returned to pool
```

Another inside host can then use that address.

---

## 2.2 Dynamic NAT Is One-to-One

Without `overload`, Dynamic NAT does **not** allow multiple inside hosts to simultaneously share one global address.

Example:

```text
10.0.0.10 ↔ 203.0.113.10
10.0.0.11 ↔ 203.0.113.11
10.0.0.12 ↔ 203.0.113.12
```

Each active inside host requires a separate pool address.

### Important

Dynamic NAT is therefore:

```text
Many inside hosts
        ↓
Many public addresses
```

It is **not**:

```text
Many inside hosts
        ↓
One public address
```

That is PAT.

ip nat inside source list 10 pool PUBLIC

```cisco

interface GigabitEthernet0/1

```

```text

NAT Rule
 ↓

```

# 4. ACL Role in Dynamic NAT

The ACL identifies which traffic is eligible to use the NAT pool.

Example:

```cisco
access-list 10 permit 10.0.0.0 0.0.0.255
```

This permits addresses in:

```text
10.0.0.0/24
```

to be considered for translation.

The ACL is used for **NAT classification** in this configuration.

### Important

The ACL does not necessarily mean:

> "These packets are allowed through the router."

It identifies traffic that should be considered for NAT.

Security filtering is a separate function.

For example:

```text
ACL used by NAT
        ≠
Security ACL used to permit/deny traffic
```

The same ACL mechanism can be used in different contexts, but the purpose of the ACL depends on how it is applied.

---

# 5. NAT Pool

Example:

```cisco
ip nat pool PUBLIC 203.0.113.10 203.0.113.20 netmask 255.255.255.0
```

The pool contains:

```text
203.0.113.10
203.0.113.11
203.0.113.12
...
203.0.113.20
```

The router dynamically allocates available addresses from this pool.

### Pool Capacity

This pool contains:

```text
11 addresses
```

Therefore, without overload, approximately 11 simultaneous address translations can consume the pool.

If all usable pool addresses are occupied, additional inside hosts cannot obtain an address from that pool.

---

# 6. Pool Exhaustion

When no pool addresses are available:

```text
Inside host
     |
     ↓
NAT lookup
     |
     ↓
No free pool address
     |
     ↓
Translation cannot be created
```

The traffic requiring a new translation cannot be translated using that pool.

### Important

Dynamic NAT does **not automatically fall back to PAT**.

To allow many inside hosts to share a smaller number of global addresses, configure PAT explicitly:

```cisco
ip nat inside source list 10 pool PUBLIC overload
```

or use an interface-based PAT configuration.

> **No `overload` = one inside host per pool address.**

---

# 7. Dynamic NAT vs PAT

## Dynamic NAT

```text
10.0.0.10 → 203.0.113.10
10.0.0.11 → 203.0.113.11
```

Each inside host consumes a separate global address.

## PAT

```text
10.0.0.10:50001 → 203.0.113.10:50001
10.0.0.11:50002 → 203.0.113.10:50002
10.0.0.12:50003 → 203.0.113.10:50003
```

Multiple inside hosts can share the same global address by using different transport-layer identifiers, primarily TCP/UDP ports.

### Exam Point

```text
Dynamic NAT
= address translation
= 1:1 while active
= pool required

PAT
= address + port translation
= many:1 possible
= port information distinguishes translations
```

# 8. `overload`

Adding `overload` changes the behavior from ordinary pool-based Dynamic NAT to **PAT using the pool addresses**.

Example:

```cisco
ip nat inside source list 10 pool PUBLIC overload
```

Without `overload`:

```text
10.0.0.10 → 203.0.113.10
10.0.0.11 → 203.0.113.11
```

With `overload`:

```text
10.0.0.10:50001 → 203.0.113.10:50001
10.0.0.11:50002 → 203.0.113.10:50002
```

The global address can therefore be reused for multiple simultaneous translations.

> **Exam trap:** `overload` is the keyword that enables PAT behavior.

---

# 9. Dynamic NAT and Inbound Traffic

Dynamic NAT does not create a permanent mapping.

Example:

```text
10.0.0.10 ↔ 203.0.113.10
```

may exist while the inside host has an active translation.

An outside host cannot normally decide:

```text
203.0.113.10 → 10.0.0.10
```

when no translation exists.

Why?

Because the pool address is not permanently assigned to that inside host.

After the mapping expires:

```text
203.0.113.10
```

could later be allocated to another inside host.

### Therefore

```text
Dynamic NAT
        ↓
Inside-initiated translation
        ↓
Temporary mapping
        ↓
No predictable inbound mapping when idle
```

For predictable inbound access, use mechanisms such as:

- Static NAT
    
- Static PAT / port forwarding

# 10. Dynamic NAT Translation Lifecycle

```text
Inside host generates eligible traffic
             ↓
        ACL matches
             ↓
       NAT pool checked
             ↓
     Free address available?
        /             \
      Yes              No
       ↓                ↓
Allocate address      Translation
       ↓              cannot be created
Create translation
       ↓
Traffic translated
       ↓
Translation remains active
       ↓
Ages out according to NAT timers
       ↓
Pool address becomes available
```

# 11. NAT Timers

Dynamic NAT translations are temporary and are subject to NAT aging timers.

Common IOS defaults include:

|Timer|Typical Default|
|---|--:|
|General NAT translation timeout|24 hours|
|TCP translation timeout|24 hours|
|UDP translation timeout|5 minutes|

Check the actual configured values on the device:

```cisco
show running-config | include ip nat translation
```

You can configure the general translation timeout with:

```cisco
ip nat translation timeout <seconds>
```

Protocol-specific timers can also be configured where supported.

### Important

Do not memorize the timer values as universal constants for every IOS/IOS XE platform.

For CCNP, understand the concept:

> **Dynamic translations are temporary and age out according to NAT timers.**

# 13. Clearing Dynamic Translations

```cisco
clear ip nat translation *
```

This can clear active dynamic translation entries.

After clearing:

```text
Inside host
    ↓
Starts traffic again
    ↓
New dynamic translation
    ↓
New pool address may be allocated
```

Unlike static NAT, there is no permanent static mapping to preserve.

# 14. Troubleshooting

|Symptom|Possible Cause|Check|Fix|
|---|---|---|---|
|No translation|NAT ACL does not match|`show access-lists`|Correct ACL|
|No translation|NAT rule missing|`show running-config \| section ip nat`|Configure NAT rule|
|No translation|Inside/outside roles incorrect|Interface configuration|Correct `ip nat inside/outside`|
|Outbound traffic fails|Pool exhausted|`show ip nat statistics`|Increase pool or use PAT|
|Unexpected hosts translated|ACL too broad|NAT ACL|Restrict ACL|
|Expected hosts not translated|ACL too narrow|NAT ACL|Permit required addresses|
|Inbound connection fails|No permanent mapping|NAT design|Use Static NAT/PAT if required|
|Translation disappears|NAT timer expired|NAT timer configuration|Adjust timer if appropriate|
|Multiple hosts cannot share one global IP|`overload` not configured|NAT configuration|Use PAT|
|Pool addresses appear unavailable|Existing translations consume them|`show ip nat translations`|Wait for expiry or clear translations|
|NAT works but traffic fails|Routing/ACL/firewall issue|`show ip route`, ACLs|Correct routing/security|

# 17. Dynamic NAT vs Static NAT

|Aspect|Static NAT|Dynamic NAT|
|---|---|---|
|Mapping|Fixed|Temporary|
|Mapping creation|Configuration|Traffic-triggered|
|Global address|Permanently associated|Allocated from pool|
|Pool|Not required|Required|
|Address relationship|1:1|1:1 while active|
|Inbound initiation|Predictable|No permanent mapping|
|Timeout|No dynamic aging|Yes|
|Port translation|No|No|
|Public IP reuse|No|Yes, after release|
|ACL for classification|Not required|Commonly required|
|Pool exhaustion|Not applicable|New translations fail|
|`overload`|Not used for basic static NAT|Converts pool-based rule to PAT behavior|

# 18. Dynamic NAT vs PAT

|Feature|Dynamic NAT|PAT|
|---|---|---|
|Public addresses|Multiple pool addresses|One or more global addresses|
|Mapping|1:1|Many:1 possible|
|Ports translated|No|Yes|
|Pool|Required|Optional depending on configuration|
|Address reuse|After translation expires|Simultaneous reuse|
|Scalability|Limited by pool size|Very high|
|Typical use|Organizations with sufficient public addresses|Internet access with limited public addresses|

# 19. NAT Pool Keywords

## `netmask`

Example:

```cisco
ip nat pool PUBLIC 203.0.113.10 203.0.113.20 netmask 255.255.255.0
```

Defines the network mask associated with the pool addresses.

---

## `overload`

Example:

```cisco
ip nat inside source list 10 pool PUBLIC overload
```

Enables PAT behavior so multiple translations can share pool addresses.

---

## `type rotary`

`type rotary` is associated with **rotary NAT**, which is a specialized NAT behavior used for distributing connections among a group of inside addresses.

Do not memorize it as:

> “Dynamic NAT load balancing.”

It is specifically associated with **rotary address translation**, not ordinary Dynamic NAT operation.

---

## `add-route`

Do not treat `add-route` as a normal IOS/IOS XE Dynamic NAT pool requirement.

The availability and behavior of NAT pool route-installation keywords are **platform/software dependent**.

For standard CCNP Enterprise Dynamic NAT, focus on:

```cisco
ip nat pool
ip nat inside source list ... pool ...
```

and understand `overload` for PAT.

---

# 20. NAT and Routing Interaction

Dynamic NAT does not replace routing.

For outbound traffic:

```text
Inside Host
    |
    ↓
NAT Router
    |
    | Translation
    ↓
Routing decision
    |
    ↓
Outside Network
```

The router still needs a valid route toward the destination.

Example:

```cisco
show ip route
```

A default route is commonly required on an Internet edge router:

```cisco
ip route 0.0.0.0 0.0.0.0 <next-hop>
```

### Important

If NAT creates a translation but the router has no route toward the destination, NAT does not fix the routing problem.

---

# 21. NAT and ACL Interaction

Dynamic NAT commonly uses an ACL to identify which source addresses should be translated.

Example:

```cisco
access-list 10 permit 10.0.0.0 0.0.0.255
```

This means:

```text
10.0.0.0/24
       ↓
Eligible for NAT
```

It does **not** automatically mean:

```text
10.0.0.0/24
       ↓
All traffic is permitted
```

NAT classification and security filtering are separate concepts.

# 22. Pool Exhaustion Example

Pool:

```text
203.0.113.10 – 203.0.113.12
```

Only three addresses are available.

Three hosts:

```text
10.0.0.10 → 203.0.113.10
10.0.0.11 → 203.0.113.11
10.0.0.12 → 203.0.113.12
```

Now:

```text
10.0.0.13
```

attempts an outbound connection.

No pool address is available.

Therefore:

```text
New translation
      ↓
No free global address
      ↓
Translation cannot be created
```

The solution could be:

- Increase the NAT pool
    
- Reduce unnecessary translation lifetime where appropriate
    
- Use PAT/overload

# 23. Important Exam Traps

### Trap 1 — Dynamic NAT is not PAT

Dynamic NAT:

```text
10.0.0.10 → 203.0.113.10
```

PAT:

```text
10.0.0.10:50001 → 203.0.113.10:50001
```

---

### Trap 2 — Dynamic NAT requires a pool

Basic Dynamic NAT uses:

```cisco
ip nat pool ...
```

PAT can instead use the outside interface address or a pool with `overload`.

---

### Trap 3 — No `overload` means no address sharing

```cisco
ip nat inside source list 10 pool PUBLIC
```

means one active inside-local-to-inside-global mapping per pool address.

Adding:

```cisco
overload
```

enables PAT behavior.

---

### Trap 4 — Pool exhaustion does not automatically become PAT

If the pool is full:

```text
No free address
      ↓
New translation cannot be created
```

The router does not automatically use ports to share an address.

---

### Trap 5 — Dynamic mappings are temporary

They are created dynamically and removed according to NAT aging behavior.

---

### Trap 6 — `clear ip nat translation *`

This can remove active dynamic translations.

It does not remove the NAT configuration itself.

---

### Trap 7 — Dynamic NAT does not provide a permanent inbound address

An outside host cannot reliably initiate a new connection to an inside host using a dynamically allocated address when no translation exists.

Use Static NAT or Static PAT for predictable inbound services.

---

### Trap 8 — NAT ACL ≠ Security ACL

The ACL used by:

```cisco
ip nat inside source list 10 ...
```

classifies addresses/traffic for NAT.

It should not automatically be interpreted as a security policy.

---

### Trap 9 — NAT does not fix routing

Always verify:

```cisco
show ip route
```

# 24. Complete Example

## Topology

```text
                    Internet
                       |
                  Gi0/1
                   R1
                  NAT
                  Gi0/0
                    |
              10.0.0.0/24
             /      |      \
           PC1     PC2     PC3
        10.0.0.10  .11     .12
```

NAT pool:

```text
203.0.113.10 – 203.0.113.20
```

### Configuration

```cisco
R1(config)# access-list 10 permit 10.0.0.0 0.0.0.255

R1(config)# ip nat pool PUBLIC 203.0.113.10 203.0.113.20 netmask 255.255.255.0

R1(config)# ip nat inside source list 10 pool PUBLIC

R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip address 10.0.0.1 255.255.255.0
R1(config-if)# ip nat inside
R1(config-if)# no shutdown

R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip address 198.51.100.1 255.255.255.0
R1(config-if)# ip nat outside
R1(config-if)# no shutdown
```

When PC1 sends traffic:

```text
10.0.0.10
     ↓
ACL 10 matches
     ↓
Pool address allocated
     ↓
203.0.113.10
```

Translation:

```text
10.0.0.10 ↔ 203.0.113.10
```

When PC1's translation expires:

```text
203.0.113.10
       ↓
returned to pool
```

Another inside host can then receive that address.
