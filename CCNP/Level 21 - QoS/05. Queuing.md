# Queuing

> **Level 21 · QoS** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Queuing** decides the **order** packets leave an interface when it's congested. The
modern answer is **CBWFQ** (class-based weighted fair queuing) with **LLQ** (low
latency queuing) for delay-sensitive voice. The exam wants you to know which queuing
mechanism maps to which need — FIFO, WFQ, PQ, CBWFQ, LLQ.

---

## 2. Core Concepts

### 2.1 Queuing mechanisms

| Mechanism | Behavior | Use |
|-----------|----------|-----|
| FIFO | first in, first out | no QoS |
| WFQ | per-flow fair | default legacy |
| PQ | strict priority | critical only |
| CBWFQ | per-class weights | modern default |
| LLQ | priority + CBWFQ | voice |

- **CBWFQ** is the standard egress queuing; **LLQ** adds a strict priority class.

### 2.2 CBWFQ

| Concept | Detail |
|---------|--------|
| Class | class-map match |
| Bandwidth | `bandwidth` kbps share |
| Weight | proportional service |
| Tail-drop | per-queue |

- Each class gets a **guaranteed bandwidth share**.

### 2.3 LLQ (strict priority)

| Item | Detail |
|------|--------|
| Priority class | served first |
| Limit | policed (pq bandwidth) |
| Risk | starving others |
| Use | voice (EF) |

- LLQ = **priority queue + CBWFQ**; the priority class is rate-limited.

### 2.4 Queuing config

```text
policy-map QUEUE-EDGE
 class VOICE
  priority 128          ! LLQ
 class VIDEO
  bandwidth 1000
 class DATA
  bandwidth 2000
!
interface Gi0/1
 service-policy output QUEUE-EDGE
```

| Command | Meaning |
|---------|---------|
| `priority` | strict priority class |
| `bandwidth` | guaranteed share |
| `queue-limit` | per-class depth |
| `fair-queue` | per-flow inside class |

### 2.5 PQ vs CBWFQ vs WFQ

| Mechanism | Selection | Priority |
|-----------|-----------|----------|
| WFQ | per-flow | fairness |
| PQ | strict | starvation risk |
| CBWFQ | per-class | weighted |
| LLQ | priority+class | voice-safe |

- **PQ can starve** lower queues — that's why LLQ polices the priority class.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Voice jitter | no LLQ | priority class |
| Starvation | PQ too big | priority limit |
| No shares | bandwidth missing | policy-map |
| Wrong order | default FIFO | service-policy |
| Queue fill | tail drop | queue-limit |

---

## 5. Exam Traps

- **CBWFQ** = per-class bandwidth; **LLQ** = priority class + CBWFQ.
- LLQ's priority class must be **policed** to avoid starvation.
- **PQ = strict (can starve); WFQ = per-flow fairness**.
- Queuing is **egress** and only matters under congestion.
- `priority` vs `bandwidth` — know the difference.
