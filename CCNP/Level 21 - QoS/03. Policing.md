# Policing

> **Level 21 · QoS** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Policing** enforces a rate by **dropping (or re-marking) excess traffic** — it does
**not buffer**. It uses the **token bucket** model and works on **ingress or egress**.
Policing is burst-sensitive, doesn't add delay, and is often used to meter customer or
class rates.

---

## 2. Core Concepts

### 2.1 Policing vs shaping

| Aspect | Policing | Shaping |
|--------|----------|---------|
| Excess | drop/re-mark | buffer |
| Delay | none | adds delay |
| Location | ingress/egress | egress |
| Burst | drops | smooths |
| Use | meter/enforce | line rate smoothing |

- Policing **drops**; shaping **delays**.

### 2.2 Token bucket basics

| Token | Meaning |
|-------|---------|
| CIR | fill rate (bps) |
| Bc | committed burst |
| Be | excess burst |
| Conform | tokens available |
| Exceed | no tokens |

- Packets that **conform** pass; **exceed** get dropped/re-marked.

### 2.3 Actions

| Action | When |
|--------|------|
| transmit | conform |
| drop | violate |
| set dscp + transmit | re-mark exceed |

- **Re-mark and transmit** is gentler than dropping.

### 2.4 Policer config

```text
policy-map POLICE-DATA
 class BULK
  police cir 1000000 bc 200000 be 200000
   conform-action transmit
   exceed-action drop
   violate-action drop
!
interface Gi0/1
 service-policy input POLICE-DATA
```

| Command | Meaning |
|---------|---------|
| `police cir` | committed rate |
| `bc` / `be` | burst sizes |
| `conform/exceed/violate-action` | behavior |

### 2.5 Multi-action policing

| State | Token condition | Action |
|-------|-----------------|--------|
| conform | Bc available | transmit |
| exceed | Be available | re-mark |
| violate | none | drop |

- The **dual-bucket** model gives three outcomes.

### 2.6 Where policing is used

| Use | Reason |
|-----|--------|
| Customer rate limit | enforce SLA |
| Bandwidth control | meter classes |
| Mark-down | re-mark over rate |
| Ingress protection | stop floods |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Too much drop | burst too small | bc/be |
| No policing | service-policy | show policy-map interface |
| Re-mark not working | action | conform-action |
| Rate off | CIR wrong | cir |
| Asymmetric | direction | input/output |

---

## 5. Exam Traps

- Policing = **drop/re-mark**, no buffering.
- Works **ingress or egress**; shaping is egress-only.
- Token bucket: **CIR, Bc, Be**.
- Three actions: **conform / exceed / violate**.
- `service-policy input` for ingress.
