# Classification

> **Level 21 · QoS** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Classification** is the QoS act of **identifying which traffic gets which treatment**.
It groups packets based on fields like DSCP, IP precedence, 802.1p, ACLs, or application
signatures. Classification is always the **first step** — before marking, policing, or
queuing can do anything.

---

## 2. Core Concepts

### 2.1 What we classify on

| Field | Layer | Notes |
|-------|-------|-------|
| DSCP | L3 | 6 bits |
| IP precedence | L3 | 3 bits |
| 802.1p | L2 | CoS 3 bits |
| ACL | L3/4 | match IP/ports |
| NBAR | L7 | application |

- Deeper match = more accurate, more expensive.

### 2.2 Trust boundaries

| Point | Trust |
|-------|-------|
| Access edge | untrusted (re-mark) |
| Core | trusted (keep DSCP) |
| Ingress switch | classify/mark |
| e.g., camera ports | set CoS/DSCP |

- Set the **trust boundary** where traffic enters your network.

### 2.3 Trust vs classify

| Mode | Action |
|------|--------|
| Trust | accept existing CoS/DSCP |
| Classify | match then act |

- On access ports, you often **trust CoS but set DSCP** — or classify everything.

### 2.4 Classification tools

| Tool | Match |
|------|-------|
| class-map | match criteria |
| ACL | IP/ports |
| NBAR | application |
| PBR | route-map match |

- A **class-map** bundles match conditions into a named class.

### 2.5 class-map example

```text
class-map match-any VOICE
 match dscp ef
!
class-map match-any BULK
 match access-group name BULK
```

| Keyword | Match logic |
|---------|-------------|
| match-all | every criterion |
| match-any | any criterion |

### 2.6 Where classification happens

- **Ingress** on routers/switches; NBAR usually on edge devices.
- Only classify **once**, at the edge, then trust the marking in the core.

---

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No match | wrong field | show class-map |
| Wrong class | match-any/all | class-map logic |
| Unmarked ingress | trust boundary | mark policy |
| NBAR misses | unsupported app | NBAR DB |
| QoS not applied | no service-policy | policy-map |

---

## 5. Exam Traps

- Classification **identifies**; marking **writes**.
- **Trust boundary** decides who's trusted.
- `class-map match-any` vs `match-all`.
- NBAR classifies at **L7**.
- Only classify at the **edge**; core trusts.
