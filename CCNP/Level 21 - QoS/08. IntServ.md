# IntServ (Integrated Services)

> **Level 21 · QoS** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**IntServ** delivers **per-flow, hard QoS guarantees** using **RSVP** to reserve
bandwidth end-to-end **before** traffic flows. Unlike DiffServ's per-class model,
IntServ has no trust-and-mark architecture — every router holds per-flow state, which
is why it **doesn't scale** to large networks. The exam contrasts IntServ (RSVP) with
DiffServ (DSCP/PHB) constantly.

---

## 2. Core Concepts

### 2.1 The IntServ model

| Item | Detail |
|------|--------|
| Flow | per session/app |
| Reservation | RSVP PATH/RESV |
| State | per-flow on every router |
| Guarantee | hard |
| Scale | poor |

- Each router keeps **per-flow reservation state**.

### 2.2 RSVP basics

| Message | Direction | Job |
|---------|-----------|-----|
| PATH | sender → receiver | announce requirements |
| RESV | receiver → sender | reserve resources |
| Admission | on each hop | accept/reject |

- **PATH** announces; **RESV** reserves; routers admit or reject.

### 2.3 Services

| Service | Guarantee |
|---------|-----------|
| Guaranteed | hard bandwidth + delay |
| Controlled load | QoS under load |
| Best effort | none |

- **Guaranteed** is the classic hard-commit service.

### 2.4 RSVP config

```text
interface Gi0/1
 ip rsvp bandwidth 128 64
 ip rsvp reservation bandwidth per-flow
```

| Command | Meaning |
|---------|---------|
| `ip rsvp bandwidth` | max/typical |
| `ip rsvp reservation` | per-flow caps |
| `ip rsvp neighbor` | explicit peers |

- Configure RSVP on **every hop** along the path.

### 2.5 IntServ vs DiffServ

| Aspect | IntServ | DiffServ |
|--------|---------|----------|
| Unit | flow | class |
| Signal | RSVP | none |
| State | per flow | per class |
| Guarantee | hard | statistical |
| Scale | low | high |
| Modern use | MPLS-TE / niche | everywhere |

- **DiffServ wins on scale; IntServ wins on guarantee.**

### 2.6 Where IntServ lives today

| Use | Note |
|-----|------|
| RSVP-TE | MPLS traffic engineering |
| Voice gateways | small segments |
| Niche | hard guarantees |

- RSVP-TE is the surviving major use (TE path setup).

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No reservation | RSVP not enabled | show ip rsvp interface |
| RESV rejected | no bandwidth | rsvp bandwidth |
| PATH not forwarded | hop missing | show ip rsvp sender |
| State cleared | refresh timeout | timers |
| Guarantee lost | mixed with DiffServ | policy |

---

## 5. Exam Traps

- IntServ = **per-flow + RSVP reservations**, hard guarantees.
- **PATH → RESV** flow; routers admit/reject.
- **Doesn't scale** (per-flow state).
- DiffServ = per-class, no signaling — **scales**.
- RSVP lives on as **RSVP-TE** for MPLS-TE.
