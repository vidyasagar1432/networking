# RESTCONF

> **Level 24 · SDN & Automation** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**RESTCONF** is an **IETF standard** that exposes **YANG models over HTTP(S) using REST**
verbs — a **REST-style interface to network config**. It's simpler than NETCONF
(stateless, JSON/XML payloads) and is the modern way to configure Cisco IOS-XE devices
via API. The exam contrasts RESTCONF vs NETCONF.

---

## 2. Core Concepts

### 2.1 What RESTCONF is

| Item | Detail |
|------|--------|
| Standard | RFC 8040 |
| Data model | YANG |
| Transport | HTTP/HTTPS |
| Payload | JSON/XML |

- **YANG models + REST verbs over HTTP.**

### 2.2 Verbs

| Verb | Use |
|------|-----|
| GET | read config/state |
| POST | create data |
| PUT | replace data |
| PATCH | partial update |
| DELETE | remove data |

- Same verb semantics as REST (note 06).

### 2.3 RESTCONF vs NETCONF

| Aspect | RESTCONF | NETCONF |
|--------|----------|---------|
| Transport | HTTP(S) | SSH |
| Encoding | JSON/XML | XML |
| State | stateless | RPC/stateful |
| Operations | HTTP verbs | RPC `<get>/<edit-config>` |
| Simplicity | simpler | richer |

- **RESTCONF = HTTP + JSON; NETCONF = SSH + XML/RPC** (note 08).

### 2.4 Data locations

| Location | Meaning |
|----------|---------|
| /data | config + state |
| /operations | RPCs |
| /yang-version | models |

- Data is addressed by **path** into the YANG tree.

### 2.5 Config example (IOS-XE)

```bash
curl -k -u admin:pass -X PATCH \
  https://192.0.2.1/restconf/data/Cisco-IOS-XE-native:native/interface/GigabitEthernet=1 \
  -d '{"Cisco-IOS-XE-interface:description":"uplink"}' \
  -H "Content-Type: application/yang-data+json"
```

- Enable with **`restconf`** in global config.

### 2.6 When to use it

| Use | Reason |
|-----|--------|
| RESTCONF | simple REST automation |
| NETCONF | rich ops/transactions |
| Both | over YANG models |

- Pick **RESTCONF for simplicity; NETCONF for power**.

## 5. Exam Traps

- RESTCONF = **HTTP(S) + YANG + JSON/XML** (RFC 8040).
- Verbs: GET/POST/PUT/PATCH/DELETE.
- **vs NETCONF: HTTP+JSON vs SSH+XML/RPC**.
- Enable `restconf` globally.
- Address config via the **YANG data path**.
