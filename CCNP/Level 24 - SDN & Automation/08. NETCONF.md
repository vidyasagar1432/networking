# NETCONF

> **Level 24 · SDN & Automation** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**NETCONF** is the **IETF standard** (RFC 6241) for managing network devices over an
**SSH session using XML RPCs**. It works on **YANG models**, supports **transactions and
candidate config**, and separates **operational vs running** datastores. It is the richer
alternative to RESTCONF (note 07).

---

## 2. Core Concepts

### 2.1 NETCONF layers

| Layer | Detail |
|-------|--------|
| Content | YANG data |
| Operations | RPCs |
| Messages | XML |
| Transport | SSH |

- **XML RPCs over SSH** on a YANG data model.

### 2.2 Key operations (RPCs)

| RPC | Use |
|-----|-----|
| `<get>` | read state |
| `<get-config>` | read running |
| `<edit-config>` | change config |
| `<copy-config>` | replace |
| `<commit>` | apply candidate |

- **`<edit-config>` is the change; `<commit>` applies the candidate.**

### 2.3 Datastores

| Store | Content |
|-------|---------|
| running | current config |
| candidate | staged changes |
| startup | on boot |
| operational | state data |

- **candidate lets you stage without applying** — transactional.

### 2.4 Config on IOS-XE

```text
netconf-yang
netconf ssh
!
show netconf-yang sessions
show netconf-yang datastore
```

| Command | Meaning |
|---------|---------|
| `netconf-yang` | enable |
| `netconf ssh` | transport |

### 2.5 NETCONF vs RESTCONF

| Aspect | NETCONF | RESTCONF |
|--------|---------|----------|
| Transport | SSH | HTTP(S) |
| Encoding | XML | JSON/XML |
| Model | RPC | verbs |
| Candidate | yes | limited |
| Transactions | yes | less |

- **NETCONF = RPC/XML/SSH; RESTCONF = verbs/JSON/HTTP.**

### 2.6 Example flow

```text
<rpc><edit-config>
 <target><running/></target>
 <config>...</config>
</edit-config></rpc>
```

- Encapsulate changes in **RPC envelopes**.

## 5. Exam Traps

- NETCONF = **SSH + XML RPC + YANG** (RFC 6241).
- Ops: **get / edit-config / commit / copy-config**.
- **candidate = stage then commit**.
- running vs candidate vs operational datastores.
- Richer but heavier than RESTCONF.
