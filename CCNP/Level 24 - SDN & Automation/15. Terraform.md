# Terraform

> **Level 24 · SDN & Automation** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Terraform** is **Infrastructure as Code (IaC)**: you declare the **desired state** in
**HCL** and Terraform **plans and applies** the changes against providers (cloud, and
via **Cisco providers**: DNA Center, IOS-XE, Meraki, SD-WAN). Its key difference from
Ansible: **state-based, declarative** with a **plan/apply** workflow.

---

## 2. Core Concepts

### 2.1 Declarative model

| Item | Detail |
|------|--------|
| Declare | desired state (HCL) |
| Plan | compute diff |
| Apply | make it so |
| State | track what exists |

- Terraform **reconciles current → desired state**.

### 2.2 Core workflow

| Command | Meaning |
|---------|---------|
| `terraform init` | install providers |
| `terraform plan` | preview changes |
| `terraform apply` | execute plan |
| `terraform destroy` | remove resources |

- **Plan → apply** = the safe workflow.

### 2.3 HCL example

```hcl
provider "iosxe" {
  host = "192.0.2.1"
  username = "admin"
}

resource "iosxe_interface" "uplink" {
  name = "GigabitEthernet1"
  description = "to core"
  shutdown = false
}
```

| Keyword | Meaning |
|---------|---------|
| provider | platform |
| resource | object |
| name | key |
| attribute | value |

### 2.4 Terraform vs Ansible

| Aspect | Terraform | Ansible |
|--------|-----------|---------|
| Model | declarative | imperative |
| State | yes | no |
| Workflow | plan/apply | run playbook |
| Use | provision infra | config/manage |

- **Terraform = state+plan; Ansible = push/imperative.**

### 2.5 Providers

| Provider | What |
|----------|------|
| iosxe | IOS-XE config |
| dnacentersdk | DNA Center |
| meraki | cloud |
| sdwan | SD-WAN |

- **Cisco providers** let Terraform drive network gear.

### 2.6 Why it matters

| Benefit | Detail |
|---------|--------|
| Codify | infra as code |
| Repeatable | state-based |
| Safe | plan previews |
| Multicloud | same tool |

- IaC + plan = **auditable, repeatable** infrastructure.

---

## 3. Configuration / Commands

```bash
terraform init
terraform plan
terraform apply -auto-approve
terraform destroy
terraform state list
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Init error | provider | init |
| Plan drift | state stale | refresh |
| Apply fail | auth | provider |
| Resource not found | name | state list |
| Destroy surprise | plan | destroy |

## 5. Exam Traps

- Terraform = **declarative IaC + state**.
- Workflow: **init → plan → apply → destroy**.
- HCL = `provider` + `resource`.
- **vs Ansible: declarative/state vs imperative/push**.
- Cisco providers: **iosxe, dnacentersdk, meraki, sdwan**.
