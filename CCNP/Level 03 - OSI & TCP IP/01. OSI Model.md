# OSI Model

> **Level 03 · OSI & TCP/IP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **Open Systems Interconnection (OSI) reference model** (ISO/IEC 7498) describes
networking in **seven layers**, each with a distinct function. It is the vocabulary
for discussing protocols, troubleshooting ("is it Layer 2 or Layer 3?"), and matching
real protocols to functions.

---

## 2. Core Concepts

### 2.1 The seven layers and their PDUs

| Layer | Name | Function | Real-world protocol/device | PDU |
|-------|------|----------|---------------------------|-----|
| 7 | Application | User services, APIs | HTTP, DNS, FTP, SMTP, DHCP | Data |
| 6 | Presentation | Encoding, encryption, compression | TLS (sometimes), SSL more OSI | Data |
| 5 | Session | Connection state, sessions | NetBIOS, RPC; TCP session logic | Data |
| 4 | Transport | End-to-end delivery, ports, reliability | **TCP, UDP** | **Segment** |
| 3 | Network | Addressing, routing, path selection | **IP**, ICMP; **routers** | **Packet** |
| 2 | Data Link | MAC addressing, framing, media access | **Ethernet**, 802.11; **switches** | **Frame** |
| 1 | Physical | Bits, signals, connectors | UTP, fiber; **hubs, transceivers** | **Bits** |

### 2.2 Layer responsibilities in depth
- **L7 Application**: interfaces apps to network services (DNS names, file, email).
- **L6 Presentation**: data format, character encoding, encryption.
- **L5 Session**: establishes/tears down sessions, checkpointing.
- **L4 Transport**: **segmentation**, **reliability (TCP)**, port multiplexing;
  error recovery via ACKs.
- **L3 Network**: **logical addressing (IP)**, best path (routing), fragmentation.
- **L2 Data Link**: frame assembly, **MAC addresses**, error detection (FCS);
  sublayers LLC + MAC.
- **L1 Physical**: bits on the wire, electrical/optical/RF signals, topology.

### 2.3 Mnemonic
**All People Seem To Need Data Processing** (bottom-up: **Please Do Not Throw
Sausage Pizza Away** for L1→L7).

### 2.4 Two useful sub-concepts
- **LLC (Logical Link Control)** — 802.2 part of L2: multiplexing protocols (EtherType).
- **MAC sublayer** handles media access (CSMA/CD history → backoff) and addressing.

### 2.5 Troubleshooting value (the biggest exam use)
- Layer-by-layer isolation: physical (link lights, errors) → data link (MAC, VLAN,
  STP) → network (IP route) → transport (ports) → application.
- "Works for some, not others" + "ping OK but telnet fails" → think L4 ports / L7.

## 3. Configuration / Commands

```text
# The test used to isolate layers:
ping <ip>            # If OK → L1–L3 are fine (ICMP is L3).
telnet <ip> <port>   # L4 port reachability.
curl http://<host>   # L7 verification for end-user services.
# In a network device:
show interfaces | include (Duplex|Speed|Error|CRC)   # L1 health
show mac address-table                                # L2 learning
show ip route                                        # L3 table
```

## 4. Exam Traps

- **PDU names are the #1 trap** (frame vs packet vs segment).
- **"Layer 4 = application port logic"** — NAT (L3/L4), ACLs (L3+L4) sit at the
  boundary; firewalls go L4–L7.
- **Encryption lives at L6 presentation** in OSI — but TLS is often described at L4/L7
  in practice; exams ask "OSI-wise, TLS ≈ L6". Know both viewpoints without mixing.
- **Device mapping trap**: switch = L2, router = L3, hub = L1, firewall/load balancer = L4–L7.
- **MAC = L2, IP = L3, port = L4**.
