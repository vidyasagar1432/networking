# Encapsulation

> **Level 03 · OSI & TCP/IP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Encapsulation** is the process of adding **headers (and trailers)** as data is
passed down the protocol stack from application to transport → network → link.
Each layer wraps the previous layer's data in its own envelope before sending it
onto the wire ("payload + header = next layer's PDU").

---

## 2. Core Concepts

### 2.1 The envelope chain (HTTP example)
```
[HTTP request ................]                   <- Application data (L7)
[TCP hdr ][HTTP data ........]  =  Segment       <- adds src/dst ports, seq, flags
[IP hdr ][TCP hdr][HTTP data ]  =  Packet        <- adds src/dst IP, TTL, proto
[Eth hdr][IP ][TCP][HTTP][FCS ]  =  Frame        <- adds MAC, EtherType, FCS
```
The **data** is "the same" all the way down; only headers grow.

### 2.2 Why header-per-layer?
- Each layer provides its own service: ports (L4), addressing/routing (L3), media
  framing + error check (L2), so every layer needs its private context in the header.
- **Peer communication**: each layer only reads the header it understands.
- **Multiplexing**: EtherType (L2), Protocol field (L3), ports (L4) tell the receiver
  exactly which higher layer to hand the data to.

### 2.3 Headers/trailers per layer (summary)

| Layer | Header/trailer | Key fields |
|-------|----------------|------------|
| L4 (TCP) | 20–60 B header | ports, seq/ack, flags, window, checksum |
| L4 (UDP) | 8 B header | ports, length, checksum |
| L3 (IPv4) | 20+ B header | version, IHL, TTL, protocol, src/dst IP, checksum |
| L3 (IPv6) | 40 B fixed | flow label, hop limit, src/dst 128-bit |
| L2 (Ethernet) | 14 B header + 4 B FCS trailer | dst/src MAC, EtherType/Len, FCS |
| L2 (802.1Q) | +4 B VLAN tag inside header | TPID, PCP, VID |

### 2.4 Encapsulation for special frames (ENCS spots)
- **VLAN trunk**: an extra 802.1Q tag → "frame harder" (see Level 07).
- **Tunnels (GRE/IPsec/VXLAN)**: the outer protocol encapsulates the whole original
  IP packet as payload → double addressing; MTU must drop (Level 01 MTU).
- **MPLS labels** shoved between L2 and L3 (shim) — the L3 header is still intact
  underneath (Level 20).

### 2.5 Encapsulation maxes to MTU
- Layered headers push the frame toward the **maximum frame size**; if it exceeds
  egress MTU → fragmentation (IPv4) or drop (large frame), governed by MTU rules
  (Level 01, MTU).

## 4. Exam Traps

- **"Which header exists in a packet?"** — segment = L4 fields; frame = L2 + all above.
- **Encapsulation direction = DOWN the source stack** (add); decapsulation = UP at
  destination (remove). Get the direction right.
- **Every hop does L2 re-encapsulation** (new Ethernet header per link) — the L3/L4
  headers only change at the endpoints.
- **Tunnels* = double IP headers** — the outer header routes, the inner is payload.
- **Checksums**: IPv4 header checksum exists; **IPv6 has NO header checksum**;
  TCP/UDP checksums are end-to-end.
