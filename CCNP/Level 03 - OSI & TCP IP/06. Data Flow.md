# Data Flow

> **Level 03 · OSI & TCP/IP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Data flow** is the lifecycle of a unit of data from a source application to a
destination application across a network: **encapsulation down** the source,
**transmission across intermediate devices**, and **decapsulation up** the
destination — plus the peer-to-peer and directional concepts (uni/broad/multi) that
frame each journey.

---

## 2. Core Concepts

### 2.1 The end-to-end journey (7 step model)
1. Application generates data (L7).
2. Down: transport adds ports → **segment**; network adds IP → **packet**;
   link adds Ethernet → **frame**; physical sends **bits**.
3. Each intermediate **switch** (L2): receives frame, checks FCS, forwards by
   destination MAC, re-encapsulates new L2 header on egress.
4. Each **router** (L3): strips Ethernet, checks TTL/sum, looks up destination
   route (CEF), rewrites new L2 header and sends out the next media.
5. (Optional) **NAT/tunnel/firewall** devices add/replace addresses or avoidate mid-path.
6. Destination host receives frame → decapsulates step by step up to the app.
7. Application replies — same process in reverse (full duplex possible).

### 2.2 Peer-to-peer concept (logical communication)
"Peer layers talk to peers": TCP at A understands TCP at B; OSPF at each router talks
to OSPF on its neighbor — even though machines exchange frames on the wire.
This is the logical "same layer ↔ same layer" relationship the OSI model promotes.

### 2.3 Direction classes of data flow

| Type | Definition | Example |
|------|-------------|---------|
| **Unicast** | One source → one destination | Normal HTTP, SSH download |
| **Broadcast** | One → all on the segment | ARP request, DHCP discover |
| **Multicast** | One group → subscribed members | Video feed, broadcasts VRRP/OSPF hello |
| **Anycast** (IPv6/BGP) | One address → nearest of several | DNS anycast, VRRP anycast gateway |

### 2.4 Where data flow gets controlled
- **Switches** filter/forward based on MAC table (Level 04).
- **Routers** decide next hop by longest-prefix match (Level 09).
- **ACLs/firewalls** accept/drop by 5-tuple; **QoS** marks/queues flows (Level 21).
- **Load balancers** distribute flows across servers (Level 05 components).

### 2.5 Data flow vs session semantics
- **TCP flow = 5-tuple** (src IP, dst IP, src port, dst port, protocol) — used by
  NetFlow/ACLs/firewalls to identify a "flow."
- Real-time (UDP RTP) flows use the same concept for QoS classification.

## 3. Configuration / Commands

```text
# Observe the flow journey
traceroute 10.9.9.9        # shows each L3 hop (ICMP/UDP)
ping <host>                # round-trip across the path
show ip fib                # CEF next-hop for flow
# Flow records (NetFlow) capture 5-tuples:
ip flow-export destination 10.1.1.10 2055
```

## 4. Exam Traps

- **"Packet hops L2 but MAC changes"** — destination MAC changes per link; source/dest
  IP typically constant (NAT excepted).
- **Don't say "the frame travels over the router"** — routers strip L2; a full IP
  packet is routed, L2 recreated per link.
- **Peer-to-peer here = layer 'peer' not file-sharing** — keep them straight (Level 00 P2P note).
- **Anycast vs multicast** distinction frequently tested at L3/IPv6.
- **TTL decreases per router hop** — it always goes down on L3 forward.

## 5. Quick Review Table

| Stage | Device | Header it reads |
|-------|--------|-----------------|
| Send down | Source | builds all |
| L2 transit | Switch | Ethernet |
| L3 transit | Router | IP (rewrites Ethernet) |
| Tunnels/NAT | Special | outer/translated |
| Receive up | Destination | strips all |
| Peer talk | Logical | same layer both ends |
| Direction | uni/bcast/mcast/anycast | defines delivery to whom |
| Flow identity | 5-tuple | src/dst IP+port+proto |
