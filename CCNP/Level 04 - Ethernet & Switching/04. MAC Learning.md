# MAC Learning

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**MAC learning** is the process by which a switch dynamically builds its  
**MAC address table (CAM table)** by examining the **Source MAC address** of  
incoming Ethernet frames.

The switch associates the learned MAC address with the **VLAN and ingress  
port** where the frame was received.

Conceptually:

```text
Source MAC + VLAN + Ingress Port
             │
             v
       MAC/CAM Table
```

The fundamental switching rule is:

> **Learn from the Source MAC; forward using the Destination MAC.**

MAC learning allows the switch to move from unnecessary flooding to  
**selective forwarding**.

---

# 2. Core Concepts

## 2.1 The Learning Rule

For every Ethernet frame received on an interface:

```text
Frame arrives
     │
     v
Read Source MAC
     │
     v
Identify VLAN context
     │
     v
Learn / update:
MAC + VLAN → Ingress Port
```

Example:

```text
Source MAC = AAAA.AAAA.AAAA
VLAN       = 10
Port       = Gi0/1
```

The switch learns:

```text
AAAA.AAAA.AAAA + VLAN 10 → Gi0/1
```

### If the Source MAC Is New

The switch creates a dynamic entry:

```text
VLAN 10
AAAA.AAAA.AAAA → Gi0/1
```

### If the Source MAC Is Already on the Same Port

The switch keeps the existing association and refreshes the dynamic entry's  
aging state.

### If the Source MAC Is Learned on Another Port

The switch updates the MAC table to reflect the new location.

Example:

```text
Before:
AAAA.AAAA.AAAA → Gi0/1

Frame arrives on Gi0/2:

After:
AAAA.AAAA.AAAA → Gi0/2
```

This is commonly described as **MAC movement** or **MAC flapping** when it  
occurs repeatedly.

---

# 3. Why MAC Learning Works Without Manual Configuration

A switch does not normally require an administrator to manually enter every  
host's MAC address.

It can dynamically learn by observing traffic.

Example:

```text
Host A
MAC = AAAA.AAAA.AAAA
        │
        │ Frame
        v
     Gi0/1
        │
        v
     Switch
```

The switch observes:

```text
Source MAC = AAAA.AAAA.AAAA
Ingress Port = Gi0/1
VLAN = 10
```

and creates:

```text
AAAA.AAAA.AAAA + VLAN 10 → Gi0/1
```

Initially, before the destination MAC has been learned, traffic may be  
flooded. Once the destination MAC is learned, the switch can perform  
**selective unicast forwarding**.

> **Mental model:**  
> **First learn → then selectively forward.**

---

# 4. MAC Learning and Forwarding

Consider this MAC table:

```text
VLAN    MAC Address        Port
----    -----------------  ----
10      AAAA.AAAA.AAAA     Gi0/1
10      BBBB.BBBB.BBBB     Gi0/2
```

Host A sends a frame to Host B:

```text
Source MAC      = AAAA.AAAA.AAAA
Destination MAC = BBBB.BBBB.BBBB
```

The switch:

1. Learns/refreshes `AAAA.AAAA.AAAA` on `Gi0/1`.
    
2. Looks up `BBBB.BBBB.BBBB` in VLAN 10.
    
3. Finds `Gi0/2`.
    
4. Forwards the frame toward `Gi0/2`.
    

Therefore:

```text
Source MAC      → LEARN
Destination MAC → FORWARD
```

---

# 5. Unknown-Unicast Flooding

Suppose the destination MAC is not present in the MAC table.

Example:

```text
Destination MAC = CCCC.CCCC.CCCC

CAM/MAC table:
No matching entry
```

The switch treats this as an **unknown unicast**.

It normally floods the frame out other eligible ports in the same VLAN,  
except the ingress port.

```text
                 ┌── Gi0/2
                 │
Incoming ──── Switch ── Gi0/3
Gi0/1            │
                 └── Gi0/4
```

> **Important:** Unknown-unicast flooding is **not the same thing as  
> broadcast**. The destination MAC remains a unicast MAC; the switch simply  
> does not yet know which port leads to it.

Once the destination MAC is learned:

```text
Unknown unicast
      ↓
   Flooding

After learning
      ↓
Known unicast
      ↓
Selective forwarding
```

---

# 6. MAC Table Aging

Dynamic MAC entries are temporary.

They have an **aging timer**, after which an inactive dynamic entry can be  
removed.

A commonly encountered Cisco IOS default is:

```text
300 seconds = 5 minutes
```

The exact default can vary by platform/software.

Conceptually:

```text
Dynamic MAC learned
        │
        v
   Aging timer
        │
        ├── Traffic received
        │       ↓
        │    Refresh
        │
        └── Timer expires
                ↓
            Entry removed
```

### Why Aging Is Important

If aging is too short:

- MAC entries expire frequently.
    
- Unknown-unicast flooding can increase.
    
- The switch repeatedly relearns hosts.
    

If aging is too long:

- Stale entries may remain longer after host movement.
    
- Troubleshooting can become more difficult.
    

> **Exam point:** Dynamic MAC entries are subject to aging; activity can  
> refresh their learned state.

---

# 7. Static MAC Entries

A **static MAC entry** is manually configured rather than dynamically learned.

Example:

```cisco
mac address-table static AAAA.AAAA.AAAA vlan 10 interface GigabitEthernet0/1
```

Static entries are not treated like ordinary dynamically learned entries and  
generally do not age out through the normal dynamic MAC aging process.

Static entries can be useful when a specific MAC-to-port forwarding  
association needs to be explicitly configured.

> **Exam distinction:**  
> **Dynamic = learned automatically and ages.**  
> **Static = manually configured and does not normally age like a dynamic  
> entry.**

---

# 8. MAC Learning Is Per VLAN

MAC learning occurs within a **VLAN context**.

The same MAC address can legitimately appear in different VLANs.

Example:

```text
VLAN 10:
AAAA.AAAA.AAAA → Gi0/1

VLAN 20:
AAAA.AAAA.AAAA → Gi0/5
```

This does not automatically indicate a duplicate device because VLAN 10 and  
VLAN 20 are separate Layer 2 broadcast domains.

Conceptually:

```text
MAC + VLAN → Port
```

not simply:

```text
MAC → Port
```

> **Exam point:** The VLAN is part of the Layer 2 forwarding context.

---

# 9. MAC Learning on Access Ports

An access port belongs to a single access VLAN.

If a frame arrives untagged on:

```text
Gi0/1
Access VLAN = 10
```

the switch learns the source MAC in VLAN 10:

```text
Source MAC + VLAN 10 → Gi0/1
```

Example:

```cisco
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10
```

---

# 10. MAC Learning on Trunk Ports

A trunk can carry multiple VLANs.

For a tagged 802.1Q frame, the switch uses the VLAN tag to determine the  
VLAN context in which the source MAC is learned.

Example:

```text
          802.1Q Trunk
Switch A ================= Switch B
          VLAN 10
          VLAN 20
          VLAN 30
```

A source MAC received in VLAN 20 is learned in VLAN 20.

Conceptually:

```text
Source MAC + VLAN 20 → Trunk Port
```

If an **untagged frame** is received on a trunk, it is associated with the  
configured **native VLAN**.

> **Exam trap:** Do not say that an untagged frame on a trunk is "learned in  
> no VLAN." It is associated with the trunk's native VLAN according to the  
> configuration/platform behavior.

---

# 11. MAC Learning and STP

Spanning Tree affects whether a port is actively participating in data  
forwarding and learning.

A port that is not in a state that permits normal data-frame processing does  
not normally learn source MAC addresses from user data traffic.

For example, a port placed into an STP **discarding/blocking state** does not  
normally learn MAC addresses from received user data frames.

Conceptually:

```text
STP forwarding port
        ↓
Data frames processed
        ↓
MAC learning occurs

STP non-forwarding/discarding port
        ↓
User data not normally processed
        ↓
No normal source-MAC learning
```

> **Exam point:** STP and MAC learning are closely related because STP  
> determines which Layer 2 paths can actively forward traffic.

---

# 12. MAC Movement / MAC Flapping

A **MAC move** occurs when the same MAC address is learned on a different  
port.

Example:

```text
Initial:
AAAA.AAAA.AAAA → Gi0/1

Later:
AAAA.AAAA.AAAA → Gi0/2
```

If the MAC repeatedly moves:

```text
Gi0/1 → Gi0/2 → Gi0/1 → Gi0/2 ...
```

this can be called **MAC flapping**.

Possible causes include:

- Layer 2 loops
    
- Incorrect cabling
    
- Redundant paths
    
- STP topology changes
    
- Host movement
    
- Virtual machine mobility
    
- Hypervisor networking
    
- Duplicate MAC addresses
    
- HSRP/VRRP virtual MACs
    
- Misconfigured switches
    

> **Important:** MAC movement does **not automatically mean a rogue switch**.  
> Always investigate the topology and connected devices.

---

# 13. MAC Table Capacity

The MAC table is stored in hardware resources with finite capacity.

The exact capacity depends on the switch model and ASIC architecture.

If the switch cannot learn a new destination MAC because the table is full,  
that MAC may remain **unknown** from the forwarding perspective.

Traffic destined for an unknown unicast MAC is then subject to  
**unknown-unicast flooding**, according to the platform and configured  
features.

Conceptually:

```text
MAC table has capacity
        │
        v
Capacity reached
        │
        v
New MAC cannot be learned
        │
        v
Destination remains unknown
        │
        v
Unknown-unicast flooding
```

> **Exam point:** Do not memorize one universal CAM-table size. **CAM  
> capacity is platform-dependent.**

---

# 14. MAC Learning and ARP

MAC learning and ARP solve different parts of the forwarding problem.

### ARP

ARP maps:

```text
IPv4 address → MAC address
```

Example:

```text
192.168.10.50 → AAAA.AAAA.AAAA
```

### MAC Address Table

The switch maps:

```text
MAC + VLAN → Switch Port
```

Example:

```text
AAAA.AAAA.AAAA + VLAN 10 → Gi0/5
```

Together:

```text
192.168.10.50
      │
      v
AAAA.AAAA.AAAA
      │
      v
VLAN 10 / Gi0/5
```

This is extremely useful when troubleshooting:

> **"I know the host's IP address. Which switch port is it connected to?"**

---

# 15. MAC Learning and Port Security

**Port Security** can restrict which MAC addresses are allowed on a switch  
port.

It can work with:

- Static secure MAC addresses
    
- Dynamic secure MAC addresses
    
- Sticky secure MAC addresses
    
- Maximum MAC address limits
    
- Violation modes
    

Common violation modes include:

```text
shutdown
restrict
protect
```

Conceptually:

```text
Incoming Source MAC
        │
        v
Port Security Check
        │
        ├── Allowed → Forward normally
        │
        └── Violation → Apply configured violation mode
```

Port security therefore adds a security policy on top of normal MAC learning.

```cisco

```

# 17. Troubleshooting Workflow

If you know the host's **MAC address**:

```text
MAC Address
     │
     v
show mac address-table address <MAC>
     │
     v
VLAN + Switch Port
     │
     v
Check Interface
     │
     v
Trace Neighbor / Uplink
```

If you know the host's **IPv4 address**:

```text
IPv4 Address
     │
     v
show arp
     │
     v
MAC Address
     │
     v
show mac address-table address <MAC>
     │
     v
Switch Port
```

Useful commands:

```cisco
show arp
show mac address-table address AAAA.AAAA.AAAA
show mac address-table vlan 10
show interfaces GigabitEthernet0/1
```

For suspected MAC flapping:

```text
1. Identify the MAC address.
2. Check where it is currently learned.
3. Look for MAC-move/flapping messages.
4. Identify the connected devices.
5. Trace the relevant uplinks.
6. Check STP topology.
7. Check for Layer 2 loops.
8. Check for duplicate or virtual MAC addresses.
```

# 18. Exam Traps

- **MAC learning uses the Source MAC.**
    
- **Forwarding uses the Destination MAC.**
    
- **Known unicast → selective forwarding.**
    
- **Unknown unicast → flooding within the VLAN**, subject to switch features.
    
- Unknown unicast is **not the same thing as broadcast**.
    
- MAC learning is performed in a **VLAN context**.
    
- The same MAC can legitimately exist in different VLANs.
    
- A commonly encountered Cisco dynamic MAC-aging default is **300 seconds**.
    
- Aging defaults can vary by platform/software.
    
- Dynamic entries can age out; static entries normally do not age like dynamic  
    entries.
    
- MAC movement means the same MAC is being learned on different ports.
    
- Repeated movement is commonly called **MAC flapping**.
    
- MAC flapping can indicate a loop, duplicate MAC, VM mobility, topology  
    change, virtual MAC, or misconfiguration.
    
- **Do not automatically assume MAC flapping means a rogue switch.**
    
- A full MAC table means new addresses may not be learned; unknown destinations  
    can then be flooded.
    
- CAM/MAC-table capacity is **platform-dependent**.
    
- Access-port traffic is learned in the configured access VLAN.
    
- Tagged trunk traffic is learned in the VLAN identified by its tag.
    
- Untagged traffic received on a trunk is associated with the configured  
    native VLAN.
    
- STP non-forwarding/discarding ports do not normally learn user-data source  
    MAC addresses.
    
- **ARP = IPv4 → MAC.**
    
- **MAC table = MAC + VLAN → switch port.**
    
- Port security adds restrictions to normal MAC learning/forwarding behavior.
    
- `show mac address-table` is the primary command for verifying learned MACs.

# 20. One-Minute Mental Model

```text
                    Ethernet Frame
                           │
                           v
                     Source MAC
                           │
                           v
                    ┌─────────────┐
                    │ MAC / CAM   │
                    │ MAC + VLAN  │
                    └──────┬──────┘
                           │
                           v
                       Port Learned


Learning:
    Source MAC
        ↓
    MAC + VLAN + Port


Forwarding:
    Destination MAC + VLAN
        ↓
    CAM Lookup
        ↓
    ┌───────────────┐
    │ Known?        │
    └───────┬───────┘
            │
       ┌────┴────┐
       │         │
      YES        NO
       │         │
       v         v
   Forward    Flood
   to port    within VLAN


Troubleshooting:
    IPv4
      ↓
    ARP
      ↓
    MAC
      ↓
    MAC/CAM Table
      ↓
    Switch Port
```

> **CCNP takeaway:**  
> **MAC learning is the foundation of Layer 2 switching. A switch learns the  
> Source MAC of incoming frames and associates it with a VLAN and ingress  
> port. It then uses the Destination MAC to perform a forwarding lookup.  
> Known destinations are selectively forwarded; unknown unicast destinations  
> are flooded until the destination is learned.**
