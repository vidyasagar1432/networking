# MAC Learning

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**MAC learning** is how a switch builds its CAM table: by examining the **source MAC**
of incoming frames on each port, it records "this MAC lives behind this port." It is
the foundation for everything else — forwarding, filtering, and flooding behavior.

---

## 2. Core Concepts

### 2.1 The learning rule
> **Learn from source, forward by destination.**

For every frame received on port X in VLAN V:
- If **source MAC is not in CAM** → add entry `V, MAC → port X`.
- If **already present on X** → refresh age timer (keep as is).
- If **present on a different port** → a **MAC move** (re-learn to the new port; shown
  in syslog as `%MAC_MOVE-4-TRUE_MOV`).

### 2.2 Why learning works without configuration
- Switches bootstrap themselves by watching traffic; zero config needed to start
  forwarding. Only after the table exists do we get **selective forwarding**.

### 2.3 Learn limits
- Table is bounded (size by ASIC/CAM); when full → **flood** unknown addresses
  (capacity limits cause flooding — a DO for sizing).
- Dynamic entries expire (default aging 300 s).
- A **static MAC** prevents aging and stays regardless of activity.

### 2.4 Learning across trunk/VLANs
- Learning is **per VLAN**: the same MAC can exist on different ports in different VLANs
  (each is a separate L2 domain / separate entry keyed by MAC+VLAN).
- Tagged frames (802.1Q) learn the MAC into the tagged VLAN, not the native.
- On access ports, the configured access VLAN is the learning VLAN.

### 2.5 Learning & topology effects
- **MAC learning works on every port** except those blocked by spanning-tree (STP
  "listening/blocking" ports do NOT learn) — see Level 08.
- **Flooding** occurs exactly when the dest MAC isn't learned yet (Level 05).
- **Duplicate MACs** (virtual machines, HSRP) can cause flurry of relearns.

## 3. Configuration / Commands

```text
# Watch learning live
debug mac address-table ?
# Build the table quickly (ping between endpoints to generate frames)

show mac address-table
show mac address-table | include Gi0/1
show mac address-table count
```

Troubleshooting a device that "can't be reached":
1. `show arp` — is IP→MAC mapped? Then
2. `show mac address-table address <MAC>` — is the MAC on the right port & VLAN?

---

## 4. Exam Traps

- **Learning is from SOURCE MAC**, forwarding uses DEST MAC — the two are easily flipped.
- **Unknown destination → flood**, not "drop" — frames to unlearned MACs are broadcast.
- **STP-blocked ports don't learn** — a reason flooding/loops are linked.
- **MAC move** means the same MAC was seen on two ports — often HSRP/VM/rogue switch.
- **Aging default 300 s** — too-short aging causes excessive flooding.
