# Broadcast Domains

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **broadcast domain** is the set of devices that receive a Layer 2 **broadcast**
frame (`FF:FF:FF:FF:FF:FF`). In Ethernet terms it is bounded by **routers** (L3) —
by default, a **VLAN = one broadcast domain**. The size/shape of broadcast domains is
a core scaling and security concept.

---

## 2. Core Concepts

### 2.1 The boundaries

| Device | Effect on broadcast domain |
|--------|-----------------------------|
| **Hub** | no boundary — extends the domain |
| **Switch** (L2) | no boundary **within a VLAN** (all ports in a VLAN are one domain) |
| **Router / L3 interface / VLAN interface** | **boundary** — each L3 network or VLAN is separate |
| **VLAN** | one broadcast domain |

So: routers segment broadcast domains; VLANs create multiple broadcast domains on one switch.

### 2.2 What rides on broadcasts
- **ARP requests** (who has this IP?), **DHCP Discover** (any DHCP server?), NBNS/mDNS,
  some routing (RIP periodically), Microsoft protocols. These are *potentially* frequent
  on large flat L2 networks.
- **Broadcast storms** — a switch loop or misconfigured NIC floods → meltdown; that's
  the reason for STP + storm control.

### 2.3 Why size matters
- **Scalability**: more hosts in a broadcast domain = more frame processing per host,
  wasted bandwidth (all hosts must inspect/abandons up).
- **Security**: any host can observe broadcasts (ARP poisoning / discovery); attackers
  probe within the domain.
- **Performance**: large domains force per-broadcast CPU load on every host.

### 2.4 Shrinking broadcast domains — standard answers

| Method | What it does |
|--------|--------------|
| **VLANs** | small L2 domains per business area |
| **VLANs + interVLAN routing** | keep L2 small, route between (Level 07) |
| **VRF/segmentation** | domain containment for multi-tenant/security (Level 25) |
| **Routed access** | each access switch is its own L2 domain routed toward the core |
| **Private VLAN** | isolate sub-groups inside a VLAN (Level 07) |
| **IGMP snooping** | stop multicast from becoming broadcast-ish floods |

### 2.5 Broadcast domain vs collision domain (the classic couple)

| | Broadcast domain | Collision domain |
|--|------------------|------------------|
| What travels | broadcast frames | any frame colored by CSMA/CD contention |
| Bounded by | routers (L3) / VLANs | switches/bridges (L2) |
| A hub | one domain (grows) | one collision domain (all) |
| A switch | per-VLAN | per-port (microsegmentation) |
| Modern default | 1 per VLAN | 1 per port (full duplex, no contention) |

## 3. Configuration / Commands

```text
# Create VLANs to split a flat domain
vlan 10
 name Users
vlan 20
 name Servers

# Route between them (SVI on the L3 switch)
interface Vlan10
 ip address 10.1.10.1 255.255.255.0
interface Vlan20
 ip address 10.1.20.1 255.255.255.0
ip routing

# Verify where broadcasts live conceptually
show vlan brief
show ip interface brief
```

---

## 4. Exam Traps

- **Routers AND VLAN interfaces segment broadcast domains; switches and hubs do not.**
- **A switch creates one round broadcast domain unless VLANs exist.**
- **Per-VLAN = separate broadcast domain** — ensure "router also required to route"
  (SVIs are routers).
- **Do not confuse with collision domain** (that's segmented per sw-port; see Level 04 Collision).
- **Broadcast storms** belong in the *loop* (STP) discussion, not sizing.
