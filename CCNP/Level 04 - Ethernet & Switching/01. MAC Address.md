# MAC Address

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **MAC (Media Access Control) address** is a **Layer 2 identifier** used by Ethernet  
network interfaces for local-frame delivery. A standard Ethernet MAC address is  
**48 bits (6 bytes)** long.

A physical NIC commonly has a **burned-in address (BIA)**, but MAC addresses can also be  
**locally administered or software-assigned**, especially on virtual machines,  
hypervisors, and virtual interfaces.

Switches use MAC addresses to build their **MAC address table** and determine where  
Ethernet frames should be forwarded.

---

## 2. Core Concepts

### 2.1 Format and Anatomy

A standard MAC address contains **48 bits / 6 bytes** and is normally written as:

```text
AA:BB:CC:DD:EE:FF
```

Other common formats:

```text
AA-BB-CC-DD-EE-FF
AABB.CCDD.EEFF        ← Cisco-style notation
```

#### OUI

The first **24 bits (3 bytes)** are commonly called the **OUI (Organizationally  
Unique Identifier)**.

Example:

```text
00:00:0C:AA:BB:CC
└───────┘
   OUI
```

The OUI identifies the organization/vendor that owns that address space.

> **Exam note:** The remaining 24 bits should not be described strictly as a  
> "serial number." They identify the interface within the address space assigned  
> by the organization.

---

### 2.2 I/G and U/L Bits

The two least-significant bits of the **first octet** have special meanings.

|Bit|Name|Value|Meaning|
|---|---|---|---|
|Bit 0|**I/G**|`0`|Individual/unicast address|
|Bit 0|**I/G**|`1`|Group address (multicast/broadcast)|
|Bit 1|**U/L**|`0`|Universally administered|
|Bit 1|**U/L**|`1`|Locally administered|

Example:

```text
First octet:  00000000
                  ││
                  │└── I/G
                  └─── U/L
```

> **Exam shortcut:** Look at the **first octet**, counting from the right:
> 
> - Rightmost bit = **I/G**
>     
> - Second-from-right bit = **U/L**
>     

---

### 2.3 Unicast, Multicast, and Broadcast

#### Unicast

A **unicast MAC address** identifies an individual destination.

```text
I/G = 0
```

Example:

```text
00:1B:21:AA:BB:CC
```

A switch normally forwards a known unicast frame toward the port associated with  
the destination MAC address.

#### Multicast

A **multicast MAC address** represents a group of receivers.

```text
I/G = 1
```

Example IPv4 multicast MAC:

```text
01:00:5E:xx:xx:xx
```

#### Broadcast

The Ethernet broadcast address is:

```text
FF:FF:FF:FF:FF:FF
```

All bits are `1`, so the address is a group address.

A broadcast frame is flooded throughout the local **Layer 2 broadcast domain**  
(subject to VLAN and switch behavior).

> **Exam trap:** Broadcast is a special form of a group address. Do not describe  
> `FF:FF:FF:FF:FF:FF` as a unicast MAC address.

---

### 2.4 Locally Administered MAC Addresses

A **locally administered MAC address (LAA)** has:

```text
U/L = 1
```

The address is assigned by software, an administrator, a hypervisor, or another  
local mechanism rather than being globally assigned through the vendor's OUI space.

Common examples include:

- Virtual machines
    
- Hypervisor virtual NICs
    
- Some virtual interfaces
    
- Certain high-availability virtual MAC addresses
    

> **Exam trap:** `U/L = 1` means **locally administered**. It does not simply mean  
> "virtual."

---

### 2.5 HSRP and VRRP Virtual MACs

First-hop redundancy protocols use virtual MAC addresses.

#### HSRP

**HSRP v1:**

```text
0000.0C07.ACxx
```

**HSRP v2:**

```text
0000.0C9F.Fxxx
```

#### VRRP

**VRRP for IPv4:**

```text
0000.5E00.01xx
```

**VRRP for IPv6:**

```text
0000.5E00.02xx
```

These virtual MAC addresses allow hosts to use a virtual default gateway while  
different physical routers can provide redundancy.

## 3. MAC Address vs IP Address

|Feature|MAC Address|IP Address|
|---|---|---|
|Layer|Layer 2|Layer 3|
|Purpose|Local frame delivery|Host/network identification and routing|
|Size|48-bit|IPv4: 32-bit / IPv6: 128-bit|
|Format|Hexadecimal|Decimal (IPv4) / hexadecimal (IPv6)|
|Scope|Local Layer 2 segment|Used across Layer 3 networks|
|Assignment|BIA, administrator, software, virtual interface|Manual, DHCP, SLAAC, etc.|
|Used by|Ethernet switching|IP routing|
|IPv4 resolution|ARP resolves next-hop IP → MAC|—|
|IPv6 resolution|ND resolves neighbor IP → MAC|—|

> **Important:** An IP address can remain logically associated with the same  
> endpoint while the Ethernet MAC addresses used to carry the packet change  
> from one Layer 2 segment to another.

## 4. MAC Addresses and Routing

A common exam misconception is:

> ❌ "The MAC address changes at every Layer 2 switch hop."

That is **incorrect**.

### Through switches

Switches normally forward an Ethernet frame **without rewriting its source or  
destination MAC addresses**.

```text
Host A
  |
  | Src MAC = A
  | Dst MAC = B
  v
Switch 1
  |
  v
Switch 2
  |
  v
Host B
```

The same Ethernet source and destination MAC addresses remain in the frame while  
it crosses the Layer 2 switching domain.

### Through a router

A router operates at Layer 3 and creates a **new Ethernet frame** on the outgoing  
interface.

```text
Host A
   |
   | Ethernet Frame
   | Src MAC = A
   | Dst MAC = Router-1
   v
Router
   |
   | New Ethernet Frame
   | Src MAC = Router-2
   | Dst MAC = Next-Hop
   v
Host B
```

The **IP packet is routed**, while the Ethernet header is replaced for the next  
Layer 2 segment.

> **CCNP exam rule:**  
> **Switch = forwards the existing Ethernet frame.**  
> **Router = removes the incoming L2 header and creates a new L2 header.**

## 5. MAC Address Table

An Ethernet switch learns source MAC addresses and associates them with ports  
and VLANs.

Example:

```text
VLAN    MAC Address        Type       Ports
----    -----------        --------   -----
10      0011.2233.4455     DYNAMIC    Gi0/1
20      0066.7788.99AA     DYNAMIC    Gi0/2
```

When a frame arrives, the switch:

1. Learns the **source MAC address**.
    
2. Looks up the **destination MAC address**.
    
3. Forwards the frame if the destination is known.
    
4. Floods the frame within the appropriate VLAN if the destination is unknown,  
    multicast, or broadcast, subject to the relevant switching behavior.

## 6. Configuration / Verification Commands

### View the MAC Address Table

```cisco
show mac address-table
```

### View a Specific MAC Address

```cisco
show mac address-table address 001B.21AA.BBCC
```

### View Dynamic MAC Addresses

```cisco
show mac address-table dynamic
```

### View MAC Addresses for a VLAN

```cisco
show mac address-table vlan 10
```

### Configure a Static MAC Entry

```cisco
mac address-table static 001B.21AA.BBCC vlan 10 interface GigabitEthernet0/1
```

Static MAC entries are useful when a specific forwarding behavior must be  
configured manually, although normal switch learning is dynamic.

### Check Interface Hardware/BIA Information

```cisco
show interfaces GigabitEthernet0/1
```

Platform output varies, but Cisco IOS commonly displays the interface's hardware  
MAC/BIA information.

## 7. MAC Address Learning

A switch normally learns MAC addresses from the **source MAC address** of  
incoming Ethernet frames.

Example:

```text
Host A
MAC = AAAA.AAAA.AAAA
        |
        | Frame enters Gi0/1
        v
     Switch
```

The switch learns:

```text
AAAA.AAAA.AAAA → Gi0/1
```

If Host A later moves to another switch port, the switch can update the MAC table  
when it receives frames with that source MAC on the new port.

> **Exam point:** Switches learn from the **source MAC**, not the destination MAC.

## 8. MAC Address and ARP

For IPv4 communication on an Ethernet network, a host needs the MAC address of  
the **next-hop IPv4 address**.

### Same subnet

```text
Host A
IP: 192.168.10.10
MAC: AAAA.AAAA.AAAA
        |
        | ARP
        v
Host B
IP: 192.168.10.20
MAC: BBBB.BBBB.BBBB
```

Host A uses ARP to discover:

```text
192.168.10.20 → BBBB.BBBB.BBBB
```

### Different subnet

If the destination is on another IP network, the source host does **not** ARP  
for the remote host's MAC address.

Instead, it resolves the MAC address of its **default gateway/next hop**.

```text
Destination IP
192.168.20.10
      |
      | Different subnet
      v
Default Gateway
192.168.10.1
MAC = CCCC.CCCC.CCCC
```

The host sends the Ethernet frame to the router's MAC address, while the IP  
destination remains the remote IP address.

## 9. MAC Address Types — Quick Comparison

|Type|I/G|U/L|Example|
|---|--:|--:|---|
|Universal unicast|0|0|`00:1B:21:AA:BB:CC`|
|Local unicast|0|1|Software/VM-assigned MAC|
|Multicast|1|Usually varies by allocation|`01:00:5E:xx:xx:xx`|
|Broadcast|1|1|`FF:FF:FF:FF:FF:FF`|

> The U/L bit and I/G bit are **independent properties**. Do not assume every  
> multicast address or every virtual MAC has the same U/L value.

## 10. Exam Traps

- **MAC address = 48 bits / 6 bytes**, not 32 bits.
    
- The **I/G bit is the least-significant bit of the first octet**.
    
- `I/G = 0` → individual/unicast.
    
- `I/G = 1` → group address.
    
- **Broadcast = `FF:FF:FF:FF:FF:FF`.**
    
- **U/L = 0** → universally administered.
    
- **U/L = 1** → locally administered.
    
- **OUI = first 24 bits / 3 bytes** of a universally administered MAC address.
    
- A MAC address is primarily used for **local Layer 2 delivery**.
    
- Switches normally **do not rewrite MAC addresses** when forwarding frames.
    
- Routers create a **new Layer 2 frame** for each outgoing Layer 2 segment.
    
- ARP resolves an IPv4 **next-hop IP address to a MAC address**.
    
- For remote destinations, a host ARPs for the **default gateway's MAC**, not the  
    remote host's MAC.
    
- IPv6 uses **Neighbor Discovery (ND)** rather than ARP.
    
- Switches learn MAC addresses from the **source MAC** of incoming frames.
    
- MAC tables are associated with **VLANs and switch ports**.
    
- A virtual MAC does not automatically mean `U/L = 1`; examine the actual address.

## 12. One-Minute Mental Model

```text
MAC = Layer 2 local delivery
IP  = Layer 3 internetwork delivery

Switch:
    MAC → switch port
    Learns source MAC
    Looks up destination MAC
    Forwards/floods Ethernet frame

Router:
    IP → routing decision
    Removes incoming L2 header
    Creates new outgoing L2 frame

IPv4:
    IP → MAC = ARP

IPv6:
    IP → MAC = Neighbor Discovery

I/G:
    0 = Individual
    1 = Group

U/L:
    0 = Universal
    1 = Local
```

> **CCNP takeaway:**  
> **MAC addresses identify Layer 2 interfaces and enable local Ethernet delivery.  
> Switches use MAC tables to forward frames, while routers use IP routing to move  
> packets between Layer 3 networks.**
