# CAM Table

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **CAM (Content-Addressable Memory) table** is the hardware-based Layer 2  
forwarding database used by a switch to associate a **MAC address and VLAN  
context with a switch port**.

Cisco commonly exposes this information through the **MAC address table**.

Conceptually:

```text
MAC Address + VLAN → Switch Port
```

Example:

```text
00:1B:21:AA:BB:CC + VLAN 10 → Gi0/1
```

The switch uses this information to decide where to forward Ethernet frames.

> **Exam terminology:**  
> **CAM table ≈ MAC address table** in normal Cisco switching discussions.

---

# 2. Core Concepts

## 2.1 What CAM Means

**CAM = Content-Addressable Memory.**

Traditional memory is searched by an address:

```text
Memory Address → Data
```

CAM works in the opposite direction:

```text
Content/Key → Matching Entry
```

For Layer 2 switching, the switch can use the destination MAC and VLAN  
context as the lookup key.

Conceptually:

```text
Destination MAC + VLAN
          │
          v
        CAM
          │
          v
     Egress Port
```

This allows hardware-based forwarding without having to examine every table  
entry sequentially.

---

## 2.2 Typical CAM/MAC Table Entry

Example:

```text
VLAN    MAC Address        Type      Port
----    -----------------  --------  ----
10      001B.21AA.BBCC     DYNAMIC   Gi0/1
10      000C.2912.3456     DYNAMIC   Gi0/2
30      AAAA.AAAA.AAAA     STATIC    Gi0/24
```

A typical entry contains:

- VLAN
    
- MAC address
    
- Entry type
    
- Associated switch port
    

### Dynamic Entry

A **dynamic** entry is learned automatically from the **Source MAC address**  
of an incoming Ethernet frame.

Example:

```text
Frame arrives on Gi0/1
Source MAC = AAAA.AAAA.AAAA
VLAN = 10

        ↓

AAAA.AAAA.AAAA + VLAN 10
        ↓
       Gi0/1
```

### Static Entry

A **static** entry is manually configured.

Example:

```cisco
mac address-table static AAAA.AAAA.AAAA vlan 10 interface GigabitEthernet0/1
```

# 3. MAC Address Learning

A switch normally learns the Source MAC address of an incoming frame.

Example:

```text
Host A
MAC = AAAA.AAAA.AAAA
        |
        | Frame enters Gi0/1
        v
     Switch
```

The switch learns:

```text
AAAA.AAAA.AAAA → VLAN 10 → Gi0/1
```

The switch can then use this information when forwarding future frames  
destined for that MAC address.

> **Exam rule:**  
> **Source MAC → Learn**  
> **Destination MAC → Forward**

---

# 4. Forwarding Using the CAM Table

Suppose the switch has:

```text
VLAN    MAC Address        Port
----    -----------------  ----
10      AAAA.AAAA.AAAA     Gi0/1
10      BBBB.BBBB.BBBB     Gi0/2
```

Host A sends a frame to Host B:

```text
Source MAC      = AAAA.AAAA.AAAA
Destination MAC = BBBB.BBBB.BBBB
```

The switch:

1. Learns the Source MAC on the incoming port.
    
2. Searches the CAM/MAC table for the Destination MAC + VLAN.
    
3. Finds `BBBB.BBBB.BBBB` on `Gi0/2`.
    
4. Forwards the frame toward `Gi0/2`.
    

Conceptually:

```text
Destination MAC + VLAN
          │
          v
      CAM Lookup
          │
          v
        Gi0/2
```

---

# 5. Unknown Unicast Flooding

If the destination MAC is **not present** in the CAM/MAC table, the switch  
does not know the correct outgoing port.

This is an **unknown unicast**.

The switch normally floods the frame out other eligible ports in the same  
VLAN, except the ingress port.

```text
             ┌── Gi0/2
             │
Incoming ─── Switch ── Gi0/3
Gi0/1        │
             └── Gi0/4
```

The frame remains within the relevant VLAN.

> **Exam point:**  
> **Known unicast → forward to the learned port.**  
> **Unknown unicast → flood within the VLAN.**

Broadcast and certain multicast traffic can also be flooded according to  
switching and multicast behavior.

---

# 6. CAM Entry Aging

Dynamic MAC entries are not kept forever.

They normally have an **aging timer**.

A commonly encountered Cisco IOS default is:

```text
300 seconds = 5 minutes
```

The exact default can vary by platform/software.

When a MAC entry ages out:

```text
MAC entry
   ↓
No longer active
   ↓
Aging timer expires
   ↓
Entry removed
```

When the switch receives traffic from that MAC again, it can relearn the  
entry.

### Why Aging Matters

If aging is too short:

- Entries may expire frequently.
    
- Unknown-unicast flooding can increase.
    
- The switch may need to relearn hosts repeatedly.
    

If aging is too long:

- Stale entries can remain longer after topology/host movement.
    
- Troubleshooting can become more difficult.
    

> **Exam point:** Activity from a source MAC refreshes its dynamic learning  
> state according to the platform's MAC-aging behavior.

---

# 7. MAC Movement / MAC Flapping

A **MAC move** occurs when the same MAC address is learned on different ports.

Example:

```text
AAAA.AAAA.AAAA → Gi0/1

Later:

AAAA.AAAA.AAAA → Gi0/2
```

The switch may update the MAC entry and generate a MAC-move/flapping message.

Possible causes include:

- Layer 2 loops
    
- Incorrect cabling
    
- Redundant paths
    
- STP topology changes
    
- A host physically moving
    
- Virtual machine mobility
    
- Hypervisor networking
    
- Duplicate MAC addresses
    
- HSRP/VRRP or other virtual MAC behavior
    
- Misconfigured switches
    

> **Exam trap:** A MAC move does **not automatically mean a rogue switch**.  
> Investigate the topology and traffic path.

---

# 8. CAM vs TCAM

CAM and TCAM are different hardware technologies.

## CAM

Traditional CAM is well suited to **exact-match lookups**, such as Layer 2  
MAC forwarding.

```text
MAC + VLAN
    ↓
Exact match
    ↓
Port
```

## TCAM

**TCAM = Ternary Content-Addressable Memory.**

TCAM supports three logical states:

```text
0
1
X = don't care
```

This allows hardware to perform more flexible matching.

TCAM is commonly used for:

- IP routing/prefix lookups
    
- ACLs
    
- QoS classification
    
- Policy matching
    
- Other hardware forwarding features
    

Example ACL-style matching:

```text
Source IP = 10.10.10.X
Destination IP = 192.168.10.X
Protocol = TCP
```

The `X`/don't-care capability makes TCAM suitable for these types of  
pattern/prefix matches.

> **Exam rule:**  
> **CAM → primarily exact-match Layer 2 lookups.**  
> **TCAM → ternary/pattern-based lookups such as routing, ACLs, and QoS.**

> Hardware architecture varies by Cisco platform. Do not assume every switch  
> has identical CAM/TCAM implementation or capacity.

# 9. MAC Address Table vs ARP Table

These tables answer different questions.

### MAC Address Table

Answers:

> **"Which switch port leads to this MAC address?"**

```text
MAC → VLAN → Port
```

### ARP Table

Answers:

> **"Which MAC address corresponds to this IPv4 address?"**

```text
IPv4 → MAC
```

Combining both can help determine where an IPv4 host is connected.

Example:

```text
ARP:

192.168.10.50 → AAAA.AAAA.AAAA

MAC Table:

AAAA.AAAA.AAAA → VLAN 10 → Gi0/5
```

Therefore:

```text
192.168.10.50
     ↓
AAAA.AAAA.AAAA
     ↓
VLAN 10 / Gi0/5
```

> **Exam troubleshooting model:**  
> **ARP = IP → MAC**  
> **CAM/MAC table = MAC → switch port**

---

# 10. CAM and VLANs

The VLAN is an important part of the Layer 2 forwarding context.

The same MAC address can legitimately appear in different VLANs.

Example:

```text
VLAN 10    AAAA.AAAA.AAAA → Gi0/1
VLAN 20    AAAA.AAAA.AAAA → Gi0/5
```

This does not necessarily represent a duplicate host.

The switch treats the entries as belonging to different Layer 2 broadcast  
domains.

> **Exam point:** Think of a CAM lookup as **MAC + VLAN context**, not simply  
> MAC address alone.

---

# 11. Port Security and CAM

**Port Security** can restrict which MAC addresses are allowed on a switch  
port.

It can use:

- Static secure MAC addresses
    
- Dynamically learned secure MAC addresses
    
- Sticky secure MAC addresses
    
- Maximum MAC address limits
    
- Violation modes
    

Common violation modes include:

```text
shutdown
restrict
protect
```

Conceptually:

```text
Port
  ↓
Allowed MAC addresses
  ↓
Incoming Source MAC
  ↓
Compare
  ↓
Allow / Violate
```

Port security is a security feature built around controlling MAC addresses  
per interface.

> **Exam note:** Port-security behavior, secure MAC persistence, and what  
> happens to entries after a violation depend on the configuration and  
> violation mode.

# 12. Configuration / Verification Commands

### Display the MAC Address Table

```cisco
show mac address-table
```

### Display MAC Addresses for a VLAN

```cisco
show mac address-table vlan 10
```

### Search for a Specific MAC

```cisco
show mac address-table address 001B.21AA.BBCC
```

### Display Dynamic MAC Entries

```cisco
show mac address-table dynamic
```

### Display Static MAC Entries

```cisco
show mac address-table static
```

### Display MAC Aging Information

```cisco
show mac address-table aging-time
```

### Display MAC Table Count

```cisco
show mac address-table count
```

This can help inspect MAC-table utilization, depending on platform/software  
support.

### Configure MAC Aging Time

```cisco
mac address-table aging-time 300
```

### Configure a Static MAC Entry

```cisco
mac address-table static AAAA.AAAA.AAAA vlan 10 interface GigabitEthernet0/1
```

# 13. Troubleshooting Workflow

When you know a host's MAC address:

```text
MAC Address
     │
     v
show mac address-table address <MAC>
     │
     v
VLAN + Switch Port
     │
     v
Check interface
     │
     v
Check neighboring device
```

For an IPv4 address:

```text
IPv4 Address
     │
     v
ARP table
     │
     v
MAC Address
     │
     v
MAC Address Table
     │
     v
Switch Port
```

Useful commands:

```cisco
show arp
show mac address-table address AAAA.AAAA.AAAA
show mac address-table vlan 10
show interfaces GigabitEthernet0/1
```

For suspected MAC movement:

```text
1. Identify the MAC.
2. Check its current port.
3. Look for MAC-move/flapping logs.
4. Check the connected device.
5. Trace neighboring switches.
6. Check STP topology.
7. Check for loops, redundant links, or duplicate MACs.
```

# 14. Exam Traps

- **CAM is primarily associated with Layer 2 exact-match MAC forwarding.**
    
- **TCAM is used for ternary/pattern matching**, including routing, ACLs,  
    QoS, and other features.
    
- A CAM/MAC-table lookup uses **MAC + VLAN context**.
    
- **Source MAC → learning.**
    
- **Destination MAC → forwarding lookup.**
    
- **Known unicast → forward to the learned port.**
    
- **Unknown unicast → flood within the VLAN**, except the ingress port and  
    subject to relevant switch features.
    
- A commonly encountered Cisco MAC aging default is **300 seconds / 5 minutes**.
    
- MAC aging defaults can vary by platform/software.
    
- Dynamic entries can be relearned when traffic arrives from the source MAC.
    
- The same MAC can legitimately exist in **different VLANs**.
    
- A MAC appearing on different ports can indicate **MAC movement/flapping**.
    
- MAC flapping does **not automatically mean a rogue switch**.
    
- Possible MAC-move causes include loops, STP changes, VM mobility, duplicate  
    MACs, redundant paths, and virtual MACs.
    
- **ARP = IPv4 → MAC.**
    
- **CAM/MAC table = MAC → VLAN/port.**
    
- Port security controls which MAC addresses are permitted on a port.
    
- CAM/TCAM capacity and implementation are **platform-dependent**.
    
- `show mac address-table` is the primary Cisco IOS command for examining the  
    Layer 2 MAC forwarding table.

# 16. One-Minute Mental Model

```text
                    Ethernet Frame
                          │
                          v
                 Source MAC Address
                          │
                          v
                   ┌─────────────┐
                   │    CAM      │
                   │ MAC + VLAN  │
                   └──────┬──────┘
                          │
                          v
                     Switch Port


Learning:
    Source MAC
        ↓
    Learn MAC + VLAN + Port


Forwarding:
    Destination MAC + VLAN
        ↓
    CAM Lookup
        ↓
    Known? ── YES ──→ Forward to port
        │
        NO
        ↓
    Flood within VLAN


Troubleshooting:
    IPv4
      ↓
    ARP
      ↓
    MAC
      ↓
    CAM/MAC Table
      ↓
    Switch Port
```

> **CCNP takeaway:**  
> **The CAM/MAC address table is the Layer 2 forwarding database. A switch  
> learns Source MAC addresses, associates them with VLANs and ports, and uses  
> Destination MAC lookups to forward known unicast frames. CAM is associated  
> with exact-match Layer 2 lookups, while TCAM provides ternary matching for  
> features such as routing, ACLs, and QoS.**
