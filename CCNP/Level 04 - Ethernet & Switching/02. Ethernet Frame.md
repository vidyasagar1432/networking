# Ethernet Frame

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

An **Ethernet frame** is the **Layer 2 data unit** used to transport upper-layer  
protocols such as IPv4, IPv6, and ARP across an Ethernet network.

A switch primarily examines the **Destination MAC**, **Source MAC**, VLAN  
information, and other Layer 2 fields to make forwarding decisions.

Understanding the Ethernet frame is essential for:

- MAC address learning
    
- MAC address forwarding
    
- EtherType
    
- VLAN tagging
    
- MTU and frame size
    
- FCS/CRC error detection
    
- Runts, giants, and baby giants
    

---

## 2. Ethernet Frame Structure

A standard Ethernet frame can be represented as:

```text
Preamble | SFD | Dest MAC | Src MAC | 802.1Q Tag | Type/Length | Payload | FCS
   7 B      1 B      6 B       6 B       4 B          2 B       46–1500 B  4 B
```

The **802.1Q tag is optional**.

### Untagged Ethernet II

```text
Dest MAC | Src MAC | EtherType | Payload | FCS
   6 B       6 B        2 B      46–1500 B  4 B
```

### 802.1Q-Tagged Ethernet

```text
Dest MAC | Src MAC | 802.1Q Tag | EtherType | Payload | FCS
   6 B       6 B        4 B          2 B      46–1500 B  4 B
```

> **Important:** Preamble and SFD are transmitted on the wire but are not  
> normally included when quoting Ethernet frame size.

---

## 3. Preamble and SFD

### 3.1 Preamble

**Size:** 7 bytes

The Preamble provides synchronization between the transmitting and receiving  
devices.

### 3.2 SFD

**Size:** 1 byte

The **Start Frame Delimiter (SFD)** indicates that the Ethernet frame is about  
to begin.

```text
Preamble          SFD
  7 B              1 B
   │                │
   └───────┬────────┘
           v
     Destination MAC
```

> **Exam point:** Preamble + SFD = **8 bytes transmitted**, but they are not  
> normally included in the Ethernet frame size calculation.

---

## 4. Destination MAC

**Size:** 6 bytes

The **Destination MAC** identifies the Layer 2 destination.

A switch uses the destination MAC to perform a MAC address table lookup.

Possible forwarding behavior:

- **Known unicast** → forward toward the learned port.
    
- **Unknown unicast** → flood within the VLAN.
    
- **Broadcast** → flood within the VLAN.
    
- **Multicast** → forwarding depends on multicast/switch configuration.
    

> **Exam rule:**  
> **Destination MAC → forwarding decision**

---

## 5. Source MAC

**Size:** 6 bytes

The **Source MAC** identifies the sender of the Ethernet frame.

A switch normally learns MAC addresses from the source MAC of incoming frames.

Example:

```text
Source MAC = AAAA.AAAA.AAAA
Incoming Port = Gi0/1
```

The switch can learn:

```text
AAAA.AAAA.AAAA → Gi0/1
```

> **Exam rule:**  
> **Source MAC → learning**

---

# 6. Type/Length Field

**Size:** 2 bytes

The field following the Source MAC can represent either:

- **Length** in IEEE 802.3 framing
    
- **EtherType** in Ethernet II framing
    

### EtherType

Values **greater than or equal to `0x0600`** are interpreted as EtherTypes.

Common examples:

|EtherType|Protocol|
|---|---|
|`0x0800`|IPv4|
|`0x0806`|ARP|
|`0x86DD`|IPv6|
|`0x8100`|IEEE 802.1Q|
|`0x88A8`|IEEE 802.1ad S-Tag / QinQ|

> **Exam trap:** `0x0800` means **IPv4 EtherType**, not an 800-byte length.

---

## 7. Ethernet II vs IEEE 802.3

### Ethernet II

Ethernet II uses the 2-byte field as an **EtherType**.

```text
Dest MAC | Src MAC | EtherType | Data | FCS
```

Examples:

```text
0x0800 → IPv4
0x0806 → ARP
0x86DD → IPv6
```

Ethernet II is the dominant framing format used by modern IP networks.

### IEEE 802.3

IEEE 802.3 can use the 2-byte field as a **Length** field.

The payload then uses **LLC** and, in some cases, **SNAP** to identify the  
upper-layer protocol.

```text
Dest | Src | Length | LLC/SNAP | Data | FCS
```

The distinction is based on the value of the 2-byte field:

```text
≤ 1500 decimal
    → Length

≥ 1536 decimal (0x0600)
    → EtherType
```

Values from **1501 through 1535** are reserved for this distinction.

> **Exam point:** IEEE 802.3 Ethernet framing is not Token Ring. Token Ring is  
> a separate IEEE technology.

---

# 8. IEEE 802.1Q VLAN Tag

An **802.1Q VLAN tag** adds **4 bytes** to the Ethernet frame.

```text
Dest MAC | Src MAC | TPID | TCI | EtherType | Payload | FCS
   6 B       6 B     2 B   2 B      2 B      46–1500 B  4 B
```

### 8.1 TPID

**TPID (Tag Protocol Identifier)** identifies a VLAN-tagged frame.

The standard 802.1Q TPID is:

```text
0x8100
```

### 8.2 TCI

**TCI (Tag Control Information)** contains:

```text
TCI = PCP | DEI | VLAN ID
       3     1      12 bits
```

|Field|Size|Purpose|
|---|--:|---|
|PCP|3 bits|Layer 2 priority / 802.1p|
|DEI|1 bit|Drop Eligibility Indicator|
|VLAN ID|12 bits|VLAN identification|

### VLAN ID

The VLAN ID field is 12 bits:

```text
0–4095
```

However:

- `0` is reserved for priority tagging.
    
- `4095` is reserved.
    
- Usable VLAN IDs are therefore commonly **1–4094**.
    

---

# 9. QinQ / IEEE 802.1ad

**QinQ** allows multiple VLAN tags to be stacked.

Conceptually:

```text
Dest | Src | Outer Tag | Inner Tag | EtherType | Payload | FCS
```

A common outer/provider TPID is:

```text
0x88A8
```

The inner customer VLAN tag commonly uses:

```text
0x8100
```

This allows service providers to transport customer VLANs while adding their  
own VLAN tag.

> **Exam point:** `0x88A8` is commonly associated with the outer S-Tag in  
> IEEE 802.1ad/QinQ, while `0x8100` is the standard 802.1Q TPID.

---

# 10. Payload

The Ethernet payload carries the upper-layer protocol.

Examples:

```text
Ethernet
   │
   ├── IPv4
   ├── IPv6
   └── ARP
```

For standard Ethernet:

```text
Minimum payload = 46 bytes
Maximum payload = 1500 bytes
```

If the actual data is smaller than 46 bytes, **padding** is added to satisfy  
the minimum Ethernet frame size.

> **Important:** A 1500-byte payload/MTU is not the same thing as a  
> 1500-byte total Ethernet frame.

---

# 11. Frame Check Sequence (FCS)

**Size:** 4 bytes

The **FCS (Frame Check Sequence)** is located at the end of the Ethernet frame.

It uses a CRC-based mechanism to detect transmission errors.

Conceptually:

```text
Ethernet Header + Payload
          │
          v
     CRC calculation
          │
          v
         FCS
```

If the received frame fails the FCS/CRC check, the receiver can identify the  
frame as corrupted and normally discards it.

Cisco interfaces may report errors using counters such as:

```text
CRC
input errors
frame
```

> **Exam points:**
> 
> - FCS is a **4-byte trailer**.
>     
> - FCS provides **error detection**, not error correction.
>     
> - Preamble and SFD are not part of the FCS calculation.
>     

---

# 12. Ethernet Frame Size

## 12.1 Minimum Frame Size

The minimum standard Ethernet frame size is:

```text
64 bytes
```

The 64-byte calculation starts at the Destination MAC and ends at the FCS:

```text
Destination MAC   6 B
Source MAC        6 B
Type/Length       2 B
Payload/Pad      46 B
FCS               4 B
                 ----
Total             64 B
```

Preamble and SFD are **not included**.

---

## 12.2 Maximum Standard Frame Size

For a standard Ethernet frame carrying a 1500-byte payload:

```text
Destination MAC    6 B
Source MAC         6 B
Type/Length        2 B
Payload         1500 B
FCS                4 B
                  ----
Total           1518 B
```

For an 802.1Q-tagged frame:

```text
Destination MAC    6 B
Source MAC         6 B
802.1Q Tag         4 B
Type/Length        2 B
Payload         1500 B
FCS                4 B
                  ----
Total           1522 B
```

|Frame Type|Maximum Standard Size|
|---|--:|
|Untagged Ethernet|**1518 bytes**|
|802.1Q tagged Ethernet|**1522 bytes**|

---

# 13. MTU vs Ethernet Frame Size

These terms are frequently confused.

### MTU

**MTU (Maximum Transmission Unit)** generally refers to the maximum Layer 3  
packet size that can be carried without fragmentation on an interface.

For standard Ethernet:

```text
IP MTU = 1500 bytes
```

### Ethernet Frame Size

The Ethernet frame includes Layer 2 overhead around the Layer 3 packet.

For a 1500-byte IP packet:

```text
Ethernet Header     14 B
IP Packet         1500 B
FCS                 4 B
                    ----
Total             1518 B
```

For an 802.1Q-tagged frame:

```text
Ethernet Header     14 B
802.1Q Tag           4 B
IP Packet         1500 B
FCS                 4 B
                    ----
Total             1522 B
```

> **Mental model:**
> 
> **MTU = maximum Layer 3 payload carried by Ethernet.**
> 
> **Frame size = Layer 2 header + payload + Layer 2 trailer.**

# 14. Runts, Giants, and Baby Giants

## 14.1 Runts

A **runt** is an Ethernet frame smaller than the minimum required frame size,  
typically less than **64 bytes** from Destination MAC through FCS.

Possible causes include:

- Physical-layer problems
    
- Collisions on legacy shared Ethernet
    
- Duplex mismatch
    
- Faulty hardware
    

---

## 14.2 Giants

A **giant** is a frame larger than the maximum frame size supported by the  
interface or platform.

---

## 14.3 Baby Giants

A **baby giant** is a frame slightly larger than the traditional 1518-byte  
Ethernet maximum but still accepted by some devices.

802.1Q-tagged frames are a classic example:

```text
1518 B → standard untagged maximum
1522 B → standard 802.1Q tagged maximum
```

> **Exam trap:** Do not automatically assume that every frame larger than  
> 1518 bytes is an error. Legitimate encapsulation can increase Layer 2 size.

---

# 15. Jumbo Frames

A **jumbo frame** is an Ethernet frame larger than the standard Ethernet  
maximum, supported through vendor/platform-specific capabilities.

A common configuration is approximately:

```text
MTU ≈ 9000 bytes
```

However, jumbo-frame support is **implementation-dependent**. All relevant  
devices/interfaces along the path must support the required frame size.

> **Exam trap:** A jumbo frame is not universally defined as exactly 9000 bytes.

---

# 16. What a Switch Reads

At a basic Layer 2 forwarding level:

```text
                  Ethernet Frame
                         │
        ┌────────────────┼────────────────┐
        │                │                │
        v                v                v
 Destination         Source MAC       VLAN Tag
    MAC                   │                │
        │                 │                │
        v                 v                v
   Forwarding          Learning       VLAN Context
      Lookup
```

### Destination MAC

Used for the forwarding decision.

### Source MAC

Used for MAC address learning.

### VLAN Tag

Provides VLAN information on tagged links.

### EtherType

Identifies the upper-layer protocol in Ethernet II.

> **Core switching model:**
> 
> **Source MAC → Learn**
> 
> **Destination MAC → Forward**
> 
> **VLAN Tag → VLAN**
> 
> **EtherType → Protocol**
> 
> **FCS → Error Detection**

---

# 17. Ethernet Frame Across a Switch

Switches normally forward the existing Ethernet frame without rewriting its  
source and destination MAC addresses.

```text
Host A
  │
  │ Src MAC = A
  │ Dst MAC = B
  v
Switch 1
  │
  v
Switch 2
  │
  v
Host B
```

The Ethernet MAC addresses normally remain the same across the Layer 2  
switching path.

> **Important:** A switch forwarding a frame is different from a router  
> forwarding a packet. A router creates a new Layer 2 frame for each outgoing  
> Layer 2 segment.

# 19. Exam Traps

- **Minimum Ethernet frame = 64 bytes.**
    
- The 64-byte count starts at **Destination MAC** and ends at **FCS**.
    
- **Preamble = 7 bytes.**
    
- **SFD = 1 byte.**
    
- Preamble + SFD are transmitted but are **not normally included in frame-size  
    calculations**.
    
- **Destination MAC → forwarding.**
    
- **Source MAC → learning.**
    
- **EtherType → upper-layer protocol identification** in Ethernet II.
    
- `0x0800` = IPv4.
    
- `0x0806` = ARP.
    
- `0x86DD` = IPv6.
    
- `0x8100` = common IEEE 802.1Q TPID.
    
- `0x88A8` = common IEEE 802.1ad S-Tag/QinQ TPID.
    
- **802.1Q adds 4 bytes.**
    
- Standard untagged maximum = **1518 bytes**.
    
- Standard 802.1Q tagged maximum = **1522 bytes**.
    
- **1500-byte MTU does not mean a 1500-byte total Ethernet frame.**
    
- **FCS = 4 bytes** at the end of the frame.
    
- FCS provides **error detection**, not error correction.
    
- A **runt** is below the minimum Ethernet frame size.
    
- A **giant** exceeds the supported maximum frame size.
    
- A **baby giant** may be slightly larger than 1518 bytes because of legitimate  
    encapsulation.
    
- Jumbo-frame support is **platform/vendor dependent**.
    
- Ethernet II uses **EtherType**.
    
- IEEE 802.3 can use a **Length** field followed by LLC/SNAP.
    
- IEEE 802.3 is **not Token Ring**.
    
- A switch normally **does not rewrite MAC addresses** while forwarding a frame.

# 21. One-Minute Mental Model

```text
                    Ethernet Frame
                          │
        ┌─────────────────┼─────────────────┐
        │                 │                 │
        v                 v                 v
 Destination           Source           Type/Length
    MAC                  MAC                  │
      │                    │                   │
      v                    v                   v
   FORWARD              LEARN              PROTOCOL
                                              │
                                              v
                                         Payload
                                              │
                                              v
                                             FCS
                                              │
                                              v
                                      ERROR DETECTION
```

Remember:

```text
Preamble       = 7 B
SFD            = 1 B

Destination MAC = 6 B
Source MAC      = 6 B
802.1Q Tag      = 4 B (optional)
Type/Length     = 2 B
Payload          = 46–1500 B
FCS              = 4 B

Minimum frame       = 64 B
Maximum untagged   = 1518 B
Maximum 802.1Q     = 1522 B
Typical IP MTU     = 1500 B
```

> **CCNP takeaway:**  
> **An Ethernet frame is the Layer 2 container used to transport Layer 3 data.  
> A switch learns from the Source MAC, forwards using the Destination MAC,  
> uses VLAN tags for VLAN context, uses EtherType to identify the encapsulated  
> protocol, and uses FCS for error detection.**
