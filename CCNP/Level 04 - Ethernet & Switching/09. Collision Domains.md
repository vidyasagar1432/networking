# Collision Domains

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **collision domain** is the set of devices that share the same transmission medium
such that only one may transmit at a time (else frames collide). It is segmented by
**switches/bridges** and eliminated by **full duplex** on switched links. It is the
L2, media-sharing counterpart to the broadcast domain — but with a different boundary.

---

## 2. Core Concepts

### 2.1 Where collisions come from
- On a **shared medium** (legacy coax bus, or a **hub**), multiple stations can
  transmit simultaneously → **collision** → both frames corrupted → CSMA/CD backoff
  and retry in half duplex.
- **Collision domain** simply means "couple of stations that can collide." One hub =
  one collision domain.

### 2.2 What segments the collision domain

| Device | Effect |
|--------|--------|
| **Hub** | extended (all connected hosts = 1 collision domain) |
| **Switch / bridge** | separates each port → each port = own collision domain |
| **Router** | any switch termination; own domain per interface |
| **Full-duplex link** | no collisions possible (n=0) |
- Microsegmentation: a 24-port switch = **24 collision domains** (each port ⇄ one host).

### 2.3 Collision domain vs broadcast domain — the table

| | Collision domain | Broadcast domain (Level 04 note) |
|--|------------------|----------------------------------|
| Contains | hosts that may collide | hosts that receive broadcasts |
| Bounded by | switches/bridges | routers |
| Hub | 1 (all) | 1 (grows) |
| Switch | per-port | per-VLAN |
| Full duplex | none | still per-VLAN |
| Example count | 24-port switch = 24 | same switch with 1 VLAN = 1 |

### 2.4 CSMA/CD — the mechanics (legacy)
1. **Carrier Sense**: listen before transmit.
2. **Multiple Access**: everyone uses the wire.
3. **Collision Detection**: if collision during transmission → jam signal → both back off
   (binary exponential backoff) → retransmit.
- Twisted-pair **half-duplex** (hub) used it; **full-duplex switched** doesn't need it.
- Modern networks: no collisions; the term survives in questions about hub/half-duplex
  and in the definition of why we stopped using hubs.

### 2.5 Design impact
- Full-duplex switch-to-switch/host = no wasted bandwidth on backoff.
- "One host per switched port" maximises effective bandwidth (a host gets the port's
  full rate).
- Legacy questions may ask: "switch with 12 hosts and 2 uplinks — collision domains?"
  → 12 access ports + 2 uplinks = **14** (unless bundled EtherChannel counts per port).

## 3. Configuration / Commands

```text
# Full duplex everywhere on modern switches (auto handles it)
interface GigabitEthernet0/1
 duplex full
# Look for legacy collision counter (will be zero/irrelevant on FDX)
show interfaces GigabitEthernet0/1 | include "(duplex|collision)"
```

---

## 4. Exam Traps

- **"A switch creates one collision domain per port" — most common number question.**
- **Hubs do NOT segment** a collision domain (they extend it).
- **Full duplex ⇔ no collisions** — a hub server isn't full duplex so its port = part
  of the hub's domain.
- **Don't confuse with broadcast domain** — boundary device differs (switch vs router).
- In modern exams: "collision domains on a full-duplex switched network" → effectively
  one per port; broadcast domains governed by VLANs.
