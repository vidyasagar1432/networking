# Forwarding

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Forwarding** is the switch's decision of **where to send a received frame** based
on its **destination MAC** and the CAM table. Combined with learning (Level 04) and
flooding/filtering, it completes the L2 forwarding pipeline: *learn from src, forward
by dst, flood if unknown, filter what's not yours*.

---

## 2. Core Concepts

### 2.1 The forwarding decision (per frame)
1. Receive frame on port p in VLAN V.
2. **Learn** source MAC → p.
3. Look up **destination MAC + VLAN** in CAM:
   - **Found, on another port** → forward only out that port (unicast).
   - **Found, on the *same* port** → **filter/drop** (dest is already on the ingress segment, no need to echo back).
   - **Not found** → **flood** (Level 05).
   - **Broadcast** → flood. **Multicast** → flood or mapped by snooping.
4. **Transmit** with appropriate (possibly tagged) egress.

### 2.2 Forwarding is hardware
- Switches forward in **ASIC hardware** (line rate) — per-port bandwidth independent
  of other ports; no CPU involvement except overflow/exceptional frames.
- **MAC table lookup = CAM** (fast, deterministic) or TCAM on ASICs for marked/ACL.

### 2.3 Cut-through vs store-and-forward

| Mode | When to transmit | Pros | Cons |
|------|------------------|------|------|
| **Store-and-forward** | after receiving whole frame | checks FCS → no bad frames; needed for QoS reclassification | adds frame-length latency |
| **Cut-through** | after dest MAC + header | very low latency | forwards corrupt frames (no FCS check) |
| **Fragment-free** | after 64 B | compromise | mid-length drop |
Cisco switches default to **store-and-forward** (with cut-through options on some ASICs).

### 2.4 Forwarding vs routing

| | L2 Forwarding | L3 Routing |
|--|---------------|------------|
| Table | CAM (MAC→port) | RIB/FIB (network→next hop) |
| Decision | dest MAC same VLAN | dest IP across VLANs |
| unit | frame | packet (frames rest on each link) |
| Devices | switches | routers / L3 switches |
| Broadcast handling | floods within VLAN | routed domains |

### 2.5 Forwarding failures to know
- Port flapping / CAM misses → repeated flooding.
- **MAC aging** → re-flooding every 5 min until relearned.
- **STP blocked port** in the path → no forwarding (Level 08) — a common "why no other
  path used" gotcha.

## 4. Exam Traps

- **A switch does NOT change the destination MAC.** It forwards by dest MAC as-is.
- **Forwarding IS done even before learning completes** — unknown dest floods.
- **Same ingress/egress port case** — the switch must not forward back out the ingress
  port (filter) — a classic filter-vs-forward trap.
- **Different-vlan frames can't cross without routing** — L2 forwarding stays in one VLAN.
- **Store-and-forward runs FCS check; cut-through doesn't** — the error-check question.
