# Gratuitous ARP

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **Gratuitous ARP (GARP)** is an **unsolicited ARP Request** in which a host
announces **its own IP→MAC mapping** even though nobody asked. It is used for
**duplicate IP detection, MAC updates, and failover signaling** — the invisible
glue behind DHCP, HSRP/VRRP, and NIC failover.

---

## 2. Core Concepts

### 2.1 What is sent
- Opcode = **ARP Request**, sender (both sender IP and target IP) = **own IP**,
  target MAC = broadcast.
- Dest MAC = broadcast; every host on the segment learns/overwrites the sender's IP→MAC.

### 2.2 Three main uses
1. **Duplicate IP detection** (e.g., a new host checks if some other already owns an IP).
2. **MAC update after change or failover** — tell everyone "this IP is now at this MAC"
   (cache refresh).
3. **Virtual/HSRP/VRRP failover** — the new active gateway sends GARP so switches and
   hosts instantly update MAC mapping (no ARP timeout wait).

### 2.3 GARP vs normal ARP (the table)

| | Normal ARP | Gratuitous ARP |
|--|------------|----------------|
| Trigger | needed for resolution | no request; proactive |
| Opcode | request/reply | request (own IP) |
| Target IP | someone else's | sender's own |
| Purpose | find MAC | broadcast a mapping change |
| Dest | broadcast (req) / unicast (reply) | broadcast |

### 2.4 In real designs
- **HSRP/VRRP (Level 14)**: new active sends GARPs to redirect traffic to the new MAC.
- **DHCP client**: after obtaining an IP, announces to detect conflicts (ARP probe).
- **NIC teamed/cabled failover** (by driver) after a NIC change.
- Some stacks discard GARP by default (security); some do not — platform-dependent.

### 2.5 Security side
- GARP is a **spoofing vector** (ARP poisoning uses GARP). mitigations: **DAI**
  (snooping the DHCP → check IP/MAC bindings), static ARP, port security.

```text
# Re-trigger a GARP manually by clearing HSRP state (test):

```

---

## 4. Exam Traps

- **GARP is an ARP *request* for its own address** — not a reply, and not "asking again."
- **Who generates it:** failover gateway (HSRP/VRRP), DHCP conflict detection, NIC bonding.
- **It updates the rest of the L2 domain's ARP caches** — that's the "instant update" value.
- **Spoofing**: GARP can poison the ARP/DHCP binding — enabled by DAI.
- **IPv6 doesn't have GARP** — uses DAD via NDP instead.
