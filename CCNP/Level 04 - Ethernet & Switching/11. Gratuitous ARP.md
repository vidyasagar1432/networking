# Gratuitous ARP (GARP)

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Gratuitous ARP (GARP)** is an **unsolicited ARP message** used by a device to  
announce or refresh the association between **its own IPv4 address and MAC address**  
on the local Layer-2 segment.

The most common GARP format is an **ARP Request where the sender IP address and  
target IP address are the same**.

GARP is commonly used for:

- Detecting or announcing duplicate IPv4 addresses
    
- Updating neighboring ARP caches after a MAC change
    
- Gateway/high-availability failover
    
- NIC teaming/bonding or interface failover
    

> **Key idea:** GARP lets a device proactively announce an IPv4-to-MAC mapping  
> instead of waiting for another device to perform normal ARP resolution.

---

## 2. Core Concepts

### 2.1 What Is Sent?

A common GARP Request looks like:

```text
ARP Opcode       = Request (1)
Sender IP        = 10.1.1.10
Sender MAC       = AA:AA:AA:AA:AA:AA
Target IP        = 10.1.1.10
Target MAC       = 00:00:00:00:00:00
```

The Ethernet frame is normally sent to:

```text
FF:FF:FF:FF:FF:FF
```

Notice the important distinction:

```text
Ethernet Destination MAC = FF:FF:FF:FF:FF:FF
ARP Target MAC           = 00:00:00:00:00:00
```

The target MAC field in the ARP message is **not the Ethernet broadcast MAC**.

A host receiving the announcement may update its ARP cache with:

```text
10.1.1.10 -> AA:AA:AA:AA:AA:AA
```

However, whether and how a host processes unsolicited ARP announcements is  
**implementation/platform dependent**.

---

## 3. Main Uses of Gratuitous ARP

### 3.1 Announcing a MAC Address Change

Suppose a device's IPv4 address remains the same but its MAC address changes:

```text
Before:

10.1.1.10 -> MAC-A

After:

10.1.1.10 -> MAC-B
```

The device can send GARP to announce:

```text
10.1.1.10 -> MAC-B
```

Neighboring devices may then update their ARP caches.

This avoids waiting for old ARP entries to age out.

---

### 3.2 High-Availability Failover

GARP is commonly used with first-hop redundancy/failover mechanisms such as  
**HSRP** and **VRRP**.

Example:

```text
                 Virtual Gateway
                    10.1.1.1
                       |
              +--------+--------+
              |                 |
           R1 Active         R2 Standby
```

If R1 fails:

```text
              Before
                |
              R1 ACTIVE
                |
                X
              FAILOVER
                |
              R2 ACTIVE
```

The newly active device can send ARP announcements so neighboring devices can  
quickly update their ARP information.

Conceptually:

```text
10.1.1.1 -> New Active Gateway MAC
```

This helps redirect traffic without waiting for existing ARP-cache entries to  
expire.

> **Exam concept:** GARP is an important mechanism for quickly updating  
> IPv4-to-MAC information after a gateway failover.

---

### 3.3 Duplicate IP Detection

GARP-related ARP mechanisms can be used to detect IPv4 address conflicts.

However, do **not** confuse a traditional GARP announcement with an **ARP probe**.

An ARP probe is commonly used before a host claims an IPv4 address and uses:

```text
Sender IP = 0.0.0.0
Target IP = address being tested
```

For example:

```text
"Is anyone using 10.1.1.10?"
```

If another device responds or otherwise indicates ownership, the address may  
already be in use.

> **CCNP distinction:** ARP probe = conflict detection before claiming an address.  
> GARP = unsolicited announcement/update of an address-to-MAC association.

---

### 3.4 NIC Teaming / Interface Failover

NIC teaming, bonding, or similar failover mechanisms can generate gratuitous  
ARP announcements after traffic moves from one interface/device to another.

Example:

```text
Before:

10.1.1.10 -> MAC-A

NIC failure

After:

10.1.1.10 -> MAC-B
```

A GARP announcement can notify neighboring devices of the new MAC association.

The exact behavior depends on the operating system, NIC driver, teaming/bonding  
implementation, and network design.

## 4. GARP vs Normal ARP

|Aspect|Normal ARP|Gratuitous ARP|
|---|---|---|
|Trigger|Need to resolve an IPv4 address|Proactive announcement|
|Typical purpose|Discover next-hop MAC|Announce/update own IPv4-to-MAC mapping|
|Common opcode|Request + Reply|Commonly Request|
|Sender IP|Sender's own IP|Commonly sender's own IP|
|Target IP|Another device's IP|Commonly sender's own IP|
|Ethernet destination|Broadcast for Request|Normally broadcast|
|Target MAC field|Depends on message|Commonly `00:00:00:00:00:00`|
|Cache effect|Resolves a mapping|May refresh/update existing mappings|
|Typical use|Normal communication|Failover/MAC change/announcement|

> GARP is **not simply "ARP again."** It is an unsolicited ARP announcement.

## 5. GARP and ARP Cache Updates

Consider:

```text
Host A
10.1.1.10
MAC-A
```

Host A sends GARP:

```text
10.1.1.10 is at MAC-A
```

Other devices on the same Layer-2 segment may update their ARP cache:

```text
10.1.1.10 -> MAC-A
```

If the MAC changes:

```text
10.1.1.10 -> MAC-B
```

another GARP can announce the new association:

```text
10.1.1.10 is at MAC-B
```

This is useful because devices do not necessarily need to wait for the old  
ARP entry to expire.

> **Important:** GARP does not guarantee that every device will accept or update  
> its ARP cache. Processing behavior is platform dependent.

---

## 6. GARP and Switching

GARP is also relevant to the switch's **MAC address learning**.

When a GARP frame arrives from a new MAC address, the switch can learn:

```text
MAC-B -> Gi0/10
```

in its CAM/MAC address table, assuming normal MAC learning applies.

This is separate from the host's ARP cache:

```text
Host ARP cache:

10.1.1.10 -> MAC-B


Switch CAM table:

MAC-B -> Gi0/10
```

> **Remember:** ARP resolves **IPv4 → MAC**.  
> The switch learns **MAC → port**.

## 7. Security Considerations

GARP can be abused for **ARP spoofing/poisoning**.

A malicious device could send a forged announcement such as:

```text
10.1.1.1 is at AA:AA:AA:AA:AA:AA
```

If `10.1.1.1` is the default gateway, devices that accept the forged information  
could associate the gateway IP with the attacker's MAC.

Possible consequences include:

- Man-in-the-middle attacks
    
- Traffic interception
    
- Traffic redirection
    
- Denial of service
    

### Cisco Mitigation

The primary Cisco Layer-2 security feature to know is:

**Dynamic ARP Inspection (DAI)**

DAI can validate ARP packets against trusted IP/MAC bindings, commonly obtained  
through **DHCP Snooping**.

Conceptually:

```text
DHCP Snooping
      |
      v
IP/MAC Binding Database
      |
      v
Dynamic ARP Inspection
      |
      v
Validate ARP
      |
   +--+--+
   |     |
 Valid  Invalid
   |     |
Forward  Drop
```

> **CCNP exam point:** Know **DAI + DHCP Snooping** as the primary Cisco  
> protection against ARP spoofing/poisoning.

## 8. IPv6 Comparison

IPv6 does **not use ARP**.

Instead, IPv6 uses **Neighbor Discovery (ND)** through **ICMPv6**.

For duplicate-address detection, IPv6 uses:

**Duplicate Address Detection (DAD)**

DAD uses Neighbor Solicitation/Neighbor Advertisement messages rather than ARP.

|IPv4|IPv6|
|---|---|
|ARP|Neighbor Discovery|
|ARP Request|Neighbor Solicitation|
|ARP Reply|Neighbor Advertisement|
|ARP-based conflict detection|DAD|
|GARP|No IPv6 equivalent of ARP/GARP|

> **Exam trap:** Do not say IPv6 uses GARP. IPv6 uses **ND/ICMPv6**, including  
> **DAD** for duplicate-address detection.

## 9. Configuration / Verification

There is generally **no universal Cisco IOS command that simply means  
"send a GARP now."**

GARP/ARP announcements are normally generated automatically by hosts,  
interfaces, or protocols such as first-hop redundancy mechanisms.

### View ARP Entries

```text
show arp
show ip arp
```

### Filter an ARP Entry

```text
show ip arp | include 10.1.1.10
```

### Debug ARP

```text
debug arp
```

Disable debugging afterward:

```text
undebug all
```

or:

```text
u all
```

> The exact ability to manually trigger a GARP depends on the platform,  
> interface, and protocol involved.

## 10. Troubleshooting GARP

When investigating a MAC/IP change or gateway failover:

### Step 1 — Check the ARP table

```text
show ip arp
```

Verify that the expected mapping exists:

```text
10.1.1.1 -> Expected Gateway MAC
```

### Step 2 — Check the switch MAC table

```text
show mac address-table
```

Verify where the MAC address is currently learned.

### Step 3 — Check ARP inspection

If DAI is enabled:

```text
show ip arp inspection
```

Also check DHCP Snooping bindings:

```text
show ip dhcp snooping binding
```

### Step 4 — Capture ARP traffic

A packet capture can identify:

- ARP Requests
    
- ARP Replies
    
- Gratuitous ARP announcements
    
- Unexpected ARP changes
    
- Potential ARP spoofing

## 11. Exam Traps

- **GARP is unsolicited ARP traffic.**
    
- The common GARP format is an **ARP Request for the sender's own IPv4 address**.
    
- GARP is **not exclusively defined as an ARP Request**; implementations can use  
    different ARP announcement forms.
    
- In a common GARP Request:
    
    - Sender IP = own IP
        
    - Target IP = own IP
        
    - Ethernet destination = broadcast
        
    - Target MAC field = commonly `00:00:00:00:00:00`
        
- **Do not confuse Ethernet broadcast MAC with the ARP target MAC field.**
    
- GARP can help update neighboring ARP caches after a MAC change or failover.
    
- **ARP probe** and **GARP** are related but not identical.
    
- ARP probe commonly uses **sender IP `0.0.0.0`** for duplicate-address detection  
    before an address is configured.
    
- HSRP/VRRP failover can use ARP announcements to accelerate gateway MAC updates.
    
- GARP can be abused for **ARP spoofing/poisoning**.
    
- **DAI** is the key Cisco protection against ARP spoofing.
    
- DAI commonly relies on **DHCP Snooping bindings**.
    
- IPv6 uses **ND/ICMPv6**, not ARP or GARP.
    
- IPv6 duplicate-address detection uses **DAD**.

## 13. One-Minute Mental Model

```text
Normal ARP:

"Who has 10.1.1.1?"
        |
        v
Find the MAC
        |
        v
10.1.1.1 -> MAC


GARP:

"I am 10.1.1.1 and my MAC is MAC-B."
        |
        v
Announce the mapping
        |
        v
10.1.1.1 -> MAC-B
```

### Remember

> **Normal ARP asks: "Who has this IPv4 address?"**

> **GARP proactively announces: "This IPv4 address is associated with this MAC."**

> **ARP probe asks: "Is anyone already using this IPv4 address?"**
