# CEF Basics

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Cisco Express Forwarding (CEF)** is Cisco's **high-performance IP forwarding  
architecture**.

CEF separates the **control plane** from the **data plane**:

- Routing protocols and static routes build the **RIB (Routing Information Base)**.
    
- CEF derives the **FIB (Forwarding Information Base)** from the RIB.
    
- CEF maintains **adjacency information** for the Layer-2 rewrite needed to forward  
    packets.
    
- On hardware platforms, this forwarding information is programmed into forwarding  
    ASICs/TCAM structures for hardware-based forwarding.
    

Instead of performing a complete routing-table lookup for every packet, the router  
can use the precomputed FIB and adjacency information.

> **Key idea:**  
> **RIB = routing knowledge**  
> **FIB = forwarding decisions**  
> **Adjacency = Layer-2 rewrite information**

---

## 2. Control Plane vs Data Plane

Understanding CEF starts with separating routing from forwarding.

```text
                 CONTROL PLANE
                      |
          Routing Protocols / Static Routes
                      |
                      v
                    RIB
                      |
                 CEF builds
                      |
                      v
                    FIB
                      |
                      v
               Adjacency Info
                      |
                      v
                 DATA PLANE
                      |
                      v
                  Packet
                      |
                      v
                  Forward
```

### Control Plane

The control plane determines **where networks are reachable**.

Examples:

- OSPF
    
- EIGRP
    
- BGP
    
- Static routes
    
- Connected routes
    

These populate the **RIB**.

### Data Plane

The data plane determines **how to forward each packet**.

CEF provides the structures used for efficient forwarding:

```text
FIB + Adjacency Information
```

---

## 3. CEF's Main Data Structures

### 3.1 FIB — Forwarding Information Base

The **FIB** is derived from the RIB and contains optimized forwarding information.

Conceptually:

```text
RIB:

10.10.10.0/24
   |
   | CEF derives
   v
FIB:

10.10.10.0/24 -> next-hop / adjacency
```

The FIB is optimized for **longest-prefix-match forwarding**.

Example:

```text
10.0.0.0/8
10.10.0.0/16
10.10.10.0/24
```

For destination:

```text
10.10.10.50
```

The most specific matching route wins:

```text
10.10.10.0/24
```

> **Exam point:** CEF forwarding uses the **FIB**, not a fresh full RIB lookup  
> for every packet.

---

## 4. Adjacency Table

The FIB determines the forwarding path, but the router also needs the information  
required to construct the outgoing Layer-2 frame.

That information is maintained in the **adjacency table**.

For an Ethernet next hop, this can include:

```text
Outgoing Interface
Next-Hop MAC
Layer-2 Rewrite Information
```

Example:

```text
FIB:

10.2.2.0/24
    |
    v
Next hop: 192.168.1.2
    |
    v
Adjacency:

192.168.1.2
MAC = AABB.CCDD.EEFF
Interface = GigabitEthernet0/0
```

The router can then construct the Ethernet frame without having to resolve the  
next-hop MAC from scratch for every packet.

> ARP can provide the IPv4 next-hop MAC information used to build an Ethernet  
> adjacency. IPv6 uses Neighbor Discovery instead.

---

## 5. RIB vs FIB vs Adjacency

|Component|Purpose|
|---|---|
|**RIB**|Contains routes learned from connected, static, and routing-protocol sources|
|**FIB**|Optimized forwarding information derived from the RIB|
|**Adjacency**|Layer-2 rewrite information for the next hop|
|**CEF**|Architecture that uses the FIB and adjacency information for efficient forwarding|

A useful mental model:

```text
Routing Protocols
       |
       v
      RIB
       |
       v
      FIB
       |
       +------> Adjacency
       |
       v
    Forwarding
```

## 6. How CEF Forwards a Packet

Suppose R1 receives:

```text
Destination IP = 10.10.10.50
```

### Step 1 — FIB Lookup

CEF searches the FIB for the destination.

```text
10.10.10.50
     |
     v
10.10.10.0/24
     |
     v
Next hop = 192.168.1.2
```

### Step 2 — Adjacency Lookup

CEF obtains the Layer-2 rewrite information:

```text
Next hop = 192.168.1.2
MAC      = AABB.CCDD.EEFF
```

### Step 3 — Rewrite and Forward

The router creates the outgoing frame:

```text
Destination MAC = AABB.CCDD.EEFF
Source MAC      = Router's outgoing-interface MAC
IP Destination = 10.10.10.50
```

Then the packet is transmitted.

```text
Incoming Packet
      |
      v
   FIB Lookup
      |
      v
Adjacency Lookup
      |
      v
L2 Rewrite
      |
      v
   Forward
```

## 7. Why CEF Is Faster

Older Cisco forwarding mechanisms included:

### Process Switching

The CPU performs significant forwarding work for packets individually.

Conceptually:

```text
Packet
  |
  v
CPU
  |
  +--> Routing lookup
  |
  +--> Rewrite
  |
  v
Forward
```

This is inefficient for high packet rates.

### CEF

CEF precomputes forwarding information:

```text
             Before traffic arrives

RIB
 |
 v
FIB + Adjacency
 |
 v
Precomputed forwarding information


             Packet arrives

Packet
  |
  v
FIB lookup
  |
  v
Adjacency
  |
  v
Rewrite
  |
  v
Forward
```

> **Key advantage:** CEF avoids performing a complete routing decision from  
> scratch for every packet.

## 8. CEF on Hardware Platforms

On Cisco hardware forwarding platforms, CEF-derived information can be programmed  
into forwarding ASICs.

These platforms can use resources such as:

- ASICs
    
- TCAM
    
- Hardware forwarding tables
    

Conceptually:

```text
RIB
 |
 v
CEF / FIB
 |
 v
Hardware forwarding tables
 |
 v
ASIC / TCAM
 |
 v
Line-rate forwarding
```

### Important distinction

**CEF is not the same thing as TCAM.**

```text
CEF
 |
 +--> FIB
 |
 +--> Adjacency
 |
 v
Hardware platform may program
these forwarding decisions into
ASIC/TCAM structures
```

TCAM is a **hardware implementation resource**, while CEF is a **forwarding  
architecture**.

> **Exam trap:** Do not answer "TCAM" when the question asks for the Cisco  
> forwarding architecture.

---

## 9. Longest Prefix Match

CEF follows normal IP routing rules, including **Longest Prefix Match (LPM)**.

Example FIB:

```text
10.0.0.0/8
10.10.0.0/16
10.10.10.0/24
```

Destination:

```text
10.10.10.50
```

Matches:

```text
10.0.0.0/8
10.10.0.0/16
10.10.10.0/24
```

The `/24` is selected because it is the **most specific match**.

> CEF does not change the fundamental IP routing rule of longest-prefix match.

---

## 10. CEF Load Balancing

CEF can perform load balancing across **equal-cost paths**.

Example:

```text
             Destination
                 |
                 v
              Router
              /    \
             /      \
          Path A    Path B
```

If both paths are eligible:

```text
10.10.10.0/24
   |
   +---- Next hop A
   |
   +---- Next hop B
```

CEF normally uses a **hash-based per-flow/per-destination approach**, depending  
on platform and configuration.

The hash can use packet information such as:

- Source IP
    
- Destination IP
    
- Layer-4 ports, depending on the configured hashing method/platform
    

The purpose is to keep packets belonging to the same flow on the same path and  
avoid unnecessary packet reordering.

### Per-Packet Load Balancing

Cisco also has/had platform-specific options for per-packet load sharing, but  
per-packet forwarding can cause packets from the same flow to arrive out of order.

Therefore, **per-flow/per-destination hashing is generally preferred**.

> **Exam concept:** CEF normally provides **flow-based load balancing**, not  
> round-robin packet-by-packet forwarding.

---

## 11. CEF and Adjacency States

An adjacency represents the information required to rewrite and forward a packet  
toward a next hop.

Common concepts include:

- Complete adjacency
    
- Incomplete adjacency
    
- Drop adjacency
    
- Punt adjacency
    
- Null adjacency
    

For example, if the router needs an Ethernet next-hop MAC but ARP resolution  
has not completed, the adjacency may be incomplete.

Conceptually:

```text
FIB
 |
 v
Next hop
 |
 v
Adjacency
 |
 +---- Complete ------> Forward
 |
 +---- Incomplete ----> Resolution/pending
 |
 +---- Drop ----------> Drop
 |
 +---- Punt ----------> CPU/control processing
```

> Do not assume that every missing or incomplete adjacency means exactly the  
> same thing on every Cisco platform. Adjacency behavior is platform dependent.

## 12. Troubleshooting CEF

### 12.1 Check the FIB

```text
show ip cef
```

For a particular destination:

```text
show ip cef 10.10.10.50
```

Detailed information:

```text
show ip cef 10.10.10.50 detail
```

### 12.2 Check the Routing Table

Always compare CEF with the RIB:

```text
show ip route
```

For a specific destination:

```text
show ip route 10.10.10.50
```

The troubleshooting relationship is:

```text
Routing Problem?
      |
      v
     RIB
      |
      v
Forwarding Problem?
      |
      v
     FIB
      |
      v
Next-hop/L2 Problem?
      |
      v
 Adjacency / ARP
```

### 12.3 Check Adjacencies

```text
show adjacency
```

Depending on platform/software version, additional CEF/adjacency commands may  
be available.

### 12.4 Check Interface CEF Status

```text
show ip interface GigabitEthernet0/0
```

Look for CEF-related forwarding information where supported.

> Command availability and output can vary between Cisco IOS/IOS XE platforms.

## 13. RIB Present but FIB Missing

A route appearing in the routing table does not automatically mean that you  
have verified successful forwarding.

For troubleshooting, compare:

```text
show ip route <destination>
show ip cef <destination>
```

Then check the next-hop adjacency:

```text
show adjacency
```

Also verify the underlying next-hop resolution:

```text
show ip arp
```

A useful troubleshooting chain is:

```text
RIB
 |
 | Is route installed?
 v
FIB
 |
 | Is forwarding entry present?
 v
Adjacency
 |
 | Is next-hop rewrite available?
 v
Interface
 |
 v
Packet forwarding
```

## 14. CEF Configuration

On many modern Cisco platforms, CEF is enabled by default.

Historically, CEF could be explicitly enabled with:

```text
ip cef
```

Verify CEF/FIB information with:

```text
show ip cef
```

Do not treat `ip cef` as a routine configuration command on every modern  
platform. The exact command support and default behavior depend on the  
Cisco IOS/IOS XE platform and release.

## 15. Exam Traps

- **CEF is a forwarding architecture, not simply "hardware acceleration."**
    
- **RIB ≠ FIB.**
    
- RIB contains routing information; FIB contains optimized forwarding information.
    
- CEF derives the FIB from the RIB.
    
- **Adjacency information provides Layer-2 rewrite information** for forwarding.
    
- ARP can provide IPv4 next-hop MAC information used to build Ethernet adjacency.
    
- IPv6 uses Neighbor Discovery rather than ARP.
    
- **CEF is not the same thing as TCAM.**
    
- Hardware platforms can program CEF-derived forwarding information into  
    ASIC/TCAM structures.
    
- CEF forwarding uses **Longest Prefix Match**.
    
- CEF normally uses **flow-based/per-destination hashing** for ECMP.
    
- Per-packet load balancing can cause packet reordering.
    
- A route in the RIB should be checked against the **FIB and adjacency** when  
    troubleshooting forwarding.
    
- `show ip route` checks the RIB.
    
- `show ip cef` checks the FIB.
    
- `show adjacency` checks adjacency information.
    
- CEF does not eliminate ARP/ND; the router still needs next-hop Layer-2  
    resolution when required.
    
- Do not assume that an incomplete adjacency has exactly the same forwarding  
    behavior on every Cisco platform.
    
- `clear ip cef` should **not** be used as a first-line troubleshooting fix.  
    Determine why the FIB/adjacency is incorrect before rebuilding forwarding state.
