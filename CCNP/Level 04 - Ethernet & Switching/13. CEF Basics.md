# CEF Basics

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Cisco Express Forwarding (CEF)** is the hardware-accelerated forwarding architecture
that removes per-packet route lookup from the slow path. It pre-builds a **FIB** and
an **adjacency table** so each packet is switched at line rate in the data plane.
Understanding CEF's data structures (FIB/adjacency, plus TCAM on hardware switches) is
needed for load-balancing and troubleshooting (Level 09, Level 29).

---

## 2. Core Concepts

### 2.1 The CEF two tables

| Table | Built from | Content |
|-------|-----------|---------|
| **FIB (Forwarding Information Base)** | routing table (RIB) | prefixes → next-hop / adjacency pointer |
| **Adjacency table** | ARP / next-hop resolution | L2 rewrite info (MAC for each next hop) |

### 2.2 Why CEF matters (vs process/ fast switching)

| | Process (slow path) | CEF (fast path) |
|--|---------------------|-----------------|
| Lookup | CPU per packet (route cache misses) | FIB in hardware |
| Speed | route-processor bound | line rate |
| Next-hop rewrite | computed per packet | adjacency table cached |
| Reset/act | may ARP; may dip | build once, reuse |

### 2.3 CEF on hardware switches (L2/L3)
- A L3 switch's **TCAM** pre-programs prefix→output-port with the FIB; packet headers
  are matched in ASIC → **hardware forwarding**, not CPU.
- **Longest-prefix-match** still applies (TCAM entries ordered by prefix length; more
  specific wins) — Level 09.

### 2.4 Load-balancing with CEF
- CEF balances across equal-cost paths (ECMP) using a **hash** of packet fields
  (default: source+dst IP; with layer4 hash: also ports).
- **Per-flow**, not per-packet — avoids reordering; hash picks one of the equal next hops.
- Config eligible: `ip load-sharing per-destination | per-packet` (mostly per-destination).

### 2.5 Troubleshooting with CEF commands
- `show ip cef <prefix>` — verify the FIB entry for a destination; down next hop?
- `show adjacency` — L2 rewrite per next hop; no ARP = "Attached" state missing.
- A prefix in RIB but not FIB (or `show ip cef` missing) → forwarding is broken even
  though routing "looks fine." Also `clear ip cef` / reload to rebuild.

## 3. Configuration / Commands

```text
ip cef                        # enable (default on most modern platforms)
show ip cef
show ip cef <dest-prefix> detail    # which Egress next hop
show adjacency
show ip interface gig0/1 | include CEF
show cef platform ?
```

## 4. Exam Traps

- **CEF = FIB + adjacency** (two structures; not just "a faster route lookup").
- **Routing table (RIB) and FIB differ** — CEF is built from RIB; questions about
  "packet forwarding uses FIB" → answer CEF path.
- **Drop implications**: no adjacency (missing ARP to next hop) = traffic not forwarded
  though route exists.
- **Load balance hash on flow (per-destination)** default on, keeps per-flow order.
- **Don't mix** CEF Layer-2 CAM (MAC) vs Layer-3 TCAM/FIB for prefix lookups.
