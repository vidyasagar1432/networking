# Flooding

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Flooding** is the switch forwarding behavior of sending a frame out **all ports in
the incoming VLAN** (except the receiving port, and typically excluding STP-blocked
ports) when the destination MAC is **unknown** to the CAM table. It is a necessity
of MAC learning — and also the mechanism behind **broadcast storms**.

---

## 2. Core Concepts

### 2.1 When does a switch flood?
- **Unknown unicast**: dest MAC not in CAM (new host, aged entry, or cache loss).
- **Broadcast** (`FF:FF:FF:FF:FF:FF`): always flooded (to intended receivers — ARP, DHCP).
- **Multicast**: flooded unless IGMP snooping/interfaces with group state (Level 04/19).
- Initially (brand-new switch, all empty table), the first frames to everyone are flooded.

### 2.2 Flooding scope
- Flood is **within a single VLAN (broadcast domain)** only. A trunk carries the frame
  only into the specified VLAN; a frame never floods into another VLAN (L2 boundary).
- On trunk links: flooded frames go out tagged in that VL who, but STP-blocked links are skipped.

### 2.3 Why flooding is a design factor
- **Slow start**: each host's first frame to you is flooded → that's fine (learning).
- **Flooding storms**: a loop + STP failure = endless broadcast floods → meltdown.
- **Unknown-unicast flood control**: solutions include *unicast flooding limits*
  (`unknown-unicast-flooding suppressed`? on some platforms), faster aging, or static entries.
- Large flat L2 campus → more flooding per unknown MAC → performance question.

### 2.4 Broadcast vs unknown-unicast flooding

| | Broadcast | Unknown unicast |
|--|-----------|-----------------|
| Dest | FF:FF:FF:FF | specific but unlearned |
| Watermark | always flooded | only until learned |
| Contribution to storms | high | moderate |
| ARP/DHCP | requires broadcast | flood only |
| Reduce by | segmentation (VLAN) | static/learning/cache |

## 4. Exam Traps

- **Flood = unknown dest OR broadcast/multicast** — don't say "flood only broadcast."
- **Never floods back out the *receiving* port** — "all except the ingress port."
- **Does not cross VLANs** — flooding stops at the L2 VLAN boundary.
- **STP-blocked ports do not flood** — robustness vs loops.
- **Aging**: if entries age, the next frame to that MAC floods again.
