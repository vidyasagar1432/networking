# Filtering

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Filtering** at Layer 2 means a switch **does not forward a received frame out a particular egress port**.

Filtering can occur as part of normal switching behavior or because a configured feature explicitly prevents forwarding.

The basic Layer-2 decision can be summarized as:

```text
Receive
   ↓
Learn Source MAC
   ↓
Look up Destination MAC + VLAN
   ↓
┌─────────────────────────────┐
│ Known destination           │
│   → Forward                 │
│ Same ingress port           │
│   → Filter                  │
│ Unknown destination         │
│   → Flood                   │
│ Policy/security violation   │
│   → Drop/filter             │
└─────────────────────────────┘
```

Filtering is therefore one of the three fundamental Layer-2 forwarding behaviors:

> **Forward → Flood → Filter**

---

## 2. Core Concepts

### 2.1 Same-Port Filtering

The classic Layer-2 filtering case occurs when the destination MAC address is already learned on the **same interface on which the frame arrived**.

Example:

```text
Host A
  │
  │ Gi0/1
  ↓
Switch
```

MAC table:

```text
AAAA.AAAA.AAAA → Gi0/1, VLAN 10
```

If the switch receives a frame on Gi0/1 destined for `AAAA.AAAA.AAAA`, it does not send that frame back out Gi0/1.

The frame is **filtered/not forwarded**.

### Why?

The destination is already reachable through the same Layer-2 segment.

```text
Destination on ingress port
          ↓
No valid alternate egress required
          ↓
Filter
```

This prevents unnecessary forwarding back onto the segment from which the frame arrived.

---

## 3. VLAN Forwarding Boundary

A Layer-2 switch does not normally forward a frame from one VLAN directly into another VLAN.

```text
VLAN 10                 VLAN 20
────────                 ────────
 Host A                   Host B
    │                       │
    └─────── Switch ────────┘
```

A VLAN 10 frame remains associated with VLAN 10.

Inter-VLAN communication requires a **Layer-3 routing function**:

```text
VLAN 10
   ↓
L3 Gateway
   ↓
Routing
   ↓
VLAN 20
```

### Important distinction

This is better understood as a **VLAN/Layer-2 forwarding boundary** rather than an ACL-style filtering operation.

---

## 4. STP and Filtering

STP prevents Layer-2 loops by placing redundant paths into a **non-forwarding state**.

```text
        SW1
       /   \
      /     \
    SW2 ─── SW3
           X
        STP blocked
```

The blocked/non-forwarding path is not used for normal Layer-2 data forwarding.

### Exam distinction

> **STP blocking is primarily a loop-prevention mechanism, not a security filtering mechanism.**

When STP topology changes, the previously blocked path can become forwarding.

---

## 5. Explicit Filtering Mechanisms

Various Cisco features can intentionally restrict or discard Layer-2 traffic.

|Feature|What It Can Restrict|Typical Configuration|
|---|---|---|
|**Port Security**|Unauthorized source MAC addresses|`switchport port-security`|
|**Trunk Allowed VLANs**|VLANs carried over a trunk|`switchport trunk allowed vlan`|
|**Storm Control**|Excessive supported broadcast/multicast/unicast traffic|`storm-control ...`|
|**MAC ACL**|Traffic based on MAC addresses|`mac access-group`|
|**VACL**|Traffic within VLANs based on ACL/policy|`vlan access-map`|
|**IP ACL**|IP traffic on Layer-3 interfaces/SVIs|`ip access-group`|
|**Protected Port**|Layer-2 traffic between protected ports|`switchport protected`|

The exact capabilities and syntax can vary by Cisco platform and IOS/IOS XE release.

---

## 6. Port Security

**Port Security** restricts which source MAC addresses are allowed on a switch port.

Example:

```cisco
interface GigabitEthernet0/1
 switchport mode access
 switchport port-security
 switchport port-security maximum 2
```

If an unauthorized source MAC is detected, the configured violation action determines what happens.

### Common violation modes

|Mode|Behavior|
|---|---|
|**Protect**|Drops violating frames; generally does not generate a violation notification|
|**Restrict**|Drops violating frames and generates violation information/counters; SNMP traps/syslog can be generated|
|**Shutdown**|Places the port into an error-disabled state|

### Sticky MAC

Sticky learning allows dynamically learned secure MAC addresses to be converted into secure MAC entries associated with the port.

```cisco
switchport port-security mac-address sticky
```

If persistence across reloads is required, the configuration must be saved appropriately.

---

## 7. Trunk Allowed VLANs

A trunk can be configured to carry only selected VLANs.

Example:

```cisco
interface GigabitEthernet0/24
 switchport trunk allowed vlan remove 50
```

This prevents VLAN 50 from being carried across that trunk.

### Important distinction

```text
VLAN allowed on trunk
        ↓
Can be carried

VLAN not allowed on trunk
        ↓
Cannot be carried
```

This is commonly described as **VLAN pruning/filtering at the trunk boundary**.

> Do not confuse manually configured trunk allowed VLANs with VTP pruning. They are different mechanisms.

---

## 8. Storm Control

**Storm control** limits excessive traffic of supported types entering an interface.

Depending on platform and configuration, storm control can be applied to categories such as:

- broadcast;
    
- multicast;
    
- unicast/unknown-unicast traffic.
    

Example:

```cisco
interface GigabitEthernet0/1
 storm-control broadcast level 20
```

The threshold is commonly expressed as a **percentage of interface bandwidth** or using platform-supported threshold units.

### Purpose

Storm control can help limit the impact of excessive Layer-2 traffic such as:

```text
Layer-2 loop
     ↓
Broadcast amplification
     ↓
Excessive traffic
     ↓
Storm Control
     ↓
Traffic above configured threshold can be dropped
```

The exact violation action and supported traffic types are platform-dependent.

> **Exam point:** Storm control is a traffic-rate protection mechanism. It does not replace STP and does not fix the underlying Layer-2 loop.

---

## 9. MAC ACL

A **MAC ACL** can filter Layer-2 traffic based on MAC addresses.

Conceptually:

```text
Source MAC
Destination MAC
     ↓
MAC ACL
     ↓
Permit / Deny
```

On platforms supporting MAC ACLs, they can be applied to interfaces using the appropriate MAC access-group configuration.

Example syntax:

```cisco
mac access-group <MAC-ACL-NAME> in
```

The exact syntax and supported direction/features depend on the Cisco platform.

---

## 10. VACL

A **VLAN Access Control List (VACL)** can apply filtering policy to traffic within VLANs.

The configuration uses:

```cisco
vlan access-map
```

and associates the policy with VLANs using:

```cisco
vlan filter
```

Conceptually:

```text
Traffic in VLAN
       ↓
VACL policy
       ↓
Forward / Drop / Capture
```

### Do not confuse

|Feature|Applied To|
|---|---|
|**IP ACL**|Layer-3 interfaces/SVIs/routed interfaces|
|**MAC ACL**|Layer-2 traffic based on MAC|
|**VACL**|VLAN-wide Layer-2/Layer-3 filtering policy|

---

## 11. Protected Ports

Cisco's `switchport protected` feature can provide Layer-2 isolation between **protected ports on the same switch**.

Example:

```cisco
interface GigabitEthernet0/1
 switchport protected

interface GigabitEthernet0/2
 switchport protected
```

Protected ports cannot directly exchange Layer-2 traffic with each other on the same switch.

Conceptually:

```text
Protected Port 1 ──X── Protected Port 2
```

However, protected-port behavior has platform-specific details and should not be confused with:

- VLAN separation;
    
- Private VLANs;
    
- port security;
    
- Layer-3 isolation.
    

---

## 12. Filtering vs. Forwarding vs. Flooding

|Behavior|Condition|Action|
|---|---|---|
|**Forward**|Destination known on another eligible port|Send to specific port|
|**Filter**|Destination is on ingress port or policy prevents forwarding|Do not send through that egress|
|**Flood**|Destination unknown/broadcast or multicast is being flooded|Send to multiple eligible ports|

### Example

```text
Known destination
       ↓
   FORWARD

Same-port destination
       ↓
    FILTER

Unknown destination
       ↓
     FLOOD
```

## 14. Exam Traps

### Trap 1 — "Filtering only means same-port destination"

**Incorrect.**

Same-port filtering is the classic **implicit Layer-2 forwarding decision**, but configured features can also intentionally prevent or discard traffic.

Examples include:

- port security;
    
- ACLs;
    
- storm control;
    
- trunk VLAN restrictions;
    
- protected ports.
    

---

### Trap 2 — "VLANs are crossed by Layer-2 filtering"

**Incorrect.**

A Layer-2 switch keeps traffic within its VLAN. **Inter-VLAN communication requires Layer-3 routing.**

---

### Trap 3 — "STP filtering is a security feature"

**Incorrect.**

STP blocking primarily prevents Layer-2 loops.

Security filtering is performed by features such as ACLs and port security.

---

### Trap 4 — "Storm control fixes Layer-2 loops"

**Incorrect.**

Storm control can limit the traffic generated by a storm, but it does not remove the underlying loop.

> **STP prevents the loop; storm control limits excessive traffic.**

---

### Trap 5 — "Protect, restrict, and shutdown are identical"

**Incorrect.**

```text
Protect
  → Drop violating traffic

Restrict
  → Drop + report/count violation

Shutdown
  → Err-disable the port
```

Exact reporting behavior depends on platform/configuration.

---

### Trap 6 — "switchport protected isolates the entire VLAN"

**Incorrect.**

Protected ports provide Layer-2 isolation **between protected ports on the same switch**. They do not create a separate VLAN.

---

### Trap 7 — "Allowed VLANs and VTP pruning are the same"

**Incorrect.**

Both can affect which VLAN traffic crosses trunks, but they are different mechanisms.

## 15. Troubleshooting Workflow

When investigating unexpected Layer-2 filtering:

```text
1. Check MAC address learning
        ↓
2. Check destination MAC location
        ↓
3. Check ingress/egress VLAN
        ↓
4. Check trunk allowed VLANs
        ↓
5. Check STP port state
        ↓
6. Check port-security status
        ↓
7. Check ACL/VACL policies
        ↓
8. Check storm-control configuration
        ↓
9. Check protected-port configuration
        ↓
10. Verify interface counters and logs
```

Useful commands:

```cisco
show mac address-table
show interfaces trunk
show spanning-tree
show port-security
show storm-control
show access-lists
show vlan
show interfaces status
```

## 17. One-Minute Exam Summary

Remember:

> **Filtering = the switch decides that a frame should NOT be forwarded through a particular egress path.**

The classic Layer-2 decision is:

```text
                 Frame received
                        ↓
                 Learn source MAC
                        ↓
             Lookup destination MAC
                        ↓
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
       Known          Same-port     Unknown /
      other port      destination   Broadcast
          ↓             ↓             ↓
       FORWARD        FILTER         FLOOD
```

And configured features can further restrict forwarding:

```text
Port Security
      ↓
MAC-based filtering

Trunk Allowed VLANs
      ↓
VLAN filtering

MAC ACL / VACL
      ↓
Policy-based filtering

Storm Control
      ↓
Traffic-rate protection

Protected Port
      ↓
Intra-switch Layer-2 isolation
```

### Core exam distinction

> **Forward = send to a specific eligible port.**  
> **Flood = send to multiple eligible ports within the VLAN.**  
> **Filter = do not forward through the applicable port/path.**
