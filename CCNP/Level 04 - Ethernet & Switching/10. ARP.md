# ARP (Address Resolution Protocol)

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**ARP (Address Resolution Protocol)** maps an **IPv4 address → MAC address** on the local  
Layer-2 segment.

Before an IPv4 host can send an Ethernet frame, it must know the MAC address of the  
**next hop**:

- **Same subnet** → ARP for the **destination host's IPv4 address**.
    
- **Different subnet** → ARP for the **default gateway's IPv4 address**.
    

ARP is carried directly inside Ethernet frames and is **not encapsulated inside IP**.  
It operates at the **Layer-2/Layer-3 boundary**.

> **Key idea:** ARP resolves the IPv4 address of the **next hop** into a MAC address.  
> The Ethernet switch then uses its **CAM/MAC address table** to forward the frame.

---

## 2. Core Concepts

### 2.1 When ARP is Used

#### Same-subnet communication

If Host A and Host B are in the same subnet:

```text
Host A
10.1.1.10/24
    |
    | ARP: Who has 10.1.1.20?
    v
Host B
10.1.1.20/24
```

Host A learns Host B's MAC address and sends:

```text
IP Source       = 10.1.1.10
IP Destination  = 10.1.1.20

MAC Source      = Host A's MAC
MAC Destination = Host B's MAC
```

#### Different-subnet communication

If Host A wants to reach a remote subnet:

```text
Host A
10.1.1.10/24
    |
    | ARP: Who has 10.1.1.1?
    v
Default Gateway
10.1.1.1
    |
    v
Remote Network
10.2.2.0/24
```

Host A **does not ARP for the remote destination**. It ARPs for the  
**next-hop router/default gateway**.

The resulting frame contains:

```text
IP Source       = 10.1.1.10
IP Destination  = 10.2.2.20

MAC Source      = Host A's MAC
MAC Destination = Gateway's MAC
```

The router removes the incoming Layer-2 frame, routes the IP packet, and creates a  
new Layer-2 frame on the outgoing interface.

> **Exam rule:** ARP resolves the **next-hop IPv4 address → next-hop MAC address**.

## 3. ARP Message Exchange

### 3.1 ARP Request

The sender broadcasts:

```text
Who has 10.1.1.20?
Tell 10.1.1.10
```

The Ethernet destination MAC is:

```text
FF:FF:FF:FF:FF:FF
```

All devices in the local broadcast domain receive the request, but only the device  
owning the requested IPv4 address should normally answer.

### 3.2 ARP Reply

The device owning `10.1.1.20` responds with its MAC address.

The reply is normally **unicast** to the requester:

```text
10.1.1.20 is at AA:BB:CC:DD:EE:FF
```

### 3.3 Basic Exchange

```text
Host A                         Host B
10.1.1.10                      10.1.1.20
   |                               |
   |--- ARP Request (Broadcast) -->|
   |    Who has 10.1.1.20?         |
   |                               |
   |<--- ARP Reply (Unicast) ------|
   |    10.1.1.20 = MAC-B          |
   |                               |
   |====== Ethernet Data =========>|
```

> **Important:** The ARP request is broadcast; the normal ARP reply is unicast.

---

## 4. ARP Frame and Message Format

ARP is **not an IP protocol packet**. It is carried directly inside the Layer-2  
frame.

Ethernet uses:

```text
EtherType = 0x0806
```

Common ARP fields include:

|Field|Meaning|
|---|---|
|HTYPE|Hardware type; Ethernet = `1`|
|PTYPE|Protocol type; IPv4 = `0x0800`|
|HLEN|Hardware address length; Ethernet MAC = `6`|
|PLEN|Protocol address length; IPv4 = `4`|
|Opcode|`1` = Request, `2` = Reply|
|Sender MAC|MAC address of sender|
|Sender IP|IPv4 address of sender|
|Target MAC|MAC address being resolved|
|Target IP|IPv4 address being queried|

Typical Ethernet encapsulation:

```text
+----------------------+ 
| Ethernet Header      |
| EtherType = 0x0806   |
+----------------------+
| ARP Message          |
+----------------------+
```

For an ARP request:

```text
Ethernet Destination = FF:FF:FF:FF:FF:FF
```

For a normal ARP reply:

```text
Ethernet Destination = Requester's MAC
```

## 5. ARP Table

An IP-capable device maintains an **ARP cache/table** containing IPv4-to-MAC  
mappings.

Example:

```text
IPv4 Address    MAC Address           Interface
10.1.1.20       aabb.ccdd.eeff        Gi0/0
10.1.1.1        1122.3344.5566        Gi0/0
```

Cisco IOS commands:

```text
show arp
show ip arp
```

Example:

```text
R1# show ip arp

Protocol  Address       Age (min)  Hardware Addr   Type   Interface
Internet  10.1.1.1             -   1122.3344.5566  ARPA   GigabitEthernet0/0
Internet  10.1.1.20            4   aabb.ccdd.eeff  ARPA   GigabitEthernet0/0
```

### 5.1 Cisco ARP Aging

Cisco IOS uses an ARP timeout of:

```text
14400 seconds = 4 hours
```

The timeout can be changed with:

```text
arp timeout <seconds>
```

Example:

```text
interface GigabitEthernet0/0
 arp timeout 7200
```

> Host operating systems can use different ARP-cache aging behavior. Do not assume  
> that all hosts use Cisco's 4-hour value.

## 6. ARP Resolution and Switching

ARP and MAC learning are related, but they are **not the same table or process**.

```text
             ARP
IPv4 Address -----> MAC Address
     |
     v
Host/Router ARP Cache

             Switching
MAC Address -----> Switch Port
     |
     v
Switch CAM/MAC Table
```

Example:

```text
Host A
10.1.1.10
MAC-A
   |
   | Ethernet Frame
   v
Switch
   |
   | CAM lookup: MAC-B -> Gi0/2
   v
Host B
10.1.1.20
MAC-B
```

> **Exam distinction:**
> 
> **ARP table** = IPv4 address → MAC address  
> **CAM/MAC table** = MAC address → switch port

---

## 7. Proxy ARP

**Proxy ARP** allows a router to answer an ARP request on behalf of another  
device when the router can route the traffic toward that destination.

Instead of the host learning the remote host's MAC address, it learns the  
router's MAC address.

```text
Host A
10.1.1.10
   |
   | ARP for remote destination
   v
Router
10.1.1.1
   |
   v
Remote Network
10.2.2.0/24
```

The router may respond with its own MAC address.

> **Important:** Proxy ARP is a router/L3-device function. It does not mean the  
> switch is using its CAM table as an ARP table.

## 8. ARP Security

### 8.1 ARP Poisoning / Spoofing

ARP does not inherently authenticate ARP messages.

A malicious device can send forged ARP information such as:

```text
10.1.1.1 is at AA:AA:AA:AA:AA:AA
```

If `10.1.1.1` is the default gateway, victims may incorrectly associate the  
gateway's IPv4 address with the attacker's MAC address.

This can enable:

- Man-in-the-middle attacks
    
- Traffic interception
    
- Traffic redirection
    
- Denial of service
    

### 8.2 Dynamic ARP Inspection (DAI)

**Dynamic ARP Inspection (DAI)** validates ARP packets on switch ports and can  
drop invalid ARP messages.

DAI commonly works with **DHCP Snooping bindings** to determine valid  
IP-to-MAC-to-port relationships.

Conceptually:

```text
DHCP Snooping
      |
      v
Binding Database
      |
      v
Dynamic ARP Inspection
      |
      v
Validate ARP
      |
      +---- Valid ------> Forward
      |
      +---- Invalid ----> Drop
```

> **CCNP exam point:** DAI is the primary Cisco Layer-2 feature to know for  
> mitigating ARP spoofing/poisoning.

---

## 9. Gratuitous ARP

A **Gratuitous ARP (GARP)** is an ARP message sent without a normal ARP request  
being received first.

Common purposes include:

- Detecting duplicate IPv4 addresses
    
- Updating neighboring ARP caches
    
- Announcing a changed MAC/IP association
    
- First-hop redundancy events such as an active gateway changing
    

Example:

```text
10.1.1.1 is at AA:BB:CC:DD:EE:FF
```

> GARP is important in troubleshooting because an unexpected GARP can change  
> other devices' ARP-cache entries.

---

## 10. ARP and IPv6

IPv6 does **not use ARP**.

IPv6 uses **Neighbor Discovery (ND)**, which operates using **ICMPv6**.

Important ND messages include:

```text
Neighbor Solicitation (NS)
Neighbor Advertisement (NA)
Router Solicitation (RS)
Router Advertisement (RA)
```

The key comparison is:

|IPv4|IPv6|
|---|---|
|ARP|Neighbor Discovery|
|ARP Request|Neighbor Solicitation|
|ARP Reply|Neighbor Advertisement|
|Broadcast-based ARP request|ICMPv6 multicast-based discovery|

> **Exam trap:** Never say IPv6 uses ARP. IPv6 uses **Neighbor Discovery over  
> ICMPv6**.

## 11. Cisco Configuration and Verification

### View ARP Entries

```text
show arp
show ip arp
```

### Filter ARP Entries

```text
show ip arp | include 10.1.1.
```

### Clear a Specific ARP Entry

```text
clear ip arp 10.1.1.2
```

This forces the device to resolve the address again when communication requires it.

### Configure a Static ARP Entry

```text
arp 10.1.1.2 abcd.1234.5678 arpa
```

Static ARP entries are uncommon in normal enterprise networks but can be useful  
for specific controlled scenarios.

### Configure ARP Timeout

```text
interface GigabitEthernet0/0
 arp timeout 14400
```

### Debug ARP

```text
debug arp
```

Disable debugging afterward:

```text
undebug all
```

or:

```text
u all
```

> Use debugging carefully, especially on production devices.

## 12. Troubleshooting ARP

When an IPv4 host cannot communicate on the local network, check:

### Step 1 — Check the IP configuration

```text
show ip interface brief
```

Verify:

- Interface is up/up
    
- Correct IPv4 address
    
- Correct subnet mask
    

### Step 2 — Check the ARP table

```text
show ip arp
```

Look for the destination or next-hop IPv4 address.

### Step 3 — Clear stale ARP information

```text
clear ip arp <IPv4-address>
```

Then generate traffic again and check whether a new entry appears.

### Step 4 — Check the switch MAC table

```text
show mac address-table
```

Remember:

```text
ARP table:
IPv4 -> MAC

MAC table:
MAC -> Port
```

### Step 5 — Check for ARP security problems

On a Cisco switch, investigate features such as:

```text
show ip arp inspection
show ip dhcp snooping binding
```

## 13. Exam Traps

- **ARP resolves IPv4 addresses to MAC addresses.**
    
- **IPv6 does not use ARP; it uses Neighbor Discovery (ND/NDP) over ICMPv6.**
    
- An ARP request is normally sent as an **Ethernet broadcast**.
    
- A normal ARP reply is normally **unicast**.
    
- Same subnet → ARP for the **destination host**.
    
- Different subnet → ARP for the **next-hop/default gateway**.
    
- ARP is **not encapsulated inside IP**.
    
- ARP uses Ethernet **EtherType `0x0806`**.
    
- IPv4 uses EtherType **`0x0800`**.
    
- ARP table ≠ CAM/MAC table.
    
- **ARP table:** IPv4 → MAC.
    
- **CAM/MAC table:** MAC → switch port.
    
- Cisco IOS default dynamic ARP timeout is **14,400 seconds (4 hours)**.
    
- **DAI** helps protect against ARP spoofing/poisoning.
    
- DAI commonly uses **DHCP Snooping bindings** for validation.
    
- **Proxy ARP** is performed by a router/L3 device, not by the Layer-2 switch's CAM table.
    
- A remote destination is **not resolved directly by the source host**; the host resolves the **next hop**.

## 15. One-Minute Mental Model

```text
                 IPv4 Packet
                     |
                     v
          "Who is my next hop?"
                     |
                     v
                    ARP
                     |
             IPv4 -> MAC
                     |
                     v
              Ethernet Frame
                     |
                     v
                L2 Switch
                     |
             MAC -> Port
                     |
                     v
                Destination
```

### Remember

> **ARP answers: "What MAC address should I use for this IPv4 next hop?"**

> **The switch answers: "Which port should I send this MAC-addressed frame out?"**
