# Proxy ARP

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Proxy ARP** is a router behavior in which a router **answers an ARP request on  
behalf of another IPv4 destination** that is reachable through the router.

Instead of giving the requesting host the destination's real MAC address, the  
router replies with **its own MAC address**.

The host then sends the Ethernet frame to the router, and the router **routes the  
IP packet toward the actual destination**.

> **Key idea:** Proxy ARP makes a remote IPv4 destination appear reachable at  
> Layer 2 by having the router answer ARP with **the router's own MAC address**.

---

## 2. Core Concepts

### 2.1 Normal Routing Without Proxy ARP

Normally, a host recognizes that a destination is outside its local subnet.

Example:

```text
Host A
10.1.1.10/24
     |
     |
     v
Router
10.1.1.1
     |
     v
Remote Host
10.2.2.2/24
```

Host A determines:

```text
10.2.2.2 is NOT in my local subnet
```

Therefore, Host A sends the packet to its **default gateway**.

It ARPs for:

```text
10.1.1.1 -> Router MAC
```

The Ethernet frame becomes:

```text
IP Destination  = 10.2.2.2
MAC Destination = Router MAC
```

---

## 3. How Proxy ARP Works

With Proxy ARP enabled:

```text
Host A
10.1.1.10/24
     |
     | ARP Request:
     | "Who has 10.2.2.2?"
     |
     v
Router R0
     |
     | Proxy ARP Reply:
     | "10.2.2.2 is at R0's MAC"
     |
     v
Remote Host
10.2.2.2
```

The host learns:

```text
10.2.2.2 -> Router MAC
```

Host A then sends:

```text
IP Source       = 10.1.1.10
IP Destination  = 10.2.2.2

MAC Source      = Host A's MAC
MAC Destination = Router's MAC
```

The router receives the frame, removes the incoming Layer-2 header, performs its  
normal Layer-3 routing lookup, and forwards the packet toward `10.2.2.2`.

> **Important:** The router never tells Host A that the destination's real MAC is  
> its own. It deliberately supplies **the router's MAC** so that the host sends  
> the frame to the router.

---

## 4. Proxy ARP Packet Flow

```text
              Local LAN                         Remote LAN

Host A                                      Host B
10.1.1.10                                    10.2.2.2
    |                                            |
    | ARP Request                                |
    | "Who has 10.2.2.2?"                       |
    |----------------->                         |
    |                                            |
    |        Router R0                          |
    |<-----------------                         |
    | ARP Reply                                 |
    | "10.2.2.2 is at R0 MAC"                   |
    |                                            |
    | Ethernet Frame                            |
    | Dest MAC = R0 MAC                         |
    | IP Dest  = 10.2.2.2                       |
    |-----------------> R0                      |
    |                                            |
    |                    R0 routes packet ------>|
    |                                            |
    |                              Host B        |
```

The critical transformation is:

```text
Host A believes:

10.2.2.2 -> Router MAC
```

while the router internally knows:

```text
10.2.2.2 -> reachable through its routing table
```

---

## 5. When Does Proxy ARP Apply?

Proxy ARP is useful when the host sends an ARP request for an address that:

1. Is **not considered local to the requesting interface's subnet**, and
    
2. The router has a valid path to the destination.
    

The router can then answer the ARP request using the MAC address of its  
receiving interface.

Conceptually:

```text
ARP Request
    |
    v
Is destination local?
    |
    +---- Yes ----> Destination normally answers
    |
    +---- No
           |
           v
    Does router have a route?
           |
       +---+---+
       |       |
      No      Yes
       |       |
     No       Proxy ARP
     reply    response
```

The exact proxy-ARP decision can depend on the platform and routing/interface  
configuration.

---

## 6. Why Proxy ARP Exists

Proxy ARP was historically useful when hosts:

- Did not have a properly configured default gateway
    
- Were configured with incorrect subnet masks
    
- Needed to communicate across routed networks without being aware of the  
    routing boundary
    

For example:

```text
Host A
10.1.1.10/24
   |
   v
Router
   |
   v
10.2.2.0/24
```

A host that incorrectly believes the remote destination is directly reachable  
can still send the Ethernet frame to the router because the router answers its  
ARP request.

> **Modern networks normally use correctly configured subnet masks and default  
> gateways, making Proxy ARP unnecessary in many designs.**

---

## 7. Proxy ARP vs Normal ARP

|Aspect|Normal ARP|Proxy ARP|
|---|---|---|
|ARP target|Local destination/next hop|Remote reachable destination|
|Who answers|Device owning target IP|Router|
|MAC returned|Target's MAC|Router's MAC|
|Destination location|Local L2 segment|Reachable through router|
|Router routing|Not necessarily involved|Router routes packet afterward|
|Main purpose|Resolve IPv4 → MAC|Make remote destination appear locally reachable|
|Typical modern use|Normal operation|Specific/legacy scenarios|

## 8. Proxy ARP vs Default Gateway

These concepts are easy to confuse.

### Without Proxy ARP

Host knows the destination is remote:

```text
Destination = 10.2.2.2
        |
        v
Not local
        |
        v
Use default gateway
        |
        v
ARP for 10.1.1.1
```

### With Proxy ARP

Host ARPs directly for the remote destination:

```text
Destination = 10.2.2.2
        |
        v
ARP for 10.2.2.2
        |
        v
Router answers with its MAC
        |
        v
Send frame to router
        |
        v
Router routes to 10.2.2.2
```

> **Exam distinction:** With normal routing, the host ARPs for the **gateway**.  
> With Proxy ARP, the host can ARP for the **remote destination**, and the router  
> answers with its own MAC.

## 9. Cisco IOS Behavior

On traditional Cisco IOS routed interfaces, **Proxy ARP is enabled by default**  
unless it has been disabled or platform-specific behavior differs.

To disable it:

```text
interface GigabitEthernet0/1
 no ip proxy-arp
```

To explicitly enable it:

```text
interface GigabitEthernet0/1
 ip proxy-arp
```

Verify the interface configuration:

```text
show running-config interface GigabitEthernet0/1
```

Look for:

```text
ip proxy-arp
```

or:

```text
no ip proxy-arp
```

> **Design principle:** Do not disable Proxy ARP blindly. Disable it where it is  
> unnecessary and where your network design/security policy calls for it.

---

## 10. Proxy ARP and the ARP Table

A common misconception is:

> "The router creates an ARP entry for the remote destination and uses that  
> entry to answer the host."

That is not the correct model.

The router's Proxy ARP response tells the requesting host:

```text
Remote-IP -> Router's MAC
```

When the router subsequently forwards the packet, it performs its normal routing  
process and, on the outgoing interface, resolves the actual next-hop/destination  
MAC as required.

Conceptually:

```text
Host's ARP cache:

10.2.2.2 -> R0 MAC
```

Router:

```text
Routing table:

10.2.2.0/24 -> appropriate outgoing interface/next hop
```

Router's outgoing ARP resolution:

```text
Actual next hop -> Actual next-hop MAC
```

> **Key distinction:** Proxy ARP changes what the **host believes about the  
> Layer-2 destination**; it does not replace the router's normal routing process.

---

## 11. Proxy ARP and Switching

Proxy ARP involves both Layer 2 and Layer 3, but the router remains a  
**Layer-3 forwarding device**.

```text
Host
  |
  | Ethernet frame
  | Destination MAC = Router MAC
  v
Switch
  |
  | MAC lookup
  v
Router
  |
  | Layer-3 routing
  v
Remote Network
```

The switch only needs to know:

```text
Router MAC -> Router's switch port
```

The switch does not perform Proxy ARP.

> **Exam trap:** Proxy ARP is a **router/L3 function**, not a CAM-table function.

---

## 12. Proxy ARP and Security

Proxy ARP can have security and operational implications.

A router answering ARP for many remote addresses can make the Layer-2 topology  
appear different from the actual Layer-3 design.

Potential concerns include:

- Unexpected Layer-2 adjacency
    
- Difficult troubleshooting
    
- Excessive ARP traffic in some environments
    
- Interaction with security controls
    
- Increased exposure to ARP-related attacks
    

Where Proxy ARP is unnecessary, network administrators may disable it as part of  
interface hardening:

```text
interface GigabitEthernet0/1
 no ip proxy-arp
```

However:

> **Do not treat disabling Proxy ARP as the primary defense against ARP  
> poisoning.** For Cisco Layer-2 ARP spoofing protection, **Dynamic ARP  
> Inspection (DAI)** is the important feature to know.

## 13. Troubleshooting Proxy ARP

### Step 1 — Check Interface Configuration

```text
show running-config interface GigabitEthernet0/1
```

Look for:

```text
ip proxy-arp
```

or:

```text
no ip proxy-arp
```

### Step 2 — Check the Routing Table

```text
show ip route
```

Verify that the router has a route toward the destination.

Example:

```text
show ip route 10.2.2.2
```

### Step 3 — Check the ARP Table

```text
show ip arp
```

Remember that this is the router's own ARP cache, not the host's ARP cache.

### Step 4 — Check the Host ARP Cache

On the host, verify whether:

```text
10.2.2.2 -> Router MAC
```

has been learned.

### Step 5 — Capture ARP Traffic

A packet capture can clearly show:

```text
Host -> Broadcast ARP Request
Router -> Unicast Proxy ARP Reply
Host -> Router MAC
Router -> Remote Destination
```

This is often the easiest way to prove that Proxy ARP is occurring.

## 14. Proxy ARP vs Gratuitous ARP

These two are frequently confused.

### Proxy ARP

Router says:

```text
"I can answer for 10.2.2.2.
Use MY MAC address."
```

The IP address belongs to **someone else**.

### Gratuitous ARP

A device says:

```text
"10.1.1.10 is associated with MY MAC address."
```

The IP address is **normally the sender's own address**.

|Feature|Proxy ARP|Gratuitous ARP|
|---|---|---|
|Typical sender|Router|Host/device|
|IP being announced|Another device's IP|Usually sender's own IP|
|MAC returned/announced|Router's MAC|Sender's MAC|
|Trigger|Host ARPs for remote reachable IP|Proactive announcement|
|Main purpose|Make remote destination appear local|Update/announce IP-to-MAC mapping|

> **Memory trick:**  
> **Proxy ARP = "I can answer for someone else."**  
> **GARP = "Here is my own IP-to-MAC mapping."**

---

## 15. Exam Traps

- **Proxy ARP replies with the router's MAC, not the remote destination's MAC.**
    
- The router then performs **normal Layer-3 routing** toward the actual destination.
    
- Proxy ARP is a **router/L3 function**, not a switch CAM-table function.
    
- Proxy ARP can answer for a **remote, routable IPv4 destination**.
    
- With normal routing, a host ARPs for its **default gateway** when the destination  
    is remote.
    
- With Proxy ARP, the host can ARP for the **remote destination itself**.
    
- The host then sends the Ethernet frame to the **router's MAC**.
    
- Proxy ARP is generally unnecessary when hosts have correct subnet masks and  
    default gateways.
    
- Traditional Cisco IOS routed interfaces have Proxy ARP **enabled by default**  
    unless disabled/configuration or platform behavior differs.
    
- Disable Proxy ARP with:
    

```text
interface GigabitEthernet0/1
 no ip proxy-arp
```

- Proxy ARP is **not the same as GARP**.
    
- **GARP announces an IP-to-MAC association**, usually for the sender's own IP.
    
- **Proxy ARP answers for another IP** using the router's MAC.
    
- Do not confuse the router's **ARP cache** with the host's ARP cache.
    
- Do not use disabling Proxy ARP as a substitute for **DAI** when protecting  
    against ARP spoofing.

## 17. One-Minute Mental Model

```text
Normal Routing:

Host
  |
  | "Destination is remote."
  |
  v
ARP for Gateway
  |
  v
Router MAC
  |
  v
Router routes packet
  |
  v
Remote Host


Proxy ARP:

Host
  |
  | "Who has Remote IP?"
  |
  v
Router
  |
  | "Use MY MAC."
  |
  v
Host sends frame to Router MAC
  |
  v
Router routes packet
  |
  v
Remote Host
```

### Remember

> **Normal routing:**  
> Remote destination → **ARP for gateway MAC**

> **Proxy ARP:**  
> Remote destination → **ARP for remote IP → router answers with its MAC**

> **The router does not pretend to be the remote host at Layer 3; it only provides  
> its own Layer-2 MAC so it can receive and route the packet.**
