# Proxy ARP

> **Level 04 · Ethernet & Switching** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Proxy ARP** is a router behavior where, when a host ARPs for an IP address the
router can reach (on a *different* segment), the router **answers on behalf of the
destination** with **its own MAC**. This lets hosts believe unrelated IPs live
"on the LAN" — the historical way to connect otherwise-routed networks with zero host
configuration.

---

## 2. Core Concepts

### 2.1 The scenario
```
Host A:    ARP for 10.2.2.2   → broadcast
Router R0 (enabled proxy-arp): "I (R0's MAC) have 10.2.2.2"   (unicast reply)
Host A:    sends frames to R0's MAC → R0 routes to 10.2.2.2.
```
Host A thinks 10.2.2.2 is directly reachable on its LAN; actually it's two hops away.

### 2.2 IOS behavior details
- Enabled **by default** on Cisco IOS router interfaces.
- Works only when the address is **not local** to the interface's subnet and the router
  has a route.
- Each target IP requiring a GARP-not-applicable answer yields a separate proxy reply
  (ARP caching keeps mapping).
- On dynamic interfaces (dial/PoE) proxy-arp can cause scaling/build-ups → frequently
  disabled.

### 2.3 Why it matters in the exam
- **History**: connecting subnets without setting gateways (down-level hosts had no GW).
- **Modern impact**: plain routers don't need it; hosts now have default gateways.
  It's mostly **disabled** in modern security (prevents a host learning wrong L2
  adjacency, and reduces proxyARP spoof exposure).
- **Security/mitigation**: disable `ip proxy-arp` on untrusted edges; part of device hardening (Level 17).

### 2.4 Proxy ARP vs Routing Table

| | Normal routing | Proxy ARP |
|--|----------------|-----------|
| Host does | knows gateway | doesn't know dest is remote |
| Router | routes normally | also answers ARP for nonlocal IPs |
| Table build | host's ARP + GW | router's own ARP for the peer |
| Risk | — | L2 spoof/MITM if malicious |
| Modern | standard | mostly legacy/edge |

### 2.5 Proxy ARP side effects
- Host ARP caches overlong (router's MAC stays until timeout) — addressing is
  approximate; moving a host makes old entries linger.
- Proxy replies are **unicast** to the requester — only the requester learns.

## 3. Configuration / Commands

```text
# Disable proxy-arp (recommended on untrusted user/edge interfaces)
interface GigabitEthernet0/1
 no ip proxy-arp

# Show ARP state to see if the router proxies
show ip arp
# (A row with a "type" of PROXY proves it was answering)
```

---

## 4. Exam Traps

- **Proxy ARP answers with the ROUTER's MAC, not the destination's** — the trap.
- **It's a L2/L3 bridge trick** — the router never claims the dest's real MAC.
- **Default enabled** on IOS; security best practice disables it.
- **Not used for the same-subnet case** — the router proxies only what it can *route to*.
- **Do not confuse with GARP** (GARP announces own mapping; proxyARP answers other IPs).
