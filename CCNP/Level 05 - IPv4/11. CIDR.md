# CIDR (Classless Inter-Domain Routing)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**CIDR (Classless Inter-Domain Routing)** replaced traditional fixed IPv4 address  
classes with **arbitrary prefix lengths**.

Instead of relying on Class A/B/C boundaries, CIDR represents a network as:

```text
address/prefix-length
```

Examples:

```text
192.168.10.0/24
10.0.0.0/8
172.16.0.0/20
```

CIDR provides:

- **Flexible address allocation** — choose a prefix appropriate for the required network size.
    
- **Route aggregation/summarization** — represent multiple contiguous networks with one route.
    
- **Classless routing** — routing protocols can carry the prefix/mask information.
    
- **More efficient use of IPv4 address space** — avoids depending on fixed class boundaries.
    

---

## 2. Core Concepts

### 2.1 The `/x` Notation

`/x` specifies the number of **leading 1-bits** in the subnet mask.

Examples:

```text
192.168.10.0/24
Mask: 255.255.255.0
```

```text
10.0.0.0/8
Mask: 255.0.0.0
```

```text
172.16.0.0/20
Mask: 255.255.240.0
```

The prefix length determines how many bits identify the **network** and how many remain for **hosts**.

> CIDR does not imply any IPv4 class. `/20`, `/21`, `/27`, etc. are all valid regardless of historical Class A/B/C boundaries.

---

### 2.2 Why CIDR Matters

|Benefit|Explanation|
|---|---|
|Flexible allocation|Prefixes can be selected according to actual network requirements.|
|Address efficiency|Smaller prefixes such as `/27` or `/28` can avoid allocating an unnecessarily large subnet.|
|Route aggregation|Multiple contiguous networks can be represented by a single summary route.|
|Smaller routing tables|Aggregation reduces the number of individual routes that routers need to maintain.|
|Classless routing|Routing information includes the prefix length/mask rather than relying on historical classes.|
|Supernetting|Multiple networks can be combined into a larger aggregate prefix.|

Example:

```text
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

can be summarized as:

```text
192.168.0.0/22
```

because these four `/24` networks are contiguous and correctly aligned on the `/22` boundary.

---

### 2.3 CIDR vs Classful Addressing

|Feature|Classful Addressing|CIDR|
|---|---|---|
|Prefix|Fixed by historical class|Arbitrary prefix length|
|Example|Class B `172.16.0.0`|`172.16.0.0/20`|
|Subnet boundary|Class-based|Explicit prefix|
|Route information|May rely on classful assumptions|Prefix/mask carried with route|
|Address allocation|Coarse|Flexible|
|Summarization|Limited by classful boundaries|Flexible aggregation|
|Example protocol|RIPv1|RIPv2, OSPF, IS-IS, BGP|

> **RIPv1 is classful.** RIPv2 is classless and carries subnet-mask information.

## 3. Working with Prefix Lengths

### 3.1 Number of Addresses

For an IPv4 prefix `/x`:

```text
Total addresses = 2^(32 − x)
```

For a traditional subnet where network and broadcast addresses are unavailable to hosts:

```text
Usable hosts = 2^(32 − x) − 2
```

Examples:

```text
/24 → 2^8  = 256 addresses → 254 traditional usable hosts
/26 → 2^6  = 64 addresses → 62 traditional usable hosts
/27 → 2^5  = 32 addresses → 30 traditional usable hosts
/28 → 2^4  = 16 addresses → 14 traditional usable hosts
```

> The `−2` rule does not universally apply. `/31` point-to-point links and `/32` host routes are important exceptions.

---

### 3.2 Network Address

The network address is calculated by performing a **bitwise AND** between the IP address and the subnet mask.

```text
Network = IP address AND subnet mask
```

Example:

```text
IP:    192.168.10.70
Mask:  255.255.255.192 (/26)

Network: 192.168.10.64
```

---

### 3.3 Prefix Block Size

The prefix determines the size of each subnet block.

Examples:

|Prefix|Mask|Addresses|Traditional Usable Hosts|
|---|---|--:|--:|
|`/24`|`255.255.255.0`|256|254|
|`/25`|`255.255.255.128`|128|126|
|`/26`|`255.255.255.192`|64|62|
|`/27`|`255.255.255.224`|32|30|
|`/28`|`255.255.255.240`|16|14|
|`/29`|`255.255.255.248`|8|6|
|`/30`|`255.255.255.252`|4|2|
|`/31`|`255.255.255.254`|2|Point-to-point use|
|`/32`|`255.255.255.255`|1|Host route|

## 4. Route Summarization

**Route summarization** combines multiple contiguous networks into a single larger prefix.

To summarize correctly:

1. Networks must be **contiguous**.
    
2. The summary prefix must be **properly aligned**.
    
3. The summary must cover all required networks.
    
4. A summary may also cover additional addresses if the design intentionally permits it, but accidental over-summarization can cause routing problems.
    

### Example

Given:

```text
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

The common prefix is:

```text
192.168.0.0/22
```

A `/22` contains four `/24` networks:

```text
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

Therefore:

```text
192.168.0.0/22
```

is an exact summary.

---

### 4.1 Misaligned Summary Trap

Consider:

```text
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

These three networks **cannot be represented exactly by one `/22`**.

A `/22` has a block size of 4 in the third octet:

```text
192.168.0.0/22 → .0 – .3
192.168.4.0/22 → .4 – .7
192.168.8.0/22 → .8 – .11
```

Therefore:

```text
192.168.0.0/22
```

would cover:

```text
.0
.1
.2
.3
```

It includes the additional `192.168.0.0/24` network.

For an exact representation of `.1` through `.3`, more than one summary is required.

> **Exam rule:** Never choose a summary prefix only because its size appears large enough. Check the **binary common prefix and alignment**.

## 5. Supernetting

**Supernetting** combines multiple smaller networks into a larger CIDR prefix.

Example:

```text
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

becomes:

```text
192.168.0.0/22
```

The prefix becomes **shorter**:

```text
/24 → /22
```

A shorter prefix represents a **larger address block**.

Remember:

```text
/22 > address space than /23
/23 > address space than /24
```

In other words:

> **Smaller prefix number = larger network.**

## 6. CIDR and Routing

CIDR is fundamental to modern IP routing.

### 6.1 Default Route

The IPv4 default route is:

```text
0.0.0.0/0
```

It matches any IPv4 destination when no more-specific route exists.

---

### 6.2 Longest-Prefix Match

When multiple routes match a destination, routers normally select the route with the **longest matching prefix**.

Example:

```text
10.0.0.0/8
10.10.0.0/16
10.10.10.0/24
```

Destination:

```text
10.10.10.50
```

All three routes match, but:

```text
/24
```

is the longest prefix, so it is preferred.

> Longest-prefix match is a routing-table decision concept and is covered in greater detail with IPv4 routing.

---

### 6.3 Internet Routing

CIDR is heavily used in Internet routing and BGP.

Examples include:

```text
0.0.0.0/0
203.0.113.0/24
203.0.113.128/25
```

More-specific routes can be preferred over broader aggregates through longest-prefix matching.

---

## 7. Special Prefixes

### `/31` — Point-to-Point Links

RFC 3021 allows `/31` prefixes to be used on suitable point-to-point links.

Example:

```text
10.0.0.0/31
```

contains two addresses:

```text
10.0.0.0
10.0.0.1
```

This avoids the traditional requirement to reserve separate network and broadcast addresses on a point-to-point link.

---

### `/32` — Host Route

A `/32` identifies exactly one IPv4 address.

Example:

```text
192.168.10.50/32
```

It is commonly used for:

- Loopback addresses
    
- Host-specific routes
    
- Router IDs
    
- Specific routing entries

## 8. Cisco Configuration

### 8.1 Assign a CIDR Prefix

Cisco IOS configuration uses the **dotted-decimal subnet mask** rather than `/x` notation in the traditional `ip address` command.

```text
interface GigabitEthernet0/1
 ip address 192.168.10.1 255.255.255.224
 no shutdown
```

The mask:

```text
255.255.255.224
```

is:

```text
/27
```

---

### 8.2 Configure a Summarized Static Route

```text
ip route 192.168.0.0 255.255.252.0 10.0.0.1
```

This represents:

```text
192.168.0.0/22
```

with next hop:

```text
10.0.0.1
```

---

### 8.3 Verify the Routing Table

```text
show ip route
```

Useful additional commands:

```text
show ip route 192.168.0.0
show ip interface brief
show running-config
```

## 9. Exam Traps

- **CIDR does not mean "smaller is better."**
    
    - `/22` represents a larger block than `/23`.
        
    - `/23` represents a larger block than `/24`.
        
- **Do not use historical class boundaries for CIDR.**
    
    - A network does not need to be `/24` simply because it was historically associated with Class C.
        
- **Summaries must be correctly aligned.**
    
    - A `/22` has a block size of 4 in the relevant octet.
        
    - Valid third-octet boundaries include `0, 4, 8, 12, ...`.
        
- **Three `/24` networks do not automatically equal one `/22`.**
    
    - A `/22` contains four `/24` networks.
        
- **Prefix length determines block size.**
    
    - Shorter prefix → larger block.
        
    - Longer prefix → smaller block.
        
- **`0.0.0.0/0` is the default route.**
    
    - It is the least-specific IPv4 prefix.
        
- **`/31` and `/32` are special cases.**
    
    - `/31` can be used for point-to-point links.
        
    - `/32` represents a single host.
        
- **CIDR is classless.**
    
    - Do not apply Class A/B/C assumptions when calculating a CIDR network.

## 11. Quick Memory Rules

```text
CIDR = Address + Prefix Length

/32 → 1 address
/31 → 2 addresses
/30 → 4 addresses
/29 → 8 addresses
/28 → 16 addresses
/27 → 32 addresses
/26 → 64 addresses
/25 → 128 addresses
/24 → 256 addresses

Shorter prefix → Larger block
Longer prefix  → Smaller block

Network = IP AND Mask

Default route = 0.0.0.0/0

Longest Prefix Match → Most-specific matching route wins
```

> **CCNP ENCOR takeaway:** CIDR replaces classful boundaries with explicit prefix lengths, enables flexible subnet sizing and route aggregation, and forms the foundation for modern classless IPv4 routing.
