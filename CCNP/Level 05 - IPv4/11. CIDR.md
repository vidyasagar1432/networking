# CIDR (Classless Inter-Domain Routing)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**CIDR** replaced fixed classes with **arbitrary prefix lengths**: an address plus a
prefix, e.g., `192.168.10.0/24` or `10.0.0.0/8`. It enables **efficient allocation**
(matching network to need) and **route summarization** (one entry for many networks),
which kept the Internet's routing tables manageable.

---

## 2. Core Concepts

### 2.1 The /x notation
- `/x` = number of leading **1-bits** in the mask.
- `192.168.10.0/24` → mask `255.255.255.0`.
- Everything is expressed as **address/prefix**, no class implied.

### 2.2 Why CIDR matters

| Benefit | Explanation |
|---------|-------------|
| Address efficiency | allocate /26, /28 exactly match host counts — no waste |
| Aggregation | many /24s → one /16 or a /20 summary (less BGP memory) |
| Classless routing | RIPng/OSPF/IS-IS/BGP carry masks |
| Flexible supernets | "say 10.1.0.0/16" instead of two /17s |

### 2.3 CIDR vs classful (comparison)

| | Classful | CIDR |
|--|----------|------|
| Mask | fixed by class | arbitrary prefix |
| Example | "class B 172.16.0.0" | 172.16.0.0/12 |
| Route | class-limited | summarized |
| Era | RIPv1 | RIPv2/OSPF/BGP |

### 2.4 Working with /x
- **Hosts** = 2^(32−x) − 2.
- **Network = IP AND prefix**.
- **Summarize**: align the leftmost matching bits across blocks.
- Example: `192.168.1.0/24` + `192.168.2.0/24` + `192.168.3.0/24` → `192.168.0.0/22`?

  Check overlap: /22 needs 4 /24s starting at .0 — so only `192.168.0.0/22` would
  cover .0–.3; the three given → need `/23` for .1-.2 or a /22 aligned at .0
  (would include extra .0, .3). Always align on the block boundary.

### 2.5 CIDR in operation
- **Internet routes** use CIDR (0.0.0.0/0 default; anycast → more-specifics).
- **Longest-prefix match** decides when overlapping (Level 09).

## 3. Configuration / Commands

```text
# Any /x allowed
interface GigabitEthernet0/1
 ip address 192.168.10.1 255.255.255.224     # /27

# Summarized static route
ip route 192.168.0.0 255.255.252.0 10.0.0.1   # /22 aggregate

show ip route
```

---

## 4. Exam Traps

- **CIDR does NOT mean "smaller is better"** — it means flexible; a /22 is LARGER than /23.
- **Summarization must be contiguous/aligned** — the /22 trap above.
- **/31 point-to-point (RFC 3021)**, **/32 host routes** — CIDR enables these exotics.
- **Default route `0.0.0.0/0`** — the "any-prefix" CIDR expression.
- **Never return to classful logic** (e.g., "class C needs /24") when a /28 fits.
