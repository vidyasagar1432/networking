# Decimal (IPv4)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Decimal** is the human-readable representation of an IPv4 address. An IPv4 address  
contains **four decimal octets**, separated by dots.

Fluency with decimal ↔ binary conversion is essential for:

- Subnetting
    
- VLSM
    
- Route summarization
    
- Subnet-mask calculation
    
- Wildcard-mask calculation
    
- Troubleshooting IPv4 addressing
    

---

## 2. Core Concepts

### 2.1 Dotted-decimal anatomy

An IPv4 address has **32 bits**, divided into four **8-bit octets**:

```text
A.B.C.D
```

Example:

```text
172.16.50.100
```

Each octet must contain a value from **0–255**.

```text
172    .    16    .    50    .    100
Octet 1     Octet 2     Octet 3     Octet 4
```

**Important:** IPv4 uses dotted decimal. IPv6 normally uses **colon-separated hexadecimal**, for example:

```text
2001:db8::1
```

---

### 2.2 The octet ↔ binary bridge

Each octet contains 8 bits with these positional weights:

|Bit|7|6|5|4|3|2|1|0|
|---|--:|--:|--:|--:|--:|--:|--:|--:|
|Weight|128|64|32|16|8|4|2|1|

Examples:

```text
128 = 10000000
192 = 11000000
224 = 11100000
240 = 11110000
248 = 11111000
252 = 11111100
254 = 11111110
255 = 11111111
```

These values are especially important when converting subnet masks between binary and decimal.

---

### 2.3 Valid subnet-mask octets

A standard IPv4 subnet mask contains **contiguous 1-bits followed by contiguous 0-bits**.

Therefore, a mask octet can only contain these values:

```text
0
128
192
224
240
248
252
254
255
```

Examples of valid masks:

```text
255.255.255.0       = /24
255.255.255.128     = /25
255.255.255.192     = /26
255.255.255.224     = /27
255.255.255.240     = /28
255.255.255.248     = /29
255.255.255.252     = /30
```

Invalid example:

```text
255.255.255.207
```

Because:

```text
207 = 11001111
```

The bits are not contiguous `1`s followed by `0`s.

---

### 2.4 Decimal values commonly seen in subnetting

|Decimal|Binary|Prefix bits in an octet|
|--:|--:|--:|
|0|`00000000`|0|
|128|`10000000`|1|
|192|`11000000`|2|
|224|`11100000`|3|
|240|`11110000`|4|
|248|`11111000`|5|
|252|`11111100`|6|
|254|`11111110`|7|
|255|`11111111`|8|

Memorize this table for fast subnetting.

## 3. Decimal and Prefix-Length Relationship

The prefix length tells you how many bits are `1` in the subnet mask.

|Prefix|Subnet Mask|
|--:|---|
|/8|`255.0.0.0`|
|/16|`255.255.0.0`|
|/24|`255.255.255.0`|
|/25|`255.255.255.128`|
|/26|`255.255.255.192`|
|/27|`255.255.255.224`|
|/28|`255.255.255.240`|
|/29|`255.255.255.248`|
|/30|`255.255.255.252`|
|/31|`255.255.255.254`|
|/32|`255.255.255.255`|

## 4. Magic Number / Block Size

The **block size** is calculated from the interesting mask octet:

```text
Block size = 256 − mask value
```

Examples:

```text
/25 → 256 − 128 = 128
/26 → 256 − 192 = 64
/27 → 256 − 224 = 32
/28 → 256 − 240 = 16
/29 → 256 − 248 = 8
/30 → 256 − 252 = 4
```

### Example: `/28`

Mask:

```text
255.255.255.240
```

Block size:

```text
256 − 240 = 16
```

Therefore, the subnets are:

```text
192.168.1.0/28
192.168.1.16/28
192.168.1.32/28
192.168.1.48/28
...
```

A `/28` contains:

```text
16 total addresses
14 usable host addresses
```

**Do not confuse block size with usable host count.**

## 7. Decimal Output in Cisco IOS

Cisco IOS commonly displays IPv4 addresses and subnet masks in dotted-decimal or prefix-length form depending on the command and platform.

Example:

```text
show ip interface brief
```

Typical output includes:

```text
Interface              IP-Address      OK? Method Status
GigabitEthernet0/1     10.10.0.1       YES manual up
```

Another useful command:

```text
show ip interface GigabitEthernet0/1
```

This can display information such as:

```text
Internet address is 10.10.0.1/24
```

Routing output may also show:

```text
0.0.0.0/0
```

which represents the **default route**.

## 9. Wildcard Masks

A wildcard mask is the **inverse of a subnet mask**.

Formula:

```text
Wildcard = 255.255.255.255 − Subnet Mask
```

Example:

```text
Subnet mask: 255.255.255.0
Wildcard:    0.0.0.255
```

Another example:

```text
Subnet mask: 255.255.255.240
Wildcard:    0.0.0.15
```

Wildcard masks are commonly encountered with:

- IPv4 ACLs
    
- OSPF network statements
    
- Other Cisco features that use wildcard matching

## 10. Special IPv4 Decimal Values

### 10.1 `0.0.0.0/0`

Represents:

```text
Any IPv4 destination
```

Most commonly seen as the **default route**.

Example:

```text
S* 0.0.0.0/0
```

---

### 10.2 `255.255.255.255`

This is the IPv4 **limited broadcast address**.

It is used to reach all hosts on the local network segment, subject to the relevant forwarding rules.

---

### 10.3 `127.0.0.0/8`

The `127.0.0.0/8` range is reserved for **IPv4 loopback**.

The commonly used loopback address is:

```text
127.0.0.1
```

## 11. Exam Traps

### Trap 1 — Values outside 0–255

Invalid IPv4 octets:

```text
300.1.1.1
192.168.1.256
10.-1.1.1
```

Every IPv4 octet must be:

```text
0–255
```

---

### Trap 2 — Invalid subnet mask

Valid:

```text
255.255.255.248
```

Invalid:

```text
255.255.255.207
```

Remember:

> Subnet-mask bits must be **contiguous 1s followed by contiguous 0s**.

---

### Trap 3 — Block size ≠ usable hosts

For `/28`:

```text
Mask:        255.255.255.240
Block size:  16 addresses
Usable:      14 hosts
```

Do not call `16` the number of hosts.

---

### Trap 4 — Network address vs host address

For:

```text
192.168.10.0/24
```

`192.168.10.0` is the **network address**, not a normal host address.

For:

```text
192.168.10.5/24
```

`192.168.10.5` is a **host address**.

---

### Trap 5 — Four-octet IPv4 notation

Always represent an IPv4 address using four octets:

```text
10.0.0.1
```

For a network:

```text
10.0.0.0/24
```

Avoid ambiguous shorthand such as:

```text
10.0.0/24
```

---

### Trap 6 — Context matters for `0.0.0.0`

`0.0.0.0/0` commonly means the **default route / any destination**, but `0.0.0.0` can have different meanings in different protocols or commands.

Always interpret it according to the command/output context.

## 12. Quick Mental Math

Memorize these:

```text
256 − 128 = 128  → /25
256 − 192 = 64   → /26
256 − 224 = 32   → /27
256 − 240 = 16   → /28
256 − 248 = 8    → /29
256 − 252 = 4    → /30
256 − 254 = 2    → /31
```

And remember:

```text
Hosts = 2^host_bits − 2
```

For traditional IPv4 subnets.

Example:

```text
/27

Host bits = 32 − 27
          = 5

Total addresses = 2^5
                = 32

Traditional usable hosts = 32 − 2
                         = 30
```

## 14. CCNP ENCOR Takeaways

For the exam, be able to immediately recognize:

1. **IPv4 = 32 bits = 4 octets**
    
2. **Each octet = 0–255**
    
3. **Each octet has weights `128 64 32 16 8 4 2 1`**
    
4. **Valid mask octets:** `0, 128, 192, 224, 240, 248, 252, 254, 255`
    
5. **Block size = `256 − interesting mask octet`**
    
6. **Subnet masks contain contiguous 1s followed by 0s**
    
7. **`/24 = 255.255.255.0`**
    
8. **`/25 = 255.255.255.128`**
    
9. **`/26 = 255.255.255.192`**
    
10. **`/27 = 255.255.255.224`**
    
11. **`/28 = 255.255.255.240`**
    
12. **`/29 = 255.255.255.248`**
    
13. **`/30 = 255.255.255.252`**
    
14. **`0.0.0.0/0` = default route / any destination**
    
15. **Wildcard mask = inverse of subnet mask**
    
16. **Decimal ↔ binary conversion is fundamental to subnetting and summarization**
    

> **Exam focus:** Do not merely memorize decimal masks. Be able to convert between **prefix length ↔ decimal mask ↔ binary mask ↔ block size ↔ network/host ranges** quickly.
