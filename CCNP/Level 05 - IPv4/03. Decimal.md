# Decimal (IPv4)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Decimal** is how IPv4 addresses and masks are presented to humans — four decimal
numbers separated by dots. Working fluently between decimal octets and binary is the
price of subnetting success.

---

## 2. Core Concepts

### 2.1 Dotted-decimal anatomy
- 4 octets, each 0–255: `A.B.C.D` — e.g., `172.16.50.100`.
- Don't confuse with **dotted hex** (IPv6 notation, Level 06).

### 2.2 The octet ↔ binary bridge (recap)

| Decimal | Binary | Note |
|---------|--------|------|
| 128 | 10000000 | first bit on |
| 192 | 11000000 | /2 |
| 224 | 11100000 | /3 |
| 240 | 11110000 | /4 |
| 248 | 11111000 | /5 |
| 252 | 11111100 | /6 |
| 254 | 11111110 | /7 |
| 255 | 11111111 | all on |

### 2.3 Mask patterns in decimal
- Masks are **contiguous 1s** → valid mask octets are only: 0,128,192,224,240,248,252,254,255.
- An octet value not on that list (e.g., 129) = **invalid contiguous mask**.

### 2.4 Decimal output in the network
- `show ip interface` prints IPv4 in dotted-decimal + prefix.
- Default routes use `0.0.0.0 0.0.0.0`; route aggregation uses `route-map` AD books.
- Wildcard masks (ACL) are shown in decimal inverses (Level 17).

### 2.5 Practical mental math table

| /prefix | mask | block of /24s | hosts |
|---------|------|---------------|-------|
| /24 | 255.255.255.0 | 1 | 254 |
| /22 | 255.255.252.0 | 4 | 1022 |
| /20 | 255.255.240.0 | 16 | 4094 |
| /19 | 255.255.224.0 | 32 | 8190 |
| /16 | 255.255.0.0 | 256 | 65534 |

## 4. Exam Traps

- **A decimal octet > 255 or negative = invalid address** (e.g., 300.1.1.1 → fail).
- **Masks must be contiguous**; 255.255.255.248 vs 255.255.255.248 — a non-mask
  octet like 255.255.255.207 is wrong on purpose.
- **Trailing zeros matter**: 10.0.0/24 vs 10.0.0.0/24 are the same thing — exams use 4-octet always.
- **The magic increment** derives from the last non-255 octet: `.240` → 16-host blocks.
- **0.0.0.0** in route outputs means default; in pics unusual — context.
