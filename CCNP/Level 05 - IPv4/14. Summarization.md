# Summarization

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Summarization (route aggregation)** replaces a set of **contiguous networks** with
**one less-specific route**. Used at distribution/core boundaries, it shrinks routing
tables, speeds convergence, and contains flaps — a core design principle (and Level 09 topic).

---

## 2. Core Concepts

### 2.1 The idea
`192.168.1.0/24, 192.168.2.0/24, 192.168.3.0/24` → one route `192.168.0.0/22`.

### 2.2 How to compute a summary
1. Convert the **network addresses to binary** (the third octet usually).
2. Find the **common leftmost bits** across all.
3. Prefix = number of matching bits; network = those bits (rest 0).

Example (third octet):
```
.1 = 00000001
.2 = 00000010
.3 = 00000011
common: 000000 = /6 host? no wait — 6 bits of hundred… let's binary the /22:
10.1.0.0/24  -> 10.1.00000000
10.1.1.0/24  -> 10.1.00000001
10.1.2.0/24  -> 10.1.00000010
10.1.3.0/24  -> 10.1.00000011
matching prefix = 10.1.000000 → /22 → 10.1.0.0/22
```
- More specific bits → fewer/more-precise.

### 2.3 Requirements for a clean summary
- **Contiguous address blocks** (continuous bits).
- **Aligned to the block size** — a /22 needs to start at a multiple of 4 (/24), etc.
- Adjacent but unaligned (e.g., wanting .4-.7 but starting at .1) → cannot produce
  one clean /22.

### 2.4 Where to summarize
- **Distribution → core**: advertise `10.1.0.0/22` from dist instead of 4 × /24.
- **EIGRP/OSPF area boundaries** (Level 10/11) — type-3 LSAs, summary-address.
- **BGP** (Level 12) — aggregate-address.
- Levels of practical "summarize at the aggregation point" = **summarize toward the core**.

### 2.5 Effects

| Benefit | Detail |
|---------|--------|
| Table size | fewer routes (memory/CPU saving) |
| Convergence | fewer updates, faster |
| Flap containment | a leaf flap doesn't ripple |
| Black-hole risk | one bad summary may doom a destination (filtering needed) |

## 3. Configuration / Commands

```text
# EIGRP summarization on an interface
router eigrp 100
 network 10.0.0.0
interface Gi0/1
 ip summary-address eigrp 100 10.1.0.0 255.255.252.0

# OSPF area summarization
router ospf 1
 area 0 range 10.1.0.0 255.255.252.0

# BGP aggregation
router bgp 65001
 aggregate-address 10.1.0.0 255.255.252.0 summarize-only
```

---

## 4. Exam Traps

- **Alignment**: summarizing misaligned networks silently deletes legitimate subnets
  (e.g., a /22 starting at .1 includes .0 wrongly).
- **Summarization ≠ supernetting** — same math, but supernetting is formal aggregation
  of classful blocks (Level 15).
- **Black-hole**: if the summary is advertised but a real path doesn't exist for part
  of it → those hosts unreachable.
- **Only works with contiguous subnets** — equals overLapping designed ranges.
- **Don't summarize small discontiguous sets** into one giant that also covers other
  regions' space.
