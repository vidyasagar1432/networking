# Private IP (RFC 1918)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Private IP addresses** (RFC 1918) are **not globally routeable**; they are reused
within LANs behind NAT or within provider-managed networks. Everyone uses the same
private ranges — uniqueness matters only inside one routing domain.

---

## 2. Core Concepts

### 2.1 The three reserved ranges

| Range | CIDR | Number of networks | Size |
|-------|------|--------------------|------|
| **10.0.0.0 – 10.255.255.255** | 10.0.0.0/8 | 1 (all) | ~16.7M addresses |
| **172.16.0.0 – 172.31.255.255** | 172.16.0.0/12 | 16 /16s | ~1M |
| **192.168.0.0 – 192.168.255.255** | 192.168.0.0/16 | 256 /24s | ~65k |

### 2.2 Rules of the range
- **Not advertised in global BGP** — they are filtered at ISP edges.
- **Free to reuse** — two different companies may both use `10.0.0.0/8` internally.
- **Not "internet-addressable"** — outside world can't route to them directly.

### 2.3 Why private + NAT
- **IPv4 conservation**: a company's internal address space is private and recycled;
  only egress uses limited public (PAT/overload, Level 15).
- **Security-by-obscurity**: ranges don't leak internally; NAT hides topology.
- Best practice (CCNP level): use **RFC 1918 with structured addressing** +
  DHCP/reservations; resist overlapping ranges in mergers (route filtering matters).

### 2.4 Other "private-like" reserved ranges

| Range | Purpose |
|-------|---------|
| 169.254.0.0/16 | APIPA/link-local (self-assigned, Level 07) |
| 127.0.0.0/8 | loopback (Level 08) |
| 100.64.0.0/10 | CGNAT (carrier-grade NAT) — shared by ISP |
| 198.18.0.0/15 | benchmarking |
| 192.0.2.0/24 etc. | documentation |

### 2.5 Design impact
- **Mergers**: overlapping 10.x nets → need renumbering/NAT.
- **Summary/traffic**: summarize private blocks for internal routing (Level 14).
- **VRF/segmentation**: separate private spaces between trusts (Level 25).

## 3. Configuration / Commands

```text
interface Vlan10
 ip address 10.1.10.1 255.255.255.0
# STATIC domain uses inside the campus; WAN between sites is usually routed
# with shared/linked addressing (or overlay tunnels).

# Proving a range is "private-like":
show ip route | include 10.|172.16.|192.168.
```

---

## 4. Exam Traps

- **The 172.16–172.31 boundary**: `172.32.x.x` is **NOT** RFC 1918 — classic trap.
- **Private ≠ blocked from use**: inside the enterprise you CAN route 10.x between sites.
- **Don't try to reach a private IP from the Internet** without NAT/VPN.
- **Memory**: 10.0.0.0/8 → all ten; 172.16/12 → "16 to 31"; 192.168/16 → "192.168".
- **100.64.0.0/10 is CGNAT, not RFC 1918** — different reserved block.
