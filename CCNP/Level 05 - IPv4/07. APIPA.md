# APIPA (Automatic Private IP Addressing)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**APIPA** is the fallback behavior of hosts (Windows etc.) when a **DHCP server is
unreachable**: the OS assigns itself an address from **169.254.0.0/16** (link-local)
so that neighboring hosts on the same segment can still talk **without config or DHCP**.

---

## 2. Core Concepts

### 2.1 How it works
- Host requests a DHCP lease; if no server responds → after retries, it **auto-configures**
  from `169.254.0.1 – 169.254.255.254` (mask /16).
- Uses a **check** mechanism (duplicate-address test via GARP-like ARP probe) before
  claiming an address.
- **Only within segment**: no gateway, no routing — traffic stays on the local L2 segments.

### 2.2 Timeline symptom (the exam story)
1. DHCP Discover sent (broadcast UDP 67/68).
2. No offer → retries, then:
   - Windows: after ~30s–1min host shows **169.254.x.x**; the NIC shows "no network access."
3. User complains "internet down" — actually they're in APIPA mode → **fix DHCP / cabling**.

### 2.3 APIPA vs Static/Private (not a substitute)

| Address | Config | Routeable | Source |
|---------|--------|-----------|--------|
| 10/172.16/192.168 | static or DHCP | inside | RFC 1918 |
| 169.254/16 | **automatic fallback** | **no (link-local only)** | APIPA |
| Public | static/DHCP | Internet | RIR |

### 2.4 It's not a "classification" — it's a symptom
- If you see `169.254.` in `ipconfig`, the device could NOT get a DHCP lease.
- Troubleshooting steps: check DHCP server, port VLAN/cabling, DHCP snooping,
  port security (Level 16/17).

### 2.5 IPv6 analog
- IPv6 link-local (`fe80::/10`) is *always* present and *normal* (Level 06) — unlike
  IPv4's APIPA which indicates a config failure. Do not confuse the two stories.

## 3. Configuration / Commands

```text
# See the APIPA state on a client
ipconfig /all        # IPv4 = 169.254.x.x, mask /16

# Server side — the real fix: healthy DHCP
service dhcp
 ip dhcp excluded-address 10.1.10.1
 ip dhcp pool CLIENTS
   network 10.1.10.0 255.255.255.0
   default-router 10.1.10.1

# Verify reachability on segment (both must be in 169.254 range)
ping 169.254.10.10
```

---

## 4. Exam Traps

- **169.254.x.x = DHCP failure symptom** — not "a class" and not "private for use."
- **No gateway, no Internet** — don't suggest a route into/out of APIPA.
- **It's within /16 link-local on the segment only.**
- **IPv6 link-local ≠ APIPA** — link-local is normal there; APIPA means DHCP broke.
- **Only applies to automatically-configured hosts**; a static bad IP never yields APIPA.
