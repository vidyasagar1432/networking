# Public IP

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **public IPv4 address** is a **globally unicast IPv4 address** that is not reserved for private or other special-purpose use and is eligible for routing on the public Internet.

Public IPv4 addresses are globally coordinated through **IANA → RIR → ISP/LIR → customer** allocation/delegation. IPv4 address scarcity led to widespread use of **NAT/PAT** and accelerated adoption of **IPv6**.

> **Exam definition:** Public does **not** simply mean "anything outside RFC 1918." An address can be non-RFC-1918 and still be reserved for another special purpose.

---

## 2. Core Concepts

### 2.1 Who Assigns Public IPv4 Addresses

The general allocation hierarchy is:

```text
IANA
  ↓
RIR
  ↓
ISP / LIR
  ↓
Customer / Organization
```

Major RIRs include:

- **ARIN** — North America
    
- **RIPE NCC** — Europe, Middle East, parts of Central Asia
    
- **APNIC** — Asia-Pacific
    
- **LACNIC** — Latin America and Caribbean
    
- **AFRINIC** — Africa
    

IPv4 address space is globally coordinated by **IANA**, while RIRs manage regional allocation and registration.

---

### 2.2 What Makes an IPv4 Address Public?

A public IPv4 address is generally:

- **Globally unicast**
    
- **Not RFC 1918 private space**
    
- **Not reserved for another special purpose**
    
- **Eligible for Internet routing**
    
- Globally coordinated/allocated so that addresses are not normally duplicated as independent unicast assignments
    

### RFC 1918 Private IPv4

|Private Range|CIDR|
|---|--:|
|`10.0.0.0 – 10.255.255.255`|`10.0.0.0/8`|
|`172.16.0.0 – 172.31.255.255`|`172.16.0.0/12`|
|`192.168.0.0 – 192.168.255.255`|`192.168.0.0/16`|

These addresses are intended for **private networks** and are **not globally routable on the public Internet**.

> **Important:** `172.20.10.5` is private, but `172.32.10.5` is not in the RFC 1918 range. However, that does **not automatically mean every non-RFC-1918 address is usable as a public Internet address**; special-purpose ranges must also be considered.

---

### 2.3 Public vs. Special-Purpose Addresses

Not every address outside RFC 1918 is a normal public address.

Examples of special-purpose IPv4 space include:

|Purpose|Range / Example|
|---|---|
|Private|`10.0.0.0/8`|
|Private|`172.16.0.0/12`|
|Private|`192.168.0.0/16`|
|Loopback|`127.0.0.0/8`|
|Link-local / APIPA|`169.254.0.0/16`|
|Multicast|`224.0.0.0/4`|
|Documentation|`192.0.2.0/24`|
|Documentation|`198.51.100.0/24`|
|Documentation|`203.0.113.0/24`|

Therefore:

```text
Not RFC 1918
        ≠
Automatically a usable public IPv4 address
```

Always check whether the address belongs to another **special-purpose range**.

## 3. Common Uses

|Use Case|Example|
|---|---|
|Internet-facing servers|Web, mail, DNS services|
|Edge routers|WAN-facing interfaces|
|NAT/PAT|Public address used for Internet access|
|Static NAT|Public address mapped to an internal server|
|Cloud services|Publicly reachable application endpoints|
|Anycast|Same public address advertised from multiple locations|

### Anycast Exception

Public addressing does **not always mean one physical location has one unique IP**.

With **anycast**, the **same IP address is intentionally advertised from multiple locations**. Internet routing directs users toward an appropriate/nearest available path.

```text
             Same public IP
             203.x.x.x
                  |
        +---------+---------+
        |                   |
      Site A              Site B
     Route it             Route it
```

> **Exam point:** Anycast intentionally uses the **same address at multiple locations**.

---

## 4. Public IPv4 and NAT/PAT

IPv4 scarcity led to widespread use of **Network Address Translation (NAT)**.

### NAT

NAT can provide a **one-to-one** translation:

```text
Inside Local          Public Address
192.168.1.10   ↔      203.x.x.10
```

### PAT / NAT Overload

PAT allows **many private hosts to share one public IPv4 address** by using different transport-layer ports.

```text
192.168.1.10:50001 ─┐
192.168.1.11:50002 ─┼──→ 203.x.x.10:xxxxx
192.168.1.12:50003 ─┘
```

> **Exam trap:**  
> **NAT ≠ always many-to-one.**  
> **PAT/NAT overload** is the many-private-hosts-to-one-public-address model.

---

## 5. Public IPv4 and IPv6

IPv4 has a limited address space, which contributed to:

- NAT/PAT deployment
    
- Address conservation
    
- IPv4 transfer markets
    
- IPv6 adoption
    

IPv6 provides a **vastly larger address space** and supports globally routable unicast addressing without IPv4-scale address exhaustion.

---

## 6. Security Reality

A public IP does **not automatically mean the host is reachable on every port**.

Reachability depends on:

- Routing
    
- ACLs
    
- Firewalls
    
- NAT rules
    
- Service configuration
    
- Host-based security controls
    

Internet-facing systems should be appropriately hardened.

Typical protections include:

- **ACLs**
    
- **Stateful firewalls**
    
- **IDS/IPS**
    
- **Rate limiting**
    
- **Secure management protocols**
    
- **Minimal exposed services**
    

> **Exam point:** Public addressing means the address is potentially Internet-reachable; it does **not** mean every service is automatically accessible.

## 7. Configuration / Commands

### 7.1 Example Public/WAN Interface

The following uses `198.51.100.0/24`, which is **RFC 5737 documentation space** and should only be used for examples/labs.

```cisco
interface GigabitEthernet0/0
 ip address 198.51.100.2 255.255.255.0
 no shutdown
```

### 7.2 Example ACL

Allow HTTPS traffic to a public server:

```cisco
access-list 100 permit tcp any host 198.51.100.10 eq 443
```

> `198.51.100.0/24` is documentation space, not a real public service network.

## 8. Documentation IPv4 Ranges

RFC 5737 defines IPv4 ranges intended for documentation and examples:

|Range|Purpose|
|---|---|
|`192.0.2.0/24`|Documentation|
|`198.51.100.0/24`|Documentation|
|`203.0.113.0/24`|Documentation|

These should **not** be treated as normal Internet-routable production addresses.

## 9. Exam Traps

### Trap 1 — Public ≠ Anything Outside RFC 1918

Incorrect:

```text
"If it isn't RFC 1918, it is public."
```

Correct:

```text
Public = globally unicast + not private/special-purpose
        + eligible for Internet routing
```

---

### Trap 2 — Public ≠ Automatically Reachable

A public address can still be protected by:

- Firewall
    
- ACL
    
- NAT
    
- Security policy
    
- Closed service ports
    

---

### Trap 3 — NAT vs. PAT

```text
NAT  → can be one-to-one
PAT  → many-to-one using ports
```

---

### Trap 4 — Documentation Addresses

These are **not production public addresses**:

```text
192.0.2.0/24
198.51.100.0/24
203.0.113.0/24
```

---

### Trap 5 — `8.8.8.8`

`8.8.8.8` is a **public IPv4 address** used by Google's public DNS service.

---

### Trap 6 — Private Addresses Are Not Internet-Routable

RFC 1918 addresses can be routed normally **inside private networks**, but they are not globally routable across the public Internet.

---

### Trap 7 — Anycast

A public IP does not necessarily identify one physical device or one location.

**Anycast intentionally advertises the same IP address from multiple locations.**
