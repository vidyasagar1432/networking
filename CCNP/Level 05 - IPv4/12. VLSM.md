# VLSM (Variable-Length Subnet Masking)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**VLSM (Variable-Length Subnet Masking)** allows a single address space to be divided  
into subnets with **different prefix lengths**, so each subnet can be sized according  
to its actual host requirement.

VLSM improves IPv4 address utilization compared with **FLSM (Fixed-Length Subnet  
Masking)**, where every subnet must use the same prefix length.

> **Core idea:** Give each subnet only as much address space as it needs.

---

## 2. Core Concepts

### 2.1 VLSM vs. FLSM

|Feature|FLSM|VLSM|
|---|---|---|
|Mask|Same mask on every subnet|Different mask per subnet|
|Example|`10.0.0.0/24` → all `/26`|`10.0.0.0/24` → `/26`, `/27`, `/28`, `/30`|
|Address efficiency|Can waste addresses|More efficient|
|Planning|Simpler|Requires careful planning|
|Routing requirement|Classless protocols for variable prefixes in routing|Classless routing protocol required|

### 2.2 Classic VLSM Example

Given:

```text
Network: 10.10.0.0/24

Requirements:
A = 50 hosts
B = 25 hosts
C = 10 hosts
D = 2 hosts
```

Always allocate **largest requirements first**.

|Subnet|Hosts Needed|Prefix|Block Size|Network|Usable Hosts|Broadcast|
|---|--:|--:|--:|---|---|---|
|A|50|`/26`|64|`10.10.0.0`|`.1 – .62`|`.63`|
|B|25|`/27`|32|`10.10.0.64`|`.65 – .94`|`.95`|
|C|10|`/28`|16|`10.10.0.96`|`.97 – .110`|`.111`|
|D|2|`/30`|4|`10.10.0.112`|`.113 – .114`|`.115`|

The remaining address space is:

```text
10.10.0.116 – 10.10.0.255
```

This can be used for additional subnets later.

> **Important:** VLSM subnets must be **properly aligned and must not overlap**.

---

### 2.3 VLSM Sizing Rule

For a traditional IPv4 subnet, reserve:

```text
Network address + usable host addresses + broadcast address
```

Therefore:

```text
2^h ≥ Hosts Required + 2
```

Where `h` is the number of host bits.

Then:

```text
Prefix Length = 32 − h
```

Examples:

|Hosts Needed|Calculation|Block Size|Prefix|
|--:|---|--:|--:|
|2|`2² = 4`|4|`/30`|
|6|`2³ = 8`|8|`/29`|
|10|`2⁴ = 16`|16|`/28`|
|14|`2⁴ = 16`|16|`/28`|
|25|`2⁵ = 32`|32|`/27`|
|30|`2⁵ = 32`|32|`/27`|
|50|`2⁶ = 64`|64|`/26`|
|62|`2⁶ = 64`|64|`/26`|
|126|`2⁷ = 128`|128|`/25`|
|254|`2⁸ = 256`|256|`/24`|

### Quick Formula

```text
Hosts + 2
    ↓
Next power of 2
    ↓
Block size
    ↓
Prefix = 32 − log₂(Block Size)
```

Example:

```text
50 hosts
50 + 2 = 52
Next power of 2 = 64
64 addresses = /26
```

---

### 2.4 Block Alignment

Every subnet must start at a valid **block boundary**.

|Prefix|Block Size|Valid Network Boundaries in Last Octet|
|---|--:|---|
|`/30`|4|`.0, .4, .8, .12, ...`|
|`/29`|8|`.0, .8, .16, .24, ...`|
|`/28`|16|`.0, .16, .32, .48, ...`|
|`/27`|32|`.0, .32, .64, .96, ...`|
|`/26`|64|`.0, .64, .128, .192`|
|`/25`|128|`.0, .128`|

For example:

```text
10.10.0.64/27  → valid
10.10.0.80/27  → invalid network boundary
```

A `/27` has a block size of `32`, so its network addresses must be multiples  
of `32`.

## 3. VLSM Requirements

VLSM requires routing protocols that can carry the **subnet mask/prefix length**  
with the route.

Examples of classless routing protocols include:

- **RIPv2**
    
- **OSPF**
    
- **EIGRP**
    
- **IS-IS**
    
- **BGP**
    

### Classful vs. Classless

|Protocol|Classless?|VLSM Support|
|---|---|---|
|RIPv1|❌ No|❌|
|RIPv2|✅ Yes|✅|
|OSPF|✅ Yes|✅|
|EIGRP|✅ Yes|✅|
|IS-IS|✅ Yes|✅|
|BGP|✅ Yes|✅|

> **Exam trap:** RIPv1 does not support VLSM because it does not advertise the subnet mask.

---

## 4. VLSM and Routing

VLSM is primarily an **addressing/subnetting technique**. The routing protocol  
must be able to advertise routes with their prefix lengths.

For example, the same major network can contain:

```text
10.10.0.0/26
10.10.0.64/27
10.10.0.96/28
10.10.0.112/30
```

A classless routing protocol can distinguish these different prefixes.

A classful protocol such as RIPv1 cannot properly advertise this variable  
subnetting information.

---

## 5. VLSM and Summarization

VLSM and route summarization are related but different concepts.

- **VLSM** → divides an address space using different prefix lengths.
    
- **Summarization** → combines multiple contiguous routes into a shorter prefix.
    

Example:

```text
10.10.0.0/26
10.10.0.64/26
10.10.0.128/26
10.10.0.192/26
```

These four contiguous `/26` networks can be summarized as:

```text
10.10.0.0/24
```

> **Important:** A summary must cover the intended networks without accidentally  
> including unrelated networks.

---

## 6. Configuration Example

VLSM itself does not require a special Cisco command.

You simply configure each interface with the appropriate subnet mask.

```cisco
interface Vlan10
 ip address 10.10.0.1 255.255.255.192
 no shutdown

interface Vlan20
 ip address 10.10.0.65 255.255.255.224
 no shutdown

interface Serial0/0
 ip address 10.10.0.113 255.255.255.252
 no shutdown
```

The masks are:

```text
255.255.255.192 = /26
255.255.255.224 = /27
255.255.255.252 = /30
```

> The interface IP must be a **usable host address**, not the network or broadcast  
> address.

## 7. VLSM Planning Procedure

Use this procedure on exam questions:

### Step 1 — Identify the available address space

Example:

```text
10.10.0.0/24
```

### Step 2 — List all host requirements

```text
A = 50
B = 25
C = 10
D = 2
```

### Step 3 — Sort from largest to smallest

```text
50 → 25 → 10 → 2
```

### Step 4 — Calculate each subnet size

```text
50 → /26 → 64 addresses
25 → /27 → 32 addresses
10 → /28 → 16 addresses
 2 → /30 →  4 addresses
```

### Step 5 — Allocate sequentially

```text
10.10.0.0/26
10.10.0.64/27
10.10.0.96/28
10.10.0.112/30
```

### Step 6 — Verify

Check:

- Correct host capacity
    
- Correct network boundaries
    
- No overlapping subnets
    
- Correct broadcast addresses
    
- Correct usable host ranges
    
- Remaining address space

## 8. Exam Traps

### Trap 1 — Allocate largest first

Always sort requirements:

```text
Largest → smallest
```

This reduces fragmentation and makes VLSM planning easier.

### Trap 2 — Forgetting `+2`

For traditional IPv4 subnetting:

```text
Required addresses = hosts + network + broadcast
```

So:

```text
50 hosts
→ 52 addresses required
→ 64-address block
→ /26
```

### Trap 3 — Wrong network boundary

A `/28` has a block size of `16`.

Valid networks:

```text
.0
.16
.32
.48
.64
.80
.96
.112
...
```

Therefore:

```text
10.10.0.96/28  → valid
10.10.0.100/28 → not a network address
```

### Trap 4 — Overlapping subnets

Incorrect:

```text
10.10.0.0/26
10.10.0.32/27
```

The `/27` lies inside the `/26` range and therefore overlaps.

Correct:

```text
10.10.0.0/26
10.10.0.64/27
```

### Trap 5 — RIPv1

If the question asks which routing protocol **cannot support VLSM**:

```text
RIPv1
```

is the classic answer.

### Trap 6 — `/30` is not the only point-to-point option

A `/30` provides:

```text
4 addresses
2 usable host addresses
```

It is traditionally common for point-to-point links.

Modern IPv4 point-to-point links can also use **/31**, which provides two addresses  
and is specifically designed for point-to-point links.

```text
VLSM = different subnet masks for different subnets.

Main goal:
→ Efficient IPv4 address utilization.

Planning:
→ Sort largest host requirement first.
→ Calculate required block size.
→ Use proper block alignment.
→ Allocate sequentially.
→ Never overlap.

Formula:
→ 2^h ≥ hosts + 2
→ Prefix = 32 − h

Common sizes:
→ 2 hosts   = /30
→ 6 hosts   = /29
→ 14 hosts  = /28
→ 30 hosts  = /27
→ 62 hosts  = /26
→ 126 hosts = /25
→ 254 hosts = /24

Routing:
→ VLSM requires classless routing protocols.
→ RIPv1 = classful = no VLSM support.
→ RIPv2, OSPF, EIGRP, IS-IS, BGP = classless.

Key exam rule:
→ Largest first + correct alignment + no overlap.
```

### Core Mental Model

```text
Host requirement
      ↓
Add network + broadcast
      ↓
Choose next power-of-2 block
      ↓
Calculate prefix
      ↓
Place at correct boundary
      ↓
Repeat from largest → smallest
```
