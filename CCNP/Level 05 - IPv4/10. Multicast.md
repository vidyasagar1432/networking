# Multicast (IPv4)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Multicast** delivers a single transmission to a **group of subscribing receivers** —
one source, many interested destinations — using **Class D** addresses (224.0.0.0/4).
It's efficient for streaming video/audio, IPTV, and some routing protocols (OSPF, EIGRP).

---

## 2. Core Concepts

### 2.1 Addressing & groups
- **Class D**: `224.0.0.0 – 239.255.255.255`.
- **Well-known/Link-local** (≤224.0.0.255, TTL 1 — same segment only):
  - `224.0.0.1` all hosts on the subnet
  - `224.0.0.2` all routers
  - `224.0.0.5` OSPF routers → 224.0.0.6 OSPF DRs/BDRs (designated)
  - `224.0.0.9` RIPv2, `224.0.0.10` EIGRP
  - `224.0.0.22` IGMP
- **Globally scopeable** (routable): `224.0.1.0 – 238.255.255.255`.
- **Admin-scoped**: `239.0.0.0/8` (enterprise-internal "local" multicast).
- **Restricted (239.192.0.0/14 etc.)** — single org.

### 2.2 How the group works
1. Receiver joins group via **IGMP** (Level 19) — "I want 239.1.1.1."
2. Routers build the multicast distribution using **PIM** (sparse/dense, RP) — Level 19.
3. Source sends **one copy** per link; routers replicate only where subscribers exist.

### 2.3 Multicast at L2/Ethernet
- IPv4 multicast → **multicast MAC**: `01:00:5E:00:00:00–01:00:5E:7F:FF:FF`.
- Mapping: **low 23 bits** of the IP group go into the MAC suffix → **~5-bit collision
  overlap** (multiple IP groups can map to same MAC) — the "mapping collision" trap.
- Switches with **IGMP snooping** forward multicast only to interested ports
  (else it floods) — Level 19.

### 2.4 Unicast/broadcast/multicast compare

| | Unicast | Broadcast | Multicast |
|--|---------|-----------|-----------|
| Dest | one | all in domain | group |
| Efficiency | one copy per recipient | always all | only subscribers |
| Routeable | yes | no | yes (PIM) |
| Typical | web/ssh | ARP/DHCP | IPTV/VRRP/OSPF hello |

### 2.5 Exam-worthy details
- **TTL=1** for 224.0.0.x — stays local (that's how OSPF hellos never route).
- **SSM** (Source-Specific Multicast, 232.0.0.0/8) — join by (S,G) — modern streaming.
- **Rendezvous Point (RP)** in PIM-SM — the meeting point (Level 19).

## 3. Configuration / Commands

```text
# Enable multicast routing totally (routers):
ip multicast-routing
interface Gi0/1
 ip igmp version 3             # receivers capability
# PIM on interfaces
interface Gi0/1
 ip pim sparse-mode            # typical

show ip mroute
show ip igmp groups
```

## 4. Exam Traps

- **Class D has no host/network split** — no subnetting of groups; they're addresses, not subnets.
- **Multicast MAC collision**: 32-group-bits → 23-bit map → overlaps possible. The
  known "0.0.0.x vs multiply to same MAC" trap.
- **TTL=1 for link-local multicast** — the reason OSPF/EIGRP hellos don't leave the segment.
- **IP multicast ≠ broadcast** — it's group-based, routed; broadcast is not routed.
- **IGMP snooping on switches** stops flooding of multicast — otherwise floods like broadcast.
- Well-known groups: 224.0.0.5/6 OSPF, 224.0.0.10 EIGRP, 224.0.0.9 RIPv2.
