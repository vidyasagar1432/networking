# Broadcast (IPv4)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

An **IPv4 broadcast** is traffic addressed to **multiple/all hosts within a broadcast domain**.

IPv4 has two important broadcast addresses:

1. **Directed broadcast** — the address with all **host bits = 1** for a specific subnet.
    
2. **Limited broadcast** — `255.255.255.255`, restricted to the **local broadcast domain**.
    

Broadcasts are normally **not routed between IPv4 subnets**. Routers form broadcast boundaries.

---

## 2. Core Concepts

### 2.1 The two IPv4 broadcast forms

|Type|Address|Scope|Key point|
|---|---|---|---|
|**Directed broadcast**|Host bits all `1`|Specific destination subnet|Normally not forwarded by routers|
|**Limited broadcast**|`255.255.255.255`|Local broadcast domain|Never routed|

### Directed broadcast

A directed broadcast identifies a **specific subnet** by using all `1`s in the host portion.

Example:

```text
10.1.1.0/24
Network:   10.1.1.0
Broadcast: 10.1.1.255
```

The destination `10.1.1.255` means **broadcast to hosts on the `10.1.1.0/24` subnet**.

### Limited broadcast

```text
255.255.255.255
```

This means **broadcast on the local IPv4 network/interface**.

It does not identify a particular remote subnet and is **not forwarded by routers**.

---

## 2.2 Broadcast domain and Layer 2

An IPv4 broadcast on Ethernet is normally carried using the Ethernet broadcast destination:

```text
FF:FF:FF:FF:FF:FF
```

Broadcast traffic remains within the **Layer 2 broadcast domain**, normally a VLAN.

```text
        VLAN 10 / Broadcast Domain
 ┌─────────────────────────────────────┐
 │                                     │
 │  PC1 ─── Switch ─── PC2             │
 │           │                         │
 │           └────── PC3               │
 │                                     │
 │       IPv4 Broadcast                │
 │              ↓                      │
 │       FF:FF:FF:FF:FF:FF             │
 └─────────────────────────────────────┘
                  │
               Router
                  │
            Broadcast stops
```

A router normally **does not forward IPv4 broadcasts** from one subnet to another.

> **Exam rule:** A router is normally a **broadcast boundary**.

---

## 2.3 Common IPv4 broadcast traffic

### ARP

ARP requests use an IPv4 broadcast at Layer 3:

```text
Who has 10.1.1.99?
```

The Ethernet destination is:

```text
FF:FF:FF:FF:FF:FF
```

IPv6 does **not** use ARP or IPv4-style broadcasts. IPv6 uses **Neighbor Discovery (ND)** with ICMPv6 multicast.

### DHCP

DHCP clients commonly use broadcast messages during initial address acquisition because the client may not yet have a usable IPv4 address or know the DHCP server.

A DHCP relay can forward DHCP requests between subnets by converting the Layer 2 broadcast into a routed/unicast forwarding process.

> **Important:** Do not assume every DHCP message is always a broadcast.

### RIPv1

RIPv1 uses the IPv4 limited broadcast:

```text
255.255.255.255
```

### RIPv2

RIPv2 uses multicast instead:

```text
224.0.0.9
```

Therefore:

> **RIPv1 = broadcast**  
> **RIPv2 = multicast**

## 2.4 Directed broadcast calculation

A subnet's broadcast address is obtained by setting **all host bits to `1`**.

### Example 1 — `/24`

```text
Network:   10.1.1.0/24
Broadcast: 10.1.1.255
```

A `/24` has:

```text
24 network bits
8 host bits
```

All 8 host bits set to `1` gives:

```text
11111111 = 255
```

Therefore:

```text
10.1.1.255
```

### Example 2 — `/26`

```text
Network: 10.1.10.64/26
```

A `/26` has a block size of:

```text
256 - 192 = 64
```

The subnet is:

```text
Network:   10.1.10.64
Usable:    10.1.10.65 - 10.1.10.126
Broadcast: 10.1.10.127
```

Therefore:

```text
10.1.10.64/26
        ↓
Broadcast = 10.1.10.127
```

> **Exam trap:** `10.1.10.79` is **not** the broadcast address of `10.1.10.64/26`.

## 2.5 Network, usable hosts, and broadcast

For a normal IPv4 subnet:

```text
Network address
      ↓
[ Network | Usable Hosts | Broadcast ]
                         ↑
                    host bits = 1
```

Example:

```text
192.168.10.0/24

Network:   192.168.10.0
Usable:    192.168.10.1 - 192.168.10.254
Broadcast: 192.168.10.255
```

For a conventional subnet:

```text
Usable hosts = 2^host_bits - 2
```

The two excluded addresses are:

- **Network address** — host bits all `0`
    
- **Broadcast address** — host bits all `1`
    

### Important exceptions

The `−2` rule should not be blindly applied to every prefix.

- `/31` is commonly used for point-to-point links and has **two usable addresses** under RFC 3021.
    
- `/32` represents a single host route and has no conventional network/broadcast pair.
    

---

## 2.6 Directed broadcast forwarding

Routers normally do **not** forward directed broadcasts.

However, a router can be explicitly configured to allow directed broadcasts toward a destination subnet.

Modern Cisco IOS commonly disables directed-broadcast forwarding by default.

```text
no ip directed-broadcast
```

This helps prevent attacks such as **Smurf attacks**, where an attacker abuses directed broadcasts to amplify ICMP traffic.

> **Exam distinction:**  
> **Directed broadcast** can identify a remote subnet, but routers normally block forwarding it.  
> **Limited broadcast** (`255.255.255.255`) is local-only and is not routed.

---

## 2.7 Broadcast storms

A **broadcast storm** occurs when excessive broadcast traffic consumes network resources.

Possible causes include:

- Layer 2 loops
    
- Misconfigured devices
    
- Excessive ARP/DHCP traffic
    
- Faulty or malicious hosts
    

Common controls include:

- **STP**
    
- **Storm control**
    
- VLAN segmentation
    
- Loop prevention
    
- Appropriate Layer 2 design
    

Example Cisco configuration:

```text
interface GigabitEthernet0/1
 storm-control broadcast level 20
```

The exact storm-control threshold should be chosen according to the network design.

## 3. Configuration / Commands

### Disable directed-broadcast forwarding

```text
interface GigabitEthernet0/1
 no ip directed-broadcast
```

This prevents the interface from forwarding directed broadcasts toward that subnet.

### View broadcast-related interface counters

```text
show interfaces
```

You can filter output in the CLI:

```text
show interfaces | include broadcast
```

### Configure broadcast storm control

```text
interface GigabitEthernet0/1
 storm-control broadcast level 20
```

## 4. Exam Traps

### Trap 1 — `255.255.255.255`

```text
255.255.255.255
```

is the **limited broadcast**, not the broadcast address of every subnet.

It is restricted to the local broadcast domain.

---

### Trap 2 — Directed broadcast

For:

```text
192.168.20.0/24
```

the directed broadcast is:

```text
192.168.20.255
```

because all host bits are `1`.

---

### Trap 3 — `/26` broadcast calculation

For:

```text
10.1.10.64/26
```

the broadcast is:

```text
10.1.10.127
```

not `.79`.

---

### Trap 4 — Broadcasts and routers

A router normally **does not forward IPv4 broadcasts** between subnets.

Exception:

- A configured **DHCP relay** can forward DHCP requests between subnets.
    
- A router can be configured to permit **directed-broadcast forwarding**.
    

---

### Trap 5 — ARP vs IPv6 ND

```text
IPv4 → ARP
IPv6 → Neighbor Discovery (ND)
```

IPv6 does not use ARP.

---

### Trap 6 — RIPv1 vs RIPv2

```text
RIPv1 → 255.255.255.255 broadcast
RIPv2 → 224.0.0.9 multicast
```

Do not confuse RIPv2 with broadcast traffic.

---

### Trap 7 — Host bits

```text
Host bits all 0 → Network address
Host bits all 1 → Broadcast address
```

For a normal subnet, neither is assigned to an ordinary host.
