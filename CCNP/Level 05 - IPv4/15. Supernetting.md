# Supernetting

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Supernetting** combines multiple **contiguous networks of the same size** into one larger network using a **shorter prefix length**.

It is essentially the **opposite of subnetting**:

- **Subnetting:** one larger network → multiple smaller networks
    
- **Supernetting:** multiple smaller networks → one larger network
    

Supernetting is enabled by **CIDR (Classless Inter-Domain Routing)** and is commonly used for **route aggregation**, especially at ISP and Internet routing boundaries.

> **Key idea:** Supernetting reduces multiple routes into one less-specific route.

---

## 2. Core Concepts

### 2.1 Supernetting vs Subnetting

|Feature|Subnetting|Supernetting|
|---|---|---|
|Direction|Large → smaller|Smaller → larger|
|Prefix|Longer|Shorter|
|Purpose|Divide address space|Aggregate address space|
|Example|`/16 → /24s`|`8 × /24 → /21`|
|Main benefit|Efficient internal allocation|Fewer routing entries|

---

### 2.2 How Supernetting Works

For networks that start as `/24` blocks:

|Number of `/24` Networks|Supernet Prefix|
|--:|--:|
|2|`/23`|
|4|`/22`|
|8|`/21`|
|16|`/20`|
|32|`/19`|
|64|`/18`|
|128|`/17`|
|256|`/16`|

### Formula

For `N` equal-sized networks:

```text
New prefix = Original prefix − log₂(N)
```

Example:

```text
8 × /24

/24 − log₂(8)
/24 − 3
= /21
```

Therefore:

```text
8 × /24 = 1 × /21
```

---

## 3. Alignment — The Critical Rule

A valid supernet must be **properly aligned** on the boundary of the new prefix.

For example, a `/20` contains:

```text
2^(24−20) = 16 × /24 networks
```

Therefore, `/20` boundaries in the third octet occur in multiples of 16:

```text
.0–.15
.16–.31
.32–.47
.48–.63
...
```

### Valid Example

These `/24` networks:

```text
200.5.16.0/24
200.5.17.0/24
...
200.5.31.0/24
```

can be aggregated into:

```text
200.5.16.0/20
```

because `/20` covers exactly:

```text
200.5.16.0 – 200.5.31.255
```

### Invalid Alignment Example

Suppose you try to summarize:

```text
200.5.20.0/24
through
200.5.35.0/24
```

into a `/20`.

This is **not valid** because a `/20` boundary cannot start at `.20`.

A `/20` must start at:

```text
.0
.16
.32
.48
...
```

## 4. Supernetting vs Route Summarization

These concepts are closely related but should not be treated as perfectly identical.

|Supernetting|Route Summarization|
|---|---|
|Combines smaller networks into a larger prefix|Represents multiple routes with one summary route|
|Focuses on address/prefix aggregation|Focuses on routing behavior/design|
|Requires proper prefix alignment|Requires the summary to cover the intended routes|
|Uses CIDR|Can be implemented using routing protocols|
|Example: `4 × /24 → /22`|Example: OSPF area routes summarized as `/22`|

### Important

**CIDR is the underlying addressing mechanism.**

**Supernetting** is the creation/use of a larger CIDR block from smaller contiguous blocks.

**Route summarization/aggregation** is the routing practice of advertising that larger prefix instead of the individual more-specific routes.

They often produce the **same mathematical result**, but the terms describe different aspects of the operation.

---

## 5. Why Supernetting Is Used

### 5.1 Smaller Routing Tables

Instead of advertising:

```text
200.5.16.0/24
200.5.17.0/24
200.5.18.0/24
...
200.5.31.0/24
```

a router can advertise:

```text
200.5.16.0/20
```

This reduces the number of routing entries.

### 5.2 BGP Scalability

Internet and ISP networks use aggregation to reduce the number of prefixes advertised between autonomous systems.

Fewer prefixes can mean:

- Smaller routing tables
    
- Lower memory requirements
    
- Less routing information to process
    
- Better scalability
    

> **Important:** Route aggregation is one of the major reasons CIDR was introduced.

### 5.3 Hierarchical Network Design

Organizations can allocate address blocks hierarchically and advertise summaries at routing boundaries.

Example:

```text
                 Core
                  |
             10.10.0.0/20
                  |
        +---------+---------+
        |         |         |
     /24       /24       /24
```

The core does not necessarily need individual knowledge of every more-specific subnet if a suitable summary can represent them.

## 6. Cisco Configuration Examples

### 6.1 BGP Network Advertisement

A BGP `network` statement can advertise a supernet:

```cisco
router bgp 65001
 network 200.5.16.0 mask 255.255.240.0
```

This represents:

```text
200.5.16.0/20
```

> The route must exist in the local routing table for the BGP `network` statement to originate it.

---

### 6.2 Static Summary / Aggregate Route

A static route can represent the aggregated prefix:

```cisco
ip route 200.5.16.0 255.255.240.0 Null0
```

This creates:

```text
200.5.16.0/20 → Null0
```

A `Null0` summary route is commonly used with routing designs to prevent unwanted forwarding loops when a summary is advertised.

## 7. Exam Traps

### Trap 1 — Supernetting Uses a Shorter Prefix

```text
/24 → /23
/24 → /22
/24 → /21
```

Correct.

```text
/24 → /26
```

That is **subnetting**, not supernetting.

---

### Trap 2 — Alignment Matters

A `/22` contains:

```text
2^(24−22) = 4 × /24
```

Therefore, valid third-octet boundaries are:

```text
.0–.3
.4–.7
.8–.11
.12–.15
...
```

So:

```text
192.168.4.0/24
192.168.5.0/24
192.168.6.0/24
192.168.7.0/24
```

can correctly summarize to:

```text
192.168.4.0/22
```

---

### Trap 3 — Contiguity Is Required for a Simple Exact Supernet

These:

```text
192.168.4.0/24
192.168.5.0/24
192.168.6.0/24
192.168.7.0/24
```

are contiguous.

But:

```text
192.168.4.0/24
192.168.5.0/24
192.168.7.0/24
```

have a gap.

A single `/22` would also cover:

```text
192.168.6.0/24
```

whether or not that network is actually used.

Therefore, **do not assume that a summary is an exact representation of only the existing networks**.

---

### Trap 4 — Supernetting Does Not Require Classful Networking

Historically, the term "supernetting" was associated with combining classful networks such as multiple Class C networks.

Modern networking is **classless**.

Today, supernetting is fundamentally based on:

```text
CIDR + prefix aggregation
```

Do not assume that supernetting requires Class A/B/C addressing.

---

### Trap 5 — Summary Routes Can Cover Unused Space

A summary does not have to contain only currently assigned networks.

For example:

```text
192.168.4.0/22
```

covers:

```text
192.168.4.0/24
192.168.5.0/24
192.168.6.0/24
192.168.7.0/24
```

Even if only `.4/24` and `.5/24` are currently used.

This is sometimes called **route summarization with a covering prefix**.

Care must be taken to avoid black holes or unintended routing.

## 8. Quick Calculation Method

When asked to find a supernet:

### Step 1 — Count the networks

Example:

```text
8 × /24
```

### Step 2 — Calculate borrowed prefix bits

```text
log₂(8) = 3
```

### Step 3 — Subtract from the original prefix

```text
/24 − 3 = /21
```

### Step 4 — Check alignment

A `/21` contains:

```text
8 × /24
```

Therefore the third-octet starting point must be a multiple of:

```text
8
```

Valid examples:

```text
192.168.0.0/21
192.168.8.0/21
192.168.16.0/21
192.168.24.0/21
```

## 10. Exam Memory Rules

> **Supernetting = smaller networks → bigger network**

> **Supernet = shorter prefix**

> **More networks aggregated → fewer prefix bits**

> **`N` equal networks → prefix decreases by `log₂(N)`**

> **Alignment must match the new prefix**

> **CIDR enables classless aggregation**

> **Route summarization uses aggregation to reduce routing information**

### One-Line Exam Definition

**Supernetting is the aggregation of multiple contiguous, properly aligned networks into a single larger CIDR prefix using a shorter subnet mask.**
