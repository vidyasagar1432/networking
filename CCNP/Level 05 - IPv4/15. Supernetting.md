# Supernetting

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Supernetting** combines **several contiguous networks** into one larger
**less-specific** network (uses a mask *shorter* than the classful/default mask).
Its purpose: **address aggregation** for the Internet/ISP edge — shrink BGP tables.

---

## 2. Core Concepts

### 2.1 Supernet vs subnet

| | Subnetting | Supernetting |
|--|------------|--------------|
| Direction | big → smaller | small → bigger |
| Mask | longer than original | shorter than original |
| Use | internal design | route aggregation |
| Example | /16 → /24s | eight /24 → `/21` |

### 2.2 Formal definition
- Given Class C networks (each /24 default): combine 2 of them → `/23`;
  8 → `/22`; is the SL-rule? Supernet = sum of contiguous /24s with short prefix.
- ISP gives customer `200.5.16.0/20` (one entry) instead of advertising 16 × /24.

### 2.3 Alignment MUST hold
- A /20 supernet = 16 blocks of /24; must start on a boundary that is a **multiple of 16**
  (`x.16, x.32, ...`).
- Combining `200.5.16.0/24 … 200.5.31.0/24` (16 nets, .16–.31) → `/20` (`200.5.16.0/20`).
  Check the /20 range covers exactly .16–.31 (aligned!) to be valid.

### 2.4 Why do we supernet

| Reason | Detail |
|--------|--------|
| BGP table size | fewer entries, less memory |
| ISP prefixes | cleaner advertisements |
| Routing efficiency | require fewer prefixes |
| Scalability | summarize huge blocks (e.g., /8) |

### 2.5 Supernet vs summary — same math, different roots

| | Supernetting | Summarization |
|--|--------------|---------------|
| Origin | classful aggregation | any (CIDR) aggregation |
| Yes | 256−1 terms in block units | contiguous networks |
| Modern | one of the CIDR tools | a design practice |
Both shrink routes; exams often use them interchangeably (see also Level 16 Route Aggregation).

## 3. Configuration / Commands

```text
# Same effect — a supernet is just an ACL/Prefix-L statement:
# In BGP:
router bgp 65001
 network 200.5.16.0 mask 255.255.240.0
# Or a static aggregate:
ip route 200.5.16.0 255.255.240.0 10.0.0.1 null0   # and/or NH discard
```

---

## 4. Exam Traps

- **Supernet mask is SHORTER than original** — a /20 for /24 blocks.
- **Alignment** trap: e.g., "/22 supernet of 192.168.4.x through 192.168.7.x"? — depends
  on starting block (must begin at .4 for a clean /22).
- **Not all same-size networks fit one supernet** — must be contiguous; gaps break it.
- **CIDR is the mechanism**; supernetting is *using* it.
- **Never call subnetting "supernetting"** — they're inverse operations.
