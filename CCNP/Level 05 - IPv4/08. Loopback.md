# Loopback (127.0.0.0/8 & Loopback Interfaces)

> **Level 05 · IPv4** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

"Loopback" means two things:
1. Host-local **IP loopback**: `127.0.0.0/8` — a device's own software address
   (e.g., `127.0.0.1` = localhost).
2. **Loopback interface** on routers — a virtual, always-up interface used for
   OSPF/BGP router-ID, management, and stable source addressing.

---

## 2. Core Concepts

### 2.1 IP loopback (host stack)
- Address `127.0.0.1` (and the whole /8) refers to the local host; packets to it are
  processed locally, never on the wire.
- Used to test the local TCP/IP stack:
  ```
  ping 127.0.0.1   # "does IP work on this host?"
  ```
- A failure of ping 127.0.0.1 = broken IP stack (driver/stack issue), not the network.

### 2.2 Loopback interface (network device)
- A **virtual interface** configured on the box (`interface Loopback0`), **never down**
  (unless administratively).
- Always reachable as long as any path exists → ideal **router-id / source / management**.
- Best practice: a /32 address on lo0/lo1.

### 2.3 Why routers use loopback (ENCS favorites)

| Use | Reason |
|-----|--------|
| **Router ID (OSPF/EIGRP/BGP)** | highest loopback IP (or manually set) stays stable |
| **BGP peering source** | remote peers can rely on the loopback address persisting |
| **Management source** | SSH/NTP/SNMP sourced from a reachable /32 |
| **Tunnels' source** | tunnel interfaces use it |
| **Testing** | ping from loopback = device self-check |

### 2.4 Default IPv4 loopback in Cisco
```text
interface Loopback0
 ip address 10.255.255.1 255.255.255.255   # convention: network (any) mannagable /32
```
- Std trick: designates a range e.g., `10.0.0.x/32` for routers' loopbacks.
- OSPF router-id precedence: **manual `router-id` > loopback > highest IP on up interface**.

### 2.5 Loopback in verification

| Command | Meaning |
|---------|---------|
| `show ip interface loopback 0` | status up |
| `ping 127.0.0.1` | host stack test |
| `ping <loopback>` from itself | L3 ambity |

## 3. Configuration / Commands

```text
# Normal device loopback interface
interface Loopback0
 ip address 10.0.0.1 255.255.255.255
 no shutdown

# Force OSPF router-id from loopback
router ospf 1
 router-id 10.0.0.1

# Test the local stack
ping 127.0.0.1
```

---

## 4. Exam Traps

- **127.0.0.1 tests the host stack** — not the network or DNS; a failing ping 127 =>
  local stack, not "internet out."
- **Loopback never "down"** — survives interface outages → chosen for router-id/peering.
- **Router-id preference**: `router-id` command > loopback IP > highest active IP.
- **Using loopback on your router ≠ 127.0.0.1** — those are private/loop, distinct things.
- BGP/OSPF stability, management, testing = the three loopback justifications.
