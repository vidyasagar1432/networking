# OSPF Troubleshooting

> **Level 10 · OSPF** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

OSPF troubleshooting follows the **layer model**: neighbor adjacency → LSDB sync → SPF →
route installation → traffic. Most exam scenarios hang on **neighbor-state issues** (MTU,
hello/dead, area, network type, auth) or **area/type misconfiguration**. Use a strict
`show`-command progression to isolate the fault level.

---

## 2. Core Concepts

### 2.1 The troubleshooting flow (top-down)

| Step | Question | Command |
|------|----------|---------|
| 1. Interface | is the link up? | `show ip interface brief` |
| 2. Neighbor | adjacency formed? | `show ip ospf neighbor` |
| 3. LSDB | databases synchronized? | `show ip ospf database` |
| 4. Routes | SPF produced routes? | `show ip route ospf` |
| 5. Forwarding | CEF has it? | `show ip cef` / `ping` |

### 2.2 Neighbor-state fault table (the exam core)

| Stuck state | Classic cause | Confirm with |
|-------------|---------------|--------------|
| Down | no hellos (link/ACL/multicast) | `show ip ospf interface` |
| Init | one-way hello visibility | check both directions |
| 2-Way (no Full) | DR/BDR election issue | `show ip ospf neighbor detail` |
| **ExStart** | **MTU mismatch** | compare `mtu` / `ip ospf mtu-ignore` |
| Exchange | DBD issue / MTU | same as above |
| Loading | LSA request unfulfilled | `show ip ospf database` |

### 2.3 Parameter mismatch causes (the memorized list)

| Parameter | Must match |
|-----------|------------|
| Hello / Dead timers | both sides |
| Area ID | both sides |
| Network type | broadcast vs P2P mismatch |
| Authentication type + key | both sides |
| MTU | both sides (else ExStart stuck) |
| Subnet / address family | interface addressing |
| Stub flag | all routers in a stub/NSSA area |

### 2.4 Common operational issues

| Issue | Likely cause | Fix |
|-------|--------------|-----|
| Adjacency forms, no routes | LSDB not identical / DR DBD errors | `show ip ospf database` |
| Routes flap | flapping interface / dead timer | hello/dead tuning |
| External routes missing | stub area blocking Type 5 | use NSSA or default |
| Cost unexpectedly equal | default reference (100 Mbps) | `auto-cost reference-bandwidth` |
| SPF storm / high CPU | area too big / flap | summarize + ISPF + throttle |

### 2.5 The `clear` commands (maintenance)

```text
clear ip ospf process        ! reset neighbors, reconverge (brief outage)
clear ip ospf neighbor
clear ip ospf counters
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Neighbor stuck ExStart | MTU mismatch | match MTU or `ip ospf mtu-ignore` |
| Neighbor stuck INIT | one-way / auth / multicast | `debug ip ospf adjacency` |
| Neighbor stuck 2-Way | DR/BDR issue on broadcast | priorities, network type |
| No routes though Full | DR DBD/LSDB desync | `show ip ospf database` compare |
| External missing | stub area blocking Type 5 | area type |
| High CPU SPF | flapping / large area | ISPF + `timers throttle spf` |

---

## 5. Exam Traps

- **MTU mismatch → stuck ExStart** — the single most-tested OSPF fault.
- **Stub/NSSA flags must match** on all routers in the area or adjacencies fail.
- **Hello/dead mismatch → stuck in Init or Down** — never Full.
- **Auth mismatch → stuck in Init**.
- **DR/BDR issues** live on **broadcast** networks; P2P bypasses them.
- `clear ip ospf process` **reconverges** — it's a maintenance action, not a config fix.
- **2-Way between DROthers is normal** — do not "fix" it.

## 6. Quick Review Table

| Fault | State | Fix |
|-------|-------|-----|
| MTU mismatch | ExStart | match MTU / mtu-ignore |
| Hello/dead mismatch | Down/Init | match timers |
| Auth mismatch | Init | match type + key |
| Network type mismatch | neighbor issues | match type |
| Stub flag mismatch | no adjacency | match area type |
| DR issue | 2-Way stuck | priorities / P2P |
| External blocked | routes missing | area type / NSSA |
| SPF storm | high CPU | summarize + ISPF |
