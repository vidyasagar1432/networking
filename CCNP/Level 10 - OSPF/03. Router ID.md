# OSPF Router ID

> **Level 10 · OSPF** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **Router ID (RID)** is a **32-bit number** that uniquely identifies an OSPF router in
the LSDB — it appears in LSA headers, the Hello, and DR/BDR election. A stable, consistent
RID is critical: it prevents **duplicate-router confusion**, stabilizes DR elections, and
keeps LSAs meaningful. The exam loves the election order and the "change requires restart"
gotcha.

---

## 2. Core Concepts

### 2.1 Election order (memorize exactly)

1. **Explicitly configured** `router-id` (highest precedence).
2. **Highest IPv4 loopback address** (if any).
3. **Highest IPv4 physical interface address** (if any).
4. No IPv4 at all → OSPF may refuse to start (especially OSPFv3).

- Loopbacks win because they're always up; the **highest** is chosen (opposite of most
  elections).

### 2.2 OSPFv3 still uses a 32-bit RID

- Even IPv6-only OSPFv3 requires a 32-bit RID (config `router-id` or derive from IPv4
  loopback). No IPv4 → you **must** configure it manually.

### 2.3 The "change needs restart" gotcha

- Changing `router-id` while OSPF is running **does not take effect until the OSPF process
  is restarted** (`clear ip ospf process` or reload) — until then the old RID persists.
- Restarting the process **reconverges everything** (brief outage) — plan for maintenance.

### 2.4 RID and neighbor/DR behavior

- Neighbor identity = RID (not IP address) in `show ip ospf neighbor`.
- **DR/BDR election** uses RID as the tie-breaker (highest RID wins if priority ties —
  note 05).
- Duplicate RIDs → neighbors flap/never form; **the RID must be unique domain-wide** per
  area (and for the backbone/domain scope).

### 2.5 Best practice

```text
router ospf 1
 router-id 10.255.255.1        ! loopback-style number, stable
```

- Use a planned loopback-like number, not the physical interface — keeps RID constant
  across interface changes/reboots.

## 3. Configuration / Commands

```text
router ospf 1
 router-id 1.1.1.1

! Force the change immediately
clear ip ospf process

show ip ospf | include Router ID
show ip ospf neighbor            ! neighbor column shows RIDs
show ip ospf database router     ! LSAs authored by each RID
```

---

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Neighbors flap | duplicate RID somewhere | `show ip ospf neighbor` RIDs |
| New RID not applied | process not restarted | `clear ip ospf process` |
| OSPFv3 won't start | no IPv4 and no configured RID | set `router-id` |
| DR unexpectedly changed | RID changed (config/reboot) | restart + verify RID |
| LSAs orphaned | old RID cached | clear database / process |

---

## 5. Exam Traps

- **Election: explicit > highest loopback > highest physical IPv4.**
- **Highest, not lowest** — RID election reverses the "lowest wins" instinct.
- **`clear ip ospf process` is required** after RID change — the classic "didn't take"
  trap.
- **RID is used for DR/BDR tie-break** (with priority first).
- OSPFv3 **needs a 32-bit RID even with no IPv4**.
