# OSPF Areas

> **Level 10 · OSPF** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**OSPF areas** partition the domain to bound flooding and SPF computation. Every area keeps
its own LSDB; **Area 0 (backbone)** is mandatory and all areas must connect to it (directly
or via virtual link). **ABRs (Area Border Routers)** sit between areas, generating Type-3
summaries. The area hierarchy is what makes OSPF scale beyond small flat networks.

---

## 2. Core Concepts

### 2.1 The role of Area 0 (backbone)

- Area 0 is the **transit core** — inter-area routes must pass through it.
- All non-backbone areas attach to area 0 (rule of thumb). If an area can't attach
  physically, use a **virtual link** (note 12).
- ABRs have interfaces in ≥2 areas, **at least one being area 0**.

### 2.2 Router roles by location

| Role | Definition |
|------|-----------|
| **Internal router** | all interfaces in one area |
| **ABR** | interfaces in ≥2 areas (one is 0) |
| **Backbone router** | has an interface in area 0 |
| **ASBR** | redistributes routes from outside OSPF |

- A router can be ABR and ASBR at once (e.g., ASBR = ABR + redistribution).

### 2.3 Why areas help (the scale story)

| Without areas | With areas |
|---------------|-----------|
| One giant LSDB domain-wide | per-area LSDB only |
| Every flap → full-domain SPF | flap contained to its area |
| Type-3/4/5 summaries at ABR | summarized inter-area routes |
| High CPU/memory | bounded CPU/memory |

### 2.4 LSA flow across areas

```
Internal (Type 1/2) → ABR generates Type 3 → next area
ASBR generates Type 5 → flooded domain-wide (except stubs)
ASBR in NSSA → Type 7 → ABR converts to Type 5
```

### 2.5 Area number & backbone rule

- Area can be a number (0, 1, ...) or dotted-decimal (0.0.0.1).
- **All routers in an area must agree** on area ID + parameters (authentication, stub flags).
- **ABR placement** is design-critical — it becomes a chokepoint and summary engine.

## 3. Configuration / Commands

```text
router ospf 1
 network 10.1.0.0 0.0.255.255 area 0
 network 10.2.0.0 0.0.255.255 area 1

! Interface mode
interface Gi0/1
 ip ospf 1 area 0

show ip ospf
show ip ospf interface brief        ! area per interface
show ip ospf database               ! what LSAs live in which area
show ip ospf border-routers
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Area not forming neighbors | area ID mismatch | `show ip ospf interface` |
| No inter-area routes | area not attached to 0 / ABR down | area-0 adjacency + ABR |
| Split backbone | area 0 broken apart | virtual link (note 12) |
| Too much LSDB traffic | no summarization at ABR | `area X range` (note 14) |
| Authentication mismatch | area-level keys differ | verify auth on both ABRs |

---

## 5. Exam Traps

- **All areas must touch area 0** (or use a virtual link).
- **ABR = interface in ≥2 areas, one in area 0** — always the exam definition.
- **Area 0 is mandatory transit** — inter-area traffic goes through it.
- Areas bound **Type 1/2** flooding and **SPF**; Type 5 is domain-wide unless stub.
- **ABR summarization is the "area range" tool** (note 14) — not configurable inside areas.
- Area type (stub/etc.) must **match on all routers** in the area.
