# OSPF Neighbor States

> **Level 10 · OSPF** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

OSPF neighbors progress through a **state machine** as they discover, negotiate, and
synchronize LSDBs. The stable states are **2-Way** (multi-access non-DR) and **Full**
(adjacency). Reading `show ip ospf neighbor` states — and knowing which one signals what
fault — is a core OSPF troubleshooting and exam skill.

---

## 2. Core Concepts

### 2.1 The state progression (memorize)

| State | What happens | Reached |
|-------|--------------|---------|
| **Down** | no hellos received | initial |
| **Attempt** (NBMA) | actively contacting | NBMA only |
| **Init** | hello seen, but I'm not in its hello | discovery |
| **2-Way** | both see each other in hellos | neighbor (not adjacency) |
| **ExStart** | elect primary/secondary, start DBD | adjacency start |
| **Exchange** | exchanging DBD (database description) | — |
| **Loading** | requesting + receiving LSAs | — |
| **Full** | LSDBs identical | **adjacency formed** |

### 2.2 The three key phases

1. **Discovery** → Init → **2-Way**: Hello exchange proves mutual visibility.
2. **Synchronization** → ExStart → Exchange → Loading: DBDs compare LSDBs, then LSA
   requests/updates fill the gaps.
3. **Established** → **Full**: databases synchronized; SPF can now run.

### 2.3 The DR/BDR twist

- On **broadcast/NBMA** networks, only **DR and BDR reach Full** with all routers.
- **DROthers stay at 2-Way** with each other — that's normal, not a fault (note 05).

| Neighbor pair | State |
|---------------|-------|
| DR/DROther | Full |
| BDR/DROther | Full |
| DROther ↔ DROther | **2-Way** (normal) |
| Point-to-point | Full (no DR) |

### 2.4 Dead timer & failure

- **Dead interval = 4 × hello** (40 s default). No hello within dead → neighbor drops to
  Down, routes withdrawn.
- Common stuck states and their causes:

| Stuck state | Most likely cause |
|-------------|-------------------|
| **Init** | one-way connectivity / ACL / multicast blocked |
| **2-Way (stuck)** | DR/BDR not being elected (misconfig) |
| **ExStart** | **MTU mismatch** (the classic) |
| **Exchange** | DBD negotiation issues / MTU |
| **Loading** | LSA request never fulfilled |

### 2.5 Adjacency vs neighbor

- **Neighbor** = any OSPF router on the segment (reached 2-Way).
- **Adjacency** = synchronized with LSDB (reached Full) — only then is SPF run and
  routes installed.

## 3. Configuration / Commands

```text
show ip ospf neighbor
show ip ospf neighbor detail
show ip ospf neighbor 10.0.0.1
show ip ospf interface Gi0/1     ! hello/dead, network type, area
show ip ospf database            ! LSDB sync check
show ip ospf
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Stuck in **Init** | one-way link / multicast filter | test both directions; ACL check |
| Stuck in **ExStart** | **MTU mismatch** | match MTU both sides (`mtu` / `ip ospf mtu-ignore`) |
| Stuck in **Loading** | missing LSA (CPU/queue) | `show ip ospf database`, clear process |
| Flap Full↔Down | dead timer / flapping link | hello/dead tuning; physical check |
| DROthers all 2-Way | normal — not a fault | confirm DR/BDR reach Full |

---

## 5. Exam Traps

- **2-Way is normal between DROthers** — don't call it broken.
- **ExStart stuck = MTU mismatch** — the #1 memorized cause.
- **Full is required only for adjacencies**; DR/BDR are the ones at Full on broadcast.
- Dead = **4× hello** (not 2×).
- On **point-to-point there's no DR**, so all neighbors go straight to Full.
- `Attempt` state exists **only on NBMA** networks.
