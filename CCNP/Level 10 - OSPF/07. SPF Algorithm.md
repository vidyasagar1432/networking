# OSPF SPF Algorithm (Dijkstra)

> **Level 10 · OSPF** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

OSPF computes routes with **Dijkstra's shortest-path-first (SPF) algorithm**: each router
runs SPF over its **LSDB** to find the shortest path tree to every destination, rooted at
itself. Because every router has the identical LSDB, each builds the **same view** and
derives **loop-free shortest paths** deterministically. SPF runs **per-area** — a change in
one area triggers SPF only for that area (unless inter-area routes change).

---

## 2. Core Concepts

### 2.1 The algorithm steps (conceptual)

1. Root the tree at **self (source router)**.
2. Pick the node with the **smallest known cost** not yet finalized.
3. Relax its neighbors: if `cost[neighbor] > cost[current] + link_cost`, update.
4. Mark the node finalized; repeat until all nodes reached.
5. Result: shortest path tree → best routes, each tagged `O` (intra-area).

### 2.2 What SPF uses

| Input | Source |
|-------|--------|
| Nodes | routers (Type 1) and segments (Type 2) |
| Link costs | interface costs in Type 1/2 LSAs |
| Inter-area reach | Type 3/4 (ABR summaries) |
| External routes | Type 5 / 7 (attached to tree via ASBR) |

### 2.3 Per-area SPF scope

- SPF is computed **once per area** a router belongs to.
- A flap inside area 1 does **not** force SPF recalculation for area 0 — only the affected
  area re-runs (plus ABR updates Type 3 as needed). This is the scalability argument for
  areas (note 08).

### 2.4 SPF vs flooding (the division of labor)

| Task | Responsibility |
|------|----------------|
| Sharing topology | **flooding** LSAs (Type 1/2 within area) |
| Computing best paths | **SPF** per router (independent) |
| Advertising summaries | **ABR** (Type 3/4/5) |

- Flooding only distributes facts; **every router computes its own tree** — no
  hop-by-hop "distance vectors."

### 2.5 SPF throttling & fast convergence

- `timers throttle spf` controls how fast SPF is recalculated after topology change
  (initial delay / hold time / max wait).
- Default IOS: 10 ms initial, 5 s hold, 10 s max — tuned in larger networks.
- **Incremental SPF (ISPF)** recalculates only affected subtrees → faster, less CPU.

---

## 3. Configuration / Commands

```text
router ospf 1
 timers throttle spf 50 1000 5000    ! initial/hold/max (ms)
 timers lsa-interval 5               ! min between LSA re-ads

show ip ospf                     ! SPF stats: "SPF algorithm executed X times"
show ip ospf spf                  ! per-run timing
show ip ospf statistics
show ip route ospf
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| High CPU on flap | SPF re-running for whole area | ISPF + throttle timers |
| Slow convergence after link change | throttle too long / full SPF | `show ip ospf spf` timing |
| Route missing though LSDB fine | SPF not run / increment missed | `clear ip ospf process` |
| Inter-area instability | Type 3 churn from ABR | summarize + ISPF |
| SPF storm | flapping interface in area | locate flap; fix physical |

---

## 5. Exam Traps

- **SPF = Dijkstra, shortest path, loop-free** — each router computes independently.
- **Per-area SPF** — a change in one area doesn't recompute others (mostly).
- **Flooding ≠ SPF** — flooding shares the LSDB; SPF computes the tree.
- **Cost sum is what SPF minimizes** (not hop count).
- `timers throttle spf` and **ISPF** are the "fast convergence" answers.
- **SPF output → routes `O`**; inter-area `O IA` come from Type 3 at the tree's edge.
