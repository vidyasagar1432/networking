# OSPFv3

> **Level 10 · OSPF** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**OSPFv3 (RFC 5340)** is OSPF for **IPv6**. It keeps the same core ideas — LSAs, LSDB,
SPF, areas, DR/BDR — but decouples protocol logic from IPv4. **Addresses are carried as
prefix options in LSAs** rather than encoded in the LSA header, which allows **multiple
IPv6 prefixes per link** and future address-family extensibility. `address-family ipv6`
(or the old `ipv6 ospf`) enables it.

---

## 2. Core Concepts

### 2.1 OSPFv2 vs OSPFv3 (the table to memorize)

| | OSPFv2 | OSPFv3 |
|--|--------|--------|
| Address family | IPv4 | IPv6 |
| LSA address encoding | in LSA header | in payload (prefix options) |
| Per-link multiple prefixes | no | **yes** |
| Runs per-address-family | no | **yes** (multiple AFs possible) |
| Authentication | inside header (note 13) | **IPv6 AH/ESP or IPsec** |
| Router ID | still required | still required (32-bit) |
| Instances | — | per-link instance ID |

### 2.2 Why the decoupling matters

- An LSA is now **address-family-independent**: one LSDB serves any number of IPv6
  prefixes on a link.
- Future address families (IPv4-within-OSPFv3) become possible without new protocol.

### 2.3 Configuration (modern address-family style)

```text
router ospf 1
 address-family ipv6
  router-id 1.1.1.1
  interface Gi0/1
  exit-address-family

! Or legacy interface style
interface Gi0/1
 ipv6 ospf 1 area 0
```

### 2.4 Router ID

- OSPFv3 still needs a **32-bit router-id** (format like an IPv4 address) — manually set
  it or OSPF may not start without an IPv4 address present. Same election rules as
  OSPFv2 (note 03).

### 2.5 Neighbors & DR/BDR behavior

- Neighbor states identical to OSPFv2 (note 04).
- DR/BDR election identical on broadcast networks (note 05).
- Hello/dead intervals default 10 s / 40 s — same.

### 2.6 Authentication difference (exam favorite)

| Version | Auth method |
|---------|-------------|
| OSPFv2 | MD5 / SHA / plaintext in header (note 13) |
| OSPFv3 | relies on **IPv6 AH / ESP / IPsec** — no OSPF-native keys |

- On the exam: "how does OSPFv3 authenticate?" → **IPsec/AH**, not OSPF-level.

## 3. Configuration / Commands

```text
router ospf 1
 address-family ipv6
  router-id 1.1.1.1
  network 2001:db8::/32 area 0
 exit-address-family

show ospf neighbor
show ospf interface
show ipv6 route ospf
show ospf database
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| OSPFv3 won't start | missing router-id | set `router-id` |
| No neighbors | IPv6 unicast-routing off / hello mismatch | `ipv6 unicast-routing` |
| Neighbor stuck | MTU / area / instance mismatch | `show ospf interface` |
| Prefixes not advertised | prefix not covered by network/interface | verify interface in area |

---

## 5. Exam Traps

- **OSPFv3 ≠ "IPv6-only LSA changes"** — it's address-family-agnostic payload design.
- **Router ID is still a 32-bit number** even for IPv6-only networks.
- **No OSPF-native authentication in v3** — IPv6 AH/ESP/IPsec.
- **`ipv6 unicast-routing`** must be enabled globally or nothing works.
- Same **hello/dead, DR/BDR, areas, SPF** concepts as v2 — questions reuse them.
