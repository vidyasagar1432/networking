# OSPF DR / BDR

> **Level 10 · OSPF** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

On **multi-access (broadcast/NBMA)** networks, electing a **Designated Router (DR)** and
**Backup Designated Router (BDR)** cuts the number of adjacencies from N×(N−1)/2 down to
N. The DR becomes the hub for LSA flooding on the segment. **Point-to-point links elect no
DR/BDR** — full mesh adjacencies instead. Election is **priority first, then RID**.

---

## 2. Core Concepts

### 2.1 Why we need a DR (adjacency math)

| Routers on segment | Full adjacencies without DR | With DR |
|--------------------|-----------------------------|---------|
| 5 | 10 | 5 (each to DR/BDR) |
| 10 | 45 | 10 |
| n | n(n−1)/2 | n |

- DR/BDR receive and relay LSAs, dramatically reducing flooding on the shared segment.

### 2.2 Election rules (memorize the order)

1. **Highest interface priority** (0–255; default 1; 0 = never eligible).
2. Tie → **highest Router ID** wins (note 03).

- Election is **non-preemptive**: the existing DR/BDR keep their role even if a higher
  priority router appears later (until a **full election reset** — link-down or OSPF restart).

### 2.3 Roles and adjacencies

| Role | Adjacency behavior |
|------|--------------------|
| **DR** | Full with BDR and all DROthers |
| **BDR** | Full with DR and all DROthers; silent until DR fails |
| **DROther** | **2-Way with other DROthers**; Full with DR + BDR only |

- DROthers **never send LSAs directly to each other** — they go via DR/BDR (multicast
  224.0.0.6 toward DR/BDR; 224.0.0.5 for all).

### 2.4 DR failure → BDR promotes

```
DR dies → BDR becomes DR → a new BDR is elected among DROthers
```

- Failure is noticed via dead timer (40 s); after promotion the segment re-converges.

### 2.5 Config & best practice

```text
interface Gi0/1
 ip ospf priority 200       ! force this router to be DR (or BDR)
 ip ospf network point-to-point   ! avoids DR entirely on P2P segments
```

- Set **equal/low priority** to prevent flapping; or use point-to-point network type on
  real P2P links so no DR election occurs (smaller LSDB, no DBD with DR).

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No DR elected | all priorities 0 / no Full adjacencies | priorities + hello params |
| DR not the intended router | higher RID or stale election | reset election (bounce link / restart) |
| Too many adjacencies | broadcast type on P2P link | set `point-to-point` |
| DROthers never Full | normal on broadcast | confirm DR/BDR are Full |
| DR flap after config | priority changed without reset | reset election cleanly |

---

## 5. Exam Traps

- **Election: highest priority, then highest RID** — both "highest," don't invert.
- **Priority 0 = never a DR/BDR.**
- **Non-preemptive** — a higher router joining does NOT take over (until reset).
- **P2P = no DR/BDR at all** — straight to Full.
- **DROthers stay 2-Way** with each other — normal (note 04).
- **224.0.0.6** = DR/BDR multicast (vs 224.0.0.5 all routers).
