# NSSA (Not-So-Stubby Area)

> **Level 10 · OSPF** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **Not-So-Stubby Area (NSSA)** is a **stub area that allows an ASBR** — external routes
are injected as **Type 7 LSAs**, flooded only inside the NSSA, then **translated to Type 5
by the ABR** at the exit. This solves the stub paradox: "I want a small LSDB, but I still
need to redistribute local routes." NSSA still blocks inbound Type 5 from the rest of the
domain.

---

## 2. Core Concepts

### 2.1 Stub vs NSSA (the one-line difference)

| | Stub | NSSA |
|--|------|------|
| ASBR inside | **no** | **yes** |
| External from inside | n/a | Type 7 → translated to 5 |
| External from outside | blocked | **blocked (Type 5)** |
| Default route | auto-injected | **optional** (`default-information-originate`) |

- NSSA keeps the stub's LSDB/CPU benefits while enabling a **local ASBR** (e.g., a branch
  redistributing a static Internet link).

### 2.2 The Type 7 → Type 5 translation

```
ASBR inside NSSA: redistributes → Type 7 LSA (only inside NSSA)
ABR at NSSA edge: sees Type 7 → generates Type 5 → floods rest of domain
```

- **Only the ABR** performs translation.
- If **multiple ABRs** exist, only one translates (the elected one) — others hold Type 7.
- P-bit (propagate bit) marks which Type 7 LSAs are eligible to be translated.

### 2.3 NSSA types & metrics (route codes)

| Code | Meaning |
|------|---------|
| `O N1` | NSSA external, **E1-style** (includes cost to ASBR) |
| `O N2` | NSSA external, **E2-style** (external cost only) |

- Same E1/E2 concept as Type 5, just for Type 7 (note 06).

### 2.4 Options on the ABR

```text
router ospf 1
 area 5 nssa                          ! on all routers in the area
 area 5 nssa default-information-originate   ! ABR: inject default into NSSA
 area 5 nssa translate type7          ! Cisco: force this ABR to translate
 area 5 nssa no-redistribution        ! ABR: don't redistribute into NSSA
```

- `default-information-originate` on the ABR gives the NSSA a default route (not
  automatic, unlike plain stub).

### 2.5 Rules & constraints

1. **Cannot be area 0.**
2. All routers in the NSSA must be configured `nssa`.
3. **Type 5 blocked** from outside (like stub).
4. Virtual link **through** an NSSA not allowed.
5. Type 7 stays **area-local**; translation happens at the ABR.

## 3. Configuration / Commands

```text
! ASBR inside the NSSA:
router ospf 1
 area 5 nssa
 redistribute static subnets          ! produces Type 7

! ABR:
router ospf 1
 area 5 nssa translate type7
 area 5 nssa default-information-originate

show ip ospf database nssa-external   ! Type 7
show ip ospf database external        ! translated Type 5
show ip route ospf | include N1|N2
show ip ospf | include NSSA
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| NSSA routes don't exit the area | ABR not translating (or two ABRs confusion) | `translate type7`, elect one ABR |
| No default in NSSA | `default-information-originate` missing | add on ABR |
| External routes missing entirely | redistribution not producing Type 7 | `show ip ospf database nssa-external` |
| Type 7 stuck inside | P-bit off / translation config | verify translate config |

---

## 5. Exam Traps

- **NSSA = stub + local ASBR** — the difference from stub.
- **Type 7 originates at the ASBR inside NSSA; ABR translates to Type 5.**
- **Type 5 still blocked** from entering the NSSA.
- **Default route is optional in NSSA** (vs automatic in stub).
- Route codes **`O N1` / `O N2`** — E1/E2 style for NSSA externals.
- **Translate happens on the ABR** — not the ASBR; only one ABR translates.
