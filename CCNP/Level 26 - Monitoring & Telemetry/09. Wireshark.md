# Wireshark

> **Level 26 · Monitoring & Telemetry** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Wireshark** is the industry-standard **packet analyzer**: capture, decode, and filter
traffic for troubleshooting. It reads **pcap/pcapng**, uses **BPF filters**, and
visualizes **conversations, flows, and handshakes**. The exam tests capture filters,
decoding, and how to analyze common problems.

---

## 2. Core Concepts

### 2.1 What Wireshark does

| Feature | Detail |
|---------|--------|
| Capture | live interface |
| Decode | protocol tree |
| Filter | BPF + display |
| Follow | TCP stream |
| Export | pcap/pcapng |
| Analysis | experts/statistics |

- Wireshark = **capture, decode, filter, and analyze**.

### 2.2 Capture vs display filters

| Filter | Format | Example |
|--------|--------|---------|
| Capture (BPF) | before capture | `tcp port 443` |
| Display | after capture | `tcp.stream eq 0` |
| Capture | pcap syntax | `host 1.2.3.4` |
| Display | rich fields | `http.request` |

- **BPF limits what's stored; display filters refine the view.**

### 2.3 Common display filters

| Filter | Meaning |
|--------|---------|
| `ip.addr == X` | host traffic |
| `tcp.port == 443` | specific port |
| `http.request` | requests |
| `tcp.stream eq 0` | one TCP session |
| `icmp` | ping traffic |
| `dns.qry.name` | DNS queries |

- Display filters inspect **decoded fields**.

### 2.4 Protocol decode

| Layer | Useful ops |
|-------|-----------|
| L2 | ARP, MAC |
| L3 | ICMP, fragmentation |
| L4 | TCP handshake/retrans |
| L7 | HTTP, TLS, DNS |
| Expert | malformed/fail |

- Decode tree shows **each header + flags**.

### 2.5 Analysis workflows

| Problem | Look for |
|---------|----------|
| Slow | retransmissions |
| Unreachable | ICMP errors |
| Auth fail | 401/403 |
| DNS issue | NXDOMAIN |
| Latency | RTT graph |

- **Follow Stream + statistics** accelerate diagnosis.

### 2.6 Capture points

| Point | Why |
|-------|-----|
| Source host | egress view |
| Server | ingress view |
| SPAN/ERSPAN | mixed view |
| Tap | full view |

- Choose the **vantage point** to match the question.

## 3. Configuration / Commands

```text
(ioanalyze/capture on IOS-XE)
monitor capture CAP interface Gi0/1 both
monitor capture CAP limit ...
monitor capture CAP buffer size 10240
monitor capture CAP start
show monitor capture CAP
Wireshark: tshark -i eth0 -f "tcp port 443"
```

| Command | Meaning |
|---------|---------|
| `monitor capture` (IOS) | on-box capture |
| `-f` (tshark) | BPF filter |
| `show monitor capture` | status |

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Nothing | interface | capture point |
| Too much | no filter | BPF |
| Wrong view | display filter | refine |
| Truncated | buffer limit | size |
| Cannot parse | capture | tool version |

## 5. Exam Traps

- **BPF = capture filter** (syntax); display filters differ.
- Follow TCP stream for **conversation** analysis.
- Use **statistics** for conversations/protocol hierarchy.
- On-box: `monitor capture` on IOS-XE.
- pcap/pcapng portability matters.
