# Flexible NetFlow

> **Level 26 · Monitoring & Telemetry** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Flexible NetFlow (FNF)** is the modern NetFlow engine: you **define your own records**
(`match` = key, `collect` = non-key fields) via **record → exporter → monitor**. It uses
**NetFlow v9/IPFIX** export and improves on fixed-format v5. The exam tests the record
constructs and the configuration flow.

---

## 2. Core Concepts

### 2.1 Flow record anatomy

| Part | Meaning | Keyword |
|------|---------|---------|
| match | key fields | `match` |
| collect | extra fields | `collect` |
| exporter | collector | `flow exporter` |
| monitor | bind | `flow monitor` |

- Keys define the flow identity; collect adds **info about it**.

### 2.2 Record examples

| Purpose | Keys | Collects |
|---------|------|----------|
| traffic analysis | IPs/ports | bytes/start |
| top talkers | src/vlan | bytes/flows |
| interface stats | ifindex | bytes |
| custom | anything | anything |

- FNF lets you **tailor fields** to the use case.

### 2.3 Exporter details

| Item | Detail |
|------|--------|
| Destination | collector IP |
| Transport | UDP (2055) |
| Version | v9/IPFIX |
| Options | templates |

- Export templates **describe the record** to the collector.

### 2.4 Monitor + cache

| Item | Detail |
|------|--------|
| Monitor | record + exporter |
| Cache | resident flows |
| Services | independent |
| Interface | enable input/output |

- Monitor binds everything; the **cache stores flow state**.

### 2.5 Why FNF over v5

| Aspect | v5 | FNF |
|--------|-----|-----|
| Fields | fixed | custom |
| Templates | none | yes |
| Applications | limited | rich |
| Scale | capped | flexible |

- **FNF wins on flexibility and scale.**

### 2.6 Integration

| Feature | Use |
|---------|-----|
| NBAR | app classification |
| sampling | high rate |
| multicast | flows |
| aggregation | top-N |

- FNF combines with **NBAR and sampling**.

## 3. Configuration / Commands

```text
flow record R1
 match ipv4 source address
 match ipv4 destination address
 match transport source-port
 match transport destination-port
 collect counter bytes
 collect counter packets
flow exporter E1
 destination 192.0.2.10
 transport udp 2055
flow monitor M1
 record R1
 exporter E1
 cache timeout active 300
interface GigabitEthernet0/1
 ip flow monitor M1 input
```

| Command | Meaning |
|---------|---------|
| `match` | key fields |
| `collect` | data fields |
| `flow exporter` | collector |
| `flow monitor` | bind record+exporter |
| `ip flow monitor` | enable on interface |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No records | match | show flow record |
| No export | exporter | show flow exporter |
| Zero cache | interface | show flow monitor cache |
| v9 fail | collector | compatibility |
| MBPS issue | timeout | cache active |

---

## 5. Exam Traps

- FNF = **custom records** (match/collect).
- Structure: **record → exporter → monitor**.
- Export uses **v9/IPFIX templates**.
- `collect` = non-key; `match` = key.
- Interfaces: `ip flow monitor ... input`.
