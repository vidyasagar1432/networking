# Telemetry

> **Level 26 · Monitoring & Telemetry** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Streaming telemetry** pushes **subscriptions of device data** continuously to
collectors using **push** (vs SNMP's pull), encoded as **protobuf/JSON** and
transported over **gRPC/gNMI/NETCONF**. It's the modern, scalable replacement for
polling. The exam focuses on **push vs pull** and the protocols.

---

## 2. Core Concepts

### 2.1 Push vs pull

| Model | Direction | Style |
|-------|-----------|-------|
| SNMP/poll | collector asks | pull |
| Streaming | device sends | push |
| NetFlow | device exports | push |
| Speed | on change/interval | sustained |

- **Device pushes on change or interval** — no polling overhead.

### 2.2 Telemetry protocol stack

| Layer | Detail |
|-------|--------|
| Encoding | protobuf/JSON |
| Transport | gRPC (best) |
| Model | gNMI/NETCONF |
| YANG | data models |
| Subscription | path/interval |

- Stack: **YANG model + gRPC/gNMI transport**.

### 2.3 Models of interest

| Model | Detail |
|-------|--------|
| gNMI | standard network mgmt/telemetry |
| gRPC | high-perf transport |
| NETCONF | config+telemetry |
| Cisco | model-driven on IOS-XE/XR |

- **gNMI over gRPC** is the modern pairing.

### 2.4 Model-driven telemetry (MDT)

| Item | Detail |
|------|--------|
| Subscription | on-change / interval |
| Path | YANG data path |
| Collector | streaming receiver |
| Darwin | cadence |

- Cisco MDT: subscribe to a **YANG path** and stream.

### 2.5 vs SNMP/NetFlow

| Aspect | SNMP | NetFlow | Telemetry |
|--------|------|---------|-----------|
| Mode | pull | push | push |
| Richness | limited | flows | full model |
| Latency | poll cycle | per flow | on change |
| Scale | poor | good | best |

- Telemetry = **richer + lower latency + scalable**.

### 2.6 Considerations

| Item | Detail |
|------|--------|
| CPU | push overhead |
| Bandwidth | continuous |
| Security | TLS |
| Collector | must scale |

- Design for **sustained stream load**.

## 3. Configuration / Commands

```text
telemetry ietf subscription 10
 encoding encode-kvgpb
 filter xpath /interfaces/interface/statistics
 stream yang-push
 update-policy periodic 30000
 receiver ip address 192.0.2.11 port 57500 protocol grpc-tcp
```

| Command | Meaning |
|---------|---------|
| `telemetry ietf` | subscription |
| `filter xpath` | YANG path |
| `update-policy` | interval |
| `receiver ... protocol grpc-tcp` | collector |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No stream | subscription | show telemetry |
| No data | xpath | filter |
| gRPC down | port | receiver |
| Cadence | update-policy | interval |
| Encoding | collector | kvgpb |

---

## 5. Exam Traps

- Telemetry = **push**; SNMP = poll.
- **gNMI/gRPC** is the modern transport.
- Data defined by **YANG models/paths**.
- On-change vs **periodic** subscriptions.
- **Model-driven telemetry** is the Cisco term.
