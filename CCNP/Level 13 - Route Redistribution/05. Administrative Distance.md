# Administrative Distance in Redistribution

> **Level 13 · Route Redistribution** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

When two protocols know the **same prefix** with different metrics, the **Administrative
Distance (AD)** picks the winner before metric comparison. Redistribution multiplies AD
interactions: an EIGRP-learned route vs an OSPF-redistributed version of it are compared
by AD, which can cause **unexpected preference or loops** (note 08). Tuning `distance`
per-source steers those conflicts.

---

## 2. Core Concepts

### 2.1 Default ADs (the reference table)

| Protocol | Default AD |
|----------|-----------|
| Connected | 0 |
| Static | 1 |
| eBGP | 20 |
| EIGRP internal | 90 |
| OSPF | 110 |
| IS-IS | 115 |
| RIP | 120 |
| EIGRP external | 170 |
| iBGP | 200 |

- **Lower wins** — metric is only compared when AD ties.

### 2.2 Why redistribution breaks AD expectations

| Scenario | Winner |
|----------|--------|
| OSPF route (AD 110) vs EIGRP internal (90) | EIGRP wins, even if metric worse |
| EIGRP external (170) vs OSPF (110) | OSPF wins — external comes last |
| Static (1) vs any | static wins |

- **AD beats metric.** A redistributed route may lose despite a better metric.

### 2.3 The external-vs-internal trap

- `redistribute ospf` creates **EIGRP external** routes (AD 170).
- If the same prefix also exists as **EIGRP internal** (AD 90), the internal wins — the
  redistributed copy is ignored.
- Reverse: OSPF (**AD 110**) vs an EIGRP-external copy — OSPF wins.

### 2.4 Tuning distance per source

```text
router ospf 1
 distance 120 10.0.0.1 0.0.0.0 ACL-OSPF-LOW
```

| Form | Effect |
|------|--------|
| `distance N` | global for protocol |
| `distance N source wildcard acl` | per-neighbor |
| EIGRP `distance eigrp int ext` | set internal/external separately |

- Keys: give the "real" source a lower AD so it wins predictably.

### 2.5 AD vs metric vs route-map (priority order)

| Level | Tool |
|-------|------|
| 1 | existence (filtering) |
| 2 | Administrative Distances |
| 3 | metric (protocol cost) |

- Redistribution design should align ADs deliberately rather than rely on defaults.

### 2.6 Multi-protocol dual-redistribute danger

- Two boundary routers redistributing both ways + different ADs = **route flapping**
  between protocols unless filtered (note 08).

```text
show ip route <prefix>          ! shows source protocol AD

```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Right path not used | AD picks other source | show ip route AD |
| Flapping between sources | AD too close / no filter | show ip protocols |
| External always loses | AD 170 | prefer internal / tune |
| iBGP unreachable | AD 200 vs others | iBGP next-hop issue |
| Static overrides | AD 1 vs dist | distance tune |

---

## 5. Exam Traps

- **AD beats metric** — always.
- EIGRP **internal 90 vs external 170** — the redistribution trap.
- eBGP 20 < EIGRP internal 90 (eBGP wins a conflict typically).
- iBGP 200 loses to everything (needs RIB next-hop).
- Tune with `distance` per source when both protocols must coexist.
