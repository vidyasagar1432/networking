# OSPF to EIGRP Redistribution

> **Level 13 · Route Redistribution** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Redistribution** injects routes from one routing domain into another. Moving **OSPF →
EIGRP** means taking OSPF-learned (and OSPF-connected) routes and putting them into EIGRP
at a boundary router (ASBR / redistribution point). The critical catch: **EIGRP requires a
seed metric** — without it, redistributed routes are **not** advertised. The OSPF metric
(COST) does not map to the EIGRP composite metric; you must supply bandwidth/delay via a
route-map or `default-metric`.

---

## 2. Core Concepts

### 2.1 One-directional example

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   redistribute ospf 1 metric 1000 100 255 1 1500
```

- The five values = **bandwidth (kbps), delay (µs/10), reliability, load, MTU**
  (note 04 Seed Metrics).

### 2.2 Route sources redistributed

| Source | Default behavior |
|--------|------------------|
| OSPF routes | yes (excluding own subnet/max) with keyword |
| Static | only with `redistribute static` |
| Connected | only with `redistribute connected` |
| Default route | only if `redistribute ... include-connected` or default-information |

- OSPF **external types 1/2 and internal** routes propagate as EIGRP **external** routes.

### 2.3 Metric mapping (the trap)

| Protocol | Metric | Redistributed metric |
|----------|--------|----------------------|
| OSPF | cost (bandwidth) | not used |
| EIGRP | composite (BW+delay) | must be seeded |

- **OSPF cost is meaningless inside EIGRP** — the boundary router assigns the seed metric.

### 2.4 Using a route-map for selectivity

```text
route-map OSPF-TO-EIGRP permit 10
 match ip address prefix-list ALLOW
 set metric 10000 100 255 1 1500

router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   redistribute ospf 1 route-map OSPF-TO-EIGRP
```

- Matched prefixes get the seed metric; the mathematics stays consistent.

### 2.5 Bidirectional (two-way) redistribution

```text
router ospf 1
 redistribute eigrp 100 subnets metric-type 1
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   redistribute ospf 1 metric 10000 100 255 1 1500
```

- **Both directions independently seeded** — missing one side breaks reachability.
- OSPF needs the **`subnets`** keyword to redistribute non-classful prefixes.

### 2.6 Redistribution design rules

| Rule | Why |
|------|-----|
| One boundary router is cleanest | no loops, predictable |
| Always seed metrics | else routes vanish |
| Filter at both edges | prevent feedback loops (note 08) |
| Set route tags | mark origin for later policy (note 06) |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No EIGRP routes for OSPF | missing seed metric | show ip eigrp topology |
| Only classful routes | missing `subnets` | redistribute ospf subnets |
| Routes never appear | route-map not matching | show route-map counters |
| Metric wrong | default-metric values | show ip route metric |
| Feedback loop | two-way without filters | show ip route / flap |

---

## 5. Exam Traps

- EIGRP **refuses redistributed routes without a seed metric**.
- OSPF redistribution to EIGRP is **external** in EIGRP (source of route = external).
- `subnets` keyword needed in OSPF.
- Seed metric format for EIGRP: **BW delay reliability load MTU**.
- One-direction config on one router → one-way reachability.
