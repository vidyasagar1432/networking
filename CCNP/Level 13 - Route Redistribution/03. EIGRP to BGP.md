# EIGRP to BGP Redistribution

> **Level 13 · Route Redistribution** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

Injecting **EIGRP routes into BGP** advertises internal EIGRP networks to the provider.
The cleanest method is `network` statements against EIGRP-present routes; `redistribute
eigrp` is the bulk alternative. Two BGP facts matter: **MED** can inherit the EIGRP
metric, and **origin** is `?` under `redistribute`. Unlike EIGRP's own redistribution,
**no special seed metric is needed** — BGP uses MED / default metric.

---

## 2. Core Concepts

### 2.1 Methods compared

| Method | Origin | MED default |
|--------|--------|-------------|
| `network` | `i` | 0 (or OSPF-style cost via metric) |
| `redistribute eigrp` | `?` | EIGRP metric / 0 |

- EIGRP internal (and external) routes become BGP routes at the boundary router.

### 2.2 Configuration

```text
router bgp 65001
 redistribute eigrp 100 metric 200
```

- `metric 200` sets the **MED** for the redistributed routes.
- Default MED without `metric` = 0 — often too attractive to providers.

### 2.3 Selective redistribution with route-map

```text
route-map EIGRP-TO-BGP permit 10
 match ip address prefix-list CUSTOMER
 set metric 300
 set community 65001:100

router bgp 65001
 redistribute eigrp 100 route-map EIGRP-TO-BGP
```

- Matched routes get MED + community; unmatched are filtered (deny/implicit).

### 2.4 EIGRP external vs internal

| EIGRP source | In BGP |
|--------------|--------|
| Internal (successor) | redistributed normally |
| External (redistributed into EIGRP) | **filter** to avoid loops |

- A route that entered EIGRP from another protocol is marked external — careful
  re-advertising it to BGP can create feedback (note 08).

### 2.5 Metric mapping detail

- EIGRP composite metric is **not** a bandwidth cost — BGP treats it as an opaque MED
  unless you override.
- Prefer explicit `set metric` / `metric` to keep MEDs predictable.

### 2.6 Best practice

```text
router bgp 65001
 network 10.10.0.0 mask 255.255.0.0
```

- Explicit `network` for precise prefix control + origin `i`; `redistribute` only for
  bulk with route-map filtering.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No EIGRP routes in BGP | missing network/redistribute | show ip bgp |
| MED 0 everywhere | no metric set | set metric |
| Origin `?` | redistribute instead of network | network statements |
| Loops | external routes re-advertised | filter external |
| Wrong prefixes | route-map miss | counters + prefix-list |

---

## 5. Exam Traps

- **No seed metric needed** for EIGRP→BGP (unlike OSPF→EIGRP).
- MED default = **0** unless `metric`/route-map set.
- `redistribute` → origin `?`; `network` → origin `i`.
- Filter **external** EIGRP routes before sending to BGP.
- BGP MED is opaque to EIGRP composite semantics.
