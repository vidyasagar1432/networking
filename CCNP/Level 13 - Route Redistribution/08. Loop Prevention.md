# Loop Prevention in Redistribution

> **Level 13 · Route Redistribution** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

Redistributing in **both directions** across two protocols is the classic recipe for
**routing loops**: a route leaves OSPF into EIGRP, comes back into OSPF as an EIGRP
external, then bounces again — inflating metrics and flapping the RIB. The prevention
tools are **route tags**, **filters**, **AD tuning**, and carefully **limited boundary
routers**.

---

## 2. Core Concepts

### 2.1 The feedback loop anatomy

```
     +------OSP-------+
     |                |
   [R1]--EIGRP----[R2]
```

1. R1 redistributes OSPF→EIGRP (tag `100`).
2. R2 receives it in EIGRP and redistributes **back** into OSPF (as E1/E2).
3. The route in OSPF now shows EIGRP as external source — metrics inflate, table flaps,
   possible blackhole (the origin is wiped).

### 2.2 The defenses

| Defense | How | Strength |
|---------|-----|----------|
| Route tags | tag at entry; deny the tag going back (note 06) | strongest |
| Filters | deny own prefixes at each boundary (note 07) | standard |
| Single boundary router | only one redistribution point | simplest |
| AD tuning | make one source win predictably (note 05) | situational |
| EIGRP stub / passive | stop queries/updates on some segments | supplemental |

### 2.3 Tag-based defense (the worked design)

```text
! On the boundary where OSPF → EIGRP
route-map TAG-OSPF permit 10
 match ip address prefix-list OSPF-RANGES
 set tag 100

router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   redistribute ospf 1 route-map TAG-OSPF

! On the EIGRP → OSPF boundary
route-map DENY-TAG-100 deny 10
 match tag 100
route-map DENY-TAG-100 permit 20

router ospf 1
 redistribute eigrp 100 route-map DENY-TAG-100 subnets
```

- OSPF-originated routes never return to OSPF — loop broken at the tag.

### 2.4 Single-boundary-router rule

- One ASBR between two domains eliminates the feedback pair entirely.
- Multi-boundary is only safe with **symmetric filters + tags on both routers**.

### 2.5 Metric inflation without loops

- Even one-directional redistribution across two hops can **inflate metrics**; ensure
  seed metrics are sensible (note 04) so the "return" path stays stable.

### 2.6 Detecting loops

| Symptom | Cause |
|---------|-------|
| Metric larger than expected | feedback re-advertisement |
| Route flap between protocols | AD flip at boundary (note 05) |
| Route missing on one side | tag deny too broad |
| BGP origin `?` everywhere | redistribute-based injection |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Loop | no deny back | tag-based deny |
| Metric growing | feedback path | remove one direction |
| Flap | AD ties | distance tuning |
| One side missing | tag too broad | match tag scope |
| Blackhole | origin wiped by loop | break loop first |

---

## 5. Exam Traps

- **Tags at entry + deny at return** is the canonical loop-prevention answer.
- **One boundary router** avoids the loop entirely.
- Filter **both directions** symmetrically on multi-boundary designs.
- A loop **wipes origin** — route becomes external with inflated metric.
- AD (note 05) beats metric: a low-AD source can survive a looped metric.
