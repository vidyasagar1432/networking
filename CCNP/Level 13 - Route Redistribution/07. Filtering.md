# Redistribution Filtering

> **Level 13 · Route Redistribution** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

Filtering decides **which routes** cross the redistribution boundary. Blind
redistribution creates loops, black holes, and metric surprises (note 08). The tools are
**route-maps** (the modern standard), **distribute-lists**, and **prefix-lists**, applied
at the boundary router on the redistributing protocol.

---

## 2. Core Concepts

### 2.1 Filter placement

| Filter | Command | Direction |
|--------|---------|-----------|
| Route-map | `redistribute ospf 1 route-map RM` | at redistribution |
| Distribute-list (EIGRP) | `distribute-list ACL in/out` | per protocol |
| Distribute-list (OSPF) | `distribute-list ACL in` | OSPF in only |
| Prefix-list in route-map | `match ip address prefix-list PL` | selection |

- Filters run **at the boundary router**, before routes enter the receiving protocol.

### 2.2 Route-map filtering (recommended)

```text
ip prefix-list ALLOWED seq 10 permit 10.10.0.0/16 le 24
ip prefix-list ALLOWED seq 20 permit 192.168.0.0/24

route-map FILTER-REDIST permit 10
 match ip address prefix-list ALLOWED
 set metric 10000 100 255 1 1500

router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   redistribute ospf 1 route-map FILTER-REDIST
```

- Only matched prefixes redistribute; **everything else is dropped** (implicit deny).

### 2.3 Distribute-lists

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   distribute-list ACL-OUT out

router ospf 1
 distribute-list ACL-IN in
```

- `in`: filter routes **received**; `out`: filter routes **sent**.
- OSPF only supports `in` on Cisco IOS (interfaces/best path).

### 2.4 Why filter (the goals)

| Goal | Filtering method |
|------|------------------|
| Loop prevention | deny own-origin prefixes back in |
| Keep table small | only advertise needed prefixes |
| Avoid feedback | deny routes already tagged (note 06) |
| Control MED | route-map set metric |
| Policy edge | prefix-list / as-path |

### 2.5 Filter direction gotcha

- **`in` vs `out`** is on the **local** router, not the neighbor:
  - `redistribute ospf ... route-map RM` filters what *enters* EIGRP locally.
  - A `neighbor ... route-map RM out` filters what *leaves* to a BGP peer (note 13, L12).
- Misplaced direction = routes slip through the policy.

### 2.6 Verifying filtered routes

```text
show route-map                    ! counters
show ip prefix-list               ! ACL state
show ip eigrp topology            ! absence of blocked routes
debug ip routing
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Too many routes | no filter / wrong direction | show ip protocols |
| Route missing | filter too strict | show route-map counters |
| Loop reappears | deny missing | tag-based deny |
| Wrong metric | route-map not matching | route-map set metric |
| Filter ignored | wrong command (distribute out) | verify protocol |

---

## 5. Exam Traps

- **Route-maps filter + set** at the redistribution command — the standard.
- **Implicit deny** at the end of a route-map blocks non-matched routes.
- OSPF distribute-list is **`in` only**.
- Filters are **local** — direction matters.
- Tag-based denies are the strongest loop defense.
