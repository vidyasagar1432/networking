# Link Redundancy

> **Level 27 · High Availability** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Link redundancy** protects against **link failure** using multiple parallel physical
links. Options: **EtherChannel** (bundle into one logical LAG), **link aggregation**,
and **multichassis LAG (M-LAG)**. Bundling kills STP blocking and spreads load. The exam
tests LACP vs PAgP and the redundancy goals.

---

## 2. Core Concepts

### 2.1 Why multiple links

| Benefit | Detail |
|---------|--------|
| Bandwidth | scale |
| Availability | no single point |
| Load-sharing | split flows |
| Failover | automatic |
| STP | no blocking on LAG |

- **Bond links to avoid one-cable SPOF.**

### 2.2 EtherChannel / LAG

| Item | Detail |
|------|--------|
| Links | bundled |
| Logical | one port-channel |
| Hash | picks member |
| Protocol | LACP/PAgP |
| Failure | member redirects |

- EtherChannel = **one logical link over many physical links**.

### 2.3 Negotiation protocols

| Protocol | Vendor | Mode |
|----------|--------|------|
| LACP | IEEE 802.3ad/802.1AX | active/passive |
| PAgP | Cisco | desirable/auto |
| Static | manual | on |

- **LACP is the standard; PAgP is Cisco-proprietary.**

### 2.4 Load balancing

| Hash input | Result |
|------------|--------|
| src/dst MAC | L2 hashing |
| src/dst IP | L3 hashing |
| src/dst port | L4 hashing |
| Mix | full flow |

- Hash **determines member per flow** — all flows stay in-order.

### 2.5 M-LAG / vPC

| Term | Meaning |
|------|---------|
| vPC (NX-OS) | dual uplink across switches |
| M-LAG | generic term |
| Active-active | both bundle |
| Access | double-homed servers |

- **M-LAG/vPC** lets two switches share one logical bundle.

### 2.6 Thumb rules

| Rule | Detail |
|------|--------|
| Consistent | speed/duplex per member |
| STP | LAG won't block |
| Hash | choose per traffic |
| Fail | remaining carries all |

- Members must match **speed/duplex** for correctness.

## 3. Configuration / Commands

```text
interface Port-channel1
 interface GigabitEthernet0/1
  channel-group 1 mode active
interface GigabitEthernet0/2
  channel-group 1 mode active
show etherchannel summary
show etherchannel load-balance
```

| Command | Meaning |
|---------|---------|
| `channel-group` | member bind |
| `mode active` | LACP active |
| `mode on` | static |
| `show etherchannel` | verify |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Not bundled | mode mismatch | summary |
| Flap | speed/duplex | config |
| One direction | protocol | peers |
| Wrong hash | algorithm | config |
| STP block | not LAG | ports |

---

## 5. Exam Traps

- **LACP = standard (active/passive); PAgP = Cisco (desirable/auto).**
- `mode on` = **static**, no negotiation.
- Members need **consistent speed/duplex**.
- Hash keeps **single flow in order** across one member.
- vPC/M-LAG = **active-active across two switches**.
