# EIGRP DUAL

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DUAL (Diffusing Update Algorithm)** is EIGRP's loop-free path computation. It is a
**hybrid** — it exchanges route *vectors* with neighbors (like distance-vector) but keeps
topology *facts* (like link-state) to guarantee **loop-free paths without full maps**.
DUAL's genius: it precomputes a **feasible successor** so most failures converge with **no
queries, no recalculation, and no loops** — only a topology-table change.

---

## 2. Core Concepts

### 2.1 The three tables EIGRP keeps

| Table | Content |
|-------|---------|
| **Neighbor table** | adjacent routers, hello timers, RTP state |
| **Topology table** | every route from every neighbor + metrics (the "map") |
| **Routing table** | the installed best paths (successors) |

- DUAL operates on the **topology table**; the routing table only reflects its output.

### 2.2 Successor vs feasible successor (the core idea)

| Term | Definition |
|------|-----------|
| **Successor** | the next-hop router with the **lowest feasible distance (FD)** — installed in RIB |
| **Feasible successor (FS)** | a **loop-free backup**: neighbor whose **advertised distance (AD) < FD of successor** |

- **FD** = metric of the best route from this router.
- **AD** (reported distance) = the metric the neighbor *reports* toward the destination.
- FS is a neighbor whose AD is **strictly less than** our current FD — that guarantees
  that path can't loop back through us.

### 2.3 The feasibility condition (memorize)

```
A neighbor is a feasible successor iff:   AD(neighbor) < FD(current successor)
```

- This is DUAL's loop-avoidance rule — the exam loves asking which neighbor qualifies.
- If a path doesn't meet it, it's **not loop-free** and cannot be a backup (would need
  querying).

### 2.4 Local computation vs diffusing computation

| Scenario | DUAL behavior |
|----------|---------------|
| Successor fails, FS exists | **local recompute**: promote FS, update RIB — no queries, near-instant |
| Successor fails, **no FS** | **diffusing computation**: query neighbors, wait for replies, recompute globally |

- Only the "no FS" case forces the slow, query-driven path. This is why EIGRP converges
  so fast on redundant designs.

### 2.5 Convergence characteristics

- **Fast**: local recompute where FS exists (milliseconds).
- **Loop-free**: the feasibility condition guarantees no transient loops.
- Queries are **reliable** (RTP, note 02) and can propagate the *entire* topology if no
  FS exists anywhere — the "stuck in active (SIA)" failure mode (note 11).

### 2.6 DUAL process example

```
Neighbors: A (FD=20, AD=10), B (FD=25, AD=20), C (FD=35, AD=30)
Successor = A (lowest FD=20)
FS candidates: B (AD=20) — NOT < 20, so no.
                C (AD=30) — no.
→ only A is usable; B and C cannot be FS.
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No FS, slow convergence | no loop-free backup path | add redundant link / check metric |
| Stuck in Active (SIA) | query unanswered (partial link loss) | `show ip eigrp topology active` |
| Wrong successor | metric/K-value confusion | `show ip eigrp topology` |
| Loops during reconverge | feasibility condition violated by metric change | recompute/clear process |
| FS not promoted | AD ≥ FD | raise other path quality |

---

## 5. Exam Traps

- **FD = our metric to destination; AD = what neighbor reports** — don't swap them.
- **FS requires AD < FD (strictly)** — equal does NOT qualify.
- **No FS → diffusing computation (queries)** — the slow path.
- **DUAL guarantees loop-freedom** without full topologies — that's its headline.
- **EIGRP = hybrid** (distance-vector + link-state traits), not pure DV.
