# EIGRP DUAL

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DUAL (Diffusing Update Algorithm)** is the algorithm EIGRP uses to select **loop-free  
paths** and perform fast convergence.

EIGRP is technically an **advanced distance-vector routing protocol**. It exchanges  
routing information with neighbors and maintains a **topology table** containing  
multiple paths to destinations.

DUAL's key advantage is the **feasibility condition**, which allows EIGRP to identify  
a **feasible successor (FS)** in advance. If the current successor fails and a valid FS  
exists, EIGRP can converge **without starting a diffusing computation or sending  
queries** for that destination.

---

## 2. EIGRP Tables

EIGRP maintains three important tables:

|Table|Purpose|
|---|---|
|**Neighbor table**|Directly connected EIGRP neighbors and their adjacency information|
|**Topology table**|EIGRP-learned routes, including paths, metrics, and successor/FS information|
|**Routing table**|Best EIGRP paths installed for packet forwarding|

### Important

**DUAL operates using information in the topology table.**

The routing table contains the routes selected by the routing process; it does not  
contain all EIGRP paths learned from neighbors.

---

## 3. Successor, Feasible Distance, and Reported Distance

These terms are fundamental to understanding DUAL.

### 3.1 Successor

The **successor** is the neighbor providing the **best path** to a destination.

Its route is installed in the routing table.

The best path is selected using the EIGRP composite metric, assuming the paths are  
eligible for installation.

---

### 3.2 Feasible Distance (FD)

**Feasible Distance (FD)** is the **total EIGRP metric from the local router to the  
destination through the successor**.

In simplified form:

```text
FD = local metric to neighbor + neighbor's reported distance
```

FD represents the local router's metric to the destination for the selected path.

---

### 3.3 Reported Distance (RD)

**Reported Distance (RD)** is the metric that a neighboring EIGRP router reports  
for reaching the destination.

It is also commonly called:

**Advertised Distance (AD)**

```text
RD = metric reported by the neighbor toward the destination
```

Cisco terminology commonly uses **Reported Distance (RD)**, while many study resources  
use **Advertised Distance (AD)**.

---

## 4. Feasible Successor

A **feasible successor (FS)** is a backup path that satisfies EIGRP's  
**feasibility condition**.

### Feasibility Condition

```text
RD(neighbor) < FD(current successor)
```

The condition must be **strictly less than**.

```text
RD < FD    → Feasible Successor
RD = FD    → NOT a Feasible Successor
RD > FD    → NOT a Feasible Successor
```

This condition provides DUAL with a loop-free backup path.

---

## 5. Why the Feasibility Condition Prevents Loops

Suppose Router A wants to reach destination X.

```text
              Destination X
                    |
                    |
              Router B
                    |
                 Router A
```

If Router B reports:

```text
RD(B → X) < FD(A → X)
```

then Router B's advertised distance to X is already smaller than A's current  
feasible distance.

This satisfies DUAL's loop-free feasibility condition, allowing A to use B as a  
**feasible successor**.

If the condition is not satisfied, EIGRP does **not** use that path as a feasible  
successor.

---

## 6. Successor vs Feasible Successor

|Term|Meaning|
|---|---|
|**Successor**|Best path to the destination; installed in the routing table|
|**Feasible Successor**|Loop-free backup path satisfying `RD < FD`|
|**FD**|Local router's total metric to the destination through the successor|
|**RD / AD**|Metric reported by a neighbor toward the destination|

### Easy memory trick

```text
FD = Full Distance from ME to destination
RD = Reported Distance from NEIGHBOR to destination
```

---

## 7. Local Convergence vs Diffusing Computation

DUAL can converge in two major ways.

### 7.1 Successor Fails + Feasible Successor Exists

If the successor fails and a valid FS already exists:

```text
Successor fails
      ↓
FS is available
      ↓
FS becomes successor
      ↓
Route is updated
```

No diffusing computation is required for that destination.

This is one of the major reasons EIGRP can converge very quickly.

---

### 7.2 Successor Fails + No Feasible Successor

If there is no valid FS:

```text
Successor fails
      ↓
No FS available
      ↓
Route becomes Active
      ↓
EIGRP sends queries
      ↓
Neighbors return replies
      ↓
DUAL completes diffusing computation
      ↓
New route is selected
```

This is the **query-driven convergence process**.

Queries can propagate through multiple EIGRP routers, increasing convergence time and  
query scope.

---

## 8. Passive vs Active

EIGRP uses two important route states:

### Passive

A route is **Passive** when EIGRP has a stable route and is not actively performing  
a diffusing computation for that destination.

```text
Passive = normal / stable
```

### Active

A route becomes **Active** when the current successor is lost and EIGRP has no  
feasible successor, requiring a diffusing computation.

```text
Active = DUAL is searching for a new path
```

**Important:** Active does not automatically mean the network is broken. It means  
DUAL is actively trying to resolve the route.

---

## 9. Stuck-in-Active (SIA)

A route can become **Stuck-in-Active (SIA)** when EIGRP does not receive the required  
query responses within the expected time.

Possible causes include:

- Unreachable or unstable neighbors
    
- Excessive query propagation
    
- Large EIGRP query domains
    
- Router overload
    
- Network instability
    
- Problems preventing query replies from returning
    

Useful command:

```text
show ip eigrp topology active
```

SIA is an important indication that EIGRP query scope or neighbor communication  
needs investigation.

## 10. DUAL Example

Assume Router R1 has three paths to destination `10.10.10.0/24`:

```text
Neighbor A:
    RD = 10
    Total metric = 20

Neighbor B:
    RD = 20
    Total metric = 25

Neighbor C:
    RD = 30
    Total metric = 35
```

### Step 1 — Select the successor

The lowest total metric is:

```text
A = 20
```

Therefore:

```text
Successor = A
FD = 20
```

### Step 2 — Check feasible successors

For B:

```text
RD(B) = 20
FD    = 20

20 < 20 → FALSE
```

Therefore B is **not** a feasible successor.

For C:

```text
RD(C) = 30
FD    = 20

30 < 20 → FALSE
```

Therefore C is **not** a feasible successor.

### Result

```text
Successor = A
FD = 20

Feasible Successor = None
```

If A fails, R1 must perform a diffusing computation because no FS is available.

---

## 11. Example With a Feasible Successor

Consider:

```text
Neighbor A:
    RD = 10
    Total metric = 20

Neighbor B:
    RD = 15
    Total metric = 25
```

The successor is:

```text
A
FD = 20
```

Check B:

```text
RD(B) = 15
FD    = 20

15 < 20 → TRUE
```

Therefore:

```text
Successor       = A
Feasible Successor = B
```

If A fails:

```text
A fails
  ↓
B satisfies feasibility condition
  ↓
B becomes successor
  ↓
No diffusing computation required
```

## 12. DUAL Decision Process

```text
              Successor available
                     |
                     v
              Route is Passive
                     |
              Successor fails
                     |
                     v
              Is there an FS?
                /          \
              YES           NO
               |             |
               v             v
         Promote FS      Route Active
               |             |
               v             v
          Fast local       Send queries
          convergence          |
                               v
                         Receive replies
                               |
                               v
                       Diffusing computation
                               |
                               v
                         Select new route
```

## 13. EIGRP Metric Relationship

For a path:

```text
Local router
     |
     | local metric to neighbor
     v
  Neighbor
     |
     | RD toward destination
     v
Destination
```

The total path metric can be conceptually represented as:

```text
Total metric = local cost to neighbor + neighbor's reported metric
```

The exact EIGRP metric depends on the configured K-values and EIGRP metric  
components.

For classic EIGRP, the default K-values use:

```text
K1 = 1
K2 = 0
K3 = 1
K4 = 0
K5 = 0
```

Therefore, by default, EIGRP's metric primarily uses:

```text
Bandwidth + Delay
```

## 14. DUAL and Queries

Queries are used when EIGRP cannot immediately select a feasible successor.

```text
Successor lost
     ↓
No FS
     ↓
Destination becomes Active
     ↓
Query neighbors
     ↓
Neighbors determine whether they have a route
     ↓
Replies return
     ↓
DUAL selects a new path
```

Queries are **reliably transported using EIGRP's Reliable Transport Protocol (RTP)**.

The important point is:

> **No FS → query-based diffusing computation.**

## 15. Troubleshooting Commands

### View EIGRP topology

```text
show ip eigrp topology
```

Displays EIGRP topology information, including successor and metric information.

### View all topology paths

```text
show ip eigrp topology all-links
```

Useful for examining additional paths, including paths that are not currently  
feasible successors.

### View active routes

```text
show ip eigrp topology active
```

Useful when troubleshooting routes undergoing diffusing computation.

### View EIGRP neighbors

```text
show ip eigrp neighbors
```

Displays EIGRP neighbor relationships and adjacency information.

### View EIGRP traffic

```text
show ip eigrp traffic
```

Useful for examining EIGRP packet activity, including queries and replies.

### View EIGRP routes

```text
show ip route eigrp
```

Displays EIGRP routes installed in the routing table.

## 16. Common Troubleshooting Symptoms

|Symptom|Likely Cause|Useful Check|
|---|---|---|
|No feasible successor|No alternate path satisfies `RD < FD`|`show ip eigrp topology`|
|Slow convergence|No FS; queries required|`show ip eigrp topology active`|
|Route stuck Active|Required query replies are not received|`show ip eigrp topology active`|
|Excessive query propagation|Large query domain / poor EIGRP design|Topology and neighbor analysis|
|Unexpected successor|Path has a better EIGRP metric|`show ip eigrp topology`|
|FS not selected|`RD >= FD`|Compare RD with FD|
|Neighbor missing|Adjacency problem|`show ip eigrp neighbors`|

## 17. Exam Traps

### Trap 1 — FD vs RD

Do not swap them.

```text
FD = our total metric to the destination
RD = neighbor's reported metric to the destination
```

---

### Trap 2 — Equal RD and FD

This does **not** satisfy the feasibility condition.

```text
RD < FD     → YES
RD = FD     → NO
RD > FD     → NO
```

---

### Trap 3 — Best Path vs Feasible Successor

The path with the second-lowest total metric is **not automatically** a feasible  
successor.

It must satisfy:

```text
RD < FD
```

---

### Trap 4 — No FS Does Not Mean Immediate Loop

If no FS exists, EIGRP does not simply install an arbitrary backup route.

Instead:

```text
No FS
  ↓
Active
  ↓
Queries
  ↓
Replies
  ↓
Diffusing computation
```

---

### Trap 5 — Active Does Not Mean Interface Is Down

**Active** refers to the EIGRP route state and indicates that DUAL is performing  
a diffusing computation.

---

### Trap 6 — EIGRP Is Not a Link-State Protocol

EIGRP is technically classified as an **advanced distance-vector protocol**.

It has some characteristics commonly associated with link-state protocols, such as  
maintaining detailed topology information and using an SPF-like loop-free  
calculation concept, but EIGRP does **not** maintain a link-state database or run  
OSPF's SPF algorithm.

---

### Trap 7 — DUAL Does Not Require a Full Network Map

EIGRP maintains topology information learned from neighbors, but DUAL does not  
require every router to possess a complete topology map of the entire network.

---

### Trap 8 — Queries Are Not the Normal Fast Path

The preferred fast-convergence case is:

```text
Successor fails
     ↓
Feasible successor exists
     ↓
Promote FS
```

Queries are required when no feasible successor is available.

## 18. Key Relationships

Memorize this chain:

```text
Neighbor reports RD
        ↓
Local router calculates total path metric
        ↓
Best path becomes Successor
        ↓
Successor's metric becomes FD
        ↓
Other paths are tested:
        RD < FD ?
       /          \
     YES           NO
      |             |
     FS          Not FS
```
