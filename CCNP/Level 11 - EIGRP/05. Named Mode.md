# EIGRP Named Mode

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Named-mode EIGRP** is the modern EIGRP configuration model. It organizes EIGRP under a single named process:

```text
router eigrp <name>
```

Address families are then configured beneath that process using `address-family`.

Named mode can support **IPv4 and IPv6 address families within the same EIGRP named process**, with each address family having its own EIGRP autonomous-system number. Cisco also supports multiple VRF address families under named EIGRP.

The key idea is:

```text
router eigrp <name>
 └── address-family
      ├── AF-level configuration
      ├── af-interface
      └── topology base
```

---

## 2. Core Concepts

### 2.1 Classic vs Named Mode

|Feature|Classic EIGRP|Named EIGRP|
|---|---|---|
|Main process|`router eigrp <AS>`|`router eigrp <name>`|
|AS number|Process-level|Configured per address family|
|IPv4|`router eigrp <AS>`|`address-family ipv4 ...`|
|IPv6|Separate `ipv6 router eigrp <AS>`|`address-family ipv6 ...`|
|Interface settings|Mostly configured directly on interfaces|`af-interface <interface>`|
|Topology settings|Router configuration mode|`topology base`|
|Configuration hierarchy|Relatively flat|Hierarchical|
|Multiple AFs|Separate processes historically|One named process can contain multiple AFs|

**Important:** The AS number is **not the named process identifier**. The name identifies the EIGRP named process; the AS is configured for each address family.

---

### 2.2 Named EIGRP Configuration Hierarchy

A typical IPv4 + IPv6 configuration looks like:

```text
router eigrp CAMPUS
 !
 address-family ipv4 unicast autonomous-system 100
  network 10.0.0.0 0.0.255.255
  !
  topology base
   distance eigrp 90 170
  exit-af-topology
  !
  af-interface GigabitEthernet0/1
   hello-interval 5
   hold-time 15
  exit-af-interface
  !
  no shutdown
 exit-address-family
 !
 address-family ipv6 unicast autonomous-system 100
  eigrp router-id 1.1.1.1
  no shutdown
 exit-address-family
```

Named EIGRP has three important configuration modes:

1. **Address-family configuration mode**
    
    - `config-router-af`
        
2. **Address-family interface configuration mode**
    
    - `config-router-af-interface`
        
3. **Address-family topology configuration mode**
    
    - `config-router-af-topology`
        

---

### 2.3 Address-Family Configuration Mode

Entered with:

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
```

Common AF-level functions include:

- `network`
    
- `eigrp router-id`
    
- `metric weights`
    
- `af-interface`
    
- `topology`
    
- `shutdown` / `no shutdown`
    

For named IPv4 EIGRP, `network` identifies local interfaces on which EIGRP should operate.

Example:

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  network 10.1.0.0 0.0.255.255
  no shutdown
 exit-address-family
```

---

### 2.4 IPv6 Named EIGRP

IPv6 EIGRP is configured as an IPv6 address family:

```text
router eigrp CAMPUS
 address-family ipv6 unicast autonomous-system 100
  eigrp router-id 1.1.1.1
  no shutdown
 exit-address-family
```

Unlike named IPv4 EIGRP, the IPv6 address-family does **not** use the IPv4-style `network` command. IPv6 EIGRP is enabled on interfaces through the IPv6 address-family/interface configuration model.

## 3. Interface Configuration

### 3.1 `af-interface`

This is one of the most important named-mode concepts.

Interface-specific EIGRP settings are configured with:

```text
af-interface <interface>
```

**not**:

```text
interface Gi0/1
 address-family ipv4
```

Example:

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  af-interface GigabitEthernet0/1
   bandwidth-percent 50
   hello-interval 5
   hold-time 15
   bfd
  exit-af-interface
 exit-address-family
```

Cisco identifies `af-interface` as the named-EIGRP mode for interface-specific settings such as authentication, bandwidth percentage, BFD, hello/hold timers, passive-interface, split horizon, and shutdown.

---

### 3.2 `af-interface default`

You can apply interface-specific EIGRP settings to all interfaces using:

```text
af-interface default
```

Example:

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  af-interface default
   passive-interface
  exit-af-interface
 exit-address-family
```

Individual interfaces can then be configured separately as required. Cisco specifically documents `af-interface default` for applying interface configuration broadly.

---

### 3.3 Important Interface Knobs

|Command|Purpose|
|---|---|
|`af-interface <interface>`|Enter EIGRP AF interface mode|
|`passive-interface`|Suppress EIGRP hellos/neighbor formation|
|`hello-interval`|Change hello interval|
|`hold-time`|Change hold timer|
|`bandwidth-percent`|Limit EIGRP's usable interface bandwidth|
|`bfd`|Enable BFD-based fast failure detection|
|`authentication`|Configure EIGRP authentication|
|`summary-address`|Configure interface-level EIGRP summarization|
|`split-horizon`|Control split horizon|
|`shutdown`|Disable EIGRP for that AF on the interface|

---

## 4. Topology Configuration

### 4.1 `topology base`

Enter topology configuration mode with:

```text
address-family ipv4 unicast autonomous-system 100
 topology base
```

The `topology base` section contains settings that operate on the EIGRP topology/routing information.

Common commands include:

- `distance`
    
- `variance`
    
- `maximum-paths`
    
- `traffic-share`
    
- `default-metric`
    
- `redistribute`
    
- `offset-list`
    
- `distribute-list`
    
- `auto-summary`
    
- topology-specific timers
    

Cisco explicitly places `variance`, `maximum-paths`, `distance`, redistribution, and related commands under address-family topology configuration mode.

Example:

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   variance 2
   maximum-paths 4
   distance eigrp 90 170
  exit-af-topology
 exit-address-family
```

---

### 4.2 Variance

`variance` controls EIGRP unequal-cost load balancing.

Example:

```text
topology base
 variance 2
```

A route must still satisfy EIGRP's loop-free condition before variance can cause it to be installed. The route's metric must also fall within the configured variance relative to the successor.

**Exam point:**

```text
variance 1
```

means normal equal-cost behavior.

```text
variance 2
```

allows eligible unequal-cost paths whose metric is within the configured multiplier.

---

### 4.3 Maximum Paths

Controls the maximum number of parallel EIGRP routes installed:

```text
topology base
 maximum-paths 4
```

Cisco documents `maximum-paths` as a topology-level command in named EIGRP.

---

### 4.4 Administrative Distance

Named mode can configure EIGRP administrative distance under topology configuration:

```text
topology base
 distance eigrp 90 170
```

The values represent:

```text
90  = internal EIGRP
170 = external EIGRP
```

---

## 5. EIGRP Process Shutdown

Named EIGRP has an important shutdown behavior.

Simply creating the address family does not necessarily start IPv4 EIGRP. Cisco documents the use of:

```text
no shutdown
```

to activate the EIGRP process/address family.

Example:

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  no shutdown
 exit-address-family
```

Therefore, if the AF is configured but neighbors do not form, check whether it is administratively shut down.

## 6. Configuration Example

### IPv4 Named EIGRP

```text
router eigrp CAMPUS
 !
 address-family ipv4 unicast autonomous-system 100
  network 10.1.0.0 0.0.255.255
  !
  af-interface GigabitEthernet0/1
   hello-interval 5
   hold-time 15
   bandwidth-percent 50
  exit-af-interface
  !
  topology base
   variance 2
   maximum-paths 4
   distance eigrp 90 170
  exit-af-topology
  !
  no shutdown
 exit-address-family
```

### IPv4 + IPv6

```text
router eigrp CAMPUS
 !
 address-family ipv4 unicast autonomous-system 100
  network 10.1.0.0 0.0.255.255
  no shutdown
 exit-address-family
 !
 address-family ipv6 unicast autonomous-system 100
  eigrp router-id 1.1.1.1
  no shutdown
 exit-address-family
```

The important distinction is that **one named EIGRP process contains both AFs**, while each AF has its own AS configuration.

## 7. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|No IPv4 neighbors|AF shutdown|`no shutdown` under IPv4 AF|
|No neighbors|AS mismatch|Verify AF autonomous-system values|
|No neighbors|Interface not matched by `network`|Check IPv4 network statement|
|Interface not participating|Incorrect `af-interface` configuration|Check named EIGRP AF interface configuration|
|Interface silent|`passive-interface`|Check `af-interface`|
|IPv6 EIGRP not working|IPv6 AF not configured/active|Check IPv6 AF and `no shutdown`|
|IPv6 router ID missing|No valid router ID|Configure `eigrp router-id`|
|Neighbor drops|Timer mismatch or connectivity problem|Check hello/hold timers and interface state|
|Wrong route metric|Metric parameters or topology settings|Check topology table|
|K-value mismatch|Different metric weights|Check `metric weights` on both neighbors|

## 9. Exam Traps

### Trap 1 — The AS number is not the process name

Incorrect mental model:

```text
router eigrp 100
```

Named mode uses:

```text
router eigrp CAMPUS
```

Then:

```text
address-family ipv4 unicast autonomous-system 100
```

The **name** identifies the named process; the **AS number** belongs to the address family.

---

### Trap 2 — Interface configuration is `af-interface`

Do **not** confuse named EIGRP with a generic interface address-family hierarchy.

Correct:

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  af-interface GigabitEthernet0/1
   hello-interval 5
  exit-af-interface
```

---

### Trap 3 — Variance belongs under `topology base`

Correct:

```text
address-family ipv4 unicast autonomous-system 100
 topology base
  variance 2
```

Not:

```text
address-family ipv4 unicast autonomous-system 100
 variance 2
```

`variance`, `maximum-paths`, and `distance` are topology-level settings.

---

### Trap 4 — IPv6 does not use the IPv4 `network` command

IPv4 named EIGRP:

```text
network 10.1.0.0 0.0.255.255
```

IPv6 named EIGRP uses the IPv6 AF/interface model instead.

---

### Trap 5 — `no shutdown` matters

Named EIGRP address families can be administratively shut down.

Remember:

```text
no shutdown
```

activates the address family/process.

---

### Trap 6 — K-values are metric parameters

EIGRP K-values are configured through metric weights, for example:

```text
metric weights 0 1 0 1 0 0
```

Neighboring EIGRP routers must use compatible K-values to form an adjacency.

## 10. Quick Review

|Item|Named EIGRP|
|---|---|
|Main process|`router eigrp <name>`|
|IPv4 AF|`address-family ipv4 unicast autonomous-system <AS>`|
|IPv6 AF|`address-family ipv6 unicast autonomous-system <AS>`|
|AS|Per address family|
|IPv4 network activation|`network` under IPv4 AF|
|Interface configuration|`af-interface <interface>`|
|All-interface defaults|`af-interface default`|
|Topology configuration|`topology base`|
|Variance|Under `topology base`|
|Maximum paths|Under `topology base`|
|EIGRP distance|Under `topology base`|
|Interface timers|Under `af-interface`|
|IPv4 + IPv6|Same named EIGRP process|
|IPv6 `network` command|Not used|
|AF activation|`no shutdown`|
|Key advantage|Hierarchical, multi-AF configuration|

## 11. One-Minute Mental Model

Think of Named EIGRP as:

```text
router eigrp NAME
        │
        ├── address-family IPv4
        │      │
        │      ├── network
        │      │
        │      ├── af-interface
        │      │      ├── hello/hold
        │      │      ├── authentication
        │      │      ├── passive
        │      │      └── BFD
        │      │
        │      └── topology base
        │             ├── variance
        │             ├── maximum-paths
        │             ├── distance
        │             └── redistribution
        │
        └── address-family IPv6
               │
               ├── router-id
               ├── af-interface
               └── topology base
```

**Core exam formula:**

> **Named EIGRP = Name → Address Family → `af-interface` + `topology base`**

That hierarchy is the most important thing to remember for ENCOR.
