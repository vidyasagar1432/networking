# EIGRP Named Mode

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Named-mode EIGRP** (IOS 15+, the modern standard) unifies EIGRP configuration under a
**single hierarchical `router eigrp <name>`** that supports **multiple address families**
(IPv4, IPv6, and even others) in one process. It replaces the old classic `router eigrp
<AS>` + `network` style with `address-family` sections and per-AF interfaces. Named mode is
what the ENCOR exam expects for EIGRP config.

---

## 2. Core Concepts

### 2.1 Classic vs Named mode

| | Classic EIGRP | Named mode |
|--|---------------|-----------|
| Process ID | AS number | name |
| IPv4 + IPv6 | separate processes | **one process, multiple AFs** |
| IPv6 support | separate `ipv6 router eigrp` | AF ipv6 in same process |
| Interface config | separate `ip/ipv6 eigrp` | unified per-AF interface |
| CLI | router, network, passive-interface | address-family subcommands |

### 2.2 The hierarchical structure

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  network 10.0.0.0 0.0.255.255
  topology base
   distance eigrp 90 170
  exit-address-family
 address-family ipv6 unicast autonomous-system 100
  network 2001:db8::/32
 exit-address-family
```

- **AS number is required** inside each AF (`autonomous-system`).
- **`topology base`** block is where per-route knobs live (offsets, variance, distance).

### 2.3 Interface config under named mode

```text
interface Gi0/1
 address-family ipv4
  bandwidth-percent 50          ! limit EIGRP BW usage
  hello-interval 5
  hold-time 15
  shutdown                    ! EIGRP per-interface shutdown
 exit-address-family
```

- Everything interface-specific moves under the **AF on the interface**.

### 2.4 Address-family knobs (the common set)

| Knob | Purpose |
|------|---------|
| `variance` | unequal load balancing (note 09) |
| `maximum-paths` | ECMP count |
| `distance eigrp` | AD internal/external |
| `default-metric` | redistributed metric |
| `passive-interface` | suppress hellos |
| `summary-address` | interface summarization |
| `bfd` | fast detection |

### 2.5 Named-mode advantages

- **One process** for IPv4+IPv6 (easier, consistent).
- **Same topology concepts** for both AFs — DUAL/FS identical.
- Cleaner **per-AF defaults** and troubleshooting (`show eigrp address-family ...`).

## 3. Configuration / Commands

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  network 10.1.0.0 0.0.255.255
  variance 2
  exit-address-family

show eigrp address-family ipv4 neighbors
show eigrp address-family ipv4 topology
show eigrp address-family ipv4 interfaces
show run | section router eigrp
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No neighbors | AS mismatch in AF | verify `autonomous-system` both ends |
| IPv6 not running | AF ipv6 missing | add address-family ipv6 |
| Interface silent | AF shutdown under interface | `show run interface`, `no shutdown` |
| Wrong metric | bandwidth-percent / delay tuned | `show eigrp ... topology` |
| K-values mismatch | set per AF differently | match K-values |

---

## 5. Exam Traps

- **Named mode = one process, multiple AFs** — the modern answer.
- **`autonomous-system` is required** per address family.
- **Interface-specific EIGRP settings live under the interface's AF block.**
- Named mode supports **IPv4 + IPv6 together** (classic needed two processes).
- `topology base` holds variance/distance — the CLI-location question.
