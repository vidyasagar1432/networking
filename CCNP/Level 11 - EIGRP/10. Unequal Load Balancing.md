# EIGRP Unequal-Cost Load Balancing

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Unequal-cost load balancing** allows EIGRP to install multiple loop-free paths to the same  
destination even when their **metrics are different**.

It is enabled with **`variance`**. The default `variance` is **1**, which permits normal  
equal-cost multipath (ECMP). A value greater than 1 expands the acceptable metric range for  
additional paths.

**Important:** `variance` does **not** bypass EIGRP's loop-prevention mechanism. An alternate  
path must still satisfy the **feasibility condition** before it can be considered.

EIGRP determines which paths are eligible and installs the routes; **CEF/data-plane forwarding**  
then performs the actual packet load sharing.

---

## 2. Core Concepts

### 2.1 Successor, Feasible Successor, and FD

- **Successor:** The best path to the destination.
    
- **Feasible Distance (FD):** The total EIGRP metric from the local router to the destination.
    
- **Reported Distance (RD):** The neighbor's advertised distance to the destination.
    
- **Feasible Successor (FS):** A backup path that satisfies the feasibility condition.
    

The feasibility condition is:

```text
RD < FD(successor)
```

If this condition is true, the alternate path is considered **loop-free** and can become a  
feasible successor.

---

### 2.2 Full Eligibility Test for Unequal-Cost Load Balancing

An alternate path must satisfy **both** conditions:

```text
1. Metric bound:
   FD(path) <= variance × FD(successor)

2. Loop-free condition:
   RD(path) < FD(successor)
```

Therefore:

```text
Variance alone is NOT enough.
```

A path can fall within the variance metric range but still be excluded if it does not satisfy  
the feasibility condition.

---

## 3. How `variance` Works

Suppose:

```text
Successor FD = 100
Variance = 2
```

The maximum acceptable FD is:

```text
2 × 100 = 200
```

Therefore, an alternate path with:

```text
FD = 180
```

can potentially be installed **if**:

```text
RD < 100
```

But an alternate path with:

```text
FD = 220
```

is outside the variance bound and cannot be installed.

### Key rule

```text
Eligible path =
    FD(path) <= variance × successor FD
    AND
    RD(path) < successor FD
```

---

## 4. Traffic Distribution

When multiple unequal-cost paths are installed, EIGRP's **balanced traffic-sharing**  
calculation gives lower-metric paths a greater share of traffic.

A useful exam representation is:

```text
Path share ratio = Highest installed-path metric / Path metric
```

Example:

|Path|Metric|Relative Share|
|---|--:|--:|
|A|100|200 / 100 = 2|
|B|200|200 / 200 = 1|

Therefore:

```text
A : B = 2 : 1
```

Approximately:

```text
Path A = 2/3
Path B = 1/3
```

**Important:** EIGRP determines the eligible paths and their route metrics; the actual packet  
forwarding/load sharing is performed by the router's forwarding mechanism, such as **CEF**.

---

## 5. Equal-Cost vs Unequal-Cost Load Balancing

|Feature|Equal-Cost (ECMP)|Unequal-Cost|
|---|---|---|
|Path metrics|Equal|Different|
|Variance|`1`|`> 1`|
|Traffic distribution|Equal-cost paths|Weighted toward lower metric|
|Loop-free requirement|Yes|Yes|
|Main enabler|Default behavior|`variance n`|
|Maximum installed paths|`maximum-paths`|`maximum-paths`|

### Remember

```text
variance 1 → normal equal-cost multipath
variance >1 → permits eligible unequal-cost paths
```

---

## 6. Important `maximum-paths` Relationship

`variance` determines **which unequal-cost paths are eligible**.

`maximum-paths` limits **how many paths can actually be installed**.

For example:

```text
variance 3
maximum-paths 2
```

Even if four paths satisfy the variance and feasibility requirements, only the permitted number  
of paths can be installed according to the configured maximum.

Therefore:

```text
variance       → metric eligibility
feasibility    → loop-free eligibility
maximum-paths  → installation limit
```

## 9. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Only one path installed|Alternate path fails FS/variance test|Check RD, FD, and variance|
|Alternate path outside range|FD too high|Check `FD <= variance × successor FD`|
|Alternate path is not loop-free|RD fails feasibility condition|Check `RD < successor FD`|
|Too few paths installed|`maximum-paths` limit|Check `maximum-paths`|
|Unexpected traffic ratio|Unequal metrics misunderstood|Calculate relative path shares|
|Path repeatedly enters/leaves|Unstable metric/link|Check interface and EIGRP metrics|
|Traffic does not appear perfectly packet-by-packet proportional|Forwarding uses hashing/flow behavior|Check CEF/load-sharing behavior|

## 10. Exam Traps

### Trap 1 — Variance bypasses loop prevention

**False.**

`variance` only expands the acceptable metric range. The alternate path must still satisfy:

```text
RD < FD(successor)
```

---

### Trap 2 — Every path inside the variance range is installed

**False.**

Both conditions are required:

```text
FD(path) <= variance × FD(successor)
AND
RD(path) < FD(successor)
```

---

### Trap 3 — Unequal paths receive equal traffic

**False.**

Balanced EIGRP traffic sharing favors the lower-metric path.

For example:

```text
Metric 100 → relative share 2
Metric 200 → relative share 1

Traffic ratio = 2 : 1
```

---

### Trap 4 — `variance 1` enables unequal-cost balancing

**False.**

```text
variance 1 → normal equal-cost behavior
variance > 1 → allows eligible unequal-cost paths
```

---

### Trap 5 — Variance controls the number of paths

**False.**

`variance` controls the **metric eligibility window**.

`maximum-paths` controls the **maximum number of paths installed**.

---

### Trap 6 — EIGRP directly forwards every packet

**False.**

EIGRP is responsible for route calculation and route installation. The forwarding plane,  
typically **CEF**, performs the actual packet forwarding and load sharing.

---

## 11. Design Considerations

Unequal-cost load balancing is useful when multiple paths have different characteristics, such  
as links with different bandwidths.

However, do not assume that different bandwidths automatically make paths eligible.

The alternate route must first satisfy:

```text
RD < successor FD
```

and then:

```text
FD <= variance × successor FD
```

Also consider:

- Link bandwidth and delay
    
- EIGRP composite metric
    
- `variance`
    
- `maximum-paths`
    
- Stability of the links
    
- Actual CEF forwarding behavior
