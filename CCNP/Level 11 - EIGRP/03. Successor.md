# EIGRP Successor

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **successor** is the EIGRP path selected as the **best path to a destination**.  
Its route is installed in the routing table.

EIGRP uses the **DUAL** algorithm to select loop-free paths. The successor is the  
path with the **lowest total EIGRP metric** among the eligible paths.

For the selected successor, that total metric is the router's **Feasible Distance  
(FD)**.

```text
Successor = best eligible path
FD         = total metric of the selected path
```

For an internal EIGRP route, the route normally appears in the routing table with:

```text
D
Administrative Distance = 90
```

---

## 2. Core Concepts

### 2.1 Feasible Distance (FD)

**Feasible Distance (FD)** is the local router's total EIGRP metric to the  
destination through a particular path.

Conceptually:

```text
FD = local cost to neighbor + neighbor's Reported Distance (RD)
```

Many study resources call **Reported Distance (RD)** the **Advertised Distance (AD)**.

Therefore:

```text
FD = local cost + RD/AD
```

Example:

```text
Local cost to A = 10
A reports RD    = 10

Total metric    = 10 + 10
                = 20
```

If this is the best eligible path, the successor's FD is:

```text
FD = 20
```

---

## 3. Successor Selection

Suppose R1 learns three paths to `10.10.10.0/24`:

```text
Neighbor       Total EIGRP Metric
---------------------------------
A                    20
B                    25
C                    35
```

The best path is:

```text
A = 20
```

Therefore:

```text
Successor = A
FD        = 20
```

The successor is installed in the routing table.

```text
R1# show ip route eigrp

D    10.10.10.0/24 [90/20] via A
```

The exact output format depends on the platform, but the important relationship is:

```text
D
[90/20]
  |  |
  |  +-- EIGRP metric
  +----- Administrative Distance
```

---

## 4. Successor vs Feasible Successor

|Feature|Successor|Feasible Successor|
|---|---|---|
|Purpose|Best path|Loop-free backup path|
|Selection|Best eligible total metric|Must satisfy `RD < FD`|
|Routing table|Installed|Not installed while merely an FS|
|Topology table|Yes|Yes|
|Used for forwarding|Yes|No, while only an FS|
|Used after successor failure|Already active|Can become successor|
|Queries required when successor fails|—|No diffusing computation if a valid FS exists|

### Remember

```text
Successor:
    Best path

Feasible Successor:
    Qualified backup path
```

---

## 5. Feasible Successor Condition

A path does not become a feasible successor merely because it has the second-best  
metric.

It must satisfy:

```text
RD < current FD
```

Example:

```text
Current successor:
    FD = 20

Neighbor B:
    RD = 15
    Total metric = 25
```

Check:

```text
15 < 20
```

True.

Therefore:

```text
B = Feasible Successor
```

Notice that B's total metric can be **higher than the successor's FD** and still  
qualify as an FS.

This is a critical EIGRP exam concept.

---

## 6. Why an FS Can Have a Higher Metric

Consider:

```text
Path A:
    RD = 10
    Local cost = 10
    Total = 20

Path B:
    RD = 15
    Local cost = 10
    Total = 25
```

Successor:

```text
A
FD = 20
```

Feasibility check for B:

```text
RD(B) = 15
FD    = 20

15 < 20 → TRUE
```

Therefore:

```text
A = Successor
B = Feasible Successor
```

Even though:

```text
B total metric = 25
A total metric = 20
```

B is still a valid loop-free backup.

---

## 7. Successor Failure

When the successor becomes unavailable, DUAL determines whether a feasible  
successor exists.

### Case 1 — Feasible Successor Exists

```text
Successor fails
       ↓
Valid FS exists
       ↓
FS becomes successor
       ↓
Route is updated
```

No **diffusing computation** or query process is required for that destination.

This is the fast-convergence case.

---

### Case 2 — No Feasible Successor

```text
Successor fails
       ↓
No FS
       ↓
Route becomes Active
       ↓
EIGRP sends Queries
       ↓
Neighbors send Replies
       ↓
DUAL performs diffusing computation
       ↓
New path selected
```

This can take longer because the route depends on query/reply processing.

---

## 8. Successor and the Routing Table

Only the currently selected successor path(s) are installed in the routing table.

The topology table can contain:

```text
Successor
Feasible Successor
Other EIGRP-learned paths
```

Conceptually:

```text
Topology Table
│
├── Path A → Successor
├── Path B → Feasible Successor
└── Path C → Other candidate
        │
        v
Routing Table
│
└── Path A → Installed
```

If Path A fails and Path B satisfies the required conditions, Path B can become  
the new successor.

---

## 9. Equal-Cost Paths and Multiple Successors

EIGRP can install **multiple equal-cost paths** when the relevant paths have equal  
metrics and the configured/platform limits permit multiple paths.

Example:

```text
Neighbor A = metric 20
Neighbor B = metric 20
Neighbor C = metric 35
```

A and B can be selected as equal-cost successor paths.

```text
A ──┐
    ├── Destination
B ──┘
```

This provides **ECMP (Equal-Cost Multi-Path)** forwarding.

Do not memorize:

```text
Equal metric = unlimited paths
```

The number of installed paths is subject to EIGRP configuration and platform  
limits, including the `maximum-paths` setting.

## 10. EIGRP Route Codes

### Internal EIGRP

```text
D
```

Default administrative distance:

```text
90
```

Example:

```text
D 10.10.10.0/24 [90/20] via 192.168.1.2
```

---

### External EIGRP

```text
D EX
```

Default administrative distance:

```text
170
```

An EIGRP external route is a route learned by EIGRP through redistribution from  
another routing source or another source of routing information.

Example:

```text
D EX 172.16.0.0/16 [170/...] via 192.168.1.2
```

### Important

Do not confuse:

```text
D    → Internal EIGRP → AD 90
D EX → External EIGRP → AD 170
```

---

## 11. Administrative Distance vs EIGRP Metric

These are different concepts.

### Administrative Distance

Determines **which routing protocol or route source is preferred** when multiple  
sources provide the same destination.

```text
Internal EIGRP = 90
External EIGRP = 170
```

### EIGRP Metric

Determines the best path **within EIGRP**.

```text
Lower EIGRP metric
        ↓
Better EIGRP path
```

Example:

```text
Path A = EIGRP metric 20
Path B = EIGRP metric 25
```

A is preferred within EIGRP.

Do not confuse:

```text
AD = trust/preference between route sources
Metric = path quality within EIGRP
```

## 12. Successor Selection Process

A simplified EIGRP process is:

```text
Receive EIGRP path information
            ↓
Calculate total EIGRP metric
            ↓
Identify best eligible path
            ↓
Select successor
            ↓
Calculate/store FD
            ↓
Evaluate other paths
            ↓
Check feasibility condition
       RD < FD ?
       /       \
     YES        NO
      |          |
     FS       Not FS
```

---

## 13. Important Metric Relationship

Suppose:

```text
Neighbor A:
    RD = 10
    Local cost = 10
    Total metric = 20

Neighbor B:
    RD = 15
    Local cost = 10
    Total metric = 25

Neighbor C:
    RD = 30
    Local cost = 5
    Total metric = 35
```

Best path:

```text
A = 20
```

Therefore:

```text
Successor = A
FD = 20
```

Check B:

```text
RD(B) = 15
15 < 20 → TRUE
```

Therefore:

```text
B = Feasible Successor
```

Check C:

```text
RD(C) = 30
30 < 20 → FALSE
```

Therefore:

```text
C = Not a Feasible Successor
```

Final result:

```text
Successor:
    A

Feasible Successor:
    B

Other candidate:
    C
```

---

## 14. Important Distinction: Total Metric vs FD

For exam questions, be precise with terminology.

```text
Neighbor reports:
    RD

Local router adds:
    local cost

Result:
    total path metric
```

The best path is selected based on the **lowest eligible total EIGRP metric**.

The metric of the selected path is the router's **FD** for that destination.

Therefore, avoid thinking of FD as merely the neighbor's metric.

```text
RD = neighbor's reported metric
FD = our total metric for the selected path
```

## 15. Troubleshooting

### Wrong Successor

Possible causes:

- Interface bandwidth/delay changes
    
- EIGRP metric changes
    
- K-value configuration
    
- Different path characteristics
    
- Route filtering or topology changes
    

Useful commands:

```text
show ip eigrp topology
show ip route eigrp
show ip eigrp neighbors
```

---

### Successor Missing

Possible causes:

- EIGRP neighbor is down
    
- Route is no longer being advertised
    
- Interface failure
    
- Filtering
    
- Topology change
    

Check:

```text
show ip eigrp neighbors
show ip eigrp topology
show ip route eigrp
```

---

### Feasible Successor Not Used

Check:

```text
RD < FD
```

If:

```text
RD >= FD
```

the path does not satisfy the feasibility condition and cannot be used as an FS.

---

### No Fast Failover

If a successor fails and no FS exists:

```text
No FS
  ↓
Active
  ↓
Queries
  ↓
Replies
  ↓
New route
```

Investigate:

```text
show ip eigrp topology active
```

## 17. Exam Traps

### Trap 1 — Successor Is Not “Second Best”

```text
Successor = best eligible path
```

The second-best path is not automatically an FS.

It must satisfy:

```text
RD < FD
```

---

### Trap 2 — FS Is Not Selected by Lowest Total Metric

The successor is selected based on the best total metric.

An FS is selected based on the **feasibility condition**.

```text
Successor:
    Best total metric

FS:
    RD < FD
```

---

### Trap 3 — FS Can Have a Higher Total Metric

Example:

```text
Successor FD = 20
FS total metric = 25
FS RD = 15
```

Because:

```text
15 < 20
```

the path can still be a feasible successor.

---

### Trap 4 — Equal RD and FD

```text
RD = FD
```

does **not** satisfy the feasibility condition.

The rule is:

```text
RD < FD
```

---

### Trap 5 — Administrative Distance Is Not the EIGRP Metric

```text
AD 90
```

does not mean the EIGRP metric is 90.

Example:

```text
D 10.10.10.0/24 [90/20]
                  | |
                  | +-- EIGRP metric
                  +---- Administrative Distance
```

---

### Trap 6 — D vs D EX

```text
D     = Internal EIGRP → AD 90
D EX  = External EIGRP → AD 170
```

---

### Trap 7 — Successor Failure Does Not Always Mean Queries

```text
Successor fails
       ↓
FS exists?
   /       \
 YES        NO
  |          |
  v          v
Promote     Query
FS          neighbors
```

A valid FS allows fast convergence without diffusing computation.

## 18. Successor vs DUAL vs RTP

These three concepts should not be mixed up.

|Concept|Main Job|
|---|---|
|**Successor**|Best EIGRP path selected for forwarding|
|**DUAL**|Calculates/selects loop-free paths and convergence behavior|
|**RTP**|Provides EIGRP-specific reliable packet delivery|
|**Feasible Successor**|Loop-free backup path|
|**Topology Table**|Stores EIGRP path information|
|**Routing Table**|Stores installed forwarding routes|

### Memory Trick

```text
DUAL → Decides
Successor → Best path
FS → Backup path
RTP → Delivers EIGRP packets
```
