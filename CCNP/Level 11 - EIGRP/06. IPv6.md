# EIGRP for IPv6

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**EIGRP for IPv6** provides dynamic routing for IPv6 using the same fundamental EIGRP mechanisms as IPv4:

- **DUAL** for loop-free route selection
    
- **RTP** for reliable EIGRP packet delivery
    
- **Successors and Feasible Successors**
    
- **Composite metrics**
    
- **Query/reply operation**
    
- **Unequal-cost load balancing with variance**
    
- **Route summarization and EIGRP stub functionality**
    

The major operational difference is that EIGRP for IPv6 runs directly over **IPv6**, uses **IPv6 multicast**, and does **not use IPv4-style `network` statements** to identify participating interfaces.

On modern IOS/IOS XE, EIGRP for IPv6 is normally configured using **named mode** with an IPv6 address family.

---

## 2. Core Concepts

### 2.1 IPv4 vs IPv6 EIGRP

|Feature|EIGRP for IPv4|EIGRP for IPv6|
|---|---|---|
|IP protocol|IP protocol 88|IPv6 Next Header 88|
|Multicast|`224.0.0.10`|`FF02::A`|
|Address family|IPv4 unicast|IPv6 unicast|
|Interface activation|`network` statement in classic mode|Interface-based|
|IPv6 `network` statement|N/A|**Not used**|
|Neighbor addressing|IPv4 addresses|IPv6 link-local addresses commonly used|
|Router ID|32-bit value|32-bit value|
|DUAL|Yes|Yes|
|RTP|Yes|Yes|
|Successor / FS|Yes|Yes|
|Composite metric|Yes|Yes|
|Named mode|Supported|Supported|

**Key exam point:**

> EIGRP for IPv6 uses **FF02::A**, has **no IPv6 `network` statements**, and commonly uses the neighbor's **link-local address** as the next hop.

---

## 3. EIGRP for IPv6 Packet Operation

EIGRP for IPv6 uses the same EIGRP packet types and fundamental operation as IPv4.

|Packet|Purpose|
|---|---|
|Hello|Discover and maintain neighbors|
|Update|Advertise routing information|
|Query|Ask neighbors for an alternate route|
|Reply|Respond to a query|
|ACK|Acknowledge reliable EIGRP packets|

EIGRP uses **RTP (Reliable Transport Protocol)** to provide reliable delivery of packets such as Updates, Queries, and Replies.

EIGRP itself is identified by **IP protocol number 88**.

For IPv6, EIGRP packets are carried directly in IPv6 rather than TCP or UDP.

---

## 4. Multicast Address

EIGRP for IPv6 uses:

```text
FF02::A
```

This is the IPv6 link-local multicast address corresponding to EIGRP routers.

IPv4 EIGRP uses:

```text
224.0.0.10
```

### Exam memory

```text
IPv4 EIGRP → 224.0.0.10
IPv6 EIGRP → FF02::A
```

Both represent the EIGRP multicast group for neighboring EIGRP routers.

---

## 5. IPv6 Link-Local Addresses

EIGRP for IPv6 can use the neighbor's **link-local IPv6 address** for the next hop.

Example:

```text
FE80::2
```

This is normal IPv6 behavior.

A global unicast address is **not required solely for EIGRP neighbor discovery** when the interfaces have valid IPv6 link-local addresses.

The link-local address is significant because it is valid only on the local link, which is exactly where an EIGRP neighbor relationship exists.

### Exam trap

If you see:

```text
FE80::2
```

as the next hop in an IPv6 EIGRP route, that is **normal**.

---

## 6. Requirements

### 6.1 Enable IPv6 Routing

IPv6 routing must be enabled globally:

```text
ipv6 unicast-routing
```

Without IPv6 routing enabled, the router cannot perform normal IPv6 routing.

---

### 6.2 IPv6 Addressing

Participating interfaces need IPv6 connectivity and normally have automatically generated link-local addresses.

Example:

```text
interface GigabitEthernet0/1
 ipv6 address 2001:db8:1::1/64
```

The interface will normally also have a link-local address.

---

### 6.3 EIGRP Router ID

EIGRP for IPv6 requires a **32-bit EIGRP router ID**.

Example:

```text
router eigrp CAMPUS
 address-family ipv6 unicast autonomous-system 100
  eigrp router-id 1.1.1.1
```

The router ID is written in IPv4 dotted-decimal format even though the EIGRP address family is IPv6.

Example:

```text
1.1.1.1
```

This is an **EIGRP router ID**, not an IPv4 address that must exist on an interface.

---

## 7. Named-Mode Configuration

Modern IOS/IOS XE uses named EIGRP configuration.

The basic hierarchy is:

```text
router eigrp CAMPUS
 address-family ipv6 unicast autonomous-system 100
  eigrp router-id 1.1.1.1
  ...
```

The important hierarchy is:

```text
router eigrp <name>
 └── address-family ipv6 unicast autonomous-system <AS>
      ├── router-id
      ├── af-interface
      └── topology base
```

---

## 8. Interface Activation in Named Mode

Unlike classic IPv4 EIGRP, IPv6 EIGRP does not use an IPv6 `network` command.

Interface-specific EIGRP configuration is performed through:

```text
af-interface <interface>
```

Example:

```text
router eigrp CAMPUS
 address-family ipv6 unicast autonomous-system 100
  eigrp router-id 1.1.1.1
  af-interface GigabitEthernet0/1
   no shutdown
  exit-af-interface
  no shutdown
 exit-address-family
```

The exact interface activation syntax can vary by IOS/IOS XE release, so for exam purposes remember the architectural rule:

> **IPv6 EIGRP participation is interface-based, not controlled by an IPv6 `network` statement.**

---

## 9. Classic EIGRP for IPv6

Older IOS implementations can use the classic configuration model:

```text
ipv6 unicast-routing

ipv6 router eigrp 100
 eigrp router-id 1.1.1.1
 no shutdown

interface GigabitEthernet0/1
 ipv6 eigrp 100
```

The important commands are:

```text
ipv6 router eigrp 100
```

and:

```text
ipv6 eigrp 100
```

under the participating interface.

### Classic vs Named

|Classic IPv6 EIGRP|Named IPv6 EIGRP|
|---|---|
|`ipv6 router eigrp 100`|`router eigrp CAMPUS`|
|Interface: `ipv6 eigrp 100`|EIGRP `af-interface`|
|Separate IPv6 EIGRP process|IPv6 AF inside named process|
|Older configuration model|Modern configuration model|

---

## 10. EIGRP Metrics for IPv6

EIGRP for IPv6 uses the same fundamental composite metric model as IPv4 EIGRP.

With the default K-values, the active metric components are:

- **Bandwidth**
    
- **Delay**
    

Other metric components exist in the EIGRP metric formula, but their default K-values are zero.

The important exam point is:

> EIGRP for IPv6 does **not** use a fundamentally different metric algorithm from EIGRP for IPv4.

---

## 11. Successor and Feasible Successor

EIGRP for IPv6 uses the same DUAL concepts as IPv4.

### Successor

The **successor** is the best loop-free path selected for a destination.

### Feasible Successor

A **Feasible Successor (FS)** is a loop-free backup path that satisfies the feasibility condition.

The key condition is:

```text
Reported Distance < Feasible Distance
```

Where:

- **RD (Reported Distance)** = neighbor's advertised distance to the destination
    
- **FD (Feasible Distance)** = local router's best-known distance to the destination
    

If a feasible successor exists when the successor fails, EIGRP can install the backup path without going active and without sending queries for that destination.

This behavior is identical in principle to IPv4 EIGRP.

---

## 12. Unequal-Cost Load Balancing

EIGRP for IPv6 supports unequal-cost load balancing using:

```text
variance
```

In named mode, the command belongs under the topology configuration:

```text
router eigrp CAMPUS
 address-family ipv6 unicast autonomous-system 100
  topology base
   variance 2
  exit-af-topology
 exit-address-family
```

The candidate route must still satisfy EIGRP's loop-free feasibility requirements.

---

## 13. Route Summarization

EIGRP for IPv6 supports route summarization.

In named mode, summarization is configured on the appropriate EIGRP address-family interface.

Conceptually:

```text
router eigrp CAMPUS
 address-family ipv6 unicast autonomous-system 100
  af-interface GigabitEthernet0/1
   summary-address 2001:db8:100::/48
  exit-af-interface
 exit-address-family
```

Summarization can reduce routing-table size and limit the propagation of more-specific routes.

---

## 14. EIGRP Stub for IPv6

EIGRP stub functionality is also available for IPv6.

The purpose is the same as IPv4:

- Reduce unnecessary query propagation
    
- Improve stability
    
- Reduce query scope
    
- Make the router appropriate for stub/branch roles
    

The underlying DUAL query-boundary concept remains the same.

---

## 15. Administrative Distance

The default EIGRP administrative distances remain:

```text
Internal EIGRP = 90
External EIGRP = 170
```

These are **administrative distances**, not EIGRP metric values.

Remember the distinction:

```text
Metric → chooses the best EIGRP path
AD     → chooses between routes from different sources
```

## 16. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|No IPv6 neighbors|IPv6 routing not enabled|`ipv6 unicast-routing`|
|No neighbors|EIGRP not enabled on interface|Check AF interface configuration|
|No neighbors|EIGRP AF shutdown|Check `no shutdown`|
|Process does not operate|Missing router ID|Configure `eigrp router-id`|
|No routes|Interface not participating|Verify EIGRP interface configuration|
|Unexpected `FE80::` next hop|None — this is normal|IPv6 EIGRP commonly uses link-local next hops|
|Neighbors fail to form|AS mismatch|Verify EIGRP AS on both sides|
|Neighbors fail|K-value mismatch|Check EIGRP metric weights|
|Routes missing|Filtering/summarization|Check topology and interface configuration|
|Backup path not installed|Feasibility condition not satisfied|Check RD vs FD|

## 18. Troubleshooting Workflow

When IPv6 EIGRP is not working, check in this order:

```text
1. ipv6 unicast-routing
        ↓
2. IPv6 addressing / link-local connectivity
        ↓
3. Correct EIGRP IPv6 address family
        ↓
4. Correct AS number
        ↓
5. EIGRP router ID
        ↓
6. EIGRP enabled on the interface
        ↓
7. AF/process is not shut down
        ↓
8. K-values match
        ↓
9. Neighbor relationship
        ↓
10. Topology table
        ↓
11. IPv6 routing table
```

This separates **neighbor formation problems** from **route installation problems**.

## 19. Exam Traps

### Trap 1 — Multicast address

```text
IPv4 EIGRP → 224.0.0.10
IPv6 EIGRP → FF02::A
```

---

### Trap 2 — No IPv6 `network` statements

Do not look for:

```text
network 2001:db8::/64
```

EIGRP for IPv6 is activated on interfaces rather than through an IPv6 `network` command.

---

### Trap 3 — Link-local next hop is normal

Seeing:

```text
FE80::2
```

as an IPv6 EIGRP next hop is expected behavior.

---

### Trap 4 — Router ID is still 32-bit

Even though EIGRP is routing IPv6, the EIGRP router ID is still represented as:

```text
1.1.1.1
```

It is not an IPv6 address.

---

### Trap 5 — `ipv6 unicast-routing`

Remember:

```text
ipv6 unicast-routing
```

enables IPv6 routing globally.

It does **not**, by itself, enable EIGRP on interfaces.

---

### Trap 6 — No `network` command does not mean no interface configuration

IPv6 EIGRP still needs participating interfaces.

The difference is:

```text
IPv4 classic:
network ...

IPv6:
interface-based EIGRP configuration
```

---

### Trap 7 — DUAL is not different

EIGRP for IPv6 still uses:

```text
DUAL
Successor
Feasible Successor
RD
FD
Queries
Replies
RTP
```

The IP version changes; the fundamental EIGRP routing algorithm does not.

---

### Trap 8 — RD vs Administrative Distance

Do not confuse:

```text
RD = Reported Distance
AD = Administrative Distance
```

The EIGRP feasibility condition is:

```text
RD < FD
```

while default administrative distances are:

```text
90  = internal EIGRP
170 = external EIGRP
```

Think of EIGRP for IPv6 as:

```text
IPv6
 │
 ├── Protocol 88
 │
 ├── Multicast FF02::A
 │
 ├── Link-local neighbor communication
 │
 └── EIGRP
      │
      ├── DUAL
      │    ├── Successor
      │    └── Feasible Successor
      │
      ├── RTP
      │
      ├── Composite Metric
      │
      ├── Queries / Replies
      │
      └── Named Mode
           │
           └── address-family ipv6
                ├── router-id
                ├── af-interface
                └── topology base
```

### Core ENCOR formula

> **EIGRP for IPv6 = IPv6 + Protocol 88 + FF02::A + interface-based activation + link-local next hops + 32-bit router ID + the same DUAL/RTP/metric concepts as IPv4.**
