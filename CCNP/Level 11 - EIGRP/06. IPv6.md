# EIGRP for IPv6

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**EIGRP for IPv6** carries IPv6 routes with the **same DUAL logic, RTP, successor/FS, and
metrics** as IPv4 EIGRP. The key difference: it runs **directly over IPv6** and has **no
`network` statements** — interfaces are enabled per-link. On modern IOS, it's configured in
**named mode** as an `address-family ipv6` block inside one process (note 05).

---

## 2. Core Concepts

### 2.1 How EIGRP IPv6 differs

| | EIGRP IPv4 | EIGRP IPv6 |
|--|-----------|-----------|
| Transport | IPv4, protocol 88 | IPv6, protocol 88 |
| Multicast | 224.0.0.10 | **FF02::A** |
| Route announcement | `network` statements | **interface-based** (`ipv6 eigrp AS`) |
| Link-local neighbors | not used for RIB | **link-local** used as next hops |
| Config | classic or named | named AF ipv6 |

- EIGRP IPv6 uses the **link-local address** of the neighbor as the next hop (global
  addresses not needed on the segment).

### 2.2 Requirements (the gotcha list)

1. **`ipv6 unicast-routing`** must be enabled globally.
2. Router needs an **IPv6 link-local** on the segment (auto-created).
3. Process needs a **router-id** (32-bit, like OSPF) — or it won't start without IPv4.
4. Interfaces enabled **per-interface**, no network statements.

### 2.3 Configuration (named mode preferred)

```text
ipv6 unicast-routing

router eigrp CAMPUS
 address-family ipv6 unicast autonomous-system 100
  router-id 1.1.1.1
  exit-address-family

interface Gi0/1
 address-family ipv6
  eigrp-instance 100          ! (IOS-XE named syntax)
  no shutdown
 exit-address-family
```

- Older IOS: `ipv6 router eigrp 100` + `ipv6 eigrp 100` on interfaces.

### 2.4 Successor/FS and metrics — identical

- Same DUAL, same feasibility condition (`AD < FD`), same composite metric (BW+delay).
- `show ipv6 eigrp topology` mirrors the IPv4 view.

### 2.5 Route summarization & stub work the same

- `summary-address` per interface under AF.
- Stub config identical (note 07) — useful to bound query propagation in IPv6 too.

## 3. Configuration / Commands

```text
ipv6 unicast-routing
interface Gi0/1
 ipv6 eigrp 100                 ! classic per-interface enable

show ipv6 eigrp neighbors
show ipv6 eigrp topology
show ipv6 route eigrp
show eigrp address-family ipv6 neighbors
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No neighbors | `ipv6 unicast-routing` off | enable globally |
| Process won't start | missing router-id | set `router-id` |
| No routes | interface not enabled for EIGRP | `ipv6 eigrp AS` per interface |
| Link-local next hops odd | expected — normal for IPv6 | note neighbor list uses link-local |
| Split protocol mismatch | classic vs named | align both ends |

## 5. Exam Traps

- **Multicast FF02::A** for EIGRP IPv6 (vs 224.0.0.10).
- **No network statements** — enable per-interface.
- **Link-local used as next hop** — the "why are next hops fe80::?" question.
- **`ipv6 unicast-routing` required.**
- **Router-id still needed** even with no IPv4.
- Same DUAL/FS/metric logic as IPv4.
