# EIGRP Variance (Unequal-Cost Load Balancing)

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**`variance`** allows EIGRP to use **multiple paths of unequal metric** for the same
destination — enabling **unequal-cost load balancing**, which OSPF and RIP cannot do.
Only routes that pass **both** the variance check **and** the **feasibility condition**
(AD < FD) become load-balanced. Default `variance 1` means equal-cost only (ECMP).

---

## 2. Core Concepts

### 2.1 The variance rule

```
A route is included iff:   metric(path)  <=  variance x metric(successor)
                          AND  AD(path) < FD(successor)   (loop-free)
```

- **variance = 1** → only equal-cost paths (ECMP).
- **variance = n** → any path up to n times the successor's metric is eligible.
- The second condition (feasibility) is **still mandatory** — variance does not bypass
  loop-freedom.

### 2.2 Worked example

```
Successor  A: FD = 100
Candidate  B: FD = 150, AD = 60
Candidate  C: FD = 300, AD = 120

variance 2:  eligible if FD <= 200
  B: 150 <= 200  and AD 60 < 100  ✓  → load-balances
  C: 300 > 200   ✗                   → excluded
```

- Only B qualifies — C fails the variance bound (and would fail condition too).

### 2.3 Effect on routing table

- All qualifying paths appear as **multiple next hops** in the RIB for the prefix.
- **Traffic is split proportionally to the metrics** (inverse ratio), not evenly —
  EIGRP balances across unequal links by weight.

### 2.4 Interaction with FS (the exam nuance)

| Path type | Usable? | Reason |
|-----------|---------|--------|
| Successor | yes | always |
| FS within variance | yes | loop-free + within bound |
| FS beyond variance | no | metric too high |
| Non-FS (AD ≥ FD) | **never** | would loop — even with high variance |

- Variance **cannot** make a non-FS path usable. That's the loop-free guarantee.

### 2.5 Config

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   variance 2
   maximum-paths 4
```

- `maximum-paths` caps how many paths are installed (default 4).
- Tune only after verifying FS status in the topology table.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Unequal paths not used | not FS (AD ≥ FD) | feasibility condition |
| Only one path in RIB | variance too low | raise variance |
| Too many paths | variance/max-paths mis-set | check `maximum-paths` |
| Traffic distribution uneven | proportional weighting | expected — inverse metric |
| Flap after variance change | metric re-eval | verify FS again |

---

## 5. Exam Traps

- **Variance is EIGRP-only** unequal-cost load balancing (OSPF/RIP can't).
- **Feasibility condition still applies** — non-FS never loads even with huge variance.
- **variance 1 = ECMP only** (the default).
- Load balance is **proportional to metric** (inverse), not even.
- `maximum-paths` caps the count.
- Config location: **`topology base`** in named mode.
