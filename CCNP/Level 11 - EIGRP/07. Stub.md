# EIGRP Stub

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

An **EIGRP stub router** is an EIGRP router configured to advertise only selected types of routes and to limit how EIGRP queries propagate through the network.

It is primarily designed for **branch, spoke, and remote-site routers** that should not be treated as transit paths for other destinations.

The main benefits are:

- **Limits EIGRP query scope**
    
- Reduces unnecessary query propagation
    
- Helps prevent **Stuck-in-Active (SIA)** conditions
    
- Improves convergence scalability
    
- Clearly identifies an edge router's routing role to its EIGRP neighbors
    

A typical design is:

```text
                 HUB
                /   \
               /     \
       [EIGRP stub] [EIGRP stub]
          SPOKE A       SPOKE B
```

The hub can use the spokes as sources of their advertised routes, but the spokes are not intended to provide transit routing for the rest of the topology.

---

## 2. What EIGRP Stub Does

An EIGRP stub controls **what routes the router advertises to its EIGRP neighbors**.

The available stub options determine which route categories can be advertised.

|Option|Purpose|
|---|---|
|`connected`|Advertise connected routes|
|`static`|Advertise static routes|
|`summary`|Advertise summary routes|
|`redistributed`|Advertise redistributed routes|
|`receive-only`|Receive EIGRP routes but advertise no EIGRP routes|
|`leak-map`|Permit selected routes to be advertised from a stub under specific configurations|

The exact available options depend on IOS/IOS XE version and EIGRP configuration mode.

---

## 3. Default Stub Behavior

When configured simply as:

```text
eigrp stub
```

the default behavior is equivalent to:

```text
eigrp stub connected summary
```

Therefore, the default stub advertises:

- Connected routes
    
- Summary routes
    

It does **not** automatically advertise all routes learned through EIGRP.

### Exam memory

```text
eigrp stub
        ↓
connected + summary
```

---

## 4. Stub Options

### 4.1 `connected`

Advertises connected routes.

Example:

```text
eigrp stub connected
```

This is useful when the router needs to advertise its directly connected networks to the hub.

---

### 4.2 `static`

Advertises static routes.

Example:

```text
eigrp stub static
```

Useful when a branch router has static routes that need to be advertised through EIGRP.

---

### 4.3 `summary`

Advertises summary routes.

Example:

```text
eigrp stub summary
```

This is useful when the router is advertising summarized prefixes.

A summary route can include a default route when a default summary route is actually configured.

---

### 4.4 `redistributed`

Allows redistributed routes to be advertised by the stub.

Example:

```text
eigrp stub connected static redistributed
```

This is useful when the branch router has routes learned from another routing source and those routes are intentionally redistributed into EIGRP.

---

### 4.5 `receive-only`

`receive-only` is a special mode.

```text
eigrp stub receive-only
```

The router:

- Can receive EIGRP routes
    
- Does not advertise EIGRP routes
    

This is useful when a router should participate in receiving EIGRP information but should not advertise routes back to its neighbors.

### Exam memory

```text
receive-only
      ↓
receive routes
      ↓
advertise nothing
```

---

## 5. How Stub Limits Queries

One of the most important purposes of EIGRP stub is **query containment**.

Consider:

```text
                HUB
               /   \
              /     \
           STUB A   STUB B
```

Suppose the hub loses a route and has no feasible successor.

Without an appropriate stub design, EIGRP may need to query neighboring routers to find an alternate path.

If queries propagate through many routers, the active computation can spread across a large part of the topology.

With a stub router, EIGRP knows that the stub is an edge router and has a limited set of advertised routes.

Therefore, the hub does not need to use the stub as a source of alternate paths for destinations the stub cannot advertise.

This **bounds the query domain**.

---

## 6. Stub and Stuck-in-Active (SIA)

### Without appropriate query containment

```text
Route failure
     ↓
No feasible successor
     ↓
Router goes Active
     ↓
Queries neighbors
     ↓
Queries propagate
     ↓
Slow / unreachable neighbor
     ↓
Query remains unanswered
     ↓
SIA risk
```

### With an EIGRP stub design

```text
Route failure
     ↓
No feasible successor
     ↓
Query scope is limited
     ↓
Edge router is not treated as a transit
     ↓
Less query propagation
     ↓
Faster, more predictable convergence
```

### Important distinction

> **EIGRP stub does not magically eliminate every possible SIA condition.**

Its purpose is to **limit query propagation and reduce the scope of active computations**, which significantly improves scalability and reduces SIA risk.

## 7. Hub-and-Spoke Design

A common EIGRP stub design is:

```text
                    HUB
                 /   |   \
                /    |    \
               /     |     \
          SPOKE A  SPOKE B  SPOKE C
           STUB      STUB      STUB
```

The spokes advertise their own permitted routes.

For example:

```text
SPOKE A
 ├── Connected LANs
 └── Static branch routes

SPOKE B
 ├── Connected LANs
 └── Static branch routes

SPOKE C
 ├── Connected LANs
 └── Static branch routes
```

The hub learns those routes from the spokes.

However, the spokes are not intended to advertise routes learned from the hub back as transit routes.

---

## 8. Stub Does Not Mean "Advertise Nothing"

A common mistake is:

> "EIGRP stub means the router doesn't advertise routes."

That is **false**.

A normal stub can advertise routes according to its configured options.

For example:

```text
eigrp stub connected static
```

means:

```text
Advertise:
    connected routes
    static routes

Do not advertise:
    ordinary EIGRP-learned routes
```

The special exception is:

```text
eigrp stub receive-only
```

which advertises no EIGRP routes.

---

## 9. Named-Mode Configuration

In named EIGRP, stub configuration is performed under:

```text
address-family
    ↓
topology base
    ↓
eigrp stub
```

Example:

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   eigrp stub connected static
  exit-af-topology
 exit-address-family
```

This configures the router to advertise:

- Connected routes
    
- Static routes
    

as EIGRP stub routes.

---

## 10. Classic-Mode Configuration

In classic EIGRP:

```text
router eigrp 100
 eigrp stub connected static
```

The command is configured under the EIGRP router configuration.

## 13. Important Behavior

### The stub still learns routes

A stub router can receive routes from its EIGRP neighbors.

For example:

```text
             HUB
              │
              │ routes
              ↓
          EIGRP STUB
```

The stub can learn:

```text
10.0.0.0/8
172.16.0.0/16
192.168.0.0/16
```

from the hub.

It simply does not advertise those learned EIGRP routes as transit routes according to its stub configuration.

---

## 14. Stub and Transit Routing

A stub router is intended to be an **edge router**, not a transit router.

Example:

```text
                HUB
               /   \
              /     \
         STUB A     STUB B
```

Traffic should normally follow:

```text
STUB A → HUB → STUB B
```

rather than:

```text
STUB A → STUB B
```

because the spokes are not supposed to advertise themselves as paths to the rest of the EIGRP topology.

### Important wording

Do not memorize:

> "Stub blocks all transit traffic."

Instead memorize:

> **Stub controls EIGRP route advertisement and query propagation so the router is not treated as a transit source for routes it should not provide.**

## 16. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Spoke advertises no expected routes|Incorrect stub options|Check `eigrp stub` options|
|Connected routes missing|`connected` not enabled|Add `connected`|
|Static routes missing|`static` not enabled|Add `static`|
|Redistributed routes missing|`redistributed` not enabled|Add `redistributed`|
|Stub advertises nothing|`receive-only` configured|Remove/change `receive-only`|
|Hub cannot use spoke for alternate routes|Expected stub behavior|Verify the spoke's role|
|Queries propagate farther than expected|Edge router not configured as stub|Configure EIGRP stub|
|SIA still occurs|Other query/convergence problem|Investigate the entire EIGRP topology|

## 17. Exam Traps

### Trap 1 — Default stub options

```text
eigrp stub
```

means:

```text
connected + summary
```

not "advertise nothing."

---

### Trap 2 — `receive-only`

```text
eigrp stub receive-only
```

means:

```text
Receive EIGRP routes
Advertise no EIGRP routes
```

---

### Trap 3 — Stub is for edge routers

Typical placement:

```text
Branch
Spoke
Remote office
Stub LAN
```

Avoid configuring it on a router that is intentionally a major transit point in the EIGRP topology.

---

### Trap 4 — Stub is about query containment

The primary design benefit is:

> **Limit EIGRP query propagation.**

This reduces the size of active computations and helps reduce SIA risk.

---

### Trap 5 — Stub does not mean "cannot learn routes"

A stub can learn routes from its EIGRP neighbors.

It controls what **it advertises**, not whether it can receive EIGRP routes.

---

### Trap 6 — Stub does not guarantee no SIA

Stub configuration reduces query scope, but SIA can still result from other failures elsewhere in the topology.

---

### Trap 7 — Route advertisement is controlled by options

Remember:

```text
connected
static
summary
redistributed
receive-only
```

The configured options determine what the stub advertises.
