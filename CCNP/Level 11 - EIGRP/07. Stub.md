# EIGRP Stub

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

An **EIGRP stub** router advertises that it has **no transit routes** — it will never be
used as a transit hop and (with the default) **replies to queries with "unreachable"**
instead of forwarding them. This **stops query propagation** at the edge, preventing
**Stuck-in-Active (SIA)** storms and speeding convergence. Stub is a branch/remote-office
feature — never on core/transit routers.

---

## 2. Core Concepts

### 2.1 What stub does

| Behavior | Default stub | Stub receiving |
|----------|-------------|----------------|
| Advertise local routes | connected + summary | neighbors know "don't transit here" |
| Forward queries | **replies "unreachable"** | query stops at stub |
| Allow transit | **no** | — |
| Routes advertised | by `stub` options | connected/summary/static/receive-only |

- The stub **advertises only what it owns** (and by default sends a **default route** if
  `stub` with default options... actually default includes a summary default only with
  specific flags) — keep to the options table below.

### 2.2 Stub options (the memorized table)

| Option | Effect |
|--------|--------|
| **connected** | advertise connected routes |
| **static** | advertise statics |
| **summary** | advertise summary routes (incl. default if set) |
| **receive-only** | receive routes, advertise nothing |
| (no keyword) | advertise connected + summary |

- Default stub advertises **connected + summary**.
- A remote site router should typically use `stub connected static` etc. to announce its
  edge networks.

### 2.3 Why stub prevents SIA

- In a normal EIGRP network, a failed successor with no FS triggers queries that **flood
  the whole topology**. Slow/one-way links → queries hang → **Stuck-in-Active**.
- A stub **never forwards queries** — the query stops there and a reply returns fast.
- This **bounds query scope** and is the primary convergence design tool for hubs.

### 2.4 Hub-and-spoke design

```
[HUB] ──── [spoke A (stub)]
       ──── [spoke B (stub)]
```

- Spokes run `eigrp stub`; hubs don't. Spokes learn routes via hub; hub never transits
  through a spoke.
- Stub also prevents the "spoke used as transit" blackhole that caused loops in classic
  WAN topologies.

### 2.5 Config & verification

```text
router eigrp CAMPUS
 address-family ipv4
  topology base
   eigrp stub connected static
```

- Per-topology config; `eigrp stub` under `topology base` in named mode.

## 3. Configuration / Commands

```text
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   eigrp stub connected static
  exit-address-family

show ip eigrp neighbors detail        ! shows "Stub Peer"
show eigrp address-family ipv4 topology base stub
show ip eigrp topology
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Spoke not learning routes | stub `receive-only` / no neighbor | verify stub flags |
| Hub queries SIA | hub not stub-aware / spoke missing stub | enable stub on spokes |
| Spoke advertised nothing | wrong stub keywords | add connected/static |
| Transit via spoke | stub not configured on spoke | `eigrp stub` on the spoke |

---

## 5. Exam Traps

- **Stub stops query propagation** — that's its main purpose (prevents SIA).
- **Configure on edge/spokes, never on transit routers.**
- Default stub advertises **connected + summary**.
- `receive-only` = learn but advertise nothing.
- Stub does **not** block the hub learning the spoke's routes — it blocks transit/query flow.
