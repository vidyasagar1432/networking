# EIGRP Authentication

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

EIGRP authentication validates the **source of routing updates** so a rogue router can't
inject routes. EIGRP (like OSPFv2) supports **plaintext** and **MD5 / HMAC-SHA256**
message-digest authentication. Modern named mode adds **HMAC-SHA-256** with **key chains**
— the secure default on exam answers. Mismatched auth → neighbors never form.

---

## 2. Core Concepts

### 2.1 Authentication methods

| Method | Security | Uses |
|--------|----------|------|
| None | none | default |
| Plaintext (key) | weak — sent in clear | legacy, avoids misconfig |
| MD5 | moderate | older classic EIGRP |
| **HMAC-SHA-256** | strong | modern named mode / key chain |

- **Key chain** with HMAC-SHA256 is the correct modern answer.

### 2.2 Classic mode (MD5, per-interface)

```text
key chain EIGRP-KEYS
 key 1
  key-string SecretKey123
  accept-lifetime infinite
  send-lifetime infinite

interface Gi0/1
 ip authentication mode eigrp 100 md5
 ip authentication key-chain eigrp 100 EIGRP-KEYS
```

- Classic uses `ip authentication mode/key-chain eigrp <AS>` on each interface.

### 2.3 Named mode (HMAC-SHA-256)

```text
key chain EIGRP-KEYS
 key 1
  key-string SecretKey123
  cryptographic-algorithm hmac-sha-256

router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  network 10.0.0.0 0.0.255.255
  af-interface default
   authentication mode hmac-sha-256
   authentication key-chain EIGRP-KEYS
  exit-af-interface
```

- `af-interface default` applies auth to **all** EIGRP interfaces at once.

### 2.4 Key chains & rotation

| Feature | Purpose |
|---------|---------|
| key ID | identifies which key |
| send-lifetime | when this key is active for sending |
| accept-lifetime | when this key is accepted for receiving |
| crypto algorithm | MD5 or HMAC-SHA-256 |

- Rotation: overlap send/accept lifetimes of old and new keys → seamless changeover.

### 2.5 Failure behavior

- Auth mismatch → hellos dropped → neighbor **never forms** (stuck in Down/Init-like
  silence for EIGRP).
- Watch `show ip eigrp neighbors` — absence of the neighbor + `show ip eigrp interfaces`
  shows authentication.

## 3. Configuration / Commands

```text
show key chain
show ip eigrp interfaces detail        ! shows auth mode + key chain
show ip eigrp neighbors
debug eigrp packets                    ! "auth fail" logs
```

---

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Neighbors never form | auth mode/key mismatch | `show ip eigrp interfaces detail` |
| Auth fails silently | key string or algorithm mismatch | `show key chain` compare |
| Flap on rotation | lifetime gap (no active key) | overlap lifetimes |
| Classic vs named mismatch | both ends must use same method | align mode |

---

## 5. Exam Traps

- **HMAC-SHA-256 via key chain** is the modern named-mode answer.
- **`af-interface default`** applies to all interfaces in the AF.
- Key rotation needs **overlapping lifetimes**.
- Auth mismatch → neighbors **do not form** (no adjacency, no routes).
- EIGRP auth is per **interface / AF**, not per area (no OSPF-area concept).
