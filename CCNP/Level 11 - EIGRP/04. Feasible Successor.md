# EIGRP Feasible Successor

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **feasible successor (FS)** is a **loop-free backup path** DUAL keeps in the topology
table. When the successor fails, the FS is **promoted instantly** with **no queries and no
recomputation** — the reason EIGRP converges so fast. An FS exists only if it satisfies the
**feasibility condition**: its advertised distance is **strictly less than** the current
successor's feasible distance.

---

## 2. Core Concepts

### 2.1 The feasibility condition (the single formula)

```
A neighbor is a feasible successor iff:   AD(neighbor)  <  FD(successor)

AD = advertised (reported) distance — the metric the neighbor claims for the destination
FD = feasible distance — OUR best metric to the destination
```

- **Strict inequality** — `AD == FD` does NOT qualify (would allow a loop).
- This rule guarantees the FS path cannot circle back through us.

### 2.2 Why the condition prevents loops

If a neighbor's path went through *us*, its AD would be ≥ our FD (it'd include our link
back to itself). Requiring AD < FD excludes exactly those "backwards" candidates — every
FS path is provably away from us.

### 2.3 Worked example (exam staple)

```
Destination 10.1.1.0/24
Neighbor  A: AD=10, local cost=10  → FD = 20  (SUCCESSOR, lowest)
Neighbor  B: AD=15, local cost=10  → FD = 25
Neighbor  C: AD=18, local cost=10  → FD = 28

FS check (AD < FD_successor = 20):
  B: 15 < 20 ✓  → FEASIBLE SUCCESSOR
  C: 18 < 20 ✓  → FEASIBLE SUCCESSOR
```

- Both B and C qualify — they're loop-free backups kept in the topology table.

### 2.4 What FS appears in (and what it doesn't)

| Table | FS present? |
|-------|-------------|
| Topology table | **yes** (shown as secondaries) |
| Routing table | **no** — only successor(s) |
| Neighbor table | neighbor is adjacent, independent |

- `show ip eigrp topology` shows FS paths after the successor line.

### 2.5 FS and failure behavior

- Successor fails → FS promoted to successor (local recompute, near-instant).
- No FS at all → **Active** state, diffusing computation (queries) — slower (note 01).
- **Variance** (note 09) can make non-FS paths usable for unequal load balancing — but the
  loop-free requirement still applies via the feasibility condition.


## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No FS, slow failover | AD ≥ FD for all backups | improve metrics / add links |
| FS never promoted | condition not met (metric drift) | `show ip eigrp topology` |
| Query storm | no FS anywhere | add redundant loop-free paths |
| Unexpected Active | FS lost via topology change | verify FS condition holds |

---

## 5. Exam Traps

- **Condition is AD < FD (strict)** — equal fails, the classic trick.
- **FS in topology table only** — not in the routing table.
- **AD is the neighbor's claim; FD is our best metric** — don't mix.
- **No FS → Active/queries** — slow convergence signal.
- **All FS paths are loop-free by construction.**
- `all-links` shows the candidates that failed the condition — a great study view.
