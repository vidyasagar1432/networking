# EIGRP Feasible Successor

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **Feasible Successor (FS)** is an EIGRP backup path that satisfies DUAL's  
**feasibility condition** and is therefore considered **loop-free**.

A feasible successor is kept in the **EIGRP topology table** but is not normally  
installed in the routing table while the current successor is available.

If the successor fails and a valid FS exists, EIGRP can promote the FS without  
performing a **diffusing computation or sending queries** for that destination.  
This is a major reason EIGRP can converge quickly.

The key rule is:

```text
RD < FD
```

where:

```text
RD = Reported Distance (also commonly called Advertised Distance)
FD = Feasible Distance of the current successor
```

---

## 2. Core Concepts

### 2.1 Reported Distance (RD)

**Reported Distance (RD)** is the metric that a neighboring EIGRP router reports  
for reaching a destination.

It is also commonly called:

**Advertised Distance (AD)**

Example:

```text
Neighbor B reports:

RD = 15
```

This means B is telling our router that its metric toward the destination is 15.

---

### 2.2 Feasible Distance (FD)

**Feasible Distance (FD)** is the local router's total EIGRP metric for the  
selected successor path.

Conceptually:

```text
FD = local cost to neighbor + neighbor's RD
```

Example:

```text
Local cost to B = 10
B's RD          = 15

Total metric    = 25
```

The current successor's total metric is the relevant FD used by the feasibility  
condition.

---

## 3. The Feasibility Condition

The fundamental DUAL rule is:

```text
RD(neighbor) < FD(current successor)
```

If the condition is true, the neighbor's path can qualify as a **Feasible  
Successor**.

### Results

```text
RD < FD  → qualifies as FS
RD = FD  → does NOT qualify
RD > FD  → does NOT qualify
```

### Memorize

> **Strictly less than. Equal does not qualify.**

---

## 4. Why the Feasibility Condition Matters

The feasibility condition provides DUAL with a **loop-free condition** for selecting  
a backup path.

The important exam rule is not:

```text
"Second-best metric = FS"
```

Instead:

```text
Neighbor's RD < Current successor's FD
```

A path can have a **higher total metric than the successor** and still be a valid  
feasible successor.

---

## 5. Worked Example

Destination:

```text
10.1.1.0/24
```

Assume:

```text
Neighbor A:
    RD = 10
    Local cost = 10
    Total metric = 20

Neighbor B:
    RD = 15
    Local cost = 10
    Total metric = 25

Neighbor C:
    RD = 18
    Local cost = 10
    Total metric = 28
```

### Step 1 — Select the successor

The lowest total metric is:

```text
A = 20
```

Therefore:

```text
Successor = A
FD = 20
```

### Step 2 — Test B

```text
RD(B) = 15
FD    = 20

15 < 20 → TRUE
```

Therefore:

```text
B = Feasible Successor
```

### Step 3 — Test C

```text
RD(C) = 18
FD    = 20

18 < 20 → TRUE
```

Therefore:

```text
C = Feasible Successor
```

### Final Result

```text
Successor:
    A
    FD = 20

Feasible Successors:
    B
    C
```

Even though:

```text
B total metric = 25
C total metric = 28
```

both are valid FS paths because their **RD values are less than the successor's  
FD of 20**.

---

## 6. Equal RD and FD — Classic Exam Trap

Suppose:

```text
Current successor FD = 20

Neighbor B:
    RD = 20
```

Check:

```text
20 < 20 → FALSE
```

Therefore:

```text
B is NOT a Feasible Successor
```

The condition is:

```text
RD < FD
```

not:

```text
RD <= FD
```

### Memorize

```text
15 < 20  ✓
19 < 20  ✓
20 < 20  ✗
21 < 20  ✗
```

---

## 7. Feasible Successor vs Successor

|Feature|Successor|Feasible Successor|
|---|---|---|
|Role|Best path|Loop-free backup|
|Selection|Best eligible total metric|`RD < FD`|
|Routing table|Installed|Not installed while only an FS|
|Topology table|Yes|Yes|
|Used for forwarding|Yes|No, while backup|
|Used after successor failure|Already active|Can become successor|
|Queries when successor fails|—|Not required if valid FS exists|

### Memory

```text
Successor = Best Path
FS        = Qualified Backup
```

---

## 8. What Happens When the Successor Fails?

### Case 1 — FS Exists

```text
Successor fails
       ↓
Valid FS exists
       ↓
DUAL processes the topology change
       ↓
FS becomes successor
       ↓
Route is installed
```

The important point is:

```text
No diffusing computation
No EIGRP query process
```

for that destination.

This provides fast convergence.

---

### Case 2 — No FS Exists

```text
Successor fails
       ↓
No FS available
       ↓
Route becomes Active
       ↓
EIGRP sends Queries
       ↓
Neighbors process Queries
       ↓
Neighbors send Replies
       ↓
DUAL performs diffusing computation
       ↓
New path is selected
```

This process is generally slower than promoting an existing FS.

---

## 9. Where Is the Feasible Successor Stored?

EIGRP maintains candidate paths in its **topology table**.

Conceptually:

```text
EIGRP Topology Table
│
├── Successor
├── Feasible Successor
└── Other candidate paths
```

The routing table normally contains only the currently selected successor path(s).

```text
Topology Table
      │
      ├── Successor ─────────→ Routing Table
      │
      ├── Feasible Successor
      │
      └── Other candidates
```

If the successor fails and the FS remains valid:

```text
FS
 ↓
Successor
 ↓
Routing Table
```

## 10. Feasible Successor and Unequal-Cost Load Balancing

EIGRP can perform **unequal-cost load balancing** using the `variance`  
configuration.

However, `variance` does **not** remove DUAL's loop-free requirement.

A path must still satisfy the appropriate feasibility requirements before it can be  
used as a valid EIGRP path for unequal-cost load balancing.

Conceptually:

```text
Feasibility condition
        ↓
Path is eligible
        ↓
Variance determines whether
its metric is acceptable
        ↓
Path may participate in load balancing
```

Do not memorize:

```text
variance = bypasses feasibility condition
```

That is incorrect.

---

## 11. Multiple Feasible Successors

A destination can have more than one feasible successor.

Example:

```text
Successor:
    A
    FD = 20

Feasible Successors:
    B → RD = 15
    C → RD = 18
```

Both B and C satisfy:

```text
RD < 20
```

Therefore both qualify as feasible successors.

If A fails, DUAL can select an appropriate qualifying path as the new successor.

---

## 12. Feasible Successor Is Not Automatically the Second-Best Path

Consider:

```text
Path A:
    Total metric = 20
    RD = 10

Path B:
    Total metric = 25
    RD = 22

Path C:
    Total metric = 30
    RD = 15
```

Successor:

```text
A
FD = 20
```

Check B:

```text
22 < 20 → FALSE
```

B is **not** an FS.

Check C:

```text
15 < 20 → TRUE
```

C **is** an FS.

Therefore:

```text
Successor = A
FS         = C
B          = Not FS
```

This is a very important exam concept:

> **The path with the second-lowest total metric is not necessarily a feasible  
> successor.**

## 13. Feasible Successor Decision Process

```text
              EIGRP learns paths
                      |
                      v
             Calculate total metrics
                      |
                      v
             Select best eligible path
                      |
                      v
                 Successor
                      |
                      v
                    FD
                      |
                      v
           Evaluate other paths
                      |
                      v
                 RD < FD ?
                /        \
              YES         NO
               |           |
               v           v
              FS       Not an FS
```

## 14. Troubleshooting

### No Feasible Successor

Possible causes:

- No alternate path exists
    
- Alternate paths do not satisfy `RD < FD`
    
- Topology changed
    
- Metrics changed
    
- Neighbor/path disappeared
    

Check:

```text
show ip eigrp topology
show ip eigrp neighbors
```

---

### Feasible Successor Disappeared

A previously valid FS can stop qualifying if the EIGRP topology or metrics change.

Check:

```text
show ip eigrp topology
show ip eigrp topology all-links
```

The exact availability/output of `all-links` can vary by IOS/platform.

---

### Successor Fails but No Fast Failover

Check whether an FS exists:

```text
show ip eigrp topology
```

If no FS exists:

```text
No FS
  ↓
Active
  ↓
Queries
```

Investigate active routes:

```text
show ip eigrp topology active
```

## 16. Exam Traps

### Trap 1 — Strict Inequality

```text
RD < FD
```

is the rule.

```text
RD = FD
```

does not qualify.

---

### Trap 2 — FS Is Not the Second-Best Path

A path can have the second-lowest total metric but still fail the feasibility  
condition.

Always check:

```text
RD < FD
```

---

### Trap 3 — FS Can Have a Higher Total Metric

Example:

```text
Successor:
    FD = 20

FS:
    Total metric = 30
    RD = 15
```

This can still be a valid FS because:

```text
15 < 20
```

The FS does **not** need to have a lower total metric than the successor.

---

### Trap 4 — RD/AD vs FD

Do not swap these terms.

```text
RD / AD = Neighbor's reported metric
FD      = Our total metric for the selected successor path
```

---

### Trap 5 — No FS Does Not Automatically Mean SIA

No FS means DUAL may need to perform a diffusing computation.

```text
No FS
  ↓
Active
  ↓
Queries
```

**SIA** occurs only when the required query/reply process does not complete as  
expected.

---

### Trap 6 — FS Does Not Mean It Is Forwarding Traffic

A normal FS is a backup in the topology table.

```text
Successor → forwarding
FS        → backup
```

---

### Trap 7 — Variance Does Not Disable Loop Prevention

`variance` allows EIGRP to consider qualifying paths for unequal-cost load  
balancing; it does not simply make arbitrary paths usable.

## 17. Successor, FS, DUAL, and RTP

Keep these concepts separate:

|Concept|Main Function|
|---|---|
|**Successor**|Best EIGRP path|
|**Feasible Successor**|Loop-free backup path|
|**DUAL**|Computes/selects loop-free paths and convergence behavior|
|**RTP**|Provides EIGRP-specific reliable packet delivery|
|**Topology Table**|Stores EIGRP path information|
|**Routing Table**|Contains installed routes|

### Memory Trick

```text
Successor = Best
FS        = Backup
DUAL      = Decides
RTP       = Delivers
```
