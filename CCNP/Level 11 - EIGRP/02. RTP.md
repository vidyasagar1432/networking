# EIGRP RTP (Reliable Transport Protocol)

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**RTP (Reliable Transport Protocol)** is EIGRP's own transport layer. It provides
**reliable delivery** of DUAL updates/queries/replies (with acknowledgements and
retransmission) and **unreliable delivery** for hellos. RTP runs directly over **IP,
protocol number 88**, using **multicast 224.0.0.10** for discovery — no TCP/UDP, no port.

---

## 2. Core Concepts

### 2.1 Packet types (the memorized table)

| Packet | Reliable? | Purpose |
|--------|-----------|---------|
| **Hello** | no (unreliable) | neighbor discovery + keepalive |
| **Update** | yes | route topology changes |
| **Query** | yes | DUAL diffusing computation |
| **Reply** | yes | answer to a query |
| **ACK** | no | confirm a reliable packet |

- **Hello/Ack** are lightweight and multicast; **Update/Query/Reply** are reliable and
  unicast or multicast depending on recipient count.

### 2.2 Reliable delivery mechanics

- Each reliable packet carries a **sequence number**.
- Receiver sends an **ACK**; sender retransmits on **RTO** (Retransmission Timeout) if no
  ACK.
- Delivery is **ordered** and **guaranteed** — DUAL can trust that queries/replies arrive.

### 2.3 Hello & neighbor timing

| Timer | Default | Purpose |
|-------|---------|---------|
| Hello | 5 s (broadcast/P2P), 60 s (NBMA) | discovery |
| Hold | 15 s (3x hello), 180 s (NBMA) | dead neighbor detection |

- Miss hold timer → neighbor removed → DUAL recomputes.
- **Hello must match?** — Unlike OSPF, EIGRP hellos do **not** need equal timers; the hold
  timer is what matters (it's per-neighbor advertised). This is a classic exam trap vs OSPF.

### 2.4 Multicast group & transport facts

```
IP protocol 88 (EIGRP)
Multicast 224.0.0.10  (all EIGRP routers)
Unicast for reliable retransmissions to specific neighbors
```

- EIGRP uses **protocol number 88** — no well-known TCP/UDP port.

### 2.5 Passive vs Active (DUAL interplay)

| State | Meaning |
|-------|---------|
| **Passive** | stable — successor + FS computed, no queries outstanding |
| **Active** | diffusing computation running — queries sent, replies awaited |

- RTP delivers the queries/replies that push DUAL between these states (note 01).

```text
show ip eigrp neighbors          ! hold time, RTO, SRTT, uptime

show ip eigrp interfaces
debug eigrp packets              ! watch RTP activity
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Neighbors flapping | hold time too low / packet loss | `show ip eigrp neighbors` hold |
| Retransmit storm | RTO too low / congested link | tune RTO/SRTT |
| Queries unanswered | RTP reliability broken / one-way | `debug eigrp packets` |
| No neighbors | multicast blocked / protocol 88 denied | `show ip eigrp neighbors` |
| SIA | query stuck (RTP delivery fail) | note 11 |

---

## 5. Exam Traps

- **EIGRP hello ≠ OSPF hello**: EIGRP does NOT require matching hello/hold timers — only
  the receiving hold timer matters.
- **Protocol 88, multicast 224.0.0.10** — no port.
- **Hello/Ack unreliable; Update/Query/Reply reliable.**
- Hold default **15 s** (3 x 5 s hello) on LAN, **180 s** (3 x 60 s) on NBMA.
- EIGRP neighbors can form with **different K-values? No** — K-values must match, but hello
  timers need not.
