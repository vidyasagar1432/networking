# EIGRP Troubleshooting

> **Level 11 · EIGRP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**EIGRP troubleshooting** follows a layered approach:

**Interface → Neighbor → Topology → RIB → Forwarding**

The main problem areas are **neighbor formation**, **DUAL state**, **successor/feasible-successor selection**, **metrics**, **filtering**, and **forwarding**.

---

## 2. Troubleshooting Flow

|Step|Question|Command|
|---|---|---|
|1. Interface|Is the interface operational?|`show ip interface brief`|
|2. Neighbor|Is an EIGRP adjacency established?|`show ip eigrp neighbors`|
|3. Topology|Are routes and feasible successors present?|`show ip eigrp topology`|
|4. Routes|Is the route installed in the RIB?|`show ip route eigrp`|
|5. Forwarding|Can the router forward traffic?|`show ip cef` / `ping` / `traceroute`|

**Exam approach:** Do not start with routing tables if the neighbor relationship is missing. Troubleshoot from the lower layer upward.

---

## 3. Neighbor Formation

### 3.1 Common Neighbor Problems

|Symptom|Likely Cause|Check|
|---|---|---|
|No neighbor|AS mismatch|EIGRP configuration on both routers|
|No neighbor|EIGRP packets blocked|ACL / CoPP / interface filtering|
|No neighbor|Authentication mismatch|Key chain / authentication configuration|
|No neighbor|Passive interface|`show running-config`|
|No adjacency|K-value mismatch|EIGRP K-values on both routers|
|Neighbor flapping|Packet loss / unstable link|Interface counters, logs, neighbor uptime|
|Authentication failure|Key/algorithm mismatch|Authentication configuration|

### 3.2 Important Facts

- **EIGRP AS numbers must match** for classic EIGRP neighbors.
    
- **K-values must match** for adjacency formation.
    
- **Hello and hold timers do not have to match** between EIGRP neighbors.
    
- EIGRP uses **224.0.0.10** for IPv4 multicast.
    
- `passive-interface` prevents EIGRP hellos from being sent on that interface, so a neighbor cannot normally form there.
    
- Authentication must be compatible on both sides.
    

> **Exam trap:** EIGRP does **not** require matching hello timers in the same way OSPF requires matching hello/dead intervals.

## 4. SIA — Stuck in Active

A route enters **Active** when DUAL is searching for a new path after the current successor is lost and no suitable feasible successor is available.

**SIA (Stuck in Active)** occurs when the router does not receive the required response to its query within the EIGRP active-timeout process.

### Common Causes

- Unidirectional or unreliable connectivity
    
- Packet loss
    
- Congestion
    
- Neighbor failure
    
- Large query scope
    
- Slow or overloaded routers
    
- Poor EIGRP topology design
    

### Symptoms

```text
show ip eigrp topology active
show ip eigrp neighbors
show ip eigrp events
```

An affected route remains **Active** while DUAL waits for the diffusing computation to complete.

### Mitigation

- Use **EIGRP stub** on appropriate spoke routers to limit query propagation.
    
- Fix unstable or unidirectional links.
    
- Reduce unnecessary EIGRP query scope through summarization and proper topology design.
    
- Investigate overloaded or slow routers.
    
- `timers active-time` can be tuned when appropriate, but it should **not** be treated as the primary fix for a broken network.
    

> **Exam trap:** Increasing the active timer does not fix the underlying cause of SIA.

## 5. Successor and Feasible Successor

### Successor

The **successor** is the best route to a destination selected by DUAL and normally installed in the routing table.

### Feasible Successor

A **feasible successor (FS)** is a backup path that satisfies the **feasibility condition** and is therefore considered loop-free.

The feasibility condition is:

**Reported Distance (RD) < Feasible Distance (FD)**

If a valid FS exists, EIGRP can generally switch to it without performing a new diffusing computation for that destination.

### Troubleshooting

```text
show ip eigrp topology
show ip route eigrp
```

Look for:

- Successor
    
- Feasible distance
    
- Reported distance
    
- Feasible successors
    
- Installed next hops
    

> **Exam trap:** A route being present in the topology table does **not** automatically make it a feasible successor. The feasibility condition must be satisfied.

## 6. Metric Problems

Classic EIGRP metric calculation primarily uses:

- **Bandwidth**
    
- **Delay**
    

By default, Cisco EIGRP uses:

**K1 = 1, K3 = 1**

and:

**K2 = K4 = K5 = 0**

Therefore, bandwidth and delay are the important default metric components.

### Common Problems

|Symptom|Possible Cause|Check|
|---|---|---|
|Unexpected successor|Incorrect bandwidth/delay|Interface configuration|
|No feasible successor|Backup path fails feasibility condition|EIGRP topology|
|Very high metric|Incorrect delay/bandwidth|Interface configuration|
|Unequal paths unused|No qualifying FS or variance not configured|Topology + variance|

Useful commands:

```text
show ip eigrp topology
show interfaces
show running-config interface <interface>
```

> **Important:** `bandwidth` changes the value EIGRP uses for metric calculation; it does **not** change the physical interface speed.

---

## 7. Unequal-Cost Load Balancing

EIGRP can perform **unequal-cost load balancing** using `variance`.

```text
router eigrp 100
 variance 2
```

However, **variance alone does not make every alternate route eligible**.

A route must first satisfy EIGRP's conditions for installation, including the feasibility requirement.

### Troubleshooting

```text
show ip eigrp topology
show ip route eigrp
```

Check:

1. Is the alternate path a feasible successor?
    
2. Is the path metric within the configured variance multiplier?
    
3. Is the route actually installed in the RIB?
    

> **Exam trap:** `variance` does not bypass the feasibility condition.

---

## 8. Passive Interface

A passive EIGRP interface does not send EIGRP hello packets and therefore does not normally form EIGRP neighbor adjacencies.

Check:

```text
show running-config | section router eigrp
show ip protocols
```

Example:

```text
router eigrp 100
 passive-interface GigabitEthernet0/1
```

To restore neighbor formation:

```text
router eigrp 100
 no passive-interface GigabitEthernet0/1
```

> **Exam trap:** A passive interface can still advertise its connected network into EIGRP; it simply does not form an EIGRP neighbor relationship on that interface.

## 9. Redistribution Problems

When routes are redistributed into EIGRP, EIGRP needs a metric for those external routes.

A common solution is:

```text
router eigrp 100
 default-metric 10000 100 255 1 1500
```

Or specify a metric directly during redistribution:

```text
redistribute ospf 1 metric 10000 100 255 1 1500
```

The five classic EIGRP metric parameters are:

```text
bandwidth delay reliability load mtu
```

> **Exam trap:** Do not assume that redistributed routes automatically receive an appropriate EIGRP metric.

---

## 10. Route Missing from the RIB

If a destination appears in the EIGRP topology table but not in:

```text
show ip route eigrp
```

check:

- Whether the route has a valid successor.
    
- Whether the route satisfies EIGRP selection rules.
    
- Whether another routing source has a better administrative distance.
    
- Whether filtering or summarization is affecting the route.
    
- Whether the route is being suppressed or redistributed incorrectly.
    

Useful commands:

```text
show ip eigrp topology
show ip route <prefix>
show ip protocols
```

> **Important:** A route can exist in the EIGRP topology table without being installed in the RIB.

---

## 11. Neighbor Flapping

If a neighbor repeatedly disappears and reappears:

```text
show ip eigrp neighbors
show interfaces
show logging
```

Investigate:

- Physical link instability
    
- Packet loss
    
- Interface errors
    
- Duplex/speed problems
    
- Congestion
    
- ACL or security filtering
    
- Authentication problems
    
- CPU overload
    
- Unstable transport path
    

Look at **neighbor uptime**, interface counters, and system logs rather than assuming the EIGRP process itself is the problem.

## 14. Exam Traps

1. **K-values must match; hello/hold timers do not have to match.**
    
2. **AS mismatch prevents classic EIGRP adjacency.**
    
3. **Passive-interface prevents neighbor formation on that interface.**
    
4. **SIA means the EIGRP query process did not complete normally.**
    
5. **EIGRP stub limits query propagation; it does not magically repair a broken neighbor.**
    
6. **A feasible successor must satisfy `RD < FD`.**
    
7. **Variance does not bypass the feasibility condition.**
    
8. **A route in the topology table is not necessarily installed in the RIB.**
    
9. **Redistributed routes require an appropriate EIGRP metric.**
    
10. **Bandwidth and delay affect the default EIGRP metric.**
    
11. **Changing the EIGRP active timer should not be used as a substitute for fixing packet loss or topology problems.**
    
12. **Always troubleshoot neighbors before investigating route metrics.**

## 16. One-Line Troubleshooting Method

**Interface → Neighbor → Topology → Successor/FS → RIB → CEF → Data Plane**

If the **neighbor is missing**, troubleshoot adjacency.

If the **route is Active**, troubleshoot DUAL/query behavior.

If there is **no feasible successor**, check the feasibility condition and topology.

If the **route is in EIGRP but not the RIB**, check route selection, filtering, and administrative distance.

If the **route is in the RIB but traffic fails**, move to CEF, adjacency, and the data plane.
