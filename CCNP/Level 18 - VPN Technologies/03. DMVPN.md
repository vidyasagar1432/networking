# DMVPN

> **Level 18 · VPN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DMVPN** builds **dynamic, full-mesh IPsec tunnels** from a **hub-and-spoke** design
using three building blocks: **mGRE** (multipoint GRE), **NHRP** (spoke discovery), and
**IPsec**. Spokes talk **directly to each other** (spoke-to-spoke shortcuts) after NHRP
maps them — no hair-pinning through the hub for data.

---

## 2. Core Concepts

### 2.1 The three protocols

| Protocol | Role |
|----------|------|
| mGRE | one tunnel interface, many destinations |
| NHRP | resolves spokes' public addresses (maps) |
| IPsec | encrypts the mGRE tunnel traffic |

- **mGRE**: a single tunnel interface peers dynamically with any endpoint.
- **NHRP**: the hub acts as a **next-hop server (NHS)** for spoke registration.

### 2.2 How a spoke-to-spoke shortcut works

```
Spoke A  --NHRP reg-->  Hub (NHS)
Spoke B  --NHRP reg-->  Hub (NHS)
A wants B: A -> NHRP query -> Hub -> "B is at X.X.X.X"
A --direct IPsec GRE tunnel--> B   (no data via hub!)
```

- Control stays at the hub; **data goes directly** between spokes.

### 2.3 DMVPN roles

| Role | Description |
|------|-------------|
| Hub | NHS + mGRE hub, always reachable |
| Spoke | registers, learns peers |
| NHRP next-hop server | resolves mapping |
| Phase 1 | hub-and-spoke only (no shortcuts) |
| Phase 2 | spoke-to-spoke shortcuts (default) |
| Phase 3 | NHRP redirect (best path) |

- **Phase 2** enables dynamic spoke-to-spoke tunnels.

### 2.4 Configuration (spoke)

```text
interface Tunnel0
 ip nhrp map 10.255.0.1 203.0.113.1
 ip nhrp network-id 1
 ip nhrp nhs 10.255.0.1
 tunnel source Gi0/0
 tunnel mode gre multipoint
 tunnel protection ipsec profile DMVPN-PROF
```

| Command | Purpose |
|---------|---------|
| `nhrp map` | static hub mapping |
| `nhrp nhs` | hub as server |
| `nhrp network-id` | identity |
| `tunnel mode gre multipoint` | mGRE |
| `tunnel protection ipsec profile` | IPsec |

### 2.5 Benefits

| Benefit | Detail |
|---------|--------|
| Scale | hub config = 1 tunnel, many spokes |
| Direct path | no hub bottleneck |
| Zero-touch | new spokes auto-register |
| Resilient | dynamic re-establishment |

- DMVPN is the classic **branch/roaming** overlay.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No NHRP map | NHRP blocked / network-id | show ip nhrp |
| Data via hub | phase 1 / no shortcut | show dmvpn |
| Tunnel down | GRE 47 + IPsec blocked | underlay reachability |
| Spoke can't register | NHS mapping wrong | nhrp map |
| mGRE issue | tunnel mode not multipoint | config |

---

## 5. Exam Traps

- DMVPN = **mGRE + NHRP + IPsec**.
- NHRP resolves **spoke public IPs** via the hub (NHS).
- **Data goes spoke-to-spoke** after the shortcut (phase 2+).
- One mGRE tunnel interface, **many destinations**.
- `tunnel protection ipsec profile` ties IPsec to the tunnel.
