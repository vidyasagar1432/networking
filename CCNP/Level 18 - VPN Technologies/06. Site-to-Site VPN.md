# Site-to-Site VPN

> **Level 18 · VPN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **site-to-site (L2L) VPN** secures traffic between two fixed sites (branch ↔ HQ)
over a shared/Internet underlay. The classic recipe is **GRE over IPsec** for routing
flexibility, or **IPsec tunnel mode** directly with an interesting-traffic ACL. It is
the simplest VPN for fixed branch locations.

---

## 2. Core Concepts

### 2.1 The recipe choices

| Design | Uses | Trade-off |
|--------|------|-----------|
| Pure IPsec | interesting-traffic ACL | no multicast/routing |
| GRE over IPsec | GRE tunnel + IPsec | routing/multicast + crypto |
| FlexVPN/IKEv2 | profiles (note 04) | modern, simpler |

- **GRE over IPsec** = dynamic routing (OSPF/EIGRP/BGP) inside the encrypted tunnel.

### 2.2 Interesting traffic (classic IPsec)

```text
access-list VPN-TRAFFIC permit ip 10.0.0.0 0.0.0.255 10.1.0.0 0.0.0.255
```

| Item | Purpose |
|------|---------|
| Source | local protected subnet |
| Destination | remote protected subnet |
| Match | what the tunnel protects |

- Only traffic matching the ACL gets encrypted (tunnel mode).
- **Both sides must define mirror-image ACLs.**

### 2.3 GRE over IPsec steps

| Step | Detail |
|------|--------|
| 1 | Tunnel interface (GRE) |
| 2 | IPsec profile/transform |
| 3 | `tunnel protection ipsec profile` |
| 4 | Run routing protocol over tunnel |

```text
interface Tunnel0
 ip address 10.10.0.1 255.255.255.252
 tunnel source Gi0/0
 tunnel destination 203.0.113.1
 tunnel protection ipsec profile IPSEC-PROF
```

- The IPsec profile encrypts the GRE packets (protocol 47).

### 2.4 Routing over the VPN

| Protocol | Behavior |
|----------|----------|
| Static | simple, no failover |
| EIGRP/OSPF | converges over tunnel |
| BGP | scales many sites |

- With GRE, the tunnel is a regular interface — **routing protocols run over it**.

### 2.5 Verification and failure model

| Check | Command |
|-------|---------|
| IPsec SA | show crypto ipsec sa |
| IKE | show crypto ikev2 sa |
| Tunnel | show interface Tunnel0 |
| Interesting traffic | show crypto map |

- **No interesting traffic = no IPsec SA**, even if IKE is up.

### 2.6 Why GRE over IPsec is preferred

| Benefit | Detail |
|---------|--------|
| Any payload | multicast/broadcast support |
| Routing | dynamic protocols |
| Simplifies ACLs | encrypt all GRE |
| Branch scale | many tunnels |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No IPsec SA | no interesting traffic | crypto map |
| IKE up, no ESP | ACL/interesting mismatch | ipsec sa |
| Tunnel flapping | underlay jitter | reachability |
| Routing not working | no GRE | tunnel status |
| One-way only | asymmetric ACLs | mirror ACLs |

---

## 5. Exam Traps

- **Interesting-traffic ACL** defines what the tunnel protects.
- GRE over IPsec = **routing + multicast + encryption**.
- `tunnel protection ipsec profile` is the modern hook.
- Mirror-image ACLs required on both ends.
- No interesting traffic → **IPsec SA never forms**.
