# MED (Multi-Exit Discriminator)

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**MED** is the **optional non-transitive** attribute that tells a neighbor AS **which of
your exit points** to use for **inbound** traffic — it is advertised **outbound** and
compared **inbound**. **Lower is better** (best-path **step 6**). The critical exam rule:
MED is compared **only between paths from the same neighbor AS** unless
`bgp always-compare-med` is set.

---

## 2. Core Concepts

### 2.1 The one job: inbound traffic selection

- You have two links to an upstream. Setting a lower MED on link A tells the upstream to
  prefer A for traffic into you.
- MED is set **outbound** (toward the neighbor) and judged **inbound** (by the neighbor).

### 2.2 Attribute properties

| Property | Value |
|----------|-------|
| Type | optional non-transitive |
| Default | 0 (missing = 0) |
| Best path | step 6, lower wins |
| Compared | same neighbor AS only |
| Global compare | `bgp always-compare-med` |
| Metric on eBGP | the router's own IGP metric |

### 2.3 MED vs Local-Pref (the direction trap)

| Attribute | Direction | Meaning |
|-----------|-----------|---------|
| Local Pref | inbound set | **my** AS picks the exit |
| MED | outbound set | **upstream** picks the entry |

- Local-pref influences your **outbound** traffic; MED influences your **inbound** traffic.

### 2.4 Configuration

```text
route-map SETMED permit 10
 match ip address prefix-list PRIMARY-LINK
 set metric 50

router bgp 65001
 neighbor 192.0.2.2 route-map SETMED out
```

- Lower `set metric` = more preferred by the upstream (step 6 lower wins).
- For a second link, set a **higher** metric (e.g., 200) so the upstream prefers link A.

### 2.5 always-compare-med and the same-AS rule

```text
router bgp 65001
 bgp always-compare-med
```

- Default: MED from AS 100 vs MED from AS 200 is **not comparable** (both treated as 0).
- `always-compare-med` forces comparison across all paths — use with caution (multihomed).

### 2.6 iBGP and MED

- MED **transits iBGP** (optional non-transitive still crosses iBGP) so internal routers
  know the neighbor's preference.
- When re-advertising to a **third** AS, MED is stripped (non-transitive) unless reset.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| MED ignored | paths from different neighbor AS | same-AS rule, always-compare-med |
| Wrong entry point | MED set in wrong direction | route-map `out` vs `in` |
| MED stripped | re-advertised to third AS | non-transitive behavior |
| Unexpected winner | missing MED = 0 beats set MED | remember default 0 |
| No effect | step order — local-pref/AS_PATH differ | earlier steps decided |

---

## 5. Exam Traps

- **Lower MED wins** (step 6).
- **Same-AS comparison only** unless `always-compare-med`.
- **Outbound set, inbound compared** — the direction trap.
- Missing MED = **0** — can accidentally win.
- MED is **optional non-transitive** (doesn't cross to a third AS by default).
- Local-pref (step 2) always beats MED (step 6).
