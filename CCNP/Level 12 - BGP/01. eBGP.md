# eBGP

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**eBGP** (External BGP) runs **between routers in different autonomous systems** (ASes).
It is the Internet's inter-domain routing protocol — carrying prefixes across provider and
customer boundaries. Because it crosses trust boundaries, eBGP defaults are conservative:
the **AD of 20**, **TTL of 1** on peers, and **next-hop set to the neighbor's own address**
when advertising.

---

## 2. Core Concepts

### 2.1 eBGP vs iBGP at a glance

| Feature | eBGP | iBGP |
|---------|------|------|
| Peers in | different AS | same AS |
| AD | 20 | 200 |
| TTL | 1 (ebgp-multihop for non-direct) | 255 |
| Next-hop | changed to self on advertise | not changed (needs next-hop-self) |
| Split horizon | no | yes (no transit re-advertisement) |
| Loop prevention | AS_PATH | originator ID / AS_PATH on re-export |

### 2.2 Next-hop behavior

- When eBGP advertises a route, it sets **next-hop to its own update-source address**
  (the interface IP facing the peer).
- Direct peers: the next hop is the directly connected peer address.

### 2.3 TTL and ebgp-multihop

- Default TTL = **1** → neighbor must be directly connected (or the packet dies).
- Non-direct peers (loopback-to-loopback across an IGP core) need:

```text
neighbor 10.1.1.1 ebgp-multihop 2
```

- `ebgp-multihop` also enables **loopback peering**, which survives a single link failure.

### 2.4 Basic eBGP configuration

```text
router bgp 65001
 neighbor 192.168.1.2 remote-as 65002
 network 172.16.0.0 mask 255.255.0.0
```

- Only the AS numbers differ on each side — everything else must match (see 14. Troubleshooting).

### 2.5 Peer groups & update-source

```text
router bgp 65001
 neighbor EBGP-GROUP peer-group
 neighbor EBGP-GROUP remote-as 65002
 neighbor EBGP-GROUP update-source Loopback0
 neighbor EBGP-GROUP ebgp-multihop 2
 neighbor 192.168.1.2 peer-group EBGP-GROUP
```

- Update-source Loopback0 + multihop = stable peering independent of interface state.

### 2.6 eBGP path advertisement rules (recap for later notes)

- eBGP-learned routes are advertised to iBGP peers **without re-advertising to other eBGP**
  peers (AS_PATH loop prevention) — note 04.
- Local-pref propagates via iBGP (note 05); MED stays within the AS (note 06).

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Neighbor Idle/Active | wrong remote-as / ACL blocks 179 | `show ip bgp neighbors` |
| Connects but resets | update-source mismatch | compare BGP identifiers |
| No eBGP session over loopbacks | TTL 1 default | `ebgp-multihop` |
| Routes not advertised | missing `network` or `redistribute` | `show ip bgp summary` |
| Next-hop unreachable | next-hop-self not needed for eBGP | verify IGP reachability |

---

## 5. Exam Traps

- eBGP **AD = 20**, iBGP **AD = 200** — the classic BGP trap.
- Default TTL = 1 → **`ebgp-multihop` required** for non-direct eBGP.
- eBGP **changes next-hop** on advertise; iBGP does not.
- eBGP-learned routes are **not re-advertised to other eBGP peers** (loop prevention).
- Peering is over TCP/179 — must reach the neighbor's **update-source** IP.
