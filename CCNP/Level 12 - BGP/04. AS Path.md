# AS_PATH Attribute

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**AS_PATH** is the **well-known mandatory** BGP attribute that records the sequence of
autonomous systems a route has traversed. It serves two jobs: **loop prevention** (a route
whose AS_PATH already contains my AS is discarded) and **path selection** (step 4 of the
best-path algorithm — shorter is preferred). Operators manipulate it with **as-path
prepend** to steer inbound traffic.

---

## 2. Core Concepts

### 2.1 AS_PATH forms

| Type | Meaning | Example |
|------|---------|---------|
| AS_SEQUENCE | ordered list of ASes traversed | `65010 65020 65030` |
| AS_SET | unordered set (from aggregation) | `{65010, 65020}` |

- Every eBGP advertisement **prepends** the local AS to the list.
- iBGP does **not** modify AS_PATH (route stays in the same AS).

### 2.2 Loop prevention

- If a router's own AS appears anywhere in an incoming route's AS_PATH, the route is
  **rejected** — it has already been through this AS.
- This makes BGP loop-free at the AS level even without split horizon.

### 2.3 Best-path impact (step 4)

- **Shorter AS_PATH wins** when everything before (weight, local-pref, origin) ties.
- Prepend exists because you can't "shorten" — you can only make others' paths longer.

### 2.4 As-path prepend (inbound traffic steering)

```text
route-map PREPEND permit 10
 match ip address prefix-list HOST
 set as-path prepend 65001 65001 65001

router bgp 65001
 neighbor 192.0.2.2 route-map PREPEND out
```

- Prepend your own AS **multiple times** to make the path appear longer.
- Only prepend **your own AS number** — prepending a neighbor's AS can break loop logic.

### 2.5 Regular expressions (the match tool)

| Pattern | Meaning |
|---------|---------|
| `^` | start of AS_PATH |
| `$` | end of AS_PATH |
| `.` | any single char |
| `_` | separator (space/brace) |
| `*` | zero or more |
| `+` | one or more |

- `^65001$` = exactly one AS; `^65001_` = starts with 65001; `_65001_` = contains 65001.

### 2.6 Filtering with as-path ACLs

```text
ip as-path access-list 10 permit ^65001_ 65002$
router bgp 65001
 neighbor 192.0.2.2 filter-list 10 in
```

- `filter-list` applies the regex ACL inbound or outbound.

## 3. Configuration / Commands

```text
show ip bgp <prefix>                ! full AS_PATH per path
show ip bgp | include 65002         ! scan for ASes
show ip as-path-access-list         ! regex ACLs
show ip bgp regexp ^65001           ! paths matching regex
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Route silently dropped | my AS already in AS_PATH | `show ip bgp neighbors` received |
| Prepend no effect | wrong AS prepended / match miss | route-map order |
| Path looks longer than intended | prepend multiplied across hops | `show ip bgp` |
| Regex ACL blocks everything | bad `_`/`^` usage | test with `show ip bgp regexp` |
| Loop flap | prepended neighbor AS | only prepend own AS |

---

## 5. Exam Traps

- AS_PATH is **well-known mandatory**.
- **eBGP prepends own AS; iBGP does not**.
- Shorter path wins (best-path **step 4**).
- Prepending **your own AS only** — the classic exam mistake is prepending the peer's AS.
- Regex separators: `_` matches space/brace; `^`/`$` anchor; empty path `^$` = locally originated.
- AS_SET appears from aggregation (`aggregate-address`), not normal advertisement.
