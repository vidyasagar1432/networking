# BGP Path Selection (Best Path Algorithm)

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

When BGP receives multiple paths for the same prefix, it runs a **deterministic best-path
algorithm** — a strict priority list. The router keeps **one best path** per prefix in the
BGP table and installs it in the RIB. The first tie-breaker that differs decides the
winner; **later steps only run if earlier ones tie**.

---

## 2. Core Concepts

### 2.1 The full best-path algorithm (in order)

| # | Criterion | Winner |
|---|-----------|--------|
| 1 | Highest Weight (Cisco prop.) | higher wins |
| 2 | Highest Local Preference | higher wins |
| 3 | Prefer locally originated | network / aggregate / redistributed |
| 4 | Shortest AS_PATH | shorter wins |
| 5 | Lowest Origin | IGP < EGP < incomplete |
| 6 | Lowest MED | lower wins |
| 7 | Prefer eBGP over iBGP | eBGP wins |
| 8 | Lowest IGP metric to next hop | lower wins |
| 9 | Tie-breakers (exam stops here) | oldest eBGP path, lowest router ID, etc. |

- Steps **7–9** are the "secret" tail — the exam usually stops at MED/eBGP.

### 2.2 Weight (step 1, Cisco-proprietary)

- Local-only, set per neighbor (`neighbor ... weight`).
- **Never advertised** — the first differentiator inside a single router.

### 2.3 Local Preference (step 2) and Origin (step 5)

- Local-pref propagates **within the AS** (note 05) — the key outbound traffic selector.
- Origin: `i` (IGP/network cmd) < `e` (EGP) < `?` (incomplete/redistributed).

### 2.4 MED (step 6) is last among the "well-known" tunables

- MED only compares **within the same neighbor AS** unless `bgp always-compare-med`.
- Lower is better (note 06).

### 2.5 Which router sees which steps

| Path source | Applicable steps |
|-------------|------------------|
| Local | weight, local-pref, origin, MED |
| eBGP neighbor | local-pref, AS_PATH, origin, MED |
| iBGP neighbor | local-pref, AS_PATH, origin (MED via eBGP) |

- Weight never survives a router hop; local-pref survives iBGP only.

### 2.6 Practical tuning advice

- **Inbound** (choosing a path): local-pref (step 2) or AS_PATH prepend (step 4).
- **Outbound** (telling upstream): MED (step 6) — and only with the same AS rule.
- Communities (note 07) automate these attribute sets across many routers.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Wrong path chosen | attribute priority misunderstood | `show ip bgp` compare attributes |
| MED ignored | different neighbor AS | verify same AS, always-compare-med |
| AS_PATH ignored | local-pref already differed | check step order |
| Unexpected eBGP pref | step 7 vs step 4 mix-up | re-read algorithm order |
| Tie weirdness | old-eBGP / router ID rules | know steps 9+ exist |

---

## 5. Exam Traps

- **Order matters** — a decision at step 2 means steps 3–9 never run.
- **Weight > Local Pref > AS_PATH > MED** is the exam mantra.
- **Origin:** `i` beats `?` — redistributed routes are `?`.
- MED compares **same-AS only** unless `always-compare-med`.
- eBGP beats iBGP **only after** metric comparisons (step 7).
- Best path = per **prefix**, not per neighbor.
