# BGP Troubleshooting

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

BGP troubleshooting spans **session establishment** (TCP/179, TTL, update-source), **route
selection** (best-path steps, note 03), and **policy effects** (route-maps in/out, notes
11–13). The standard flow: establish sessions → verify BGP table → trace best path →
check policy/RIB. Most exam failures hide in **session mismatch**, **next-hop**, or
**route-map direction**.

---

## 2. Core Concepts

### 2.1 The troubleshooting flow

| Step | Question | Command |
|------|----------|---------|
| 1. Sessions | neighbors Established? | `show ip bgp summary` |
| 2. Table | prefixes present? | `show ip bgp` |
| 3. Best path | why this winner? | `show ip bgp <prefix>` |
| 4. RIB | installed? | `show ip bgp` vs `show ip route bgp` |
| 5. Policy | route-map effect | counters + neighbors routes |

### 2.2 Session-state failures

| State | Meaning | Likely cause |
|-------|---------|--------------|
| Idle | init | remote-as not configured |
| Connect | SYN sent | no route to peer |
| Active | retrying | TCP 179 blocked / wrong update-source |
| OpenSent/Confirm | negotiated | capability mismatch |
| Established | good | — |

- **Active** almost always = the neighbor can't reach your advertised address (TTL,
  update-source, ACL).

### 2.3 Common session problems

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| eBGP won't form over bow | TTL 1 default | ebgp-multihop |
| iBGP flaps | update-source mismatch | loopback + update-source |
| Active loop | TCP 179 blocked | ACL on interfaces |
| No eBGP peering | remote-as swapped | neighbor AS numbers |
| Newer peer upgrades | capability mismatch | IOS versions / peers |

### 2.4 Route-selection problems

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Wrong path installed | attribute priority | `show ip bgp` attributes |
| Next hop unreachable | outside RIB | iBGP recursion, next-hop-self |
| MED ignored | cross-AS comparison | same-AS rule / always-compare |
| Route filtered | route-map in/out | neighbors routes/advertised |
| Old path lingers | session flaps | timers / keepalive |

### 2.5 Policy misconfiguration signatures

| Sign | Cause |
|------|-------|
| Inbound attributes missing | route-map applied `out` instead of `in` |
| Communities lost | no `send-community` |
| Everything blocked | prefix-list implicit deny |
| Only self routes advertised | no `network` statements |
| Best path never changes | policy on wrong neighbor |

### 2.6 Key diagnostic commands

```text
show ip bgp summary
show ip bgp
show ip bgp neighbors <ip>
show ip bgp neighbors <ip> received-routes
show ip bgp neighbors <ip> advertised-routes
show ip bgp neighbors <ip> packet-statistics
show ip bgp paths
show ip route bgp
```

- `advertised-routes` vs `received-routes` isolate policy direction.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Neighbor not established | TCP/179, TTL, remote-as | summary + neighbors |
| Flapping session | update-source / hold timers | neighbors detail |
| No routes learned | prefix-list filter in | received-routes |
| Best path wrong | attribute priority or cross-AS MED | show ip bgp prefix |
| Route not in RIB | next-hop recursion | show ip route |
| Routes stuck | send-community / route-map out | advertised-routes |

---

## 5. Exam Traps

- **Active state** ⇒ reachability/policy, not remote-as.
- **received-routes** vs **advertised-routes** split policy direction.
- iBGP routes need **next-hop-self / recursion** before installing.
- **MED same-AS rule** — cross-AS comparison needs always-compare-med.
- **Communities stripped** without send-community.
- Best path fails at the **first differing step** (note 03).
