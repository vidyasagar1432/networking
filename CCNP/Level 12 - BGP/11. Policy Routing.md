# Policy-Based Routing (PBR)

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PBR** forwards traffic based on **policy** (source, protocol, DSCP, etc.) instead of the
routing table. It uses a **route-map** applied **inbound on an interface**; matching
traffic is given a **`set`** action — typically a next hop, output interface, or packet
marking. PBR is evaluated **before** the normal longest-match lookup, so it overrides the
RIB for the matched flows.

---

## 2. Core Concepts

### 2.1 PBR vs normal routing vs BGP policy

| Mechanism | Decision basis | Scope |
|-----------|---------------|-------|
| IP routing | destination + RIB | all traffic |
| BGP policy | attributes | path selection |
| PBR | match criteria | forwarding per-flow |

- PBR can send traffic to a next hop the RIB wouldn't choose.

### 2.2 Match → Set structure

```text
route-map PBR permit 10
 match ip address prefix-list VOIP
 set ip next-hop 10.1.1.2
 set ip precedence 5
```

- `match ip address` / `match ip precedence` / `match length` are common criteria.
- `set ip next-hop` / `set interface` / `set default next-hop` are the forwarding actions.

### 2.3 set ip next-hop vs set default next-hop

| Command | Effect |
|---------|--------|
| `set ip next-hop X` | always send matched traffic to X (if reachable) |
| `set ip default next-hop X` | use X **only if** no RIB route exists |
| `set interface` | force out a given interface |

- `set ip next-hop` is the strict override; `set default next-hop` is a fallback.

### 2.4 Applying PBR

```text
interface Gi0/1
 ip policy route-map PBR
```

- Applied **inbound** on the interface receiving the traffic.
- Check reachability: the next hop must be in the routing table or PBR won't install.
- `ip local policy route-map` applies PBR to **locally generated** traffic.

### 2.5 Verifying

```text
show ip policy                        ! interfaces + route-maps
show route-map                        ! match/set and counters
debug ip policy                       ! PBR decisions
```

- `show route-map` counters show matched traffic — the first verification step.

### 2.6 Common uses

| Use | Match | Set |
|-----|-------|-----|
| Voice over dedicated link | DSCP EF | next-hop to voice router |
| Traffic from branch A | source prefix-list | next-hop to uplink A |
| Marking | length/precedence | set ip precedence |
| Local PBR | source | next-hop for own traffic |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Policy not applied | wrong interface/direction | `show ip policy` |
| No traffic counted | match never hits | `show route-map` counters |
| Next hop unreachable | RIB lacks the hop | route-map next-hop RIB check |
| Local traffic unaffected | no `ip local policy` | local policy |
| Default hop ignored | route exists | set default next-hop semantics |

---

## 5. Exam Traps

- PBR is **inbound** on an interface (and overrides RIB for matched flows).
- `set ip next-hop` **overrides**; `set default next-hop` is only a **fallback**.
- `ip local policy route-map` for **locally sourced** traffic.
- Match/set lives in a **route-map**, applied with `ip policy route-map`.
- PBR is evaluated **before** the routing table for matched packets.
