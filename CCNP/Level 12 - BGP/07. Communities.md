# BGP Communities

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Communities** are **optional transitive** tags attached to routes so operators can group
routes and apply policy **remotely** — the upstream applies the action, not the sender.
Because they're transitive, communities travel across AS boundaries (unlike MED). The exam
covers the four **well-known communities**, the **4-byte ASN:value** format, and how
`neighbor ... send-community` controls what leaves the router.

---

## 2. Core Concepts

### 2.1 Attribute properties

| Property | Value |
|----------|-------|
| Type | optional transitive |
| Scope | travels across ASes |
| Format (standard) | 0–65535 (16-bit) |
| Format (extended) | ASN:value (32-bit) |
| Goal | tag + remote policy |

### 2.2 The four well-known communities

| Community | Value | Action it triggers |
|-----------|-------|--------------------|
| NO_EXPORT | 0xFFFFFF01 | don't advertise outside the local AS |
| NO_ADVERTISE | 0xFFFFFF02 | don't advertise to **any** BGP peer |
| LOCAL_AS | 0xFFFFFF03 | don't advertise outside local confed sub-AS |
| INTERNET | 0x00000000 | advertise anywhere (default) |

- **NO_EXPORT vs NO_ADVERTISE** is the classic trap: NO_EXPORT still flows within the AS;
  NO_ADVERTISE stops at this router entirely.

### 2.3 Setting and sending communities

```text
route-map COMM permit 10
 match ip address prefix-list MKT
 set community 65001:100

router bgp 65001
 neighbor 192.0.2.2 route-map COMM out
 neighbor 192.0.2.2 send-community       ! REQUIRED to transmit
```

- Without `send-community`, the attribute is stripped — communities silently vanish.
- `neighbor ... send-community both` also sends extended communities.

### 2.4 Matching communities (policy on the receiving side)

```text
ip community-list standard 10 permit 65001:100

route-map APPLY permit 10
 match community 10
 set local-preference 200

router bgp 65001
 neighbor 192.0.2.2 route-map APPLY in
```

- Standard community-list = exact/tagged match; **expanded** list = regex.

### 2.5 Well-known community shorthand

```text
set community no-export
set community no-advertise
set community local-as
```

- IOS accepts the names directly in `set community`.

### 2.6 Community propagation rules

| Condition | Community sent? |
|-----------|-----------------|
| `send-community` configured | yes |
| missing `send-community` | **no** — stripped |
| standard | sent with `send-community standard` |
| extended | needs `send-community both/extended` |
| private | optional 4-byte, needs both |

```text
show community-list               ! configured lists
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Community lost | missing `send-community` | neighbor config |
| Policy not applied | match list wrong type | standard vs expanded |
| NO_ADVERTISE effect | route hidden everywhere | confirm intent vs NO_EXPORT |
| Route too visible | NO_EXPORT vs LOCAL_AS mixup | pick correct well-known |
| Match miss | value format (ASN:value) | verify `set` vs `match` |

---

## 5. Exam Traps

- **`send-community` is mandatory** — the #1 reason communities vanish.
- **NO_EXPORT** (stays in AS) vs **NO_ADVERTISE** (dies at this router).
- Communities are **optional transitive** — they cross ASes (unlike MED).
- Standard list = exact; expanded = regex.
- Extended format = **ASN:value** (e.g., 65001:100).
