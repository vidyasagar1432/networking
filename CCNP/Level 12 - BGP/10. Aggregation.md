# BGP Aggregation (Summarization)

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**BGP aggregation** summarizes more-specific prefixes into a single shorter prefix before
advertising to neighbors, shrinking the global table and hiding internal flaps. The core
commands are **`aggregate-address`** and **`network`** (with masks); the exam focuses on
**`summary-only`**, the **`as-set`** behavior, and the **atomic-aggregate / aggregator**
attributes that mark the aggregation point.

---

## 2. Core Concepts

### 2.1 The two ways to summarize

| Method | Command | Conditions |
|--------|---------|------------|
| Static network | `network X mask Y` | must exist in BGP table or be IGP-known |
| Aggregate | `aggregate-address X mask` | **any** more-specific in BGP table |

- `network` needs the exact route present; `aggregate-address` synthesizes from more-specifics.

### 2.2 aggregate-address behavior

```text
router bgp 65001
 aggregate-address 172.16.0.0 255.255.0.0
```

- Advertises the summary **plus** the more-specifics by default.
- Add **`summary-only`** to suppress the more-specifics.

```text
router bgp 65001
 aggregate-address 172.16.0.0 255.255.0.0 summary-only
```

### 2.3 AS_SET (the `as-set` keyword)

```text
router bgp 65001
 aggregate-address 172.16.0.0 255.255.0.0 as-set
```

- Without `as-set`, the aggregate's AS_PATH lists **only the aggregating AS** — hiding the
  originating ASes (a black-hole / loop risk for multi-origin aggregates).
- With `as-set`, the aggregate carries an **AS_SET** `{AS1, AS2}` listing the origins.

### 2.4 Attributes of the aggregate

| Attribute | Meaning |
|-----------|---------|
| atomic-aggregate | set automatically — "less specific exists" |
| aggregator | router ID + AS that aggregated |

- `atomic-aggregate` is a **well-known discretionary** hint that details were lost.

### 2.5 Suppressing with filters

```text
ip prefix-list HIDE seq 10 deny 172.16.1.0/24
ip prefix-list HIDE seq 20 permit 0.0.0.0/0 le 32

router bgp 65001
 aggregate-address 172.16.0.0 255.255.0.0 summary-only
 neighbor 192.0.2.2 route-map HIDE out
```

- `summary-only` hides everything; route-maps hide **selected** more-specifics.

### 2.6 Aggregation benefits vs risks

| Pro | Con |
|-----|-----|
| smaller tables | loss of path diversity |
| hides flaps | MED/pref differences lost |
| stable upstream view | AS_SET needed for multi-origin |
| fewer RIB entries | filtering must be precise |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Summary missing | no more-specific in BGP table | `show ip bgp` |
| More-specifics leak | missing summary-only | neighbor out filter |
| Black hole | no as-set on multi-origin | add as-set |
| Upstream sees origin AS lost | aggregation without as-set | attributes |
| Flap at edge | prefix filtered wrong | prefix-list order |

---

## 5. Exam Traps

- `aggregate-address` works from **any** more-specific; `network` needs the exact route.
- **`summary-only`** suppresses more-specifics.
- **`as-set`** records origins; without it the path looks like only the aggregator.
- **atomic-aggregate + aggregator** mark the aggregation.
- Aggregation **loses attributes** (MED, communities) — the tradeoff.
