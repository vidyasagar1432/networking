# Route Maps

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Route maps** are the general-purpose policy engine: a sequence of **match/set**
blocks used for BGP attribute manipulation, redistribution filtering, PBR (note 11), NAT,
and route filtering. The exam focuses on **sequence numbers**, **match/set pairs**, the
**permit/deny** action, **first-match-wins** order, and the difference from a simple ACL.

---

## 2. Core Concepts

### 2.1 Structure

```text
route-map NAME permit|deny SEQ
 match ...
 set ...

route-map NAME permit 10
 match ip address prefix-list X
 set local-preference 200
```

- Each entry = one `match` block (conditions) + its `set` actions.
- Lower **seq** runs first.
- **First match wins** — later entries skipped for that route.

### 2.2 The permit/deny semantics

| Action | With match | Without match |
|--------|-----------|---------------|
| **permit** | apply `set`, let route pass | **default pass** with no set |
| **deny** | block route (filter) | **default pass** (skip) |

- **deny** in BGP filters = route rejected.
- Empty **permit** = accept everything (acts like implicit permit for non-BGP contexts).
- In redistribution, a matched **deny** stops redistribution of that prefix.

### 2.3 Common match and set pairs

| Match | Set |
|-------|-----|
| `match ip address prefix-list PC` | `set local-preference` |
| `match ip address acl X` | `set metric` (MED) |
| `match as-path 10` | `set community` |
| `match ip next-hop` | `set ip next-hop` (PBR) |
| `match interface` | `set interface` (PBR) |

### 2.4 Applying route maps to BGP neighbors

```text
router bgp 65001
 neighbor 192.0.2.2 route-map INBOUND-AM in
 neighbor 192.0.2.2 route-map OUTBOUND-POLICY out
```

- `in`: filter/set on routes **received**.
- `out`: filter/set on routes **sent**.
- Route-map direction is the single most common misconfig.

### 2.5 Iterative nature (NAT, PBR)

- Only the **matching entry's set** applies; a route can pass through the map only once.
- `continue` keyword allows falling through to later seqs for additional sets.

### 2.6 Route map vs access-list vs policy

| Tool | Purpose |
|------|---------|
| Access-list | can it match IP/proto/port? |
| Prefix-list | matches routes by prefix/len |
| Route-map | matches AND modifies |

- Route maps **wrap** prefix-list / ACL / as-path matches and add **actions**.


## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Policy no effect | wrong `in`/`out` direction | neighbor route-map |
| Routes filtered unexpectedly | deny entry hit first | seq order |
| Attribute unchanged | no matching seq | `show route-map` counters |
| Route dropped at edge | deny + implicit deny | add explicit permit |
| Extra attributes set | continue / later seq | trace seqs |

---

## 5. Exam Traps

- **First match wins** by seq number.
- **deny** at a matched seq = **filter**; matched **permit** = apply `set`.
- **In / out direction** is a frequent exam trap.
- Empty permit entry = **pass through** (no set applied).
- Route maps are used by BGP **and also** redistribution, PBR, NAT.
- `show route-map` counters tell you if matches actually fired.
