# Route Reflector (RR)

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **route reflector** breaks iBGP's full-mesh requirement (note 02): one or more
reflectors act as hubs that **re-advertise iBGP-learned routes**, cutting the session count
from n(n-1)/2 to n. Reflection is controlled by three attributes — **ORIGINATOR_ID,
CLUSTER_LIST, and CLUSTER_ID** — which guarantee loop-freedom when iBGP split horizon is
bypassed.

---

## 2. Core Concepts

### 2.1 Why reflect

| | Full mesh | With RR |
|--|-----------|---------|
| Sessions | n(n-1)/2 | n (per client) |
| Scale | collapses > ~10 routers | linear |
| Config | all-to-all | reflector + clients |

### 2.2 Roles

| Role | Meaning |
|------|---------|
| RR | re-advertises iBGP routes |
| Client | iBGP peer of the RR; only peers with the RR |
| Non-client | iBGP peer of RR but not a client |

### 2.3 The reflection rules (exam-critical)

| Route learned from | Sent to |
|-------------------|---------|
| Client | all other clients **and** non-clients |
| Non-client | clients **only** |
| eBGP | everyone |
| iBGP (general) | not re-advertised (split horizon) — **except** the rules above |

- A client never peers with another client — the RR relays between them.

### 2.4 Loop prevention attributes

| Attribute | Purpose | Set by |
|-----------|---------|--------|
| ORIGINATOR_ID | the original router ID; any router seeing its own ID drops the route | originator |
| CLUSTER_ID | identifies the reflector cluster | each RR |
| CLUSTER_LIST | cluster IDs traversed; any router in the list drops on re-receipt | each RR |

- Two RRs in one cluster share a **CLUSTER_ID**; distinct clusters have distinct IDs.

### 2.5 Configuration

```text
router bgp 65001
 neighbor 10.0.0.2 remote-as 65001
 neighbor 10.0.0.2 route-reflector-client   ! client
```

- Add `route-reflector-client` per client; the reflector **must** peer with each client.
- Clients keep `remote-as 65001` and normal iBGP config (loopback, update-source).

### 2.6 Multi-cluster design

```text
router bgp 65001
 bgp cluster-id 1        ! cluster 1
```

- Several reflectors, each with its own cluster-id, scale larger ASes; clients peer only
  with their local RR, RRs peer with each other.

## 3. Configuration / Commands

```text
show ip bgp
show ip bgp neighbors <ip>
show ip bgp cluster-list 1
show ip bgp paths
```

---

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Routes missing | client doesn't peer with RR | `show ip bgp neighbors` |
| Loop / flapping | same cluster-id on distinct clusters | cluster-id uniqueness |
| Route dropped | ORIGINATOR_ID loop | trace originator |
| Clients only see RR routes | non-client rule | reflection rules |
| RR redundancy broken | no RR-RR peering | multi-cluster design |

---

## 5. Exam Traps

- **RR re-advertises iBGP routes** — bypasses split horizon safely via attributes.
- **ORIGINATOR_ID** and **CLUSTER_LIST** do the loop prevention.
- Routes from a **non-client** go to **clients only**.
- Clients peer **only with the RR**, never with each other.
- `route-reflector-client` config goes on the **reflector**, per client.
