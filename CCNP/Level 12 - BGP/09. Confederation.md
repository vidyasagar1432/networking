# BGP Confederation

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Confederation** is an alternative to route reflectors (note 08) for scaling iBGP. The
AS is split into **sub-ASes** that peer with each other using **eBGP-like** sessions,
while presenting a **single confederation AS** to the outside world. It reduces the iBGP
full-mesh burden but is rarer in the exam than reflectors — the focus is on **when** to
use it and how the attributes behave across sub-AS boundaries.

---

## 2. Core Concepts

### 2.1 Confederation vs Route Reflector

| | Route Reflector | Confederation |
|--|-----------------|---------------|
| Model | hub-and-spoke clients | eBGP-style sub-ASes |
| Loop guard | ORIGINATOR_ID / CLUSTER_LIST | AS_PATH (confed subset) |
| Config effort | reflectors + clients | sub-AS split |
| Exam frequency | high | lower |
| Attribute loss | none | none (keeps local-pref, MED) |

### 2.2 How sub-ASes peer

- Each sub-AS runs its own AS number **internally**.
- Sessions **between sub-ASes** behave like eBGP (different AS numbers) but are treated as
  confederation peers — iBGP attributes survive.

| Session type | Remote-as | AD | Behavior |
|--------------|-----------|-----|----------|
| iBGP within sub-AS | same sub-AS | 200 | iBGP rules |
| Confederation eBGP | other sub-AS | 200 | eBGP-ish, attributes kept |
| Real eBGP | outside AS | 20 | normal eBGP |

- Confederation eBGP sessions use **AD 200** (like iBGP), not 20.

### 2.3 Attribute behavior (the exam point)

- **Local-pref, MED, and next-hop** are preserved across sub-AS boundaries — unlike real
  eBGP.
- Next hop is **not** changed between sub-ASes (unless `next-hop-self` needed for real
  eBGP).
- **AS_PATH** is extended with the **confederation sequence** but the confed ASes are
  stripped before the route leaves to the real world — outsiders see only the confederation
  **identifier**.

### 2.4 Configuration

```text
router bgp 64512            ! sub-AS 64512
 bgp confederation identifier 65001        ! public AS
 bgp confederation peers 64513 64514       ! other sub-ASes
 neighbor 10.0.0.2 remote-as 64513         ! confed eBGP peer
```

- `bgp confederation identifier` = the real AS shown to the outside.
- `bgp confederation peers` = the sub-ASes that are actually confed members.

### 2.5 Loop prevention

- Confed sub-ASes appear in the confederation sequence; a route with my confed ID in the
  confed part is rejected.
- The confederation sequence is **stripped** at the real eBGP boundary, so outsiders see a
  clean AS_PATH of real ASes.

### 2.6 When to choose

- Confederation shines when the AS is already **segmented by policy/geography** and you
  want eBGP-like boundary control **without** changing attributes.
- Otherwise, route reflectors are simpler to operate.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Sub-AS peers not forming | missing `confederation peers` | router config |
| Attribute changed across | real eBGP, not confed | AD 20 vs 200 |
| Outside AS sees confed ASes | confed seq not stripped | eBGP boundary |
| Route loop | confed ID in received path | AS_PATH inspect |
| Local-pref lost | wrong session type | remote-as matching |

---

## 5. Exam Traps

- Confederation eBGP peers use **AD 200**, not 20.
- **Attributes survive** sub-AS boundaries (local-pref, MED, next-hop) — unlike real eBGP.
- `confederation identifier` = public AS; `confederation peers` = sub-AS list.
- Confed AS_PATH is **stripped** before leaving to real eBGP.
- Prefer reflectors in exam answers unless confed is explicitly asked.
