# Prefix Lists

> **Level 12 · BGP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Prefix lists** filter routes by **prefix and prefix-length** — the preferred way to match
routes in BGP policy (route-maps, distribute-lists, filters) because they're faster and
cleaner than access-lists for routing. The exam focuses on the **`ge` / `le`** modifiers
and the **first-match-wins** evaluation order.

---

## 2. Core Concepts

### 2.1 Syntax

```text
ip prefix-list NAME {seq} deny|permit PREFIX/LEN [ge GE] [le LE]
```

- Without `ge`/`le`, only an **exact** prefix of that length matches.

### 2.2 The implicit rules

| Rule | Meaning |
|------|---------|
| Default len | only the stated /len matches |
| default ge | ge = stated length |
| default le | le = 32 |
| Longest > short | prefix part must be identical |
| Implicit deny | nothing matches at end |

- Matching requires the **prefix bits** equal AND **length within [ge, le]**.

### 2.3 ge/le combinations

`ip prefix-list FOO permit 10.0.0.0/8 ge 16 le 24`

| Written | Matches |
|---------|---------|
| `/16` only | 10.0.0.0/16 (len = ge = 16) |
| `/16 le 24` | 10.x.x.x /16 through /24 |
| `/8 ge 16` | any 10.0.0.0/8 with len up to 32 |
| `/8 ge 16 le 24` | len 16–24 only; /25+ NOT matched |

- **ge/le are about length, not bits** — the /8 prefix part is fixed.

### 2.4 Exact vs range examples

| Config | Result |
|--------|--------|
| `permit 10.0.0.0/8` | only 10.0.0.0/8 |
| `permit 10.0.0.0/8 le 32` | all 10.x.x.x any length |
| `permit 0.0.0.0/0 le 32` | **everything** |
| `permit 0.0.0.0/0` | default route only |

- `0.0.0.0/0 le 32` is the universal permit — common at the end of lists.

### 2.5 Order of evaluation

- Sequences evaluated **lowest seq first**; **first match wins**.
- Unlike ACLs, prefix lists **always<91> apply implicit deny** at the end.

```text
ip prefix-list DENY-HOSTS seq 10 deny 10.1.1.0/24
ip prefix-list DENY-HOSTS seq 20 permit 10.0.0.0/8 le 32
```

- Hosts in 10.1.1.0/24 blocked; everything else in 10.0.0.0/8 allowed.

### 2.6 Using prefix lists in BGP

```text
ip prefix-list UPSTREAM permit 192.0.2.0/24 le 32

route-map FILTER permit 10
 match ip address prefix-list UPSTREAM
```

- `match ip address prefix-list ...` inside a route-map (note 13).
- Also usable directly with `neighbor ... prefix-list NAME {in|out}`.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| More routes than expected | le 32 over-matched | tighten le |
| Route filtered by accident | implicit deny | add final permit |
| len matches but prefix doesn't | bit comparison | verify /len part |
| Nothing matches | ge > le impossible | reject invalid ge/le |
| Wrong seq wins | first-match order | renumber seq |

---

## 5. Exam Traps

- **ge/le modify length, not prefix bits**.
- Explicit **len only** = exact-length match.
- **Implicit deny** at the end — always add `permit 0.0.0.0/0 le 32` if needed.
- First-match wins, evaluated by **seq**.
- `ip prefix-list` supports **sequence numbers** you can reorder/delete.
- Longest prefix part is NOT auto-included — only the stated /len is the anchor.
