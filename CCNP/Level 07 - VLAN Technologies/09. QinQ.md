# QinQ (802.1ad / Double Tagging)

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**QinQ** (IEEE 802.1ad, Provider Bridges) stacks **two 802.1Q tags** — an outer
**service-provider (S-tag)** VLAN over the customer's **inner (C-tag)** VLAN. Service
providers carry thousands of customers over a **single metro trunk**, preserving each
customer's own VLAN numbering.

---

## 2. Core Concepts

### 2.1 The double tag
```
[DA | SA | TPID 0x88A8 | S-VID | TPID 0x8100 | C-VID | Type | Payload | FCS]
          ├── outer (provider) ──┘  └── inner (customer) ──┘
```
- **S-TAG (0x88A8)** — service provider's outer tag; identifies the customer/service.
- **C-TAG (0x8100)** — customer's original 802.1Q tag, carried intact.
- Frame overhead +8 bytes total.

### 2.2 Roles

| Role | Behavior |
|------|----------|
| **CE (customer edge)** | normal customer switch, single tag |
| **PE (provider edge)** | adds S-tag (QinQ) toward provider, strips toward customer |
- 4094 customer VLANs can be carried per S-VLAN — provider scales by S-tag, customer
  keeps its space.
- Also called **QinQ tunneling / 802.1ad / Provider Bridging**.

### 2.3 Modes (provider switchconfig)

| Mode | Meaning |
|------|---------|
| **dot1q-tunnel** (`switchport dot1q-tunnel`) | access port that **encapsulates all incoming tagged frames** in S-tag |
| **L2PT / tunnel vlan** | tunnel customer VLANs mapped to S-VLANs (Layer-2 tracing) |
- Provider port: `switchport mode dot1q-tunnel` + `switchport access vlan <S>`
  → everything in that port goes into S-VLAN `<S>` with a second tag.

### 2.4 When to use QinQ

| Use | Why |
|-----|-----|
| Metro/ISP Ethernet | carry many customers on one fiber |
| VLAN exhaustion | customer's 4K space + provider space both preserved |
| Multi-tenant services | isolate tenants logically |
| VPLS predecessors | transport transparent customer switching |

### 2.5 QinQ vs performance/size
- Adds 8 bytes → **MTU ≥ 1508/1510** on the provider path (Level 01 MTU).
- MAC learning stays based on **inner (customer) MAC? — on the tunnel access it learns
  the customer MAC; on backbone by outer** — campus want details in labs.
- `show interfaces dot1q-tunnel` to verify.

## 3. Configuration / Commands

```text
! Provider-facing access port (toward customer)
interface GigabitEthernet0/1
 switchport access vlan 100          # S-VLAN (service)
 switchport mode dot1q-tunnel        # QinQ in
 no ip address

! Backbone port carries the S-tag onward (trunk)
interface TenGigabitEthernet1/1
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk allowed vlan 100

! Verify
show interfaces Gi0/1 dot1q-tunnel
show interfaces trunk
```

## 4. Exam Traps

- **Two TPIDs — 0x88A8 (outer) vs 0x8100 (inner)** — the naming trap.
- **QinQ ≠ "double tagging attack"** — double tagging (VLAN hopping) is an attack on
  802.1Q; QinQ is legitimately separate.
- **Customer's VLAN preserved** — provider can't renumber = charm of QinQ.
- **Adds 8 bytes**, not 4.
- **`dot1q-tunnel` on the provider access port toward customer** — direction matters.
