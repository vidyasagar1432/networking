# Access Port

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

An **access port** is a switch port that is associated with **one access VLAN** and is normally used to connect endpoint devices such as PCs, printers, cameras, or other single-VLAN devices.

Traffic sent to an endpoint is normally **untagged**. When the switch receives an untagged frame on an access port, it associates that frame with the port's configured **access VLAN**.

## 2. Core Concepts

### 2.1 What an access port does

An access port:

- Is assigned **one access VLAN**.
    
- Normally receives **untagged** frames from an endpoint.
    
- Associates received untagged frames with the configured access VLAN.
    
- Normally sends endpoint traffic **untagged**.
    
- Does **not operate as an 802.1Q trunk**.
    
- Uses `switchport mode access` to explicitly force access mode.
    

Example:

```cisco
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10
```

Here, Gi0/1 is an access port for **VLAN 10**.

---

### 2.2 Access vs Trunk

|Feature|Access Port|Trunk Port|
|---|---|---|
|VLANs|One access VLAN|Multiple VLANs|
|Normal endpoint traffic|Untagged|802.1Q tagged|
|Typical peer|PC, printer, camera|Switch, router, firewall, AP|
|Configuration|`switchport mode access`|`switchport mode trunk`|
|Access VLAN|Yes|No|
|Native VLAN|Not applicable as a trunk concept|One VLAN carried untagged|
|DTP trunk negotiation|Prevented by access mode|Depends on configuration|

> **Key distinction:**  
> An access port is **not an 802.1Q trunk**. It is associated with an access VLAN and normally handles untagged endpoint traffic.

---

### 2.3 Voice VLAN — Important Exception

A Cisco access port can support both:

- **Access VLAN** → data traffic
    
- **Voice VLAN** → voice traffic
    

A common IP-phone topology is:

```text
        PC
         │
   Untagged Data
         │
         ▼
    ┌─────────┐
    │ IP Phone│
    └─────────┘
         │
         │ 802.1Q tagged Voice
         │
         ▼
      Switch
```

The switch can distinguish:

- **Untagged data traffic** → access VLAN
    
- **802.1Q-tagged voice traffic** → voice VLAN
    

Example:

```cisco
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10
 switchport voice vlan 20
```

This does **not** make the port a normal trunk. It remains an **access port** with an additional voice VLAN configuration.

> **Exam trap:**  
> Do not interpret "access port = only one VLAN under all circumstances."  
> An access port can have an **access VLAN plus a voice VLAN**.

---

### 2.4 Access Ports and Spanning Tree

Access ports still participate in **Spanning Tree Protocol (STP)**.

For end-host ports, Cisco commonly recommends **PortFast**:

```cisco
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
```

PortFast allows an edge/host port to transition rapidly to the **forwarding state**, avoiding the normal STP startup delay.

It does **not disable STP**.

> **Important:** PortFast should normally be used on ports connected to end devices, not between switches.

---

### 2.5 Security Features

Access ports are common locations for Layer 2 security controls, including:

- **Port Security**
    
- **BPDU Guard**
    
- **802.1X**
    
- **DHCP Snooping trust/untrust configuration**
    
- **IP Source Guard**
    
- **Dynamic ARP Inspection**
    

These features are not all exclusive to access ports, but endpoint-facing access ports are common places to configure them.

Example:

```cisco
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
 spanning-tree bpduguard enable
```

---

### 2.6 PoE

Access ports commonly connect to PoE-powered devices such as:

- IP phones
    
- Wireless access points
    
- IP cameras
    

PoE is a **power-delivery feature**, not a requirement of access-port operation.

An access port can exist without PoE, and PoE can also be used on ports serving other types of connections.

## 3. Explicit Access Mode vs Dynamic Modes

### 3.1 `switchport mode access`

```cisco
switchport mode access
```

Forces the port into **access mode**.

The port does not negotiate with the neighbor to become an 802.1Q trunk through DTP.

This is the preferred configuration for normal endpoint ports.

---

### 3.2 `switchport mode dynamic desirable`

```cisco
switchport mode dynamic desirable
```

The port **actively attempts to negotiate trunking using DTP**.

Depending on the neighbor's configuration, the link can become a trunk.

Therefore, using `dynamic desirable` on an endpoint-facing port is generally undesirable from a security and operational perspective.

---

### 3.3 `switchport mode dynamic auto`

```cisco
switchport mode dynamic auto
```

The port is willing to become a trunk if the neighbor actively negotiates trunking.

It does not actively initiate trunking itself.

For example:

```text
Desirable + Auto
      │
      └── Can negotiate a trunk

Auto + Auto
      │
      └── Remains non-trunking
```

> **Best practice:**  
> Explicitly configure endpoint-facing ports with:
> 
> ```cisco
> switchport mode access
> ```

## 6. Troubleshooting

### Problem 1 — Wrong Access VLAN

If the port is assigned to the wrong VLAN:

```cisco
show interfaces Gi0/1 switchport
```

Check:

```text
Access Mode VLAN
```

Correct it with:

```cisco
interface Gi0/1
 switchport access vlan 10
```

A wrong access VLAN can cause:

- DHCP failure
    
- ARP failure
    
- Wrong IP subnet
    
- Inability to reach expected hosts
    
- Unexpected Layer 2 connectivity
    

---

### Problem 2 — Port is Err-Disabled

Check:

```cisco
show interfaces status err-disabled
```

Then investigate the cause, for example:

- BPDU Guard
    
- Port Security
    
- Link Flap
    
- Other configured errdisable conditions
    

Do not assume every err-disabled port is simply "down."

---

### Problem 3 — Unexpected Trunking

Check:

```cisco
show interfaces Gi0/1 switchport
```

Look at:

```text
Administrative Mode
Operational Mode
```

For an endpoint port, normally configure:

```cisco
interface Gi0/1
 switchport mode access
```

This prevents DTP from dynamically turning the port into a trunk.

---

### Problem 4 — Host Gets the Wrong Network

Use this troubleshooting sequence:

```text
Host
  │
  ▼
Physical Link
  │
  ▼
Access Port
  │
  ├── Correct access VLAN?
  │
  ▼
VLAN Exists?
  │
  ▼
DHCP / Gateway
  │
  ▼
Routing
```

Start with:

```cisco
show interfaces Gi0/1 status
show interfaces Gi0/1 switchport
show vlan brief
```

## 7. Exam Traps

### Trap 1 — "Access port means no VLAN tag can ever exist"

Not strictly correct.

Normal access-port endpoint traffic is **untagged**, but an access port can have a **voice VLAN**, where tagged voice traffic is supported.

---

### Trap 2 — "PortFast disables STP"

Incorrect.

PortFast changes how an edge port enters the forwarding state. The port remains part of the STP topology.

---

### Trap 3 — "Dynamic desirable is safe for hosts"

Incorrect.

`dynamic desirable` actively participates in DTP negotiation and can result in trunking with a compatible neighbor.

Use:

```cisco
switchport mode access
```

for endpoint-facing ports.

---

### Trap 4 — "Access ports never run STP"

Incorrect.

Access ports normally participate in STP. PortFast simply provides faster edge-port convergence.

---

### Trap 5 — "APs always use access ports"

Incorrect.

A simple AP may use an access port, but an enterprise AP carrying multiple SSIDs/VLANs commonly uses a **trunk**.

---

### Trap 6 — "Access VLAN and native VLAN are the same thing"

Incorrect.

- **Access VLAN** → VLAN associated with an access port.
    
- **Native VLAN** → VLAN whose traffic is normally sent **untagged on an 802.1Q trunk**.
    

The native VLAN is a trunk concept.
