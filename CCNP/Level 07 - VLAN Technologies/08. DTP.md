# DTP (Dynamic Trunking Protocol)

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DTP (Dynamic Trunking Protocol)** is a Cisco-proprietary negotiation that lets two
switch ports agree whether to form a **trunk** or stay **access** — with modes
`desirable`, `auto`, `trunk`, and `access`. It is **off by default security risk**:
automatic trunks are a **VLAN-hopping vector**.

---

## 2. Core Concepts

### 2.1 DTP modes table (the exam matrix)

| Mode (one side) | Peer also trunk-capable? | Result |
|------------------|--------------------------|--------|
| **dynamic desirable** | wants trunk | trunk forms |
| **dynamic auto** | *others* want trunk | trunk forms |
| **trunk** | — | trunk |
| **access** | — | access (never trunk) |
- Mode pairs that result in a trunk:
```
desirable <-> desirable   = YES
desirable <-> auto        = YES
desirable <-> trunk       = YES
auto     <-> trunk        = YES
trunk    <-> trunk        = YES (DTP not even needed)
dynamic auto <-> dynamic auto = NO (both wait)
access <-> anything       = NO
```

### 2.2 How it works
- DTP sends **frames on the native VLAN (untagged)** using a Cisco SNAP/LLC protocol
  (not 802.1Q-aware); the peer's mode determines negotiation outcome.
- On 802.1Q links DTP still runs; on ISL too (legacy).
- Disable with **`switchport nonegotiate`** so the port never sends DTP and never
  becomes a trunk by accident.

### 2.3 Security problem
- A host that "asks" for a trunk (sends DTP desirable) can get a switch to put an
  access port into trunk = **VLAN hopping** (accessing other VLANs).
- Mitigation:
  - `switchport mode access` + `switchport nonegotiate` on user ports.
  - Disable DTP globally/port (§ `switchport nonegotiate`), enable `switchport port-security`.
  - Use `switchport mode trunk` (no negotiation) on real trunks.

### 2.4 DTP vs other negotiation protocols

| Protocol | For | Non-proprietary? |
|----------|-----|------------------|
| DTP | trunk/access mode | Cisco-only |
| VTP | VLAN database sync | Cisco-only (risk) |
| LLDP (standard) | neighbor info / voice | yes |
- DTP and VTP are separate; don't conflate.

### 2.5 Verification
```text
show interfaces Gi0/1 switchport     # shows "Trunking mode: ..." "Trunking VLANS enabled:"
show interfaces trunk
show dtp interface Gi0/1
```
- An unintended "Trunking mode: desirable" on user ports is a red flag.

## 3. Configuration / Commands

```text
# Hard-set user access port (no negotiation)
interface GigabitEthernet0/1
 switchport mode access
 switchport nonegotiate

# Explicit trunk (no negotiation needed either)
interface GigabitEthernet0/24
 switchport mode trunk
 switchport nonegotiate

show dtp
show interfaces switchport | include Trunking mode
```

---

## 4. Exam Traps

- **automatic trunks = security hole** — never leave `dynamic` on user ports.
- **`nonegotiate`** stops DTP on a trunk-conf'd port (trunk stays but no frames sent).
- **access <-> access never trunks; `auto` with `auto` never trunks** — bot table rows
  are precisely tested.
- **DTP is Cisco-proprietary** — interop with non-Cisco = no auto trunks (use static trunk).
- **Doesn't affect VLAN membership** — it negotiates mode only.
