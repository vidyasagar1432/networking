# DTP (Dynamic Trunking Protocol)

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DTP (Dynamic Trunking Protocol)** is a **Cisco-proprietary Layer 2 protocol** used to dynamically negotiate whether a switch-to-switch Ethernet link should operate as a **trunk** or remain a **non-trunk/access link**.

DTP supports these main switchport modes:

- `dynamic desirable`
    
- `dynamic auto`
    
- `trunk`
    
- `access`
    

DTP is primarily relevant to **Cisco switch-to-switch links**. For security, user-facing ports should normally be configured with a **static access mode** and DTP disabled.

> **CCNP Mental Model:**  
> **DTP negotiates whether the link becomes a trunk. It does NOT negotiate which VLANs are allowed on the trunk.**

---

## 2. Core Concepts

### 2.1 DTP Modes

|Mode|Behavior|Trunk Formation|
|---|---|---|
|**dynamic desirable**|Actively attempts to negotiate a trunk|Yes, if peer supports/triggers trunking|
|**dynamic auto**|Passively waits for the peer to initiate|Yes, if peer is `desirable` or `trunk`|
|**trunk**|Forces the port into trunk mode|Yes|
|**access**|Forces the port into access mode|No|
|**nonegotiate**|Stops DTP frames from being sent|Does not itself determine access/trunk mode|

### 2.2 DTP Negotiation Matrix

|Side A|Side B|Trunk Forms?|
|---|---|---|
|`desirable`|`desirable`|**YES**|
|`desirable`|`auto`|**YES**|
|`desirable`|`trunk`|**YES**|
|`auto`|`trunk`|**YES**|
|`trunk`|`trunk`|**YES**|
|`auto`|`auto`|**NO**|
|`access`|`desirable`|**NO**|
|`access`|`auto`|**NO**|
|`access`|`trunk`|**NO**|
|`access`|`access`|**NO**|

### Exam Rule

```text
desirable = actively wants a trunk
auto      = passively waits
trunk     = statically forces trunk
access    = statically forces access

desirable + desirable = trunk
desirable + auto       = trunk
desirable + trunk      = trunk
auto + trunk           = trunk
auto + auto            = NO trunk
access + anything      = NO trunk
```

## 3. How DTP Works

DTP allows Cisco switches to exchange information about their desired trunking state.

DTP frames use Cisco's proprietary protocol encapsulation and are associated with the Cisco multicast MAC:

```text
01:00:0C:CC:CC:CC
```

DTP is separate from the actual trunk encapsulation.

### Important distinction

```text
DTP
└── Negotiates trunking state

802.1Q
└── Tags Ethernet frames with VLAN information

VLAN Allowed List
└── Determines which VLANs can cross the trunk

Native VLAN
└── Determines which VLAN is transmitted untagged
```

DTP therefore does **not** negotiate:

- Which VLANs exist
    
- Which VLANs are allowed
    
- The native VLAN
    
- VLAN membership
    

Those are configured separately.

---

## 4. DTP and Trunk Encapsulation

On modern Cisco networks, **802.1Q** is the standard trunk encapsulation.

Older Cisco platforms also supported **ISL (Inter-Switch Link)**, a Cisco-proprietary trunking encapsulation.

DTP and the trunk encapsulation are separate concepts:

```text
DTP
│
└── Determines whether trunking should occur

802.1Q / ISL
│
└── Determines how VLAN information is carried
```

> **Exam Tip:** Do not confuse **DTP** with **802.1Q**.  
> DTP negotiates trunking; 802.1Q carries VLAN tags.

---

## 5. DTP Security

Dynamic trunk negotiation can create a security risk on user-facing switchports.

An attacker may connect a device capable of generating DTP frames and attempt to make the switch negotiate a trunk. This is commonly associated with **switch spoofing**, which can potentially expose traffic from VLANs that should not be available to the attacker.

### Recommended user-port configuration

```cisco
interface GigabitEthernet0/1
 switchport mode access
 switchport nonegotiate
```

This provides two important controls:

```text
switchport mode access
└── Prevents the port from becoming a trunk

switchport nonegotiate
└── Stops DTP negotiation frames from being sent
```

Additional security controls such as **port security**, unused-port shutdown, and appropriate VLAN assignment may also be used.

---

## 6. Recommended Trunk Configuration

For a known switch-to-switch trunk, explicitly configure both sides.

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport nonegotiate
```

This means:

```text
switchport mode trunk
└── Force trunk operation

switchport nonegotiate
└── Disable DTP negotiation
```

The trunk remains a trunk because its mode is **statically configured**.

> **Important:** `switchport nonegotiate` does **not** convert a port to access mode. It only disables DTP negotiation.

## 7. DTP vs VTP vs LLDP

|Protocol|Purpose|Type|
|---|---|---|
|**DTP**|Negotiates trunking|Cisco proprietary|
|**VTP**|Distributes/synchronizes VLAN database information|Cisco proprietary|
|**LLDP**|Advertises neighbor/device information|IEEE standard|
|**802.1Q**|Carries VLAN tags across trunks|IEEE standard|

### Do not confuse them

```text
DTP
└── "Should this link become a trunk?"

802.1Q
└── "How is VLAN information carried?"

VTP
└── "How can VLAN database information be distributed?"

LLDP
└── "Who is my neighbor and what capabilities does it advertise?"
```

## 8. Configuration Examples

### 8.1 User Access Port

```cisco
interface GigabitEthernet0/1
 description USER-PC
 switchport mode access
 switchport access vlan 10
 switchport nonegotiate
```

Purpose:

```text
Access mode
└── Port remains an access port

VLAN 10
└── Frames belong to VLAN 10

nonegotiate
└── No DTP negotiation
```

---

### 8.2 Static Trunk

```cisco
interface GigabitEthernet0/24
 description SWITCH-UPLINK
 switchport mode trunk
 switchport nonegotiate
```

Optional VLAN controls:

```cisco
 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,30,99
```

Here:

```text
DTP
└── Disabled

Trunk
└── Statically configured

Native VLAN
└── VLAN 99

Allowed VLANs
└── 10,20,30,99
```

## 10. Default DTP Behavior

Historically, many Cisco Catalyst switches used:

```text
dynamic auto
```

as the default administrative switchport mode.

However, **do not treat `dynamic auto` as a universal default for every modern Cisco platform or software release**. Always verify the actual platform/version when documenting production behavior.

The important exam concept is the behavior of the modes, especially:

```text
auto + auto       = NO trunk
desirable + auto  = trunk
desirable + desirable = trunk
```

## 12. Exam Traps

### Trap 1 — `auto + auto`

```text
dynamic auto + dynamic auto
            ↓
        NO TRUNK
```

Both sides are passive.

---

### Trap 2 — `desirable + auto`

```text
dynamic desirable + dynamic auto
            ↓
        TRUNK
```

The desirable side initiates negotiation.

---

### Trap 3 — `nonegotiate`

```text
switchport nonegotiate
```

Does **not** mean:

```text
"Make this port access"
```

It means:

```text
"Stop sending DTP negotiation frames."
```

The port's configured mode still determines whether it operates as access or trunk.

---

### Trap 4 — DTP ≠ 802.1Q

```text
DTP
└── Negotiates trunking

802.1Q
└── VLAN tagging
```

---

### Trap 5 — DTP ≠ VLAN membership

DTP does not decide:

```text
Which VLAN is assigned to a PC
Which VLANs are allowed on a trunk
Which VLAN is the native VLAN
```

Those are separate configuration functions.

---

### Trap 6 — Cisco proprietary

DTP is **Cisco proprietary**.

A non-Cisco device generally should not be expected to participate in Cisco DTP negotiation.

For interoperability, configure trunking explicitly rather than relying on dynamic negotiation.

---

### Trap 7 — `trunk + nonegotiate`

```cisco
switchport mode trunk
switchport nonegotiate
```

The link remains a trunk.

```text
mode trunk
    ↓
forces trunk

nonegotiate
    ↓
disables DTP
```

## 13. Best-Practice Configuration

### User-facing ports

```cisco
interface GigabitEthernet0/1
 description USER-ACCESS
 switchport mode access
 switchport access vlan 10
 switchport nonegotiate
```

### Switch-to-switch trunks

```cisco
interface GigabitEthernet0/24
 description SWITCH-UPLINK
 switchport mode trunk
 switchport nonegotiate
 switchport trunk allowed vlan 10,20,30,99
 switchport trunk native vlan 99
```

### Security principle

```text
USER PORT
│
├── Static access
├── DTP disabled
└── Additional edge security as appropriate

SWITCH UPLINK
│
├── Static trunk
├── DTP disabled
├── Explicit allowed VLANs
└── Explicit native VLAN
```
