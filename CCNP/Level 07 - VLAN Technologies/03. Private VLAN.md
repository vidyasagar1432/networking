# Private VLAN (PVLAN)

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **Private VLAN (PVLAN)** divides a Layer 2 VLAN into smaller forwarding domains  
while allowing hosts to remain within the **same primary VLAN/IP subnet** in the  
common design.

PVLANs provide **Layer 2 isolation without requiring a separate VLAN and subnet for  
every isolated host or group**.

They are useful when multiple devices need to share the same IP subnet but should not  
be able to communicate directly with one another.

Typical use cases include:

- Service-provider or subscriber networks
    
- Hosting environments
    
- Data-center segments
    
- DMZ designs
    
- Shared infrastructure networks
    
- Multi-tenant environments
    

> **Key idea:** PVLANs provide Layer 2 isolation between hosts while allowing selected  
> devices, such as a gateway or shared service, to communicate with all hosts.

---

# 2. PVLAN Architecture

A PVLAN consists of:

```text
Primary VLAN
     │
     ├── Isolated Secondary VLAN
     │
     ├── Community Secondary VLAN A
     │
     └── Community Secondary VLAN B
```

The **primary VLAN** represents the overall PVLAN domain.

The **secondary VLANs** define the isolation relationships.

There are two types of secondary VLANs:

- **Isolated VLAN**
    
- **Community VLAN**
    

---

## 3. PVLAN Port Roles

PVLANs use three major port roles:

|Port Role|Can Communicate With|
|---|---|
|**Promiscuous (P)**|All PVLAN hosts/secondary VLANs|
|**Isolated (I)**|Promiscuous ports only|
|**Community (C)**|Ports in the same community + promiscuous ports|

### 3.1 Promiscuous Port

A **promiscuous port** can communicate with hosts belonging to all associated  
secondary VLANs.

Typical examples:

- Default gateway
    
- Router
    
- Firewall
    
- Load balancer
    
- Shared service
    

Example:

```text
              Router / Firewall
                     │
              Promiscuous Port
                     │
        ┌────────────┼────────────┐
        │            │            │
     Isolated     Community    Community
       Host          A            B
```

> A promiscuous port is **not the same thing as an 802.1Q trunk**. It is a PVLAN  
> port role that permits communication with all associated secondary VLANs.

---

## 4. Isolated Ports

An **isolated port** can communicate with:

```text
Isolated Host → Promiscuous Port
```

but cannot directly communicate with another isolated port.

Example:

```text
        Gateway
           │
     Promiscuous
           │
     ┌─────┼─────┐
     │     │     │
    H1    H2    H3
     │     │     │
     └─X───┴─X───┘
       Isolated
```

H1 cannot directly communicate with H2 or H3.

All isolated hosts can communicate with the promiscuous gateway.

### Typical use

A provider may place many customer devices in an isolated secondary VLAN:

```text
Customer A ─┐
Customer B ─┤
Customer C ─┼── Isolated VLAN
Customer D ─┘
       │
       ▼
   Gateway/Router
```

The customers can reach the gateway but cannot directly communicate with one another.

---

## 5. Community Ports

A **community port** can communicate with:

- Other ports in the **same community**
    
- Promiscuous ports
    

It cannot directly communicate with ports belonging to:

- Another community
    
- An isolated VLAN
    

Example:

```text
              Promiscuous
                   │
          ┌────────┴────────┐
          │                 │
     Community A       Community B
       │     │           │     │
      A1    A2          B1    B2
```

Communication:

```text
A1 ↔ A2       Yes
B1 ↔ B2       Yes

A1 ↔ B1       No

A1 ↔ Gateway  Yes
B1 ↔ Gateway  Yes
```

---

# 6. PVLAN Communication Matrix

|Source|Promiscuous|Same Community|Different Community|Isolated|
|---|--:|--:|--:|--:|
|Promiscuous|Yes|Yes|Yes|Yes|
|Same Community|Yes|Yes|No|No|
|Different Community|Yes|No|Yes|No|
|Isolated|Yes|No|No|No|

The key rule is:

```text
Promiscuous → everyone
Community → same community + promiscuous
Isolated → promiscuous only
```

---

# 7. Primary and Secondary VLANs

### Primary VLAN

The **primary VLAN** represents the main PVLAN domain.

Example:

```text
Primary VLAN 100
```

### Secondary VLANs

Secondary VLANs provide the actual isolation groups.

Example:

```text
Primary VLAN 100
      │
      ├── Isolated VLAN 200
      │
      ├── Community VLAN 300
      │
      └── Community VLAN 400
```

The secondary VLANs are **associated with the primary VLAN**.

---

# 8. PVLAN and IP Subnets

A common PVLAN design places hosts in the **same IP subnet** even though their Layer 2  
communication is restricted.

Example:

```text
Primary VLAN: 100

IP subnet:
192.168.100.0/24
```

Hosts might have:

```text
Host A → 192.168.100.10
Host B → 192.168.100.20
Host C → 192.168.100.30
```

Even though the hosts share the same subnet, PVLAN forwarding rules can prevent:

```text
Host A ↛ Host B
Host A ↛ Host C
Host B ↛ Host C
```

while allowing:

```text
Host A → Gateway
Host B → Gateway
Host C → Gateway
```

> **Important:** “Same subnet” is the common PVLAN design model, not the definition  
> of PVLAN itself. PVLAN is fundamentally a Layer 2 forwarding/isolation mechanism.

---

# 9. Layer 3 Gateway

In the traditional PVLAN design, the Layer 3 gateway is associated with the  
**primary VLAN**.

Example:

```text
             Router / L3 Switch
             192.168.100.1
                    │
             Primary VLAN 100
                    │
       ┌────────────┼────────────┐
       │            │            │
   Isolated      Community    Community
```

The hosts can use:

```text
Default Gateway = 192.168.100.1
```

The gateway can communicate with hosts in the associated secondary VLANs.

> The gateway is not configured as an SVI for each secondary VLAN in the normal  
> single-subnet PVLAN design.

# 10. PVLAN Configuration

PVLAN configuration is platform and IOS/IOS XE dependent. The following illustrates  
the common Cisco IOS configuration model.

## 10.1 Create the Primary VLAN

```cisco
vlan 100
 private-vlan primary
```

## 10.2 Create the Isolated Secondary VLAN

```cisco
vlan 200
 private-vlan isolated
```

## 10.3 Associate the Secondary VLAN

```cisco
vlan 100
 private-vlan association 200
```

The resulting relationship is:

```text
Primary VLAN 100
      │
      └── Isolated VLAN 200
```

---

# 11. Configure an Isolated Host Port

Example:

```cisco
interface GigabitEthernet0/1
 switchport mode private-vlan host
 switchport private-vlan host-association 100 200
```

This associates the host port with:

```text
Primary VLAN   = 100
Secondary VLAN = 200
Type           = Isolated
```

Some Cisco platforms/IOS versions may use slightly different command syntax, so always  
verify the platform-specific syntax.

---

# 12. Configure a Community VLAN

Create the community secondary VLAN:

```cisco
vlan 300
 private-vlan community
```

Associate it with the primary:

```cisco
vlan 100
 private-vlan association 300
```

Configure a community host port:

```cisco
interface GigabitEthernet0/2
 switchport mode private-vlan host
 switchport private-vlan host-association 100 300
```

The result:

```text
Primary VLAN 100
      │
      └── Community VLAN 300
```

Hosts in VLAN 300 can communicate with other hosts in the same community.

---

# 13. Configure a Promiscuous Port

A promiscuous port can communicate with all associated secondary VLANs.

Example:

```cisco
interface GigabitEthernet0/24
 switchport mode private-vlan promiscuous
 switchport private-vlan mapping 100 200,300
```

This maps:

```text
Primary VLAN 100
     │
     ├── Isolated VLAN 200
     └── Community VLAN 300
```

to the promiscuous port.

Typical destination:

```text
Switch → Router
Switch → Firewall
Switch → Load Balancer
```

# 15. PVLAN Traffic Flow Example

Consider:

```text
Primary VLAN 100
IP subnet: 192.168.100.0/24

Secondary VLAN 200 = Isolated
Secondary VLAN 300 = Community A
```

Topology:

```text
                         Gateway
                    192.168.100.1
                           │
                    Promiscuous Port
                           │
             ┌─────────────┴─────────────┐
             │                           │
       Isolated VLAN 200          Community VLAN 300
          │       │                  │       │
         H1      H2                 H3      H4
```

Communication:

```text
H1 → Gateway     ✓
H2 → Gateway     ✓
H3 → Gateway     ✓
H4 → Gateway     ✓

H1 → H2           ✗
H1 → H3           ✗
H1 → H4           ✗

H3 → H4           ✓
H4 → H3           ✓

H3 → H1           ✗
H4 → H2           ✗
```

# 16. PVLAN Across Switches

PVLANs can span multiple switches, but the infrastructure must support PVLANs and  
preserve the required primary/secondary VLAN relationships.

Example:

```text
        Switch 1                    Switch 2
   ┌───────────────┐          ┌───────────────┐
   │ H1  H2        │          │ H3  H4        │
   │ Isolated      │          │ Isolated      │
   └───────┬───────┘          └───────┬───────┘
           │                          │
           └──────── PVLAN ───────────┘
                       │
                  Gateway
```

When troubleshooting a multi-switch PVLAN, verify:

- PVLAN configuration on every switch
    
- Primary/secondary VLAN associations
    
- Required VLANs across trunks
    
- Promiscuous mappings
    
- Host associations
    
- Platform support

# 17. PVLAN vs Normal VLAN Segmentation

|Feature|Normal VLANs + Routing/ACLs|PVLAN|
|---|---|---|
|Layer 2 segmentation|Yes|Yes|
|Same common IP subnet|Usually no|Common design|
|Host-to-host L2 isolation|Requires design/ACLs|Built into PVLAN forwarding rules|
|Secondary VLANs|No|Yes|
|Promiscuous ports|No|Yes|
|Isolated ports|No|Yes|
|Community ports|No|Yes|
|Gateway|Per subnet/VLAN design|Commonly associated with primary VLAN|
|Scaling many isolated hosts|More VLANs/subnets may be needed|Can isolate many hosts within PVLAN domain|

PVLANs are particularly useful when hosts need to remain in the same IP subnet while  
receiving different Layer 2 forwarding permissions.

---

# 18. PVLAN vs `switchport protected`

Cisco also provides **protected ports**, configured with:

```cisco
switchport protected
```

Protected ports provide local Layer 2 isolation between protected ports on the same  
switch.

Example:

```text
Gi0/1 → protected
Gi0/2 → protected

Gi0/1 ↛ Gi0/2
```

However, protected ports and PVLANs are not identical.

### Protected Port

- Simple per-port Layer 2 isolation
    
- Does not create PVLAN secondary VLANs
    
- Useful for local isolation
    
- Limited compared with full PVLAN architecture
    

### PVLAN

- Uses primary and secondary VLANs
    
- Supports isolated and community relationships
    
- Can span supported switch infrastructure
    
- Provides more granular and scalable Layer 2 segmentation
    

> **Exam point:** `switchport protected` is a simpler port-isolation feature, not  
> simply a one-for-one replacement for PVLANs.

# 19. Security Considerations

PVLANs provide **Layer 2 isolation**, but they are not a complete security solution.

PVLANs can help prevent:

```text
Host A → Host B
```

at Layer 2.

However, traffic may still reach:

```text
Host → Gateway → Security Policy → Destination
```

Therefore, additional controls may still be required:

- ACLs
    
- Firewalls
    
- Security groups
    
- Host-based security
    
- Routing policy
    
- Authentication
    
- Monitoring
    

> PVLAN controls Layer 2 forwarding relationships. It does not replace Layer 3 or  
> firewall security policy.

# 20. Common Use Cases

### 20.1 Service Provider / Subscriber Isolation

Multiple subscribers can share a subnet:

```text
             Gateway
                │
         Promiscuous Port
                │
       ┌────────┼────────┐
      C1       C2       C3
   Isolated  Isolated  Isolated
```

Subscribers cannot directly communicate with each other.

---

### 20.2 Hosting / Data Center

Servers can share a subnet while being prevented from directly communicating.

```text
Server 1 ─┐
Server 2 ─┼── Isolated PVLAN
Server 3 ─┤
Server 4 ─┘
      │
      ▼
 Firewall / Load Balancer
```

---

### 20.3 Shared Community

Servers that need to communicate with one another can be placed into the same  
community.

```text
Community A
   │
 ┌─┴─┐
 S1  S2
```

S1 and S2 can communicate with each other while remaining isolated from another  
community.

# 21. Exam Traps

### Trap 1 — PVLAN creates separate IP subnets

**False in the common PVLAN design.**

Hosts can remain in the same IP subnet while PVLAN rules restrict their Layer 2  
communication.

---

### Trap 2 — Isolated hosts can communicate with each other

**False.**

An isolated port can communicate with promiscuous ports but not directly with another  
isolated port.

---

### Trap 3 — Community A can communicate with Community B

**False.**

A community can communicate with members of the **same community** and with  
promiscuous ports.

Different communities are isolated from one another.

---

### Trap 4 — Promiscuous means untrusted

**False.**

In PVLAN terminology, **promiscuous** describes the port's communication permissions.

A promiscuous port can communicate with all associated PVLAN hosts.

---

### Trap 5 — Promiscuous port = trunk

**False.**

A PVLAN promiscuous port is a PVLAN role. It should not be confused with an  
802.1Q trunk.

---

### Trap 6 — The SVI belongs to the isolated VLAN

**Normally false.**

In the common PVLAN design, Layer 3 gateway connectivity is associated with the  
**primary VLAN**.

---

### Trap 7 — PVLAN eliminates the need for VLAN IDs

**False.**

PVLANs still use VLAN IDs.

They use:

```text
Primary VLAN
+
Secondary VLANs
```

---

### Trap 8 — `switchport protected` is exactly the same as PVLAN

**False.**

Protected ports provide local port-to-port isolation, while PVLANs provide a more  
complete primary/secondary VLAN architecture.

---

### Trap 9 — PVLAN replaces all ACLs and firewalls

**False.**

PVLAN provides Layer 2 isolation. Layer 3 and security policies may still be required.

---

### Trap 10 — PVLAN is supported on every Cisco switch

**False.**

PVLAN support and configuration syntax depend on the Cisco platform and software  
version.

Always verify platform support before deploying or labbing PVLANs.

# 23. Key Takeaways

1. **PVLAN provides Layer 2 isolation within a primary VLAN domain.**
    
2. **Hosts can commonly remain in the same IP subnet.**
    
3. **PVLANs use a primary VLAN and secondary VLANs.**
    
4. **Secondary VLANs are either isolated or community.**
    
5. **Isolated hosts can communicate only with promiscuous destinations.**
    
6. **Community hosts can communicate with members of their own community.**
    
7. **Different communities cannot directly communicate.**
    
8. **Promiscuous ports can communicate with all associated PVLAN hosts.**
    
9. **The common Layer 3 gateway is associated with the primary VLAN.**
    
10. **PVLAN is not the same as an 802.1Q trunk.**
    
11. **`switchport protected` provides simpler local port isolation but is not equivalent  
    to full PVLAN functionality.**
    
12. **PVLAN provides Layer 2 isolation but does not replace ACLs or firewalls.**

### One important CCNP memory shortcut

Think of PVLAN as:

```text
                    PROMISCUOUS
                         │
              ┌──────────┼──────────┐
              │          │          │
          ISOLATED   COMMUNITY A  COMMUNITY B
              │          │          │
              X          ↔          ↔
              │
        isolated hosts
        cannot talk
        to each other
````

**The three words to memorize are:**

> **Promiscuous = Everyone**  
> **Isolated = Gateway only**  
> **Community = Group + Gateway**
