# Private VLAN

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **Private VLAN (PVLAN)** partitions a single broadcast-domain VLAN into multiple
**isolated sub-groups** while keeping them in the **same IP subnet** — ports can be
blocked from talking to each other without adding VLANs/ACLs. Ideal for service
providers (one customer subnet, isolated users) and DMZ designs.

---

## 2. Core Concepts

### 2.1 The three port roles

| Role | Permission |
|------|-----------|
| **Promiscuous (P)** | trunk-like: talks to ALL (usually Uplink to router/gateway) |
| **Isolated (I)** | talks ONLY to promiscuous; no isolated↔isolated |
| **Community (C)** | talks to other community ports in same community + promiscuous; no cross-community |
- Protocol: **PVLAN itself uses 802.1Q**; mapping built from a **primary VLAN** and
  secondary (isolated/community) VLANs.

### 2.2 The VLAN structure

| VLAN | Type |
|------|------|
| Primary VLAN | carries all traffic (the "real" subnet) |
| Isolated secondary | flood domain for isolated ports |
| Community secondary | shared between members of that community |
- Mapping: an **isolated secondary** or **community secondary** VLAN maps to the primary.
- Switch fabric: isolated ports never see each others' broadcast/unicast/multicast.

### 2.3 Example use cases
- **ISP/MTU**: one subscriber VLAN, users can't see each other (isolated).
- **DMZ**: web servers isolated per server, only LB/edge can reach them (promiscuous).
- **Shared services**: community VLAN for a printer group inside the same subnet.
- **Special hosts**: management host as promiscuous while user ports isolated.

### 2.4 Configuration essentials (IOS)
```text
vlan 100                        # primary
vlan 200                        # isolated secondary
vlan 300                        # community secondary
! assign ports
interface Gi0/1                 # promiscuous (uplink)
 switchport private-vlan mapping 100 200,300
interface Gi0/2                 # isolated host
 switchport private-vlan host-association 100 200
 switchport private-vlan host mode isolated
```
- Host ports = `host-association` + role; uplink = `mapping` + `promiscuous`.
- L3 SVI sits on the **primary** VLAN only.

### 2.5 PVLAN vs ACL/no-layer-3

| | Separate VLAN + ACL | PVLAN |
|--|---------------------|-------|
| Subnets | different | **same** |
| ACLs | many workload | none at L2 |
| Trunking | more VLANs/hog | one subnet |
| Scale | moderate | excellent (still L3-routed subnet) |
- PVLAN requires switch hardware support; on access typically **PVLAN Edge** = `switchport protected` (simpler, no VLANs).

## 3. Configuration / Commands

```text
# Confirm on switch hardware:
show vlan private-vlan
# Full setup
vlan 100
 private-vlan primary
vlan 200
 private-vlan isolated
vlan 100
 private-vlan association 200
interface Gi0/1
 switchport private-vlan host-association 100 200
 switchport private-vlan host mode isolated
# Promiscuous
interface Gi0/24
 switchport mode promiscuous
 switchport private-vlan mapping 100 200
```

## 4. Exam Traps

- **Same VLAN/subnet but isolated** — the point of PVLAN (most asked).
- **Isolated ports can ONLY reach promiscuous** — the access-permission table.
- **Community ports can reach each other + promiscuous, not other communities.**
- **SVI/gateway lives on the primary** — not the secondary.
- **A PVLAN still uses VLAN IDs** — do not say "no VLAN." 
- **`switchport protected`** = per-port isolation without PVLAN (a lightweight answer).

## 5. Quick Review Table

| Role | Can talk to |
|------|-------------|
| Promiscuous | everyone |
| Isolated | promiscuous only |
| Community | same community + promiscuous |
| Primary VLAN | gateway subnet |
| Isolation | at L2, no ACL needed |
| Uplink role | promiscuous + mapping |
| Host role | isolated/community association |
| Lite version | switchport protected |
