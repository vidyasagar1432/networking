# Inter-VLAN Routing

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Inter-VLAN routing** allows devices in different VLANs to communicate by forwarding traffic between their Layer 3 IP subnets.

A VLAN creates a separate **Layer 2 broadcast domain**. When different VLANs use different IP subnets, communication between them requires an **Layer 3 gateway/router interface**.

The three major implementation models are:

1. **Router-on-a-Stick (ROAS)** — router subinterfaces over an 802.1Q trunk
    
2. **SVI-based routing** — multilayer switch routes using Switch Virtual Interfaces
    
3. **Routed access** — Layer 3 routed links are used instead of Layer 2 trunks between network layers
    

> **CCNP Mental Model:**  
> **VLAN = Layer 2 boundary → IP subnet = Layer 3 boundary → L3 gateway = forwards traffic between subnets**

---

## 2. Why Inter-VLAN Routing Is Required

Consider:

```text
VLAN 10 → 10.1.10.0/24
VLAN 20 → 10.1.20.0/24
```

A host in VLAN 10:

```text
10.1.10.10
```

wants to communicate with:

```text
10.1.20.20
```

The destination is on a different IP subnet.

The host therefore sends the packet to its **default gateway**:

```text
10.1.10.1
```

The Layer 3 device then routes the packet toward VLAN 20.

### Packet flow

```text
Host A
10.1.10.10
VLAN 10
   │
   │ Destination = 10.1.20.20
   │
   ▼
Default Gateway
10.1.10.1
   │
   │ Layer 3 routing
   ▼
VLAN 20 Gateway
10.1.20.1
   │
   ▼
Host B
10.1.20.20
VLAN 20
```

The Layer 2 broadcast domains remain separate.

# 3. Three Inter-VLAN Routing Designs

|Method|L3 Gateway Location|Main Interface Type|Typical Use|
|---|---|---|---|
|**Router-on-a-Stick**|Router|Subinterfaces|Small/simple networks|
|**SVI Routing**|Multilayer switch|`interface VlanX`|Campus networks|
|**Routed Access**|L3 switch/router|Routed physical interface|Modern routed campus designs|

# 4. Router-on-a-Stick (ROAS)

**Router-on-a-Stick** uses one physical router interface connected to a switch through an **802.1Q trunk**.

The router creates one subinterface per VLAN.

```text
                 Router
             ┌─────────────┐
             │             │
             │ Gi0/0       │
             │  .10        │ → VLAN 10 Gateway
             │  .20        │ → VLAN 20 Gateway
             └──────┬──────┘
                    │
              802.1Q Trunk
                    │
             ┌──────┴──────┐
             │   Switch    │
             └─────────────┘
               │          │
            VLAN 10     VLAN 20
```

## 4.1 Router Configuration

```cisco
interface GigabitEthernet0/0
 no ip address
 no shutdown

interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 10.1.10.1 255.255.255.0

interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 10.1.20.1 255.255.255.0
```

The router uses:

```text
Gi0/0.10
└── VLAN 10 gateway = 10.1.10.1

Gi0/0.20
└── VLAN 20 gateway = 10.1.20.1
```

## 4.2 Switch Configuration

The switch port connected to the router must operate as a trunk.

```cisco
interface GigabitEthernet0/24
 description ROUTER-UPLINK
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

## 4.3 Host Configuration

VLAN 10 host:

```text
IP address:      10.1.10.10/24
Default gateway: 10.1.10.1
```

VLAN 20 host:

```text
IP address:      10.1.20.20/24
Default gateway: 10.1.20.1
```

---

# 5. Router-on-a-Stick Traffic Flow

Suppose:

```text
Host A = 10.1.10.10
Host B = 10.1.20.20
```

Traffic flows:

```text
Host A
   │
   │ VLAN 10
   ▼
Switch
   │
   │ 802.1Q VLAN 10
   ▼
Router Gi0/0.10
   │
   │ Layer 3 routing
   ▼
Router Gi0/0.20
   │
   │ 802.1Q VLAN 20
   ▼
Switch
   │
   │ VLAN 20
   ▼
Host B
```

The router receives the packet, performs an L3 routing decision, and sends the packet back toward the switch using the destination VLAN.

---

# 6. Router-on-a-Stick Advantages and Disadvantages

### Advantages

- Simple
    
- Low cost
    
- Requires only one physical router interface
    
- Useful for small networks and labs
    

### Disadvantages

- One physical link carries traffic for multiple VLANs
    
- Link bandwidth can become a bottleneck
    
- Router must process the inter-VLAN traffic
    
- Less scalable than hardware-based L3 switching
    

> **Exam Mental Model:**  
> **ROAS = simple but centralized.**

# 7. SVI-Based Inter-VLAN Routing

A **Switch Virtual Interface (SVI)** is a logical Layer 3 interface associated with a VLAN.

Example:

```cisco
interface Vlan10
 ip address 10.1.10.1 255.255.255.0

interface Vlan20
 ip address 10.1.20.1 255.255.255.0
```

On a multilayer switch, these SVIs can act as the default gateways for hosts.

```text
             Multilayer Switch
        ┌─────────────────────────┐
        │                         │
        │ SVI VLAN 10             │
        │ 10.1.10.1               │
        │                         │
        │ SVI VLAN 20             │
        │ 10.1.20.1               │
        │                         │
        │ Layer 3 Routing         │
        └─────────────────────────┘
             │              │
          VLAN 10         VLAN 20
```

---

# 8. Enabling Layer 3 Routing

On a Cisco multilayer switch:

```cisco
ip routing
```

Then configure the SVIs:

```cisco
ip routing

interface Vlan10
 ip address 10.1.10.1 255.255.255.0
 no shutdown

interface Vlan20
 ip address 10.1.20.1 255.255.255.0
 no shutdown
```

Now the switch can route between the connected VLAN subnets.

### Important distinction

An SVI can exist without the switch acting as an inter-VLAN router.

```text
SVI
└── Logical Layer 3 interface for a VLAN

ip routing
└── Enables the multilayer switch to perform IP routing
```

Therefore:

> **Do not memorize “SVI = `ip routing`.”**  
> Instead remember: **`ip routing` enables Layer 3 routing between interfaces/SVIs on a multilayer switch.**

---

# 9. SVI Requirements

For an SVI to become operational, the associated VLAN and Layer 2 conditions must be valid.

Example:

```cisco
vlan 10
vlan 20

interface Vlan10
 ip address 10.1.10.1 255.255.255.0

interface Vlan20
 ip address 10.1.20.1 255.255.255.0
```

If the SVI is not operational, verify:

```cisco
show vlan brief
show interfaces vlan 10
show ip interface brief
```

Also verify that the VLAN exists and has an active Layer 2 port where appropriate.

# 10. Hardware-Based L3 Forwarding

Modern multilayer switches perform Layer 3 forwarding using **hardware-based switching/forwarding ASICs** and platform-specific forwarding tables.

This provides high-speed forwarding compared with sending every packet to a software-only router process.

Conceptually:

```text
SVI
 │
 ▼
Routing Decision
 │
 ▼
Hardware Forwarding
 │
 ▼
Destination VLAN
```

Cisco platforms use forwarding architectures such as **CEF concepts** and hardware tables/TCAM, but the exact implementation varies by Catalyst platform and architecture.

> **CCNP Tip:**  
> Say **hardware-assisted/hardware-based Layer 3 forwarding** rather than assuming every Catalyst platform forwards exactly the same way internally.

---

# 11. Routed Access

A **routed access design** uses Layer 3 links between network devices rather than extending Layer 2 VLANs across those links.

A physical switch interface can be converted into a routed Layer 3 interface:

```cisco
interface GigabitEthernet1/0/1
 no switchport
 ip address 10.255.1.1 255.255.255.252
```

The opposite device can use:

```cisco
interface GigabitEthernet1/0/1
 no switchport
 ip address 10.255.1.2 255.255.255.252
```

Now the link is:

```text
Layer 3 point-to-point link
```

rather than:

```text
Layer 2 trunk
```

---

# 12. Routed Access Architecture

Traditional three-tier campus:

```text
Access
   │
   │ Layer 2
   ▼
Distribution
   │
   │ Layer 3
   ▼
Core
```

Routed access design:

```text
Access
   │
   │ Layer 3
   ▼
Distribution/Core
```

The exact architecture depends on the campus design.

Routed access can reduce Layer 2 domain size and simplify spanning-tree boundaries.

> **Important:** Do not treat routed access as universally superior. Traditional three-tier designs and modern routed designs are both valid depending on requirements.

# 13. Inter-VLAN Routing with SVI

Example:

```text
VLAN 10
10.1.10.0/24
Gateway = 10.1.10.1

VLAN 20
10.1.20.0/24
Gateway = 10.1.20.1
```

Configuration:

```cisco
ip routing

vlan 10
vlan 20

interface Vlan10
 ip address 10.1.10.1 255.255.255.0
 no shutdown

interface Vlan20
 ip address 10.1.20.1 255.255.255.0
 no shutdown
```

The switch automatically has connected routes for the directly connected SVI networks.

```text
10.1.10.0/24 → VLAN 10
10.1.20.0/24 → VLAN 20
```

---

# 14. Routing Beyond the VLANs

Inter-VLAN routing does not stop at the local SVIs.

A multilayer switch can also route toward other networks using:

- Connected routes
    
- Static routes
    
- OSPF
    
- EIGRP
    
- BGP
    
- Other supported routing protocols
    

Example:

```text
                Core
                 │
            OSPF / Static
                 │
        ┌────────┴────────┐
        │  L3 Switch      │
        │                 │
        │ SVI VLAN 10     │
        │ SVI VLAN 20     │
        └───────┬─────────┘
             │       │
          VLAN 10  VLAN 20
```

The SVI provides the local VLAN gateway; the routing table determines how traffic reaches remote networks.

---

# 15. Policy at the L3 Boundary

The Layer 3 gateway is an important enforcement point for segmentation.

Example:

```text
VLAN 10 = Employees
VLAN 20 = Guests
VLAN 30 = Management
```

An ACL can implement policies such as:

```text
Employees → Servers     ALLOW
Guests → Servers        DENY
Guests → Internet       ALLOW
Management → Devices    ALLOW
```

Conceptually:

```text
VLAN
 │
 ▼
SVI / L3 Gateway
 │
 ├── Routing
 │
 ├── ACL
 │
 └── QoS / Other L3 Policy
 │
 ▼
Destination Network
```

The exact location of ACLs and QoS policies depends on the network design.

# 16. Native VLAN on Router-on-a-Stick

The native VLAN is transmitted **untagged** on an 802.1Q trunk.

For router-on-a-stick, the router can explicitly identify a native VLAN using:

```cisco
interface GigabitEthernet0/0.99
 encapsulation dot1Q 99 native
 ip address 10.1.99.1 255.255.255.0
```

The important point is:

```text
encapsulation dot1Q 99 native
            │
            └── VLAN 99 is handled as the native VLAN
```

It is incorrect to say that every ROAS subinterface automatically represents an untagged VLAN.

> **Exam Trap:**  
> A normal `encapsulation dot1Q 10` subinterface expects VLAN 10 tagging.  
> `encapsulation dot1Q 99 native` explicitly identifies VLAN 99 as native/untagged.

```cisco

```

Look for:

```text
Vlan10    10.1.10.1    up    up
Vlan20    10.1.20.1    up    up
```

```cisco
show ip route
```

You should see connected routes such as:

```text
C    10.1.10.0/24 is directly connected, Vlan10

```

### Check VLANs

```cisco
show vlan brief
```

### Check trunk

```cisco
show interfaces trunk
```

### Test connectivity

```cisco
ping 10.1.20.20 source 10.1.10.1
```

The source address must be configured and operational on the device.

### Trace the path

```cisco
traceroute 10.1.20.20
```

# 18. Troubleshooting Flow

When inter-VLAN routing fails, troubleshoot from Layer 2 toward Layer 3.

```text
1. Is the VLAN created?
        │
        ▼
2. Is the host in the correct VLAN?
        │
        ▼
3. Is the trunk carrying the VLAN?
        │
        ▼
4. Is the SVI/subinterface operational?
        │
        ▼
5. Is the host using the correct default gateway?
        │
        ▼
6. Does the L3 device have the connected route?
        │
        ▼
7. Are ACLs blocking the traffic?
        │
        ▼
8. Is the return route correct?
```

Useful commands:

```cisco
show vlan brief
show interfaces trunk
show interfaces switchport
show ip interface brief
show ip route
show arp
show mac address-table
show access-lists
```

# 19. Exam Traps

### Trap 1 — VLANs do not route by themselves

```text
VLAN 10 ─────X───── VLAN 20
             │
        L3 required
```

A Layer 2 switch cannot route traffic between separate IP subnets.

---

### Trap 2 — Default gateway

Hosts need a default gateway corresponding to their VLAN/subnet.

```text
VLAN 10
Host → 10.1.10.1

VLAN 20
Host → 10.1.20.1
```

---

### Trap 3 — ROAS requires 802.1Q subinterfaces

```cisco
interface Gi0/0.10
 encapsulation dot1Q 10
```

Without the correct VLAN encapsulation configuration, the router does not know which VLAN the subinterface represents.

---

### Trap 4 — SVI ≠ routing automatically

```text
interface Vlan10
```

creates/configures an SVI.

```cisco
ip routing
```

enables Layer 3 routing on a multilayer switch.

Keep those concepts separate.

---

### Trap 5 — Native VLAN

Normal:

```cisco
encapsulation dot1Q 10
```

Native:

```cisco
encapsulation dot1Q 99 native
```

The `native` keyword matters.

---

### Trap 6 — Routed interface

A routed interface uses:

```cisco
no switchport
```

Example:

```cisco
interface GigabitEthernet1/0/1
 no switchport
 ip address 10.255.1.1 255.255.255.252
```

This is different from a Layer 2 switchport.

---

### Trap 7 — ROAS vs SVI

```text
ROAS
└── Router subinterfaces

SVI
└── Multilayer switch VLAN interfaces
```

---

### Trap 8 — Routing ≠ switching

Within the same VLAN:

```text
Host A ── Layer 2 switching ── Host B
```

Between different IP subnets:

```text
Host A
   │
   ▼
Default Gateway
   │
   ▼
Layer 3 Routing
   │
   ▼
Destination Subnet
```

# 20. Comparison Table

|Feature|Router-on-a-Stick|SVI Routing|Routed Access|
|---|---|---|---|
|L3 device|Router|Multilayer switch|L3 switch/router|
|Gateway|Router subinterface|SVI|L3 interface/SVI depending on design|
|Link between devices|802.1Q trunk|Usually Layer 2/Layer 3 depending on topology|Layer 3 routed link|
|VLAN trunk required|Yes|Not inherently for routing itself|No for the routed uplink|
|Scalability|Lower|High|High|
|Main bottleneck|Shared router link|Depends on platform/design|Depends on routed topology|
|Common use|Small/simple sites|Campus|Modern routed campus|
|Configuration complexity|Low/medium|Medium|Medium|
|Hardware L3 forwarding|Router-dependent|Multilayer-switch ASICs|L3 forwarding|
|Typical gateway|Subinterface|SVI|L3 gateway/interface|
|Layer 2 domain size|Can extend across trunk|Design dependent|Smaller L2 domains|
