# VLAN

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **VLAN (Virtual Local Area Network)** logically divides a Layer 2 switched network into  
multiple **broadcast domains**.

Devices in the same VLAN can communicate at Layer 2, while devices in different VLANs  
are isolated at Layer 2 and require **Layer 3 routing** for communication.

VLANs provide:

- Logical segmentation without separate physical switches
    
- Broadcast-domain separation
    
- Better scalability and organization
    
- Separation of users, servers, voice, management, and other traffic
    

> **Key idea:** A VLAN is a **Layer 2 broadcast domain**. An IP subnet is a **Layer 3  
> addressing/routing domain**. They are related in normal designs but are not the same thing.

---

## 2. Core Concepts

### 2.1 What a VLAN actually does

|Flat Network|VLAN-Based Network|
|---|---|
|One large broadcast domain|Multiple broadcast domains|
|All ports belong to the same L2 domain|Ports are separated into VLANs|
|Broadcast traffic reaches all ports in the domain|Broadcast traffic is contained within its VLAN|
|Limited logical segmentation|Users, servers, voice, and management can be separated|
|Usually one IP subnet|Typically one IP subnet per VLAN|

A switch maintains VLAN membership and uses it when making Layer 2 forwarding decisions.

An Ethernet frame received from an **access port** is normally untagged. The switch  
associates that frame internally with the port's configured VLAN.

When multiple VLANs traverse a **trunk link**, 802.1Q tagging is normally used to identify  
the VLAN to which each frame belongs.

> **Important:** Access-port traffic is normally untagged; trunk links normally carry  
> multiple VLANs using 802.1Q tags.

---

## 3. VLAN Identification and VLAN IDs

802.1Q provides a **12-bit VLAN Identifier (VID)**.

|VLAN ID|Meaning|
|---|---|
|0|Reserved; indicates priority tagging rather than a specific VLAN|
|1–4094|Usable VLAN IDs|
|4095|Reserved|
|1002–1005|Legacy Cisco default VLANs associated with FDDI/Token Ring|

Therefore:

**12-bit VID → 4096 possible values → 4094 usable VLAN IDs**

### 3.1 Cisco VLAN ranges

Cisco IOS/IOS XE commonly distinguishes:

|Range|Description|
|---|---|
|1|Default VLAN|
|2–1001|Normal VLAN range|
|1002–1005|Legacy VLANs|
|1006–4094|Extended VLAN range|

> Exact VLAN capabilities and restrictions can vary by Cisco platform and software  
> release.

### 3.2 VLAN 1

**VLAN 1** is the default VLAN on Cisco switches.

Important characteristics:

- It exists by default.
    
- Switch ports are assigned to VLAN 1 by default.
    
- It cannot normally be deleted on Cisco switches.
    
- It is the default native VLAN on many Cisco switch configurations.
    
- Control-plane protocols may use VLAN 1 depending on the protocol/platform.
    

### Security best practice

It is common to avoid using VLAN 1 for normal user/data traffic and to explicitly define  
native VLAN and allowed VLAN policies.

However:

> **Changing the native VLAN is not, by itself, a security control.**

Security comes from correct VLAN configuration, trunk restrictions, access controls,  
switch hardening, and Layer 3 policy.

---

## 4. VLAN Membership

A switch port can operate as an **access port** or a **trunk port**.

### Access Port

An access port normally belongs to a single VLAN.

Example:

```cisco
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10
```

An untagged frame received from the device is associated with VLAN 10.

### Trunk Port

A trunk can carry traffic for multiple VLANs between network devices.

Example:

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

Frames belonging to VLANs on the trunk are normally identified using **802.1Q tags**.

> Native VLAN traffic is the important exception: frames transmitted for the native VLAN  
> are normally sent **untagged** on an 802.1Q trunk unless the platform/configuration  
> explicitly uses native-VLAN tagging.

---

## 5. VLANs and Broadcast Domains

Each VLAN represents a separate Layer 2 broadcast domain.

For example:

```text
VLAN 10 → Users
VLAN 20 → Servers
VLAN 30 → Voice
VLAN 40 → Management
```

A broadcast generated in VLAN 10 is forwarded only within the VLAN 10 Layer 2 domain.

It does not automatically cross into VLAN 20, VLAN 30, or VLAN 40.

### Broadcast containment

VLANs contain Layer 2 broadcast traffic such as:

- ARP broadcasts
    
- DHCP Discover broadcasts
    
- Other Ethernet broadcasts
    

This reduces the size of individual broadcast domains and provides logical  
segmentation.

> VLANs provide **Layer 2 segmentation**, not complete security isolation.

---

## 6. VLAN and IP Subnet Relationship

A VLAN and an IP subnet are different concepts.

### VLAN

- Layer 2 concept
    
- Identifies a broadcast domain
    
- Used by switches for Layer 2 segmentation
    

### IP Subnet

- Layer 3 concept
    
- Defines an IP addressing and routing boundary
    
- Used by routers and Layer 3 switches
    

### Normal enterprise design

The common design is:

```text
VLAN 10 ↔ 10.10.10.0/24
VLAN 20 ↔ 10.10.20.0/24
VLAN 30 ↔ 10.10.30.0/24
```

This makes each VLAN correspond to one IP subnet and allows a Layer 3 gateway/SVI to  
provide inter-VLAN routing.

> **Best practice:** One VLAN ↔ one IP subnet is the normal enterprise design model,  
> but VLANs and subnets are technically different concepts.

---

## 7. Inter-VLAN Communication

Devices in different VLANs cannot communicate directly through normal Layer 2  
switching.

They require a **Layer 3 device**, such as:

- Router
    
- Layer 3 switch
    
- Firewall
    

A Layer 3 switch commonly uses **SVIs (Switch Virtual Interfaces)**.

Example:

```cisco
interface Vlan10
 ip address 10.10.10.1 255.255.255.0
 no shutdown

interface Vlan20
 ip address 10.10.20.1 255.255.255.0
 no shutdown
```

The SVI becomes the default gateway for hosts in that VLAN.

```text
        Layer 3 Switch
       ┌───────────────┐
       │ VLAN 10 SVI   │ 10.10.10.1
       │ VLAN 20 SVI   │ 10.10.20.1
       └───────┬───────┘
               │
       Inter-VLAN Routing
```

Traffic from VLAN 10 to VLAN 20 must therefore pass through Layer 3 routing.

## 9. VLAN Trunking

A trunk is used when multiple VLANs must traverse a single physical link.

Common examples:

```text
Switch ↔ Switch
Switch ↔ Router
Switch ↔ Firewall
Switch ↔ Hypervisor
```

Example:

```text
             802.1Q Trunk
      ┌────────────────────────┐
      │ VLAN 10,20,30,40       │
      ▼                        ▼
┌──────────┐              ┌──────────┐
│ Switch 1 │──────────────│ Switch 2 │
└──────────┘              └──────────┘
```

The trunk carries multiple VLANs while maintaining their logical separation.

### Allowed VLANs

A trunk should carry only the VLANs that are actually required.

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

This reduces unnecessary VLAN propagation and limits the scope of potential Layer 2  
problems.

---

## 10. Native VLAN

On an 802.1Q trunk, the **native VLAN** is the VLAN whose traffic is normally sent  
untagged.

Example:

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk native vlan 999
```

Both ends of the trunk should agree on the native VLAN.

A native VLAN mismatch can cause connectivity problems and Cisco may report a  
native-VLAN mismatch.

### Best practice

A commonly used design is:

- Use a dedicated unused/native VLAN where appropriate.
    
- Do not use the native VLAN for normal user traffic.
    
- Ensure both trunk endpoints use the same native VLAN.
    
- Explicitly control the allowed VLAN list.
    

---

## 11. VLAN Security and Segmentation

VLANs provide **logical Layer 2 separation**, but they should not be treated as a complete  
security boundary.

For example:

```text
VLAN 10 → Users
VLAN 20 → Servers
VLAN 30 → Guest
VLAN 40 → Management
```

Inter-VLAN traffic can be controlled with:

- ACLs
    
- Firewall policies
    
- Security policies
    
- VRFs
    
- Authentication and access-control mechanisms
    
- Switch security features
    

A compromised host inside VLAN 10 can still attack other devices in VLAN 10.

Therefore:

> VLAN segmentation reduces the Layer 2 scope of traffic, but additional security  
> controls are required for strong isolation.

---

## 12. VLAN Design Guidelines

Common enterprise design practices include:

### Separate traffic types

Use dedicated VLANs where appropriate for:

- User/data traffic
    
- Servers
    
- Voice
    
- Wireless clients
    
- Guest access
    
- Network management
    
- Infrastructure services
    

### Keep VLANs appropriately sized

Avoid unnecessarily large broadcast domains.

### Use meaningful VLAN IDs and names

Example:

```text
VLAN 10  USERS
VLAN 20  SERVERS
VLAN 30  VOICE
VLAN 40  MANAGEMENT
VLAN 50  GUEST
VLAN 999 NATIVE
```

### Restrict trunk VLANs

Allow only required VLANs:

```cisco
switchport trunk allowed vlan 10,20,30
```

### Avoid unnecessary use of VLAN 1

Do not rely on merely changing VLAN 1 or the native VLAN as a standalone security  
mechanism.

## 13. VLANs in Modern Cisco Networks

Traditional campus networks commonly use:

```text
Access VLANs
     ↓
802.1Q Trunks
     ↓
Layer 3 SVIs
     ↓
Inter-VLAN Routing
```

Modern Cisco architectures can extend segmentation beyond traditional VLANs.

### VXLAN

**VXLAN (Virtual Extensible LAN)** uses a **24-bit VNI (VXLAN Network Identifier)** to  
identify VXLAN segments.

This provides a much larger segmentation namespace than traditional 12-bit VLAN IDs.

Conceptually:

```text
Traditional Campus
VLAN → 12-bit VLAN ID

VXLAN Fabric
VNI → 24-bit VXLAN Network Identifier
```

VXLAN does not simply replace VLANs in every context; VLANs may still exist at the  
access/edge of the network while VXLAN provides the overlay segmentation.

In Cisco **SD-Access**, VXLAN is used as part of the fabric data plane and segmentation  
architecture.

# 14. Exam Traps

### Trap 1 — VLAN = subnet

**False.**

A VLAN is a Layer 2 broadcast domain.

An IP subnet is a Layer 3 addressing/routing concept.

---

### Trap 2 — Access ports tag frames

**Normally false.**

Frames received from normal end hosts on access ports are untagged.

The switch internally associates them with the configured access VLAN.

---

### Trap 3 — Trunks are untagged

**Normally false.**

802.1Q trunks normally use VLAN tags to identify VLAN membership.

The native VLAN is normally transmitted untagged.

---

### Trap 4 — VLAN 1 carries all VLANs

**False.**

VLAN 1 is simply one VLAN.

A trunk can carry VLAN 1 together with other allowed VLANs, but VLAN 1 does not  
"carry" the other VLANs.

---

### Trap 5 — VLAN 1 is a security feature

**False.**

VLAN 1 is the default VLAN and cannot normally be deleted on Cisco switches.

Avoiding VLAN 1 for user traffic may be a design practice, but VLAN 1 itself does not  
provide additional security.

---

### Trap 6 — Changing the native VLAN automatically secures a trunk

**False.**

Changing the native VLAN can help avoid certain design and attack scenarios, but it is  
not sufficient security by itself.

---

### Trap 7 — VLAN 1006–4094 always require `vlan database`

**False.**

Modern Cisco IOS/IOS XE platforms generally use normal configuration mode:

```cisco
vlan 1006
 name EXTENDED_VLAN
```

Older Cisco platforms/software may have different VLAN configuration mechanisms.

Always consider the platform and IOS/IOS XE release.

---

### Trap 8 — VLANs provide complete security isolation

**False.**

VLANs provide Layer 2 segmentation.

Inter-VLAN traffic can still be routed, and additional security controls are required  
when strong isolation is needed.

---

### Trap 9 — VLAN 0 is a normal VLAN

**False.**

VLAN ID 0 is reserved and is used for priority-tagged frames; it does not identify a  
normal VLAN.

---

### Trap 10 — VLAN 4095 is usable

**False.**

VLAN ID 4095 is reserved.

The usable 802.1Q VID range is **1–4094**.

## 17. Key Takeaways

1. **VLAN = Layer 2 broadcast domain.**
    
2. **Different VLANs require Layer 3 routing to communicate.**
    
3. **Access-port host traffic is normally untagged.**
    
4. **802.1Q trunks normally use VLAN tags.**
    
5. **Native VLAN traffic is normally untagged.**
    
6. **VLAN 1 is the default VLAN, not a security mechanism.**
    
7. **Usable 802.1Q VLAN IDs are 1–4094.**
    
8. **One VLAN ↔ one IP subnet is the normal enterprise design model.**
    
9. **VLANs provide segmentation, not complete security.**
    
10. **VXLAN extends segmentation using a 24-bit VNI.**
    
11. **Always verify VLAN membership, trunk state, allowed VLANs, and native VLAN when  
    troubleshooting VLAN connectivity.**
