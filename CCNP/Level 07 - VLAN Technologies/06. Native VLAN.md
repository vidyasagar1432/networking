# Native VLAN

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **native VLAN** is the one VLAN on a **802.1Q trunk** that is sent **untagged**.
Both ends must agree on it; mismatch produces the classic "strange connectivity across
one VLAN" failure and is a security angle for **double-tagging / VLAN hopping**.

---

## 2. Core Concepts

### 2.1 The untagged exception
- On a trunk all frames are tagged **except** those of the native VLAN (default **1**).
- Both switches assume anything untagged belongs to *their* configured native VLAN.
- Router subinterfaces: native VLAN often maps to the **untagged subinterface** for L3.

```
Trunk frame (VLAN 10):   [tag 10]
Trunk frame (native 1):  [no tag]
```

### 2.2 Why it exists
- Backward compatibility: an untagged device (e.g., old access-style peer) can still
  plug into a trunk and talk (VLAN 1).
- Keeps "no-tag" frames meaningful — CDP, DTP, PAgP often ride untagged (native).

### 2.3 Native VLAN mismatch — symptoms

| Symptom | Why |
|---------|-----|
| Device on VLAN 10 unreachable cross-trunk | frames between mismatched natives are misinterpreted |
| Broadcast loop-ish messages | frames injected into wrong VLAN |
| CDP shows native-mismatch error | switches tell each other |
| Silent breakage on one VLAN | other VLANs still forward fine |
- Mismatch can also enable **VLAN hopping**: attacker double-tags, native forward
  gives access to another VLAN.

### 2.4 Best practices
- **Change native away from VLAN 1** (e.g., 999) IF consistent across the fabric.
- Or explicitly **block VLAN 1** (`allowed vlan remove 1`) where unused.
- Keep the same native on both ends of every trunk.
- Use **private VLAN edge**/VACL hardening to reduce hopping risk (Level 07/17).

### 2.5 Verification commands
```text
show interfaces trunk                    # Native  VLAN: 999 (if set)
show interfaces Gi0/24 tag? no — switchport
show interfaces Gi0/24 switchport | include Native
show cdp neighbors detail                # shows native mismatch warning
```

---

## 3. Configuration / Commands

```text
interface GigabitEthernet0/24
 switchport trunk native vlan 999
 switchport mode trunk

# verify consistent on both ends of the trunk
show interfaces trunk
# optional security hardening
switchport trunk allowed vlan remove 1     # drop VLAN 1 from this trunk
```

---

## 4. Exam Traps

- **Native = untagged on a trunk** — the "which frames are untagged?" answer.
- **Default is VLAN 1** — both ends; changing only one end = mismatch.
- **Mismatch breaks the NATIVE VLAN's traffic, not the tagged ones.**
- **VLAN hopping via double tagging** ties native to security (Level 17).
- **Router side**: native VLAN commonly = untagged-only subinterface or the physical
  interface in router-on-a-stick (Level 07).
