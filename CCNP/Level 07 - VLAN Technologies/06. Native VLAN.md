# Native VLAN

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **native VLAN** is the VLAN associated with **untagged traffic on an 802.1Q trunk**.

On a Cisco 802.1Q trunk, normal VLAN traffic is tagged with an 802.1Q VLAN ID, while traffic belonging to the native VLAN is **normally transmitted without an 802.1Q tag**.

Both ends of a trunk should use the **same native VLAN**. A native VLAN mismatch causes the two switches to interpret untagged frames as belonging to different VLANs.

> **CCNP Mental Model**
> 
> ```text
> NATIVE VLAN
> │
> ├── Exists on an 802.1Q trunk
> │
> ├── Untagged traffic
> │     └── Normally associated with native VLAN
> │
> ├── Default Cisco native VLAN
> │     └── VLAN 1
> │
> ├── Both trunk ends
> │     └── Should use the same native VLAN
> │
> ├── Native VLAN mismatch
> │     └── Untagged traffic classified differently
> │
> └── Security
>       └── Important in VLAN-hopping considerations
> ```

## 2. Core Concepts

### 2.1 The Untagged Exception

An 802.1Q trunk normally uses VLAN tags to identify VLAN traffic.

Example:

```text
VLAN 10:
[Ethernet Frame][802.1Q Tag: VLAN 10]

VLAN 20:
[Ethernet Frame][802.1Q Tag: VLAN 20]

Native VLAN 999:
[Ethernet Frame][NO 802.1Q TAG]
```

Therefore:

> **Native VLAN = VLAN associated with untagged traffic on the trunk.**

It is important not to say that a trunk simply "removes the tag" from every native-VLAN frame in every circumstance. The key operational concept is that **native VLAN traffic is normally transmitted untagged**.

---

## 3. Default Native VLAN

On many Cisco switches, the default native VLAN is:

```text
VLAN 1
```

You can change it:

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk native vlan 999
```

Now:

```text
Tagged:
  VLAN 10 → 802.1Q tagged
  VLAN 20 → 802.1Q tagged
  VLAN 30 → 802.1Q tagged

Untagged:
  VLAN 999 → Native VLAN
```

> **Exam trap:**  
> Native VLAN is **not inherently VLAN 1**. VLAN 1 is simply the common default.

---

## 4. Why the Native VLAN Exists

The native VLAN provides a defined VLAN association for **untagged traffic on an 802.1Q trunk**.

This is useful because not every Ethernet frame traversing a trunk necessarily carries an 802.1Q tag.

Cisco Layer 2 control protocols can also use untagged Ethernet frames. Examples include:

- CDP
    
- DTP
    
- PAgP
    

However, these control-plane frames should **not be thought of simply as ordinary data frames belonging to the native VLAN**. Their handling is protocol/platform dependent.

> **CCNP distinction:**  
> "Untagged frame" does not automatically mean "ordinary user data belonging to the native VLAN." Control protocols can have their own Layer 2 handling.

---

## 5. Native VLAN on Both Ends

Both ends of a trunk should agree on the native VLAN.

Correct:

```text
Switch A                         Switch B

Native VLAN 999                  Native VLAN 999
      │                                │
      └──────────── TRUNK ─────────────┘
```

Incorrect:

```text
Switch A                         Switch B

Native VLAN 999                  Native VLAN 100
      │                                │
      └──────────── TRUNK ─────────────┘
```

With a mismatch:

- Switch A interprets an untagged frame as VLAN 999.
    
- Switch B interprets the same untagged frame as VLAN 100.
    

This can cause:

- Unexpected Layer 2 connectivity
    
- Misclassification of untagged traffic
    
- One-VLAN connectivity problems
    
- CDP native-VLAN mismatch warnings
    
- Security concerns
    

### Important distinction

A native VLAN mismatch does **not normally break correctly tagged traffic** for other VLANs.

For example:

```text
VLAN 10 → tagged → normally unaffected
VLAN 20 → tagged → normally unaffected
Native VLAN → untagged → affected by mismatch
```

> **Exam answer:**  
> Native VLAN mismatch primarily affects **untagged/native-VLAN traffic**, not correctly tagged VLAN traffic.

---

## 6. Native VLAN and VLAN Hopping

The native VLAN is relevant to the security concept of **double-tagging VLAN hopping**.

Conceptually:

```text
Attacker
   │
   │ Double-tagged frame
   ▼
Switch
   │
   │ Outer/native VLAN tag removed
   ▼
Second 802.1Q tag remains
   │
   ▼
Potential forwarding toward another VLAN
```

The native VLAN is involved because the first/outer tag can be associated with the native VLAN and removed at the first switch.

However:

> **Native VLAN mismatch itself does not automatically cause VLAN hopping.**

The security issue is the interaction between **native VLAN behavior and double-tagged frames**.

## 7. Native VLAN Security Best Practices

### 7.1 Use an Unused Native VLAN

A common design is to use a dedicated VLAN that is not assigned to normal user endpoints.

Example:

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk native vlan 999
```

Where VLAN 999 is reserved for native-trunk purposes.

The exact VLAN number is a design choice.

---

### 7.2 Keep Native VLAN Consistent

Both ends should use the same native VLAN:

```text
Switch A: Native VLAN 999
Switch B: Native VLAN 999
```

Do not configure:

```text
Switch A: Native VLAN 999
Switch B: Native VLAN 100
```

---

### 7.3 Restrict Allowed VLANs

Limit which VLANs are carried over the trunk:

```cisco
switchport trunk allowed vlan 10,20,30,999
```

This reduces unnecessary Layer 2 propagation.

The native VLAN should be considered separately when designing the allowed VLAN list and trunk behavior.

---

### 7.4 Consider Tagging Native VLAN Traffic

On platforms that support it, Cisco can be configured to **tag native VLAN traffic**:

```cisco
vlan dot1q tag native
```

This changes the normal behavior so native VLAN traffic is tagged as well.

This can provide additional protection against certain native-VLAN/double-tagging scenarios.

> **Exam point:**  
> Native VLAN is normally untagged, but Cisco supports configurations where native VLAN traffic is explicitly tagged.

---

### Change the Native VLAN

```cisco

```

Both ends should be configured consistently:

```cisco
! Switch A

 switchport trunk native vlan 999

! Switch B
interface Gi0/24
 switchport mode trunk
 switchport trunk native vlan 999
```

## 9. Native VLAN with Router-on-a-Stick

A router can map a native VLAN to a router subinterface using:

```cisco
interface GigabitEthernet0/0.999
 encapsulation dot1Q 999 native
 ip address 192.168.99.1 255.255.255.0
```

The keyword:

```cisco
native
```

tells the router that this subinterface handles **untagged frames associated with VLAN 999**.

Example:

```text
Switch                         Router

VLAN 10 ── tagged ───────────► G0/0.10
VLAN 20 ── tagged ───────────► G0/0.20
VLAN 999 ─ untagged ─────────► G0/0.999
                                  │
                              native
```

Configuration:

```cisco
interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0

interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0

interface GigabitEthernet0/0.999
 encapsulation dot1Q 999 native
 ip address 192.168.99.1 255.255.255.0
```

> **Important:**  
> A router-on-a-stick native VLAN is normally configured using the `native` keyword on a **subinterface**.

## 12. Exam Traps

### Trap 1 — "Native VLAN = VLAN 1"

Incorrect.

VLAN 1 is the **default** native VLAN on many Cisco configurations.

The native VLAN can be changed:

```cisco
switchport trunk native vlan 999
```

---

### Trap 2 — "Native VLAN is tagged"

Normally incorrect.

On a standard 802.1Q trunk:

```text
Normal VLAN → tagged
Native VLAN → untagged
```

However, Cisco can be configured to tag native VLAN traffic with:

```cisco
vlan dot1q tag native
```

---

### Trap 3 — "Native VLAN mismatch breaks the whole trunk"

Incorrect.

Correctly tagged VLAN traffic can continue to operate.

The primary problem is with **untagged/native-VLAN traffic**.

---

### Trap 4 — "Native VLAN mismatch automatically causes VLAN hopping"

Incorrect.

A mismatch is a configuration error.

**Double-tagging** is the VLAN-hopping technique in which native VLAN behavior can be exploited.

---

### Trap 5 — "Changing only one side is enough"

Incorrect.

If you configure:

```text
Switch A → Native VLAN 999
Switch B → Native VLAN 1
```

the trunk has a native VLAN mismatch.

Both ends should agree.

---

### Trap 6 — "Every untagged frame is user traffic in the native VLAN"

Not necessarily.

Layer 2 control protocols can use untagged Ethernet frames and have their own protocol-specific handling.

---

### Trap 7 — "Router native VLAN means the physical interface automatically handles it"

Not necessarily.

In router-on-a-stick, the native VLAN is normally explicitly mapped with:

```cisco
encapsulation dot1Q <vlan-id> native
```

on a subinterface.
