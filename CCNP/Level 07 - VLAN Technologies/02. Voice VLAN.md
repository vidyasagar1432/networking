# Voice VLAN

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **voice VLAN** is a dedicated VLAN for IP phones (Voice over IP). It separates
telephony traffic from PC data on the **same port** using **802.1Q tagging from the
phone**: the phone tags its own frames with the voice VLAN, while the PC behind it
stays untagged on the access (data) VLAN.

---

## 2. Core Concepts

### 2.1 Why a separate VLAN

| Reason | Detail |
|--------|--------|
| QoS trust | voice marked EF, prioritized (Level 21) |
| Security | phones isolated from user's data VLAN |
| Broadcast containment | CDP/phine random traffic isolated |
| Management | phones get their own subnet/DHCP |
| Policy | voice gets its own L3 subnet + scoped ACLs |

### 2.2 The topology
```
PC ──data(untagged)──┐
                      [switch port]
IP Phone ──voice(tagged)→ [access port, voice vlan X]
```
- The **switch port** is still an **access port** in the data VLAN (untagged traffic).
- The **phone tags its voice frames** with the voice VLAN (the switch treats them as
  tagged on that access port).
- Switch may also declare **CDP/LLDP-MED** to give the phone the voice VLAN ID.

### 2.3 Config on the access port
```text
interface Gi0/1
 switchport mode access
 switchport access vlan 10           # data subnet (PC)
 switchport voice vlan 20            # voice (tagged from phone)
 spanning-tree portfast
```
- "voice vlan X" → the port accepts tagged X from the phone, quiet frames in 10 for PC.
- Without: phones can't get a VLAN → classic "phone no IP / no dial tone" trail.

### 2.4 Voice DHCP & options
- Phones use DHCP; option 150 (TFTP server) or 242 (Skinny) for provisioning.
- Phones on voice VLAN usually get a separate DHCP pool/scope.
- If using **auto QoS**, trust the phone (CoS 5 / DSCP EF).

### 2.5 QoS connection (why it matters for ENCOR)
- Marking: DSCP **EF** for RTP; **CS3/AF31** for signaling (SIP).
- Switch trusts **CoS from the phone** on voice, but **not the PC** (trust boundary at phone)
  → see Level 21.

## 3. Configuration / Commands

```text
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10
 switchport voice vlan 20
 mls qos trust device cisco-phone          # (Cisco) trust phone CoS
 spanning-tree portfast

# Verify
show interfaces Gi0/1 switchport          # Voip vlan: 20
show vlan id 20
show power inline gig 0/1 | include Admin   # PoE status
```

---

## 4. Exam Traps

- **Voice VLAN traffic is TAGGED from the phone**, PC traffic stays untagged — don't say
  "the port is a trunk."
- **Port remains an access port** — `voice vlan` is NOT `switchport mode trunk`.
- **Phones get the voice VLAN via CDP/LLDP-MED** — if CDP/LLDP is off, no voice VLAN.
- **Option 150** (TFTP) and **EF** marking for audio — both asked.
- **PoE powers the phone** — a port without power = dead phone (Level 01).
