# 802.1Q

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**IEEE 802.1Q** is the IEEE standard that defines **VLAN tagging and VLAN-aware Ethernet bridging**.

It allows multiple VLANs to share the same physical Ethernet link by carrying a **VLAN Identifier (VID)** inside an Ethernet frame.

Cisco 802.1Q trunks use this tagging mechanism to transport multiple VLANs over a single link.

> **CCNP Mental Model**
> 
> ```text
> IEEE 802.1Q
> │
> ├── VLAN Tagging
> │     └── Identifies the VLAN associated with a frame
> │
> ├── 4-Byte Tag
> │     ├── TPID
> │     └── TCI
> │
> ├── TCI
> │     ├── PCP
> │     ├── DEI
> │     └── VID
> │
> ├── Trunks
> │     └── Multiple VLANs over one link
> │
> ├── Native VLAN
> │     └── Normally transmitted untagged
> │
> └── Router-on-a-Stick
>       └── Subinterfaces use dot1Q VLAN identification
> ```

## 2. The 802.1Q Tag

An 802.1Q VLAN tag is **4 bytes** inserted into the Ethernet frame between the **Source MAC Address** and the **EtherType/Length field**.

```text
+----------------+----------------+----------------+----------------+
| Destination    | Source MAC     | 802.1Q Tag    | EtherType /   |
| MAC            |                | 4 bytes       | Length        |
+----------------+----------------+----------------+----------------+
                                      │
                                      ├── TPID
                                      └── TCI
```

The tag contains:

```text
802.1Q TAG
│
├── TPID — 16 bits
│
└── TCI  — 16 bits
      │
      ├── PCP — 3 bits
      ├── DEI — 1 bit
      └── VID — 12 bits
```

---

## 3. Tag Fields

### 3.1 TPID

**TPID (Tag Protocol Identifier)** is 16 bits.

For the common IEEE 802.1Q VLAN tag:

```text
TPID = 0x8100
```

It identifies the following field as an IEEE VLAN tag.

> **Important:** `0x8100` is the common VLAN-tag TPID. Provider bridging/Q-in-Q environments can use additional tag types/TPIDs.

---

### 3.2 PCP

**PCP (Priority Code Point)** is a **3-bit** field.

It provides **8 priority values**:

```text
0–7
```

PCP is used for Layer 2 traffic prioritization and is commonly associated with **802.1p priority / Class of Service (CoS)**.

Conceptually:

```text
PCP
 │
 ├── 0
 ├── 1
 ├── 2
 ├── ...
 └── 7
```

Switch QoS mechanisms can use PCP to classify traffic and map it to internal queues or QoS classes.

---

### 3.3 DEI

**DEI (Drop Eligible Indicator)** is **1 bit**.

It indicates whether the frame may be considered eligible for dropping during congestion.

```text
DEI = 0 → not marked drop-eligible
DEI = 1 → marked drop-eligible
```

The exact treatment depends on the network's QoS/congestion-management implementation.

---

### 3.4 VID

**VID (VLAN Identifier)** is **12 bits**.

A 12-bit field can represent:

```text
0–4095
```

However, not all values are usable as normal VLAN IDs.

For normal VLAN assignment:

```text
1–4094
```

are the relevant VLAN ID range.

```text
0     → reserved for priority-tagged frames
1–4094 → normal VLAN IDs
4095  → reserved
```

> **Exam trap:**  
> Do not answer **4095 usable VLANs**. The normal VLAN ID range is **1–4094**.

---

## 4. Frame Format

### Untagged Ethernet Frame

```text
+------+-----+------+---------+-----+
| DA   | SA  | Type | Payload | FCS |
+------+-----+------+---------+-----+
```

### 802.1Q Tagged Frame

```text
+------+-----+------+-----------+------+---------+-----+
| DA   | SA  | TPID | TCI       | Type | Payload | FCS |
+------+-----+------+-----------+------+---------+-----+
                    │
                    ├── PCP
                    ├── DEI
                    └── VID
```

The 802.1Q tag adds:

```text
4 bytes
```

to the Ethernet frame.

---

## 5. Frame Size

A standard Ethernet frame with a 1500-byte Layer 3 payload has a maximum size of approximately:

```text
1518 bytes
```

including:

- Destination MAC
    
- Source MAC
    
- EtherType/Length
    
- Payload
    
- FCS
    

Adding an 802.1Q tag increases the Layer 2 frame size by 4 bytes:

```text
1518 + 4 = 1522 bytes
```

Therefore:

```text
Untagged maximum Ethernet frame → 1518 bytes
802.1Q tagged frame             → 1522 bytes
```

> **Important:**  
> This does not mean the IP MTU automatically becomes 1522 bytes. A common configuration still uses an **IP MTU of 1500 bytes** while the Layer 2 frame carrying that packet can be 1522 bytes.

## 6. Native VLAN and 802.1Q

On a Cisco 802.1Q trunk, the **native VLAN is normally transmitted untagged**.

Example:

```text
VLAN 10:
[Ethernet][802.1Q Tag: VID 10]

VLAN 20:
[Ethernet][802.1Q Tag: VID 20]

Native VLAN 999:
[Ethernet][No 802.1Q Tag]
```

Therefore:

```text
Normal VLAN traffic → Tagged
Native VLAN traffic → Normally untagged
```

Cisco can also be configured to tag native VLAN traffic:

```cisco
vlan dot1q tag native
```

where supported.

> **Exam trap:**  
> "802.1Q means every frame is tagged" is too absolute. The normal native-VLAN behavior is the important exception.

## 7. Where 802.1Q Is Used

### 7.1 Switch-to-Switch Trunks

```text
Switch A                         Switch B

VLAN 10 ──┐                  ┌── VLAN 10
VLAN 20 ──┼──── 802.1Q ──────┼── VLAN 20
VLAN 30 ──┘     TRUNK        └── VLAN 30
```

The VLAN tag allows the receiving switch to determine which VLAN the frame belongs to.

---

### 7.2 Router-on-a-Stick

A router can use 802.1Q subinterfaces:

```cisco
interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0

interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
```

The router uses the VLAN ID in the 802.1Q tag to determine which subinterface should process the frame.

For a native VLAN:

```cisco
interface GigabitEthernet0/0.999
 encapsulation dot1Q 999 native
 ip address 192.168.99.1 255.255.255.0
```

---

### 7.3 Firewalls and Other Devices

Many firewalls, hypervisors, servers, and network appliances can use **802.1Q VLAN tagging** to support multiple logical VLAN interfaces over one physical Ethernet interface.

Example:

```text
             Physical NIC
                  │
             802.1Q trunk
                  │
        ┌─────────┼─────────┐
        │         │         │
      VLAN 10   VLAN 20   VLAN 30
```

---

## 8. Tag Insertion and Removal

The tag is not necessarily present for the entire path.

A switch can add or remove the VLAN tag according to the port and VLAN behavior.

Conceptually:

```text
Access Device
     │
     │ Untagged
     ▼
  Switch
     │
     │ 802.1Q tagged
     ▼
  Trunk
     │
     │ 802.1Q tagged
     ▼
  Switch
     │
     │ Untagged
     ▼
 Endpoint
```

For ordinary access ports:

- Endpoint traffic is normally untagged.
    
- The switch associates the traffic with the access VLAN.
    
- The trunk can add the 802.1Q VLAN identification when forwarding the frame across a trunk.
    

> **Important exception:**  
> Voice VLAN operation can involve tagged voice traffic on an access port.

## 9. 802.1Q vs ISL

|Feature|802.1Q|ISL|
|---|---|---|
|Organization|IEEE standard|Cisco proprietary|
|VLAN identification|4-byte tag inside frame|External encapsulation|
|Native VLAN|Supported|No native VLAN concept|
|Current Cisco use|Standard|Legacy|
|Modern networks|Common|Obsolete/unsupported on modern platforms|

### 802.1Q

```text
Ethernet Frame
     │
     ├── 802.1Q tag inserted
     │
     ▼
Tagged Ethernet frame
```

### ISL

```text
ISL Header
    │
    ▼
Entire Ethernet frame encapsulated
    │
    ▼
ISL Trailer
```

ISL is legacy Cisco technology and is not used on modern Cisco switching platforms.

> **Exam answer:**  
> Modern Cisco trunking → **802.1Q**.

## 10. QoS Relationship

The 802.1Q tag contains the **PCP field**.

```text
802.1Q TCI
│
├── PCP → 3 bits
├── DEI → 1 bit
└── VID → 12 bits
```

PCP provides Layer 2 priority information.

Cisco commonly refers to Layer 2 priority as **CoS**.

Conceptually:

```text
PCP
 │
 ▼
Layer 2 QoS classification
 │
 ▼
QoS class / queue
 │
 ▼
Transmission scheduling
```

PCP and DSCP are different fields at different layers:

```text
802.1Q PCP → Layer 2 priority
IP DSCP    → Layer 3 QoS marking
```

## 11. Configuration

### Cisco Switch Trunk

On older Cisco platforms where trunk encapsulation is configurable:

```cisco
interface GigabitEthernet0/24
 switchport trunk encapsulation dot1q
 switchport mode trunk
```

On many modern Catalyst platforms, `switchport trunk encapsulation dot1q` is unavailable because **802.1Q is the only supported encapsulation**.

---

### Allowed VLANs

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

This controls which VLANs can be carried over the trunk.

---

### Native VLAN

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk native vlan 999
```

---

### Disable DTP

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport nonegotiate
```

`nonegotiate` disables **DTP**, not 802.1Q.

## 14. Exam Traps

### Trap 1 — "TPID is the VLAN ID"

Incorrect.

```text
TPID → identifies the VLAN-tagging protocol
VID  → identifies the VLAN
```

Common TPID:

```text
0x8100
```

---

### Trap 2 — "802.1Q tag is 2 bytes"

Incorrect.

The complete 802.1Q tag is:

```text
4 bytes
```

```text
TPID = 2 bytes
TCI  = 2 bytes
```

---

### Trap 3 — "VID supports 4095 normal VLANs"

Incorrect.

The VID field is 12 bits:

```text
0–4095
```

But normal VLAN IDs are:

```text
1–4094
```

---

### Trap 4 — "Every 802.1Q frame is tagged"

Too absolute.

The native VLAN on a standard 802.1Q trunk is normally transmitted **untagged**.

---

### Trap 5 — "PCP is the VLAN ID"

Incorrect.

```text
PCP → priority
VID → VLAN
```

---

### Trap 6 — "PCP and DSCP are the same"

Incorrect.

```text
PCP  → Layer 2 priority
DSCP → Layer 3 IP QoS marking
```

---

### Trap 7 — "802.1Q changes the IP MTU to 1522"

Incorrect.

The common Layer 3 MTU can remain:

```text
1500 bytes
```

while the tagged Layer 2 Ethernet frame can be:

```text
1522 bytes
```

---

### Trap 8 — "ISL is the modern Cisco trunking protocol"

Incorrect.

Modern Cisco Ethernet trunking uses:

```text
802.1Q
```

ISL is legacy Cisco technology.

---

### Trap 9 — "`switchport nonegotiate` disables 802.1Q"

Incorrect.

It disables:

```text
DTP
```

The port can remain an explicitly configured 802.1Q trunk.
