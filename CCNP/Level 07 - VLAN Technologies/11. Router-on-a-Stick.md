# Router-on-a-Stick (ROAS)

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Router-on-a-Stick (ROAS)** is an inter-VLAN routing design in which a **single physical router interface** connects to a switch through an **802.1Q trunk**.

The router uses **subinterfaces**, with one subinterface representing each VLAN's Layer 3 gateway.

```text
                 802.1Q Trunk
   Switch ───────────────────────── Router
                                      │
                                   Gi0/0
                                      │
                    ┌─────────────────┼─────────────────┐
                    │                 │                 │
                 Gi0/0.10          Gi0/0.20          Gi0/0.30
                 VLAN 10           VLAN 20           VLAN 30
                 Gateway           Gateway           Gateway
```

### Core idea

```text
VLAN 10
   │
   └── Router Gi0/0.10 → 10.1.10.1

VLAN 20
   │
   └── Router Gi0/0.20 → 10.1.20.1

VLAN 30
   │
   └── Router Gi0/0.30 → 10.1.30.1
```

> **CCNP Mental Model:**  
> **One physical link → one trunk → multiple router subinterfaces → one gateway per VLAN.**

---

# 2. Core Concepts

## 2.1 Physical Interface vs Subinterfaces

The router has one physical interface:

```text
GigabitEthernet0/0
```

Multiple logical subinterfaces are created:

```text
GigabitEthernet0/0.10
GigabitEthernet0/0.20
GigabitEthernet0/0.30
```

The physical interface carries the trunk traffic.

The subinterfaces provide the Layer 3 gateway functions.

```text
Gi0/0
│
├── Gi0/0.10 → VLAN 10
├── Gi0/0.20 → VLAN 20
└── Gi0/0.30 → VLAN 30
```

The physical interface normally has **no IP address** when it is being used as the parent for ROAS subinterfaces.

---

# 3. 802.1Q Encapsulation

Each subinterface is associated with a VLAN using:

```cisco
encapsulation dot1Q <vlan-id>
```

Example:

```cisco
interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 10.1.10.1 255.255.255.0
```

This tells the router that:

```text
Gi0/0.10
└── Handles VLAN 10 traffic
```

For VLAN 20:

```cisco
interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 10.1.20.1 255.255.255.0
```

> **Important:**  
> `Gi0/0.10` does not automatically mean VLAN 10. The VLAN association comes from `encapsulation dot1Q 10`.

---

# 4. Basic ROAS Configuration

## 4.1 Router Configuration

```cisco
interface GigabitEthernet0/0
 no ip address
 no shutdown

interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 10.1.10.1 255.255.255.0

interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 10.1.20.1 255.255.255.0

interface GigabitEthernet0/0.30
 encapsulation dot1Q 30
 ip address 10.1.30.1 255.255.255.0
```

The router now provides:

```text
VLAN 10 → 10.1.10.1
VLAN 20 → 10.1.20.1
VLAN 30 → 10.1.30.1
```

---

# 5. Switch Configuration

The switch port connected to the router must carry the required VLANs as a trunk.

```cisco
interface GigabitEthernet0/24
 description ROUTER-ROAS-UPLINK
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

The topology becomes:

```text
          802.1Q Trunk
Switch ───────────────── Router
 Gi0/24                    Gi0/0
   │
   ├── VLAN 10 ─────────── Gi0/0.10
   ├── VLAN 20 ─────────── Gi0/0.20
   └── VLAN 30 ─────────── Gi0/0.30
```

Both sides must agree on the VLANs being carried.

# 6. Host Default Gateways

Each host uses the router subinterface for its VLAN as its default gateway.

### VLAN 10

```text
IP address:      10.1.10.10
Subnet mask:     255.255.255.0
Default gateway: 10.1.10.1
```

### VLAN 20

```text
IP address:      10.1.20.20
Subnet mask:     255.255.255.0
Default gateway: 10.1.20.1
```

### VLAN 30

```text
IP address:      10.1.30.30
Subnet mask:     255.255.255.0
Default gateway: 10.1.30.1
```

# 7. How ROAS Routes Traffic

Suppose:

```text
Host A = 10.1.20.10
Host B = 10.1.10.10
```

Host A is in VLAN 20 and wants to communicate with Host B in VLAN 10.

## Step 1 — Host determines destination is remote

Host A determines:

```text
10.1.10.10
```

is outside its local subnet:

```text
10.1.20.0/24
```

Therefore, it sends the packet to its default gateway:

```text
10.1.20.1
```

---

## Step 2 — Switch sends VLAN 20 traffic to router

The switch forwards the Ethernet frame across the trunk with VLAN 20 tagging.

```text
[Ethernet][802.1Q VLAN 20][IP Packet]
```

---

## Step 3 — Router receives VLAN 20

The router associates the incoming frame with:

```text
Gi0/0.20
```

The router removes the Layer 2 framing/tag information as part of receiving the Ethernet frame and processes the IP packet.

---

## Step 4 — Router performs Layer 3 lookup

The routing table contains:

```text
C 10.1.10.0/24 is directly connected, Gi0/0.10
C 10.1.20.0/24 is directly connected, Gi0/0.20
```

The router determines that the destination belongs to:

```text
Gi0/0.10
```

---

## Step 5 — Router creates a new Ethernet frame

The router builds a new Layer 2 frame for VLAN 10.

Conceptually:

```text
Incoming:

[VLAN 20][IP Packet]

        ↓
   L3 Routing
        ↓

Outgoing:

[VLAN 10][IP Packet]
```

The IP packet is routed; the Layer 2 frame is rebuilt for the destination network.

---

## Step 6 — Switch delivers to VLAN 10

The switch receives the VLAN 10 frame and forwards it to the destination host.

```text
Host A
VLAN 20
   │
   ▼
Switch
   │
   │ VLAN 20
   ▼
Router Gi0/0.20
   │
   │ Layer 3 routing
   ▼
Router Gi0/0.10
   │
   │ VLAN 10
   ▼
Switch
   │
   ▼
Host B
VLAN 10
```

---

# 8. Native VLAN on ROAS

802.1Q trunks can have a **native VLAN**, whose frames are transmitted untagged.

On a Cisco router, explicitly configure the native VLAN with:

```cisco
interface GigabitEthernet0/0.999
 encapsulation dot1Q 999 native
 ip address 10.1.999.1 255.255.255.0
```

The important keyword is:

```text
native
```

This tells the router that VLAN 999 is the native VLAN for that subinterface.

### Important distinction

Normal VLAN subinterface:

```cisco
encapsulation dot1Q 10
```

Native VLAN subinterface:

```cisco
encapsulation dot1Q 999 native
```

Do not assume that every subinterface is automatically associated with untagged traffic.

---

# 9. ROAS Configuration Example with Native VLAN

```cisco
interface GigabitEthernet0/0
 no ip address
 no shutdown

interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 10.1.10.1 255.255.255.0

interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 10.1.20.1 255.255.255.0

interface GigabitEthernet0/0.999
 encapsulation dot1Q 999 native
 ip address 10.1.99.1 255.255.255.0
```

Switch:

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk native vlan 999
 switchport trunk allowed vlan 10,20,999
```

The native VLAN configuration must be consistent between the connected devices.

# 10. Advantages of ROAS

### Simple

Only one router interface and one switch trunk are required.

### Low Cost

A separate multilayer switch is not required for basic inter-VLAN routing.

### Easy to Understand

Each VLAN maps directly to a router subinterface:

```text
VLAN 10 → Gi0/0.10
VLAN 20 → Gi0/0.20
VLAN 30 → Gi0/0.30
```

### Useful for Labs

ROAS is excellent for learning:

- VLANs
    
- 802.1Q trunks
    
- Subinterfaces
    
- Default gateways
    
- Routing
    
- ARP
    
- Inter-VLAN traffic flow
    

---

# 11. Disadvantages of ROAS

### 11.1 Shared Physical Link

All VLAN traffic uses the same physical router link.

```text
VLAN 10 ─┐
VLAN 20 ─┼── 1 Physical Link ── Router
VLAN 30 ─┘
```

This can become a bandwidth bottleneck.

### 11.2 Router Processing

The router performs the Layer 3 forwarding for the inter-VLAN traffic.

### 11.3 Single Link Failure

If the physical trunk fails:

```text
Switch ───X─── Router
```

all VLANs lose their router gateway through that connection.

### 11.4 Scaling

As the number of VLANs and traffic volume increases, a multilayer switch with SVIs is generally more appropriate for campus inter-VLAN routing.

---

# 12. ROAS vs SVI

|Feature|Router-on-a-Stick|SVI|
|---|---|---|
|L3 device|Router|Multilayer switch|
|Gateway|Router subinterface|SVI|
|Physical uplink|802.1Q trunk|Depends on topology|
|VLANs|Subinterfaces|`interface VlanX`|
|`ip routing`|Not required on router|Required on L3 switch for routing|
|Forwarding|Router forwarding architecture|Switch hardware-based L3 forwarding|
|Scalability|Lower|Higher|
|Typical use|Small networks/labs|Campus networks|
|Shared trunk bottleneck|Yes|Not necessarily|
|Configuration|Simple|More scalable|

Use a structured Layer 2 → Layer 3 approach.

```text
Host
 │
 ▼
Access VLAN
 │
 ▼
Switch Trunk
 │
 ▼
Router Physical Interface
 │
 ▼
Router Subinterface
 │
 ▼

 │
 ▼

```

## 13.1 Check Physical Interface

```cisco
show ip interface brief
```

Look for:

```text
GigabitEthernet0/0    up    up
```

If the parent interface is down, its subinterfaces cannot function correctly.

---

## 13.2 Check Subinterfaces

```cisco
show ip interface brief
```

Example:

```text
GigabitEthernet0/0.10    10.1.10.1    up    up
GigabitEthernet0/0.20    10.1.20.1    up    up
```

If a subinterface is `up/down`, investigate:

- Parent interface
    
- 802.1Q encapsulation
    
- VLAN ID
    
- Switch trunk
    
- VLAN allowed list
    
- Native VLAN configuration
    

---

## 13.3 Check Switch Trunk

```cisco
show interfaces trunk
```

Verify:

```text
VLAN 10
VLAN 20
VLAN 30
```

are allowed and active on the trunk.

---

## 13.4 Check VLANs

```cisco
show vlan brief
```

Make sure the required VLANs exist.

---

## 13.5 Check Encapsulation

```cisco
show running-config interface GigabitEthernet0/0.10
```

Verify:

```cisco
encapsulation dot1Q 10
```

A VLAN ID mismatch can cause that VLAN's routing to fail.

---

## 13.6 Check Routing Table

```cisco
show ip route
```

Expected:

```text
C    10.1.10.0/24 is directly connected, GigabitEthernet0/0.10
C    10.1.20.0/24 is directly connected, GigabitEthernet0/0.20
```

---

## 13.7 Check ARP

```cisco
show ip arp
```

ARP is used to resolve IPv4 addresses to MAC addresses on directly connected networks.

---

## 13.8 Test with a Specific Source

```cisco
ping 10.1.20.20 source 10.1.10.1
```

This tests connectivity using the VLAN 10 gateway as the source.

# 14. Common Failure Scenarios

### Problem 1 — VLAN missing from trunk

```text
Switch trunk
    │
    ├── VLAN 10 ✓
    └── VLAN 20 ✗
```

VLAN 20 traffic cannot reach the router.

Check:

```cisco
show interfaces trunk
```

---

### Problem 2 — VLAN ID mismatch

Router:

```cisco
encapsulation dot1Q 20
```

Switch traffic:

```text
VLAN 30
```

The router will not associate that traffic with the VLAN 20 subinterface.

---

### Problem 3 — Missing subinterface IP

```cisco
interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
```

but no:

```cisco
ip address ...
```

The router has no Layer 3 gateway address for that VLAN.

---

### Problem 4 — Parent interface shutdown

```cisco
interface GigabitEthernet0/0
 shutdown
```

All subinterfaces depend on the parent physical interface.

---

### Problem 5 — Native VLAN mismatch

Switch:

```cisco
switchport trunk native vlan 999
```

Router:

```cisco
encapsulation dot1Q 10 native
```

The devices disagree about which VLAN is native.

Correct the configuration so both sides agree.

---

# 15. Router MAC and ARP Behavior

A router is not a Layer 2 switch.

A switch primarily uses:

```text
MAC address → switch port
```

for Layer 2 forwarding.

A router primarily uses:

```text
Destination IP → routing table → outgoing interface
```

for Layer 3 forwarding.

However, the router still uses **ARP** on IPv4 Ethernet interfaces to resolve a next-hop/destination IP address to a MAC address.

Conceptually:

```text
Destination IP
      │
      ▼
Routing Table
      │
      ▼
Outgoing Interface
      │
      ▼
ARP Resolution
      │
      ▼
Destination MAC
      │
      ▼
New Ethernet Frame
```

So:

> **Router ≠ Layer 2 switch**, but the router still participates in Ethernet Layer 2 framing and maintains an ARP cache.

# 17. Exam Traps

### Trap 1 — Subinterface Number ≠ VLAN ID

This:

```cisco
interface GigabitEthernet0/0.10
```

does not automatically mean VLAN 10.

The actual VLAN association comes from:

```cisco
encapsulation dot1Q 10
```

Therefore, this is valid:

```cisco
interface GigabitEthernet0/0.100
 encapsulation dot1Q 10
 ip address 10.1.10.1 255.255.255.0
```

The subinterface number and VLAN ID do not have to match.

> **Best practice:** Usually make them match because it makes the configuration easier to understand.

---

### Trap 2 — Physical Interface IP

With ROAS, normally:

```cisco
interface GigabitEthernet0/0
 no ip address
```

and IP addresses are placed on the subinterfaces.

---

### Trap 3 — `encapsulation dot1Q`

Every normal tagged ROAS subinterface needs the appropriate:

```cisco
encapsulation dot1Q <vlan-id>
```

Without the correct encapsulation configuration, the router cannot associate the expected VLAN traffic with that subinterface.

---

### Trap 4 — Native VLAN

Native VLAN traffic is untagged.

On Cisco router subinterfaces, explicitly configure:

```cisco
encapsulation dot1Q 999 native
```

Do not simply assume:

```text
Gi0/0.999 = native VLAN
```

---

### Trap 5 — One Link Does Not Mean One VLAN

A single ROAS trunk can carry many VLANs:

```text
VLAN 10 ─┐
VLAN 20 ─┤
VLAN 30 ─┤── 802.1Q trunk ── Router
VLAN 40 ─┘
```

The VLANs are multiplexed over the same physical link using 802.1Q tags.

---

### Trap 6 — Router Does Not Bridge VLANs

The router performs:

```text
VLAN 10
   ↓
Layer 3 routing
   ↓
VLAN 20
```

It does not simply bridge VLAN 10 directly into VLAN 20.

---

### Trap 7 — ROAS Bottleneck

The classic scaling problem is:

```text
Many VLANs
    │
    ▼
One physical trunk
    │
    ▼
One router interface
```

This can become a bandwidth and availability bottleneck.

---

# 19. CCNP Mental Model

```text
ROUTER-ON-A-STICK
│
├── ONE physical router interface
│
├── ONE 802.1Q trunk
│
├── MULTIPLE subinterfaces
│     │
│     ├── Gi0/0.10
│     │     └── VLAN 10 gateway
│     │
│     ├── Gi0/0.20
│     │     └── VLAN 20 gateway
│     │
│     └── Gi0/0.30
│           └── VLAN 30 gateway
│
├── Host sends traffic to default gateway
│
├── Switch sends tagged frame to router
│
├── Router
│     ├── Receives VLAN tag
│     ├── Processes IP packet
│     ├── Performs routing lookup
│     ├── Resolves destination MAC if needed
│     └── Builds a new Ethernet frame
│
└── Sends frame through destination VLAN
```
