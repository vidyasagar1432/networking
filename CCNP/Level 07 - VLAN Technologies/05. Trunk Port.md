# Trunk Port

> **Level 07 · VLAN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

A **trunk port** is a Layer 2 switch port that carries traffic for **multiple VLANs over a single physical link**.

On a Cisco 802.1Q trunk, VLAN information is normally carried in an **802.1Q tag**. The **native VLAN** is the important exception: its frames are normally transmitted **untagged**.

Common trunk connections include:

- Switch ↔ Switch
    
- Switch ↔ Router
    
- Switch ↔ Firewall
    
- Switch ↔ Hypervisor
    
- Switch ↔ Wireless AP carrying multiple VLANs
    
- Switch ↔ EtherChannel/Port-Channel
    

> **CCNP Mental Model**
> 
> ```text
> TRUNK PORT
> │
> ├── One physical link
> │     └── Carries multiple VLANs
> │
> ├── 802.1Q
> │     └── VLAN ID carried in the frame tag
> │
> ├── Native VLAN
> │     └── Normally transmitted untagged
> │
> ├── Allowed VLANs
> │     └── Defines which VLANs may cross
> │
> ├── DTP
> │     └── Can negotiate trunking
> │
> └── Typical Use
>       └── Switch-to-switch / multi-VLAN links
> ```

## 2. Core Concepts

### 2.1 What a trunk does

A trunk allows multiple VLANs to share the same physical link.

For example:

```text
VLAN 10 ─────┐
VLAN 20 ─────┤
VLAN 30 ─────┼──► Trunk ───► Switch
VLAN 40 ─────┤
VLAN 50 ─────┘
```

Instead of requiring one physical link per VLAN, a trunk uses **802.1Q VLAN tagging** to identify the VLAN associated with a frame.

---

### 2.2 802.1Q Tag

An Ethernet frame carried as a tagged 802.1Q frame contains a **4-byte VLAN tag** inserted between the source MAC address and the EtherType/Length field.

Conceptually:

```text
+-------------+-------------+-------------+-------------+
| Destination | Source MAC  | 802.1Q Tag  | EtherType   |
| MAC         |             |             |             |
+-------------+-------------+-------------+-------------+
                                      │
                                      └── VLAN information
```

The 802.1Q tag contains:

```text
TPID
│
├── 0x8100
│
└── TCI
     │
     ├── PCP
     ├── DEI
     └── VID
```

The **VID (VLAN Identifier)** is **12 bits**.

Normal VLAN IDs are:

```text
1–4094
```

VLAN 0 and VLAN 4095 are reserved and are not normal assignable VLAN IDs.

---

## 3. Native VLAN

The **native VLAN** is the VLAN associated with **untagged traffic on an 802.1Q trunk**.

For example:

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk native vlan 999
```

The conceptual behavior is:

```text
Tagged:
  VLAN 10 ──► 802.1Q tagged
  VLAN 20 ──► 802.1Q tagged
  VLAN 30 ──► 802.1Q tagged

Untagged:
  VLAN 999 ──► Native VLAN
```

The native VLAN is **not inherently VLAN 1**.

Cisco switches commonly use VLAN 1 as the default native VLAN, but the native VLAN can be changed.

> **Best practice:** Configure an unused VLAN as the native VLAN and make sure both ends of the trunk agree.

---

## 4. Trunk vs Access

|Feature|Trunk Port|Access Port|
|---|---|---|
|VLANs|Multiple|One primary access VLAN|
|Normal VLAN identification|802.1Q tags|Untagged|
|Native VLAN|Yes|Not a trunk concept|
|Typical peer|Switch, router, firewall, AP|PC, printer, camera|
|Configuration|`switchport mode trunk`|`switchport mode access`|
|Allowed VLAN list|Yes|No trunk allowed list|
|DTP|May participate|Forced access disables trunk negotiation|

> **Key distinction:**
> 
> **Access = one primary VLAN**
> 
> **Trunk = multiple VLANs over one link**

## 5. Allowed VLAN List

The command:

```cisco
switchport trunk allowed vlan 10,20,30
```

defines the VLANs that are **allowed to be carried across the trunk**.

Example:

```text
Switch A                         Switch B

VLAN 10 ─────┐               ┌──── VLAN 10
VLAN 20 ─────┼─── TRUNK ─────┼──── VLAN 20
VLAN 30 ─────┘               └──── VLAN 30

VLAN 40 ───── X  Not allowed
```

This provides:

- VLAN scope control
    
- Reduced unnecessary Layer 2 propagation
    
- Better operational hygiene
    
- Reduced broadcast-domain exposure
    

Verify with:

```cisco
show interfaces trunk
```

> **Important:** The allowed VLAN list is not the same thing as the VLANs that currently have active traffic. It defines which VLANs are permitted on the trunk.

## 6. Trunk Configuration

### Basic trunk

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
```

### Trunk with allowed VLANs

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

### Trunk with custom native VLAN

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk native vlan 999
 switchport trunk allowed vlan 10,20,30,999
```

### Explicit trunk with DTP disabled

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport nonegotiate
```

`switchport nonegotiate` means:

> **Do not send DTP negotiation frames.**

It does **not** mean:

> "Do not trunk."

The port remains a statically configured trunk.

## 7. Trunk Encapsulation

Cisco historically supported multiple trunk encapsulations, including:

- **802.1Q**
    
- **ISL** — legacy Cisco proprietary technology
    

Modern Cisco Catalyst platforms generally use **802.1Q**.

On older platforms that support configurable encapsulation:

```cisco
switchport trunk encapsulation dot1q
```

may be required before:

```cisco
switchport mode trunk
```

However, on many modern Catalyst switches this command is unavailable because **802.1Q is the only supported encapsulation**.

> **Exam point:**  
> For modern Cisco networks, think **802.1Q** when you hear "trunk."

---

## 8. DTP and Trunk Negotiation

**DTP (Dynamic Trunking Protocol)** is a Cisco protocol used to negotiate trunking between compatible Cisco switchports.

Common modes include:

|Mode|Behavior|
|---|---|
|`access`|Forces access mode|
|`trunk`|Forces trunk mode|
|`dynamic desirable`|Actively attempts to negotiate trunking|
|`dynamic auto`|Passively waits for trunk negotiation|
|`nonegotiate`|Disables DTP frames|

Example:

```text
Dynamic Desirable + Dynamic Auto
          │
          ▼
       Can form trunk
```

But:

```text
Dynamic Auto + Dynamic Auto
          │
          ▼
      No trunk
```

For an explicitly configured trunk:

```cisco
interface Gi0/24
 switchport mode trunk
 switchport nonegotiate
```

This avoids unnecessary DTP negotiation.

## 9. Security Considerations

### 9.1 Unauthorized Trunk Formation

If an endpoint-facing port is left in a dynamic DTP mode, a device capable of participating in DTP may potentially negotiate a trunk.

This can expose multiple VLANs to an unauthorized device.

Best practice for endpoint ports:

```cisco
switchport mode access
```

and, where appropriate:

```cisco
switchport nonegotiate
```

> **Important distinction:** DTP and VLAN hopping are related to Layer 2 security, but they are **not the same attack**.

---

### 9.2 VLAN Hopping

Two classic VLAN-hopping concepts are:

1. **Switch spoofing**
    
2. **Double-tagging**
    

Switch spoofing attempts to make an endpoint-facing port become a trunk.

Double-tagging takes advantage of **802.1Q native-VLAN behavior** and nested VLAN tags.

Therefore:

```text
DTP
 │
 └── Can contribute to unauthorized trunk formation

Native VLAN
 │
 └── Important in double-tagging considerations
```

Security best practices include:

- Force endpoint ports to access mode.
    
- Avoid unnecessary DTP.
    
- Use an unused native VLAN where appropriate.
    
- Keep the native VLAN consistent on both ends.
    
- Restrict allowed VLANs.
    
- Avoid unnecessary VLAN 1 propagation.

## 10. Native VLAN Mismatch

A native VLAN mismatch occurs when the two ends of a trunk use different native VLAN IDs.

Example:

```text
Switch A                         Switch B

Native VLAN 999                  Native VLAN 100
      │                                │
      └──────────── TRUNK ─────────────┘
```

The two switches disagree about which VLAN an **untagged frame** belongs to.

Potential consequences include:

- Misclassified untagged traffic
    
- Unexpected connectivity
    
- CDP/native-VLAN mismatch warnings
    
- Layer 2 traffic leakage or incorrect forwarding
    
- Security concerns
    

Correct configuration:

```text
Switch A                         Switch B

Native VLAN 999                  Native VLAN 999
      │                                │
      └──────────── TRUNK ─────────────┘
```

> **Exam trap:**  
> Native VLAN must be **consistent on both ends** of the trunk.

## 11. Router-on-a-Stick

A trunk can connect a switch to a router for **inter-VLAN routing**.

Example:

```text
                    Router
                 ┌───────────┐
                 │ G0/0      │
                 │           │
                 │ G0/0.10   │── VLAN 10
                 │ G0/0.20   │── VLAN 20
                 └─────┬─────┘
                       │
                     TRUNK
                       │
                 ┌─────┴─────┐
                 │  Switch   │
                 └───────────┘
```

The router uses **802.1Q subinterfaces**:

```cisco
interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0

interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
```

The switch-facing interface is configured as a trunk.

## 12. EtherChannel + Trunk

An EtherChannel combines multiple physical links into one logical link.

The logical interface is the **Port-Channel**.

A Port-Channel can then operate as a trunk:

```text
Gi0/1 ──┐
Gi0/2 ──┼── EtherChannel ── Port-Channel1
Gi0/3 ──┘                       │
                                │
                              TRUNK
```

Example:

```cisco
interface range GigabitEthernet0/1-3
 channel-group 1 mode active

interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

> **Important:** EtherChannel and trunking are separate concepts.
> 
> **EtherChannel = link aggregation**
> 
> **Trunk = multiple VLANs over the logical link**

```text

          │
          ▼

          │

          │
```

## 15. Exam Traps

### Trap 1 — "All trunk traffic is tagged"

Not strictly correct.

The **native VLAN is normally transmitted untagged** on an 802.1Q trunk.

---

### Trap 2 — "Native VLAN is always VLAN 1"

Incorrect.

VLAN 1 is the common default, but the native VLAN can be changed.

Example:

```cisco
switchport trunk native vlan 999
```

---

### Trap 3 — "`switchport nonegotiate` disables the trunk"

Incorrect.

It disables **DTP negotiation**, not trunk operation.

```cisco
switchport mode trunk
switchport nonegotiate
```

The port is still a trunk.

---

### Trap 4 — "Dynamic desirable always creates a trunk"

Incorrect.

Trunk formation depends on the combination of the two endpoints' modes and platform behavior.

---

### Trap 5 — "Dynamic auto + dynamic auto creates a trunk"

Incorrect.

Both sides are passive.

```text
Auto + Auto = No trunk
```

---

### Trap 6 — "Allowed VLAN list means VLANs are removed from the switch"

Incorrect.

The VLAN still exists locally.

The allowed list controls whether the VLAN can be **carried across that trunk**.

---

### Trap 7 — "Native VLAN mismatch only affects management"

Incorrect.

It affects the interpretation of **untagged traffic** and can cause unexpected Layer 2 behavior.

---

### Trap 8 — "EtherChannel is a trunk"

Not exactly.

EtherChannel aggregates physical links into a logical interface.

That logical interface can then be configured as an **access port or trunk**, depending on the design.

---

### Trap 9 — "APs always use access ports"

Incorrect.

An AP carrying multiple SSIDs mapped to different VLANs commonly requires a **trunk**.
