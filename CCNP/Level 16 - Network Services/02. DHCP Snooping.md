# DHCP Snooping

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DHCP snooping** is a layer-2 security feature that builds a **trusted/untrusted port
model**: only traffic from **trusted** ports (toward the real DHCP server) is forwarded
for servers; **untrusted** ports (toward hosts) get every DHCP message validated. It
blocks **rogue DHCP servers**, **starvation attacks**, and spoofed options.

---

## 2. Core Concepts

### 2.1 Trusted vs untrusted ports

| Port | Toward | DHCP server messages |
|------|--------|----------------------|
| Trusted | server side | allowed (OFFER/ACK) |
| Untrusted | hosts | blocked unless spoofed match |

- Default: all ports **untrusted** — you must mark the uplink trusted.

### 2.2 What gets dropped on untrusted ports

| Attack | Dropped |
|--------|---------|
| Rogue server | server messages (OFFER/ACK) |
| Starvation | excess DISCOVER beyond rate limit |
| Spoof | mismatched option-82 / binding |
| Lease theft | inconsistent subnet |

### 2.3 Configuration

```text
ip dhcp snooping
ip dhcp snooping vlan 10
interface Gi0/1
 ip dhcp snooping trust          ! uplink to real server
 ip dhcp snooping limit rate 10  ! packets/sec on untrusted
```

- `ip dhcp snooping` global + VLAN list.
- **Trust the uplink**, never host ports.
- Rate-limit caps flooding on untrusted ports.

### 2.4 The binding table

| Field | Source |
|-------|--------|
| MAC | client |
| IP | from ACK |
| VLAN/interface | port of entry |
| Lease | expiry |

- Built from successful **DHCP transactions**.
- Used for DAI, IP source guard, and validation of spoof attempts.

### 2.5 Snooping + option 82 insertion

- Relay/snooping adds **option 82** (circuit/remote ID) on untrusted ingress.
- Compare received vs expected to block clients impersonating in a different port/VLAN.

### 2.6 Verification and troubleshooting

```text
show ip dhcp snooping
show ip dhcp snooping binding
show ip dhcp snooping statistics
debug ip dhcp snooping packet
```

- `statistics` shows dropped vs forwarded packets — the quick health check.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Hosts get no IP | uplink untrusted | ip dhcp snooping trust |
| Legit server blocked | server port untrusted | trust the uplink |
| Rate limit kills hosts | limit too low | limit rate |
| Bindings missing | snooping VLAN not enabled | global + vlan |
| Option-82 mismatches | relay mismatch | snooping config |

---

## 5. Exam Traps

- **All ports start untrusted** — the uplink must be trusted.
- Blocks **OFFER/ACK from hosts**, not just DISCOVER floods.
- Works per **VLAN**; must be enabled per VLAN.
- Binding table feeds **DAI** and **IP Source Guard**.
- **Rate limit** on untrusted ports defeats starvation.
