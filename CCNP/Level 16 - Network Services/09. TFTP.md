# TFTP (Trivial File Transfer Protocol)

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**TFTP** (UDP 69) is a simple, **connectionless** file transfer used by network devices
for **IOS images, configs, and phones**. It has **no authentication, no directory
listing, and no reliability beyond lock-step retransmission** — that simplicity is why
routers use it, and also why it's a security risk.

---

## 2. Core Concepts

### 2.1 Protocol model

| Item | Detail |
|------|--------|
| Port | UDP 69 |
| Reliability | lock-step ack |
| Sessions | RRQ/WRQ → data + ack |
| Auth | none |
| Directory | none (flat files) |
| Error recovery | retransmit only |

- Every block is acked before the next (window = 1).

### 2.2 The message flow

```
client  -->RRQ (file)  --> server
server  -->DATA block1 --> client
client  -->ACK block1   --> server
server  -->DATA block2 --> client
... last DATA with zero-length final block signals end
```

- Block numbers identify data; final block of < 512 bytes marks EOF.

### 2.3 TFTP vs FTP vs SFTP

| Aspect | TFTP | FTP | SFTP/SCP |
|--------|------|-----|----------|
| Transport | UDP 69 | TCP 21 | SSH |
| Auth | none | yes | yes |
| Reliability | lock-step | TCP | TCP/SSH |
| Directory | none | yes | yes |
| Security | weak | weak (plaintext) | strong |

- TFTP wins for **simplicity + low overhead** in device operations.

### 2.4 Router usage

```text
copy tftp://10.0.0.5/ios.bin flash:
copy tftp://10.0.0.5/config.txt startup-config
copy flash:ios.bin tftp://10.0.0.5/
```

- The #1 tool for **IOS upgrade / backup / config transfer** on Cisco gear.
- No prompts beyond the URL — scriptable, but unauthenticated.

### 2.5 Risks and mitigations

| Risk | Mitigation |
|------|-----------|
| No auth | restrict TFTP to OOB/VPN |
| Plaintext | use SCP/SFTP for sensitive data |
| No directory | keep server single-purpose |
| DoS | server-side rate limiting |

- Enterprise exam answer: **SCP/SFTP over TFTP** for sensitive transfers.

### 2.6 Voice phones

- **DHCP option 150** points phones at the TFTP server for config/firmware.
- A TFTP outage = phones cannot boot configs (common UC failure).

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No transfer | UDP 69 blocked | ACL |
| Timeout mid-file | lossy link (lock-step) | retransmit |
| Permission denied | server file ACLs | server side |
| Partial file | small block / corrupted | re-copy with hash |
| Phones fail | option 150 wrong | DHCP options |

---

## 5. Exam Traps

- **UDP 69** — connectionless.
- **Lock-step**: one block per ack (no window).
- **No authentication** — the classic security trap.
- Block size 512; final short block ends the transfer.
- DHCP option **150** ties phones to TFTP.
