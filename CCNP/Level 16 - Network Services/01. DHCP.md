# DHCP

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DHCP (Dynamic Host Configuration Protocol)** automatically provides hosts with IPv4  
configuration information such as:

- IP address
    
- Subnet mask
    
- Default gateway
    
- DNS server
    
- Domain name
    
- Lease duration
    
- Other DHCP options
    

DHCP uses:

- **UDP 67** — DHCP server
    
- **UDP 68** — DHCP client
    

The classic IPv4 exchange is remembered as:

**DORA → Discover → Offer → Request → Acknowledge**

DHCP can operate directly between clients and servers on the same Layer 2 segment, or a  
**DHCP relay agent** can forward DHCP messages between different IP subnets.

---

## 2. DHCP Architecture

A typical enterprise DHCP deployment looks like:

```text
                         DHCP SERVER
                         10.20.20.10
                              |
                              |
                        IP Network
                              |
                    +-------------------+
                    | Router / L3 Switch|
                    |  DHCP Relay       |
                    +-------------------+
                              |
                       Client VLAN
                              |
                    +-------------------+
                    | Access Switch     |
                    +-------------------+
                       |           |
                    Client A    Client B
```

If the DHCP server is on another subnet, the router or Layer 3 switch acts as a  
**DHCP relay agent**.

---

# 3. DHCP Ports

|Device|UDP Port|
|---|--:|
|DHCP Server|**67**|
|DHCP Client|**68**|

Typical client request:

```text
Client:  UDP source 68
Server:  UDP destination 67
```

Typical server response:

```text
Server:  UDP source 67
Client:  UDP destination 68
```

> **Exam trap:** Remember **67 = Server, 68 = Client**.

---

# 4. DORA Exchange

The initial DHCP process is commonly remembered as **DORA**.

|Step|Message|Purpose|
|---|---|---|
|1|**DHCPDISCOVER**|Client searches for DHCP servers|
|2|**DHCPOFFER**|Server offers an IP configuration|
|3|**DHCPREQUEST**|Client requests the offered configuration|
|4|**DHCPACK**|Server confirms the lease|

### DORA Flow

```text
Client                         DHCP Server
  |                                |
  | DHCPDISCOVER                   |
  |------------------------------->|
  |                                |
  | DHCPOFFER                      |
  |<-------------------------------|
  |                                |
  | DHCPREQUEST                    |
  |------------------------------->|
  |                                |
  | DHCPACK                        |
  |<-------------------------------|
  |                                |
```

A client that does not yet have an IPv4 address commonly begins by broadcasting the  
DHCPDISCOVER.

Typical initial packet:

```text
Source IP      = 0.0.0.0
Destination IP = 255.255.255.255
Source UDP     = 68
Destination    = 67
```

> DHCP is **not necessarily broadcast for the entire lease process**. Packet addressing  
> depends on the client's DHCP state and the `broadcast` flag.

---

# 5. DHCP Message Types

DORA contains the four most important messages, but DHCP has additional message types.

|Message|Purpose|
|---|---|
|**DHCPDISCOVER**|Client searches for DHCP servers|
|**DHCPOFFER**|Server offers configuration|
|**DHCPREQUEST**|Client requests configuration/renews lease|
|**DHCPACK**|Server acknowledges the request|
|**DHCPNAK**|Server rejects the request|
|**DHCPDECLINE**|Client reports that offered address is already in use|
|**DHCPRELEASE**|Client releases its lease|
|**DHCPINFORM**|Client requests configuration parameters without obtaining an IP address|

### Important

**DHCPNAK** can occur when:

- The requested IP is invalid for the client's current subnet.
    
- The lease is no longer valid.
    
- The client moved to another subnet.
    

---

# 6. DHCP Client States

A DHCP client goes through several logical states.

```text
INIT
  |
  | DHCPDISCOVER
  v
SELECTING
  |
  | DHCPOFFER
  v
REQUESTING
  |
  | DHCPACK
  v
BOUND
  |
  | T1
  v
RENEWING
  |
  | T2 if renewal fails
  v
REBINDING
  |
  | DHCPACK
  v
BOUND
```

### Main States

|State|Meaning|
|---|---|
|**INIT**|Client does not have a valid lease|
|**SELECTING**|Client is choosing an offered lease|
|**REQUESTING**|Client is requesting a specific lease|
|**BOUND**|Client has a valid lease|
|**RENEWING**|Client is trying to renew with original server|
|**REBINDING**|Client tries any available DHCP server|

---

# 7. DHCP Lease

DHCP does not normally give an address permanently.

Instead, the server grants a **lease** for a specific period.

Example:

```text
Lease = 24 hours
```

The client can continue using the address as long as the lease remains valid and is  
successfully renewed.

---

## 7.1 T1 — Renewal Timer

**T1 = 50% of the lease duration.**

For a 24-hour lease:

```text
T1 = 12 hours
```

At T1, the client normally attempts to renew the lease with the **DHCP server that  
originally provided the lease**.

---

## 7.2 T2 — Rebinding Timer

**T2 = 87.5% of the lease duration.**

For a 24-hour lease:

```text
T2 = 21 hours
```

If the original server cannot renew the lease, the client enters the **REBINDING** state  
at T2.

The client can then attempt to renew with **any available DHCP server**.

---

## 7.3 Lease Timeline

```text
0%                50%                 87.5%              100%
|------------------|--------------------|-------------------|
                  T1                   T2                Expiry
                  |                    |
                  |                    |
             Renew original       Rebind with
                server            any server
```

> **Exam trap:** T1 = **50%**, T2 = **87.5%**.

# 8. Cisco IOS DHCP Server

A Cisco router or Layer 3 switch can operate as a DHCP server.

Example:

```cisco
ip dhcp excluded-address 10.0.0.1 10.0.0.99

ip dhcp pool LAN
 network 10.0.0.0 255.255.255.0
 default-router 10.0.0.1
 dns-server 10.0.0.2
 domain-name example.local
 lease 1 0 0
```

---

## 8.1 Excluded Addresses

```cisco
ip dhcp excluded-address 10.0.0.1 10.0.0.99
```

Prevents the specified addresses from being dynamically allocated.

This is commonly used to reserve addresses for:

- Routers
    
- Switch management
    
- Servers
    
- Printers
    
- Network appliances
    
- Other statically configured devices
    

> **Exam trap:** `ip dhcp excluded-address` is configured in **global configuration  
> mode**, not inside the DHCP pool.

---

## 8.2 DHCP Pool

```cisco
ip dhcp pool LAN
```

Creates or enters a DHCP pool named `LAN`.

---

## 8.3 Network

```cisco
network 10.0.0.0 255.255.255.0
```

Defines the subnet from which DHCP addresses are allocated.

---

## 8.4 Default Gateway

```cisco
default-router 10.0.0.1
```

Provides the client with its default gateway.

---

## 8.5 DNS Server

```cisco
dns-server 10.0.0.2
```

Provides DNS server information to DHCP clients.

---

## 8.6 Domain Name

```cisco
domain-name example.local
```

Provides the client's DNS domain name.

---

## 8.7 Lease Duration

```cisco
lease 1 0 0
```

Format:

```text
lease <days> <hours> <minutes>
```

Example:

```cisco
lease 1 0 0
```

means:

```text
1 day
```

---

# 9. DHCP Pool Selection

A Cisco DHCP server uses the client's network information to determine the appropriate  
DHCP pool.

For a directly connected client:

```text
Client VLAN
   |
   | DHCP request
   v
Cisco DHCP Server
   |
   +--> Select matching network/pool
   |
   +--> Allocate address
```

When a DHCP relay is involved, the relay supplies information that allows the DHCP  
server to identify the client's subnet.

---

# 10. DHCP Relay

DHCP client broadcasts normally do not cross a Layer 3 boundary.

If the DHCP server is on another subnet, configure a **DHCP relay**.

Cisco IOS uses:

```cisco
interface GigabitEthernet0/0
 ip address 10.10.10.1 255.255.255.0
 ip helper-address 10.20.20.10
```

Here:

```text
Client VLAN
10.10.10.0/24
       |
       | DHCP Broadcast
       v
Router / L3 Switch
10.10.10.1
       |
       | Relay / Unicast
       v
DHCP Server
10.20.20.10
```

---

## 10.1 `ip helper-address`

```cisco
ip helper-address 10.20.20.10
```

Specifies the DHCP server to which the relay forwards DHCP requests.

Configure it on the **Layer 3 interface facing the client subnet**, such as:

- Routed interface
    
- SVI
    
- Layer 3 interface
    

Example SVI:

```cisco
interface Vlan10
 ip address 10.10.10.1 255.255.255.0
 ip helper-address 10.20.20.10
```

> **Exam trap:** `ip helper-address` belongs on the **client-facing Layer 3 interface**.

---

# 11. DHCP Relay and `giaddr`

A DHCP relay can populate the **`giaddr` (Gateway IP Address)** field in the DHCP  
message.

The DHCP server uses this information to determine the client's subnet and select the  
appropriate DHCP scope/pool.

Example:

```text
Client
10.10.10.0/24
    |
    | DHCPDISCOVER
    v
Relay
10.10.10.1
    |
    | DHCP request with giaddr
    v
DHCP Server
    |
    +--> Identifies client subnet
    |
    +--> Selects matching DHCP pool
```

> **CCNP concept:** `giaddr` is important because the DHCP server can use the relay's  
> gateway address to determine which client subnet the request came from.

# 12. DHCP Options

DHCP options provide additional configuration information.

|Option|Meaning|
|--:|---|
|**53**|DHCP message type|
|**54**|DHCP server identifier|
|**66**|TFTP server name|
|**67**|Bootfile name|
|**82**|Relay Agent Information|
|**150**|TFTP server address, commonly used by Cisco IP phones|

## 12.1 Option 53 — DHCP Message Type

Option 53 identifies the DHCP message type.

Examples:

```text
DHCPDISCOVER
DHCPOFFER
DHCPREQUEST
DHCPACK
DHCPNAK
DHCPDECLINE
DHCPRELEASE
DHCPINFORM
```

---

## 12.2 Option 54 — Server Identifier

Identifies the DHCP server involved in the DHCP exchange.

---

## 12.3 Option 66 — TFTP Server Name

Provides the TFTP server name.

---

## 12.4 Option 67 — Bootfile Name

Provides the bootfile name.

These options can be important for network booting and PXE-related deployments.

---

## 12.5 Option 150 — TFTP Server

Option 150 provides the **TFTP server IPv4 address**.

It is commonly used with **Cisco IP phones** to identify a TFTP server.

Example:

```cisco
ip dhcp pool VOICE
 network 10.20.20.0 255.255.255.0
 default-router 10.20.20.1
 option 150 ip 10.20.20.10
```

> **Exam trap:** Cisco voice deployments commonly use **Option 150** for TFTP server  
> information.

# 13. DHCP Option 82

**Option 82 = Relay Agent Information.**

A DHCP relay can add information identifying where the client request originated.

Common sub-options include:

- **Circuit ID**
    
- **Remote ID**
    

### Circuit ID

Can identify information such as:

- Switch interface
    
- VLAN
    
- Circuit/port information
    

### Remote ID

Can identify information such as:

- Relay device
    
- Subscriber/device information
    

Example concept:

```text
Client
  |
  | DHCPDISCOVER
  v
Access Switch / Relay
  |
  | Adds Option 82
  | +----------------+
  | | Circuit ID     |
  | | Remote ID      |
  | +----------------+
  v
DHCP Server
```

Option 82 can be used for:

- Client identification
    
- Location-based addressing
    
- DHCP policy
    
- Security controls
    

> **Important:** Option 82 is **Relay Agent Information**. It is not the same thing as  
> DHCP snooping.

---

# 14. DHCP Snooping

**DHCP Snooping** is a Layer 2 security feature that protects against unauthorized or  
rogue DHCP servers.

The switch classifies interfaces as:

- **Trusted**
    
- **Untrusted**
    

---

## 14.1 Trusted Port

A trusted port is normally connected toward:

- Legitimate DHCP server
    
- DHCP relay
    
- Network infrastructure/uplink carrying legitimate DHCP server responses
    

Example:

```cisco
interface GigabitEthernet0/1
 ip dhcp snooping trust
```

---

## 14.2 Untrusted Port

Client-facing ports normally remain untrusted.

If a rogue device attempts to send DHCP server messages through an untrusted port, the  
switch can block those messages.

Typical topology:

```text
                 DHCP Server
                     |
                     |
               Trusted Port
                     |
              +-------------+
              |   Switch    |
              +-------------+
                |         |
          Untrusted    Untrusted
             |             |
          Client A       Client B
```

---

# 15. DHCP Snooping Configuration

Enable DHCP snooping:

```cisco
ip dhcp snooping
```

Enable it for VLAN 10:

```cisco
ip dhcp snooping vlan 10
```

Trust the interface toward the legitimate DHCP server/relay:

```cisco
interface GigabitEthernet0/1
 ip dhcp snooping trust
```

Rate-limit DHCP messages on an untrusted interface:

```cisco
interface GigabitEthernet0/10
 ip dhcp snooping limit rate 15
```

---

# 16. DHCP Snooping Binding Database

DHCP snooping builds a **binding database**.

It can contain:

- Client MAC address
    
- Assigned IP address
    
- VLAN
    
- Interface
    
- Lease information
    

Conceptually:

```text
MAC Address       IP Address       VLAN       Interface
--------------------------------------------------------
AAAA.BBBB.CCCC    10.10.10.101    10         Gi0/10
DDDD.EEEE.FFFF    10.10.10.102    10         Gi0/11
```

The binding database can be used by other security features.

---

# 17. DHCP Snooping + DAI + IP Source Guard

DHCP snooping is important because its binding database can provide information to other  
security mechanisms.

```text
             DHCP Snooping
                   |
                   v
          Binding Database
             /         \
            /           \
           v             v
 Dynamic ARP          IP Source
 Inspection             Guard
    (DAI)
```

### DHCP Snooping

Helps prevent:

- Rogue DHCP servers
    
- DHCP-related attacks
    

### Dynamic ARP Inspection

Uses DHCP snooping bindings to validate ARP information.

### IP Source Guard

Uses DHCP snooping information to restrict traffic to valid IP/MAC bindings.

> **Exam concept:** DHCP snooping can act as the foundation for **DAI and IP Source  
> Guard**.

---

# 18. DHCP Snooping Rate Limiting

An untrusted interface can be rate-limited:

```cisco
interface GigabitEthernet0/10
 ip dhcp snooping limit rate 15
```

This limits the rate of DHCP packets received on that interface.

It can help mitigate excessive DHCP traffic and DHCP starvation-style attacks.

---

# 19. DHCP Conflict Detection

A DHCP server should avoid assigning an address that is already in use.

Cisco IOS provides conflict detection.

Check conflicts:

```cisco
show ip dhcp conflict
```

The output can show addresses that the DHCP server considers conflicted.

The DHCP server can also perform address conflict checking before assigning an address.

> **Exam focus:** Know `show ip dhcp conflict` and understand that duplicate/static  
> addressing can cause DHCP conflicts.

# 22. Clear DHCP Bindings

To clear a specific binding:

```cisco
clear ip dhcp binding 10.0.0.100
```

To clear all dynamic bindings:

```cisco
clear ip dhcp binding *
```

> **Warning:** Clearing bindings removes active DHCP lease information. Use carefully in  
> production.

# 24. Complete DHCP Server Example

Network:

```text
Network:       192.168.10.0/24
Gateway:       192.168.10.1
DNS Server:    8.8.8.8
DHCP Range:    192.168.10.100-192.168.10.254
```

Configuration:

```cisco
ip dhcp excluded-address 192.168.10.1 192.168.10.99

ip dhcp pool USERS
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 8.8.8.8
 lease 1 0 0
```

The DHCP server can dynamically allocate:

```text
192.168.10.100
192.168.10.101
192.168.10.102
...
192.168.10.254
```

while:

```text
192.168.10.1 - 192.168.10.99
```

are excluded from dynamic allocation.

# 27. Troubleshooting Workflow

Use a structured approach.

```text
Client
  |
  v
Layer 2 Switch
  |
  v
Client VLAN / SVI
  |
  v
DHCP Relay
  |
  v
Network
  |
  v
DHCP Server
```

### Step 1 — Check the client

Verify the client is actually requesting DHCP.

Check:

- NIC status
    
- VLAN
    
- DHCP enabled
    
- Received address
    

---

### Step 2 — Check Layer 2

Verify:

```text
Client port
   |
Correct VLAN
   |
Trunk
   |
SVI
```

Check for:

- Wrong VLAN
    
- Down interface
    
- Trunk problems
    
- DHCP snooping blocking traffic
    

---

### Step 3 — Check the SVI / Layer 3 Interface

Verify:

```cisco
show ip interface brief
```

Confirm:

- Interface is up/up
    
- Correct IP address
    
- Correct VLAN
    

---

### Step 4 — Check DHCP Relay

Verify:

```cisco
show running-config interface Vlan10
```

Look for:

```cisco
ip helper-address <DHCP-SERVER-IP>
```

---

### Step 5 — Check DHCP Server

Verify:

```cisco
show ip dhcp pool
show ip dhcp binding
show ip dhcp conflict
show ip dhcp statistics
```

Check:

- Correct pool
    
- Available addresses
    
- Correct network
    
- Correct gateway
    
- Correct DNS server
    
- Address conflicts
    

---

### Step 6 — Check DHCP Snooping

Verify:

```cisco
show ip dhcp snooping
show ip dhcp snooping binding
```

Check:

- Correct VLAN enabled
    
- Correct trusted interface
    
- Client interface is not incorrectly trusted
    
- Rate limiting is not too restrictive

# 28. Common DHCP Failures

|Symptom|Possible Cause|What to Check|
|---|---|---|
|Client gets no address|DHCP server unavailable|Server/pool|
|Client gets no address across subnet|Missing relay|`ip helper-address`|
|Pool exhausted|Too few available addresses|`show ip dhcp pool`|
|Static address is offered|Address not excluded|`ip dhcp excluded-address`|
|Wrong gateway|Incorrect DHCP option|`default-router`|
|Wrong DNS|Incorrect DHCP option|`dns-server`|
|IP conflict|Duplicate/static address|`show ip dhcp conflict`|
|Rogue DHCP server works|Snooping not enabled|DHCP snooping|
|Legitimate DHCP blocked|Server/uplink not trusted|`ip dhcp snooping trust`|
|DHCP messages excessive|No rate limit|`ip dhcp snooping limit rate`|
|Cisco phone cannot locate TFTP|Option 150 missing/wrong|`option 150 ip`|
|Wrong DHCP pool through relay|Incorrect relay/subnet information|`giaddr`, relay configuration|
|Client renews unsuccessfully|Server unreachable|T1/T2 and connectivity|

# 30. ENCOR Exam Traps

- **UDP 67 = Server**
    
- **UDP 68 = Client**
    
- DORA = **Discover → Offer → Request → ACK**
    
- DHCPDISCOVER commonly begins as a **broadcast**.
    
- DHCP broadcasts do not normally cross a Layer 3 boundary.
    
- Use **`ip helper-address`** for DHCP relay.
    
- `ip helper-address` is configured on the **client-facing Layer 3 interface/SVI**.
    
- DHCP relay can populate **`giaddr`**.
    
- The DHCP server can use `giaddr` to select the appropriate subnet/pool.
    
- **T1 = 50%** of the lease.
    
- **T2 = 87.5%** of the lease.
    
- T1 normally renews with the **original DHCP server**.
    
- T2 allows rebinding with **any available DHCP server**.
    
- `ip dhcp excluded-address` is configured **globally**.
    
- `ip dhcp pool` creates a DHCP pool.
    
- `default-router` supplies the default gateway.
    
- `dns-server` supplies DNS information.
    
- **Option 53 = DHCP message type**.
    
- **Option 54 = DHCP server identifier**.
    
- **Option 82 = Relay Agent Information**.
    
- Option 82 can contain **Circuit ID and Remote ID**.
    
- **Option 150 = TFTP server address**, commonly for Cisco IP phones.
    
- DHCP snooping primarily protects against **rogue DHCP servers**.
    
- DHCP snooping ports are either **trusted or untrusted**.
    
- Server/uplink-facing interfaces normally need to be **trusted**.
    
- Client-facing interfaces normally remain **untrusted**.
    
- DHCP snooping creates a **binding database**.
    
- DAI and IP Source Guard can use the DHCP snooping binding database.
    
- Do not confuse **DHCP Option 82** with **DHCP snooping**.
    
- DHCP is not necessarily broadcast during every phase of the lease process.

```text
 |    150 = TFTP Server
 |
 +-- SECURITY
      DHCP Snooping
      Trusted / Untrusted

```

**Core idea:** DHCP automatically supplies host configuration; **DORA** establishes the  
lease, **T1/T2** manage renewal, **`ip helper-address`** enables DHCP across subnets,  
**Option 82** carries relay information, and **DHCP snooping** protects the Layer 2  
network from rogue DHCP behavior.
