# HTTPS

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**HTTPS** = **HTTP over TLS** (TCP 443). It encrypts web management sessions that would
otherwise cross the network in clear text. On Cisco devices it's the **recommended**
embedded web server, enabled with a **trustpoint/certificate**. The exam tests the port,
TLS handshake, and the `ip http secure-server` configuration.

---

## 2. Core Concepts

### 2.1 What TLS adds

| Layer | HTTP (note 10) | HTTPS |
|-------|----------------|-------|
| Port | 80 | 443 |
| Encryption | none | TLS record |
| Auth of server | none | certificate |
| Integrity | none | MAC in TLS |

- The TLS handshake negotiates cipher, authenticates the server (certificate), and
  derives session keys.

### 2.2 TLS handshake (simplified)

```
client --ClientHello
server --ServerHello + Certificate
client --verify cert, exchange keys
both   --Finished; encrypted channel live
```

- Server identity is proven by its **certificate** (signed by a CA).

### 2.3 Cisco secure server

```text
crypto key generate rsa modulus 2048
ip http secure-server
ip http secure-port 443
ip http authentication local
ip http access-class MGMT in
```

| Command | Role |
|---------|------|
| `crypto key generate rsa` | device keypair |
| `ip http secure-server` | enable HTTPS |
| `ip http secure-trustpoint` | server cert if CA used |
| `ip http authentication local` | user auth |

- Without an RSA keypair the secure server cannot start.

### 2.4 Certificates

| Type | Source | Use |
|------|--------|-----|
| Self-signed | generated locally | labs, quick setup |
| CA-signed | trusted CA | production |

- Modern devices alert on self-signed (or trust them after fingerprint check).

### 2.5 HTTPS vs SSH (management protocols)

| Aspect | HTTPS | SSH (note 12) |
|--------|-------|---------------|
| Purpose | web GUI/REST | CLI |
| Port | 443 | 22 |
| Auth | local / token | local / AAA |
| Result | GUI sessions | exec sessions |

- Both are **encrypted** management channels — the exam's secure answers.

### 2.6 Security practices

| Practice | Why |
|----------|-----|
| Disable plain HTTP | avoid cleartext |
| ACL the mgmt port | restrict access |
| Rotate certs | maintain trust |
| Use AAA | centralize auth |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No HTTPS | RSA key missing | crypto key generate |
| Cert warnings | self-signed | CA trustpoint |
| Host unreachable | 443 blocked | ACL |
| Auth loop | AAA config | authentication order |
| TLS error | time/cert mismatch | NTP + cert |

---

## 5. Exam Traps

- HTTPS = **TCP 443**, HTTP = 80.
- An **RSA keypair is required** for the secure server.
- `ip http secure-server` enables it; `ip http server` is the insecure twin.
- Server authenticated by **certificate**; NTP fixes cert-validity issues.
- Web GUI / REST = HTTPS is the expected answer.
