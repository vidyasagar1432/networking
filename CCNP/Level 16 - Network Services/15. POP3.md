# POP3

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**POP3** (TCP 110) downloads email from a server to a single client and **typically
removes it from the server**. It's the simple, **offline/download-and-go** protocol —
great for one device, poor for sync across phones/laptops. Secure variant = **POP3S (995)**.

---

## 2. Core Concepts

### 2.1 The model

| Aspect | POP3 |
|--------|------|
| Port | TCP 110 (995 SSL) |
| Direction | client **pulls** from server |
| Storage | client-local (server usually emptied) |
| State | offline |
| Sync | none across clients |

- Mail moves **server → client** and is deleted; the client owns the mailbox.

### 2.2 POP3 vs IMAP (the exam's core comparison)

| Aspect | POP3 | IMAP (note 16) |
|--------|------|----------------|
| Server storage | no (download) | yes (keep on server) |
| Multi-device | poor | strong |
| State | offline | online |
| Folders | single INBOX | server folders |
| Ports | 110 / 995 | 143 / 993 |

- **POP3 = download; IMAP = synchronized** — the classic trap.

### 2.3 Basic session

```
client: USER bob
server: +OK
client: PASS secret
server: +OK
client: LIST
client: RETR 1
client: DELE 1
client: QUIT
```

- Messages listed with numbers; RETR downloads; DELE marks delete (final on QUIT).

### 2.4 Security

| Port | Mode |
|------|------|
| 110 | plaintext |
| 995 | POP3S (TLS) |

- Mail credentials should never cross on 110; **995 (or STARTTLS)** is required.

### 2.5 When to choose POP3

| Need | Choose |
|------|--------|
| Single client / low server load | POP3 |
| Offline travel access | POP3 |
| Multiple devices / sync | IMAP |
| Server-side search | IMAP |

### 2.6 Enterprise note

- Network teams see POP3 mostly as a **traffic/permit need** and a **DLP consideration**
  (data lands on endpoints, not just servers).

## 3. Configuration / Commands

```text
telnet mailhost 110              ! manual POP3 test
USER user / PASS pass
LIST / RETR n / DELE n / QUIT
```

- Manual conversation verifies reachability and mailbox state.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Cannot connect | TCP 110 blocked | ACL |
| -ERR auth | wrong user/pass | credentials |
| Mail vanished | deleted after download | keep-on-server option |
| Connection reset | TLS vs plaintext | use 995 |
| Timeout | server load | server status |

---

## 5. Exam Traps

- **POP3 = 110** (plain), **995** (SSL).
- **Downloads and deletes** by default — the "no sync" trap.
- IMAP keeps mail on the server **and syncs** — the contrast answer.
- RETR/DELE sequence with state change at QUIT.
- One mailbox ≈ one client.
