# SSH

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**SSH (Secure Shell)** is a secure remote-management protocol that provides **encrypted CLI access** to network devices. It uses **TCP port 22** and is the secure replacement for Telnet.

SSH provides:

- **Confidentiality** — encrypts the session.
    
- **Integrity** — detects tampering.
    
- **Server authentication** — verifies the SSH server/device using host keys.
    
- **User authentication** — verifies the administrator using passwords, public keys, or AAA mechanisms, depending on platform/configuration.
    
- **Secure file transfer** — **SCP** uses SSH for secure file copying.
    

On Cisco IOS, SSH is typically enabled by configuring a hostname/domain, generating cryptographic keys, configuring SSHv2, and restricting VTY lines to SSH.

## 2. Core Concepts

### 2.1 What SSH Provides

|Feature|SSH|
|---|---|
|Protocol|Secure remote-management protocol|
|Transport|TCP|
|Port|**22**|
|Confidentiality|Yes|
|Integrity|Yes|
|Server authentication|Host key|
|User authentication|Password / public key / AAA, depending on configuration|
|Remote CLI|Yes|
|Secure file transfer|SCP|

Unlike Telnet, SSH encrypts the management session, including credentials and commands.

---

### 2.2 SSH Versions

|Version|Status|
|---|---|
|SSHv1|Legacy / insecure|
|SSHv2|Modern and preferred|

For Cisco IOS, explicitly configure:

```text
ip ssh version 2
```

**Exam point:** Do not confuse SSH version with the cryptographic key type. SSHv2 is the protocol version; RSA is one possible public-key algorithm used by Cisco IOS.

---

## 3. How SSH Works

A simplified SSH connection proceeds through these stages:

```text
1. TCP 3-way handshake
        ↓
2. SSH version exchange
        ↓
3. Key exchange / cryptographic negotiation
        ↓
4. Server authentication using host key
        ↓
5. User authentication
        ↓
6. Encrypted SSH session
```

### Important distinction

- **Host key** → authenticates the **SSH server/device**.
    
- **User credentials/key** → authenticate the **administrator/user**.
    

A changed host key can indicate a possible **man-in-the-middle attack**, but it can also happen legitimately when a device is replaced, rebuilt, or its keys are regenerated.

## 4. Enabling SSH on Cisco IOS

A typical local-user SSH configuration:

```text
hostname R1
ip domain-name ccnp.example
!
username admin privilege 15 secret AdminPass123
!
crypto key generate rsa modulus 2048
!
ip ssh version 2
!
line vty 0 15
 login local
 transport input ssh
```

### What each command does

|Command|Purpose|
|---|---|
|`hostname R1`|Sets the device hostname|
|`ip domain-name ccnp.example`|Sets the IP domain name|
|`crypto key generate rsa modulus 2048`|Generates RSA cryptographic keys used by the SSH server|
|`ip ssh version 2`|Forces SSHv2|
|`username ... secret ...`|Creates a local login account|
|`login local`|Uses the local username database|
|`transport input ssh`|Allows SSH on the VTY lines and prevents Telnet|

### Key-generation requirement

On typical Cisco IOS configurations, the **hostname and IP domain name are used to form the device's FQDN and are required before generating RSA keys**.

Example:

```text
R1(config)# hostname R1
R1(config)# ip domain-name ccnp.example
R1(config)# crypto key generate rsa modulus 2048
```

## 5. SSH Authentication

SSH can use different authentication mechanisms depending on the Cisco platform and configuration.

### Local authentication

```text
username admin secret AdminPass123
!
line vty 0 15
 login local
 transport input ssh
```

`login local` tells the VTY line to authenticate users against the locally configured username database.

### AAA authentication

SSH can also use centralized AAA through mechanisms such as:

- **TACACS+**
    
- **RADIUS**
    

Example concept:

```text
SSH client
    ↓
Cisco device
    ↓
AAA
    ↓
TACACS+ / RADIUS server
```

**Exam point:** SSH provides the secure transport; **AAA determines how users are authenticated/authorized/accounted for**.

## 6. VTY Lines and SSH

The VTY lines control incoming remote terminal sessions.

```text
line vty 0 15
 transport input ssh
 login local
```

### `transport input`

```text
transport input ssh
```

Allows:

```text
SSH
```

and prevents:

```text
Telnet
```

Other possibilities include:

```text
transport input telnet
transport input ssh telnet
transport input none
```

**Exam trap:**

`transport input ssh` controls **incoming connections to the device's VTY lines**. It does not configure the router's outbound SSH client.

---

## 7. SSH Client vs SSH Server

A Cisco router can act as both an SSH **server** and an SSH **client**.

### SSH server

The router accepts incoming SSH sessions:

```text
Administrator
     |
     | SSH TCP/22
     ↓
   Router
```

Relevant configuration:

```text
crypto key generate rsa modulus 2048
ip ssh version 2
line vty 0 15
 transport input ssh
```

### SSH client

The router initiates an SSH connection to another device:

```text
Router A
   |
   | SSH TCP/22
   ↓
Router B
```

Example:

```text
R1# ssh -l admin 10.0.0.2
```

## 8. SSH File Transfer

### SCP

**SCP (Secure Copy Protocol)** transfers files over SSH and uses **TCP port 22**.

Example:

```text
copy running-config scp:
```

or:

```text
copy scp: running-config
```

SCP is commonly used for securely transferring:

- Cisco IOS images
    
- Configuration files
    
- Other device files
    

### SFTP

**SFTP (SSH File Transfer Protocol)** is also an SSH-based file-transfer protocol and normally uses **TCP 22**.

However, **SFTP availability and command support depend on the Cisco platform and IOS/IOS XE release**.

For CCNP ENCOR, emphasize:

> **SCP = secure file transfer over SSH/TCP 22.**

Do not assume every Cisco IOS platform supports SFTP simply because it supports SSH.

## 9. SSH vs Telnet

|Aspect|SSH|Telnet|
|---|---|---|
|Protocol|SSH|Telnet|
|Transport|TCP|TCP|
|Port|**22**|**23**|
|Encryption|Yes|No|
|Credentials|Protected by encrypted SSH session|Sent in cleartext|
|Session data|Encrypted|Cleartext|
|Secure management|Yes|No|
|Recommended|Yes|No|

### Exam rule

> **SSH = TCP 22 + encrypted management**  
> **Telnet = TCP 23 + cleartext management**

## 10. Important SSH Configuration Commands

### Configure SSHv2

```text
ip ssh version 2
```

### Set SSH timeout

```text
ip ssh time-out 60
```

The value specifies how long the SSH authentication process can remain incomplete before timing out.

### Set authentication retries

```text
ip ssh authentication-retries 3
```

Controls the number of authentication attempts allowed.

### Configure VTY access

```text
line vty 0 15
 login local
 transport input ssh
```

### Generate RSA keys

```text
crypto key generate rsa modulus 2048
```

## 12. Troubleshooting SSH

|Symptom|Possible Cause|Check|
|---|---|---|
|SSH unavailable|RSA keys not generated|`show crypto key mypubkey rsa`|
|Cannot connect|SSH not configured/enabled|`show ip ssh`|
|Telnet works but SSH doesn't|SSH/keys/VTY configuration problem|SSH configuration|
|Telnet connection refused|`transport input ssh`|`show running-config \| section line vty`|
|Authentication failure|Wrong credentials or AAA problem|Local user / AAA configuration|
|Timeout|ACL, routing, reachability, or SSH timeout|Ping / ACL / routing|
|SSHv1 issue|Client/server version mismatch|`show ip ssh`|
|Host-key warning|Key changed or possible MITM|Verify device/key|
|No VTY access|VTY lines unavailable or restricted|VTY configuration|
|Connection reaches device but login fails|Authentication configuration|`login local` / AAA|

### Basic troubleshooting sequence

```text
1. Verify IP connectivity
        ↓
2. Verify TCP/22 is reachable
        ↓
3. Verify SSH is enabled
        ↓
4. Verify RSA/cryptographic keys exist
        ↓
5. Verify SSH version
        ↓
6. Verify VTY configuration
        ↓
7. Verify local/AAA authentication
        ↓
8. Check ACLs and other security policies
```

## 14. Common SSH Failure Causes

### No RSA keys

Problem:

```text
SSH server cannot operate correctly because required cryptographic keys are absent.
```

Check:

```text
show crypto key mypubkey rsa
```

Generate:

```text
crypto key generate rsa modulus 2048
```

---

### SSH version problem

Check:

```text
show ip ssh
```

Configure:

```text
ip ssh version 2
```

---

### VTY does not permit SSH

Incorrect:

```text
line vty 0 15
 transport input telnet
```

Correct:

```text
line vty 0 15
 transport input ssh
```

---

### Authentication failure

Check:

```text
username admin secret AdminPass123
```

and:

```text
line vty 0 15
 login local
```

If centralized AAA is being used, verify the TACACS+/RADIUS configuration and reachability as well.

---

### ACL blocks SSH

An ACL can prevent TCP/22 from reaching the device.

Check:

```text
show access-lists
show running-config
```

Also verify:

```text
ping <destination>
```

and network routing/reachability.

## 15. SSH Security Best Practices

- Use **SSHv2**.
    
- Disable Telnet where possible.
    
- Use strong local secrets or centralized AAA.
    
- Restrict VTY access with an access-class/ACL where appropriate.
    
- Use management networks or dedicated management interfaces where appropriate.
    
- Use appropriate cryptographic key sizes and algorithms supported by the platform.
    
- Limit authentication retries.
    
- Configure a reasonable SSH timeout.
    
- Monitor active SSH sessions.
    
- Avoid exposing device management directly to untrusted networks.
    
- Use TACACS+ or another appropriate AAA solution for centralized administrative control.
    

Example:

```text
ip ssh version 2
ip ssh time-out 60
ip ssh authentication-retries 3
!
line vty 0 15
 login local
 transport input ssh
```

## 16. SSH vs SCP vs SFTP

|Technology|Purpose|Transport|Port|
|---|---|---|---|
|SSH|Secure remote CLI|TCP|**22**|
|SCP|Secure file copy|SSH/TCP|**22**|
|SFTP|SSH-based file transfer|SSH/TCP|**22**|
|Telnet|Remote CLI|TCP|**23**|
|FTP|File transfer|TCP|**21 control**|
|TFTP|Simple file transfer|UDP|**69**|

**Important:** SCP and SFTP are file-transfer mechanisms; SSH itself is the secure remote-management protocol.

## 17. Exam Traps

- **SSH uses TCP 22.**
    
- **Telnet uses TCP 23.**
    
- SSH encrypts the management session; Telnet does not.
    
- SSHv2 is preferred; explicitly configure `ip ssh version 2`.
    
- `crypto key generate rsa` generates RSA keys used by typical Cisco IOS SSH server configurations.
    
- A hostname and IP domain name are normally required before generating RSA keys.
    
- `transport input ssh` permits SSH and prevents Telnet on the affected VTY lines.
    
- `login local` uses the local username database.
    
- AAA can provide centralized authentication/authorization/accounting.
    
- **SCP uses SSH/TCP 22.**
    
- Do not assume SFTP support is identical across all Cisco IOS/IOS XE platforms.
    
- SSH server and SSH client are separate roles; a router can perform both.
    
- An ACL can block TCP/22 even when SSH itself is correctly configured.
    
- A changed SSH host key is not automatically proof of a MITM attack; legitimate key changes can also trigger warnings.
    
- **SSH does not mean "RSA only."** RSA is one cryptographic mechanism used in common Cisco IOS SSH configurations.
    
- `transport input ssh` affects **incoming VTY access**, not outbound SSH connections initiated by the device.
