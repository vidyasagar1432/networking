# SSH

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**SSH** (TCP 22) is the **encrypted** remote-management protocol — the mandated
replacement for Telnet on network devices. Cisco enables it with `crypto key generate rsa`
plus VTY `transport input ssh`. It supports **SSHv2**, **authentication via local
users/AAA**, and secure **file transfer (SCP/SFTP)**.

---

## 2. Core Concepts

### 2.1 What SSH provides

| Security feature | Detail |
|------------------|--------|
| Confidentiality | session encrypted |
| Integrity | data authenticated |
| Server auth | host key |
| Client auth | password / key |

- Unlike Telnet (note 13), nothing crosses in cleartext.

### 2.2 Versions

| Version | Status |
|---------|--------|
| SSHv1 | legacy, known flaws |
| SSHv2 | current, required |

- Cisco default (modern) uses **SSHv2**; disable v1.

### 2.3 Enabling SSH on Cisco IOS

```text
hostname R1
ip domain-name ccnp.example
crypto key generate rsa modulus 2048
!
username admin secret adminpass
line vty 0 15
 transport input ssh
 login local
```

- **Hostname + domain** feed the RSA key generation.
- RSA key is the server identity; 2048-bit is the safe minimum.
- `transport input ssh` **blocks Telnet** on the VTY lines.

### 2.4 Client and file transfer

```text
ssh -l admin 10.0.0.1
copy running-config scp://admin@10.0.0.1/
```

| Tool | Port | Uses |
|------|------|------|
| SSH CLI | 22 | exec sessions |
| SCP | 22 | secure copy (files) |
| SFTP | 22 | secure file transfer |

- SCP/SFTP replace TFTP/FTP for secure config/image exchange.

### 2.5 SSH vs Telnet

| Aspect | SSH | Telnet |
|--------|-----|--------|
| Port | 22 | 23 |
| Encryption | yes | no |
| Auth | password/key/AAA | plaintext password |
| Cisco default | on (modern) | off |
| Best practice | yes | no |

- The exam's secure-management answer is **SSH**.

### 2.6 Troubleshooting SSH

| Symptom | Likely cause |
|---------|--------------|
| No RSA key | key not generated |
| "No supported authentication" | v1-only client |
| Connection refused | VTY transport input not ssh |
| Timeout | ACL / TCP 22 |
| Host key changed | MITM alert — verify |

## 5. Exam Traps

- **SSH = TCP 22**; **Telnet = 23**.
- RSA keypair **required** — `crypto key generate rsa`.
- `transport input ssh` on VTY (blocks Telnet).
- SSHv2 over v1.
- SCP/SFTP ride SSH (22) for secure file transfer.
- Hostname + domain-name needed before key generation.
