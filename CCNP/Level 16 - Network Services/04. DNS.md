# DNS

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DNS (Domain Name System)** translates human-readable domain names into IP  
addresses and can also provide other service information.

Typical DNS communication uses:

- **UDP 53** — normal DNS queries/responses in most cases
    
- **TCP 53** — zone transfers and DNS exchanges that require TCP, including  
    responses that cannot be completed over UDP
    

DNS normally follows a **distributed hierarchy**:

```text
Client
  |
  | Recursive query
  v
Recursive DNS resolver
  |
  | Iterative queries
  v
Root DNS servers
  |
  v
TLD DNS servers
  |
  v
Authoritative DNS server
```

The recursive resolver obtains the answer and returns it to the client,  
often using a cached result.

---

## 2. Core Concepts

### 2.1 Recursive vs Iterative Queries

|Query type|Meaning|
|---|---|
|Recursive|The DNS server is asked to obtain the final answer on behalf of the client|
|Iterative|The server returns the best information it has, such as an answer or referral|

Typical flow:

```text
Client
  |
  | Recursive
  v
Local recursive resolver
  |
  | Iterative
  v
Root
  |
  v
TLD
  |
  v
Authoritative server
```

Important:

> **Recursion is a service provided by a DNS resolver; iteration is the normal  
> method used by that resolver when walking the DNS hierarchy.**

A recursive resolver may answer immediately from its cache without contacting  
the root, TLD, or authoritative server.

---

## 3. DNS Hierarchy

DNS is hierarchical:

```text
.
├── com
│   └── example.com
│       ├── www
│       ├── mail
│       └── vpn
└── org
    └── example.org
```

### Root

The root (`.`) is the top of the DNS hierarchy.

### TLD

Top-Level Domains include:

```text
.com
.org
.net
.in
```

### Authoritative DNS Server

An authoritative DNS server contains authoritative information for a DNS  
zone and can provide the definitive answer for that zone.

### Recursive Resolver

A recursive resolver performs resolution on behalf of clients and normally  
maintains a cache.

# 4. DNS Record Types

|Record|Purpose|Example|
|---|---|---|
|**A**|Name → IPv4 address|`www.example.com → 192.0.2.10`|
|**AAAA**|Name → IPv6 address|`www.example.com → 2001:db8::10`|
|**CNAME**|Alias → canonical name|`www → web.example.com`|
|**MX**|Mail server for a domain|`example.com → mail.example.com`|
|**PTR**|IP address → hostname|`10.2.0.192.in-addr.arpa → host.example.com`|
|**NS**|Authoritative nameserver for a zone|`example.com → ns1.example.com`|
|**SOA**|Zone authority and administrative parameters|Primary server, serial, timers|
|**SRV**|Service location: priority, weight, port, target|`_sip._tcp.example.com`|
|**TXT**|Arbitrary text; commonly SPF-related information and verification data|`example.com → "..."`|
|**CAA**|Specifies which CAs may issue certificates for a domain|`example.com → 0 issue "..."`|

### High-priority ENCOR records

Know these especially well:

```text
A       IPv4
AAAA    IPv6
CNAME   Alias
MX      Mail
PTR     Reverse lookup
NS      Nameserver
SRV     Service discovery
SOA     Zone authority
TXT     Text / verification
```

## 5. Important Record Details

### A

Maps a hostname to an IPv4 address.

```text
www.example.com → 192.0.2.10
```

### AAAA

Maps a hostname to an IPv6 address.

```text
www.example.com → 2001:db8::10
```

### CNAME

Creates an alias for another hostname.

```text
www.example.com CNAME web.example.com
```

A CNAME points to a **name**, not directly to an IP address.

A CNAME generally cannot coexist with other data at the same DNS name,  
with important DNS-specific exceptions such as DNSSEC-related records.

### MX

Identifies mail servers and includes a **preference value**.

Lower preference values are preferred.

```text
example.com MX 10 mail1.example.com
example.com MX 20 mail2.example.com
```

### PTR

Provides reverse DNS:

```text
192.0.2.10
    |
    v
10.2.0.192.in-addr.arpa
    |
    v
host.example.com
```

IPv4 reverse DNS uses:

```text
in-addr.arpa
```

IPv6 reverse DNS uses:

```text
ip6.arpa
```

### NS

Identifies authoritative nameservers for a zone.

### SRV

Used for service discovery.

It can specify:

- Service
    
- Protocol
    
- Priority
    
- Weight
    
- Port
    
- Target host
    

Example:

```text
_sip._tcp.example.com
```

### SOA

The **Start of Authority** record contains important zone information,  
including:

- Primary authoritative server
    
- Responsible party
    
- Serial number
    
- Refresh timer
    
- Retry timer
    
- Expire timer
    
- Negative-cache TTL

# 6. DNS Resolution

Suppose a client requests:

```text
www.example.com
```

A typical resolution process is:

```text
1. Client → Recursive Resolver
              |
              | cache lookup
              v
2. If not cached → Root
              |
              v
3. Root → .com TLD information
              |
              v
4. Resolver → .com TLD
              |
              v
5. TLD → example.com authoritative server
              |
              v
6. Resolver → Authoritative DNS
              |
              v
7. Authoritative → A/AAAA answer
              |
              v
8. Resolver → Client
```

If the resolver already has a valid cached answer, steps 2–6 may not be  
necessary.

---

# 7. DNS Caching and TTL

DNS resolvers cache answers to reduce:

- DNS traffic
    
- Resolution latency
    
- Load on authoritative servers
    

**TTL (Time To Live)** specifies how long a DNS record may normally be  
cached.

Example:

```text
www.example.com → 192.0.2.10
TTL = 300
```

The resolver can normally cache that answer for up to **300 seconds**.

### Important

TTL is **not a guarantee that every DNS cache will behave identically**.  
It is the DNS record's cache lifetime parameter.

Shorter TTL:

- Faster propagation of changes
    
- More DNS queries
    

Longer TTL:

- Better caching
    
- Fewer queries
    
- Changes may remain cached longer
    

---

# 8. Positive and Negative Responses

A DNS lookup can return:

### Positive answer

The requested record exists.

```text
www.example.com → 192.0.2.10
```

### NXDOMAIN

The requested DNS name does not exist.

```text
NXDOMAIN
```

Negative responses can also be cached according to DNS negative-caching  
rules.

# 9. DNS on Cisco IOS / IOS XE

Cisco routers can perform DNS name resolution for their own CLI and  
management functions.

### Enable DNS lookup

```cisco
ip domain lookup
```

### Configure DNS server

```cisco
ip name-server 10.0.0.5
```

Multiple DNS servers can be configured:

```cisco
ip name-server 10.0.0.5 10.0.0.6
```

### Configure the router's domain name

```cisco
ip domain name ccnp.example
```

The domain name is used for functions such as forming the router's FQDN  
and other IOS features that depend on a domain name.

### Disable DNS lookup

```cisco
no ip domain lookup
```

This is commonly used in labs because a mistyped IOS command can otherwise  
cause the router to attempt DNS resolution.

Example:

```text
R1# shwo ip interface brief
```

Without DNS lookup disabled, IOS may interpret `shwo` as a hostname and  
attempt DNS resolution.

# 10. Router Host Table

IOS can maintain local hostname-to-address mappings.

### Configure a static host entry

```cisco
ip host R2 192.0.2.2
```

### Display host information

```cisco
show hosts
```

### Clear IOS host cache

```cisco
clear host *
```

Important:

> `clear host *` affects the Cisco device's local hostname/cache information.  
> It does **not** flush the cache of an external DNS resolver.

# 11. DNS Verification and Troubleshooting

### IOS

```cisco
show hosts
show running-config | include ip name-server
show running-config | include ip domain
```

### Test name resolution

```cisco
ping www.example.com
```

### DNS testing tools

```text
nslookup www.example.com
dig www.example.com
```

### IOS DNS debugging

```cisco
debug ip domain
```

Use debugging carefully on production devices because debug output can  
consume CPU and generate large amounts of console output.

Disable debugging with:

```cisco
undebug all
```

# 13. Enterprise DNS Concepts

### Split-Horizon DNS

Provides different answers depending on where the query originates.

Example:

```text
Internal user:
www.example.com → 10.10.10.10

Internet user:
www.example.com → 203.0.113.10
```

Also commonly called **split DNS** or **DNS views**, depending on  
implementation.

### DNS Round-Robin

Multiple A/AAAA records can be returned for the same name.

```text
www.example.com → 192.0.2.10
www.example.com → 192.0.2.11
www.example.com → 192.0.2.12
```

This can distribute clients across multiple addresses, but it is **not a  
replacement for a proper load balancer**.

### DNS64

DNS64 can synthesize an AAAA record from an IPv4-only A record so an  
IPv6-only client can communicate with an IPv4 destination through NAT64.

Conceptually:

```text
IPv6-only client
       |
       v
     DNS64
       |
       | synthesized AAAA
       v
      NAT64
       |
       v
    IPv4 server
```

# 14. DNSSEC Awareness

**DNSSEC (DNS Security Extensions)** provides authentication of DNS data  
using cryptographic signatures.

It helps protect against attacks such as forged DNS responses.

DNSSEC provides:

- Data origin authentication
    
- Data integrity
    
- Authenticated denial of existence
    

DNSSEC does **not** encrypt normal DNS queries.

> For ENCOR, understand the purpose of DNSSEC rather than memorizing all  
> DNSSEC record/signing details unless specifically required by your study  
> plan.


# 16. DNS Security Considerations

Common DNS-related concerns include:

- DNS spoofing
    
- DNS cache poisoning
    
- Unauthorized zone transfers
    
- DNS amplification attacks
    
- Malicious or compromised DNS records
    
- Misconfigured recursive resolvers
    

Enterprise DNS servers should therefore control:

- Who may perform recursive queries
    
- Who may perform zone transfers
    
- Which clients may access internal DNS
    
- Which DNS servers are authoritative

# 18. Exam Traps

- **UDP 53** is commonly used for DNS queries.
    
- **TCP 53** is used for zone transfers and DNS exchanges requiring TCP.
    
- Do not memorize “TCP = only large responses”; that is incomplete.
    
- **Recursive** means the resolver obtains the final answer for the requester.
    
- **Iterative** means the server provides the best information/referral it  
    has.
    
- `A` = IPv4.
    
- `AAAA` = IPv6.
    
- `CNAME` = alias to another hostname.
    
- `MX` = mail server + preference.
    
- `PTR` = reverse DNS.
    
- `NS` = nameserver.
    
- `SRV` = service discovery.
    
- `SOA` = zone authority information.
    
- **Lower MX preference is preferred.**
    
- DNS caching is controlled by **TTL**.
    
- `ip name-server` configures DNS servers used by the Cisco device.
    
- `ip domain lookup` enables DNS name resolution.
    
- `no ip domain lookup` disables DNS lookup.
    
- `ip domain name` configures the router's domain name; it is not simply a  
    DNS-server setting.
    
- `show hosts` displays IOS hostname/cache information.
    
- `clear host *` does not flush an external DNS server's cache.
    
- DNSSEC authenticates DNS data but **does not encrypt DNS traffic**.
    
- DNS64 is associated with **NAT64/IPv6-only clients**.
    
- Split-horizon DNS can return different answers to internal and external  
    clients.
    
- DNS round-robin is basic distribution, not full load balancing.
