# DNS

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DNS** (UDP 53, TCP 53 for large responses) resolves hostnames to IP addresses. Clients
query **local servers**, which may **recursively** chase **authoritative** servers. The
exam tests record types, the recursion/authority model, and the router-side config
(`ip name-server`, `ip domain lookup`).

---

## 2. Core Concepts

### 2.1 Queries: recursive vs iterative

| Type | Client action | Server behavior |
|------|---------------|-----------------|
| Recursive | one query | server hunts the answer for you |
| Iterative | query, maybe redirect | server returns best known / referral |

- Real clients send **recursive**; servers talk **iterative** to roots/TLDs.

### 2.2 Record types

| Record | Maps | Example |
|--------|------|---------|
| A | name → IPv4 | host.example.com → 10.0.0.5 |
| AAAA | name → IPv6 | → 2001:db8::5 |
| CNAME | alias → canonical | www → host |
| MX | domain → mail server (+preference) | 10 mail.corp |
| PTR | IP → name (reverse) | 5.0.0.10.in-addr.arpa |
| NS | domain → nameserver | example.com NS |
| SRV | service → host/port | _sip._udp |

- Exam favorites: **A, AAAA, CNAME, MX, PTR, SRV**.

### 2.3 The resolution model

```
client -->(recursive) local DNS -->(iterative) root/TLD --> authoritative
                           <--answer back down the chain
```

- Authoritative servers actually **own** the zone; caching improves performance.

### 2.4 Router-side config

```text
ip domain lookup
ip name-server 10.0.0.5
ip domain name ccnp.example
```

- `ip name-server` sets the resolver; `ip domain name` appends the suffix.
- `no ip domain lookup` disables the DNS attempt (speeds CLI `ping hostname`).

### 2.5 DNS in the enterprise

| Aspect | Detail |
|--------|--------|
| Split-horizon | internal vs public views |
| DNS64 | AAAA synthesis for NAT64 (note L15) |
| Round-robin | multiple A records |
| TTL | cache lifetime (300 s typical) |

- DNS is a dependency for **application delivery** — a leading outage suspect.

### 2.6 Verification

```text
nslookup / dig host.example
show hosts
debug ip domain
```

- `show hosts` lists cached name→address mappings on the router.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Unknown host | no name-server / lookup off | ip domain lookup |
| Timeout | DNS port blocked | ACL UDP 53 |
| Wrong answers | resolver cached stale | clear host * |
| App slow | TTL / recursion slow | server metrics |
| Split mismatch | internal vs external views | DNS views |

---

## 5. Exam Traps

- Ports: **UDP 53** primary; TCP 53 for zone transfers / big answers.
- **Recursive = client-side**; iterative = server side.
- `ip name-server` + `ip domain lookup` = basic router resolver.
- **MX** has a preference; **CNAME** can't coexist with other data at the same name.
- DNS64 (note 15) synthesizes AAAA for IPv6-only clients.
