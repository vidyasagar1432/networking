# DHCP Relay

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DHCP relay** forwards broadcast DHCP requests to a server in **another subnet**. Since
DHCP starts as a broadcast, an L3 boundary would kill it; the router converts DISCOVER to
a **unicast** toward `ip helper-address`, carrying the client's subnet in **option 82 /
giaddr** so the server assigns a correct address.

---

## 2. Core Concepts

### 2.1 Why a relay is needed

- Client broadcasts to 255.255.255.255 → routers won't forward by default.
- Without helper, DHCP only works within the same VLAN/subnet.

### 2.2 Configuration

```text
interface Gi0/0.10
 ip address 10.0.10.1 255.255.255.0
 ip helper-address 10.0.0.5    ! DHCP server
```

- The two **most important facts**: it is **per-interface**, supports multiple helpers.

### 2.3 How the relay works

| Step | Action |
|------|--------|
| 1 | Client broadcasts DISCOVER |
| 2 | Router relays to helper as unicast |
| 3 | Server sees giaddr=client VLAN subnet |
| 4 | Server sends OFFER via relay (broadcast on client VLAN) |
| 5 | Client REQUEST -> relay -> server -> ACK |

- giaddr tells the server which subnet the client is in.

### 2.4 UDP ports forwarded by helper

| Port | Service |
|------|---------|
| 67/68 | DHCP |
| 69 | TFTP |
| 53 | DNS |
| 137/138 | NetBIOS (legacy) |

- `ip helper-address` forwards **multiple UDP broadcasts** by default, not only DHCP.
- Modern practice: `ip forward-protocol` to limit what crosses.

### 2.5 Relay + option 82 / snooping integration

- Relay inserts option 82 (circuit/remote id) — snooping and policy can then validate the
  client's exact port/VLAN (note 02).

### 2.6 Verification

```text
show ip interface Gi0/0.10 | include helper
debug ip dhcp server packet
```

- Confirm the helper is attached to the **client-facing interface** (the one on the
  client's subnet).

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No DHCP across subnet | helper missing | ip helper-address |
| Wrong scope | helper on wrong interface | giaddr checks |
| Extra broadcasts | helper forwards many UDP | ip forward-protocol |
| Relay in wrong VLAN | SVI without helper | per-interface config |
| Option 82 mismatch | relay unsupported on path | snooping config |

---

## 5. Exam Traps

- `ip helper-address` = **per-interface** (on the client-side VLAN/SVI).
- Relay **unicasts** DISCOVER to the server; giaddr carries the client subnet.
- Helper forwards TFTP/DNS/NetBIOS broadcasts too — not just DHCP.
- Multiple server helpers allowed (failover).
- Servers answer via the relay, which restores broadcast on the client VLAN.
