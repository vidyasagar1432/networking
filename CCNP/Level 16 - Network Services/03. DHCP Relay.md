# DHCP Relay

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**DHCP Relay** allows DHCP clients and DHCP servers to communicate across **different IP  
subnets**.

A DHCP client initially sends a **DHCPDISCOVER as a broadcast**. Routers and Layer-3  
switches do not normally forward these broadcasts between subnets.

A Layer-3 interface configured with:

```cisco
ip helper-address <DHCP-server-IP>
```

acts as a **DHCP relay agent**. It receives the client's broadcast, forwards the DHCP  
request toward the DHCP server, and sets **`giaddr`** so the DHCP server can determine the  
client's subnet and select the appropriate DHCP scope.

> **Core formula:**  
> **DHCP Relay = `ip helper-address` + `giaddr` + Layer-3 reachability to the DHCP server**

---

# 2. Why DHCP Relay Is Required

### Without DHCP Relay

```text
Client VLAN 10
10.10.10.0/24
      |
      | DHCPDISCOVER
      | Broadcast
      v
   L3 Router
      X
      |
      | Broadcast is NOT normally routed
      X
DHCP Server
10.0.0.5
```

The router does not normally forward the DHCP broadcast across the Layer-3 boundary.

### With DHCP Relay

```text
Client
10.10.10.x
   |
   | DHCPDISCOVER
   | Broadcast
   v
L3 Switch / Router
10.10.10.1
   |
   | DHCP Relay
   | Unicast toward server
   v
DHCP Server
10.0.0.5
```

The relay converts the **server-bound forwarding behavior** from a local broadcast into  
traffic that can cross the routed network.

# 3. Basic Configuration

## 3.1 Router Interface

```cisco
interface GigabitEthernet0/0
 ip address 10.10.10.1 255.255.255.0
 ip helper-address 10.0.0.5
 no shutdown
```

The interface:

```text
10.10.10.1/24
```

is the client's default gateway.

The DHCP server is:

```text
10.0.0.5
```

---

## 3.2 Router-on-a-Stick

```cisco
interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 10.10.10.1 255.255.255.0
 ip helper-address 10.0.0.5
```

The helper is configured on the **client-facing Layer-3 subinterface**.

---

## 3.3 Layer-3 Switch / SVI

```cisco
interface Vlan10
 ip address 10.10.10.1 255.255.255.0
 ip helper-address 10.0.0.5
 no shutdown
```

For a multilayer switch, the helper is configured on the **SVI for the client VLAN**.

> **Exam rule:** Configure `ip helper-address` on the Layer-3 interface that receives the  
> client's DHCP broadcast.

# 4. DHCP Relay Operation

The simplified process is:

```text
1. Client
   |
   | DHCPDISCOVER - Broadcast
   v
2. Relay
   |
   | Sets giaddr
   | Forwards toward DHCP server
   v
3. DHCP Server
   |
   | DHCPOFFER
   v
4. Relay
   |
   v
5. Client

6. Client
   |
   | DHCPREQUEST
   v
7. Relay
   |
   v
8. DHCP Server
   |
   | DHCPACK
   v
9. Relay
   |
   v
10. Client
```

The normal DHCP process is known as **DORA**:

```text
D = Discover
O = Offer
R = Request
A = Acknowledgment
```

---

# 5. DHCP DORA Through a Relay

|Step|Source|Destination|Important Point|
|---|---|---|---|
|1|Client|Broadcast|DHCPDISCOVER|
|2|Relay|DHCP Server|Forwards request|
|3|DHCP Server|Relay|DHCPOFFER|
|4|Relay|Client|Forwards OFFER|
|5|Client|Relay/Server|DHCPREQUEST|
|6|Relay|DHCP Server|Forwards REQUEST|
|7|DHCP Server|Relay|DHCPACK|
|8|Relay|Client|Forwards ACK|

The exact Layer-2 destination of DHCP replies can depend on the DHCP message fields and  
client state. Therefore, do not memorize that every OFFER or ACK is always a broadcast.

# 6. `giaddr` — Gateway IP Address

**`giaddr` is one of the most important DHCP relay concepts.**

When the relay receives the DHCP request, it sets `giaddr` to identify the client subnet.

Example:

```text
Client subnet:
10.10.10.0/24

Relay interface:
10.10.10.1

DHCP Server:
10.0.0.5
```

The relay can set:

```text
giaddr = 10.10.10.1
```

The DHCP server can then determine:

```text
giaddr 10.10.10.1
        |
        v
Client subnet = 10.10.10.0/24
        |
        v
Use DHCP scope for 10.10.10.0/24
```

### Why `giaddr` matters

Without the relay information identifying the client's subnet, a centralized DHCP server would  
not know which subnet/scope should service the client.

> **Exam memory:**  
> **`giaddr` → identifies the subnet from which the DHCP request originated.**

---

# 7. `giaddr` vs. Option 82

These are **different DHCP relay mechanisms**.

## `giaddr`

- DHCP/BOOTP relay field.
    
- Set by the relay agent.
    
- Identifies the client's Layer-3 subnet.
    
- Used by the DHCP server to select the appropriate scope.
    

## Option 82

**DHCP Relay Agent Information Option.**

It provides additional information about where the client is connected.

Common suboptions include:

```text
Circuit ID
Remote ID
```

### Circuit ID

Can identify information such as:

- Switch port
    
- VLAN
    
- Interface
    
- Circuit/attachment information
    

### Remote ID

Can identify information such as:

- Relay device
    
- Switch
    
- Administrative identifier
    

Option 82 is especially useful with **DHCP snooping and DHCP security policies**.

> **Critical exam trap:**  
> **`giaddr` ≠ Option 82**

# 9. UDP Ports

DHCP uses:

```text
UDP 67 = DHCP Server
UDP 68 = DHCP Client
```

Typical communication:

```text
Client  -> Server
UDP 68  -> UDP 67

Server  -> Client
UDP 67  -> UDP 68
```

> **Exam memory:**  
> **67 = Server**  
> **68 = Client**

# 10. `ip helper-address` Is Not DHCP-Only

Cisco IOS `ip helper-address` is a general mechanism for forwarding certain **UDP  
broadcasts** across a Layer-3 boundary.

DHCP is the most common use.

Historically, the default forwarding set can include protocols such as:

|UDP|Example Service|
|--:|---|
|67/68|DHCP/BOOTP|
|69|TFTP|
|53|DNS|
|137/138|NetBIOS|

The exact default forwarding behavior can vary by IOS/platform and configuration.

You can control UDP broadcast forwarding with:

```cisco
ip forward-protocol
```

> **Exam trap:**  
> `ip helper-address` does **not** mean "DHCP only."

---

# 11. Multiple Helper Addresses

Multiple DHCP servers can be configured:

```cisco
interface Vlan10
 ip helper-address 10.0.0.5
 ip helper-address 10.0.0.6
```

The relay can forward DHCP requests toward multiple configured helper addresses.

### Important

Multiple helpers do **not automatically provide DHCP failover**.

Actual DHCP failover/load balancing depends on the DHCP-server architecture.

> **Exam trap:**  
> **Multiple helper addresses ≠ DHCP failover protocol.**

# 12. DHCP Relay Across Multiple VLANs

A centralized DHCP server can serve multiple client VLANs.

```text
                    DHCP Server
                    10.0.0.5
                        |
                        |
                 +-------------+
                 | L3 Switch   |
                 +-------------+
                  /     |      \
                 /      |       \
             VLAN 10  VLAN 20  VLAN 30
             10.10.10 10.10.20 10.10.30
```

Configuration:

```cisco
interface Vlan10
 ip address 10.10.10.1 255.255.255.0
 ip helper-address 10.0.0.5

interface Vlan20
 ip address 10.10.20.1 255.255.255.0
 ip helper-address 10.0.0.5

interface Vlan30
 ip address 10.10.30.1 255.255.255.0
 ip helper-address 10.0.0.5
```

Each client VLAN requires its own Layer-3 interface configuration.

The DHCP server can distinguish the client networks using the relay information.

# 13. Routing Requirements

`ip helper-address` does **not** create a route.

The relay must be able to reach the DHCP server.

Example:

```text
Client VLAN
10.10.10.0/24
       |
       v
Relay
10.10.10.1
       |
       | Routing required
       v
10.0.0.0/24
       |
       v
DHCP Server
10.0.0.5
```

Check routing:

```cisco
show ip route 10.0.0.5
```

Test reachability:

```cisco
ping 10.0.0.5
```

The DHCP server must also have a valid return path toward the relay/client subnet.

---

# 14. DHCP Relay and ACLs

DHCP relay traffic can fail if an ACL or firewall blocks the required traffic.

At minimum, investigate:

```text
UDP 67
UDP 68
```

Check interface ACLs:

```cisco
show ip interface
show access-lists
```

If a firewall exists between the relay and DHCP server, verify that DHCP traffic is permitted.

---

# 15. DHCP Relay and DHCP Snooping

DHCP snooping is a Layer-2 security feature that helps prevent rogue DHCP servers.

The relationship is important:

```text
DHCP Snooping
      |
      +---- Trusted / Untrusted ports
      |
      +---- DHCP message inspection
      |
      +---- Binding database
      |
      +---- Option 82 interaction
      |
      v
DHCP Relay
```

Option 82 can provide additional information about the client's attachment point.

### Important distinction

```text
DHCP Relay
    |
    +-- Provides Layer-3 forwarding of DHCP

DHCP Snooping
    |
    +-- Provides Layer-2 DHCP security

Option 82
    |
    +-- Provides relay-agent information
```

They are related, but they are **not the same feature**.

---

# 16. DHCP Snooping + Option 82

A common enterprise design is:

```text
Client
   |
   | DHCP
   v
Access Switch
   |
   | DHCP Snooping
   | Option 82 information
   v
L3 Gateway / Relay
   |
   | DHCP Relay
   v
DHCP Server
```

Option 82 can help the DHCP infrastructure identify the client's attachment point.

However, Option 82 behavior depends on the switch/relay configuration and platform.

> **Exam trap:** Do not assume every DHCP relay automatically inserts Option 82 in every  
> deployment. Treat Option 82 as a separate configurable relay/snooping feature.

# 17. DHCP Relay and DHCPREQUEST

DHCP relay is involved in different stages of the DHCP process.

### Initial lease

```text
DISCOVER
   |
   v
Relay
   |
   v
Server

OFFER
   |
   v
Relay
   |
   v
Client

REQUEST
   |
   v
Relay
   |
   v
Server

ACK
   |
   v
Relay
   |
   v
Client
```

### Important DHCP client states

|State|Purpose|
|---|---|
|SELECTING|Client chooses an offered address|
|INIT-REBOOT|Client attempts to verify a previously used address|
|RENEWING|Client attempts renewal with the original DHCP server|
|REBINDING|Client attempts renewal with any available DHCP server|

You should understand that DHCP relay is not only relevant to the first DHCPDISCOVER.

---

# 18. DHCP Relay and Client Renewal

After receiving a lease, the client eventually needs to renew it.

A client in **RENEWING** state normally attempts to communicate directly with the DHCP  
server that provided the lease.

If the original server cannot be reached and the client enters **REBINDING**, it can use a  
broader broadcast-based process.

The important CCNP concept is:

> DHCP relay is primarily required when DHCP messages must cross a Layer-3 boundary.

Do not assume every DHCP renewal packet always traverses the relay.

---

# 19. DHCP Relay and VRF

In more advanced enterprise environments, the DHCP server and clients may exist in  
different **VRFs**.

The important concept is:

```text
Client VRF
    |
    v
Relay
    |
    | VRF-aware routing
    v
DHCP Server VRF
```

A normal `ip helper-address` configuration does not magically solve VRF routing.

When VRFs are involved, verify:

- Which VRF owns the client interface
    
- Which VRF contains the DHCP server
    
- Whether the platform supports the required VRF-aware DHCP relay behavior
    
- Routing between the relevant VRFs
    
- Return routing
    

> **CCNP focus:** Understand that DHCP relay and routing/VRF design are separate concerns.

# 21. Packet-Level Troubleshooting

When troubleshooting DHCP relay, think in terms of **three segments**:

```text
Segment 1
Client
   |
   | DHCP Broadcast
   v
Relay

Segment 2
Relay
   |
   | Routed DHCP traffic
   v
DHCP Server

Segment 3
DHCP Server
   |
   | Reply
   v
Relay
   |
   v
Client
```

Check each segment independently.

### Segment 1 — Client → Relay

Verify:

- Client is in the correct VLAN.
    
- VLAN is active.
    
- SVI/subinterface is up.
    
- DHCP broadcast reaches the relay.
    
- `ip helper-address` exists.
    

### Segment 2 — Relay → Server

Verify:

- Route to DHCP server exists.
    
- UDP DHCP traffic is permitted.
    
- Helper address is correct.
    
- DHCP server is reachable.
    
- `giaddr` identifies the expected client subnet.
    

### Segment 3 — Server → Client

Verify:

- DHCP server has the correct scope.
    
- Server can return traffic to the relay.
    
- Relay receives the DHCP response.
    
- ACLs/firewalls are not blocking the response.
    
- Client receives the DHCP response.

# 23. Common Failure Scenarios

|Symptom|Possible Cause|What to Check|
|---|---|---|
|No DHCP address|Missing helper|`show run interface`|
|DHCP works in one VLAN but not another|Helper missing on one SVI|Check each SVI|
|Wrong DHCP scope|Incorrect `giaddr`/relay interface|Inspect relay|
|Relay cannot reach server|Missing route|`show ip route`|
|Server unreachable|Routing/ACL/firewall|`ping`, ACLs|
|DHCP server receives nothing|Relay/helper problem|Check helper and packet path|
|Server replies but client gets nothing|Return-path problem|Routing/ACLs|
|Wrong VLAN gets address|VLAN/SVI/`giaddr` problem|Check VLAN and relay|
|Unexpected UDP forwarding|Helper forwards additional UDP broadcasts|`ip forward-protocol`|
|Option 82 error|Snooping/relay mismatch|Check Option 82 configuration|
|Rogue DHCP behavior|DHCP snooping not configured correctly|Trusted ports/binding|
|Multiple DHCP responses|Multiple servers/helpers|Check DHCP architecture|
|DHCP server has no matching scope|Incorrect subnet configuration|Check DHCP server scope|
|DHCP works locally but not remotely|Missing relay|`ip helper-address`|
|DHCP relay works intermittently|Multiple/incorrect DHCP servers or network issue|Packet capture/logs|

# 25. Important Design Rules

### Rule 1

Configure the helper on the **client-facing Layer-3 interface**.

```cisco
interface Vlan10
 ip helper-address 10.0.0.5
```

### Rule 2

The DHCP server needs a scope matching the client subnet.

```text
Client subnet = 10.10.10.0/24

DHCP scope must provide addresses for:
10.10.10.0/24
```

### Rule 3

The relay needs routing to the DHCP server.

```text
Relay ---- route ----> DHCP Server
```

### Rule 4

The DHCP server needs a return path.

```text
DHCP Server ---- route ----> Relay
```

### Rule 5

`giaddr` identifies the client subnet.

### Rule 6

Option 82 provides additional relay-agent information.

### Rule 7

Multiple helpers do not automatically equal DHCP failover.

# 28. CCNP Exam Traps

> **Trap 1:** Configure `ip helper-address` on the DHCP server-facing interface.

**Wrong.**

Configure it on the **client-facing Layer-3 interface**.

---

> **Trap 2:** `giaddr` and Option 82 are the same thing.

**Wrong.**

```text
giaddr  = Client subnet identification
Option 82 = Additional relay-agent information
```

---

> **Trap 3:** `ip helper-address` only forwards DHCP.

**Wrong.**

It can forward multiple configured UDP broadcast protocols.

---

> **Trap 4:** Multiple helper addresses provide DHCP failover.

**Not necessarily.**

They provide multiple destinations for forwarded DHCP traffic. DHCP failover is a  
server-side capability.

---

> **Trap 5:** `ip helper-address` creates a route to the DHCP server.

**Wrong.**

Routing must already exist.

---

> **Trap 6:** Every DHCP OFFER is always broadcast.

**Wrong.**

The exact forwarding behavior depends on DHCP message fields and client state.

---

> **Trap 7:** DHCP relay automatically inserts Option 82 in every deployment.

**Wrong.**

Option 82 behavior depends on relay/snooping configuration and platform behavior.

---

> **Trap 8:** DHCP relay is only required for DHCPDISCOVER.

**Oversimplified.**

Relay can participate in forwarding DHCP messages that must cross the Layer-3 boundary.

---

> **Trap 9:** DHCP snooping and DHCP relay are the same feature.

**Wrong.**

```text
DHCP Relay   = Layer-3 DHCP forwarding
DHCP Snooping = Layer-2 DHCP security
```
