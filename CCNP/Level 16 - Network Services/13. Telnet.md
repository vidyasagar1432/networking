# Telnet

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Telnet** is a legacy remote-access protocol that uses **TCP port 23**. It provides a  
virtual terminal session but **does not encrypt the session**.

Commands, session data, and authentication information can be observed by an attacker  
who can capture the traffic. For secure remote management, **SSH** should be used instead.

> **Exam focus:** Telnet = **TCP 23 + unencrypted remote access**.

---

## 2. Core Concepts

### 2.1 Protocol Basics

|Item|Detail|
|---|---|
|Protocol|Telnet|
|Port|**TCP 23**|
|Encryption|**None**|
|Terminal|Network Virtual Terminal (NVT)|
|Purpose|Remote interactive terminal access|
|Cisco VTY|Used for remote CLI access|

Telnet provides a bidirectional text-based terminal session between a client and server.

### 2.2 Security Exposure

Telnet provides **no confidentiality**. An attacker able to capture the traffic may  
observe credentials, commands, and other session information.

|Risk|Effect|
|---|---|
|Eavesdropping|Session data can be read|
|Credential exposure|Authentication information can be captured|
|Session hijacking|Unencrypted sessions are vulnerable to interception/manipulation|
|MITM|Traffic can potentially be intercepted and modified|
|Compliance risk|Commonly prohibited for secure management|

> **Key point:** The fundamental security problem with Telnet is **lack of encryption**.

## 3. Cisco IOS Telnet Configuration

Telnet access is controlled on the device's **VTY lines**.

### 3.1 Allow Telnet

```text
line vty 0 15
 transport input telnet
 login
 password cisco123
```

This permits incoming Telnet connections on the selected VTY lines.

> The available VTY line range varies by Cisco IOS/platform. `0 15` is common but  
> should not be assumed for every platform.

### 3.2 Transport Input Commands

|Command|Effect|
|---|---|
|`transport input telnet`|Permit incoming Telnet|
|`transport input ssh`|Permit incoming SSH only|
|`transport input all`|Permit all supported incoming transport protocols|
|`transport input none`|Disable incoming remote-access protocols|

### 3.3 Disable Telnet and Allow SSH

```text
line vty 0 15
 transport input ssh
```

This prevents Telnet connections from being accepted on those VTY lines while allowing  
SSH.

> **Exam trap:** `transport input ssh` is the command that prevents Telnet access on the  
> affected VTY lines.

## 4. Restricting Telnet with an ACL

If Telnet must exist on a legacy device, restrict which source addresses can connect.

```text
ip access-list standard MGMT
 permit 192.168.10.0 0.0.0.255
 deny any

line vty 0 15
 access-class MGMT in
 transport input telnet
```

- `access-class MGMT in` applies the ACL to incoming VTY connections.
    
- Only permitted source addresses can access the VTY lines.
    
- This provides **access control**, but it does **not encrypt Telnet**.
    

> **Important:** An ACL limits **who can connect**; it does not make Telnet secure.

## 5. Telnet vs SSH

|Aspect|Telnet|SSH|
|---|---|---|
|Port|**TCP 23**|**TCP 22**|
|Encryption|**No**|**Yes**|
|Confidentiality|None|Protected|
|Remote CLI|Yes|Yes|
|Cisco VTY|Yes|Yes|
|Recommended for management|**No**|**Yes**|
|Typical use|Legacy/lab environments|Secure remote management|

> **Remember:** Telnet and SSH both provide remote terminal access, but **SSH adds  
> encryption and secure authentication**.

## 6. Cisco Commands

### 6.1 Telnet Client

```text
telnet <host>
```

Example:

```text
telnet 192.168.1.10
```

### 6.2 View Current Users

```text
show users
```

Displays users currently connected to the device, including VTY sessions.

### 6.3 View Terminal Lines

```text
show line
```

Displays information about the device's terminal lines, including VTY lines.

### 6.4 View Outbound Sessions

```text
show sessions
```

Displays active outbound Telnet/SSH sessions initiated from the device.

### 6.5 End a Telnet Session

```text
exit
```

or, depending on the session/state:

```text
disconnect
```

## 7. Troubleshooting

|Symptom|Possible Cause|Check|
|---|---|---|
|Connection refused|Telnet not permitted on VTY|`show running-config \| section line vty`|
|Connection timeout|TCP/23 blocked or unreachable|Routing, ACL, firewall|
|Authentication failure|Incorrect VTY authentication configuration|`show running-config \| section line vty`|
|Source rejected|VTY `access-class` denies source|Check the applied ACL|
|No available VTY|VTY lines occupied/exhausted|`show users`|
|Session terminates unexpectedly|Idle/session timeout or connectivity problem|`show line`, `exec-timeout`, network path|

### Useful verification

```text
show running-config | section line vty
show users
show line
show access-lists
```

## 8. Telnet Security Best Practice

### Preferred approach

Use SSH instead of Telnet:

```text
line vty 0 15
 transport input ssh
```

For management-plane protection, combine secure transport with appropriate  
authentication and source restrictions.

Example:

```text
ip access-list standard MGMT
 permit 192.168.10.0 0.0.0.255
 deny any

line vty 0 15
 transport input ssh
 access-class MGMT in
```

> **Best practice:** SSH provides encryption; the ACL restricts the permitted management  
> sources. They solve different security problems.

## 9. Common Exam Traps

### Trap 1 — Telnet port

**Telnet = TCP 23**

Do not confuse it with:

- SSH = TCP 22
    
- FTP control = TCP 21
    
- DNS = UDP/TCP 53
    

### Trap 2 — Telnet is not encrypted

If a question asks which protocol provides secure remote CLI access:

> **SSH**, not Telnet.

### Trap 3 — `transport input ssh`

```text
line vty 0 15
 transport input ssh
```

This allows SSH and prevents Telnet on those VTY lines.

### Trap 4 — `access-class`

```text
access-class MGMT in
```

Restricts **which source addresses** can access the VTY lines.

It does **not** encrypt Telnet.

### Trap 5 — `transport input all`

```text
transport input all
```

Allows all supported incoming transport protocols.

Do not use it when the requirement is **SSH only**.

### Trap 6 — Cisco does not universally have SSH enabled by default

Do not memorize:

> “Cisco devices always have SSH enabled and Telnet disabled by default.”

Instead remember:

> **SSH must be properly configured for secure remote management, and Telnet should  
> be disabled/restricted.**

## 11. Exam Memory

> **TELNET = TCP 23 + NO ENCRYPTION**

Remember these five points:

1. **TCP 23**
    
2. **Unencrypted remote terminal access**
    
3. Uses **VTY lines** on Cisco devices
    
4. `transport input ssh` prevents Telnet on those VTY lines
    
5. **SSH (TCP 22)** is the secure replacement
    

> **ACL ≠ encryption:** `access-class` restricts the source; SSH protects the session.
