# Telnet

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Telnet** (TCP 23) is the legacy remote-access protocol — **completely unencrypted**.
Credentials and commands cross the wire in clear text. Modern devices ship with Telnet
**disabled** (SSH on), and the exam expects you to recognize Telnet as the insecure choice
and know how to **disable / restrict** it.

---

## 2. Core Concepts

### 2.1 The protocol

| Item | Detail |
|------|--------|
| Port | TCP 23 |
| Encryption | none |
| Authentication | plaintext password |
| Data | cleartext (NVT) |
| Session | virtual terminal (VTY) |

- Telnet uses the **Network Virtual Terminal** for bidirectional text.

### 2.2 Security exposure

| Risk | Effect |
|------|--------|
| Password sniffing | clear text on wire |
| Session hijack | replay possible |
| MITM | easy on shared LAN |
| Compliance | banned by policy |

- **Everything is readable** — this is the exam's reason to avoid Telnet.

### 2.3 Cisco Telnet config

```text
line vty 0 15
 transport input telnet          ! allow telnet (discouraged)
 login
 password cisco123
```

| Command | Effect |
|---------|--------|
| `transport input telnet` | allow Telnet on VTY |
| `transport input ssh` | **only** SSH (recommended) |
| `transport input all` | both |
| `transport input none` | no remote access |

### 2.4 Disabling / replacing Telnet

```text
line vty 0 15
 transport input ssh
```

- `transport input ssh` blocks Telnet and forces the secure path.
- ACLs can also restrict Telnet sources:
  - `access-class MGMT in` on the VTY.

### 2.5 Telnet vs SSH recap

| Aspect | Telnet | SSH |
|--------|--------|-----|
| Port | 23 | 22 |
| Encrypted | no | yes |
| Auth | plaintext | encrypted/keys |
| Modern use | legacy only | standard |
| Cisco default | off | on |

### 2.6 When Telnet still exists

- Legacy devices / lab gear with no SSH.
- Out-of-band console via jump host.
- Always behind a **management ACL**.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Refused | transport input ssh | line vty |
| Timeout | TCP 23 blocked | ACL |
| Auth loop | login config | username/password |
| Session drop | idle timeout | exec-timeout |
| No VTY left | sessions exhausted | show users |

---

## 5. Exam Traps

- **Telnet = TCP 23, plaintext** — never the security answer.
- `transport input ssh` on VTY disables Telnet.
- Default modern Cisco: **SSH on, Telnet off**.
- `access-class` restricts management sources.
- Password over Telnet is **sniffable** — that's the trap.
