# RTP / RTCP

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**RTP** carries the actual **media** (voice/video) for real-time sessions, delivering
millisecond-spaced packets with **sequence numbers, timestamps, and payload-type**
headers. **RTCP** is its control sidekick, reporting QoS stats. SIP (note 18) sets up the
call; **RTP carries the payload** — the pairing the exam repeats.

---

## 2. Core Concepts

### 2.1 RTP vs RTCP vs SIP

| Protocol | Function | Ports |
|----------|----------|-------|
| SIP | signaling | 5060 / 5061 |
| RTP | media payload | even UDP 16384+ |
| RTCP | control/statistics | RTP port + 1 (odd) |

- **RTP = even port, RTCP = next odd port**, by registration convention.

### 2.2 Why UDP

| Aspect | RTP |
|--------|-----|
| Transport | UDP (low latency) |
| Reliability | none (packet loss tolerated) |
| Ordering | sequence numbers |
| Timing | timestamp field |
| Re-transmit | never good for voice |

- Retransmission of old voice is useless — RTP favors **freshness** over completeness.

### 2.3 Header essentials

| Field | Purpose |
|-------|---------|
| Payload-type (PT) | codec (e.g., G.711, G.729) |
| Sequence number | detect loss/order |
| Timestamp | decode timing |
| SSRC | identifies the media source |
| CSRC | contributing sources (mixes) |

- Codec negotiation happens via **SDP** during call setup.

### 2.4 RTCP role

| Report | Provides |
|--------|----------|
| SR (Sender Report) | sender stats |
| RR (Receiver Report) | loss/jitter from receiver |
| SDES | session description |

- RTCP bandwidth ≈ **5%** of the session — small but useful for QoE monitoring.

### 2.5 QoS requirements

| Goal | Numbers |
|------|---------|
| Latency | < 150 ms one-way (target) |
| Jitter | < 30 ms |
| Loss | < 1% (voice) |

- Marking: **DSCP EF (46)** for voice, **AF41 (34)** for video, **CS3** for signaling.
- Queuing/LLQ protects RTP in congestion (see later QoS levels).

### 2.6 Jitter buffer & NAT

| Problem | Effect/Fix |
|---------|-----------|
| Jitter buffer | smooths arrival time |
| NAT | one-way audio (note 18) |
| RTP hardened ports | secure static media ranges |

```text
show voice call status           ! active RTP streams (where supported)

```

- Verify RTP exists by watching even UDP ports >16384 in `show ip arp`/statistics.

---

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| One-way audio | RTP path broken / NAT | media flow |
| Garbled audio | jitter/loss | jitter buffer, QoS |
| No media at all | UDP blocked | ACL even ports |
| Static/noise | packet loss | loss % |
| Delay | latency / queueing | LLQ config |

---

## 5. Exam Traps

- **RTP = media (UDP)**, **RTCP = control** (port+1).
- RTP never retransmits — **freshness over reliability**.
- **DSCP EF** marks voice; jitter is the RTP killer.
- SIP sets up → **RTP carries** — memorize the pair.
- Even RTP / odd RTCP ports > 16384.
