# SIP

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**SIP** (TCP/UDP 5060, 5061 TLS) is the **signaling** protocol for VoIP/UC — it sets up,
tears down, and locates sessions, but carries **no voice** (that's RTP, note 19). It uses
HTTP-style methods and works with **SDP** to negotiate media. The exam pairs **SIP
(control) with RTP (media)** — the core memorization.

---

## 2. Core Concepts

### 2.1 SIP vs RTP (the essential pair)

| Protocol | Job | Port |
|----------|-----|------|
| SIP | signaling (setup/teardown) | 5060 / 5061 |
| RTP | media (voice packets) | 16384–32767 (typical) |

- **SIP sets it up; RTP carries the call.** Both are needed for VoIP.

### 2.2 SIP methods

| Method | Meaning |
|--------|---------|
| INVITE | establish session |
| ACK | confirm INVITE |
| BYE | end session |
| REGISTER | register with registrar/phone |
| OPTIONS | capability query |
| CANCEL | abort pending setup |

- SIP is text-based like HTTP.

### 2.3 The SIP triangle (entities)

| Entity | Role |
|--------|------|
| UAC | caller |
| UAS | called party / server |
| Registrar | records addresses |
| Proxy | routes signaling |
| Redirect | returns alternative path |

- A **SIP UA** can be both UAC and UAS.

### 2.4 URL / addressing

```
sip:bob@corp.example
To: <sip:bob@corp.example>
```

- SIP URI = name@domain; used in To/From/Contact headers.
- **SDP** in the INVITE body carries codec + media IP/port for RTP.

### 2.5 NAT/security issues (exam-critical)

| Problem | Cause / Fix |
|---------|-------------|
| One-way audio | RTP behind NAT (only signaling translated) |
| ALG damage | NAT ALG rewrites SDP wrongly |
| Auth | Digest auth over SIP |
| TLS | SIP over 5061 with certs |

- Fix media NAT with **media-address/static RTP port maps** or NAT ALG inspection.

### 2.6 Call flow sketch

```
UAC            UAS
 |--INVITE---->|
 |<--100/180---|  (trying/ringing)
 |<--200-------|  (OK with SDP)
 |--ACK------->|
 |====RTP=====>|  (media flows directly!)
 |--BYE------->|  (hang up)
 |<--200-------|
```

- After ACK, RTP flows **end-to-end**, not through the SIP proxy.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No call setup | 5060 blocked | ACL |
| One-way audio | RTP/NAT | SDP + media ports |
| Reg failures | registrar unreachable | status |
| Dropped calls | BYE handling | call legs |
| Auth loop | digest mismatch | credentials |

---

## 5. Exam Traps

- **SIP = signaling (5060)**, **RTP = media (audio)**.
- Text/HTTP-like methods: INVITE/ACK/BYE/REGISTER.
- Audio flows **directly** between endpoints after ACK — not via proxy.
- NAT breaks **media**, not signaling — one-way audio is the symptom.
- SIP over **TLS = 5061**.
