# FTP

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**FTP** (TCP 21 control + TCP 20 data) transfers files reliably but transmits
**credentials and data in cleartext** — a security liability. It supports **active** and
**passive** modes; the exam checks port numbers, the control/data split, modes, and why
FTPS/TFTP replace it in practice.

---

## 2. Core Concepts

### 2.1 Control vs data channels

| Channel | Port | Purpose |
|---------|------|---------|
| Control | TCP 21 | commands, replies |
| Data | TCP 20 (active) / random (passive) | file content |

- Control connection persists; data connections open per transfer.

### 2.2 Active mode

```
client(20)  <--data--   server(20)
client(1024) --ctrl-->  server(21)
```

- Client listens for the server to connect **to** it for data.
- Often blocked by client firewalls.

### 2.3 Passive mode (modern default)

```
client(1024) --ctrl-->  server(21)
client(1025) --data-->  server(random)
```

- Client initiates **both** connections — firewall friendly.
- Server replies with a port via PASV.

| Mode | Who initiates data | Firewall-friendly |
|------|--------------------|-------------------|
| Active | server → client (20) | poor |
| Passive | client → server | good |

### 2.4 Authentication & security

| Weakness | Consequence |
|----------|-------------|
| Plaintext passwords | sniffed on wire |
| Cleartext data | content exposure |
| FTP bounce | port scan abuse |

- Fix: **FTPS (SSL/TLS)**, **SFTP (SSH)**, or SCP.

### 2.5 Router use (image transfer)

```text
copy ftp://user:pass@10.0.0.5/ios.bin flash:
```

- Cisco supports FTP for IOS backup/upgrade; TFTP is simpler but limited (note 09).

### 2.6 Common replies

| Code | Meaning |
|------|---------|
| 220 | service ready |
| 331 | user ok, need password |
| 200/250 | OK / success |
| 550 | file unavailable |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Connect but no transfer | active mode blocked | switch to passive |
| Auth fails | plaintext blocked by policy | use FTPS/SFTP |
| Timeout | port 21 blocked | ACL |
| Data stalls | 20 vs PASV mismatch | mode negotiation |
| Refused | server NAT/ALG | NAT inspection |

---

## 5. Exam Traps

- **Control = 21, data = 20 (active)**.
- **Active**: server connects to client; **Passive**: client connects (PASV).
- FTP is **plaintext** — FTPS/SFTP are the secure answers.
- Data channel opens **per transfer**; control stays up.
- Routers use FTP/TFTP for **IOS transfer**.
