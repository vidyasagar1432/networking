# FTP

> **Level 16 · Network Services** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**FTP (File Transfer Protocol)** transfers files using **TCP** and separates **control**  
traffic from **data** traffic.

FTP uses:

- **TCP 21** — control connection
    
- **TCP 20** — server-side source port for **active-mode data**
    
- **Dynamic/high server port** — data connection in **passive mode**
    

FTP sends usernames, passwords, commands, and file data **in cleartext**, making it  
unsuitable for secure file transfer across untrusted networks.

---

## 2. Core Concepts

### 2.1 Control vs. Data Connections

|Connection|Port|Purpose|
|---|--:|---|
|Control|TCP 21|Commands and server replies|
|Data — Active|TCP 20 (server source port)|File/listing transfer|
|Data — Passive|Dynamic/high server port|File/listing transfer|

- The **control connection** carries FTP commands and replies.
    
- A separate **data connection** carries files and directory listings.
    
- A new data connection is normally established for each transfer/listing operation.
    
- The control connection normally remains established for the FTP session.
    

---

## 3. Active FTP

In **active mode**, the client tells the server which client-side port to use for  
the data connection. The **server initiates the data connection** from its  
TCP 20 source port to the client's negotiated port.

```text
                 Control
Client --------------------------> Server
       TCP high port        TCP 21

                 Data
Client <-------------------------- Server
       Client high port     TCP 20
```

### Key points

- Server listens on **TCP 21** for control.
    
- Server initiates the data connection.
    
- Server uses **TCP 20 as the source port** for the data connection.
    
- Client listens on a negotiated high/dynamic port.
    
- Active mode can cause problems with **client-side firewalls/NAT** because the  
    server must initiate a connection toward the client.
    

---

## 4. Passive FTP

In **passive mode**, the server tells the client which dynamic/high port it is  
listening on. The **client initiates both connections**.

```text
                 Control
Client --------------------------> Server
       TCP high port        TCP 21

                 Data
Client --------------------------> Server
       TCP high port        TCP dynamic/high port
```

### Key points

- Server listens on **TCP 21** for control.
    
- Server selects a **dynamic/high port** for data.
    
- Client initiates the data connection to that server port.
    
- Passive mode is generally more firewall/NAT friendly for clients.
    
- The server must allow the negotiated passive-port range through its firewall.
    

### PASV

The FTP server uses the **PASV** command to enter passive mode and provide the  
client with the server-side data port.

---

## 5. Active vs. Passive

|Feature|Active|Passive|
|---|---|---|
|Control port|TCP 21|TCP 21|
|Data connection initiated by|Server|Client|
|Server data source port|TCP 20|Dynamic/high port|
|Client data connection|Listens for server|Initiates connection|
|Firewall/NAT friendliness|Generally worse for client|Generally better for client|
|Common mechanism|`PORT`|`PASV`|

> **Exam shortcut:**  
> **Active = server connects to client for data.**  
> **Passive = client connects to server for data.**

---

## 6. Authentication & Security

FTP does **not encrypt** its traffic by itself.

|Security Problem|Consequence|
|---|---|
|Username/password in cleartext|Credentials can be captured|
|File data in cleartext|Files can be sniffed|
|Commands in cleartext|Session information can be exposed|
|FTP bounce abuse|Server can potentially be abused to make connections to third parties|

### Secure alternatives

|Protocol|Security|
|---|---|
|FTP|No encryption|
|FTPS|FTP protected with **TLS/SSL**|
|SFTP|File transfer over **SSH**|
|SCP|Secure file copy over **SSH**|

> **Important:** **SFTP is not "secure FTP."** It is a different protocol that  
> operates over SSH.

---

## 7. FTP Bounce

**FTP bounce** is an abuse of FTP active-mode behavior, particularly the  
`PORT` command, to make an FTP server initiate a connection toward another  
host/port.

Potential abuse includes:

- Port scanning through the FTP server
    
- Reaching systems that the attacker cannot directly reach
    
- Bypassing some network restrictions
    

Modern FTP servers commonly restrict or disable unsafe bounce behavior.

---

## 8. Cisco IOS Use

Cisco IOS can use FTP for transferring files such as IOS images and configuration  
files, depending on platform and software support.

Example:

```text
copy ftp://user:password@10.0.0.5/ios.bin flash:
```

FTP can be used for:

- IOS image transfers
    
- Configuration backup/restore
    
- Other supported file transfers
    

### FTP vs. TFTP

|Feature|FTP|TFTP|
|---|---|---|
|Transport|TCP|UDP|
|Default port|TCP 21 control|UDP 69|
|Authentication|Yes|No|
|Encryption|No|No|
|Reliability|TCP-based|Application-level simplicity|
|Typical use|Larger/managed file transfers|Simple network-device transfers|

## 9. Common FTP Replies

|Code|Meaning|
|--:|---|
|**220**|Service ready|
|**230**|User logged in|
|**331**|User name okay, need password|
|**200**|Command okay|
|**250**|Requested file action completed|
|**425**|Can't open data connection|
|**530**|Not logged in / authentication required|
|**550**|Requested action not taken; file unavailable|

## 10. Troubleshooting

|Symptom|Possible Cause|What to Check|
|---|---|---|
|Cannot connect to FTP server|TCP 21 blocked/server unavailable|ACL, firewall, routing, server status|
|Authentication fails|Invalid credentials/account policy|Username/password and server logs|
|Login succeeds but transfer fails|Data connection blocked|Active/passive mode and firewall|
|Active mode fails|Server cannot initiate connection to client|Client firewall/NAT|
|Passive mode fails|Passive port range blocked|Server firewall/NAT and passive-port range|
|Data connection times out|Data ports filtered|ACL/firewall/NAT|
|FTP behaves incorrectly through NAT|FTP control messages contain connection information|NAT/FTP ALG inspection|
|File unavailable|File/path/permission problem|Server path and permissions|

> **Important:** Opening **TCP 21** only allows the control connection. FTP also  
> requires the appropriate **data connection** to succeed.

## 11. Exam Traps

- **TCP 21 = FTP control connection.**
    
- **TCP 20 is the server's source port for active-mode data.**
    
- **Active:** server initiates the data connection toward the client.
    
- **Passive:** client initiates the data connection toward the server.
    
- Passive mode uses a **dynamic/high server port** for data.
    
- FTP control and data are **separate connections**.
    
- FTP sends credentials and data **in cleartext**.
    
- **FTPS = FTP + TLS/SSL.**
    
- **SFTP = SSH-based file transfer; it is not FTP.**
    
- TCP 21 being open does **not** guarantee that file transfers will work.
    
- Active mode can be problematic with **client-side firewalls/NAT**.
    
- Passive mode can still fail if the server's **passive port range** is blocked.
    
- FTP bounce abuses the FTP server's ability to initiate connections using  
    active-mode behavior.
    
- Cisco devices can use FTP for supported **IOS/configuration file transfers**.

### Final Exam Rule

> **21 = Control.**  
> **20 = Active-mode server data source.**  
> **Active = Server → Client data.**  
> **Passive = Client → Server data.**  
> **FTP = Cleartext unless protected by another mechanism.**
