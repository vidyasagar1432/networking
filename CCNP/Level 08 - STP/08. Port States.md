# STP Port States

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**STP port states** describe the operational behavior of a port with respect to:

- Forwarding user/data frames
    
- Learning source MAC addresses
    
- Processing STP BPDUs
    

Classic **802.1D STP** uses five states:

```text
Blocking
Listening
Learning
Forwarding
Disabled
```

**RSTP (802.1w)** simplifies these to three states:

```text
Discarding
Learning
Forwarding
```

> **Critical distinction:**  
> **Role = what the port is for**  
> **State = what the port is currently doing**

Example:

```text
Root Port     → Role
Forwarding    → State
```

A Root or Designated port can be Forwarding, while an Alternate or Backup port is normally Discarding.

---

# 2. Classic STP Port States

## 2.1 Blocking

A **Blocking** port does not forward user data and does not learn MAC addresses, but it continues to process STP BPDUs.

|Behavior|Blocking|
|---|---|
|Forward user data|No|
|Learn MAC addresses|No|
|Process BPDUs|Yes|
|Purpose|Prevent loops while retaining STP information|

Conceptually:

```text
Blocking
│
├── No user-data forwarding
├── No MAC learning
└── Continues STP BPDU processing
```

> **Exam trap:** Blocking does **not** mean the port is completely inactive.

A Blocking port can receive/process BPDUs and can move to another state if the topology requires it.

---

# 3. Listening

A **Listening** port participates in STP topology calculation but does not yet forward user data or learn MAC addresses.

|Behavior|Listening|
|---|---|
|Forward user data|No|
|Learn MAC addresses|No|
|Process BPDUs|Yes|
|STP role calculation|Yes|

Conceptually:

```text
Listening
│
├── No data forwarding
├── No MAC learning
└── Participates in STP calculation
```

The port uses this period to determine whether it should become a forwarding port without immediately creating a Layer 2 loop.

---

# 4. Learning

A **Learning** port begins learning source MAC addresses but still does not forward user data.

|Behavior|Learning|
|---|---|
|Forward user data|No|
|Learn MAC addresses|Yes|
|Process BPDUs|Yes|

Conceptually:

```text
Learning
│
├── No user-data forwarding
├── MAC addresses learned
└── BPDUs processed
```

The purpose is to populate the MAC address table before the port begins forwarding user traffic.

This reduces unnecessary flooding when the port eventually transitions to Forwarding.

---

# 5. Forwarding

A **Forwarding** port performs normal Layer 2 switching.

|Behavior|Forwarding|
|---|---|
|Forward user data|Yes|
|Learn MAC addresses|Yes|
|Process BPDUs|Yes|

Conceptually:

```text
Forwarding
│
├── Forward data
├── Learn MAC addresses
└── Process BPDUs
```

Typical forwarding roles are:

```text
Root Port       → Forwarding
Designated Port → Forwarding
```

---

# 6. Disabled

A **Disabled** port does not participate in STP forwarding behavior.

Typical causes include:

- Administrative shutdown
    
- Interface being down
    
- Port not operational
    

|Behavior|Disabled|
|---|---|
|Forward user data|No|
|Learn MAC addresses|No|
|Process STP BPDUs|No|
|Participate in STP|No|

Conceptually:

```text
Disabled
│
└── Not participating in STP
```

> **Important:** Do not confuse **Disabled** with **Blocking**.  
> A Blocking port is still participating in STP and processes BPDUs.

---

# 7. Classic STP State Transition

The traditional 802.1D progression toward forwarding is:

```text
Blocking
    ↓
Listening
    ↓
Learning
    ↓
Forwarding
```

A port can also move to:

```text
Disabled
```

depending on administrative/operational conditions.

Typical purpose:

```text
Blocking
   ↓
Listen for STP information
   ↓
Listening
   ↓
Determine role/topology
   ↓
Learning
   ↓
Build MAC table
   ↓
Forwarding
   ↓
Forward user data
```

---

# 8. STP Timers

Classic 802.1D STP commonly uses these default timer values:

|Timer|Default|Purpose|
|---|--:|---|
|**Hello Time**|2 seconds|Interval between BPDUs from the root|
|**Max Age**|20 seconds|Determines when received BPDU information is considered expired|
|**Forward Delay**|15 seconds|Duration of Listening/Learning states|

Therefore:

```text
Hello Time      = 2 s
Max Age         = 20 s
Forward Delay   = 15 s
```

### Important correction about "50 seconds"

It is common to hear:

```text
20 + 15 + 15 = 50 seconds
```

but this should **not** be memorized as a universal STP convergence time.

Max Age is primarily associated with **aging out stale BPDU information**. It does not simply mean that every port spends 20 seconds in Blocking and then 15 seconds in Listening and 15 seconds in Learning.

A more accurate exam model is:

```text
Classic 802.1D
│
├── Max Age → BPDU information aging
│
├── Forward Delay → Listening
│
└── Forward Delay → Learning
```

The exact convergence behavior depends on the topology and failure type.

> **Exam focus:** Know the default timer values and understand why classic 802.1D is slower than RSTP. Do not treat "50 seconds" as a guaranteed convergence time for every failure.

---

# 9. RSTP Port States

RSTP simplifies the five classic states into three:

```text
Discarding
Learning
Forwarding
```

Mapping:

|Classic 802.1D|RSTP|
|---|---|
|Blocking|Discarding|
|Listening|Discarding|
|Learning|Learning|
|Forwarding|Forwarding|
|Disabled|Not participating|

RSTP therefore eliminates the separate **Listening** state.

---

# 10. RSTP Discarding State

RSTP combines the functional behavior of classic Blocking and Listening into **Discarding**.

|Behavior|Discarding|
|---|---|
|Forward user data|No|
|Learn MAC addresses|No|
|Process STP BPDUs|Yes|

Conceptually:

```text
RSTP Discarding
│
├── No user-data forwarding
├── No MAC learning
└── STP control information processed
```

An RSTP Alternate or Backup port is normally in Discarding.

---

# 11. RSTP Learning State

RSTP Learning behaves similarly to classic Learning:

```text
Learning
│
├── No user-data forwarding
├── Learn MAC addresses
└── Process BPDUs
```

The switch prepares the MAC table before allowing normal data forwarding.

---

# 12. RSTP Forwarding State

RSTP Forwarding allows normal Layer 2 operation:

```text
Forwarding
│
├── Forward user data
├── Learn MAC addresses
└── Process BPDUs
```

Typical roles:

```text
Root Port
Designated Port
```

are normally Forwarding after convergence.

---

# 13. Role vs State

This is one of the most important STP concepts.

### Role

The role describes the **purpose of the port in the topology**.

```text
Root
Designated
Alternate
Backup
```

### State

The state describes the **current operational behavior**.

Classic STP:

```text
Blocking
Listening
Learning
Forwarding
Disabled
```

RSTP:

```text
Discarding
Learning
Forwarding
```

### Mental Model

```text
PORT
│
├── ROLE
│     ├── Root
│     ├── Designated
│     ├── Alternate
│     └── Backup
│
└── STATE
      ├── Discarding
      ├── Learning
      └── Forwarding
```

Example:

```text
Root Port
    +
Forwarding
```

Another:

```text
Alternate Port
    +
Discarding
```

---

# 14. Typical Role/State Combinations

|Port Role|Typical State|
|---|---|
|Root Port|Forwarding|
|Designated Port|Forwarding|
|Alternate Port|Discarding|
|Backup Port|Discarding|

These are **typical steady-state combinations**, not a statement that role and state are the same thing.

A port role and state must always be considered separately.

---

# 15. Why Learning Exists

Before a port starts forwarding user data, the switch needs an opportunity to populate its MAC address table.

Example:

```text
Learning
│
├── Receive frames
├── Learn source MAC addresses
└── Do not yet forward user data
       ↓
Forwarding
│
└── Normal switching
```

This helps reduce unnecessary flooding when the port enters Forwarding.

> **Exam wording:** Learning allows the switch to build its MAC table before normal data forwarding begins.

---

# 16. How RSTP Converges Faster

RSTP does not simply wait through the traditional 802.1D timer sequence.

It uses mechanisms such as:

- Proposal/agreement
    
- Explicit synchronization
    
- Alternate and Backup roles
    
- Rapid transition on appropriate point-to-point links
    
- Edge-port behavior
    

Conceptually:

```text
802.1D STP
│
└── More timer-based waiting
        ↓
   Slower convergence


RSTP
│
├── Proposal/Agreement
├── Explicit synchronization
├── Alternate/Backup roles
└── Rapid transition
        ↓
   Faster convergence
```

RSTP still uses timers for specific functions such as BPDU aging and failure detection, so it is incorrect to say that RSTP is completely timerless.

---

# 17. Edge Ports / PortFast

An edge port is a port connected to an end device such as:

- PC
    
- Printer
    
- Server
    
- IP phone access connection
    

Cisco's **PortFast** allows an access/edge port to transition directly to Forwarding instead of waiting through the normal STP transition.

Example:

```text
PC
 │
 │
SW1
 │
 └── Edge / PortFast
       ↓
   Forwarding quickly
```

Configuration:

```text
interface GigabitEthernet0/1
 spanning-tree portfast
```

> **Important:** PortFast should normally be used only on ports connected to end devices, not on ordinary switch-to-switch links.

# 19. STP Timer Configuration

Cisco allows STP timer configuration, for example:

```text
spanning-tree vlan 10 forward-time 15
spanning-tree vlan 10 max-age 20
spanning-tree vlan 10 hello-time 2
```

However, timer modification should be done carefully.

Do not use arbitrary timer changes as the normal solution to slow convergence.

Prefer:

```text
RSTP
+
Correct topology
+
Edge/PortFast where appropriate
+
Correct STP protection
```

rather than randomly lowering timers.

### Default values

```text
Hello Time    = 2 seconds
Max Age       = 20 seconds
Forward Delay = 15 seconds
```

# 20. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Port remains Discarding|Alternate/Backup role or STP protection|Check role and `show spanning-tree`|
|Port remains Blocking|Classic STP topology or non-designated path|Check root/designated roles|
|Slow host connectivity after link-up|PortFast/edge not enabled on an end-device port|Configure PortFast where appropriate|
|Slow STP convergence|802.1D or topology/failure detection issue|Check STP mode and topology|
|Port repeatedly changes state|Link/BPDU instability|Check interface, logs, UDLD/Loop Guard as appropriate|
|Port enters inconsistent state|STP guard feature|`show spanning-tree inconsistentports`|
|MAC table instability|Layer 2 loop/topology issue|Check STP roles, MAC flapping and topology|
|Unexpected Forwarding port|Wrong role/topology or VLAN/instance issue|Check Role + State together|

---

# 21. Important Troubleshooting Distinction

Do not troubleshoot a port only from its state.

For example:

```text
Port State = Forwarding
```

does not tell you whether the port is:

```text
Root Port
```

or:

```text
Designated Port
```

Similarly:

```text
Port State = Discarding
```

does not automatically mean:

```text
Alternate Port
```

It could also be a Backup Port or another condition depending on the protocol and implementation.

Always inspect:

```text
Role + State + Cost + Root information
```

# 22. Classic STP vs RSTP

|Feature|802.1D STP|RSTP|
|---|---|---|
|Standard|802.1D|802.1w|
|States|Blocking, Listening, Learning, Forwarding, Disabled|Discarding, Learning, Forwarding|
|Separate Listening state|Yes|No|
|Alternate role|No|Yes|
|Backup role|No|Yes|
|Rapid proposal/agreement|No|Yes|
|Rapid alternate-path recovery|Limited|Yes|
|Convergence|Generally slower|Generally much faster|
|Edge/PortFast concept|Cisco feature|Edge-port behavior|

# 25. Exam Traps

### Trap 1 — Blocking means no BPDUs

**Wrong:**

> A Blocking port does nothing.

**Correct:**

> A Blocking port does not forward user data or learn MAC addresses, but it **continues processing STP BPDUs**.

---

### Trap 2 — Learning forwards data

**Wrong:**

> A Learning port forwards frames while learning MACs.

**Correct:**

> Learning builds the MAC table but **does not forward user data**.

---

### Trap 3 — RSTP has five states

**Wrong:**

> RSTP uses Blocking, Listening, Learning, Forwarding and Disabled.

**Correct:**

> RSTP uses **Discarding, Learning and Forwarding** as its operational port states.

---

### Trap 4 — Discarding means Alternate

**Wrong:**

> Every Discarding port is an Alternate Port.

**Correct:**

> Alternate and Backup ports are normally Discarding, but **role and state are separate concepts**.

---

### Trap 5 — Disabled is the same as Blocking

**Wrong:**

> A disabled port is just another blocked STP port.

**Correct:**

> A disabled port is not participating in STP, whereas a Blocking/Discarding port still participates in STP control processing.

---

### Trap 6 — STP always takes exactly 50 seconds

**Wrong:**

> Every STP convergence event takes exactly 50 seconds.

**Correct:**

> Classic STP uses **Hello 2 s, Max Age 20 s and Forward Delay 15 s** by default, but actual convergence depends on the topology and failure type.

---

### Trap 7 — RSTP has no timers

**Wrong:**

> RSTP is completely timerless.

**Correct:**

> RSTP still uses timers for functions such as BPDU aging and failure detection, but reduces dependence on the traditional 802.1D transition delays.

---

### Trap 8 — PortFast is for switch links

**Wrong:**

> Enable PortFast on every port for faster convergence.

**Correct:**

> PortFast/edge behavior is intended for **end-device ports**, not normal switch-to-switch links.

# 27. One-Minute CCNP Summary

```text
STP PORT STATES
│
├── CLASSIC STP
│     │
│     ├── Blocking
│     │     └── No data / No learning / BPDUs
│     │
│     ├── Listening
│     │     └── No data / No learning / STP calculation
│     │
│     ├── Learning
│     │     └── No data / Learn MACs / BPDUs
│     │
│     └── Forwarding
│           └── Data / Learn MACs / BPDUs
│
└── RSTP
      │
      ├── Discarding
      │     └── No data / No learning / BPDUs
      │
      ├── Learning
      │     └── No data / Learn MACs / BPDUs
      │
      └── Forwarding
            └── Data / Learn MACs / BPDUs
```

> **Core exam idea:**

```text
ROLE
  ↓
What is this port responsible for?

STATE
  ↓
What is this port currently allowed to do?

Classic STP:
Blocking → Listening → Learning → Forwarding

RSTP:
Discarding → Learning → Forwarding

RSTP removes the separate Listening state
and uses rapid role transitions/proposal-agreement
instead of relying primarily on the old timer sequence.
```
