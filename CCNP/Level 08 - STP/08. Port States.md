# STP Port States

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Port states** describe what a switch port is *doing* at a point in time during STP
convergence: **Blocking → Listening → Learning → Forwarding** (plus Disabled), each with
rules about forwarding frames and learning MAC addresses. **RSTP collapses these to
Discarding / Learning / Forwarding.** States are orthogonal to **roles** (note 07):
a Forwarding port can be Root or Designated; a Discarding port is usually Alternate/Backup.

---

## 2. Core Concepts

### 2.1 Classic STP states & behavior

| State | Forwards user data | Learns MACs | Receives/processes BPDUs |
|-------|-------------------|-------------|--------------------------|
| **Blocking** | no | no | yes (listens for better paths) |
| **Listening** | no | no | yes (electing roles) |
| **Learning** | no | **yes** | yes |
| **Forwarding** | yes | yes | yes |
| **Disabled** | no | no | no (admin down/port shut) |

- **Blocking still processes BPDUs** — it is the "quiet monitor," not dead.

### 2.2 Timers & the transition math

| Phase | Duration | What happens |
|-------|----------|--------------|
| Blocking (topology change) | ~Max Age (20 s) | waits to age stale BPDU info |
| Listening | **15 s** (forward delay) | electing roles, no data |
| Learning | **15 s** (forward delay) | building MAC table, no data |
| **Total (nominal)** | ≈ **50 s** | Blocking→Listening→Learning→Forwarding |

- Timers **overlap** in practice — don't treat "50 s" as absolute. The exam wants the
  timer values (Hello 2 s / MaxAge 20 s / FwdDelay 15 s) and the *concept* that classic
  STP is slow vs RSTP's ~1–3 s.

### 2.3 RSTP state mapping

| Classic | RSTP | Forward? | Learn? |
|---------|------|----------|--------|
| Blocking + Listening | **Discarding** | no | no |
| Learning | Learning | no | yes |
| Forwarding | Forwarding | yes | yes |

- RSTP reduces **blind timer-waiting** — ports reach Forwarding via roles + agreement
  once the tree settles (proposal/agreement on P2P links).

### 2.4 Why "Learning before Forwarding"

- Prevents MAC-table poisoning during convergence: the switch learn MACs on the soon-to-be
  active path **before** sending data, so frames don't momentarily take a stale ring path.

### 2.5 State vs Role (again, the must-know)

- **State** = Blocking / Listening / Learning / Forwarding (phases).
- **Role** = Root / Designated / Alternate / Backup (purpose) — see Level 08 note 07.
- A port can be **Forwarding** but role **Root/Designated**; or **Discarding** with role
  **Alternate**. Always read both columns of `show spanning-tree`.

## 3. Configuration / Commands

```text
show spanning-tree                        # Role + State per port
show spanning-tree interface Gi0/1
show spanning-tree vlan 10 | include "Role|State"
show spanning-tree | include "Max age|Hello time|Forward delay"

! Adjust (cautious) — affects convergence on that instance
spanning-tree vlan 10 forward-time 10
spanning-tree vlan 10 max-age 20
spanning-tree vlan 10 hello-time 2
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Port stuck in Blocking | no superior path / root guard | `show spanning-tree inconsistentports` |
| Slow link-up (30–50 s) | classic 802.1D, no PortFast/edge | timer values; enable rapid |
| Port loops between Learning/Forwarding | flapping BPDUs / unidirectional link | Loop Guard + UDLD (note 13) |
| MAC table storms during convergence | learning window mis-tuned | verify forward-time, TCN aging |
| Edge host waits forever | PortFast missing | `spanning-tree portfast` |

## 5. Exam Traps

- **Blocking ports still receive/process BPDUs** — "blocked means no BPDUs" is wrong.
- **Learning ports do NOT forward user data** — only learn MACs.
- **Only Forwarding forwards data.**
- **RSTP: 3 states not 5** — no separate Listening.
- **Don't state a fixed "50 s"** as gospel — timers overlap; know Hello 2s / MaxAge 20s /
  ForwardDelay 15s.
- **Disabled ≠ Blocking** — Disabled is admin shut/physical down (no BPDUs at all).
