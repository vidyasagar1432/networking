# STP (Spanning Tree Protocol)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Spanning Tree Protocol (STP, IEEE 802.1D)** prevents **Layer-2 loops** in redundant
switched networks. It computes a loop-free **tree topology**: one **root bridge**, one
deterministic path per segment, and all redundant links placed in **Blocking**. Without
it, with redundant links you get broadcast storms, MAC-table flapping, and duplicated
frames.

---

## 2. Core Concepts

### 2.1 Why loops are catastrophic (the "why STP exists")
| Problem | Cause |
|---------|-------|
| **Broadcast storm** | broadcast frames loop forever (exponential) |
| **MAC table flapping** | switching learns the same MAC on two ports |
| **Duplicate frames** | unicast frames take multiple paths |
| **CPU meltdown** | switches process endless copies |
- STP exists precisely to make redundant L2 failover **loop-free**.

### 2.2 STP decision process (3 steps)
To build the tree every switch runs:
1. **Elect the Root Bridge** — lowest **Bridge ID** (priority + MAC).
2. **Determine Root Ports** — per non-root switch: the best path to root.
3. **Determine Designated Ports** — per segment: the switch that serves it best.
   Everything else → **Blocking** (nonsense path closed).

### 2.3 Bridges and Bridge ID
```
Bridge ID = Priority (2 B) + System ID/MAC (6 B)
```
- Priority default **32768**; manually lower on the intended root (e.g., `spanning-tree
  vlan 10 priority 4096`).
- In per-VLAN flavors, an **extended system ID** (12 bits) encodes the VLAN into the
  priority field — that's how PVST+ gets per-VLAN roots.

### 2.4 The port states & roles (STP only)
| State | Forwards data | Learns MAC | Purpose |
|-------|---------------|------------|---------|
| Blocking | no | no | no BPDUs accepted, switch off path |
| Listening | no | no | electing role; waiting |
| Learning | no | yes | building table, quiet forwarding |
| Forwarding | yes | yes | active data path |
| Disabled | no | no | admin-shutdown |
- Convergence: Blocking→Listening→Learning→Forwarding ≈ **50 s** (slow!) → RSTP fixes.

### 2.5 BPDUs — the STP language
- **BPDU (Bridge Protocol Data Unit)** sent every **2 s** (default hello).
- Contains: root bridge ID, root path cost, sender bridge ID, sender port ID.
- Timers: **MaxAge 20 s, Hello 2 s, Forward Delay 15 s** → the ~30–50 s convergence.

### 2.6 Cost calculation (path cost)
- Cisco classic: 100 Mbps→19, 1 Gbps→4, 10 Gbps→2; IEEE: 100M→19, 1G→4, 10G→2.
- Lower cost path chosen; ties broken by lowest neighbor bridge ID, then port ID.

## 3. Configuration / Commands

```text
# Force a root (elect it)
spanning-tree vlan 10 priority 4096
# (also) spanning-tree vlan 10 root primary

# Verify tree
show spanning-tree
show spanning-tree vlan 10
show spanning-tree bridge
show interfaces Gi0/1 spanning-tree | include Role|State
```

---

## 4. Exam Traps

- **STP ≠ link protection only** — it's loop prevention; without it you get storms.
- **Root is chosen by LOWEST bridge ID** (priority first, then MAC).
- **Blocking ports still receive BPDUs** (they listen for better paths); Listening is a
  transient in classic STP.
- **Default priority 32768** — adjustments needed for real roots.
- **50-second convergence** is the classic complaint — that's why RSTP/Rapid PVST+ exist.
- **Don't confuse port state (blocking/forwarding) with port role (root/designated/alternate).**
