# STP (Spanning Tree Protocol)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Spanning Tree Protocol (STP, IEEE 802.1D)** prevents **Layer-2 loops** in redundant
switched networks. It computes a loop-free **tree topology**: one **root bridge**, one
deterministic path per segment, and all redundant links placed in **Blocking**. Without
it, redundant links cause broadcast storms, MAC-table flapping, and duplicated frames.
Classic STP converges in **~30–50 s** — that slowness is the entire motivation for RSTP
(Level 08 note 02).

---

## 2. Core Concepts

### 2.1 Why loops are catastrophic (the "why STP exists")

| Problem | Cause |
|---------|-------|
| **Broadcast storm** | broadcast frames loop forever (exponential) |
| **MAC table flapping** | switch learns the same MAC on two ports |
| **Duplicate frames** | unicast frames take multiple paths |
| **CPU meltdown** | switches process endless copies |

- STP exists precisely to make redundant L2 failover **loop-free**.
- It is **not** a link-redundancy protocol — it is a **loop-prevention** protocol that
  permits redundant topologies to exist safely.

### 2.2 STP decision process (3 steps)

To build the tree every switch runs, in order:

1. **Elect the Root Bridge** — lowest **Bridge ID** (priority + MAC).
2. **Determine Root Ports** — per non-root switch: the best path to root.
3. **Determine Designated Ports** — per segment: the switch that serves it best.
   Everything else → **Blocking**.

### 2.3 Bridges and Bridge ID

```
Bridge ID = Priority (2 B) + Extended System ID/VLAN (12 bits) + System MAC (6 B)
```

- Priority default **32768**; a bridge with the lowest priority **then lowest MAC** wins.
- In per-VLAN flavors, the **extended system ID (12 bits)** encodes the VLAN into the
  priority field — that's how PVST+ gets per-VLAN roots.
- Because the low 12 bits carry the VLAN, configurable priority values are limited to
  **multiples of 4096**: `0, 4096, 8192, ..., 61440` (default 32768).
- Effective bridged-priority == `configured_priority + VLAN` (e.g., `priority 4096` for
  VLAN 10 → effective 4106).

### 2.4 Path selection / the 4-way comparison

For every port, STP chooses the best BPDU by this exact order:

1. **Lowest Root Bridge ID**
2. **Lowest Root Path Cost**
3. **Lowest Sender Bridge ID**
4. **Lowest Sender Port ID**

This same comparison elects the root (step 1), picks root ports (steps 1–4), and picks
designated ports per segment.

### 2.5 The port states & roles

| State | Forwards data | Learns MAC | Purpose |
|-------|---------------|------------|---------|
| Blocking | no | no | no BPDUs accepted, switch off path |
| Listening | no | no | electing role; waiting |
| Learning | no | yes | building table, quiet forwarding |
| Forwarding | yes | yes | active data path |
| Disabled | no | no | admin-shutdown |

- **Roles** (purpose) are separate from **states** (phases): Root / Designated /
  Non-designated under 802.1D; RSTP adds Alternate / Backup. Never label by state alone.
- Convergence: Blocking→Listening→Learning→Forwarding ≈ **50 s** (slow!) → RSTP fixes.

### 2.6 BPDUs — the STP language

- **BPDU (Bridge Protocol Data Unit)** sent every **2 s** (default hello).
- Contents: root bridge ID, root path cost, sender bridge ID, sender port ID, and the
  timer values (max age / hello / forward delay).
- **Root** originates BPDUs; **non-roots relay** them toward the leaves. Blocking ports
  still **receive** BPDUs (they monitor for a better path) but do not send.

### 2.7 Timers and the 50 s problem

| Timer | Default | Role |
|-------|---------|------|
| **Hello** | 2 s | BPDU interval |
| **Max Age** | 20 s | how long a port waits for a BPDU before aging the info |
| **Forward Delay** | 15 s | duration of Listening and of Learning phases |

- A topology change uses the **TCN (Topology Change Notification)** mechanism: the
  detecting switch sends a TCN toward the root, the root echoes a TC in its BPDUs, and
  switches shorten MAC aging to ~15 s.
- Nominal convergence ≈ 20 (max age) + 15 (listening) + 15 (learning) = **50 s**, but
  timers overlap — memorize the *timers*, not an absolute convergence figure.

### 2.8 Cost calculation (path cost)

| Speed (reference) | Cost |
|-------------------|------|
| 10 Mbps | 100 |
| 100 Mbps | 19 |
| 1 Gbps | 4 |
| 10 Gbps | 2 |
| 40/100 Gbps | 1 |

- Lower cost path chosen; ties broken by lowest sender bridge ID, then sender port ID.
- Costs are **per-VLAN** in PVST+-style flavors, and per-interface cost can be tuned:
  `spanning-tree vlan 10 cost 19`.

## 3. Configuration / Commands

```text
! Force a root (elect it)
spanning-tree vlan 10 priority 4096
spanning-tree vlan 10 root primary       # macro: 24576 (or lower if required)
spanning-tree vlan 10 root secondary     # macro: 28672

! Verify tree
show spanning-tree
show spanning-tree vlan 10
show spanning-tree bridge
show spanning-tree root                  # which switch believes it is root
show spanning-tree detail | include "State|Role|Priority"
show interfaces Gi0/1 spanning-tree
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Wrong root | no root priority set; lowest MAC won | `show spanning-tree root`, set priority |
| 50 s outage per change | classic 802.1D still running | `show spanning-tree summary`; switch to rapid |
| Port never reaches Forwarding | forward delay / max age tuned too long | `show spanning-tree \| include "Max age\|Forward"` |
| Total loop/broadcast storm | STP disabled or redundant link not bridged | `spanning-tree mode`, check all uplinks |
| MAC flapping | stale MACs after topology change | aging ~15 s during TC window; verify TCN |

---

## 5. Exam Traps

- **STP ≠ link protection only** — it's loop prevention; without it you get storms.
- **Root is chosen by LOWEST bridge ID** (priority first, then MAC).
- **Blocking ports still receive BPDUs** (they listen for better paths); Listening is a
  transient in classic STP.
- **Default priority 32768**, and per-VLAN configurable priorities are **multiples of 4096**.
- **50-second convergence** is the classic complaint — that's why RSTP/Rapid PVST+ exist.
- **Don't confuse port state (blocking/forwarding) with port role (root/designated/alternate).**
- **Decision order: root ID → path cost → sender bridge ID → sender port ID.**
