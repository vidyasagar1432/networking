# STP (Spanning Tree Protocol)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Spanning Tree Protocol (STP, IEEE 802.1D)** prevents **Layer-2 loops** in redundant switched networks by building a **loop-free logical topology**.

STP allows physical redundancy while placing selected redundant paths into a **non-forwarding state**. This prevents:

- Broadcast storms
    
- Unknown-unicast flooding loops
    
- MAC-table instability / flapping
    
- Duplicate frames
    

Classic 802.1D STP converges relatively slowly because it relies heavily on timers. This limitation led to **RSTP (802.1w)** and Cisco **Rapid PVST+**.

> **CCNP Mental Model**
> 
> ```text
> REDUNDANT L2 TOPOLOGY
>        │
>        ▼
>      STP
>        │
>        ├── Elect Root Bridge
>        │
>        ├── Select Root Port on each non-root switch
>        │
>        ├── Select Designated Port on each segment
>        │
>        └── Put unnecessary paths into non-forwarding state
>                 │
>                 ▼
>          LOOP-FREE L2 TOPOLOGY
> ```

---

# 2. Core Concepts

## 2.1 Why L2 loops are catastrophic

Ethernet frames do not contain a Layer-2 TTL/hop limit. Therefore, a loop can allow frames to circulate repeatedly.

|Problem|What happens|
|---|---|
|**Broadcast storm**|Broadcast and flooded frames circulate repeatedly|
|**MAC-table flapping**|A switch learns the same source MAC from different ports|
|**Duplicate frames**|The same frame can reach a destination through multiple paths|
|**CPU / link saturation**|Continuous flooding consumes bandwidth and switch resources|

### Key idea

**STP is primarily a loop-prevention protocol, not a link-redundancy protocol.**

Redundancy exists physically; STP determines which links are allowed to forward at a given time.

---

## 2.2 STP decision process

The simplified STP process is:

### 1. Elect the Root Bridge

The switch with the **lowest Bridge ID (BID)** becomes the Root Bridge.

### 2. Select Root Ports

Every **non-root switch** selects one **Root Port (RP)**.

The Root Port is the port providing the **best path toward the Root Bridge**.

### 3. Select Designated Ports

For each Layer-2 segment, STP selects one **Designated Port (DP)** that provides the best path toward the Root Bridge.

### 4. Block redundant paths

Ports that are neither Root Ports nor Designated Ports become **non-designated / alternate paths** and do not forward user traffic in classic STP.

> **Important:** A switch does not simply choose "one port per segment." STP establishes a loop-free forwarding tree by selecting Root Ports and Designated Ports and suppressing redundant paths.

---

# 3. Bridge ID (BID)

The Bridge ID is used to elect the Root Bridge.

Conceptually:

```text
Bridge ID
│
├── Bridge Priority
│      ├── Configured priority
│      └── Extended System ID (VLAN ID)
│
└── MAC Address
```

In PVST+/Rapid PVST+, the Bridge ID uses:

```text
16-bit Priority field
│
├── 4 bits: configurable priority
└── 12 bits: Extended System ID (VLAN ID)
```

Therefore, configurable bridge priorities occur in increments of **4096**:

```text
0
4096
8192
12288
16384
20480
24576
28672
32768   ← default
36864
40960
45056
49152
53248
57344
61440
```

### Root election

The lowest Bridge ID wins:

```text
Lowest Bridge Priority
        ↓
Lowest Extended System ID when applicable
        ↓
Lowest MAC Address
```

For the same VLAN, this is commonly simplified as:

> **Lowest priority wins; if tied, lowest MAC wins.**

### Example

```text
SW1
Priority = 32768
MAC      = 0000.0000.0001

SW2
Priority = 32768
MAC      = 0000.0000.0002
```

Result:

```text
SW1 = Root Bridge
```

---

## 3.1 Effective priority

For a PVST+/Rapid PVST+ instance:

```text
Effective BID priority = Configured Priority + VLAN ID
```

Example:

```text
Configured priority = 4096
VLAN                 = 10

Effective priority   = 4106
```

The configurable priority itself remains a multiple of **4096**.

# 4. STP Port Roles

Port **roles** describe what a port does in the spanning-tree topology.

|Role|Purpose|
|---|---|
|**Root Port (RP)**|Best path from a non-root switch toward the Root Bridge|
|**Designated Port (DP)**|Best port for a segment toward the Root Bridge|
|**Non-designated / Blocking**|Redundant path that does not forward user traffic in classic STP|

### Root Bridge

The Root Bridge has:

```text
No Root Port
```

Its active ports toward connected segments are normally **Designated Ports**.

### RSTP adds:

```text
Alternate Port
Backup Port
```

These are covered in the RSTP note.

---

# 5. STP Port States

Classic 802.1D STP uses these states:

|State|Forwards data|Learns MAC|Purpose|
|---|--:|--:|---|
|**Blocking**|No|No|Prevents loops while receiving STP information|
|**Listening**|No|No|Participates in STP calculation|
|**Learning**|No|Yes|Builds MAC-address table|
|**Forwarding**|Yes|Yes|Normal data forwarding|
|**Disabled**|No|No|Administratively disabled / not participating|

### Important distinction

```text
PORT ROLE ≠ PORT STATE
```

Examples:

```text
Root Port       → Forwarding
Designated Port → Forwarding
Non-designated  → Blocking
```

In classic STP, **Listening and Learning are transitional states**.

RSTP significantly reduces the dependence on these timer-driven states.

---

# 6. BPDU — STP's Control Message

**BPDU = Bridge Protocol Data Unit**

Switches exchange BPDUs to build and maintain the spanning tree.

A configuration BPDU carries information such as:

- Root Bridge ID
    
- Root Path Cost
    
- Sender Bridge ID
    
- Sender Port ID
    
- Hello Time
    
- Max Age
    
- Forward Delay
    
- Topology Change information
    

### Default Hello Time

```text
2 seconds
```

---

## 6.1 How BPDUs move through the topology

A useful mental model is:

```text
Root Bridge
    │
    │ Configuration BPDUs
    ▼
Designated Ports
    │
    ▼
Non-root Switch
    │
    ├── Receives superior STP information
    │
    ├── Selects Root Port
    │
    └── Generates/updates BPDUs on its Designated Ports
```

The Root Bridge is the reference point for the spanning-tree information.

### Important correction

Do **not** think of STP as:

```text
Root sends BPDU
        ↓
Every other switch blindly relays it
```

Instead, each bridge participates in the STP process, evaluates received information, selects its own port roles, and transmits configuration BPDUs from its Designated Ports.

### Blocking ports

A blocking/non-designated port:

- Does **not** forward normal user traffic.
    
- Can **receive BPDUs**.
    
- Continues monitoring STP information so it can react if the topology changes.
    

---

# 7. STP Path Selection

When comparing received STP information, the important BPDU fields are considered in this general order:

```text
1. Lowest Root Bridge ID
2. Lowest Root Path Cost
3. Lowest Sender Bridge ID
4. Lowest Sender Port ID
```

This is the key comparison sequence to remember for CCNP.

### Root Path Cost

The Root Path Cost represents the cumulative cost of reaching the Root Bridge.

Example:

```text
        1G
SW2 ───────── SW1
             ROOT

SW2 Root Path Cost = 4
```

If another path has:

```text
Path A = 4
Path B = 19
```

STP prefers:

```text
Path A
```

because:

```text
4 < 19
```

### Important

The four-field comparison is the **BPDU information comparison logic**. Root-port and designated-port selection also involve the local port/interface context and tie-breakers; do not memorize it as a simplistic universal "four comparisons always and only" algorithm.

---

# 8. STP Path Cost

Classic short-method reference costs:

|Link Speed|Short STP Cost|
|---|--:|
|10 Mbps|100|
|100 Mbps|19|
|1 Gbps|4|
|10 Gbps|2|
|40 Gbps|1|
|100 Gbps|1|

Lower total path cost is preferred.

### Cisco STP cost methods

Cisco supports different cost methods.

#### Short method

Common reference values:

```text
10 Mbps   → 100
100 Mbps  → 19
1 Gbps    → 4
10 Gbps   → 2
100 Gbps  → 1
```

#### Long method

The long method provides much larger values and better granularity for high-speed links.

Common examples:

```text
100 Mbps → 200,000
1 Gbps   → 20,000
10 Gbps  → 2,000
100 Gbps → 200
```

> **CCNP Tip:** Do not assume every `show spanning-tree` output uses the short-cost values. Know that Cisco can use a configurable **short or long path-cost method**.

### Per-interface cost

A port's STP cost can be manually changed:

```text
interface GigabitEthernet0/1
 spanning-tree vlan 10 cost 19
```

This can influence Root Port selection.

# 9. STP Timers

Classic 802.1D uses three major timers:

|Timer|Default|Purpose|
|---|--:|---|
|**Hello**|2 s|Interval between Configuration BPDUs|
|**Max Age**|20 s|Maximum time STP information is considered valid|
|**Forward Delay**|15 s|Time spent in Listening and Learning|

### Forward Delay

Classic STP normally spends:

```text
Listening = 15 s
Learning  = 15 s
```

Therefore:

```text
15 + 15 = 30 s
```

If Max Age must also expire:

```text
20 + 15 + 15 ≈ 50 s
```

### Important

Do not memorize:

> "STP always takes exactly 50 seconds."

Instead:

> **Classic STP can converge slowly, with a commonly cited worst-case sequence approaching ~50 seconds.**

The actual time depends on the failure and where it occurs in the topology.

---

# 10. Topology Changes and TCN

Classic 802.1D uses **Topology Change Notification (TCN)** BPDUs.

A simplified process:

```text
Topology change detected
        │
        ▼
Switch generates TCN
        │
        ▼
TCN travels toward Root Bridge
        │
        ▼
Root acknowledges the TCN
        │
        ▼
Root sets TC flag in Configuration BPDUs
        │
        ▼
Switches temporarily reduce MAC aging
        │
        ▼
MAC entries age using Forward Delay
        │
        ▼
Stale MAC information is removed faster
```

### MAC aging during a topology change

The temporary aging behavior uses the **Forward Delay**, normally:

```text
15 seconds
```

This allows switches to remove stale MAC entries more quickly after a topology change.

> **Important:** The TCN itself does not directly "set MAC aging to 15 seconds." The Root's **Topology Change (TC) indication** causes the temporary aging behavior.

# 11. Cisco Configuration

## 11.1 Set a specific STP priority

```text
spanning-tree vlan 10 priority 4096
```

Lower priority makes the switch more likely to become Root Bridge.

Example:

```text
SW1(config)# spanning-tree vlan 10 priority 4096
```

---

## 11.2 Root Primary

Cisco provides a convenience macro:

```text
spanning-tree vlan 10 root primary
```

This attempts to make the switch the primary Root Bridge by adjusting its priority appropriately based on the current spanning-tree information.

Do not treat it as simply:

```text
root primary = always 24576
```

The macro can choose a lower priority when required.

---

## 11.3 Root Secondary

```text
spanning-tree vlan 10 root secondary
```

This is used to make the switch a predictable backup Root Bridge.

Under common default conditions, Cisco uses:

```text
28672
```

# 13. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|**Unexpected Root Bridge**|Priority not intentionally configured|`show spanning-tree root`|
|**Root changes unexpectedly**|Priority/MAC/topology changed|`show spanning-tree vlan 10`|
|**Slow convergence**|Classic 802.1D STP|`show spanning-tree summary`|
|**Port remains non-forwarding**|STP role/state or topology issue|`show spanning-tree interface ... detail`|
|**Broadcast storm**|STP disabled/misconfigured or L2 loop exists|Check STP mode and topology|
|**MAC flapping**|Loop or topology instability|Check STP + MAC-table movement|
|**Unexpected blocked link**|STP selected another path as superior|Compare Root Path Cost and BPDUs|
|**Wrong path selected**|Incorrect port cost/priority|Check interface STP cost and port priority|

### Useful troubleshooting sequence

```text
1. Identify the Root Bridge
        ↓
2. Check Root Port on each non-root switch
        ↓
3. Check Designated Ports
        ↓
4. Identify blocked/non-forwarding paths
        ↓
5. Compare Root Path Cost
        ↓
6. Check STP priority / port priority / cost
        ↓
7. Check topology changes and MAC flapping
```

# 14. STP Port Priority

When path costs tie, **port priority** can influence the Port ID used for tie-breaking.

Cisco's default STP port priority is commonly:

```text
128
```

Port priority values are configured in increments of **16**.

Example:

```text
interface GigabitEthernet0/1
 spanning-tree vlan 10 port-priority 64
```

This can be used to influence which port becomes preferred when the relevant STP information is otherwise tied.

> **Do not confuse:**
> 
> ```text
> Bridge Priority → influences Root Bridge election
> Port Priority   → influences port selection/tie-breaking
> ```

# 16. STP vs RSTP

|Feature|Classic STP|RSTP|
|---|---|---|
|Standard|802.1D|802.1w|
|Convergence|Slow|Rapid|
|States|Blocking, Listening, Learning, Forwarding|Discarding, Learning, Forwarding|
|Roles|Root, Designated, Non-designated|Root, Designated, Alternate, Backup|
|Transition|Timer-driven|Proposal/Agreement + edge behavior|
|Typical modern use|Legacy|Preferred|

### Key idea

```text
STP
│
└── Timer-dependent convergence
          ↓
       Slow

RSTP
│
└── Explicit roles + rapid transitions
          ↓
       Fast
```

See **Level 08 · RSTP** for the detailed rapid-convergence mechanism.

# 17. Exam Traps

### Trap 1 — Lowest Bridge ID wins

Correct:

```text
Lowest Bridge ID
    ↓
Lowest priority
    ↓
Lowest MAC if necessary
```

---

### Trap 2 — STP is not "link redundancy"

STP does not make every redundant link simultaneously forward.

Instead:

```text
Physical redundancy
        ↓
STP calculates topology
        ↓
Some paths forward
Some paths do not
```

---

### Trap 3 — Role ≠ state

Do not confuse:

```text
Root Port        ← ROLE
Designated Port  ← ROLE
Blocking         ← STATE
Forwarding       ← STATE
```

---

### Trap 4 — Blocking ports still receive STP information

A non-forwarding port can still receive BPDUs and monitor the topology.

---

### Trap 5 — Classic STP does not always mean exactly 50 seconds

`~50 s` represents a commonly cited worst-case timer sequence, not a universal fixed convergence time.

---

### Trap 6 — STP cost matters

If two paths reach the Root Bridge:

```text
Path A = 4
Path B = 19
```

STP prefers:

```text
Path A
```

because lower Root Path Cost wins.

---

### Trap 7 — Priority is not arbitrary

For PVST+/Rapid PVST+:

```text
0, 4096, 8192, ... 61440
```

---

### Trap 8 — TCN and TC are different

```text
TCN = notification mechanism

TC = topology-change indication in Configuration BPDUs
```

The TC indication causes temporary faster MAC aging.

# 20. Final CCNP Takeaway

```text
STP does NOT remove physical redundancy.

It converts:

     REDUNDANT L2 TOPOLOGY
              │
              ▼
       STP CALCULATION
              │
      ┌───────┴────────┐
      ▼                ▼
   FORWARD          BLOCK
   BEST PATH       REDUNDANT PATH
      │                │
      └───────┬────────┘
              ▼
       LOOP-FREE L2
```

Remember the core sequence:

```text
1. Elect Root Bridge
       ↓
2. Select Root Port
       ↓
3. Select Designated Port
       ↓
4. Suppress redundant paths
       ↓
5. Maintain a loop-free Layer-2 topology
```

And remember:

> **Lowest Bridge ID → Root → Lowest Root Path Cost → Root Port → Designated Port → Redundant paths do not forward**
