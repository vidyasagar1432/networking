# Loop Guard

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Loop Guard** protects against **unidirectional link failure**: when a link goes one-way
(fiber break, one-directional fault/switch bug), a blocking port stops receiving BPDUs
and might wrongly transition to Forwarding — creating a Layer-2 loop. Loop Guard puts
such a port into **loop-inconsistent (discarding)** until valid BPDUs return. It guards
against the *silent* failure that Root Guard cannot see.

---

## 2. Core Concepts

### 2.1 The failure it fixes

```
Normal:   [A] ──BPDU──▶ [B]   B's blocking port keeps hearing BPDUs
One-way:  [A] ──✘───▶ [B]   B stops seeing BPDUs entirely
```

- Without Loop Guard, B sees "no superior BPDU" → after MaxAge it may declare itself
  designated/forwarding on what became a **half-dead link** → L2 loop.
- Loop Guard instead holds the port **Discarding (loop-inconsistent)** until BPDUs resume.

### 2.2 Behavior

| Condition | Loop Guard outcome |
|-----------|--------------------|
| BPDU loss on a blocked / non-designated port | port → **loop-inconsistent (discarding)** |
| BPDUs return | port **auto-reverts** |
| Normal operation | no impact |

- It does NOT prevent the link failure — it prevents the **wrong STP transition** after it.

### 2.3 Config & placement

```text
interface Gi0/24
 spanning-tree guard loop
! or globally
spanning-tree loopguard default
```

- Best on **blocking/backup/redundant ports** (where a silent failure is dangerous) —
  commonly across redundant distribution/core uplink pairs.
- Complements **UDLD**: UDLD detects one-way at the physical layer; Loop Guard reacts at
  the STP layer. On fiber, both are often deployed together.

### 2.4 Loop Guard vs UDLD

| | Loop Guard | UDLD |
|--|-----------|------|
| Detect | missing BPDUs (STP view) | physical one-way detection |
| Action | block port (loop-inconsistent) | errdisable (aggressive) |
| Scope | any STP context | fiber / P2P links |
| Standard | STP feature | Cisco-specific |

- They work together — UDLD aggressive mode error-disables; Loop Guard holds STP-safe.

### 2.5 Loop Guard vs Root Guard (recap)

| | Loop Guard | Root Guard |
|--|-----------|------------|
| Fixes | BPDU loss → loop | superior-root BPDU → stolen root |
| Action | loop-inconsistent | root-inconsistent |
| Trigger | silent one-way loss | misbehaving root candidate |
| Both | block at STP level, auto-recover | — |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Port loop-inconsistent | BPDUs stopped (one-way link) | repair physical link; UDLD to detect |
| Loop still appeared | Loop Guard not on the blocking path | enable on all redundant uplinks |
| Hard to detect silently | Loop Guard vs UDLD choice | run both on fiber pairs |
| Guard state flapping | marginal optics | check fiber/optics power |

---

## 5. Exam Traps

- **Loop Guard ≠ Root Guard** — one for silent link loss, one for root theft.
- **It makes the port Discarding/loop-inconsistent, NOT errdisabled** (errdisable is
  BPDU Guard/UDLD aggressive).
- **Auto-recovery** once BPDUs flow again.
- **Place on blocking/redundant uplinks**, where one-way failure is the hazard — not edge ports.
- **Complements UDLD** (physical detection) — both may appear in the same answer.
- Named state in output: **loop-inconsistent**.
