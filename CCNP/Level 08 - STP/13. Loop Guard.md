# Loop Guard

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Loop Guard** protects STP from **unexpected BPDU loss** on a **non-designated port**.

If a redundant link experiences a unidirectional failure or another condition that causes  
expected BPDUs to stop arriving, a non-designated port could incorrectly transition toward  
forwarding. That can create a **Layer-2 loop**.

Loop Guard prevents this by placing the affected port into  
**loop-inconsistent (discarding)** state until valid BPDUs are received again.

> **Loop Guard protects against the STP symptom — unexpected BPDU loss.**  
> It does not directly detect the physical failure itself.

---

## 2. Core Concepts

### 2.1 The Failure It Protects Against

Normal operation:

```text
        BPDU
[A] ───────────────▶ [B]
                      │
                Non-Designated
                   Port
                      │
                 Discarding
```

Possible one-way failure:

```text
[A] ────────✘───────▶ [B]
                      │
                 BPDU stops
                 arriving
                      ↓
              Loop Guard detects
               unexpected BPDU
                   loss
                      ↓
              loop-inconsistent
```

Without Loop Guard, loss of expected BPDUs can cause STP to reconsider the port's role and  
potentially allow a redundant path to become forwarding.

With Loop Guard:

```text
Expected BPDU
     │
     ↓
BPDU disappears
     │
     ↓
Loop Guard
     │
     ↓
loop-inconsistent
     │
     ↓
Keep port from forwarding
     │
     ↓
BPDU returns
     │
     ↓
Automatic recovery
```

---

## 3. What Loop Guard Actually Detects

Loop Guard does **not** directly determine:

> "The fiber is broken."

Instead, it observes the STP condition:

> **"A port that should be receiving BPDUs has stopped receiving them."**

Possible causes include:

- Unidirectional link failure
    
- Fiber/optic problems
    
- Switch hardware problems
    
- BPDU transmission failure
    
- Other conditions causing expected BPDUs to disappear
    

This distinction is important for the CCNP exam:

```text
UDLD
│
└── Detects unidirectional communication

Loop Guard
│
└── Protects STP when expected BPDUs disappear
```

---

## 4. Behavior

|Condition|Loop Guard Result|
|---|---|
|Expected BPDUs continue arriving|Normal STP operation|
|Expected BPDUs unexpectedly stop|Port becomes **loop-inconsistent**|
|Port is loop-inconsistent|Port remains **discarding**|
|Valid BPDUs return|Port automatically recovers|
|Physical failure itself repaired|Depends on whether BPDUs resume|
|Manual shutdown/no shutdown normally required|**No**|

### Important

Loop Guard does **not** repair the failed link.

It prevents STP from making an unsafe forwarding decision while the expected BPDUs are  
missing.

---

## 5. Where to Configure Loop Guard

Loop Guard is most useful on **redundant/non-designated paths** where the loss of expected  
BPDUs could cause a port to incorrectly transition toward forwarding.

Typical topology:

```text
                 DISTRIBUTION
                /            \
               /              \
              /                \
        [Non-Designated]   [Designated]
             Port              Port
               │                │
               │                │
               └──── ACCESS ────┘
```

Example:

```cisco
interface GigabitEthernet0/24
 description Redundant STP path
 spanning-tree guard loop
```

### Global Configuration

Cisco also supports:

```cisco
spanning-tree loopguard default
```

This enables Loop Guard globally for applicable **point-to-point STP links**.

### Placement Rule

Remember:

> **Protect redundant STP paths where expected BPDUs must continue arriving.**

Do not think of Loop Guard simply as:

> "Put it on every blocked port."

The more accurate mental model is:

> **"Protect non-designated ports that depend on receiving BPDUs to remain safely non-forwarding."**

## 6. Loop Guard vs UDLD

|Feature|Loop Guard|UDLD|
|---|---|---|
|Primary purpose|Protect STP from unexpected BPDU loss|Detect unidirectional communication|
|Looks at|STP BPDUs|Link/device neighbor communication|
|Trigger|Expected BPDUs stop arriving|Unidirectional condition detected|
|Typical action|**loop-inconsistent**|Can place interface in **err-disabled** state|
|Layer/context|STP protection|Link/device-level detection|
|Cisco-specific|STP feature|Cisco technology|
|Best mental model|"Why did my STP BPDUs disappear?"|"Can both sides communicate correctly?"|

### They Complement Each Other

```text
          Unidirectional Failure
                   │
          ┌────────┴────────┐
          ↓                 ↓
        UDLD            Loop Guard
          │                 │
 Detects one-way       Sees expected
 communication         BPDUs missing
          │                 │
          ↓                 ↓
    Errdisable*        loop-inconsistent
```

* Depending on UDLD mode and platform behavior.

### Exam Memory

```text
UDLD       → Detect the link problem
Loop Guard → Prevent the STP loop
```

---

## 7. Loop Guard vs Root Guard

|Feature|Loop Guard|Root Guard|
|---|---|---|
|Protects|STP loop prevention|Root Bridge placement|
|Trigger|Expected BPDU loss|Superior BPDU|
|Main threat|Redundant path incorrectly forwarding|Unexpected switch influencing root|
|Result|**loop-inconsistent**|**root-inconsistent**|
|Recovery|Automatic when BPDUs return|Automatic when superior BPDUs disappear|
|Mental model|"BPDUs disappeared."|"A better root appeared."|

### Easy Comparison

```text
ROOT GUARD
│
├── Superior BPDU
│
└── root-inconsistent
```

```text
LOOP GUARD
│
├── Expected BPDU disappears
│
└── loop-inconsistent
```

---

## 8. Loop Guard vs BPDU Guard

|Feature|Loop Guard|BPDU Guard|
|---|---|---|
|Primary purpose|Protect redundant STP paths|Protect edge/PortFast ports|
|Trigger|Expected BPDU loss|Any BPDU|
|Typical port|Non-designated/redundant path|Host/edge port|
|Result|**loop-inconsistent**|**err-disabled**|
|Automatic recovery|Yes|Not by default|
|PortFast required|No|Commonly used with PortFast|

### Mental Model

```text
LOOP GUARD
│
├── BPDU expected
├── BPDU disappears
└── loop-inconsistent
```

```text
BPDU GUARD
│
├── Edge port
├── BPDU appears
└── err-disabled
```

## 10. Troubleshooting

### Symptom: Port is loop-inconsistent

Likely condition:

```text
Expected BPDU
     ↓
BPDU disappears
     ↓
Loop Guard
     ↓
loop-inconsistent
```

Check:

```cisco
show spanning-tree inconsistentports
show spanning-tree interface Gi0/24
show spanning-tree vlan 10
```

Then investigate why BPDUs stopped arriving.

Check:

- Fiber/copper cabling
    
- Optics
    
- Interface errors
    
- Neighbor switch
    
- STP configuration
    
- BPDU transmission
    
- UDLD status
    

---

### Symptom: Loop Guard keeps changing state

Possible causes:

- Intermittent fiber
    
- Bad optic/transceiver
    
- Interface errors
    
- Unstable neighbor
    
- BPDU loss
    
- Physical-layer problems
    

Useful commands:

```cisco
show interfaces Gi0/24
show interfaces counters errors
show spanning-tree interface Gi0/24
show spanning-tree inconsistentports
show udld interface Gi0/24
```

---

### Symptom: STP loop still occurs

Check whether the affected redundant path is protected:

```cisco
show spanning-tree inconsistentports
show spanning-tree summary | include Guard
```

Verify that Loop Guard is actually enabled on the appropriate STP interfaces.

Also investigate:

- UDLD
    
- STP topology
    
- Port roles
    
- EtherChannel configuration
    
- Physical-layer faults
    
- Unexpected switches

## 11. Recovery

Loop Guard is designed for **automatic recovery**.

Normal sequence:

```text
BPDUs present
     │
     ↓
Normal STP
     │
     ↓
Expected BPDUs disappear
     │
     ↓
loop-inconsistent
     │
     ↓
BPDUs return
     │
     ↓
Automatic recovery
     │
     ↓
Normal STP
```

Normally, you do not need:

```cisco
shutdown
no shutdown
```

to recover the STP state.

## 13. Exam Traps

### Trap 1 — Loop Guard does not detect the physical failure directly

**Wrong:**

> Loop Guard detects a broken fiber.

**Correct:**

> Loop Guard reacts to **unexpected loss of expected BPDUs**.

UDLD is the feature specifically associated with detecting unidirectional communication.

---

### Trap 2 — Loop Guard is not Root Guard

**Loop Guard:**

```text
BPDU loss
    ↓
loop-inconsistent
```

**Root Guard:**

```text
Superior BPDU
    ↓
root-inconsistent
```

---

### Trap 3 — Loop Guard is not BPDU Guard

**Loop Guard:**

```text
Expected BPDU disappears
    ↓
loop-inconsistent
```

**BPDU Guard:**

```text
Any BPDU arrives on protected edge port
    ↓
err-disabled
```

---

### Trap 4 — Loop Guard is not the same as UDLD

```text
UDLD
└── Detects unidirectional communication

Loop Guard
└── Protects STP when expected BPDUs disappear
```

They can complement each other.

---

### Trap 5 — Remember the state name

The important Cisco STP state is:

```text
loop-inconsistent
```

Not:

```text
err-disabled
```

Loop Guard is an **STP protection state**, whereas BPDU Guard and aggressive UDLD can  
result in **err-disabled**.

---

### Trap 6 — Do not memorize only "blocked port"

A better exam rule is:

> **Loop Guard protects a non-designated port that expects BPDUs and must not incorrectly  
> transition to forwarding when those BPDUs disappear.**
