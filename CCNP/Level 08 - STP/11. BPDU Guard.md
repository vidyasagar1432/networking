# BPDU Guard

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**BPDU Guard** protects **edge/PortFast ports** by shutting down a port if it
receives a **BPDU**. A BPDU indicates that a device capable of participating in
Spanning Tree has appeared on the port.

When BPDU Guard detects a BPDU, the interface is placed into the
**err-disabled** state, preventing the unexpected device from participating in
STP and helping protect the Layer-2 topology.

> **Mental model:** PortFast says "this is an edge port"; BPDU Guard says
> "if a BPDU appears here, shut the port."

---

## 2. Core Concepts

### 2.1 Why BPDU Guard exists

**PortFast** is designed for ports connected to end devices such as PCs,
printers, servers, and similar hosts.

A problem occurs if someone connects a switch to a PortFast-enabled port:

```text
Normal:

PC ─────────── Access Port
                │
             PortFast
                │
          Forward quickly


Rogue Switch:

Switch ──────── Access Port
                  │
               PortFast
                  │
              BPDU Guard
                  │
             BPDU received
                  │
              ERRDISABLE
```

Without BPDU Guard, the connected switch can participate in STP and potentially  
alter the Layer-2 topology.

With BPDU Guard:

> **BPDU received on protected port → interface goes err-disabled**

---

### 2.2 How BPDU Guard works

|Event|BPDU Guard Enabled|BPDU Guard Not Enabled|
|---|---|---|
|BPDU received|Port becomes **err-disabled**|BPDU is processed by STP|
|Normal host traffic|Unaffected|Unaffected|
|Protection against unexpected switch|Strong|No BPDU Guard protection|
|Recovery required after violation|Yes|No|

The important point is:

**BPDU Guard does not filter the BPDU. It reacts to the BPDU by shutting down  
the interface.**

---

## 3. Configuration

### 3.1 Per-interface BPDU Guard

Use this when you want BPDU Guard on a specific interface:

```cisco
interface GigabitEthernet0/1
 spanning-tree portfast
 spanning-tree bpduguard enable
```

`spanning-tree bpduguard enable` directly enables BPDU Guard on that interface.

---

### 3.2 Global BPDU Guard default

For a campus environment, the common approach is to enable BPDU Guard by  
default on **PortFast-enabled ports**:

```cisco
spanning-tree portfast bpduguard default
```

This means:

```text
PortFast-enabled port
        │
        └── BPDU Guard automatically applied
```

This is commonly preferred over configuring BPDU Guard manually on every  
individual access port.

---

### 3.3 Automatic err-disable recovery

By default, an err-disabled interface may remain down until manually recovered.

Enable automatic recovery:

```cisco
errdisable recovery cause bpduguard
errdisable recovery interval 300
```

The interface will attempt recovery after **300 seconds**.

> Automatic recovery should be used carefully. If the offending device remains  
> connected, the port can repeatedly become err-disabled.

---

### 3.4 Manual recovery

You can manually recover the interface:

```cisco
interface GigabitEthernet0/1
 shutdown
 no shutdown
```

On platforms supporting it, you can also use:

```cisco
clear errdisable interface GigabitEthernet0/1
```

## 4. BPDU Guard vs BPDU Filter

This is a **high-value CCNP exam distinction**.

|Feature|BPDU Guard|BPDU Filter|
|---|---|---|
|Main purpose|Protect edge ports|Suppress/filter BPDUs|
|BPDU received|**Err-disables port**|BPDUs may be suppressed depending on configuration|
|STP protection|Strong|Potentially dangerous|
|Typical use|PortFast/edge ports|Specialized edge designs|
|Security role|Defensive|Can hide STP information|
|Key command|`spanning-tree bpduguard enable`|`spanning-tree bpdufilter ...`|

### Remember

```text
BPDU GUARD
    BPDU received
         ↓
    ERRDISABLE
         ↓
      Port down


BPDU FILTER
    BPDU handling
         ↓
    Suppress/filter
         ↓
    STP information can be hidden
```

> **Guard = shut**
> 
> **Filter = suppress**

Do not confuse the two.

## 5. PortFast + BPDU Guard

The standard enterprise edge-port combination is:

```text
              EDGE PORT
                  │
          ┌───────┴───────┐
          │               │
      PortFast        BPDU Guard
          │               │
   Fast forwarding    BPDU received?
          │               │
          │          ┌────┴────┐
          │          │         │
          │         NO        YES
          │          │         │
          │       Normal    ERRDISABLE
          │
          └───────┬───────┘
                  │
             Host access
```

### PortFast

Provides **fast transition to forwarding** for an edge port.

### BPDU Guard

Provides **protection if a BPDU appears** on that edge port.

Therefore:

> **PortFast = fast**
> 
> **BPDU Guard = safe**

## 6. Where BPDU Guard Should Be Used

Typical deployment:

```text
                 ACCESS SWITCH
                      │
        ┌─────────────┼─────────────┐
        │             │             │
       PC           Printer        Server
        │             │             │
     PortFast      PortFast       PortFast
        │             │             │
   BPDU Guard     BPDU Guard     BPDU Guard
```

Good candidates include:

- User access ports
    
- Server access ports
    
- Printer access ports
    
- Other genuine edge/host-facing ports
    

---

## 7. Where BPDU Guard Should NOT Normally Be Used

Do **not** blindly enable BPDU Guard on a normal switch-to-switch  
STP-facing link.

Example:

```text
        Switch A
           │
           │  BPDUs are expected
           │
        Switch B
```

If BPDU Guard is enabled on this legitimate STP link, the expected BPDUs can  
trigger the protection and put the interface into **err-disabled** state.

### Exam rule

> **Host-facing edge port → BPDU Guard**
> 
> **Trusted switch-facing STP link → normally no BPDU Guard**

The exact design can vary, but never treat a legitimate STP-facing link as a  
normal PortFast edge port.

## 8. Troubleshooting

### 8.1 Port unexpectedly becomes err-disabled

Check:

```cisco
show interfaces status
show interfaces status err-disabled
show errdisable recovery
show logging | include BPDU|ERR
```

Look for a BPDU Guard violation.

---

### 8.2 Check the interface

```cisco
show spanning-tree interface GigabitEthernet0/1 detail
```

Useful information includes:

- PortFast status
    
- BPDU Guard status
    
- STP role/state
    
- BPDU information
    

---

### 8.3 Typical troubleshooting flow

```text
Port is DOWN
     │
     ↓
Check interface status
     │
     ↓
Is it ERR-DISABLED?
     │
    YES
     │
     ↓
Check logs / errdisable reason
     │
     ↓
BPDU Guard violation?
     │
    YES
     │
     ↓
Find what is connected
     │
     ├── Rogue/unexpected switch
     │       └── Remove or correct device
     │
     └── Legitimate switch
             └── Remove BPDU Guard from edge port
                 and correct the topology
```

## 9. Common Failure Scenarios

|Symptom|Likely Cause|Fix|
|---|---|---|
|Access port is err-disabled|BPDU received|Find the connected device|
|User connected a switch|BPDU Guard triggered|Remove unauthorized switch or correct design|
|Legitimate switch uplink is err-disabled|BPDU Guard incorrectly enabled|Remove BPDU Guard from the uplink|
|Port repeatedly becomes err-disabled|Offending BPDU source remains connected|Fix the source before/alongside recovery|
|PortFast port has no BPDU protection|BPDU Guard not configured|Enable BPDU Guard|
|STP protection is bypassed/hidden|BPDU Filter misused|Review/remove BPDU Filter|

## 12. BPDU Guard vs Root Guard vs Loop Guard

These features solve different problems.

|Feature|Protects Against|Main Action|
|---|---|---|
|**BPDU Guard**|Unexpected BPDU on edge port|**Err-disables port**|
|**Root Guard**|Unexpected superior BPDUs / root takeover|Places port into **root-inconsistent** state|
|**Loop Guard**|STP loops caused by unidirectional BPDU loss|Places port into **loop-inconsistent** state|
|**BPDU Filter**|BPDU transmission/reception suppression|**Filters/suppresses BPDUs**|

### Mental model

```text
BPDU GUARD
    "Why is a switch talking to my edge port?"
             ↓
         ERRDISABLE


ROOT GUARD
    "Why is this neighbor trying to become Root?"
             ↓
      ROOT-INCONSISTENT


LOOP GUARD
    "Why did expected BPDUs stop arriving?"
             ↓
      LOOP-INCONSISTENT


BPDU FILTER
    "Suppress BPDU exchange."
             ↓
       USE CAREFULLY
```

## 13. Exam Traps

### Trap 1

**BPDU Guard does NOT filter BPDUs.**

Correct:

```text
BPDU received
     ↓
BPDU Guard
     ↓
ERRDISABLE
```

---

### Trap 2

**BPDU Guard is not the same thing as PortFast.**

```text
PortFast
→ Fast edge transition

BPDU Guard
→ Protection when BPDU is received
```

They are commonly deployed together, but they perform different jobs.

---

### Trap 3

**Global BPDU Guard default applies to PortFast ports.**

```cisco
spanning-tree portfast bpduguard default
```

Do not interpret this as "BPDU Guard on every interface regardless of  
PortFast."

---

### Trap 4

**Do not blindly enable BPDU Guard on trusted switch uplinks.**

A legitimate switch sends BPDUs. Those BPDUs can trigger BPDU Guard.

---

### Trap 5

**Err-disabled recovery is not the same as fixing the root cause.**

If the rogue switch remains connected:

```text
BPDU Guard
    ↓
ERRDISABLE
    ↓
300 seconds
    ↓
Recovery
    ↓
BPDU received again
    ↓
ERRDISABLE again
```

Fix the offending connection first.

## 15. Quick Review

|Item|BPDU Guard|
|---|---|
|Purpose|Protect edge/PortFast ports|
|Trigger|BPDU received|
|Action|**Err-disables the port**|
|Common pairing|**PortFast**|
|Global command|`spanning-tree portfast bpduguard default`|
|Per-port command|`spanning-tree bpduguard enable`|
|Recovery|Manual or errdisable recovery|
|Automatic recovery|`errdisable recovery cause bpduguard`|
|Compared with Filter|Guard **shuts**, Filter **suppresses**|
|Compared with Root Guard|Guard protects edge ports; Root Guard protects root placement|
|Compared with Loop Guard|Guard reacts to BPDUs; Loop Guard protects against unexpected BPDU loss|
|Best use|Host-facing access/edge ports|
|Avoid blindly using on|Trusted switch-to-switch STP links|

## 16. One-Line Exam Definition

> **BPDU Guard protects an edge/PortFast port by placing the interface into  
> err-disabled state when a BPDU is received, preventing an unexpected switch  
> from participating in the Layer-2 topology.**
