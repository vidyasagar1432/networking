# BPDU Guard

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**BPDU Guard** protects **edge/PortFast ports**: if the switch receives a **BPDU** on one
of those ports (a signal that a switch was plugged in), the port is put into
**errdisabled** immediately — preventing a rogue switch from creating a Layer-2 loop.
It is the "trust nothing on my edge ports" control and the standard companion to PortFast.

---

## 2. Core Concepts

### 2.1 Why it exists

- **PortFast** already assumes "no switch here" (Level 08 note 10).
- If a user plugs in a switch, that switch **sends BPDUs** → without BPDU Guard a loop is
  possible before STP can reconfigure.
- **BPDU Guard = instant defense**: on BPDU receipt → **errdisable** + log. Clean,
  deterministic edge protection.

### 2.2 How it works

| Event | Result (guard on) | Result (no guard) |
|-------|-------------------|-------------------|
| BPDU arrives on PortFast/edge port | port **errdisabled (down)** | port may convert/loop |
| Normal host traffic | unaffected | unaffected |

- The port stays down until **re-enabled manually or automatically** (`errdisable
  recovery cause bpduguard`).
- When the port is errdisabled, `show interfaces status` shows it in **err-disabled**.

### 2.3 Configuration options

```text
! Per-interface
interface Gi0/1
 spanning-tree bpduguard enable

! Global default for edge/access ports
spanning-tree portfast bpduguard default
```

- Applies per-VLAN in PVST+/Rapid modes where relevant.
- Errdisable recovery:

```text
errdisable recovery cause bpduguard
errdisable recovery interval 300
```

- To manually recover: shut / no shut (or `clear errdisable interface Gi0/1`).

### 2.4 BPDU Guard vs BPDU Filter (critical difference)

| | BPDU Guard | BPDU Filter |
|--|-----------|------------|
| On BPDU received | **ERRDisable** the port | **ignore** them (and stop sending) |
| Loop protection | strong | weak — a filter can hide a loop |
| Recommended | yes (with PortFast) | risky on trunks |
| Command | `bpduguard enable` | `portfast bpdufilter default` |

- Exams hammer that **filter ≠ guard** and guard is the safer edge default.

### 2.5 PortFast + BPDU Guard — the ideal edge combo

- The correct answer for "protect user ports that connect hosts" →
  **PortFast (fast) + BPDU Guard (safe)**.
- Mitigates rogue-switch / STP attacks (also covered in Level 17 Infrastructure Security).
- Do **not** enable on a trunk toward a trusted switch — legitimate BPDUs would shut it.

## 3. Configuration / Commands

```text
spanning-tree portfast bpduguard default       # all access/edge
interface Gi0/1
 spanning-tree bpduguard enable                # per port

errdisable recovery cause bpduguard            # auto-recovery
errdisable recovery interval 300

show interfaces status | include err-disab
show errdisable recovery
show spanning-tree interface Gi0/1 | include BPDU
show logging | include BPDU_Guard|Errdisable
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Edge port down as err-disabled | BPDU Guard triggered (rogue switch) | find device; `clear` / recovery |
| Legit uplink err-disabled | guard enabled toward trusted switch | remove guard from uplinks |
| Port loops despite guard | guard not applied (only PortFast) | add `bpduguard` |
| Repeated triggering | PoE phone w/ embedded switch | whitelist or move to untrusted segment |

---

## 5. Exam Traps

- **BPDU Guard ERRDisables on receiving a BPDU** — the port goes down (it does NOT filter).
- **Filter is different** — it ignores; don't use it to "protect against loops."
- **Default for PortFast-enabled edges** — a solid, correct security answer.
- **Recovery** via `errdisable recovery` — a downed port needs re-enable.
- **Do not enable on a trunk to a trusted switch** — legitimate BPDUs would shut it.
