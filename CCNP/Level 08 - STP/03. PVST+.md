# PVST+ (Per-VLAN Spanning Tree Plus)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PVST+ (Per-VLAN Spanning Tree Plus)** is Cisco's per-VLAN implementation of  
Spanning Tree Protocol that runs a **separate 802.1D-style STP instance for each VLAN**.

Each VLAN independently elects:

- A **root bridge**
    
- Root ports
    
- Designated ports
    
- Blocking ports
    
- A loop-free Layer 2 topology
    

Because every VLAN has its own spanning-tree instance, different VLANs can use  
different forwarding paths. This enables **per-VLAN Layer 2 load balancing** across  
redundant links.

PVST+ uses **classic STP (IEEE 802.1D) convergence behavior**, so it is slower than  
Rapid PVST+, which uses RSTP mechanics while retaining one instance per VLAN.

> **Important:** Modern Cisco switches commonly default to **Rapid PVST+**, not PVST+.

---

# 2. Core Concepts

## 2.1 One Spanning Tree Instance per VLAN

PVST+ maintains a separate STP instance for every active VLAN.

Each VLAN has its own:

- Root bridge
    
- Bridge ID
    
- Root path cost
    
- Root port
    
- Designated ports
    
- Blocking ports
    
- Port states
    
- STP topology
    

For example:

```text
VLAN 10
  Root = SW1
  Gi0/1 = Forwarding
  Gi0/2 = Blocking

VLAN 20
  Root = SW2
  Gi0/1 = Blocking
  Gi0/2 = Forwarding
```

Therefore, the **same physical interface can forward VLAN 10 while blocking VLAN 20**.

This is the foundation of PVST+ load balancing.

### Mental Model

```text
PVST+
│
├── VLAN 10
│     └── Own STP topology
│
├── VLAN 20
│     └── Own STP topology
│
├── VLAN 30
│     └── Own STP topology
│
└── VLAN N
      └── Own STP topology
```

---

## 2.2 PVST+ BPDUs on an 802.1Q Trunk

PVST+ must identify which VLAN an STP BPDU belongs to when crossing an  
802.1Q trunk.

The simplified rule is:

```text
PVST+ BPDU
│
├── Native VLAN BPDU
│     └── Untagged
│
└── Other VLAN BPDUs
      └── 802.1Q tagged
```

However, there is an important **VLAN 1/CST nuance** that is frequently tested.

PVST+ interoperates with the IEEE Common Spanning Tree (CST) through **VLAN 1  
by default**. Cisco sends the IEEE-formatted VLAN 1/CST BPDU untagged for  
interoperability, while PVST+ BPDUs for other VLANs are tagged. If the native VLAN  
is different from VLAN 1, the native-VLAN BPDU is also untagged, while VLAN 1's  
PVST+ BPDU can be tagged.

Therefore, do **not** memorize the oversimplification:

> "Every BPDU for the native VLAN is simply the only untagged BPDU."

Instead remember:

```text
PVST+ over 802.1Q
│
├── VLAN 1 / CST
│     └── IEEE BPDU is untagged for interoperability
│
├── Native VLAN
│     └── Native-VLAN BPDU is untagged
│
└── Other PVST+ VLANs
      └── Tagged with their VLAN ID
```

A **native VLAN mismatch** can cause PVST+ inconsistency because the switches  
associate untagged BPDUs with different VLANs. Cisco uses PVST+ consistency  
checking to detect this condition.

### CCNP Exam Rule

> **PVST+ BPDUs for non-native VLANs are tagged; untagged BPDU handling involves  
> the native VLAN and the special CST/VLAN 1 interoperability mechanism.**

# 2.3 PVST+ vs Classic Single-Instance STP

|Feature|Classic CST / 802.1D|PVST+|
|---|---|---|
|STP instances|1|**1 per VLAN**|
|Root bridge|One global root|**Root per VLAN**|
|Topology|Same for all VLANs|**Independent per VLAN**|
|Path selection|Same tree|**Different trees possible**|
|Load balancing|Limited|**Per-VLAN load balancing**|
|Protocol logic|802.1D|**802.1D per VLAN**|
|Cisco successor|—|**Rapid PVST+**|

---

# 2.4 Extended System ID and Bridge ID

The **Bridge ID (BID)** is used to elect the root bridge.

Conceptually:

```text
Bridge ID
│
├── Priority / System ID Extension
│
└── System MAC Address
```

With the **Extended System ID**, the 12-bit VLAN ID is incorporated into the  
priority field so that each VLAN has a unique Bridge ID.

The configurable STP priority therefore uses increments of **4096**:

```text
0
4096
8192
12288
...
61440
```

The default configurable priority is:

```text
32768
```

For a VLAN, the effective priority portion can be understood as:

```text
Configured Priority + VLAN ID
```

Example:

```text
spanning-tree vlan 10 priority 4096

Effective priority portion:

4096 + 10 = 4106
```

So:

```text
VLAN 10 → 4106
VLAN 20 → 4116
```

The VLAN ID is therefore part of the Bridge ID calculation and helps distinguish  
the STP instance for each VLAN.

### Important

Do **not** write:

```text
Bridge priority = 612
```

The correct concept is:

```text
Effective priority = configured priority + VLAN ID
```

For example:

```text
Configured priority = 4096
VLAN ID             = 10
Effective priority  = 4106
```

---

# 2.5 Root Bridge Election

PVST+ elects a root bridge **independently for every VLAN**.

The switch with the **lowest Bridge ID** becomes the root bridge.

The comparison is:

```text
Lowest Bridge ID
│
├── Lowest effective priority
│
└── Lowest MAC address
```

Example:

```text
SW1
VLAN 10 priority = 4096
MAC = 0000.1111.1111

SW2
VLAN 10 priority = 8192
MAC = 0000.2222.2222
```

SW1 becomes the VLAN 10 root because:

```text
4096 + 10 = 4106
8192 + 10 = 8202

4106 < 8202
```

### Root Placement

A distribution/core switch is normally intentionally configured as the root.

Example:

```text
spanning-tree vlan 10 priority 4096
```

or:

```text
spanning-tree vlan 10 root primary
```

Cisco's `root primary` command is a macro that adjusts the switch's priority  
based on the existing root priority rather than simply meaning "always set  
priority to 4096."

# 3. How PVST+ Selects Ports

Port roles are determined **independently for each VLAN**.

---

## 3.1 Root Port

Every **non-root switch** selects one Root Port per VLAN.

The Root Port is the port providing the **best path toward the root bridge**.

The root bridge itself has:

```text
No Root Port
```

---

## 3.2 Designated Port

Each Layer 2 segment has one **Designated Port** for a given VLAN.

The Designated Port represents the switch that provides the best path toward  
the root for that segment.

The root bridge's active ports are normally Designated Ports.

---

## 3.3 Blocking Port

A redundant path that is not selected for forwarding is placed into the  
appropriate non-forwarding state.

In classic 802.1D/PVST+ terminology, this is commonly described as a  
**Blocking port**.

With **Rapid PVST+**, the corresponding RSTP role terminology includes:

- Root
    
- Designated
    
- Alternate
    
- Backup
    

> **Exam trap:** **Alternate** is an RSTP/Rapid PVST+ port role. Classic PVST+  
> uses the 802.1D terminology and does not use Alternate as its formal role.

---

# 3.4 Port Selection / BPDU Comparison

When choosing the best path, STP compares BPDU information.

The important hierarchy is:

```text
1. Lowest Root Bridge ID
        ↓
2. Lowest Root Path Cost
        ↓
3. Lowest Sender Bridge ID
        ↓
4. Lowest Sender Port ID
```

In practical terms:

```text
Who is the root?
      ↓
What is my total cost to the root?
      ↓
Which neighboring switch provides the better BPDU?
      ↓
Which port on that neighboring switch wins the final tie-break?
```

The exact comparison is performed per VLAN.

---

# 3.5 Root Path Cost

STP chooses the path with the **lowest total path cost** toward the root.

Common Cisco short-method reference costs include:

|Link Speed|STP Cost|
|---|--:|
|10 Mbps|100|
|100 Mbps|19|
|1 Gbps|4|
|10 Gbps|2|

Example:

```text
Path A:

SW2 ── 1G ── SW1
Cost = 4

Path B:

SW2 ── 100M ── SW3 ── 1G ── SW1
Cost = 19 + 4
     = 23
```

STP prefers:

```text
Path A = 4
```

because:

```text
4 < 23
```

You can influence the cost for a specific VLAN:

```text
interface Gi0/23
 spanning-tree vlan 10 cost 19
```

---

# 3.6 Classic PVST+ Port States

PVST+ follows classic 802.1D STP state behavior.

|State|Forwards User Data|Learns MAC Addresses|
|---|---|---|
|Blocking|No|No|
|Listening|No|No|
|Learning|No|Yes|
|Forwarding|Yes|Yes|

### Timers

Default classic STP timers:

```text
Hello Time     = 2 seconds
Forward Delay  = 15 seconds
Max Age        = 20 seconds
```

The classic transition is conceptually:

```text
Blocking
   ↓
Listening
   ↓
Learning
   ↓
Forwarding
```

The **20-second Max Age is not simply a "Blocking timer."**

Max Age controls how long received BPDU information is considered valid before  
the switch can age it out.

Forward Delay controls the time spent in:

```text
Listening = 15 s
Learning  = 15 s
```

Therefore, the commonly quoted worst-case calculation is:

```text
20 + 15 + 15 ≈ 50 seconds
```

but actual convergence depends on the topology and event.

> **Exam focus:** Classic PVST+ is slow because it relies on 802.1D timers;  
> Rapid PVST+ uses RSTP mechanisms to converge much faster.

---

# 3.7 Topology Changes

Classic STP uses **Topology Change Notification (TCN)** BPDUs.

A switch detecting a topology change can notify the root bridge using a  
TCN BPDU.

The root then signals the topology change to the rest of the STP domain.

A topology change causes switches to temporarily reduce MAC address aging so  
that stale Layer 2 entries are removed more quickly.

### Mental Model

```text
Topology change
      ↓
TCN toward root
      ↓
Root acknowledges / propagates TC information
      ↓
MAC aging behavior temporarily changes
      ↓
Stale MAC entries are removed faster
```

# 4. Per-VLAN Load Balancing

One of PVST+'s major advantages is that different VLANs can have different  
root bridges.

Example:

```text
             SW1
          Root VLAN 10
          Root VLAN 20
             /   \
            /     \
           /       \
         SW2-------SW3

             SW2
          Root VLAN 30
          Root VLAN 40
```

Possible forwarding:

```text
VLAN 10/20:
    SW2 → SW1
    SW3 → SW1

VLAN 30/40:
    SW2 → SW3
    SW1 → SW3
```

Another simple dual-uplink example:

```text
Switch A = Root for VLANs 10,20
Switch B = Root for VLANs 30,40

             +---------+
             | Access  |
             | Switch  |
             +---------+
               /     \
              /       \
        Gi0/23         Gi0/24
           /             \
          /               \
       Switch A         Switch B
```

Result:

```text
Gi0/23:
  VLAN 10 → Forwarding
  VLAN 20 → Forwarding
  VLAN 30 → Blocking
  VLAN 40 → Blocking

Gi0/24:
  VLAN 10 → Blocking
  VLAN 20 → Blocking
  VLAN 30 → Forwarding
  VLAN 40 → Forwarding
```

Thus both physical uplinks can carry useful traffic.

> **PVST+ = redundancy + per-VLAN path selection.**

# 5. Protection Features

PVST+ works with several STP protection mechanisms.

|Feature|Purpose|Typical Use|
|---|---|---|
|**PortFast**|Allows an edge port to transition rapidly toward forwarding|End-host ports|
|**BPDU Guard**|Err-disables a PortFast/edge port if a BPDU is received|User-facing ports|
|**Root Guard**|Prevents a port from accepting a superior BPDU and becoming a path toward an unexpected root|Downstream/uplink boundaries|
|**Loop Guard**|Places a port into loop-inconsistent state when expected BPDUs stop arriving|Redundant STP paths|
|**BPDU Filter**|Suppresses BPDUs; potentially dangerous if misused|Specialized cases|

### PortFast + BPDU Guard

Typical access-port protection:

```text
interface Gi0/1
 spanning-tree portfast
 spanning-tree bpduguard enable
```

Conceptually:

```text
End host
   │
   │
PortFast + BPDU Guard
   │
Switch
```

If another switch is accidentally connected:

```text
BPDU received
      ↓
BPDU Guard
      ↓
Err-disabled
```

---

# 5.1 Root Guard vs Loop Guard

This is a common CCNP exam distinction.

### Root Guard

Protects **root placement**.

```text
Unexpected superior BPDU
        ↓
Root Guard
        ↓
Root-inconsistent
```

Think:

> **"Do not let this side become a path toward a new root."**

### Loop Guard

Protects against a failure where expected BPDUs stop arriving and a  
previously non-forwarding port might incorrectly transition toward forwarding.

```text
Expected BPDU disappears
        ↓
Loop Guard
        ↓
Loop-inconsistent
        ↓
Prevents potential loop
```

Think:

> **"Do not let missing BPDUs accidentally create a loop."**

# 6. PVST+, Rapid PVST+, and MST

|Feature|PVST+|Rapid PVST+|MST|
|---|---|---|---|
|STP logic|802.1D|RSTP|RSTP|
|Instances|**1 per VLAN**|**1 per VLAN**|**1 per instance/group of VLANs**|
|Convergence|Slow|Fast|Fast|
|Per-VLAN topology|Yes|Yes|VLANs mapped to instances|
|Scale|Lower|Lower|**Better**|
|Cisco proprietary|Yes|Yes|Based on IEEE 802.1s|
|Typical use|Legacy/specific environments|Common Cisco campus|Large VLAN environments|

### Key Relationship

```text
PVST+
  │
  └── 802.1D per VLAN

Rapid PVST+
  │
  └── RSTP per VLAN

MST
  │
  └── RSTP instances
        └── Multiple VLANs mapped to one instance
```

---

# 6.1 Why MST Scales Better

Suppose a network has:

```text
500 VLANs
```

PVST+/Rapid PVST+ conceptually maintains:

```text
500 STP instances
```

MST can instead map those VLANs into a much smaller number of instances:

```text
VLANs 1–100   → MST Instance 1
VLANs 101–200 → MST Instance 2
VLANs 201–500 → MST Instance 3
```

This reduces the number of independent spanning-tree calculations.

> **Mental model:**  
> **PVST+/Rapid PVST+ = VLAN-centric**  
> **MST = instance-centric**

---

# 6.2 PVST+ / Rapid PVST+ ↔ MST Interoperability

At an MST boundary, the MST region presents its **Common and Internal  
Spanning Tree (CIST)** toward an external STP domain.

PVST+/Rapid PVST+ uses its per-VLAN trees, while the MST region represents  
the external boundary using the CIST.

Cisco performs the required interoperability processing at the boundary.

Important MST configuration parameters include:

```text
Region Name
Revision Number
VLAN-to-Instance Mapping
```

These must match between switches that are intended to belong to the same  
MST region.

> **Exam trap:** A change to the MST region name, revision, or VLAN mapping  
> can cause switches to become separate MST regions.

# 7. Configuration

## 7.1 Enable Classic PVST+

```cisco
spanning-tree mode pvst
```

For Rapid PVST+:

```cisco
spanning-tree mode rapid-pvst
```

> Modern Cisco Catalyst platforms commonly use Rapid PVST+ as the default  
> STP mode. Verify the platform/version before assuming the default.

---

## 7.2 Configure a VLAN Root

Explicit priority:

```cisco
spanning-tree vlan 10 priority 4096
```

Another VLAN can use the same switch or a different switch as root:

```cisco
spanning-tree vlan 20 priority 4096
```

Using the root macro:

```cisco
spanning-tree vlan 10 root primary
```

Backup root:

```cisco
spanning-tree vlan 10 root secondary
```

The exact priority chosen by the root macros depends on the existing  
spanning-tree topology and priorities.

---

## 7.3 Configure Per-VLAN Path Cost

```cisco
interface Gi0/23
 spanning-tree vlan 10 cost 19
```

This changes the STP cost for VLAN 10 on that interface.

---

## 7.4 PortFast + BPDU Guard

```cisco
interface Gi0/1
 spanning-tree portfast
 spanning-tree bpduguard enable
```

Or, on platforms supporting the combined syntax:

```cisco
interface Gi0/1
 spanning-tree portfast bpduguard
```

Use this only on appropriate **edge/access ports**.

# 9. Troubleshooting

|Symptom|Possible Cause|Check|
|---|---|---|
|All VLANs use one uplink|Root placement not designed for load balancing|`show spanning-tree vlan X`|
|One VLAN has unexpected path|Per-VLAN root/cost differs|Check root and path cost|
|Unexpected root bridge|Priority/MAC election|`show spanning-tree vlan X`|
|Native VLAN inconsistency|Native VLAN mismatch|`show interfaces trunk`|
|Port becomes root-inconsistent|Root Guard received superior BPDU|`show spanning-tree inconsistentports`|
|Port becomes loop-inconsistent|Loop Guard detected missing BPDUs|`show spanning-tree inconsistentports`|
|Port becomes err-disabled|BPDU Guard received a BPDU|`show interfaces status`|
|Slow STP convergence|Classic PVST+ / 802.1D|`show spanning-tree summary`|
|Redundant link not forwarding|Normal STP loop prevention|Check port role/state|
|VLAN path not using expected uplink|Wrong root or higher path cost|Check root/cost per VLAN|

# 11. Exam Traps

### Trap 1 — PVST+ vs Rapid PVST+

```text
PVST+        = 802.1D per VLAN
Rapid PVST+  = RSTP per VLAN
```

Do not treat the two names as interchangeable.

---

### Trap 2 — One root for the whole switch

Wrong:

```text
PVST+ has one root for all VLANs.
```

Correct:

```text
PVST+ elects a root bridge independently for each VLAN.
```

---

### Trap 3 — Same port role for every VLAN

Wrong:

```text
Gi0/1 is blocking.
```

Correct:

```text
Gi0/1 may be:
  Forwarding for VLAN 10
  Blocking for VLAN 20
```

STP roles and states are **per VLAN**.

---

### Trap 4 — Root bridge has a Root Port

Wrong:

```text
Root bridge → Root Port
```

Correct:

```text
Root bridge → No Root Port
```

The root bridge's active ports are Designated Ports.

---

### Trap 5 — Bridge ID priority

Remember:

```text
Effective priority = configured priority + VLAN ID
```

Example:

```text
4096 + VLAN 10
= 4106
```

Configurable priorities use multiples of:

```text
4096
```

---

### Trap 6 — Native VLAN BPDU oversimplification

Do not memorize:

```text
"Only native VLAN BPDUs are untagged."
```

PVST+ has special **VLAN 1/CST interoperability behavior**.

The safer exam rule is:

```text
Non-native PVST+ VLANs → tagged
Native VLAN → untagged
VLAN 1/CST → special IEEE interoperability handling
```

Cisco specifically documents this distinction.

---

### Trap 7 — Root Guard vs Loop Guard

```text
Root Guard
    ↓
Protects root placement

Loop Guard
    ↓
Protects against loops caused by missing BPDUs
```

---

### Trap 8 — PortFast

PortFast is for **edge ports connected to end devices**.

It does not mean:

```text
"Disable STP."
```

STP still exists; PortFast changes how an edge port transitions.

---

### Trap 9 — PVST+ scalability

If you have:

```text
500 VLANs
```

PVST+/Rapid PVST+ can involve:

```text
500 STP instances
```

MST reduces this by mapping multiple VLANs to fewer STP instances.

# 13. Final CCNP Takeaway

```text
PVST+
│
├── 1 STP instance per VLAN
│
├── Each VLAN elects its own root
│
├── Each VLAN builds its own loop-free topology
│
├── Different VLANs can use different paths
│
├── Therefore → per-VLAN load balancing
│
├── Uses classic 802.1D mechanics
│
├── Therefore → slower convergence
│
├── Rapid PVST+ fixes the convergence model
│
└── MST reduces the number of STP instances
```

> **One sentence to remember:**
> 
> **PVST+ runs a separate 802.1D spanning-tree instance for each VLAN, allowing  
> each VLAN to elect its own root and forwarding topology, but at the cost of  
> slower convergence and more STP instances.**
