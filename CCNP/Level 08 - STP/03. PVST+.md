# PVST+ (Per-VLAN Spanning Tree +)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PVST+** runs **one Spanning Tree instance per VLAN** over 802.1Q trunks (Cisco).
Each VLAN elects its own **root and blocking decisions**, enabling **per-VLAN load
balancing** across redundant uplinks and per-VLAN tuning. The protocol logic is classic
**IEEE 802.1D** — slower convergence — so modern IOS defaults to **Rapid PVST+**
(RSTP mechanics, same one-instance-per-VLAN model).

---

## 2. Core Concepts

### 2.1 One Spanning Tree instance per VLAN
- Every VLAN has its own STP instance: its own **root bridge, Hello/timers, path cost,
  port roles, and blocking/forwarding map**.
- A single physical port can be **Forwarding in VLAN 10 but Blocking in VLAN 20** —
  this is exactly what enables path diversity.
- BPDUs are generated/processed **per VLAN** (the switch maintains N independent STP
  state machines).

### 2.2 How to carry per-VLAN info over an 802.1Q trunk
- On a trunk, PVST+ must distinguish which BPDU belongs to which VLAN:
  - **Non-native VLAN BPDUs** → **tagged** (carry the 802.1Q tag with that VLAN).
  - **Native VLAN BPDUs** → **untagged** (the native VLAN is untagged on the trunk).
- This is the precise statement: *PVST+ sends non-native VLAN BPDUs tagged; native
  VLAN BPDUs untagged.* Do not say "all BPDUs are tagged."
- The native VLAN must match on both ends, or per-VLAN STP association breaks.

### 2.3 PVST+ vs classic 802.1D (comparison)

| | Classic 802.1D | PVST+ |
|--|----------------|-------|
| Instances | 1 (all VLANs) | **1 per VLAN** |
| Traffic paths | all VLANs same tree | per-VLAN choices |
| Root bridge | global | per-VLAN selectable |
| BPDU on trunk | untagged/native only | native untagged, others tagged |
| Load balancing | no | **yes** |
| Protocol logic | 802.1D | 802.1D (per VLAN) |
| Cisco default today | — | Rapid PVST+ |

### 2.4 Extended System ID & the Bridge ID
- The **Bridge ID** is 8 bytes = **2-byte priority field + 6-byte system MAC**.
- To keep per-VLAN roots unique, **12 bits of the priority field are taken by the
  extended system ID (the VLAN number)**.
- Effective Bridge ID priority = **612 (VLAN_frag)**, computed as:
  ```
  bridge priority (config) + VLAN ID
  example: spanning-tree vlan 10 priority 4096
           -> effective priority portion = 4096 + 10 = 4106
  ```
- Because 12 bits are consumed, the **configurable priority steps are multiples of
  4096**: `0, 4096, 8192, 12288, …, 61440` (default 32768).
- Two VLANs can never collide: VLAN 10 prio 4096 → 4106; VLAN 20 prio 4096 → 4116.

### 2.5 Root Bridge election (lowest Bridge ID)
Per VLAN, elect the root by **lowest effective Bridge ID**:
1. Lowest **Bridge priority** (+ extended sys ID / VLAN).
2. Then lowest **system MAC address** (tie-break).

Place the intended root with a low priority (`priority 4096` or `root primary`).

## 3. How a port is selected — Root, Designated, Alternate

### 3.1 The decision criteria (per VLAN, in order)
For each switch/port, STP resolves the tree using, in sequence:
1. **Lowest Root Bridge ID** (who is the root).
2. **Lowest Root Path Cost** (cost of the best path to the root).
3. **Lowest Sender Bridge ID** (which switch is sending the better BPDU).
4. **Lowest Sender Port ID / Port Priority** (which port on that switch).

### 3.2 The three port roles

| Role | Meaning | On which switch |
|------|---------|-----------------|
| **Root Port (RP)** | best path toward the root (one per non-root switch) | every non-root switch (per VLAN) |
| **Designated Port (DP)** | the port that serves its segment (one per segment) | root bridge or the best switch on that segment |
| **Blocked / Non-designated (incl. Alternate)** | loop-free backup, Discarding | worst path on the segment |
| **Disabled** | admin-shut / physical down | any |

- The **root bridge** has **no root port** — all its ports are Designated (Forwarding).
- In PVST+ (802.1D) the blocked port is just "blocking"; the term **Alternate** is the
  RSTP role for the ready backup. With Rapid PVST+ (RSTP per VLAN) it appears as Alternate.

### 3.3 Root path cost (per-VLAN)
- Cisco/reference costs: **100 Mbps = 19, 1 Gbps = 4, 10 Gbps = 2**.
- Lower cost path to root wins; the runner-up path becomes the blocked/alternate port.
- You can influence it: `spanning-tree vlan 10 cost <n>` on an interface.

### 3.4 Classic 802.1D port states & timers (PVST+ convergence)

| State | Sends user data | Learns MACs | Time in 802.1D |
|-------|-----------------|-------------|----------------|
| Blocking | no | no | 20 s max-age (if no better BPDU) |
| Listening | no | no | **15 s** (forward delay) |
| Learning | no | yes | **15 s** (forward delay) |
| Forwarding | yes | yes | steady state |

- **Timers**: Hello **2 s**; Forward Delay **15 s**; Max Age **20 s**.
- Rough worst-case reconvergence ≈ **20 + 15 + 15 = 50 s**, **BUT** there is timer
  overlap — do **not** memorize an absolute number. The exam wants the conceptual
  "classic STP is slow; RSTP fast" idea plus exact timer values.
- **TCN (Topology Change Notification)**: a classic-STP switch detecting a topology
  change sends a TCN BPDU toward the root; the root sets the TCN bit in its BPDUs so
  all switches shorten MAC aging to ~15 s (topology-change growth window).

### 3.5 Load-balancing example (per-VLAN roots)
```
Switch A = root for VLANs 10, 20
Switch B = root for VLANs 30, 40
Uplink Gi0/23: Forwarding 10,20 / Blocking 30,40
Uplink Gi0/24: Forwarding 30,40 / Blocking 10,20
```
→ Both trunks carry traffic (the two big selling points of PVST+): **redundant +
  bandwidth efficient**.

## 4. Protection features (interaction with PVST+)

| Feature | What it does | When used (per VLAN) |
|---------|--------------|----------------------|
| **PortFast** | edge ports skip to Forwarding instantly | access/endpoint ports |
| **BPDU Guard** | any BPDU on a PortFast port → errdisabled | with PortFast on edges |
| **Root Guard** | port ignoring superior BPDUs → root-inconsistent | uplinks where root must not appear |
| **Loop Guard** | missing BPDUs on blocking port → loop-inconsistent | blocking/redundant uplinks |
| **BPDU Filter** | ignore BPDUs entirely (risky) | advanced, rarely ports |

These features run on the per-VLAN instances — you can enable per-VLAN
(`spanning-tree vlan 10 portfast`, etc.) or globally. See Level 08 notes 10–13.

## 5. PVST+, Rapid PVST+, MST — interaction

| | PVST+ | Rapid PVST+ | MST (802.1s) |
|--|-------|-------------|--------------|
| Logic | 802.1D | RSTP | RSTP |
| Instances | 1 per VLAN | 1 per VLAN | few (VLAN groups) |
| Speed | slow | fast | fast |
| Scale | CPU grows with VLANs | CPU grows with VLANs | best at huge scale |
| Interop | Cisco | Cisco | standard / cross-vendor |
| Boundary to MST | acts as one PVST+ instance per VLAN | acts as one PVST+ instance per VLAN | region → one bridge outside |

- **PVST+/Rapid-PVST+ ↔ MST**: at a **region boundary**, an MST switch presents a single
  Common/Internal Spanning Tree (CIST) instance to PVST+ neighbors, and conversely the
  PVST+ neighbor's per-VLAN trees are collapsed/mapped where needed. Cisco translates
  this automatically; a mismatch in region name/revision/mapping is a fault.
- **Interoperability note**: PVST+ is Cisco-per-VLAN over any IEEE trunk; MST is the
  standards-based multi-instance option that interoperates across vendors — choose MST
  where you must merge Cisco with third-party switches at scale.

## 6. Configuration / Commands

```text
spanning-tree mode pvst                ! classic per-VLAN (Rapid: rapid-pvst)
! Root control per VLAN
spanning-tree vlan 10 priority 4096    ! effective = 4096 + 10 = 4106
spanning-tree vlan 20 root primary     ! macro: sets 24576 (or 4096 if lower)
spanning-tree vlan 30 root secondary   ! macro: backup 28672

! Influence path cost per VLAN on an interface
interface Gi0/23
 spanning-tree vlan 10 cost 19

! Per-VLAN protection
spanning-tree vlan 10 priority? (already)
interface Gi0/1
 spanning-tree portfast bpduguard enable

! Verify
show spanning-tree summary
show spanning-tree vlan 10              ! read Root ID / Bridge / Role / State
show spanning-tree vlan 20 bridge
show spanning-tree active | include "VLAN|Root|Role|State"
show spanning-tree interface Gi0/23 vlan 10
```

## 7. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| All VLANs cross one trunk | wrong per-VLAN root (both roots on same switch) | `show spanning-tree vlan X root` |
| One VLAN totally dark | native VLAN mismatch or that instance blocked | `show interfaces trunk`, native match |
| Unexpected root / flapping | a switch elected root by MAC, or `root primary` not applied | check priority/MAC; set macro |
| Port keeps going Forwarding then blocking | Root Guard hitting a "better" BPDU | `show spanning-tree inconsistentports` |
| Loop appears despite redundant links | Loop Guard not enabled on blocking path; PortFast on a trunk | `show spanning-tree summary \| include Guard` |
| Very slow convergence | classic PVST+ (802.1D) instead of Rapid | set `spanning-tree mode rapid-pvst` |
| BPDU Guard port errdisabled | rogue switch BPDU on an edge port | `show interfaces status \| include err-disab` |

## 8. Exam Traps

- **PVST+ ≠ Rapid PVST+** — PVST+ = 802.1D (slow), Rapid PVST+ = RSTP (fast). The single
  biggest trap name.
- **BPDU statement** — "native VLAN, BPDUs untagged; non-native VLAN, BPDUs tagged."
  Not "all tagged."
- **Extended System ID** — 12 bits of the priority field hold the VLAN;
  configurable priority only as **multiples of 4096** (4106 for VLAN 10 @ 4096).
- **Root = lowest Bridge ID** (priority then MAC). Root has **no root port**.
- **Port selection order**: Root Bridge ID → Root Path Cost → Sender Bridge ID →
  Sender Port ID.
- **Timers**: Hello 2 s, MaxAge 20 s, FwdDelay 15 s; don't quote absolute convergence.
- **PortFast + BPDU Guard** is the correct edge-port answer; **Root Guard** protects
  root placement; **Loop Guard** protects against silent uni-directional loss.
- **Many instances = CPU/BPDU cost** → large VLAN fleets: MST (note 05).
