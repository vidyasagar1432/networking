# EtherChannel — Static (ON)

> **Level 08 · STP / EtherChannel** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Static EtherChannel (`mode on`)** bundles multiple physical interfaces into one logical  
**Port-channel without using LACP or PAgP negotiation**.

The switch is manually configured to treat the specified interfaces as one EtherChannel.

```text
Physical Links
     │
     ├── Gi0/1
     └── Gi0/2
          ↓
     Static EtherChannel
          ↓
       Po1
```

There are:

```text
No LACP PDUs
No PAgP PDUs
No negotiation
```

Because there is no negotiation, **both ends must be configured consistently**.

> **Modern best practice:** Use **LACP** when supported.  
> Static `on` is mainly useful when the peer cannot or should not use LACP/PAgP.

---

# 2. Core Concepts

## 2.1 EtherChannel Methods

| Method        | Protocol               | Negotiation | Modes            |
| ------------- | ---------------------- | ----------- | ---------------- |
| **Static ON** | None                   | ❌ No        | `on`             |
| **LACP**      | IEEE 802.3ad / 802.1AX | ✅ Yes       | active / passive |
| **PAgP**      | Cisco proprietary      | ✅ Yes       | desirable / auto |

### Mental Model

```text
STATIC
└── on
     └── No negotiation

LACP
├── active
└── passive
     └── LACP negotiation

PAgP
├── desirable
└── auto
     └── PAgP negotiation
```

---

# 3. Static `ON` Mode

The configuration:

```cisco
channel-group 1 mode on
```

means:

```text
Create/use EtherChannel 1
        ↓
Do NOT negotiate
        ↓
Treat configured member ports as one bundle
```

There is no requirement for an `active`, `passive`, `desirable`, or `auto` state.

---

# 4. Both Ends Must Match

For a static EtherChannel:

```text
ON + ON = Static EtherChannel
```

But:

```text
ON + LACP     = ❌
ON + PAgP     = ❌
```

A static EtherChannel has no protocol with which to negotiate compatibility.

### Correct

```text
SW1                     SW2

Gi0/1 ──────── Gi0/1
Gi0/2 ──────── Gi0/2
  │              │
  └── Po1 ───── Po1
       ON          ON
```

### Incorrect

```text
SW1                     SW2

Po1 = ON                Po1 = LACP
       │
       ✗
```

# 5. Configuration

### SW1

```cisco
interface range GigabitEthernet0/1 - 2
 channel-group 1 mode on

interface Port-channel1
 description Static EtherChannel to SW2
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

### SW2

```cisco
interface range GigabitEthernet0/1 - 2
 channel-group 1 mode on

interface Port-channel1
 description Static EtherChannel to SW1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

The resulting topology is:

```text
             SW1
          ┌─────────┐
          │         │
        Gi0/1     Gi0/2
          │         │
          │         │
        Gi0/1     Gi0/2
          │         │
          └─────────┘
             SW2

        Physical Links
              ↓
         Port-channel1
              ↓
       One logical link
```

---

# 6. No Negotiation

Unlike LACP and PAgP:

```text
Static ON
    │
    ├── No LACP PDUs
    ├── No PAgP PDUs
    └── No negotiation
```

The switch relies entirely on the administrator's configuration.

This makes static EtherChannel simple, but it also removes the protocol's ability to  
detect an incompatible peer configuration through negotiation.

---

# 7. When to Use Static `ON`

Static EtherChannel can make sense when:

### 7.1 Peer Does Not Support LACP/PAgP

Some devices may support link aggregation but not the protocol you want to use.

```text
Cisco Switch
     │
     │ Static EtherChannel
     ↓
Device with no LACP/PAgP
```

### 7.2 Explicit No-Negotiation Requirement

Some environments may intentionally require a manually configured, non-negotiated bundle.

### 7.3 Lab / Learning Environment

Static EtherChannel is useful for understanding the difference between:

```text
Negotiated EtherChannel
        vs
Static EtherChannel
```

### Important

For normal modern switch-to-switch deployments:

> **Prefer LACP when the peer supports it.**

---

# 8. Member Consistency

Static EtherChannel still requires compatible member interfaces.

Common requirements include:

- Compatible speed
    
- Compatible duplex
    
- Same switchport mode
    
- Same access VLAN when operating as access
    
- Compatible trunk configuration
    
- Same native VLAN where applicable
    
- Same allowed VLANs where applicable
    
- Compatible Layer-3 configuration for Layer-3 EtherChannel
    
- Same EtherChannel grouping
    

Example:

```text
Gi0/1 ──┐
        │
Gi0/2 ──┼── Port-channel1
        │
Gi0/3 ──┘
```

The member ports must have compatible characteristics.

> Exact compatibility checks are platform and configuration dependent.

---

# 9. Static EtherChannel and STP

When the EtherChannel is correctly formed:

```text
Gi0/1 ─┐
       ├── Port-channel1 ── STP
Gi0/2 ─┘
```

STP sees:

```text
ONE logical port
```

rather than treating the individual member links as separate parallel STP paths.

### CCNP Mental Model

```text
Physical Links
      ↓
Static EtherChannel
      ↓
Port-channel
      ↓
STP sees ONE logical port
```

### Important

The **one-STP-port behavior depends on the EtherChannel being correctly formed**.

A configuration problem can prevent the intended bundle from forming and may result in  
connectivity problems, blocked links, or, in an incorrectly designed topology, a  
Layer-2 loop.

> Never assume that configuring `mode on` automatically makes an unsafe topology safe.

---

# 10. Load Balancing

Static EtherChannel uses the same general EtherChannel load-balancing mechanism as  
LACP and PAgP.

Example:

```cisco
port-channel load-balance src-dst-ip
```

Verify:

```cisco
show etherchannel load-balance
```

The switch uses a hash to select a physical member.

```text
Flow A ──→ Gi0/1
Flow B ──→ Gi0/2
Flow C ──→ Gi0/1
Flow D ──→ Gi0/2
```

### Important

EtherChannel provides **aggregate bandwidth** across multiple flows.

It does not normally combine all member links into one larger pipe for a single flow.

```text
4 × 1-Gbps members
        ↓
≈ 4-Gbps aggregate

One flow
        ↓
Typically one member
```

# 11. Verification

### EtherChannel Summary

```cisco
show etherchannel summary
```

This is the primary command for quickly checking bundle status.

Typical flags include:

```text
S = Layer-2 EtherChannel
U = In use
P = Port is bundled
```

For example:

```text
SU
```

means:

```text
S → Layer-2 EtherChannel
U → In use
```

And:

```text
P
```

means the member is:

```text
Bundled in the port-channel
```

> **Exam trap:** `P` does **not** mean PAgP.  
> It means the interface is successfully **bundled**.

# 12. Troubleshooting

|Symptom|Likely Cause|Fix|
|---|---|---|
|Member not bundled|Member configuration mismatch|Compare member configuration|
|Bundle does not form|Incompatible physical/configuration parameters|Align both sides|
|`ON` ↔ LACP|Protocol/mode mismatch|Configure both sides consistently|
|`ON` ↔ PAgP|Protocol/mode mismatch|Configure both sides consistently|
|STP blocks unexpected path|EtherChannel not formed as intended|Verify `show etherchannel summary`|
|Traffic is uneven|Hash distribution|Check load-balancing method|
|No traffic through bundle|Port-channel/configuration problem|Check Port-channel and member state|
|Loop after adding links|Incorrect EtherChannel configuration/topology|Verify both ends and STP state|

---

# 13. Troubleshooting Workflow

```text
1. Check physical interfaces
        ↓
2. Verify both sides use STATIC `on`
        ↓
3. Check EtherChannel summary
        ↓
   show etherchannel summary
        ↓
4. Check member consistency
        ↓
   speed / duplex / VLAN / trunk
        ↓
5. Check Port-channel state
        ↓
   show interfaces port-channel 1
        ↓
6. Check STP
        ↓
   show spanning-tree
        ↓
7. Check load balancing
        ↓
   show etherchannel load-balance
```

# 14. Static ON vs LACP vs PAgP

|Feature|Static `ON`|LACP|PAgP|
|---|---|---|---|
|Negotiation|❌ No|✅ Yes|✅ Yes|
|Protocol|None|IEEE|Cisco proprietary|
|Modes|`on`|active / passive|desirable / auto|
|PDUs|None|LACP|PAgP|
|Multi-vendor|Depends on static support/configuration|✅ Yes|❌ No|
|Failure detection through negotiation|❌ No|✅ Yes|✅ Yes|
|Modern recommendation|Special cases|**Preferred**|Legacy|
|Configuration|Manual|Negotiated|Negotiated|

### Simple Comparison

```text
STATIC ON
│
├── No protocol
├── No negotiation
└── Both sides manually configured

LACP
│
├── IEEE standard
├── active / passive
└── Negotiation

PAgP
│
├── Cisco proprietary
├── desirable / auto
└── Negotiation
```

# 15. Exam Traps

### Trap 1 — `ON` Means No Negotiation

```text
mode on
   ↓
No LACP
No PAgP
No negotiation
```

---

### Trap 2 — Both Ends Must Be `ON`

```text
ON + ON       = Static bundle
ON + LACP     = ❌
ON + PAgP     = ❌
```

---

### Trap 3 — LACP Is Usually Preferred

If the question asks for the **preferred modern EtherChannel protocol**:

```text
LACP
```

Why?

```text
IEEE standard
     ↓
Multi-vendor support
     ↓
Negotiation
     ↓
Better operational safety
```

---

### Trap 4 — `P` Does Not Mean PAgP

In:

```cisco
show etherchannel summary
```

`P` means:

```text
Bundled
```

It does not mean:

```text
PAgP
```

---

### Trap 5 — Static EtherChannel Still Requires Consistency

`mode on` does not bypass EtherChannel compatibility requirements.

You still need compatible:

```text
Speed
Duplex
VLAN
Trunk
Switchport mode
Layer-3 configuration
```

where applicable.

---

### Trap 6 — STP Sees One Port Only When the Bundle Is Correctly Formed

Correct:

```text
Gi0/1 ─┐
       ├── Po1 ── STP
Gi0/2 ─┘
```

Incorrectly configured EtherChannel:

```text
Physical links
      ↓
Bundle problem
      ↓
Potential blocking / connectivity issue / loop risk
```

# 18. One-Minute Revision

> **Static `ON` = EtherChannel without negotiation.**

Remember:

```text
1. `mode on` = NO LACP and NO PAgP
2. Both ends must be configured consistently
3. Member interfaces must have compatible configuration
4. No negotiation means less protection against configuration mistakes
5. Correctly formed EtherChannel appears as ONE logical STP port
6. LACP is preferred for modern deployments
```

### Most Important CCNP Rule

```text
ON + ON       = STATIC ETHERCHANNEL
ON + LACP     = NO NEGOTIATED BUNDLE
ON + PAgP     = NO NEGOTIATED BUNDLE

LACP          = MODERN IEEE STANDARD
PAgP          = CISCO PROPRIETARY
ON            = STATIC / NO NEGOTIATION
```
