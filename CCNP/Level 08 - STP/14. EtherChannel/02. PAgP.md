# EtherChannel — PAgP

> **Level 08 · STP / EtherChannel** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PAgP (Port Aggregation Protocol)** is Cisco's **proprietary EtherChannel negotiation  
protocol**. It dynamically negotiates multiple physical interfaces into one logical  
**Port-Channel**.

PAgP uses the modes:

```text
desirable
auto
```

PAgP is a **legacy Cisco-specific** EtherChannel protocol. **LACP** is the preferred  
modern standard for new deployments because it provides multi-vendor interoperability.

> **CCNP Mental Model**
> 
> ```text
> PAgP
> │
> ├── Cisco Proprietary
> │
> ├── Negotiation
> │     ├── desirable
> │     └── auto
> │
> ├── Port-Channel
> │     └── Multiple physical links → ONE logical link
> │
> ├── Load Balancing
> │     └── Hash selects member per flow
> │
> └── STP
>       └── Sees the bundle as ONE logical port
> ```

---

# 2. Core Concepts

## 2.1 PAgP Modes

PAgP has two negotiation modes:

|Mode|Behavior|Forms bundle with|
|---|---|---|
|**desirable**|Actively attempts to negotiate PAgP|desirable / auto|
|**auto**|Passively waits for PAgP negotiation|desirable only|

### Negotiation Matrix

|Local|Remote|Bundle?|
|---|---|---|
|desirable|desirable|✅ Yes|
|desirable|auto|✅ Yes|
|auto|desirable|✅ Yes|
|auto|auto|❌ No|

### Key Rule

> At least **one side must be `desirable`**.

```text
desirable + desirable = YES
desirable + auto      = YES
auto + desirable      = YES
auto + auto           = NO
```

`auto + auto` fails because neither side actively initiates PAgP negotiation.

# 3. PAgP vs LACP

|Feature|PAgP|LACP|
|---|---|---|
|Vendor|Cisco proprietary|IEEE standard|
|Standard|None|IEEE 802.3ad / 802.1AX|
|Modes|desirable / auto|active / passive|
|Negotiation|Yes|Yes|
|Protocol|PAgP|LACP|
|Multi-vendor|❌ No|✅ Yes|
|Modern choice|Legacy|Preferred|
|EtherChannel|Yes|Yes|

### Exam Rule

```text
PAgP = Cisco proprietary
LACP = IEEE standard
```

If the question asks:

> **Which EtherChannel negotiation protocol is Cisco proprietary?**

Answer:

> **PAgP**

If the question asks:

> **Which protocol should be preferred for multi-vendor EtherChannel?**

Answer:

> **LACP**

# 4. PAgP Configuration

### Basic Configuration

```cisco
interface GigabitEthernet0/1
 channel-group 1 mode desirable

interface GigabitEthernet0/2
 channel-group 1 mode desirable

interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

The command:

```cisco
channel-group 1 mode desirable
```

does two things:

```text
Physical interface
       ↓
EtherChannel 1
       ↓
PAgP desirable mode
```

The resulting logical interface is:

```text
Port-channel1
```

---

# 5. Example: PAgP Between Two Switches

### SW1

```cisco
interface range GigabitEthernet0/1 - 2
 channel-group 1 mode desirable

interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

### SW2

```cisco
interface range GigabitEthernet0/1 - 2
 channel-group 1 mode auto

interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

This forms because:

```text
SW1 desirable
      ↓
PAgP negotiation
      ↓
SW2 auto
      ↓
Port-channel1
```

# 6. Static `on` Mode

`on` is **not a PAgP mode**.

```cisco
channel-group 1 mode on
```

creates a **static EtherChannel without negotiation**.

```text
PAgP
├── desirable
└── auto

Static EtherChannel
└── on
```

For a static EtherChannel:

```text
on ↔ on = YES
on ↔ desirable = NO
on ↔ auto = NO
```

> Do not mix PAgP/LACP negotiation modes with `on`.

---

# 7. PAgP and Cisco Interoperability

PAgP is Cisco proprietary.

Therefore:

```text
Cisco Switch
     │
     │ PAgP
     ↓
Cisco Switch
     ✓
```

But:

```text
Cisco Switch
     │
     │ PAgP
     ↓
Non-Cisco Switch
     ✗
```

For a multi-vendor EtherChannel, use:

```text
LACP
```

or, when appropriate:

```text
Static EtherChannel
```

# 8. EtherChannel Member Consistency

PAgP does not remove the requirement for compatible member interfaces.

Common parameters must be compatible, including:

- Speed
    
- Duplex
    
- Switchport mode
    
- Access VLAN
    
- Native VLAN
    
- Allowed VLANs
    
- Trunk configuration
    
- Layer-3 configuration when using a Layer-3 EtherChannel
    
- EtherChannel protocol/mode
    

Example:

```text
Gi0/1 ──┐
        │
Gi0/2 ──┼── Port-channel1
        │
Gi0/3 ──┘
```

The physical interfaces must be suitable members of the same logical bundle.

> Exact compatibility checks are platform and configuration dependent.

# 9. PAgP and Load Balancing

PAgP does **not** determine the EtherChannel traffic hashing algorithm.

Load balancing is configured at the **EtherChannel/platform level**.

Example:

```cisco
port-channel load-balance src-dst-ip
```

Verify:

```cisco
show etherchannel load-balance
```

### Per-Flow Distribution

```text
Flow A ──→ Gi0/1
Flow B ──→ Gi0/2
Flow C ──→ Gi0/1
Flow D ──→ Gi0/2
```

The switch uses a hash based on configured packet fields to select a member.

A single flow generally remains on **one physical member**.

Therefore:

```text
4 × 1-Gbps members
        ↓
≈ 4-Gbps aggregate capacity

One flow
        ↓
typically one 1-Gbps member
```

Multiple flows can be distributed across multiple members.

# 10. PAgP and STP

Once the EtherChannel is successfully formed, STP sees the bundle as **one logical  
bridge port**.

```text
        SW1
       /   \
    Gi0/1  Gi0/2
       \   /
       Po1
        │
        │
       Po1
        │
        SW2
```

STP conceptually sees:

```text
SW1 ───────── Po1 ───────── SW2
```

not:

```text
SW1 ── Gi0/1 ── SW2
SW1 ── Gi0/2 ── SW2
```

### CCNP Mental Model

```text
Physical Links
      ↓
EtherChannel
      ↓
Port-channel
      ↓
STP sees ONE logical port
```

# 11. Verification Commands

### EtherChannel Summary

```cisco
show etherchannel summary
```

This is one of the most important verification commands.

Typical output contains:

```text
SU
```

where:

```text
S = Layer-2 EtherChannel
U = in use
```

A member interface may show:

```text
P
```

`P` means:

> **Port is bundled in the port-channel.**

### Important Exam Correction

Do **not** interpret:

```text
P = PAgP negotiated
```

Instead:

```text
P = bundled in the port-channel
```

The `P` flag by itself does not identify whether the bundle uses PAgP, LACP, or static  
EtherChannel.

# 12. Troubleshooting

|Symptom|Likely Cause|Fix|
|---|---|---|
|`auto + auto` does not form|No side is initiating|Set one side to `desirable`|
|No bundle with non-Cisco peer|PAgP is Cisco proprietary|Use LACP|
|Member is stand-alone|Configuration/protocol mismatch|Check EtherChannel mode and member configuration|
|Member is suspended|Inconsistent member configuration|Compare speed, VLAN, trunk, etc.|
|Trunk does not work|Trunk configuration mismatch|Compare Port-channel/trunk settings|
|Uneven traffic|Hash distribution|Check load-balancing method|
|Members repeatedly join/leave|Physical or configuration problem|Check interface and EtherChannel consistency|
|`on` + PAgP mode|Protocol mismatch|Use `on` on both sides or use PAgP/LACP correctly|

# 15. Exam Traps

### Trap 1 — Auto + Auto

```text
desirable + desirable = YES
desirable + auto      = YES
auto + desirable      = YES
auto + auto           = NO
```

> At least one side must be **desirable**.

---

### Trap 2 — PAgP Is Cisco Proprietary

```text
PAgP = Cisco proprietary
LACP = IEEE standard
```

For modern multi-vendor deployments:

```text
Use LACP
```

---

### Trap 3 — `on` Is Not PAgP

```cisco
channel-group 1 mode on
```

means:

```text
Static EtherChannel
       ↓
No PAgP
No LACP
No negotiation
```

---

### Trap 4 — Do Not Mix Protocols

These are different negotiation protocols:

```text
PAgP
├── desirable
└── auto

LACP
├── active
└── passive
```

Do not expect:

```text
PAgP desirable ↔ LACP active
```

to negotiate a channel.

---

### Trap 5 — `P` Does Not Mean PAgP

In:

```cisco
show etherchannel summary
```

`P` means:

```text
Bundled in the port-channel
```

It does **not** mean:

```text
PAgP negotiated
```

---

### Trap 6 — EtherChannel Does Not Guarantee One Flow Uses All Links

```text
Multiple flows
      ↓
Hashing
      ↓
Multiple members

Single flow
      ↓
Typically one member
```

EtherChannel provides **aggregate bandwidth**, not necessarily the sum of all member  
bandwidth for one individual flow.

# 18. One-Minute Revision

> **PAgP = Cisco-proprietary EtherChannel negotiation.**

Remember these six points:

```text
1. PAgP = Cisco proprietary
2. desirable ↔ desirable = bundle
3. desirable ↔ auto = bundle
4. auto ↔ auto = NO bundle
5. LACP is the modern standard alternative
6. `on` = static EtherChannel, no negotiation
```

### Most Important CCNP Rule

```text
DESIRABLE + DESIRABLE = BUNDLE
DESIRABLE + AUTO      = BUNDLE
AUTO + AUTO           = NO BUNDLE
ON + ON               = STATIC BUNDLE
PAgP + LACP           = NO NEGOTIATION
```
