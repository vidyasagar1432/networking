# EtherChannel — PAgP

> **Level 08 · STP / EtherChannel** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PAgP (Port Aggregation Protocol)** is Cisco's **proprietary** EtherChannel negotiation
(requires a Cisco switch at both ends). It auto-bundles two links with modes
`desirable` / `auto` and is **legacy** — LACP (IEEE standard) is the modern default, but
the mode table still appears on the exam. PAgP links fail to bundle with non-Cisco peers.

---

## 2. Core Concepts

### 2.1 PAgP modes (negotiation matrix)

| Mode | Behavior | Forms bundle with |
|------|----------|-------------------|
| **desirable** | actively solicits | desirable / auto |
| **auto** | passive, responds | desirable only |
| on | static (no PAgP) | on (no negotiation) |

- `desirable ↔ desirable` = YES · `desirable ↔ auto` = YES · `auto ↔ auto` = **NO**.
- At least one side **desirable** is required to bring the channel up.

### 2.2 PAgP vs LACP (the comparison)

| | PAgP | LACP |
|--|------|------|
| Vendor | Cisco proprietary | IEEE 802.3ad / 802.1AX standard |
| Modes | desirable / auto | active / passive |
| PDU | PAgP (Cisco) | LACP (Slow Protocol) |
| Interop | Cisco-only | multi-vendor |
| Today | legacy | default / standard |

- Exam: "which is proprietary?" → **PAgP**.

### 2.3 Configuration

```text
interface GigabitEthernet0/1
 channel-group 1 mode desirable
interface GigabitEthernet0/2
 channel-group 1 mode desirable
interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

- Use `desirable` on at least one side to form automatically.
- Members must still match (speed, duplex, VLANs).

### 2.4 Behavior notes

- PAgP uses Cisco PAgP PDUs toward the peer; misconfig can leave links in a non-bundled
  `I` state.
- Load balancing is **port-channel level** (`port-channel load-balance`), protocol-agnostic
  — hashing behaves the same for PAgP, LACP, or static bundles.
- PAgP learned ports/GAVP behavior: not needed for modern campus (old benefactor of PAgP
  to learn VLANs — not required with VTPv3/manual trunking).

### 2.5 Verification

```text
show etherchannel summary          # SU (in use), P = PAgP negotiated
show etherchannel 1 detail
show pagp counters
show pagp neighbor
show port-channel load-balance
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| No `P` in summary | negotiated mode mismatch / non-Cisco peer | use LACP or `on` with matching side |
| auto+auto silent | no desirable side | set one side desirable |
| Bundle up but no traffic | hash policy biased | change `port-channel load-balance` |
| Members inconsistent | speed/duplex/VLAN drift | align member configs |
| Trunk allowed VLAN mismatch | bundle carries wrong set | compare `switchport trunk allowed` |

---

## 5. Exam Traps

- **PAgP = Cisco-only** — interop with a non-Cisco switch requires LACP (or static).
- **desirable vs auto** — "auto" needs the other side "desirable" (auto+auto = no).
- **Don't mix PAgP with LACP modes** on the same bundle.
- **`on` (static)** is not PAgP negotiation and needs `on` on both ends.
- **Modern recommendation is LACP** — answer "best/best practice" with LACP, not PAgP.
