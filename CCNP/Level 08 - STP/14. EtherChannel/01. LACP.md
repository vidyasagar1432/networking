# EtherChannel — LACP

> **Level 08 · STP / EtherChannel** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**LACP (Link Aggregation Control Protocol)** is the **IEEE-standard** EtherChannel negotiation  
protocol. It was originally defined by **IEEE 802.3ad** and is now specified by  
**IEEE 802.1AX**.

LACP dynamically negotiates multiple physical interfaces into one logical  
**Port-Channel**. The resulting bundle provides increased aggregate bandwidth,  
redundancy, and a single logical Layer-2/Layer-3 interface to protocols such as STP.

> **CCNP Mental Model**
> 
> ```text
> LACP
> │
> ├── Physical Links
> │     ├── Gi0/1
> │     └── Gi0/2
> │
> ├── LACP Negotiation
> │     └── Active ↔ Active/Passive
> │
> ├── Port-Channel
> │     └── One logical interface
> │
> ├── Load Balancing
> │     └── Hash selects one member per flow
> │
> └── STP
>       └── Sees the bundle as ONE logical link
> ```

---

## 2. Core Concepts

### 2.1 LACP Modes

LACP has two negotiation modes:

|Mode|Behavior|Can form with|
|---|---|---|
|**active**|Actively sends LACP PDUs|active / passive|
|**passive**|Waits for LACP PDUs; responds when received|active only|

### Negotiation Matrix

|Local|Remote|Bundle?|
|---|---|---|
|active|active|✅ Yes|
|active|passive|✅ Yes|
|passive|active|✅ Yes|
|passive|passive|❌ No|

**Key rule:**

> At least **one side must be active**.

`passive + passive` does not form an LACP bundle because neither side initiates LACP negotiation.

> **Important:** Cisco `on` is **not an LACP mode**.  
> `on` creates a **static EtherChannel with no negotiation protocol**.

---

## 3. LACP PDU & Identification

LACP uses **LACP PDUs** to exchange information between participating interfaces.

LACP is carried as an IEEE **Slow Protocol** using EtherType:

```text
0x8809
```

### LACP Timing

LACP supports two periodic transmission rates:

|Mode|PDU interval|
|---|--:|
|**Fast**|1 second|
|**Slow**|30 seconds|

Therefore:

> Do **not** memorize LACP as universally "1-second PDUs."  
> **1 second = fast LACP; 30 seconds = slow LACP.**

LACP information includes items such as:

- Actor System ID
    
- Partner System ID
    
- Actor/Partner Key
    
- Port Priority
    
- Port Number
    
- LACP state information
    

---

## 4. LACP System ID & Port Selection

LACP uses a **System ID** to identify the LACP system.

The System ID is based on:

```text
System Priority + System MAC Address
```

Lower **system priority** is preferred when determining the LACP system relationship.

LACP also uses **port priority** when determining which links should be selected when the number of eligible member links exceeds the platform's supported active-member limit.

### Important distinction

```text
System Priority
    ↓
Helps determine LACP system selection

Port Priority
    ↓
Helps select member ports when there are more
eligible links than the active-member limit
```

> Exact active-member limits are **platform-dependent**.  
> Do not memorize a universal "8 active / 16 total" rule for all Cisco platforms.

# 5. Configuration

### Basic LACP Configuration

```cisco
interface GigabitEthernet0/1
 channel-group 1 mode active

interface GigabitEthernet0/2
 channel-group 1 mode active

interface Port-channel1
 description LACP bundle to CORE-A
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

`channel-group 1 mode active`:

- Associates the physical interface with EtherChannel 1
    
- Enables LACP active mode
    
- Creates/binds the logical `Port-channel1` interface
    

### Recommended Configuration Model

Configure the **Port-channel interface** for the common logical configuration:

```cisco
interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

The physical member interfaces should have compatible configuration.

> `switchport trunk encapsulation dot1q` is **platform-dependent**.  
> On platforms where 802.1Q is the only supported trunk encapsulation, the command may not exist.

# 6. Example: Two-Switch LACP Bundle

### SW1

```cisco
interface range GigabitEthernet0/1 - 2
 channel-group 1 mode active

interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

### SW2

```cisco
interface range GigabitEthernet0/1 - 2
 channel-group 1 mode passive

interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

This works because:

```text
SW1 active
      ↓
LACP negotiation
      ↓
SW2 passive
      ↓
Port-channel1 forms
```

# 7. EtherChannel Load Balancing

EtherChannel does **not normally send every packet round-robin across all links**.

Instead, the switch calculates a **hash** from selected packet fields and uses that result to choose a member link.

Possible hash inputs include combinations of:

- Source MAC
    
- Destination MAC
    
- Source + destination MAC
    
- Source IP
    
- Destination IP
    
- Source + destination IP
    
- Layer-4 source/destination ports
    
- Other platform-supported combinations
    

Example:

```cisco
port-channel load-balance src-dst-ip
```

Check the current method:

```cisco
show etherchannel load-balance
```

### Per-Flow Behavior

```text
Flow A ──→ Member Gi0/1
Flow B ──→ Member Gi0/2
Flow C ──→ Member Gi0/1
Flow D ──→ Member Gi0/2
```

A single flow normally remains on **one physical member**.

This prevents packet reordering that could occur if packets from the same flow were constantly moved between links.

### Important

EtherChannel increases **aggregate bandwidth**, but a single flow is generally limited by the bandwidth of **one physical member link**.

For example:

```text
4 × 1-Gbps links

Aggregate capacity ≈ 4 Gbps

One flow
    ↓
typically uses one 1-Gbps member
```

The actual distribution depends on the platform and hashing algorithm.

# 8. EtherChannel Consistency

Member interfaces must have compatible configuration.

Common parameters that must be consistent include:

|Parameter|Requirement|
|---|---|
|Speed|Compatible|
|Duplex|Compatible|
|Switchport mode|Consistent|
|Access VLAN|Consistent when used|
|Native VLAN|Consistent for trunks|
|Allowed VLANs|Consistent|
|Trunk configuration|Consistent|
|Layer-3 configuration|Consistent when using L3 EtherChannel|
|EtherChannel protocol/mode|Must be compatible|

> The exact compatibility checks are **platform and configuration dependent**.

### Best Practice

Configure the logical interface:

```cisco
interface Port-channel1
```

for the common bundle behavior, and avoid unnecessary differences between physical members.

# 9. STP and EtherChannel

STP treats an EtherChannel as **one logical link**.

```text
        SW1
       /   \
    Gi0/1  Gi0/2
       \   /
     Po1
       │
       │
     Po1
       │
      SW2
```

STP does **not** normally see Gi0/1 and Gi0/2 as two independent Layer-2 paths.

Instead:

```text
Gi0/1 ─┐
       ├── Port-channel1 ── STP logical port
Gi0/2 ─┘
```

This prevents STP from blocking individual member links simply because they are parallel physical connections inside the same EtherChannel.

> **CCNP Mental Model**
> 
> ```text
> Physical Links
>       ↓
> EtherChannel
>       ↓
> One Logical Port
>       ↓
> STP sees ONE link
> ```

# 10. Verification Commands

### EtherChannel Summary

```cisco
show etherchannel summary
```

Typical output contains flags such as:

```text
SU
```

Meaning:

- `S` = Layer-2 EtherChannel
    
- `U` = in use
    

Member ports may show:

```text
P
```

`P` means the port is **bundled in the port-channel**.

> **Exam trap:** `P` does **not** mean "LACP negotiated."  
> It means the interface is successfully **bundled**.

Other commonly encountered flags include:

```text
I = Stand-alone
D = Down
s = Suspended
```

The exact flag set and interpretation should be read from the platform's command output.

# 11. Troubleshooting

|Symptom|Likely Cause|Check / Fix|
|---|---|---|
|Member is `I`|Port is stand-alone|Check LACP mode and compatibility|
|`passive + passive`|No LACP initiator|Make at least one side `active`|
|Member is suspended|EtherChannel inconsistency|Compare member configuration|
|Bundle does not form|Physical/config mismatch|Check speed, duplex, VLAN/trunk settings|
|Bundle forms but traffic is uneven|Hash distribution|Check load-balancing algorithm|
|One member carries most traffic|Few large flows / hash result|Normal possible behavior; review hash inputs|
|Member repeatedly joins/leaves|Configuration drift or physical issue|Compare members and check interfaces|
|Trunk does not work|VLAN/trunk mismatch|Compare Port-channel and peer configuration|
|STP behaves unexpectedly|EtherChannel not formed correctly|Verify `show etherchannel summary`|

|---|---|---|---|
|Standard|IEEE|Cisco proprietary|None|
|Negotiation|Yes|Yes|No|
|Modes|active / passive|desirable / auto|on|

|Multi-vendor|Yes|Limited to Cisco ecosystem|Depends on matching static config|
|Protocol PDUs|LACP|PAgP|None|
|Modern choice|**Yes**|Legacy Cisco option|Static only|


# 14. Exam Traps

### Trap 1 — Passive + Passive

```text
active + active     → YES
active + passive    → YES
passive + active    → YES
passive + passive   → NO
```

> **At least one side must be active.**

---

### Trap 2 — LACP vs PAgP

```text
LACP = IEEE standard
PAgP = Cisco proprietary
```

---

### Trap 3 — `on` Is Not LACP

```cisco
channel-group 1 mode on
```

means:

```text
Static EtherChannel
       ↓
No LACP
No PAgP
No negotiation
```

---

### Trap 4 — `P` Flag

In:

```cisco
show etherchannel summary
```

`P` means:

```text
Port is bundled
```

It does **not** specifically mean:

```text
LACP negotiated
```

---

### Trap 5 — LACP Timing

Do not memorize:

```text
LACP = always 1 second
```

Correct:

```text
Fast LACP = 1 second
Slow LACP = 30 seconds
```

---

### Trap 6 — One Flow ≠ All Links

A four-link EtherChannel does not mean one TCP flow automatically gets four times the bandwidth.

```text
4 × 1 Gbps
      ↓
Aggregate ≈ 4 Gbps

Single flow
      ↓
Typically one 1-Gbps member
```

Multiple flows can be distributed across the members.

---

### Trap 7 — STP Sees One Port

```text
Gi0/1 ─┐
       ├── Po1
Gi0/2 ─┘
        ↓
      STP
        ↓
  One logical port
```

## 17. One-Minute Revision

> **LACP = IEEE-standard EtherChannel negotiation.**

Remember these six points:

```text
1. LACP = IEEE 802.3ad / 802.1AX
2. active ↔ active/passive forms
3. passive ↔ passive does NOT form
4. Fast = 1 s, Slow = 30 s
5. EtherChannel uses hash-based per-flow distribution
6. STP sees the Port-channel as ONE logical port
```

**Most important CCNP exam rule:**

```text
ACTIVE + ACTIVE     = BUNDLE
ACTIVE + PASSIVE    = BUNDLE
PASSIVE + PASSIVE   = NO BUNDLE
ON                  = STATIC / NO LACP
```
