# EtherChannel — LACP

> **Level 08 · STP / EtherChannel** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**LACP (Link Aggregation Control Protocol, IEEE 802.3ad / 802.1AX)** is the **open
standard** EtherChannel negotiation. It bundles multiple physical links into one logical
**Port-Channel** with real negotiation — the modern, multi-vendor choice for
switch-to-switch and switch-to-server bundle links.

---

## 2. Core Concepts

### 2.1 LACP modes (negotiation matrix)

| Mode | Talks | Forms bundle with |
|------|-------|-------------------|
| **active** | actively sends LACP PDUs | active / passive peer |
| **passive** | only responds | active peer only |
| **off** | disabled | never (no LACP) |

- **active ↔ active** = yes · **active ↔ passive** = yes · **passive ↔ passive** = **NO**.
- At least one side must be **active**.

### 2.2 The PDU & actors

- LACP PDUs (a **Slow Protocol**, ethertype 0x8809) exchanged every **1 s**.
- Carries actor/partner **System ID (LACP MAC)**, **Admin/Oper key**, port priority.
- **System priority** + **port priority** decide which links stay when the member limit
  is exceeded; strictly the lower system priority wins the whole bundle.

### 2.3 Configuration

```text
interface GigabitEthernet0/1
 channel-group 1 mode active
interface GigabitEthernet0/2
 channel-group 1 mode active
interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

- Peer NICS / ESXi / VMware typically `active` or `passive` — both fine with our `active`.
- `channel-group N` creates or binds the `Port-channel N` logical interface.

### 2.4 Load balancing

- Hash of **src/dst MAC** (layer 2), **src/dst IP** (layer 3), or **L4 ports**
  (`port-channel load-balance <type>`).
- **Per-flow** distribution → no packet reordering within a flow.
- Note: the hash is fixed at config time — changing the module can remap flows.

### 2.5 Speed/duplex & consistency rules

| Requirement | Rule |
|-------------|------|
| Member links | **must match** speed + duplex |
| Trunking | same `switchport mode`, same allowed VLANs |
| STP | bundle appears as **one logical bridge port** to STP |
| Limit | typically 8 active members per bundle (16 with `max-bundles`) |

## 3. Configuration / Commands

```text
interface GigabitEthernet0/1
 channel-group 1 mode active
interface GigabitEthernet0/2
 channel-group 1 mode active

interface Port-channel1
 description LACP bundle to CORE-A
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30

port-channel load-balance src-dst-ip     ! hash policy

show etherchannel summary                 # SU (in use), P = LACP negotiated
show etherchannel 1 port-channel          # members in bundle
show lacp counters                        # exchanged PDUs
show lacp neighbor
show port-channel load-balance
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Member shows `I` (not bundled) | mode mismatch / physical mismatch | correct mode; align speed/duplex |
| No `P` in summary | LACP never negotiated | verify active on one side |
| Bundle UP but no traffic | hash imbalance (one hot link) | change `port-channel load-balance` |
| Links flap in/out of bundle | config drift on member | compare all member configs |
| passive+passive silent | no active side | set one side active |

## 5. Exam Traps

- **passive ↔ passive never forms** — one side must be active.
- **LACP = standard; PAgP = Cisco** — the protocol comparison always asked.
- **PDU every 1 s** (LACP), not 2 s like STP hello.
- **`active` is the "says yes first" mode**; passive waits to be asked.
- **`on` ≠ LACP** — `on` is static (no negotiation, see note 03).
- **Member config must be identical** (speed/duplex/trunk/VLANs) or not bundled.
- **Bundled port = one STP port** — STP treats the bundle as a single link.
