# Root Bridge

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

The **root bridge** is the switch that serves as the **anchor/center of the spanning
tree** — every other switch computes its path toward it, and loops are blocked based on
that path calculation. It is elected by **lowest Bridge ID** (priority, then MAC), and
it anchors a topology *per VLAN* in PVST+ flavors (one root per VLAN). The root is the
**only** switch with **no root port** — all its ports are Designated.

---

## 2. Core Concepts

### 2.1 Election rule — lowest bridge ID

```
Bridge ID = Bridge Priority (2 B = 16 bits)
            ├─ bits 16–5: configured priority (multiples of 4096)
            └─ bits 4–0:  extended system ID (VLAN)  ── used in PVST+ flavors
          + Switch MAC (6 B)
Winner = lowest priority first; tie = lowest MAC
```

- Default priority **32768** → with ext-sys-ID, VLAN 10 root priority appears as
  `32768 + 10 = 32778`.
- Intended root: set priority low (`priority 4096` → effective `4096 + VLAN`) or use the
  `root primary` macro.

### 2.2 How the election spreads (BPDU flood)

- Every switch starts by claiming itself root and sending BPDUs.
- Switches compare Bridge IDs and adopt the **lowest seen** as root, relaying that root's
  identity outward.
- Eventually all converge on **one root**; non-roots forward BPDUs but do not originate
  root claims (they keep the received root ID).

### 2.3 What being root means

| Attribute | Root | Non-root |
|-----------|------|----------|
| Root port | none (it IS root) | one toward root |
| Port roles | all Designated (usually Forwarding) | may have blocking |
| BPDU source | originates | relays |
| Priority | lowest in domain | higher |
| Placement | should be the **fastest/central** switch | rest |

- Best practice: place root at **core/distribution**, not the access edge.

### 2.4 Root in per-VLAN (PVST+ / Rapid PVST+ / MST)

- **PVST+/Rapid PVST+**: root is elected **per VLAN** → different switches can be root
  for different VLANs to distribute load (Level 08 notes 03/04).
- **MST**: root is elected **per instance** (`spanning-tree mst 1 root primary`).
- `root primary` / `root secondary` are **macros**:
  - primary: set priority to **24576** (or **4096** if current root is lower).
  - secondary: set priority to **28672** (just above primary's default).

### 2.5 Root misplacement problems

| Symptom | Cause |
|---------|-------|
| High-bandwidth links blocked oddly | a low-MAC or low-priority switch won root |
| All traffic through a cheap/access switch | root where it should not be |
| Flapping root | portable/legacy switch keeps advertising lower ID |
| Unexpected root | no priority set; lowest MAC decided |

- Proactive fixes: set low priority on the core, use `root primary`/`root secondary`,
  and protect the election with **Root Guard** (Level 08 note 12).

## 3. Configuration / Commands

```text
spanning-tree vlan 10 priority 4096        # hard-set (effective 4106)
spanning-tree vlan 10 root primary         # macro → 24576 (or 4096 if needed)
spanning-tree vlan 10 root secondary       # macro → 28672
spanning-tree mst 1 root primary           # per-instance (MST)

show spanning-tree                          # "Root ID ... This bridge is the root"
show spanning-tree vlan 10 bridge
show spanning-tree root
show spanning-tree summary
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Wrong switch elected root | unset priorities, MAC decided | explicit priority / root primary |
| Root flaps every few min | legacy switch reboots/keeps claiming | `root guard` on uplink (note 12) |
| Core not the root | another distribution switch lower MAC | set equal low priority on intended core |
| Root changed after new switch | new switch default 32768 but lower MAC | set priority < new switch |

## 5. Exam Traps

- **Root = LOWEST bridge ID**, not highest, not MAC alone.
- **Tie-break = lowest MAC**, after priority is equal.
- **Root has no root port** — all its ports are Designated (usually Forwarding).
- **Per VLAN = per-VLAN root** in PVST flavors; **per instance** in MST.
- **Root BPDUs originate from root; non-roots relay** — a tracing question staple.
- **`root primary/secondary` is a macro**, with specific values (24576 / 28672), not just
  "low priority."
- **Extended System ID**: effective priority is `configured + VLAN`, so configured values
  stay multiples of 4096.
