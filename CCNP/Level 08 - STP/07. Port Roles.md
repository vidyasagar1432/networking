# STP Port Roles

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**STP port roles** describe the **function a port performs in the spanning-tree topology**.

The main roles are:

- **Root Port (RP)**
    
- **Designated Port (DP)**
    
- **Alternate Port** — RSTP
    
- **Backup Port** — RSTP
    

A port role is different from a **port state**.

> **Role = What the port is responsible for**  
> **State = What the port is currently doing**

Example:

```text
Root Port      → Role
Forwarding     → State
```

A correct interpretation of `show spanning-tree` requires reading **both Role and State**.

---

# 2. Core Concepts

## 2.1 STP Port Roles

|Role|Purpose|Where it exists|Typical RSTP state|
|---|---|---|---|
|**Root Port (RP)**|Best path toward the root bridge|One per non-root switch per STP instance|Forwarding|
|**Designated Port (DP)**|Best path from a segment toward the root|Normally one per active segment|Forwarding|
|**Alternate Port**|Alternate path toward the root|Non-root switch|Discarding|
|**Backup Port**|Backup for another Designated Port on the same segment|Usually shared-media/redundant connection|Discarding|

The **root bridge has no Root Port**.

Its participating active ports are normally **Designated Ports**.

---

## 2.2 Root Port

Every **non-root switch** normally selects one Root Port for each spanning-tree instance.

The Root Port is the port providing the **best path toward the root bridge**.

Example:

```text
                  Root Bridge
                      SW1
                    /    \
                   /      \
                 SW2      SW3
                  │        │
              Root Port  Root Port
```

SW2 and SW3 each select the interface toward SW1 as their Root Port.

### Important

```text
Root Bridge
    ↓
No Root Port

Non-Root Switch
    ↓
Normally one Root Port
```

A switch does **not** have one Root Port for the entire network if it participates in multiple STP instances.

For example:

```text
PVST+/Rapid PVST+
    ↓
One Root Port per VLAN

MST
    ↓
One Root Port per MST instance
```

---

# 3. Root Port Selection

The Root Port is selected by comparing the **received BPDUs** and choosing the superior path.

For candidate paths toward the same root, the important comparison order is:

```text
1. Lowest Root Bridge ID
2. Lowest Root Path Cost
3. Lowest Sender Bridge ID
4. Lowest Sender Port ID
5. Lowest Local Port ID
   when a final local tie-break is required
```

In practical troubleshooting, when all candidate BPDUs already identify the same root, focus on:

```text
Lowest Root Path Cost
        ↓
Lowest Upstream/Sender Bridge ID
        ↓
Lowest Upstream/Sender Port ID
        ↓
Lowest Local Port ID
```

### Mental model

```text
Which path gets me to the root?

        ↓

Lowest Root Path Cost

        ↓ tie

Lowest Upstream Bridge ID

        ↓ tie

Lowest Upstream Port ID

        ↓ tie

Lowest Local Port ID
```

> **CCNP exam tip:** Do not compare only the local interface speed. STP compares the BPDU information and path cost.

---

# 4. Root Path Cost

The **Root Path Cost** is the total STP cost from a switch toward the root bridge.

Example:

```text
SW1 ================= SW2 ================= SW3
Root                    1G                     1G
```

Assume each 1-Gigabit link has an STP cost of 4:

```text
SW1 → SW2
Cost = 4

SW1 → SW2 → SW3
Cost = 4 + 4
     = 8
```

Therefore:

```text
SW2 Root Path Cost = 4
SW3 Root Path Cost = 8
```

If SW3 has another path with a lower total cost, that path can become the Root Port path.

---

# 5. Designated Port

A **Designated Port** is the port selected as the **best path toward the root for a particular segment**.

The switch advertising the superior BPDU on that segment becomes the **Designated Bridge**, and its port becomes the **Designated Port**.

Example:

```text
              Root
               SW1
                │
                │
          ┌─────┴─────┐
          │           │
         SW2         SW3
```

On the SW1-SW2 segment:

```text
SW1 → Designated Port
SW2 → Root Port
```

On the SW1-SW3 segment:

```text
SW1 → Designated Port
SW3 → Root Port
```

### Important distinction

```text
Root Port
    ↓
Best path FROM a non-root switch
    ↓
Toward the root

Designated Port
    ↓
Best path ON a segment
    ↓
Toward the root
```

---

# 6. Alternate Port

An **Alternate Port** is an RSTP port that provides an **alternate path toward the root**.

It receives a superior BPDU from another switch but is not selected as that switch's Root Port.

Example:

```text
                 SW1
                ROOT
               /    \
              /      \
            SW2------SW3
```

SW2 may have:

```text
Port toward SW1 → Root Port
Port toward SW3 → Alternate Port
```

The Alternate Port is normally in:

```text
Discarding
```

If the Root Port fails and the Alternate Port provides a valid alternate path, RSTP can rapidly promote it to Root Port.

```text
Root Port fails
       ↓
Alternate Port
       ↓
Rapid transition
       ↓
New Root Port
```

> **Alternate = alternate path toward the root.**

---

# 7. Backup Port

A **Backup Port** is different from an Alternate Port.

A Backup Port provides redundancy for a **Designated Port on the same shared segment**.

Conceptually:

```text
          Shared Segment
   ──────────────────────────
        │              │
       SW1             SW1
     Port A           Port B
        │              │
        └──────────────┘

Port A → Designated
Port B → Backup
```

The Backup Port is normally placed in the **Discarding** state.

### Alternate vs Backup

|Role|Backup for|Typical situation|
|---|---|---|
|**Alternate**|Root Port/path toward root|Alternate path through another switch|
|**Backup**|Designated Port on same segment|Redundant connection to same shared segment|

### Easy memory trick

```text
ALTERNATE
    ↓
Backup path to the ROOT

BACKUP
    ↓
Backup of a DESIGNATED port
on the SAME segment
```

Backup Ports are relatively uncommon in modern switched Ethernet because point-to-point full-duplex links dominate enterprise networks.

---

# 8. Root Bridge Port Roles

The root bridge does not have a Root Port.

Example:

```text
                  SW1
                 ROOT
              /    |    \
             /     |     \
           SW2    SW3    SW4
```

On the root:

```text
SW1
│
├── Designated
├── Designated
└── Designated
```

The root's active participating ports are normally Designated Ports because the root has the best possible path to itself:

```text
Root Path Cost = 0
```

---

# 9. Role vs State

This is one of the most important STP exam concepts.

### Port Role

Describes the **function** of the port:

```text
Root
Designated
Alternate
Backup
```

### Port State

Describes the **operational state** of the port.

Classic 802.1D STP uses:

```text
Blocking
Listening
Learning
Forwarding
Disabled
```

RSTP simplifies this to:

```text
Discarding
Learning
Forwarding
```

RSTP combines the old:

```text
Blocking + Listening
        ↓
   Discarding
```

### Mental model

```text
ROLE                       STATE

Root Port       ───────→   Forwarding
Designated      ───────→   Forwarding
Alternate       ───────→   Discarding
Backup          ───────→   Discarding
```

These are typical steady-state combinations, not an absolute rule for every transient or administrative condition.

---

# 10. RSTP Port Roles and States

RSTP defines:

### Roles

```text
Root
Designated
Alternate
Backup
```

### States

```text
Discarding
Learning
Forwarding
```

Therefore:

```text
RSTP
│
├── Port Role
│     ├── Root
│     ├── Designated
│     ├── Alternate
│     └── Backup
│
└── Port State
      ├── Discarding
      ├── Learning
      └── Forwarding
```

Do not confuse the two.

# 11. Role Selection Example

Consider:

```text
                 SW1
                ROOT
               /    \
             /        \
           SW2--------SW3
```

Suppose:

```text
SW2 → SW1 cost = 4
SW2 → SW3 → SW1 cost = 8
```

SW2 chooses:

```text
SW2 → SW1 = Root Port
```

The SW2-SW3 link now needs a Designated/Alternate decision.

If SW3 has the superior path toward the root, then:

```text
SW3 → Designated Port
SW2 → Alternate Port
```

Therefore:

```text
                 SW1
                ROOT
               /    \
             RP      RP
             SW2----SW3
               ALT  DP
```

The Alternate Port remains Discarding while the Designated Port forwards.

# 12. Failure and Convergence

## 12.1 Root Port Failure

Example:

```text
                 SW1
                ROOT
               /    \
              /      \
            SW2------SW3
```

SW2:

```text
Toward SW1 → Root Port
Toward SW3 → Alternate
```

If the Root Port fails:

```text
Root Port fails
      ↓
Alternate Port remains available
      ↓
RSTP recalculates
      ↓
Alternate becomes Root Port
      ↓
Forwarding
```

RSTP can perform this transition rapidly once the failure is detected and the alternate path is suitable.

---

## 12.2 Designated Port Failure

If a Designated Port fails, another switch may need to become the Designated Port for that segment.

The exact convergence behavior depends on:

- STP version
    
- Link type
    
- BPDU exchange
    
- Neighbor roles
    
- Topology
    

RSTP uses its proposal/agreement mechanisms and rapid role transitions to converge faster than traditional 802.1D STP.

---

## 12.3 Root Bridge Failure

If the root bridge fails:

```text
Root Bridge fails
       ↓
Other switches detect loss
       ↓
New root election
       ↓
New Root Bridge
       ↓
Root/Designated/Alternate roles recalculate
```

All affected STP instances can recalculate their topology.

---

# 13. RSTP and UplinkFast

Classic Cisco STP had features such as:

```text
UplinkFast
BackboneFast
```

RSTP inherently provides mechanisms for rapid alternate-path recovery.

Therefore, when studying RSTP:

```text
RSTP
│
├── Alternate Port
│     └── Rapid backup path
│
├── Proposal/Agreement
│     └── Rapid synchronization
│
└── Rapid transition
```

> **Exam point:** Do not configure classic UplinkFast as the mechanism that makes RSTP Alternate Ports work. RSTP already provides rapid alternate-path behavior.

# 14. Configuration / Commands

You normally **do not configure port roles directly**.

Instead, you influence the inputs that STP uses to calculate roles.

### Set STP path cost

```text
interface GigabitEthernet0/1
 spanning-tree vlan 10 cost 4
```

A lower path cost can make the path more attractive for the Root Port/designated-path calculation.

### Set STP port priority

```text
interface GigabitEthernet0/1
 spanning-tree vlan 10 port-priority 32
```

Port priority influences the **Port ID tie-break**.

On typical Cisco IOS/IOS XE platforms, port priority is configured in increments of **16**.

Lower Port ID wins the relevant tie-break.

### Influence root placement

```text
spanning-tree vlan 10 root primary
```

This can change which switch becomes root, which then affects downstream port roles.

# 16. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Wrong Root Port selected|Path cost or BPDU tie-break|Check root path cost, upstream Bridge ID and Port ID|
|Expected backup is not Alternate|It may not provide an alternate path to the root|Examine received BPDUs and topology|
|Two ports appear to forward unexpectedly|Different segments/instances may be involved|Check VLAN, topology, role and state|
|Alternate does not promote|Failure detection or alternate path conditions|Check link, BPDUs and STP guards|
|Wrong Designated Port|Superior BPDU exists on the segment|Compare root path cost and Bridge/Port IDs|
|Link has unexpected blocking/discarding|STP role calculation|`show spanning-tree vlan N`|
|Port is forwarding but thought it should block|Role/state or VLAN/instance mismatch|Read both Role and State|
|STP topology differs per VLAN|PVST+/Rapid PVST+ calculates separately|Check `show spanning-tree vlan N`|
|MST topology differs by instance|MSTI has separate root/path calculation|Check `show spanning-tree mst`|

# 18. Root Port vs Designated Port

This distinction is extremely important.

```text
ROOT PORT
│
└── Selected by a SWITCH
    │
    └── "What is my best path to the root?"

DESIGNATED PORT
│
└── Selected for a SEGMENT
    │
    └── "Which switch has the best path
        to the root on this segment?"
```

Example:

```text
             ROOT
              SW1
             /  \
            /    \
          SW2----SW3
```

Possible roles:

```text
SW1 → Designated toward SW2
SW2 → Root toward SW1

SW1 → Designated toward SW3
SW3 → Root toward SW1

SW2 ↔ SW3
One side → Designated
Other side → Alternate
```

# 19. Exam Traps

### Trap 1 — Role = State

**Wrong:**

> Blocking is a port role.

**Correct:**

> Blocking is a classic STP **state**. Root, Designated, Alternate and Backup are **roles**.

---

### Trap 2 — Root bridge has a Root Port

**Wrong:**

> Every switch has one Root Port.

**Correct:**

> Every **non-root switch** normally has one Root Port per STP instance. The root bridge has none.

---

### Trap 3 — Alternate = any blocked port

**Wrong:**

> Every blocked RSTP port is automatically an Alternate Port.

**Correct:**

> An Alternate Port specifically provides an **alternate path toward the root**.

---

### Trap 4 — Backup = alternate path to root

**Wrong:**

> Backup Port is another path toward the root.

**Correct:**

> Backup Port is a backup for a **Designated Port on the same segment**.

---

### Trap 5 — Lower local port number always wins

**Wrong:**

> STP always chooses the lowest local interface number.

**Correct:**

> STP first compares the superior BPDU/path information. Port IDs are used only in the appropriate tie-break stages.

---

### Trap 6 — Root Port selection is based only on cost

**Wrong:**

> The lowest-cost interface always becomes Root Port.

**Correct:**

> Root Port selection uses the **superior BPDU comparison**, including Root Path Cost and the required Bridge ID/Port ID tie-breakers.

---

### Trap 7 — RSTP uses Blocking and Listening

**Wrong:**

> RSTP has Blocking, Listening, Learning and Forwarding states.

**Correct:**

> RSTP uses **Discarding, Learning and Forwarding**.

---

### Trap 8 — RSTP failure recovery is always instantaneous

**Wrong:**

> An Alternate Port always becomes Forwarding immediately when the Root Port fails.

**Correct:**

> RSTP can transition rapidly after failure detection when the alternate path and topology permit it.
