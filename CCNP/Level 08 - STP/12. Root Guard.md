# Root Guard

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Root Guard** protects **who remains the root bridge**: on designated/uplink ports where
a **superior (better) BPDU** must never be accepted, Root Guard puts that port into
**root-inconsistent (blocking) state** if a would-be new root advertises itself — instead
of letting a rogue switch steal the root and reroute the whole topology through itself.

---

## 2. Core Concepts

### 2.1 The threat

- A low-priority (or low-MAC) rogue/legacy switch plugged into the campus could advertise
  a "better" Bridge ID and **become root** — misplacing the tree, funneling all traffic
  through it, or causing outages.
- Root Guard blocks **only the incoming direction**: the offending port stops forwarding
  (root-inconsistent); the rest of the topology stays safe.

### 2.2 How it behaves

| Scenario | Result |
|----------|--------|
| Superior root ID arrives on root-guard port | port → **root-inconsistent (blocking)** |
| Normal traffic | unaffected |
| Bad BPDUs stop | port returns to normal **automatically** |

- The port stays in root-inconsistent while the superior BPDU value persists, then
  auto-recovers.

### 2.3 Config & placement

```text
interface Gi0/24              # toward the rest of the network (not toward host)
 spanning-tree guard root
```

- Enable on ports where a **superior root must never come** — usually distribution/core
  downlinks toward access, or uplinks toward untrusted segments.
- **Don't put it toward the intended root** — it would block the legitimate root election.
- Command: `spanning-tree guard root` (per interface). Per-VLAN-tolerant where relevant.

### 2.4 Root Guard vs BPDU Guard

| | Root Guard | BPDU Guard |
|--|-----------|------------|
| Trigger | superior (better root) BPDU | ANY BPDU (on edge/PortFast) |
| Action | port → root-inconsistent (blocks) | port → errdisable |
| Recovery | automatic when BPDUs stop | manual / errdisable-recovery |
| Ideal on | uplinks toward untrusted | host edge ports |

- Root Guard doesn't need PortFast; BPDU Guard usually lives on edge ports.

### 2.5 Root Guard vs Loop Guard

| | Root Guard | Loop Guard |
|--|-----------|------------|
| Saves | root placement | from unidirectional link loss |
| Trigger | better (superior) BPDU | BPDU loss on a link |
| Result | root-inconsistent | loop-inconsistent (discarding) |
| Recovery | automatic | automatic |

- Both keep STP sane in specific failure modes — often deployed together on the same
  redundant distribution links.

## 3. Configuration / Commands

```text
interface GigabitEthernet0/24
 spanning-tree guard root

show spanning-tree interface Gi0/24
show spanning-tree inconsistentports       # root-inconsistent list
show spanning-tree summary | include Guard
show spanning-tree vlan 10 | include "ROOT|inconsistent"
```

---

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Port root-inconsistent | a superior root BPDU arriving there | find rogue; root guard did its job |
| Legit root not elected | guard accidentally toward intended root | move guard placement |
| Flapping root between cores | neither core protected / priorities equal | `root primary/secondary` + guard |

---

## 5. Exam Traps

- **Root Guard blocks the superior BPDU's port, not the whole switch** — targeted defense.
- **Automatic recovery** when the bad BPDUs disappear.
- **Put it where a root must NEVER be** (toward untrusted/downstream), NOT toward the real root.
- **Distinguish from BPDU Guard** (edge, errdisable) and **Loop Guard** (unidirectional loss).
- Named state in output: **root-inconsistent**.
