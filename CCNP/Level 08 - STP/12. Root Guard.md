# Root Guard

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Root Guard** protects the **intended root-bridge placement**. It is configured on ports  
where this switch should remain **Designated Port** and where a **superior BPDU must never  
be accepted**.

If a superior BPDU is received on a Root Guard-enabled port, Cisco places that port into  
**root-inconsistent** state and stops it from forwarding. This prevents a downstream or  
untrusted switch from influencing the root election and changing the Layer-2 topology.

---

## 2. Core Concepts

### 2.1 The Threat

A rogue, misconfigured, or incorrectly prioritized switch can advertise a **superior BPDU**.

A superior BPDU can contain a better **Root Bridge ID**, potentially causing the existing  
root election to change.

Without Root Guard:

```text
Existing Root
     │
     ├── Distribution
     │
     └── Access
            │
         Rogue Switch
            │
      Superior BPDU
            ↓
     Root election can change
```

With Root Guard:

```text
Existing Root
     │
     ├── Distribution
     │
     └── Access ──X── Rogue Switch
                    ↑
              Superior BPDU

          Port → root-inconsistent
```

The offending port is isolated from forwarding rather than allowing the superior BPDU to  
change the intended root topology.

---

## 3. How Root Guard Behaves

|Event|Result|
|---|---|
|Superior BPDU received on Root Guard port|Port enters **root-inconsistent**|
|Port in root-inconsistent|Port stops forwarding|
|Superior BPDUs continue|Port remains root-inconsistent|
|Superior BPDUs disappear|Port automatically recovers|
|Manual shutdown/no shutdown required|**No**|

### Important

Root Guard does **not** permanently disable the interface.

It is a **conditional STP protection mechanism**:

```text
Normal STP
   │
   │ Superior BPDU arrives
   ↓
Root-Inconsistent
   │
   │ Superior BPDU disappears
   ↓
Normal STP
```

---

## 4. Where to Configure Root Guard

Configure Root Guard on a port where:

> **"This port must never learn a better root from the device connected beyond it."**

Typical placement:

```text
              CORE / DISTRIBUTION
               Intended Root
                    │
                    │
              Designated Port
                    │
             [ ROOT GUARD ]
                    │
                    ↓
             ACCESS / DOWNSTREAM
                    │
              Untrusted Switch
```

Example:

```cisco
interface GigabitEthernet0/24
 spanning-tree guard root
```

### Placement Rule

**Put Root Guard toward the downstream/untrusted side where a superior root must never  
appear.**

Do **not** blindly configure Root Guard toward the legitimate root bridge.

If Root Guard is placed on a port that legitimately needs to receive superior BPDUs from  
the intended root, that port can become **root-inconsistent** and break the intended STP  
topology.

---

## 5. Root Guard vs BPDU Guard

|Feature|Root Guard|BPDU Guard|
|---|---|---|
|Primary purpose|Protect root placement|Protect edge/PortFast ports|
|Trigger|**Superior BPDU**|**Any BPDU**|
|Typical port|Designated/downstream-facing port|Host/edge port|
|Result|**root-inconsistent**|**err-disabled**|
|Automatic STP recovery|Yes|Not by default|
|Requires PortFast?|No|Commonly used with PortFast|
|Main threat|Rogue switch becoming/influencing root|Switch accidentally connected to edge port|

### Mental Model

```text
ROOT GUARD
│
├── "You must NOT become a better root"
│
├── Superior BPDU
│
└── Port → root-inconsistent
```

```text
BPDU GUARD
│
├── "This is an edge/host port"
│
├── ANY BPDU
│
└── Port → err-disabled
```

---

## 6. Root Guard vs Loop Guard

|Feature|Root Guard|Loop Guard|
|---|---|---|
|Protects|Root placement|STP loop prevention|
|Trigger|Superior BPDU|Expected BPDUs stop arriving|
|Main concern|Unexpected better root|Unidirectional/BPDU-loss failure|
|Result|**root-inconsistent**|**loop-inconsistent**|
|Recovery|Automatic when superior BPDUs disappear|Automatic when expected BPDUs return|
|Typical purpose|Prevent downstream switch from influencing root|Prevent blocked/alternate port from incorrectly becoming forwarding|

### Mental Model

```text
ROOT GUARD
│
├── Superior BPDU appears
│
└── "This switch must not become root"
       ↓
   root-inconsistent
```

```text
LOOP GUARD
│
├── Expected BPDU disappears
│
└── "Do not assume the path is safe"
       ↓
   loop-inconsistent
```

## 7. Configuration

### Enable Root Guard

```cisco
interface GigabitEthernet0/24
 description Downstream switch - protect root placement
 spanning-tree guard root
```

### Verify

```cisco
show spanning-tree interface Gi0/24
show spanning-tree inconsistentports
show spanning-tree summary | include Guard
show spanning-tree vlan 10
```

Useful output to look for:

```text
Root Inconsistent
```

or:

```text
root-inconsistent
```

## 8. Troubleshooting

### Symptom: Port is root-inconsistent

Likely cause:

```text
Superior BPDU received
        ↓
Root Guard detected it
        ↓
Port became root-inconsistent
```

Check:

```cisco
show spanning-tree inconsistentports
show spanning-tree interface Gi0/24
show spanning-tree vlan 10
```

Then identify the device sending the superior BPDU.

---

### Symptom: Legitimate root cannot reach the switch

Possible cause:

```text
Root Guard configured on the wrong port
```

Check whether Root Guard was accidentally configured toward the intended root.

Fix:

```cisco
interface GigabitEthernet0/24
 no spanning-tree guard root
```

---

### Symptom: Root topology changes unexpectedly

Check:

```cisco
show spanning-tree root
show spanning-tree vlan 10
show spanning-tree summary
```

Then verify:

- Root Bridge identity
    
- Bridge priority
    
- Root Port
    
- Designated Ports
    
- Root Guard placement
    
- Unexpected switches/BPDUs
    

For predictable root placement, explicitly configure the intended root:

```cisco
spanning-tree vlan 10 root primary
```

and, where appropriate:

```cisco
spanning-tree vlan 10 root secondary
```

## 9. Root Guard Decision Flow

```text
             BPDU received
                   │
                   ↓
        Is it a superior BPDU?
             /          \
           No            Yes
           │              │
           ↓              ↓
      Continue STP   Root Guard enabled?
                         /      \
                       No        Yes
                       │          │
                       ↓          ↓
                  STP may      Port →
                  accept it    root-inconsistent
                                  │
                                  ↓
                         Stops forwarding
                                  │
                                  ↓
                    Superior BPDUs disappear
                                  │
                                  ↓
                         Automatic recovery
```

```text
ROOT GUARD
│
├── Goal
│     └── Protect intended Root Bridge placement
│
├── Placement
│     └── Port toward downstream/untrusted switches
│
├── Watches for
│     └── Superior BPDU
│
├── Reaction
│     └── root-inconsistent
│
├── Forwarding
│     └── Port stops forwarding
│
├── Recovery
│     └── Automatic when superior BPDUs disappear
│
├── Does NOT require
│     └── PortFast
│
└── Remember
      └── "A root must NEVER come from this direction."
```

## 11. Exam Traps

### Trap 1 — Root Guard does not react to every BPDU

**Wrong:**

> Any BPDU causes Root Guard to block the port.

**Correct:**

> Root Guard reacts when a **superior BPDU** is received on the protected port.

---

### Trap 2 — Root Guard is not BPDU Guard

**Root Guard:**

```text
Superior BPDU
      ↓
root-inconsistent
```

**BPDU Guard:**

```text
Any BPDU
      ↓
err-disabled
```

---

### Trap 3 — Root Guard is not Loop Guard

**Root Guard:**

```text
Superior BPDU
      ↓
root-inconsistent
```

**Loop Guard:**

```text
Expected BPDU disappears
      ↓
loop-inconsistent
```

---

### Trap 4 — Root Guard automatically recovers

When the superior BPDUs stop arriving, the port can automatically return to normal STP  
operation.

You normally do **not** need:

```cisco
shutdown
no shutdown
```

---

### Trap 5 — Think about direction, not just port type

Do not memorize:

> "Root Guard goes on uplinks."

Instead memorize:

> **"Root Guard goes on a port where I want to prevent a superior root from coming from  
> that direction."**

This is the safer CCNP mental model.
