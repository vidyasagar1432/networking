# MST (Multiple Spanning Tree, 802.1s)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**MST (IEEE 802.1s)** maps **many VLANs into a few spanning-tree instances** (`mst 0`,
`mst 1`, ...). It gives RSTP-speed convergence and per-VLAN load-balancing **without**
one instance per VLAN — the scaled solution for large/flexible fabrics, and Cisco & IEEE
interoperable.

---

## 2. Core Concepts

### 2.1 Instance & region concept
```
MST region = a set of switches sharing the same name, revision, and VLAN→instance map
Example:
  instance 1  →  VLANs 1-50
  instance 2  →  VLANs 51-100
  instance 0  →  everything else (IST, internal spanning tree)
```
- **IST (instance 0 / internal spanning tree)** — bridges the region to the outside and
  aggregates; the "one tree" linking regions.
- Outside the region, MST behaves/propagates as a single (rapid) tree — a **single MST
  bridge** toward legacy.

### 2.2 Why MST over Rapid PVST+
| | Rapid PVST+ | MST |
|--|-------------|-----|
| Instances | = VLANs (many) | few (mapped) |
| BPDU/CPU cost | scales with VLANs | bounded |
| Load balance | per VLAN | per instance (covers many VLANs) |
| Cisco/Xe standard | Cisco-only | 802.1s standard |
| Ideal | small-medi campus | large scale, provider, fabric |
- Same RSTP mechanics inside instances → fast.

### 2.3 Region configuration essentials
```text
spanning-tree mst configuration
 name CORP-REGION                 ! same name all switches
 revision 2                        ! bump on change
 instance 1 vlan 1-50
 instance 2 vlan 51-100
 exit
spanning-tree mode mst
spanning-tree mst 1 priority 4096   ! per-instance root
```
- Mismatched **name/revision/mapping** = switches are in **different regions** (and
  strange tree behavior; different mappings break load-balance logic). "Region boundary"
  is exam gold.

### 2.4 How MST scales & interops
- A region appears to outsiders as **one bridge** (via IST) → neighbor sees one tree.
- MST BPDUs carry the region identity; RSTP/customer sees version 2 (rapid).
- Very stable BPDU count regardless of VLAN count.

### 2.5 MST instance details
- **Instance 0 (IST)** always exists (default instance for the region).
- Instance numbering 1–15, plus 0.
- Path costs/timers apply **per instance**, not per VLAN.

## 3. Configuration / Commands

```text
spanning-tree mst configuration
 name CORP
 revision 1
 instance 1 vlan 10-20
 instance 2 vlan 30-40
spanning-tree mode mst
spanning-tree mst 1 root primary
spanning-tree mst 2 root secondary

show spanning-tree mst
show spanning-tree mst configuration
show spanning-tree mst 1
```

---

## 4. Exam Traps

- **MST = few instances mapped over many VLANs** — not "per VLAN."
- **Region definition = name + revision + VLAN map** — mismatch = different regions.
- **Instance 0 (IST) is automatic and always there.**
- **Outside the region MST appears as a single bridge/spanning tree.**
- **RSTP mechanics** — MST instances converge as fast as RSTP.
- **Don't answer Rapid PVST+ for "scale to thousands of VLANs"** — choose MST.
