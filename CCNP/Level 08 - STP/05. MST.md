# MST (Multiple Spanning Tree, 802.1s)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**MST (Multiple Spanning Tree)** is an IEEE standard originally defined by **802.1s** and incorporated into later IEEE 802.1Q revisions. It reduces STP scale by mapping **multiple VLANs to a smaller number of spanning-tree instances**.

Instead of maintaining one spanning-tree instance per VLAN, MST allows many VLANs to share an **MSTI (MST Instance)**.

MST uses **RSTP mechanisms** for rapid convergence and supports **per-instance load balancing**.

> **CCNP Mental Model:**  
> **Many VLANs → Few MST instances → Less STP overhead → Per-instance load balancing**

---

## 2. Core Concepts

### 2.1 MST Region

An **MST region** is a group of switches that have an identical MST configuration.

A region is identified by three matching parameters:

1. **MST region name**
    
2. **MST revision number**
    
3. **VLAN-to-MST instance mapping**
    

```text
MST Region
│
├── Name
├── Revision
└── VLAN → Instance Mapping
```

All switches intended to belong to the same MST region must have the same values.

Example:

```text
Region Name: CORP
Revision:    2

VLAN 10-50   → MSTI 1
VLAN 51-100  → MSTI 2
Other VLANs  → MSTI 0 (IST)
```

If any of the three parameters differ, the switches are considered to be in **different MST regions**.

> **Important:** A different MST region is not automatically a problem. Multiple MST regions can be connected together. The important point is that a configuration mismatch means the switches do **not** form one MST region.

---

## 2.2 IST, CIST, and MSTI

MST uses several related spanning-tree concepts.

### IST — Internal Spanning Tree

**MST instance 0** is the **IST (Internal Spanning Tree)**.

- It always exists.
    
- It cannot be removed.
    
- It carries VLANs that are not explicitly mapped to another MSTI.
    
- It represents the region internally.
    
- It participates in the **CIST** that connects the MST region to external spanning-tree domains.
    

### MSTI — MST Instance

MSTIs are the additional spanning-tree instances:

```text
MSTI 1
MSTI 2
MSTI 3
...
MSTI 15
```

Each MSTI can have its own:

- Root bridge
    
- Port roles
    
- Port states
    
- Path costs
    
- Load-balancing behavior
    

VLANs mapped to the same MSTI share that instance's spanning-tree topology.

### CIST — Common and Internal Spanning Tree

The **CIST (Common and Internal Spanning Tree)** provides the overall spanning-tree structure that connects:

- switches within an MST region
    
- multiple MST regions
    
- MST regions to external STP/RSTP/PVST+ domains
    

Think of it as the **common spanning-tree view across the entire bridged network**.

```text
                    CIST
                     │
        ┌────────────┴────────────┐
        │                         │
    MST Region A              MST Region B
        │                         │
      IST 0                     IST 0
     /  |  \                   /  |  \
   MSTI1 MSTI2 MSTI3        MSTI1 MSTI2 MSTI3
```

---

## 2.3 MST Region vs MST Instance

Do not confuse these concepts:

|Concept|Meaning|
|---|---|
|**MST Region**|Group of switches with identical MST configuration|
|**IST / MST 0**|Mandatory instance inside every MST region|
|**MSTI 1–15**|Additional instances created for VLAN groups|
|**CIST**|Common spanning-tree structure connecting regions/domains|

---

## 3. Why MST?

With traditional per-VLAN STP, the number of spanning-tree instances can grow with the number of VLANs.

For example:

```text
Rapid PVST+

1000 VLANs
     │
     └── ~1000 STP instances
```

MST can group those VLANs:

```text
MST

1000 VLANs
     │
     ├── MSTI 1 → VLAN 1-200
     ├── MSTI 2 → VLAN 201-400
     ├── MSTI 3 → VLAN 401-600
     ├── MSTI 4 → VLAN 601-800
     └── MSTI 5 → VLAN 801-1000
```

This significantly reduces STP control-plane overhead.

### Rapid PVST+ vs MST

|Feature|Rapid PVST+|MST|
|---|---|---|
|STP instances|Typically one per VLAN|Multiple VLANs share an instance|
|Load balancing|Per VLAN|Per MSTI|
|Scalability|Lower as VLAN count grows|Better|
|Standard|Cisco implementation|IEEE standard|
|Convergence|RSTP-based|RSTP-based|
|Best use|Per-VLAN control|Large VLAN environments|
|Multivendor|Less universal|IEEE-standard approach|

> **Exam clue:** If the question emphasizes **many VLANs + fewer STP instances + scalability**, think **MST**.

## 4. MST Configuration

Example:

```text
spanning-tree mst configuration
 name CORP
 revision 2
 instance 1 vlan 10-50
 instance 2 vlan 51-100
 exit

spanning-tree mode mst
```

This creates:

```text
MST 0 → VLANs not explicitly mapped
MST 1 → VLAN 10-50
MST 2 → VLAN 51-100
```

### Configure the MST root

```text
spanning-tree mst 1 priority 4096
spanning-tree mst 2 priority 8192
```

Or use Cisco's convenience commands:

```text
spanning-tree mst 1 root primary
spanning-tree mst 2 root secondary
```

> `root primary` and `root secondary` are convenience commands that adjust the bridge priority. They do not create a permanent guarantee of primary/secondary status against every possible topology or configuration.

## 5. MST Region Matching

For switches to belong to the same MST region:

```text
Switch A                  Switch B
────────                  ────────
Name: CORP       =        Name: CORP
Revision: 2      =        Revision: 2
VLAN mapping      =       VLAN mapping
```

Example of a mismatch:

```text
SW1:
Name: CORP
Revision: 2
VLAN 10-20 → MSTI 1

SW2:
Name: CORP
Revision: 3
VLAN 10-20 → MSTI 1
```

Result:

```text
SW1 ≠ SW2
     │
     └── Different MST regions
```

Another example:

```text
SW1:
VLAN 10-20 → MSTI 1

SW2:
VLAN 10-20 → MSTI 2
```

Even though the name and revision match, the VLAN mapping differs, so they are **different MST regions**.

### Important exam point

The **revision number is part of region identification**.

Do not think:

> "The revision number automatically synchronizes the configuration."

It does not.

All switches must actually have matching:

```text
Name + Revision + VLAN-to-instance mapping
```

---

## 6. VLAN-to-Instance Mapping

Example:

```text
Instance 1 → VLAN 10-20
Instance 2 → VLAN 30-40
```

Then:

```text
VLAN 10 ─┐
VLAN 11  │
VLAN 12  │
...      ├── MSTI 1
VLAN 20 ─┘

VLAN 30 ─┐
VLAN 31  │
...      ├── MSTI 2
VLAN 40 ─┘
```

All VLANs mapped to the same MSTI use the **same spanning-tree topology**.

This is the key trade-off:

> **You gain scalability by giving up independent spanning-tree topology per VLAN.**

If VLAN 10 and VLAN 20 are both mapped to MSTI 1, they cannot have different STP topologies inside that MSTI.

---

## 7. MST Root Bridge

MST allows different instances to have different root bridges.

Example:

```text
MSTI 1
Root = SW1

MSTI 2
Root = SW2
```

This allows Layer 2 load balancing:

```text
             SW1
          MSTI 1 Root
           /      \
          /        \
        SW3        SW4
          \        /
           \      /
             SW2
          MSTI 2 Root
```

Traffic belonging to VLANs mapped to MSTI 1 can prefer the topology toward SW1, while VLANs mapped to MSTI 2 can prefer the topology toward SW2.

> **MST load balancing is per instance, not per VLAN.**

---

## 8. MST and RSTP

MST uses **RSTP (802.1w) mechanisms** for rapid convergence.

Important mechanisms include:

- Port roles
    
- Proposal/agreement process
    
- Edge ports
    
- Point-to-point link behavior
    
- Rapid transition of appropriate ports
    

Therefore:

```text
MST
 │
 └── RSTP convergence mechanisms
```

MST does **not** mean "slow STP with multiple instances."

It is an RSTP-based spanning-tree architecture.

---

## 9. MST and External Networks

An MST region does not expose every internal MSTI as a separate spanning-tree bridge to external networks.

From outside the region, the region is represented through the **CIST** as a logical spanning-tree entity.

Conceptually:

```text
          External STP Domain
                  │
                  │
             MST Region
        ┌─────────┴─────────┐
        │                   │
      MSTI 1              MSTI 2
        │                   │
      VLANs               VLANs
```

The external network does not need to understand every internal MSTI.

This is one of MST's major scalability advantages.

---

## 10. MST Region Boundaries

A switch can determine whether its neighbor belongs to the same MST region.

If the MST configuration matches:

```text
SW1 ================= SW2
       Same Region
```

If it does not:

```text
SW1 ================= SW2
       Region Boundary
```

The boundary can occur because of:

- Different region name
    
- Different revision
    
- Different VLAN-to-instance mapping
    
- Neighbor using a different spanning-tree domain/protocol
    

### Important

A **region boundary is not inherently an error**.

For example:

```text
MST Region A
     │
     │
     ├── Boundary
     │
MST Region B
```

Multiple MST regions can legitimately exist in the same Layer 2 topology.

The important question is whether the resulting CIST/root/path relationships are correct.

---

## 11. MST ↔ PVST+/Rapid-PVST+ Interoperability

Cisco supports **PVST+ simulation** when connecting MST to PVST+/Rapid-PVST+ environments.

Conceptually:

```text
Rapid-PVST+ Domain
       │
       │
PVST+ Simulation / Boundary
       │
       │
   MST Region
```

The MST region internally uses its MST instances, while the PVST+/Rapid-PVST+ side continues operating with its per-VLAN spanning trees.

### Important exam distinction

Do not memorize:

> "MST creates one MST instance for every VLAN at the boundary."

Instead:

> **PVST+ simulation provides interoperability between the MST region and the per-VLAN PVST+/Rapid-PVST+ domain.**

Boundary/root consistency must be maintained to avoid undesirable spanning-tree behavior.

Useful command:

```text
show spanning-tree mst
```

and, on Cisco platforms that support it:

```text
show spanning-tree mst interface
```

## 12. MST Instance Limits

On Cisco IOS/IOS XE implementations commonly used for CCNP study:

```text
MST 0  → IST
MST 1  → User-defined
MST 2  → User-defined
...
MST 15 → User-defined
```

Therefore:

```text
16 total MST instances
│
├── Instance 0 = IST
└── Instances 1-15 = MSTIs
```

> **Exam point:** VLANs that are not explicitly mapped to MSTI 1–15 remain in **MST 0 (IST)**.

## 15. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Switches unexpectedly form different regions|Name/revision/mapping mismatch|`show spanning-tree mst configuration`|
|VLANs remain in MST 0|VLANs were not mapped to another MSTI|Check MST configuration|
|Wrong MSTI root|Incorrect priority or another switch has better priority|`show spanning-tree mst`|
|Expected load balancing is missing|VLANs mapped to same MSTI or root placement is wrong|Check VLAN mapping and MST roots|
|Unexpected boundary|Neighbor has different MST configuration or protocol|Check MST configuration and interface information|
|PVST+/MST interoperability problem|Boundary/root relationship is inconsistent|Check MST/PVST boundary behavior|
|Topology differs between switches|MST region configuration is inconsistent|Compare name, revision, and mapping|
|Root appears different from expectation|Lower bridge priority/MAC address wins|Check bridge priority and root information|

## 18. Exam Traps

### Trap 1 — MST is per VLAN

**Wrong:**

> MST creates one STP instance for every VLAN.

**Correct:**

> MST maps multiple VLANs to a smaller number of MST instances.

---

### Trap 2 — Region = name only

**Wrong:**

> Switches with the same MST name are in the same region.

**Correct:**

> Region identity depends on the **name + revision + VLAN-to-instance mapping**.

---

### Trap 3 — MST 0 can be removed

**Wrong:**

> Disable MST 0 and use only MSTI 1 and 2.

**Correct:**

> **MST 0 (IST) always exists.**

---

### Trap 4 — Load balancing is per VLAN

**Wrong:**

> VLAN 10 can have one topology and VLAN 20 another topology even though both belong to MSTI 1.

**Correct:**

> VLANs in the same MSTI share the same spanning-tree topology.

---

### Trap 5 — Different regions are always a failure

**Wrong:**

> Two different MST regions automatically indicate a configuration error.

**Correct:**

> Different MST regions can be intentional. They become a problem when the resulting spanning-tree design/root/path relationships are incorrect.

---

### Trap 6 — MST is the same as classic STP

**Wrong:**

> MST uses the old 802.1D convergence process.

**Correct:**

> MST uses **RSTP mechanisms** for rapid convergence.

---

### Trap 7 — Revision number synchronizes configuration

**Wrong:**

> Increasing the revision number automatically synchronizes the region.

**Correct:**

> Every switch must have the same **name, revision, and VLAN-to-instance mapping**.

---

### Trap 8 — MST has one root only

**Wrong:**

> MST can have only one root bridge for the entire MST network.

**Correct:**

> Different MSTIs can have different root bridges, while the **CIST** has its own root relationship.
