# MST (Multiple Spanning Tree, 802.1s)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**MST (IEEE 802.1s)** maps **many VLANs into a few spanning-tree instances** (`mst 0`,
`mst 1`, ...). It gives RSTP-speed convergence and per-instance load balancing **without**
one instance per VLAN — the scaled solution for large fabrics, and interoperable with
Cisco & IEEE. MST is the exam answer when "thousands of VLANs" or "mixed-vendor" appears.

---

## 2. Core Concepts

### 2.1 Instance & region concept

```
MST region = a set of switches sharing the same name, revision, and VLAN→instance map
Example:
  instance 1 → VLANs 1-50
  instance 2 → VLANs 51-100
  instance 0 → everything else (IST, internal spanning tree)
```

- **IST (instance 0 / Internal Spanning Tree)** — bridges the region to the outside,
  aggregates, and is mandatory (always exists).
- **MSTI (1–15)** — the instances you define; each computes its own root/blocked ports.
- Outside the region, MST behaves/propagates as a **single RSTP tree** — a single
  "MST bridge" toward legacy networks.

### 2.2 Why MST over Rapid PVST+

| | Rapid PVST+ | MST |
|--|-------------|-----|
| Instances | = VLANs (many) | few (mapped, 1–15) |
| BPDU/CPU cost | scales with VLANs | bounded |
| Load balance | per VLAN | per instance (covers many VLANs) |
| Vendors | Cisco-only | 802.1s standard |
| Ideal | small/medium campus | large scale, provider, fabric |

- Same RSTP mechanics inside instances → fast convergence.

### 2.3 Region configuration essentials

```text
spanning-tree mst configuration
 name CORP-REGION                 ! same name on all switches
 revision 2                       ! bump on any topology/mapping change
 instance 1 vlan 1-50
 instance 2 vlan 51-100
 exit
spanning-tree mode mst
spanning-tree mst 1 priority 4096 ! per-instance root
spanning-tree mst 2 root primary
```

- Mismatched **name / revision / mapping** = switches in **different regions** → each
  group acts as its own MST region bridged by IST; load-balance and root expectations
  break. "Region boundary" is exam gold.
- **Instances supported: 0 and 1–15.** VLANs not mapped fall into **instance 0 (IST)**.

### 2.4 How MST scales & interops

- A region appears to outsiders as **one bridge** (via the IST) → a neighbor sees one
  spanning tree even if the region has 1000 VLANs.
- **MST ↔ PVST+/Rapid-PVST+ boundary**: Cisco maps the MST region's per-VLAN trees to
  the classic per-VLAN protocol at the edge — each VLAN's tree is presented to the PVST+
  neighbor (this is "PVST+ simulation"). Region-name mismatch here creates inconsistent
  behavior at the boundary — check `show spanning-tree mst border`.
- BPDU count stays stable regardless of VLAN count.

### 2.5 MST instance details

- **Instance 0 (IST)** is automatic and mandatory.
- Instance numbers: **0, and 1–15** (16 total on Cisco).
- Path costs/timers apply **per instance**, not per VLAN.
- VLAN→instance mapping is a region-wide parameter — must match to stay one region.

## 3. Configuration / Commands

```text
spanning-tree mst configuration
 name CORP
 revision 1
 instance 1 vlan 10-20
 instance 2 vlan 30-40
 exit
spanning-tree mode mst
spanning-tree mst 1 root primary
spanning-tree mst 2 root secondary

show spanning-tree mst
show spanning-tree mst configuration
show spanning-tree mst 1
show spanning-tree mst 1 interface Gi0/24
show spanning-tree mst border
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Load balance not working | mapping or name differs → different regions | `show spanning-tree mst configuration` on each |
| Root not as expected | per-instance priority not set / MAC tie | `spanning-tree mst N priority` |
| Strange boundary loops | PVST+↔MST simulation mismatch | `show spanning-tree mst border` |
| VLANs all on IST | never mapped to an instance | assign `instance N vlan ...` |
| Region split | revision/name drift after config change | bump revision truthfully on ALL switches |
| Legacy neighbor slow | port falls back to 802.1D at boundary | per-port migration, link type |

---

## 5. Exam Traps

- **MST = few instances mapped over many VLANs** — not "per VLAN."
- **Region definition = name + revision + VLAN map — all three** — mismatch = different regions.
- **Instance 0 (IST) is automatic and always there.**
- **Only instances 1–15 plus IST** can be defined on Cisco.
- **Outside the region MST appears as a single bridge / single spanning tree.**
- **RSTP mechanics** — MST instances converge as fast as RSTP.
- **Don't answer Rapid PVST+ for "scale to thousands of VLANs"** — choose MST.
