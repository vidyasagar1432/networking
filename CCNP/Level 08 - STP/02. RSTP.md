# RSTP (Rapid Spanning Tree Protocol)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**RSTP (IEEE 802.1w)** is the fast-evolution of STP: **sub-second convergence** (≈1–3 s
instead of 30–50 s) using **explicit port roles + proposal/agreement handshake** instead
of blind timer waiting. It's backward-compatible with classic STP and is the basis for
Rapid PVST+ (Cisco default). Note: RSTP itself is a **single spanning-tree instance for
all VLANs** — the per-VLAN superpowers come from **Rapid PVST+** (Level 08 note 04).

---

## 2. Core Concepts

### 2.1 The three big changes vs classic STP

| Change | Classic STP | RSTP |
|--------|-------------|------|
| Notification | rely on MaxAge/ForwardDelay | **explicit RSTP BPDU** (version 2, flag bits) |
| Port states | 5 | **3** (Discarding/Learning/Forwarding) |
| Roles | Root/Designated/other | Root/Designated/**Alternate/Backup** |
| Link failure detect | MaxAge 20 s | **3 × missed hello (6 s)** |
| Edge ports | need PortFast config | **native edge ports**, instant forwarding |

### 2.2 Port states simplified

| State | Forwards data | Learns MAC | RSTP |
|-------|---------------|------------|------|
| **Discarding** | no | no | blocking + listening merged |
| Learning | no | yes | — |
| Forwarding | yes | yes | — |

- No separate "listening" state — a discarding port moves straight toward Forwarding
  once its role is confirmed.

### 2.3 Port roles (RSTP adds readiness intelligence)

| Role | Purpose |
|------|---------|
| **Root port** | best path to root (each non-root switch) |
| **Designated port** | best port of the segment's designated switch |
| **Alternate port** | backup to the root path (discarding, ready) |
| **Backup port** | redundant path to the **same segment** (rare) |

- Alternate/Backup are "pre-computed" — they transition fast on failure (this is the RSTP
  equivalent of the old UplinkFast behavior, built-in).

### 2.4 How RSTP converges fast (proposal / agreement)

- A designated port sends a **Proposal**; the neighbor replies **Agreement**; the links
  go straight to Forwarding — **no ForwardDelay wait**.
- **Edge ports** (host-facing, i.e., PortFast-style) go to Forwarding immediately and
  **never** send proposals.
- RSTP BPDU is sent every **hello 2 s** (like STP) but carries fresh state each time;
  missing **3 × hello → link considered down** — no MaxAge liturgy.
- Works only on **point-to-point links**; a shared/legacy link falls back to 802.1D rules.

### 2.5 Link types and interaction with STP hello

| Link type | How identified | RSTP behavior |
|-----------|----------------|---------------|
| Point-to-point | full duplex | proposal/agreement fast convergence |
| Shared | half duplex | classic-style waiting, no handshake |
| Edge | PortFast/edge config | forwards immediately, no handshake |

### 2.6 RSTP timers vs STP

| Timer | Classic | RSTP note |
|-------|---------|-----------|
| Hello | 2 s | 2 s (kept) |
| MaxAge | 20 s | mostly irrelevant on P2P; link-down via missed hellos |
| ForwardDelay | 15 s | only used (rarely) for transitions to legacy neighbors |

- Backward compatible: an RSTP port talking to a classic-STP neighbor downgrades its
  behavior to STP rules **for that port only** (per-port migration).

### 2.7 RSTP vs Rapid PVST+

| | RSTP | Rapid PVST+ |
|--|------|-------------|
| Instances | **1 for all VLANs** | **1 per VLAN** |
| Convergence | fast | fast |
| Cisco default | — | **rapid-pvst** (IOS/Catalyst) |
| Typical use | standard, mixed-vendor | Cisco campus |

## 3. Configuration / Commands

```text
spanning-tree mode rapid-pvst         # Cisco per-VLAN RSTP (typical)
! or spanning-tree mode rstp          # single-instance RSTP

! Edge ports (native in RSTP)
interface Gi0/1
 spanning-tree portfast

show spanning-tree
show spanning-tree vlan 10
show spanning-tree detail
show spanning-tree interface Gi0/1
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Still 30 s to converge | a link is half-duplex/shared → 802.1D fallback | duplex check, link type |
| Port stuck discarding | no alternates; forward delay tuning | `show spanning-tree detail` |
| Legacy neighbor slow | RSTP port degraded to STP per-port | check neighbor RSTP support |
| Edge port still waiting | PortFast not applied / not "edge" | `spanning-tree portfast` |
| Root port flapping | BPDUs lost / unidirectional | UDLD + Loop Guard notes 13 |

## 5. Exam Traps

- **RSTP forward delay exists in the config but is not the driver** — agreement/proposal
  replaces it on RSTP-RSTP P2P links.
- **Alternate port** is the "ready backup" — the fastest failover.
- **3 states, not 5** — "listening" is merged into Discarding.
- **BPDU version 2** with flag bits encodes role/state/agreement — not just "TC/TCN."
- **Edge ports (PortFast) go Forwarding instantly** and send no handshake.
- **RSTP itself = one instance for all VLANs** — "per VLAN" is Rapid PVST+ (Cisco).
- **MaxAge is not how RSTP detects failure** — missed hellos (3×2 s = 6 s) are.
