# RSTP (Rapid Spanning Tree Protocol)

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**RSTP (Rapid Spanning Tree Protocol, IEEE 802.1w)** is the rapid evolution of classic STP (802.1D). It provides much faster Layer-2 convergence by using **explicit port roles, rapid state transitions, point-to-point link assumptions, and a proposal/agreement synchronization mechanism** rather than relying primarily on the long 802.1D timer sequence.

RSTP maintains the fundamental STP objective:

> **Allow Layer-2 redundancy while maintaining a loop-free forwarding topology.**

RSTP does **not** eliminate the Root Bridge election or STP path-selection process. It primarily improves **how quickly the topology can safely transition after a change**.

Cisco's per-VLAN implementation is:

```text
Rapid PVST+
```

---

# 2. RSTP Core Concepts

RSTP keeps the fundamental STP logic:

```text
1. Elect Root Bridge
        ↓
2. Select Root Port
        ↓
3. Select Designated Ports
        ↓
4. Identify redundant paths
        ↓
5. Keep unnecessary paths non-forwarding
```

The major improvement is the convergence mechanism:

```text
CLASSIC STP
    │
    ├── Blocking
    ├── Listening
    ├── Learning
    └── Forwarding
           │
           └── Timer-dependent transition

RSTP
    │
    ├── Discarding
    ├── Learning
    └── Forwarding
           │
           └── Rapid role-based transition
                 + Proposal/Agreement
```

---

# 3. RSTP Port States

RSTP reduces the five classic 802.1D states to three operational states.

|RSTP State|Forwards Data|Learns MAC|Purpose|
|---|--:|--:|---|
|**Discarding**|No|No|Prevents forwarding while the port is not ready|
|**Learning**|No|Yes|Learns source MAC addresses|
|**Forwarding**|Yes|Yes|Normal user-data forwarding|

### Important mapping

```text
802.1D STP             RSTP
--------------------------------
Blocking       ───────► Discarding
Listening      ───────► Discarding
Learning       ───────► Learning
Forwarding     ───────► Forwarding
Disabled       ───────► Not an RSTP operational state
```

> **Exam trap:** RSTP does **not** use Blocking, Listening, and Learning as its three states. Its operational states are **Discarding, Learning, and Forwarding**.

---

# 4. RSTP Port Roles

RSTP has four major port roles:

|Role|Purpose|
|---|---|
|**Root Port**|Best path from a non-root switch toward the Root Bridge|
|**Designated Port**|Best port for a segment toward the Root Bridge|
|**Alternate Port**|Backup path toward the Root Bridge|
|**Backup Port**|Backup path for a Designated Port on the same shared segment|

### Root Port

Every non-root switch has one Root Port:

```text
Non-root Switch
      │
      ▼
Best path to Root
      │
      ▼
Root Port
```

The Root Bridge itself has:

```text
No Root Port
```

---

## 4.1 Alternate Port

An **Alternate Port** provides an alternate path toward the Root Bridge.

Example:

```text
             ROOT
            /    \
           /      \
         SW1      SW2
           \      /
            \    /
             SW3
```

SW3 could have:

```text
SW3 → SW1 = Root Port
SW3 → SW2 = Alternate Port
```

If the Root Port fails, the Alternate Port may rapidly become the new Root Port and enter forwarding.

> **Key idea:** Alternate Port = **backup path toward the Root Bridge**.

---

## 4.2 Backup Port

A **Backup Port** is a redundant path to the **same shared segment** where another port on the same switch is already the Designated Port.

Conceptually:

```text
          Shared Segment
       ───────────────────
          │            │
       DP │            │ Backup
          │            │
        Switch
```

Backup Ports are mainly associated with **shared-media / half-duplex Ethernet scenarios** and are uncommon in modern point-to-point switched Ethernet networks.

> **Exam trap:**  
> **Alternate = backup path toward the Root Bridge**  
> **Backup = backup path for a Designated Port on the same segment**

---

# 5. Role vs State

This distinction is critical.

```text
ROLE
│
├── Root
├── Designated
├── Alternate
└── Backup

STATE
│
├── Discarding
├── Learning
└── Forwarding
```

A port has both a **role** and a **state**.

Examples:

```text
Root Port
    └── Forwarding

Designated Port
    └── Forwarding

Alternate Port
    └── Discarding

Backup Port
    └── Discarding
```

> **Never use "Blocking" as an RSTP port role.**  
> Blocking describes the behavior of classic STP; RSTP uses **Discarding** as the corresponding operational state.

---

# 6. Proposal and Agreement

This is one of the most important RSTP mechanisms.

Classic STP relies heavily on timers before a port can safely transition.

RSTP uses a **Proposal/Agreement handshake** to rapidly synchronize the topology.

### Basic process

```text
                 SW1
                  │
            Proposal BPDU
                  │
                  ▼
                 SW2
                  │
          Synchronize ports
                  │
                  ▼
             Agreement
                  │
                  ▼
          Rapid Forwarding
```

---

## 6.1 Detailed synchronization

Suppose SW1 wants its port toward SW2 to become Designated and forward.

```text
SW1
 │
 │ Proposal
 ▼
SW2
 │
 ├── Determines its best Root Port
 │
 ├── Synchronizes other relevant
 │   non-edge ports
 │
 └── Sends Agreement
          │
          ▼
SW1 can rapidly transition
its proposed port toward
Forwarding
```

The important concept is:

> **RSTP does not blindly transition a port to forwarding. It uses synchronization and agreement to maintain a loop-free topology.**

---

# 7. How RSTP Detects Failures

RSTP does not have to wait for the classic 802.1D Max Age process in every failure scenario.

It uses:

- Frequent BPDUs
    
- Port roles
    
- Link status
    
- Proposal/Agreement
    
- Alternate ports
    
- Rapid topology changes
    

### Example

```text
             ROOT
            /    \
           /      \
         SW1      SW2
           \      /
            \    /
             SW3
```

Normal:

```text
SW3 → SW1 = Root Port
SW3 → SW2 = Alternate
```

If the Root Port fails:

```text
Root Port fails
       ↓
Alternate Port detected
       ↓
Alternate becomes Root Port
       ↓
Rapid transition
       ↓
Forwarding
```

This is one of the biggest practical advantages of RSTP.

---

# 8. RSTP BPDUs

RSTP changes BPDU behavior compared with classic 802.1D.

### Important rule

> **Every RSTP switch generates BPDUs.**

Do not think of RSTP as simply:

```text
Root
  ↓
BPDU
  ↓
Non-root switch relays it
```

Instead:

```text
Every RSTP switch
       │
       ├── Generates BPDUs
       │
       ├── Receives BPDUs
       │
       ├── Compares STP information
       │
       └── Uses BPDUs for rapid synchronization
```

RSTP BPDUs contain STP information such as:

- Root Bridge ID
    
- Root Path Cost
    
- Sender Bridge ID
    
- Sender Port ID
    
- Timer information
    
- RSTP-specific role/state flags
    
- Proposal/Agreement information
    
- Topology Change information
    

---

# 9. RSTP BPDU Hello Behavior

The default Hello interval remains:

```text
2 seconds
```

A major difference is that RSTP switches actively generate BPDUs on their designated ports rather than relying on the classic "root originates and downstream switches relay" model.

### Important nuance

RSTP can use the absence of expected BPDUs for failure detection.

A commonly used rule of thumb is:

```text
3 missed BPDUs
      ↓
Neighbor considered lost
```

With a default 2-second Hello interval:

```text
3 × 2 s ≈ 6 s
```

However, do **not** confuse this with the actual rapid convergence time of every topology failure.

An alternate path can often transition rapidly without waiting for a full Max Age expiration.

> **Exam focus:** RSTP is not simply "6-second convergence." Failure detection and topology convergence are separate concepts.

---

# 10. RSTP Link Types

RSTP uses link type information to determine how rapidly a port can transition.

There are two important categories:

```text
Point-to-Point
Shared
```

### Point-to-Point

Typical full-duplex switch-to-switch Ethernet:

```text
SW1 ═════════ SW2
       Full Duplex
```

Point-to-point links are ideal for the RSTP Proposal/Agreement mechanism.

### Shared

Historically associated with half-duplex/shared-media Ethernet.

Modern switched Ethernet networks are overwhelmingly full-duplex and therefore typically operate as point-to-point links.

> **CCNP Tip:** Don't equate "Ethernet" automatically with point-to-point. The operational duplex/link characteristics matter.

---

# 11. Edge Ports

RSTP introduces the concept of an **Edge Port**.

An edge port connects to an end device that does not participate in STP.

Typical example:

```text
Switch ───────── PC
         Edge Port
```

Because an end host should not create an L2 loop, the switch can immediately place the edge port into forwarding.

Cisco commonly configures this with:

```text
interface GigabitEthernet0/10
 spanning-tree portfast
```

### Important

Edge ports should normally connect to:

- PCs
    
- Servers
    
- Printers
    
- IP phones
    
- Other end devices
    

They should **not** normally connect to another switch.

---

# 12. BPDU Guard

Because an edge/PortFast port is expected to connect to an end device, receiving a BPDU there can indicate an unexpected switch connection or possible Layer-2 loop.

Cisco provides:

```text
spanning-tree portfast bpduguard default
```

or per interface:

```text
interface GigabitEthernet0/10
 spanning-tree portfast
 spanning-tree bpduguard enable
```

Conceptually:

```text
EDGE PORT
    │
    ▼
Expected: End Device
    │
    └── No BPDU

Unexpected:
Another Switch
    │
    ▼
BPDU received
    │
    ▼
BPDU Guard
    │
    ▼
Protect the network
```

> **Exam trap:** PortFast does **not** disable STP. It causes the port to transition rapidly as an edge port.

---

# 13. RSTP Topology Changes

RSTP simplifies topology-change handling compared with classic 802.1D.

RSTP uses the **Topology Change (TC) flag** in BPDUs rather than relying on the classic TCN propagation process in the same way.

Conceptually:

```text
Topology Change
      │
      ▼
RSTP BPDU with TC information
      │
      ▼
Neighboring switches
      │
      ▼
MAC information updated/aged
      │
      ▼
Network converges
```

### Important distinction

```text
Classic STP
    TCN mechanism
       ↓
    Root processes notification
       ↓
    TC indication propagated

RSTP
    TC information handled directly
    through RSTP BPDUs
```

RSTP therefore has a more direct topology-change mechanism.

# 14. RSTP vs Classic STP

|Feature|Classic STP|RSTP|
|---|---|---|
|Standard|IEEE 802.1D|IEEE 802.1w|
|Main Goal|Prevent L2 loops|Prevent L2 loops + rapid convergence|
|States|Blocking, Listening, Learning, Forwarding|Discarding, Learning, Forwarding|
|Roles|Root, Designated, Non-designated|Root, Designated, Alternate, Backup|
|BPDU Generation|Root-centric behavior|Every switch generates BPDUs|
|Synchronization|Timer-driven|Proposal/Agreement|
|Alternate Path|Blocking/non-designated|Explicit Alternate role|
|Edge Port|PortFast concept|Explicit edge behavior|
|Convergence|Slow|Rapid|
|Cisco Per-VLAN Version|PVST+|Rapid PVST+|

# 15. RSTP vs 802.1D Convergence

### Classic STP

```text
Failure
   ↓
Wait for STP information to age
   ↓
Listening
   ↓
Learning
   ↓
Forwarding
```

Potentially:

```text
~30–50 seconds
```

depending on the failure and timers involved.

### RSTP

```text
Failure
   ↓
Detect topology change
   ↓
Use Alternate Port / Proposal-Agreement
   ↓
Rapid transition
   ↓
Forwarding
```

RSTP can therefore converge much faster.

> **Important:** Do not write "RSTP always converges in 1–3 seconds." RSTP is designed for rapid convergence, but the exact time depends on topology, failure type, link characteristics, device behavior, and configuration.

# 16. Cisco Rapid PVST+

Cisco supports RSTP on a per-VLAN basis using:

```text
Rapid PVST+
```

Configuration:

```text
spanning-tree mode rapid-pvst
```

Conceptually:

```text
VLAN 10 → RSTP instance
VLAN 20 → RSTP instance
VLAN 30 → RSTP instance
```

Therefore, each VLAN can independently have:

- Root Bridge
    
- Root Ports
    
- Designated Ports
    
- Alternate Ports
    
- STP topology
    

Example:

```text
VLAN 10
   SW1 = Root

VLAN 20
   SW2 = Root
```

This allows STP load distribution across VLANs.

# 19. Troubleshooting

|Symptom|Possible Cause|Check|
|---|---|---|
|**Unexpected Root**|Incorrect STP priority|`show spanning-tree root`|
|**Slow convergence**|Classic STP still active|`show spanning-tree summary`|
|**Alternate port not forwarding after failure**|Role/state or topology issue|`show spanning-tree vlan 10`|
|**Unexpected blocking/discarding port**|Another path has better STP information|Check Root Path Cost / BID|
|**Port immediately goes down after BPDU**|BPDU Guard triggered|`show interfaces status err-disabled`|
|**Loop after connecting switch**|PortFast used on switch-facing port|Check edge/PortFast configuration|
|**Wrong Root Port**|Cost/priority/path selection|Check STP cost and port priority|
|**MAC flapping**|L2 loop or topology instability|Check STP topology and MAC table|
|**No rapid transition**|Link type/role/configuration issue|Check interface and STP details|

### Troubleshooting sequence

```text
1. Confirm STP mode
        ↓
2. Identify Root Bridge
        ↓
3. Identify Root Port
        ↓
4. Identify Designated / Alternate ports
        ↓
5. Check port state
        ↓
6. Check Root Path Cost
        ↓
7. Check port priority/cost
        ↓
8. Check edge/PortFast/BPDU Guard
        ↓
9. Check topology changes
```

# 20. RSTP Compatibility with Classic STP

RSTP was designed to interoperate with legacy 802.1D STP.

A mixed environment can therefore contain:

```text
RSTP Switch ───── RSTP Switch
      │
      │
      └────────── STP Switch
```

However, connecting to a legacy 802.1D switch can cause that portion of the topology to operate with **slower 802.1D behavior**, limiting rapid convergence across that boundary.

> **CCNP idea:** RSTP is backward-compatible, but compatibility with legacy STP can reduce the benefits of rapid convergence.

---

# 21. Important RSTP Decision Logic

RSTP does **not** replace the fundamental STP path-selection logic.

The basic BPDU comparison remains:

```text
1. Lowest Root Bridge ID
2. Lowest Root Path Cost
3. Lowest Sender Bridge ID
4. Lowest Sender Port ID
```

Then the switch determines roles such as:

```text
Root Port
Designated Port
Alternate Port
Backup Port
```

> **Important:** The four-field comparison is the BPDU-information comparison order. Actual Root Port / Designated Port selection also considers the local port/interface context and tie-breakers.

# 23. Exam Traps

### Trap 1 — RSTP does not eliminate the Root Bridge

RSTP still elects a Root Bridge using the lowest Bridge ID.

---

### Trap 2 — RSTP has 3 states, not 5

```text
Discarding
Learning
Forwarding
```

---

### Trap 3 — Alternate is a role, not a state

Correct:

```text
Alternate Port → Discarding
```

Not:

```text
Alternate = state
```

---

### Trap 4 — Backup is not the same as Alternate

```text
Alternate = alternate path toward Root

Backup = backup path for a Designated Port
         on the same shared segment
```

---

### Trap 5 — RSTP BPDUs

Don't memorize:

> "Only the Root generates BPDUs."

RSTP switches generate BPDUs themselves.

---

### Trap 6 — Proposal/Agreement

Proposal/Agreement is a major mechanism responsible for RSTP's rapid synchronization.

---

### Trap 7 — PortFast

PortFast does not disable STP.

It allows an edge port to transition rapidly toward forwarding.

---

### Trap 8 — BPDU Guard

BPDU Guard protects edge ports from unexpected BPDUs.

If a BPDU arrives where one is not expected, the port can be placed into an error-disabled condition.

---

### Trap 9 — RSTP is not "always 1–3 seconds"

RSTP is designed for rapid convergence, but exact convergence time depends on topology and failure conditions.

---

### Trap 10 — Point-to-point matters

RSTP's rapid Proposal/Agreement mechanism is particularly effective on **full-duplex point-to-point links**.

# 26. Final CCNP Takeaway

Classic STP primarily relies on **timers** to safely transition the topology.

RSTP keeps the same fundamental spanning-tree objective but replaces much of that slow process with **explicit roles, rapid synchronization, and proposal/agreement**.

```text
CLASSIC STP

Failure
   ↓
Timer-based process
   ↓
Listening
   ↓
Learning
   ↓
Forwarding
   ↓
Slow convergence
```

```text
RSTP

Failure
   ↓
Detect topology change
   ↓
Use explicit Alternate/Root/Designated roles
   ↓
Proposal / Agreement where synchronization is required
   ↓
Rapid role/state transition
   ↓
Forwarding
```

```text
                 RSTP
                  │
        ┌─────────┴─────────┐
        │                   │
    STP LOGIC          RAPID LOGIC
        │                   │
    Root Bridge       Proposal/Agreement
        │                   │
    Root Port          Synchronization
        │                   │
 Designated Port       Rapid Transition
        │                   │
 Alternate/Backup      Edge Ports
        │                   │
        └─────────┬─────────┘

          LOOP-FREE + RAPID

```

> **Remember:**  
> **RSTP = same fundamental STP topology calculation + faster convergence mechanism.**
