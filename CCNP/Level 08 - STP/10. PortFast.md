# PortFast

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**PortFast** is a Cisco feature that allows an **edge port** connected to an end host  
to transition to **Forwarding immediately**, instead of waiting through the normal  
802.1D STP Listening and Learning states.

PortFast is designed for **host-facing ports** such as PCs, servers, printers, IP  
phones, cameras, and access points.

**PortFast does NOT disable STP.** STP remains enabled and BPDUs can still be processed.  
PortFast simply tells STP that the port is expected to be connected to an endpoint,  
so the port can enter Forwarding immediately.

In **RSTP (802.1w)** terminology, a PortFast port is an **edge port**.

---

## 2. Core Concepts

### 2.1 What PortFast is for

|Use PortFast for|Do NOT normally use PortFast for|
|---|---|
|PCs / workstations|Switch-to-switch links|
|Servers|Distribution/core uplinks|
|Printers|Normal Layer 2 inter-switch trunks|
|IP phones|Any link that may connect another bridge|
|Cameras|Unknown infrastructure links|
|Access points|Switch-facing ports|

### Key idea

> **PortFast = “I expect an end host here, not another switch.”**

If another switch is connected to a PortFast port, a Layer 2 loop can potentially form  
before normal STP protection can react.

Therefore, **PortFast should normally be paired with BPDU Guard** on edge ports.

---

## 2.2 What PortFast actually changes

### Traditional 802.1D STP

A newly active port normally goes through:

```text
Blocking
   ↓
Listening
   ↓
Learning
   ↓
Forwarding
```

The normal Listening and Learning periods are approximately:

```text
15 seconds Listening
+
15 seconds Learning
=
30 seconds
```

PortFast allows an eligible edge port to move directly toward:

```text
Link Up
   ↓
Forwarding
```

### Important

PortFast:

- Skips the normal STP transition delay for an edge port
    
- Does NOT disable STP
    
- Does NOT remove the port from the spanning-tree topology
    
- Does NOT make a switch-facing link safe
    
- Does NOT replace BPDU Guard
    

---

## 2.3 PortFast and RSTP Edge Ports

With **RSTP (802.1w)**, Cisco uses the concept of an **edge port**.

A port configured with PortFast is treated as an edge port.

```text
PortFast
   ↓
Edge Port
   ↓
Immediate Forwarding
```

RSTP is already designed for rapid convergence, so the old 802.1D  
Listening/Learning delay is not the normal mechanism used for rapid edge-port  
activation.

### Important distinction

Do not think:

> PortFast disables RSTP.

Think:

> PortFast tells STP/RSTP that this port is an edge/host-facing port and can  
> safely transition to Forwarding immediately.

---

## 2.4 PortFast + BPDU Guard

**BPDU Guard** protects PortFast/edge ports from receiving BPDUs.

If a BPDU is received on a port protected by BPDU Guard:

```text
BPDU received
     ↓
BPDU Guard violation
     ↓
Port placed into err-disabled state
```

This protects against accidentally connecting a switch to an edge port.

### Recommended design

```text
End Host
   │
   │
Access Port
   │
PortFast
   +
BPDU Guard
```

### Behavior

|Scenario|PortFast only|PortFast + BPDU Guard|
|---|---|---|
|Normal host connected|Immediate forwarding|Immediate forwarding|
|Rogue/accidental switch connected|Potential loop risk|BPDU → err-disabled|
|STP protection|Limited|Strong edge protection|

### Important

PortFast and BPDU Guard are **separate features**.

This command:

```text
spanning-tree portfast bpduguard default
```

globally enables BPDU Guard on **PortFast-enabled ports**.

It does not mean that configuring PortFast by itself automatically enables  
BPDU Guard.

---

## 2.5 PortFast + BPDU Filter

**BPDU Filter and BPDU Guard are NOT the same.**

|Feature|Purpose|Result when BPDU appears|
|---|---|---|
|PortFast|Fast edge-port transition|Fast forwarding|
|BPDU Guard|Protect edge ports|Port goes err-disabled|
|BPDU Filter|Suppress/filter BPDUs|Can effectively remove STP protection|

### BPDU Guard

```text
BPDU received
     ↓
Protect the network
     ↓
Err-disable port
```

### BPDU Filter

BPDU Filter is dangerous when used incorrectly because it can suppress BPDUs and  
prevent normal STP behavior from protecting the topology.

There are two important Cisco behaviors:

- **Interface-level BPDU Filter** can suppress transmitted BPDUs and ignore received  
    BPDUs on the interface.
    
- **Global PortFast BPDU Filter** suppresses BPDUs while the port is operating as an  
    edge/PortFast port; if a BPDU is received, PortFast is disabled on that port so  
    the port can participate in STP normally.
    

### Exam rule

> **BPDU Guard protects. BPDU Filter suppresses.**

For normal user-facing edge ports, **BPDU Guard is generally the safer choice**.

---

## 2.6 Global PortFast Configuration

Cisco provides a global PortFast default:

```text
spanning-tree portfast default
```

This enables PortFast on **access ports**.

It does **not** enable PortFast on normal trunks.

This makes the global default safer than blindly enabling PortFast on every  
interface.

### Example

```text
spanning-tree portfast default
```

Then:

```text
show spanning-tree summary
```

can be used to verify the spanning-tree configuration.

---

## 2.7 PortFast on Trunks

PortFast can be explicitly configured on a trunk with:

```text
spanning-tree portfast trunk
```

This should only be used when the trunk is genuinely **edge/host-facing**.

Examples can include certain:

- Hypervisor connections
    
- Server virtualization hosts
    
- Host-facing devices requiring a trunk
    
- Other explicitly designed edge trunks
    

### Do NOT normally use it on:

```text
Switch ───── Switch
```

or:

```text
Access Switch ───── Distribution Switch
```

Normal switch-to-switch trunks should participate normally in STP.

## 3. Configuration

### 3.1 Per-interface PortFast

```text
interface GigabitEthernet0/1
 switchport mode access
 spanning-tree portfast
```

### 3.2 PortFast + BPDU Guard

```text
interface GigabitEthernet0/1
 switchport mode access
 spanning-tree portfast
 spanning-tree bpduguard enable
```

This is the common recommended configuration for a host-facing access port.

---

### 3.3 Global PortFast + BPDU Guard

```text
spanning-tree portfast default
spanning-tree portfast bpduguard default
```

This provides a convenient protection model for PortFast-enabled access ports.

---

### 3.4 Host-facing trunk

Only when intentionally designed as an edge trunk:

```text
interface GigabitEthernet0/1
 switchport mode trunk
 spanning-tree portfast trunk
 spanning-tree bpduguard enable
```

Use this only when the connected device is expected to behave as an endpoint  
rather than as another Layer 2 bridge.

## 5. Troubleshooting

|Symptom|Likely Cause|Fix|
|---|---|---|
|Host waits during startup|PortFast not enabled|`spanning-tree portfast`|
|Port becomes err-disabled|BPDU Guard received a BPDU|Identify why a BPDU-producing device is connected|
|Unexpected loop|PortFast used on a switch-facing link|Remove PortFast and correct topology|
|Port does not show expected edge behavior|PortFast not applied or port is not eligible|Check interface mode/configuration|
|Edge port unexpectedly loses PortFast|BPDU received under global BPDU Filter behavior|Investigate connected device and STP topology|
|Trunk does not get PortFast from global default|Global PortFast default targets access ports|Use explicit `spanning-tree portfast trunk` only when appropriate|

## 6. PortFast vs UplinkFast

|Feature|PortFast|UplinkFast|
|---|---|---|
|Purpose|Fast host-port activation|Fast uplink/root-port failover|
|Designed for|Edge/host ports|Uplink paths|
|Main event|Link comes up|Active uplink fails|
|STP generation|Cisco feature|Legacy Cisco STP enhancement|
|RSTP equivalent|Edge-port behavior|Built into RSTP|

In modern RSTP/Rapid PVST+, the functionality provided by legacy UplinkFast is  
built into the protocol, so the old UplinkFast configuration is normally unnecessary.

## 7. PortFast vs BPDU Guard vs BPDU Filter

```text
                    STP EDGE PROTECTION
                           │
          ┌────────────────┼────────────────┐
          │                │                │
       PortFast        BPDU Guard       BPDU Filter
          │                │                │
          │                │                │
    Fast Forwarding    Detect BPDU      Suppress/filter
          │                │                │
          │                ↓                │
          │          Err-disable            │
          │                                 │
          └───────────────┬─────────────────┘
                          │
                    Different jobs
```

### Mental model

```text
PortFast
   └── "Go Forward quickly; this should be an endpoint."

BPDU Guard
   └── "If a BPDU appears here, shut the port down."

BPDU Filter
   └── "Suppress/filter BPDUs; use with extreme care."
```

## 9. Exam Traps

### Trap 1 — PortFast disables STP

**Wrong:**

```text
PortFast = STP disabled
```

**Correct:**

```text
PortFast = fast edge-port transition
```

STP remains active.

---

### Trap 2 — PortFast is for switch-to-switch links

**Wrong:**

```text
Switch ─── PortFast ─── Switch
```

**Correct:**

```text
Switch ─── PortFast ─── Host
```

---

### Trap 3 — PortFast automatically enables BPDU Guard

**Wrong:**

```text
spanning-tree portfast
```

automatically means BPDU Guard is enabled.

**Correct:**

BPDU Guard must be configured separately, either per interface:

```text
spanning-tree bpduguard enable
```

or through the global default:

```text
spanning-tree portfast bpduguard default
```

---

### Trap 4 — BPDU Guard and BPDU Filter are equivalent

They are not.

```text
BPDU Guard
    → BPDU received
    → err-disable
```

```text
BPDU Filter
    → suppress/filter BPDUs
    → potentially removes STP protection
```

---

### Trap 5 — Global PortFast applies to trunks

**Wrong:**

```text
spanning-tree portfast default
```

enables PortFast on every port.

**Correct:**

The global default applies PortFast to **access ports**, not normal trunks.

---

### Trap 6 — PortFast means the port has no STP role

PortFast does not eliminate STP participation.

The port is still part of the spanning-tree topology.

The important distinction is:

```text
Normal STP port
    → normal transition process

PortFast / Edge port
    → immediate Forwarding behavior
```
