# Rapid PVST+

> **Level 08 · STP** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Rapid PVST+ (Rapid Per-VLAN Spanning Tree Plus)** is Cisco's implementation of **RSTP (IEEE 802.1w) running as a separate spanning-tree instance for each VLAN**.

It combines:

```text
Rapid PVST+
     │
     ├── RSTP mechanics
     │      ├── Rapid convergence
     │      ├── Proposal / Agreement
     │      ├── Alternate / Backup roles
     │      └── Discarding / Learning / Forwarding
     │
     └── PVST+ architecture
            └── One STP instance per VLAN
```

Each VLAN can therefore have its own:

- Root Bridge
    
- Root Port
    
- Designated Ports
    
- Alternate / Backup Ports
    
- Path costs
    
- Blocking/discarding decisions
    

This allows **per-VLAN STP load balancing**.

Cisco configuration:

```text
spanning-tree mode rapid-pvst
```

> **Important:** Rapid PVST+ is **RSTP per VLAN**. Do not confuse it with classic **PVST+**, which is based on 802.1D STP.

---

# 2. Rapid PVST+ Architecture

## 2.1 One RSTP instance per VLAN

Example:

```text
VLAN 10
    │
    └── RSTP Instance
          └── Root = SW1

VLAN 20
    │
    └── RSTP Instance
          └── Root = SW2

VLAN 30
    │
    └── RSTP Instance
          └── Root = SW1
```

Therefore:

```text
VLAN 10 → independent STP topology
VLAN 20 → independent STP topology
VLAN 30 → independent STP topology
```

A link can therefore be:

```text
VLAN 10 → Forwarding
VLAN 20 → Discarding
```

on the **same physical interface**, because each VLAN has an independent spanning-tree instance.

---

# 3. Rapid PVST+ vs PVST+

|Feature|PVST+|Rapid PVST+|
|---|---|---|
|Foundation|802.1D STP|802.1w RSTP|
|Instances|One per VLAN|One per VLAN|
|Convergence|Slow|Rapid|
|States|Blocking, Listening, Learning, Forwarding|Discarding, Learning, Forwarding|
|Roles|Root, Designated, Non-designated|Root, Designated, Alternate, Backup|
|Proposal/Agreement|No RSTP mechanism|Yes|
|Edge behavior|PortFast|PortFast / RSTP edge behavior|
|Cisco implementation|Per-VLAN classic STP|Per-VLAN RSTP|

### Key memory

```text
PVST+
   = STP per VLAN

Rapid PVST+
   = RSTP per VLAN
```

---

# 4. Why Rapid PVST+ Is Useful

## 4.1 Rapid convergence

Rapid PVST+ inherits RSTP's rapid-convergence mechanisms:

- Explicit port roles
    
- Alternate Ports
    
- Proposal/Agreement
    
- Rapid synchronization
    
- Edge ports
    
- Faster topology-change handling
    

It does **not** normally rely on the classic 802.1D:

```text
Max Age
   ↓
Listening
   ↓
Learning
   ↓
Forwarding
```

sequence for every topology change.

---

## 4.2 Per-VLAN load balancing

Different VLANs can use different Root Bridges.

Example:

```text
              DIST1
             /     \
            /       \
           /         \
        ACCESS       ACCESS
           \         /
            \       /
             \     /
              DIST2
```

Configure:

```text
VLAN 10 → DIST1 = Root
VLAN 20 → DIST2 = Root
```

Result:

```text
VLAN 10 traffic → prefers path toward DIST1

VLAN 20 traffic → prefers path toward DIST2
```

This allows both physical uplinks to carry useful traffic for different VLANs.

> **Important:** Rapid PVST+ does not automatically load-balance traffic. You achieve load distribution by **intentionally placing different VLAN roots on different switches**.

# 5. Bridge ID and Extended System ID

Rapid PVST+ uses the same fundamental Bridge ID concept as PVST+.

Conceptually:

```text
Bridge ID
│
├── Bridge Priority
│      │
│      ├── Configured priority
│      └── 12-bit VLAN ID
│
└── MAC Address
```

The Extended System ID allows the VLAN ID to participate in the Bridge ID.

Therefore, configurable priorities occur in increments of:

```text
4096
```

Examples:

```text
0
4096
8192
12288
...
32768   ← default
...
61440
```

For example:

```text
Configured priority = 4096
VLAN ID             = 10

Effective priority  = 4106
```

### Important

The VLAN ID is part of the Bridge ID, but the configurable bridge priority itself is still expressed in **multiples of 4096**.

---

# 6. Root Bridge Per VLAN

Each Rapid PVST+ instance independently elects its Root Bridge.

Example:

```text
VLAN 10

SW1 priority = 4096
SW2 priority = 8192

Result:
SW1 = Root
```

For VLAN 20:

```text
VLAN 20

SW1 priority = 8192
SW2 priority = 4096

Result:
SW2 = Root
```

Therefore:

```text
VLAN 10 → SW1 Root
VLAN 20 → SW2 Root
```

---

# 7. Root Configuration

## 7.1 Explicit priority

```text
spanning-tree vlan 10 priority 4096
```

This gives the switch a lower priority and makes it more likely to become Root Bridge.

---

## 7.2 Root Primary

```text
spanning-tree vlan 10 root primary
```

Cisco's macro attempts to make the switch the preferred Root Bridge by adjusting its priority appropriately.

Do not memorize:

```text
root primary = always 24576
```

The command can select a lower priority when necessary.

---

## 7.3 Root Secondary

```text
spanning-tree vlan 10 root secondary
```

This makes the switch a predictable backup candidate for the Root Bridge.

Under common default conditions, Cisco uses:

```text
28672
```

# 8. Rapid PVST+ Port Roles

Each VLAN instance can have its own port role.

RSTP roles are:

```text
Root
Designated
Alternate
Backup
```

Example:

```text
VLAN 10

SW1 = Root
 │
 ├── Designated Port
 │
 ▼
SW2
 │
 └── Root Port
```

A redundant path could become:

```text
Alternate Port
```

for that VLAN.

The same physical port can have a different role for another VLAN:

```text
Gi0/1

VLAN 10 → Root Port
VLAN 20 → Designated Port
VLAN 30 → Alternate Port
```

> **CCNP concept:** STP role is evaluated **per Rapid PVST+ instance**, not simply per physical interface.

---

# 9. Rapid PVST+ States

The operational RSTP states are:

|State|Forwards Data|Learns MAC|
|---|--:|--:|
|**Discarding**|No|No|
|**Learning**|No|Yes|
|**Forwarding**|Yes|Yes|

Do not use classic STP states as the primary Rapid PVST+ state model.

```text
PVST+
   Blocking
   Listening
   Learning
   Forwarding

Rapid PVST+
   Discarding
   Learning
   Forwarding
```

---

# 10. Proposal / Agreement

Rapid PVST+ inherits RSTP's **Proposal/Agreement** mechanism.

Example:

```text
SW1
 │
 │ Proposal
 ▼
SW2
 │
 ├── Synchronize
 │
 └── Agreement
       │
       ▼
SW1 rapidly transitions
toward Forwarding
```

The purpose is to ensure that the topology is synchronized before a new Designated Port rapidly enters forwarding.

This avoids relying on the long classic-STP timer sequence.

---

# 11. Rapid Convergence

A common misconception is:

> "Rapid PVST+ takes 1–3 seconds."

This is not a fixed protocol timer.

Rapid PVST+ can converge very quickly because it uses:

- Alternate Ports
    
- Proposal/Agreement
    
- Rapid synchronization
    
- Edge ports
    
- Physical link-state information
    

### Example

```text
             ROOT
            /    \
           /      \
         SW1      SW2
           \      /
            \    /
             SW3
```

Normal:

```text
SW3 → SW1 = Root Port
SW3 → SW2 = Alternate Port
```

If the Root Port fails:

```text
Root Port fails
      ↓
Alternate Port available
      ↓
Alternate becomes Root Port
      ↓
Rapid transition
      ↓
Forwarding
```

The Alternate Port provides a precomputed backup path.

> **Important:** Exact convergence time depends on the failure, topology, link type, device behavior, and configuration. Do not memorize `1–3 seconds` as a guaranteed Rapid PVST+ convergence time.

---

# 12. BPDU Failure Detection

Rapid PVST+ uses RSTP BPDU behavior.

The default Hello interval is:

```text
2 seconds
```

RSTP can consider a neighbor lost after approximately **three missed BPDUs**.

Therefore:

```text
3 × 2 seconds ≈ 6 seconds
```

is a useful **failure-detection rule of thumb**.

However:

> **6 seconds is not the Rapid PVST+ convergence time.**

If a usable Alternate Port already exists, the topology may transition without waiting six seconds.

```text
Failure Detection
       ≠
Convergence Time
```

This distinction is important for CCNP.

---

# 13. Edge Ports and PortFast

Rapid PVST+ supports RSTP edge-port behavior.

Cisco commonly configures an end-device-facing port with:

```text
interface GigabitEthernet0/10
 spanning-tree portfast
```

Typical edge devices:

- PC
    
- Server
    
- Printer
    
- IP phone
    
- Other end hosts
    

PortFast allows the port to move rapidly toward forwarding rather than waiting for normal STP synchronization.

### Important

PortFast should normally be used only on ports connected to **end devices**.

Do not use PortFast as a replacement for STP on switch-to-switch links.

---

# 14. BPDU Guard

Because an edge/PortFast port is expected to connect to an end device, receiving a BPDU can indicate an unexpected switch connection.

Configure:

```text
interface GigabitEthernet0/10
 spanning-tree portfast
 spanning-tree bpduguard enable
```

Or globally:

```text
spanning-tree portfast bpduguard default
```

Concept:

```text
Edge Port
    │
    ▼
Expected: End Device
    │
    └── No BPDU

Unexpected Switch
    │
    ▼
BPDU received
    │
    ▼
BPDU Guard
    │
    ▼
Port protected / error-disabled
```

> **Exam trap:** PortFast does not disable STP. BPDU Guard provides protection against unexpected BPDUs on an edge port.

---

# 15. Path Cost Per VLAN

Rapid PVST+ allows each VLAN instance to have its own STP path selection.

Example:

```text
interface GigabitEthernet0/1
 spanning-tree vlan 10 cost 4
```

A different VLAN can have a different cost:

```text
interface GigabitEthernet0/1
 spanning-tree vlan 20 cost 19
```

This allows different VLANs to prefer different paths.

### Example

```text
VLAN 10
Gi0/1 cost = 4
Gi0/2 cost = 19

→ Gi0/1 preferred
```

For VLAN 20:

```text
Gi0/1 cost = 19
Gi0/2 cost = 4

→ Gi0/2 preferred
```

---

# 16. STP Port Priority Per VLAN

Port priority can also influence selection when the relevant STP information is tied.

Example:

```text
interface GigabitEthernet0/1
 spanning-tree vlan 10 port-priority 64
```

The default Cisco STP port priority is commonly:

```text
128
```

Port priority is configured in increments of:

```text
16
```

Remember:

```text
Bridge Priority
    ↓
Root Bridge election

Port Priority
    ↓
Port selection / tie-breaking
```

---

# 17. Interoperability with Classic PVST+

Rapid PVST+ is designed to interoperate with legacy STP.

If a Rapid PVST+ switch communicates with a classic 802.1D STP neighbor, the RSTP process must interoperate with the slower protocol on that connection/instance.

Conceptually:

```text
Rapid PVST+ ───── Rapid PVST+
     │
     │
     └──── Classic PVST+ neighbor
                 │
                 ▼
          Legacy STP behavior
          on that boundary
```

This can reduce the rapid-convergence benefits across the legacy boundary.

> **CCNP idea:** Backward compatibility exists, but a legacy 802.1D segment can behave according to slower STP mechanisms.

---

# 18. Interoperability with MST

MST and Rapid PVST+ can interoperate at an STP boundary, but the behavior is more complex than simply "one VLAN equals one tree."

MST uses:

```text
MST Region
   │
   ├── Multiple VLANs
   │
   └── Mapped to fewer MST instances
```

At an MST boundary, the MST region participates in the external spanning-tree topology through the **Common and Internal Spanning Tree (CIST)**.

Cisco also has PVST+/MST interoperability rules and consistency requirements.

For CCNP, remember:

```text
Rapid PVST+
    │
    ├── One instance per VLAN
    │
    ▼
MST
    │
    ├── VLANs mapped into fewer instances
    │
    ▼
Better scalability
```

> **Do not memorize "MST is simply one tree for all VLANs."** MST can contain multiple instances, each with its own topology, while VLANs are mapped to those instances.

---

# 19. Rapid PVST+ vs MST

|Feature|Rapid PVST+|MST|
|---|---|---|
|Foundation|RSTP|RSTP|
|VLAN handling|One instance per VLAN|Multiple VLANs mapped to instances|
|Root topology|Per VLAN|Per MST instance|
|Scale|Instance count grows with VLANs|Fewer instances|
|Configuration|Relatively simple|More complex|
|Load balancing|Per VLAN|Per MST instance|
|Large VLAN environments|More CPU/memory overhead|More scalable|
|Standard|Cisco implementation|IEEE 802.1s / 802.1Q MST|
|Best use|Smaller/medium Cisco VLAN environments|Large environments with many VLANs|

### Exam mental model

```text
Few VLANs
    ↓
Rapid PVST+ is simple

Many VLANs
    ↓
Many STP instances
    ↓
Consider MST
```

Do not treat this as an absolute rule. Actual platform scale, topology, operational requirements, and design standards matter.

---

# 20. Operational Trade-Off

The major Rapid PVST+ trade-off is:

```text
Per-VLAN control
       +
Rapid convergence
       +
Easy Cisco operation
       │
       ▼
More STP instances
       │
       ▼
More CPU / memory / BPDU processing
```

Therefore:

```text
Rapid PVST+
    │
    └── Excellent per-VLAN control

MST
    │
    └── Better scalability by grouping VLANs
```

# 23. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|**Slow convergence**|Classic PVST+ instead of Rapid PVST+|`show spanning-tree summary`|
|**Wrong Root for VLAN**|Incorrect priority / MAC election|`show spanning-tree root`|
|**No expected load balancing**|Same Root Bridge for all VLANs|`show spanning-tree vlan X`|
|**Access host waits for STP**|PortFast missing|Check interface configuration|
|**Port becomes err-disabled after BPDU**|BPDU Guard triggered|`show interfaces status`|
|**Unexpected blocked/discarding path**|Superior STP path exists elsewhere|Compare Root Path Cost/BID|
|**Wrong path selected**|Cost or port priority|Check interface STP details|
|**VLAN cannot use expected link**|STP instance or VLAN/trunk issue|Check `show spanning-tree vlan X`|
|**MAC flapping**|L2 loop or topology instability|Check STP topology and MAC table|
|**Rapid behavior lost near legacy switch**|802.1D interoperability|Check neighboring switch STP mode|

### Troubleshooting sequence

```text
1. Confirm Rapid PVST+ mode
        ↓
2. Identify Root for affected VLAN
        ↓
3. Check Root Port
        ↓
4. Check Designated / Alternate ports
        ↓
5. Check port state
        ↓
6. Compare path costs
        ↓
7. Check port priority
        ↓
8. Check PortFast / BPDU Guard
        ↓
9. Check VLAN/trunk consistency
        ↓
10. Check topology changes and MAC flapping
```

# 24. Common Design Example

Consider two distribution switches:

```text
                    DIST1
                   /     \
                  /       \
                 /         \
              ACCESS1     ACCESS2
                 \         /
                  \       /
                   \     /
                    DIST2
```

Configure:

```text
VLAN 10 → DIST1 Root
VLAN 20 → DIST2 Root
```

Result:

```text
VLAN 10
    ↓
DIST1 preferred
    ↓
Uplink A carries VLAN 10 traffic


VLAN 20
    ↓
DIST2 preferred
    ↓
Uplink B carries VLAN 20 traffic
```

This creates **STP-based load distribution**.

> **Important:** This is logical load balancing at the VLAN/STP level. It does not mean a single VLAN simultaneously forwards over both redundant Layer-2 paths.

# 26. Exam Traps

### Trap 1 — Rapid PVST+ ≠ PVST+

```text
PVST+
    = Classic 802.1D per VLAN

Rapid PVST+
    = RSTP per VLAN
```

---

### Trap 2 — Do not say 6 seconds = convergence

```text
3 missed BPDUs × 2 s
        ≈ 6 s
```

is a useful failure-detection rule of thumb.

It is **not** a fixed Rapid PVST+ convergence time.

An Alternate Port may transition much sooner.

---

### Trap 3 — Do not say 1–3 seconds is guaranteed

Rapid PVST+ is designed for rapid convergence, but actual convergence depends on:

- Failure type
    
- Topology
    
- Alternate-path availability
    
- Link type
    
- Device behavior
    
- Configuration
    

---

### Trap 4 — PortFast does not disable STP

PortFast is an **edge-port optimization**.

STP still exists on the switch.

---

### Trap 5 — PortFast does not replace BPDU Guard

Recommended edge protection:

```text
PortFast
    +
BPDU Guard
```

---

### Trap 6 — Different VLANs can have different STP roles

A physical interface can be:

```text
VLAN 10 → Root Port
VLAN 20 → Designated Port
VLAN 30 → Alternate Port
```

---

### Trap 7 — Rapid PVST+ does not automatically load-balance

You must intentionally configure different Root Bridges per VLAN.

---

### Trap 8 — More VLANs means more instances

```text
1 VLAN
   ↓
1 Rapid PVST+ instance

100 VLANs
   ↓
Potentially 100 instances
```

This is one reason MST can scale better.

---

### Trap 9 — MST is not "one tree for everything"

MST maps VLANs into **MST instances**.

Multiple MST instances can have different topologies.

---

### Trap 10 — Extended System ID

Per-VLAN Bridge ID includes the VLAN ID, and configurable priorities occur in increments of:

```text
4096
```

# 29. Final CCNP Takeaway

Rapid PVST+ combines the two ideas:

```text
                    RAPID PVST+
                         │
             ┌───────────┴───────────┐
             │                       │
            RSTP                    PVST+
             │                       │
      Rapid convergence         Per-VLAN instances
             │                       │
      Proposal/Agreement        Root per VLAN
             │                       │
      Alternate paths           Per-VLAN topology
             │                       │
             └───────────┬───────────┘
                         ▼
              FAST PER-VLAN STP
```

The most important CCNP mental model is:

```text
PVST+
    = 802.1D per VLAN

Rapid PVST+
    = 802.1w per VLAN

MST
    = RSTP-style multiple instances
      with VLANs mapped into instances
```

And remember:

```text
Different VLAN
      ↓
Different STP instance
      ↓
Different Root election
      ↓
Different path calculation
      ↓
Different forwarding/discarding decisions
```

> **Final memory:**  
> **Rapid PVST+ = RSTP speed + PVST+ per-VLAN control.**
