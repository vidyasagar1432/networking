# Duplex

> **Level 01 · 02. Ethernet** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Duplex** defines whether a link transmits and receives at the same time.
**Full duplex** = simultaneous send/receive (modern wiring). **Half duplex** = one
direction at a time, relying on CSMA/CD (legacy hubs). Misconfiguration produces the
famous **late collisions / runts** symptom set, so duplex logic is a core
troubleshooting skill.

---

## 2. Core Concepts

### 2.1 Half-duplex (HDX)
- One wire pair used at a time (2 pairs for 10/100 use shared TX/RX timelines).
- **CSMA/CD** gives deterministic access: listen-before-send (Carrier Sense),
  protect against simultaneous transmissions (Multiple Access), abort on **Collision**,
  re-send after **Detection** + backoff.
- Only viable on 10/100 Mbps **hub**-based links or non-switched topologies.

### 2.2 Full-duplex (FDX)
- Separate TX and RX paths → **no collisions**, no CSMA/CD needed.
- Requires a **switched** point-to-point link (or fiber duplex pair).
- Numeric logic: a 100 Mbps FDX link transfers 200 Mbps of simultaneous line
  utilization (100 each way).

### 2.3 Auto-negotiation (AN)
- Modern 10/100/1000 use **IEEE 802.3 auto-negotiation** on the electrical layer:
  link pulse exchange determines speed then duplex.
- If both ends support AN → highest common speed, full duplex preferred.
- If **one side forced** (e.g., `speed 100` + `duplex full`) and the other auto:
  the auto side falls back to **half duplex** (it reads no FLP). → Mismatch symptoms.

### 2.4 Duplex mismatch symptoms (classic)
- Device A full, Device B half:
  - B sees late collisions; A sees CRC errors / runts (B's received frames clobbered).
  - RFC 2734-ish view: **packet loss both directions**, application slowness,
    retransmissions in TCP.
- **Late collisions** counter increments on the incorrectly-configured **half** end.

### 2.5 Which duplex on which link
| Media | Allowed duplex |
|-------|----------------|
| 10BASE-T FX? (no) | 10/100M UTP hub | HDX or FDX wired hub? fixed |
| Switch–switch / switch–host copper | Auto (FDX at same speed) |
| 1000BASE-T | **FDX only** (1G has no HDX mode) |
| Any fiber link (FX/SX/LX) | FDX only |
| 10/100M modern switch ports | Auto works; force only where required |

## 3. Configuration / Commands

```text
interface GigabitEthernet0/1
 speed 100
 duplex full          # forcing; beware of the mtu? mismatch — see below

show interfaces GigabitEthernet0/1   # "Full-duplex, 100Mb/s"
show interfaces counters errors      # late collisions / CRC / runts
```

Troubleshoot a slow / error-laden link:
1. `show interfaces | include (duplex|collision|CRC|runts)`
2. Verify both ends match (`show interfaces status` at the dist for the same link).
3. Fix: put both sides on **auto** (recommended) or force identically.

---

## 4. Exam Traps

- **Half-duplex has collisions; full does not.** "Collision counter" questions on a
  full-duplex link → look immediately at the *other* port.
- **Autoneg mismatch default behavior**: forcing one speed while peer is auto → peer
  learns speed (fast link pulses always) but **defaults to half-duplex** — the classic
  mismatch.
- **1000M "speed 100 duplex full"** is impossible — 1000BASE-T is FDX-only;
  speed commands on 1G ports are about **fiber/no-negotiation** choices.
- **Late collisions** counter = the signature of duplex mismatch on 10/100.
- **1G fiber** has no autonegotiation for speed (fixed); usually configured `no negotiate`.
