# MTU

> **Level 01 · 02. Ethernet** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**MTU (Maximum Transmission Unit)** is the largest L3 packet a link can carry; the
Ethernet frame carrying it adds L2 overhead. Constraints across a path can cause
**fragmentation**, **black holes** (PMTUD failures), or **MTU mismatch flapping** —
all classic exam troubleshooting.

---

## 2. Core Concepts

### 2.1 MTU vs frame size
- **MTU** → Layer 3 (IP) payload limit (default **1500 bytes**).
- **Frame size** → MTU + Ethernet header (14 B) + 4-byte **FCS** + (with 802.1Q)
  +4-byte VLAN tag + possible 1-byte start-flag for SNAP (in L3+ counts).
  So a 1500-MTU frame = 1518 bytes (untrunked), **1522** with a dot1Q tag.
- Some platforms support **Jumbo frames** up to ~9216 / 9000 B MTU.

### 2.2 Fragmentation & Path MTU
- If an IP packet exceeds the egress interface MTU, IPv4 **fragments** it
  (IPv6 does **not** fragment — uses PMTUD + ICMPv6 Packet Too Big).
- **PMTUD (path MTU discovery)**: sender sets DF (Don't Fragment); a router that
  can't forward replies **ICMP Type 3, Code 4** (fragmentation needed & DF set).
  If firewalls block that ICMP → **PMTUD black hole**: large flows stall, small ones pass.

### 2.3 MTU mismatch / inconsistency across the path
- Seen with L3 links where one interface has jumbo and a peer doesn't.
- OSPF/IS-IS hello dead in MTU-mismatch paths (they carry MTU info — BFD-like `ip mtu`).
- The classic device-side configuration: `ip mtu` (L3) vs `mtu` (L2) on the interface.

### 2.4 Encapsulation overheads and MTU
| Technology | Overhead to account for | Resulting advice |
|------------|--------------------------|------------------|
| 802.1Q trunk | +4 B | keep MTU 1500 unless jumbo |
| VXLAN (Level 24) | +8+20+14 ≈ 50 B | lower egress MTU (1450) on tunnels |
| GRE (Level 18) | +24 B | set 1476 on tunnel |
| MPLS labels | +4 B/label | for 1500-MTU, set 1504 or keep path MTU |
| PPPoE (Level 23) | +8 B | MTU 1492 |
Overlay tunnels must shrink MTU; otherwise encapsulation makes IP > link MTU → drop/frag.

### 2.5 MTU at layer 2 (Cisco `system mtu`)
- On switches: `system mtu jumbo` sets L2 MTU for all ports; `mtu` on routed port
  sets the IP MTU. Distinguish "interface mtu" (L3) from `ip mtu`.
- Default 1500; jumbo links must match across the switched path (STP-independent).

## 3. Configuration / Commands

```text
# Routed interface: set MTU
interface GigabitEthernet0/0
 ip mtu 1500

# Ensure path MTU works end to end
ping <target> size 1400 df-bit
ping <target> size 9000 df-bit     # jumbo test (also "repeat")

# Tunnel example (GRE overhead)
interface Tunnel0
 tunnel source gi0/0
 tunnel destination 10.0.0.2
 ip mtu 1476          # 1500 - 24 GRE overhead (20 IP + 4 GRE)
```

Troubleshoot MTU:
1. `ping ip <dst> packet-size 1472` (1500-28 ICMP) → if that works but MTU killer
   fails, it's a link MTU.
2. Check `show interfaces | include MTU`.
3. Verify ICMP unreachable (frag-needed) isn't filtered.

---

## 4. Exam Traps

- **MTU ≈ IP payload, frame = MTU + 18/22 B.**
- **IPv6 never fragments** (sender does PMTUD); don't answer "routers fragment."
- **Black hole**: DF + filtered ICMP → big packets die silently; patch: lower MTU or
  allow ICMP PTB.
- **Encapsulation must shrink MTU** — GRE 1476, PPPoE 1492, VXLAN ~1450.
- **Don't confuse `mtu` (L2/default) vs `ip mtu` (L3)** — Cisco CLI differs per type.
- **Jumbo everywhere or nowhere** — a partially-jumbo campus silently drops big frames.
