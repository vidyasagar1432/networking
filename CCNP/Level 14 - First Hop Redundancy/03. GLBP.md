# GLBP (Gateway Load Balancing Protocol)

> **Level 14 · First Hop Redundancy** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**GLBP (Gateway Load Balancing Protocol)** is a **Cisco-proprietary First Hop Redundancy Protocol (FHRP)** that provides both:

- **Default-gateway redundancy**
    
- **Gateway load balancing**
    

Unlike HSRP and VRRP, where a single router normally forwards traffic for a virtual IP within a group, GLBP allows **multiple routers to actively forward traffic for the same virtual IP**.

GLBP achieves this by using:

- One **AVG (Active Virtual Gateway)**
    
- Up to **four active AVFs (Active Virtual Forwarders)**
    
- One **virtual IP address**
    
- Multiple **virtual MAC addresses**
    
- ARP-based distribution of virtual MAC addresses
    

### GLBP protocol information

|Item|Value|
|---|---|
|Type|Cisco proprietary FHRP|
|Transport|UDP|
|UDP port|**3222**|
|IPv4 multicast|**224.0.0.102**|
|Virtual MAC prefix|**0007.b400**|
|Maximum active forwarders|**4**|

### Core idea

```text
                 Virtual IP
                  10.0.0.1
                      |
                     AVG
                      |
             ARP/MAC assignment
                      |
        +-------------+-------------+
        |             |             |
       AVF1          AVF2          AVF3
        |             |             |
       R1            R2            R3
        |             |             |
        +-------------+-------------+
              Active forwarding
```

### Key exam statement

> **GLBP provides built-in gateway load balancing by allowing multiple routers to actively forward traffic for the same virtual IP.**

---

# 2. Why GLBP Exists

Traditional FHRPs primarily provide redundancy.

For example:

```text
HSRP:

             VIP
              |
          Active R1
              |
           Hosts
              
          Standby R2
```

Only the active router normally forwards traffic.

GLBP improves utilization:

```text
GLBP:

              VIP
               |
              AVG
               |
      +--------+--------+
      |        |        |
     AVF1     AVF2     AVF3
      |        |        |
     R1       R2       R3
      |        |        |
      +--------+--------+
```

Multiple routers can forward traffic simultaneously.

Therefore:

```text
HSRP/VRRP
= Redundancy

GLBP
= Redundancy + Load Balancing
```

---

# 3. GLBP Architecture

## 3.1 AVG — Active Virtual Gateway

The **AVG** is the router elected to manage the GLBP group.

The AVG:

- Is elected for the GLBP group.
    
- Maintains information about the GLBP forwarders.
    
- Assigns virtual MAC addresses to forwarders.
    
- Responds to ARP requests for the virtual IP.
    
- Selects which virtual MAC address is returned to hosts.
    

There is **one AVG per GLBP group**.

### Important

The AVG is **not necessarily the only router forwarding traffic**.

Its primary responsibility is managing the GLBP group and distributing virtual MAC addresses.

---

# 4. AVF — Active Virtual Forwarder

An **AVF** is a router actively forwarding traffic for a GLBP virtual MAC.

GLBP supports:

> **Up to four active virtual forwarders per GLBP group.**

Example:

```text
GLBP Group 10

        AVG
         |
   +-----+-----+-----+
   |     |     |     |
 AVF1  AVF2  AVF3  AVF4
   |     |     |     |
  R1    R2    R3    R4
```

Each active forwarder is associated with a different virtual MAC.

---

# 5. GLBP Virtual IP

Hosts configure **one default-gateway IP address**.

Example:

```text
Default gateway:
10.0.0.1
```

The physical routers might use:

```text
R1 = 10.0.0.2
R2 = 10.0.0.3
R3 = 10.0.0.4
R4 = 10.0.0.5
```

But hosts use:

```text
10.0.0.1
```

as their default gateway.

The host does not need to know which physical router is forwarding its traffic.

---

# 6. GLBP Virtual MAC Addresses

GLBP uses multiple virtual MAC addresses.

The GLBP virtual MAC format is:

```text
0007.b400.XXYY
```

Where:

- `0007.b400` = GLBP virtual MAC prefix
    
- `XX` = GLBP group identifier in hexadecimal
    
- `YY` = forwarder identifier
    

Typical forwarder identifiers:

```text
01
02
03
04
```

Example:

```text
0007.b400.0A01
0007.b400.0A02
0007.b400.0A03
0007.b400.0A04
```

These can represent four active virtual forwarders.

### Memory rule

```text
0007.b400
     |
     +---- GLBP MAC prefix
```

---

# 7. How GLBP Handles ARP

This is one of the most important GLBP concepts.

Suppose a host wants to reach its default gateway:

```text
10.0.0.1
```

The host sends:

```text
ARP:
Who has 10.0.0.1?
```

The **AVG responds** with a GLBP virtual MAC.

For example:

```text
10.0.0.1
    ↓
0007.b400.0A01
    ↓
AVF1
```

Another host may receive:

```text
10.0.0.1
    ↓
0007.b400.0A02
    ↓
AVF2
```

Another host may receive:

```text
10.0.0.1
    ↓
0007.b400.0A03
    ↓
AVF3
```

Therefore:

```text
One VIP
   ↓
Multiple virtual MACs
   ↓
Multiple AVFs
   ↓
Load balancing
```

# 8. GLBP Load-Balancing Methods

GLBP supports three load-balancing methods:

1. **Round-robin**
    
2. **Host-dependent**
    
3. **Weighted**
    

---

## 8.1 Round-Robin

**Round-robin is the default GLBP load-balancing method.**

The AVG rotates the virtual MAC address returned in ARP replies.

Example:

```text
Host A → AVF1
Host B → AVF2
Host C → AVF3
Host D → AVF4
Host E → AVF1
Host F → AVF2
```

Configuration:

```text
glbp 10 load-balancing round-robin
```

---

## 8.2 Host-Dependent

The same host consistently receives the same virtual MAC.

Example:

```text
Host A → AVF1
Host B → AVF2
Host C → AVF3
```

Repeated ARP resolution for the same host generally preserves its association with the same forwarder.

Configuration:

```text
glbp 10 load-balancing host-dependent
```

### Use case

Useful when a stable host-to-forwarder relationship is desirable.

---

## 8.3 Weighted

Traffic distribution is influenced by the **GLBP weighting** of the active forwarders.

Example:

```text
AVF1 = 100
AVF2 = 50
```

AVF1 receives a greater proportion of the load than AVF2.

Configuration:

```text
glbp 10 load-balancing weighted
```

---

# 9. AVG Election

GLBP elects **one AVG per group**.

The primary election factor is:

```text
Highest GLBP priority
```

If priorities are equal:

```text
Highest IP address
```

Example:

```text
R1 = priority 110
R2 = priority 100
R3 = priority 90
```

R1 becomes the AVG.

If:

```text
R1 = priority 100
R2 = priority 100
```

the router with the higher IP address wins the tie.

---

# 10. GLBP Priority vs Weighting

This distinction is extremely important for CCNP.

## Priority

Used primarily for:

```text
AVG election
```

Example:

```text
glbp 10 priority 110
```

---

## Weighting

Used for:

```text
AVF forwarding eligibility
```

Example:

```text
glbp 10 weighting 110
```

### Remember

```text
Priority
   ↓
AVG election

Weighting
   ↓
AVF forwarding eligibility
```

Do **not** confuse the two.

---

# 11. GLBP Weighting

Weighting allows GLBP to determine whether an AVF should continue forwarding based on its available resources or tracked objects.

Example:

```text
glbp 10 weighting 110 lower 1 upper 110
```

This means:

```text
Initial weighting = 110
Lower threshold   = 1
Upper threshold   = 110
```

If the weighting falls below the lower threshold, the forwarder can become inactive.

When the weighting recovers to the upper threshold, it can become active again.

### Important

Do not memorize:

> "Weighting 0 always means inactive."

Instead remember:

> **The lower and upper thresholds determine when the forwarder becomes inactive or active again.**

---

# 12. GLBP Object Tracking

GLBP can track an object and reduce the AVF's weighting when that object fails.

Example:

```text
glbp 10 track 1 decrement 30
```

If:

```text
Current weighting = 110
```

and tracked object 1 fails:

```text
110 - 30 = 80
```

New weighting:

```text
80
```

If that causes the weighting to cross the configured lower threshold, the AVF becomes inactive.

### Critical distinction

Tracking changes:

```text
GLBP weighting
```

not:

```text
GLBP priority
```

---

# 13. GLBP Preemption

Preemption allows a higher-priority router to reclaim its preferred role after recovering.

Example:

```text
R1 = priority 110
R2 = priority 100
```

R1 is preferred for AVG.

Configuration:

```text
glbp 10 preempt
```

If R1 fails:

```text
R2 → becomes AVG
```

When R1 returns:

```text
R1 → can preempt R2
```

Preemption is particularly important when you want the preferred router to regain the AVG role after recovery.

---

# 14. GLBP Timers

GLBP uses hello and hold timers to maintain neighbor and role information.

### Hello timer

Determines how frequently GLBP peers send hello messages.

### Hold timer

Determines how long information about a peer is considered valid before the peer is considered unavailable.

Default timer values commonly encountered in Cisco IOS GLBP are:

```text
Hello = 3 seconds
Hold  = 10 seconds
```

### Configuration example

```text
glbp 10 timers 3 10
```

This should be configured consistently among GLBP peers.

### Exam concept

```text
Hello
  ↓
Keepalive / neighbor communication

Hold
  ↓
Failure detection
```

---

# 15. GLBP Forwarder States

An AVF can transition through different forwarding states.

Important states include:

|State|Meaning|
|---|---|
|**Listen**|Forwarder is participating but not currently active|
|**Active**|Forwarder is actively forwarding traffic|
|**Disabled**|Forwarder is not currently functioning as an active forwarder|

The most important state for troubleshooting is:

```text
Active
```

because an AVF in the active state is eligible to forward traffic.

---

# 16. GLBP Failover

## 16.1 AVG Failure

Suppose:

```text
R1 = AVG
R2 = AVF
R3 = AVF
```

R1 fails:

```text
R1
 ↓
Failure detected
 ↓
AVG election
 ↓
New AVG elected
```

Another eligible router becomes the AVG.

The GLBP group continues operating.

---

## 16.2 AVF Failure

Suppose:

```text
AVF1 = R1
AVF2 = R2
AVF3 = R3
```

R1 fails.

GLBP detects that AVF1 is no longer available.

Another router can take over the failed forwarder's role/virtual MAC responsibility so traffic destined to that forwarder can continue during convergence.

This is different from simply changing the host's default-gateway IP.

The host continues using the same virtual IP.

---

# 17. GLBP Redirect and Secondary Forwarding

GLBP has mechanisms for handling traffic when an active forwarder fails.

A host may still have an ARP entry pointing to a failed AVF's virtual MAC.

Instead of requiring every host to immediately relearn the gateway MAC, GLBP can temporarily redirect traffic associated with the failed forwarder toward another active forwarder.

This behavior is associated with **redirect and secondary forwarder mechanisms**.

### Important concept

```text
Host still has old virtual MAC
          ↓
Old AVF failed
          ↓
GLBP provides forwarding continuity
          ↓
Another AVF handles the traffic
```

This helps minimize disruption during AVF failure and convergence.

---

# 18. GLBP Authentication

GLBP supports authentication to help ensure that only authorized routers participate in the GLBP group.

Authentication can be configured using supported Cisco IOS GLBP authentication mechanisms.

Examples may include:

- Plain-text authentication
    
- MD5 authentication
    

Authentication must match between participating GLBP peers.

If authentication parameters do not match, GLBP neighbors may fail to establish correctly.

### Troubleshooting implication

If two routers appear correctly configured but do not become GLBP peers, check:

```text
Authentication
Group number
Virtual IP
Interface connectivity
Multicast
UDP 3222
```

# 19. GLBP Configuration

## 19.1 Basic Configuration

### R1

```text
interface GigabitEthernet0/0
 ip address 10.0.0.2 255.255.255.0
 glbp 10 ip 10.0.0.1
 glbp 10 priority 110
 glbp 10 preempt
 glbp 10 load-balancing round-robin
```

### R2

```text
interface GigabitEthernet0/0
 ip address 10.0.0.3 255.255.255.0
 glbp 10 ip 10.0.0.1
 glbp 10 priority 100
 glbp 10 preempt
 glbp 10 load-balancing round-robin
```

Both routers use:

```text
Virtual IP = 10.0.0.1
```

R1 has the higher priority and therefore becomes the preferred AVG.

Both routers can participate as active forwarders.

|Symptom|Possible Cause|What to Check|
|---|---|---|
|No GLBP load balancing|Incorrect load-balancing configuration|`show glbp`|
|Only one AVF active|Other router not eligible|Weighting/state/configuration|
|AVF becomes inactive|Weighting crossed lower threshold|`show glbp`, `show track`|
|Unexpected AVG|Priority/IP difference|GLBP priority|
|AVG does not form|Communication problem|VLAN, multicast, UDP 3222|
|GLBP peers do not form|Authentication mismatch|Authentication configuration|
|Traffic appears to use one gateway|ARP caching|Host ARP table and load-balancing method|

|GLBP instability|Timer/connectivity problem|Hello/hold timers and interface state|
|Forwarder failure|AVF/router failure|`show glbp` and interface status|

# 25. Common GLBP Failure Causes

### 25.1 Wrong GLBP Group

Example:

```text
R1:
glbp 10 ip 10.0.0.1

R2:
glbp 20 ip 10.0.0.1
```

These are different GLBP groups.

They will not operate as the same GLBP group.

---

### 25.2 Different Virtual IP

Example:

```text
R1:
glbp 10 ip 10.0.0.1

R2:
glbp 10 ip 10.0.0.254
```

This is a configuration mismatch.

---

### 25.3 Multicast Problem

GLBP uses:

```text
224.0.0.102
```

If GLBP multicast communication is disrupted, neighbors may fail to communicate correctly.

---

### 25.4 UDP 3222 Problem

GLBP uses:

```text
UDP 3222
```

Filtering or disruption of the required traffic can prevent proper GLBP operation.

---

### 25.5 Authentication Mismatch

If authentication is configured but does not match, GLBP peers may fail to establish correctly.

---

### 25.6 Weighting Problem

A router can be configured correctly but still become inactive because its GLBP weighting has crossed the configured threshold.

Check:

```text
show glbp
show track
```

# 26. GLBP vs HSRP vs VRRP

|Feature|HSRP|VRRP|GLBP|
|---|---|---|---|
|Type|Cisco / standards-track RFC|Open standard|Cisco proprietary|
|Main purpose|Gateway redundancy|Gateway redundancy|Gateway redundancy + load balancing|
|Main role|Active / Standby|Master / Backup|AVG / AVF|
|Active forwarding gateways per group|Normally 1|Normally 1|Up to 4 AVFs|
|Virtual IP|Yes|Yes|Yes|
|Multiple virtual MACs for one VIP|No|No|**Yes**|
|Built-in load balancing|No|No|**Yes**|
|Transport|UDP 1985|IP protocol 112|UDP 3222|
|IPv4 multicast|224.0.0.2 (v1) / 224.0.0.102 (v2)|224.0.0.18|224.0.0.102|

### Important

HSRP and VRRP can distribute traffic by using **multiple groups/VIPs**.

GLBP provides load balancing **within one GLBP group and one virtual IP**.

# 27. GLBP Packet Flow

Assume:

```text
VIP = 10.0.0.1

AVF1 → 0007.b400.0A01
AVF2 → 0007.b400.0A02
AVF3 → 0007.b400.0A03
AVF4 → 0007.b400.0A04
```

### Step 1 — Host sends ARP

```text
Who has 10.0.0.1?
```

### Step 2 — AVG answers

Example:

```text
10.0.0.1
     ↓
0007.b400.0A02
```

### Step 3 — Host stores the mapping

```text
10.0.0.1 → 0007.b400.0A02
```

### Step 4 — Host sends traffic

```text
Destination MAC:
0007.b400.0A02
```

### Step 5 — AVF2 forwards

```text
Host
  |
  | MAC .02
  ↓
AVF2
  |
  ↓
Destination
```

Another host may receive:

```text
10.0.0.1 → 0007.b400.0A03
```

and therefore use AVF3.

# 30. Exam Traps

### Trap 1

> GLBP has only one active router.

**False.**

GLBP can have up to **four active virtual forwarders**.

---

### Trap 2

> The AVG forwards all traffic.

**False.**

The AVG manages the group and answers ARP. AVFs perform forwarding.

---

### Trap 3

> GLBP requires multiple virtual IP addresses for load balancing.

**False.**

GLBP can load-balance using:

```text
1 virtual IP
+
multiple virtual MACs
+
multiple AVFs
```

---

### Trap 4

> GLBP priority controls whether an AVF forwards.

**False.**

```text
Priority → AVG election
Weighting → AVF forwarding eligibility
```

---

### Trap 5

> Weighting 0 is the only condition for AVF inactivity.

**False.**

The configured **lower threshold** determines when an AVF becomes inactive.

---

### Trap 6

> Round-robin is the only GLBP load-balancing method.

**False.**

GLBP supports:

```text
Round-robin
Host-dependent
Weighted
```

Round-robin is the default.

---

### Trap 7

> GLBP uses HSRP's multicast address.

**False.**

GLBP uses:

```text
224.0.0.102
```

---

### Trap 8

> GLBP uses UDP 1985.

**False.**

UDP 1985 is associated with HSRP.

GLBP uses:

```text
UDP 3222
```
