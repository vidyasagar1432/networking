# GLBP (Gateway Load Balancing Protocol)

> **Level 14 · First Hop Redundancy** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**GLBP** (Cisco-proprietary) is the only FHRP that does **load balancing across multiple
gateways for one virtual IP**. One **AVG** (Active Virtual Gateway) assigns **virtual MACs**
to participating routers (**AVFs** — Active Virtual Forwarders); ARP answers rotate MACs so
hosts spread across gateways. Protocol = **UDP 3222, multicast 224.0.0.102**.

---

## 2. Core Concepts

### 2.1 The GLBP roles

| Role | Meaning |
|------|---------|
| **AVG** | owns the VIP, runs election, assigns virtual MACs |
| **AVF** | forwards traffic for an assigned virtual MAC |
| Active AVF | actually forwarding |
| Listen AVF | backup forwarder |

- **One AVG per group**, up to **four AVFs** per group.
- Hosts see one VIP but different virtual MACs via ARP.

### 2.2 Virtual MAC assignment

| MAC | Purpose |
|-----|---------|
| AVG's own | 0007.b400.XX01 (group id) |
| AVF 2 | 0007.b400.XX02 |
| AVF 3 | 0007.b400.XX03 |
| AVF 4 | 0007.b400.XX04 |

- Each active forwarder owns one of the `0007.b400` MACs — ARP round-robins between them.

### 2.3 Load balancing methods

| Method | Behavior |
|--------|----------|
| round-robin (default) | each ARP reply = next AVF MAC |
| host-dependent | same host always same MAC |
| weighted | proportional to AVF weight |

- `glbp X load-balancing round-robin|host-dependent|weighted`.

### 2.4 Configuration

```text
interface Gi0/0
 glbp 10 ip 10.0.0.1
 glbp 10 priority 110
 glbp 10 preempt
 glbp 10 weighting 110 lower 1 upper 110
 glbp 10 track 1 decrement 30          ! reduces weighting
 glbp 10 load-balancing round-robin
```

- **Weighting tracks uplinks** (not priority): failure drops AVF weight → AVFs with 0
  stop forwarding.
- `lower`/`upper` set the threshold where the AVF goes inactive/recovered.

### 2.5 GLBP vs HSRP vs VRRP

| Item | HSRP | VRRP | GLBP |
|------|------|------|------|
| Standard | Cisco | RFC | Cisco |
| Load balance | groups only | groups only | **built-in** |
| Role model | 1 active | 1 master | AVG + AVFs |
| VIP MACs | one/group | one/VRID | up to 4 |
| Protocol | UDP 1985 | IP 112 | UDP 3222 |
| Multicast | 224.0.0.2 | 224.0.0.18 | 224.0.0.102 |

- Only GLBP balances **within one group**.

### 2.6 Failover behavior

- AVG tracks hellos; on AVG loss a new AVG elects (highest priority/IP).
- AVF loss: others take over the failed MAC, or the AVG reassigns.
- Weighting 0 → AVF stops forwarding; traffic shifts to surviving AVFs.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No load balancing | hosts cache one MAC | ARP aging / round-robin |
| Single AVF | other routers listen only | priority/weighting config |
| AVF drops traffic | weighting 0 | weighting/track |
| Two AVGs | hello blocked | show glbp both sides |
| All to one gateway | host-dependent + sticky hosts | load-balancing method |

---

## 5. Exam Traps

- GLBP = **built-in load balancing** — the exam's distinguishing fact.
- Roles: one **AVG**, max **four AVFs**.
- UDP 3222, **224.0.0.102**.
- Virtual MACs `0007.b400.XX01–04`.
- **Weighting** (not priority) handles link tracking; weighting 0 = inactive AVF.
- Only FHRP where multiple routers serve the **same VIP** simultaneously.
