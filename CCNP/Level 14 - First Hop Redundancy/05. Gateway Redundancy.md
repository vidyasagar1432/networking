# Gateway (First Hop) Redundancy — Comparing FHRPs

> **Level 14 · First Hop Redundancy** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**First Hop Redundancy Protocols (FHRPs)** provide hosts with a **redundant default gateway** by  
using a **virtual IP address (VIP)** and **virtual MAC address** shared by multiple routers or  
Layer 3 switches.

Hosts configure **one default gateway** — the VIP — while multiple FHRP devices participate  
behind it.

The three major FHRPs to know for CCNP Enterprise are:

- **HSRP** — Cisco proprietary
    
- **VRRP** — open standard
    
- **GLBP** — Cisco proprietary with built-in gateway load balancing
    

The most important exam distinctions are **roles, election, multicast address, virtual MAC,  
preemption, timers, and load-balancing behavior**.

---

## 2. Core Concepts

### 2.1 The problem FHRPs solve

Without an FHRP:

```text
Host
  |
  | Default Gateway = 10.10.10.1
  |
Router
```

If that router fails, hosts lose their default gateway.

With an FHRP:

```text
                    +--- R1 ---+
                    |          |
Host --- LAN -------+--- R2 ---+--- Upstream
                    |          |
                    +--- R3 ---+

             Virtual IP = 10.10.10.1
             Virtual MAC = FHRP MAC
```

The hosts continue using:

```text
Default Gateway = 10.10.10.1
```

The FHRP determines which device forwards traffic and what happens when that device fails.

# 4. HSRP

**Hot Standby Router Protocol (HSRP)** is a Cisco-proprietary FHRP.

For a traditional HSRP group:

```text
             Virtual IP
             10.10.10.1
                  |
        +---------+---------+
        |                   |
      R1 Active          R2 Standby
```

The **Active** router forwards traffic for the virtual IP.

The **Standby** router waits to take over if the Active router fails.

### HSRP roles

- **Active** — forwards traffic for the HSRP virtual IP.
    
- **Standby** — backup Active router.
    
- **Listen** — knows about the HSRP group but is neither Active nor Standby.
    

### HSRP election

HSRP normally uses:

1. Highest **priority**
    
2. If priorities tie, highest **IP address**
    

Default priority:

```text
100
```

Higher priority wins.

Example:

```text
R1 priority = 110
R2 priority = 100

R1 → Active
R2 → Standby
```

### HSRP preemption

By default, HSRP does **not** preempt.

If R1 originally has priority 110, fails, and R2 becomes Active, R1 does not  
automatically reclaim the Active role simply because it has a higher priority.

Enable:

```cisco
interface GigabitEthernet0/0
 standby 10 ip 10.10.10.1
 standby 10 priority 110
 standby 10 preempt
```

### HSRP versions

#### HSRPv1

```text
Multicast: 224.0.0.2
Virtual MAC: 0000.0c07.acXX
```

#### HSRPv2

```text
Multicast: 224.0.0.102
Virtual MAC: 0000.0c9f.fXXX
```

> **Exam trap:** Do not assume `224.0.0.2` is the multicast address for every HSRP  
> configuration. HSRPv2 uses `224.0.0.102`.

### HSRP load sharing

HSRP does **not** load-balance multiple routers for one VIP.

You can distribute traffic by using multiple HSRP groups:

```text
VLAN 10:
R1 = Active
R2 = Standby

VLAN 20:
R2 = Active
R1 = Standby
```

This is **load sharing across different FHRP groups/VLANs**, not per-packet or  
per-host load balancing within one HSRP group.

# 5. VRRP

**Virtual Router Redundancy Protocol (VRRP)** is an open-standard FHRP.

For IPv4:

```text
Multicast = 224.0.0.18
Protocol  = IP 112
```

### VRRP roles

- **Master** — forwards traffic for the virtual IP.
    
- **Backup** — monitors the Master and takes over if necessary.
    

VRRP uses a **Virtual Router ID (VRID)** to identify the virtual router.

### VRRP priority

Default:

```text
100
```

The router owning the virtual IP can use:

```text
Priority = 255
```

This is known as the **address owner**.

Other routers normally use priorities from 1–254.

### VRRP preemption

VRRP preemption is **enabled by default**.

Therefore, if a higher-priority router becomes available again, it can normally  
reclaim the Master role.

> **Exam trap:** VRRP differs from the common Cisco HSRP default: VRRP preemption  
> is enabled by default, while HSRP preemption is disabled by default.

### VRRP virtual MAC

For IPv4:

```text
0000.5e00.01XX
```

Where `XX` represents the VRID.

Example:

```text
VRID = 10
Virtual MAC = 0000.5e00.010a
```

### VRRP load sharing

VRRP does not provide built-in load balancing for multiple routers behind a  
single VIP.

Traffic distribution can be designed using **multiple VRRP groups/VRIDs**,  
but that is different from GLBP's built-in load balancing.

---

# 6. GLBP

**Gateway Load Balancing Protocol (GLBP)** is a Cisco-proprietary FHRP that provides  
**gateway redundancy and built-in load balancing**.

This is the major feature that separates GLBP from HSRP and VRRP.

```text
                    Virtual IP
                   10.10.10.1
                        |
                      AVG
                 /      |      \
               AVF1    AVF2    AVF3
                |       |       |
               R1      R2      R3
```

### GLBP roles

#### AVG — Active Virtual Gateway

There is **one AVG** for a GLBP group.

The AVG:

- Responds to ARP requests for the virtual IP.
    
- Assigns virtual MAC addresses.
    
- Coordinates the AVFs.
    

#### AVF — Active Virtual Forwarder

An AVF forwards traffic destined for its assigned virtual MAC.

A GLBP group can support **up to four active virtual forwarders**.

### GLBP virtual MAC

The virtual MAC range is:

```text
0007.b400.XX01
0007.b400.XX02
0007.b400.XX03
0007.b400.XX04
```

The AVG assigns these virtual MAC addresses to participating AVFs.

### GLBP load balancing

A host still uses **one virtual IP**:

```text
Default Gateway = 10.10.10.1
```

However, ARP responses can cause different hosts to learn different virtual MAC  
addresses.

Example:

```text
Host A → VIP → MAC 0007.b400.0a01 → R1
Host B → VIP → MAC 0007.b400.0a02 → R2
Host C → VIP → MAC 0007.b400.0a03 → R3
Host D → VIP → MAC 0007.b400.0a04 → R4
```

Therefore, multiple routers can forward traffic for the **same VIP**.

> **Key exam fact:** GLBP provides **built-in gateway load balancing within one  
> FHRP group/VIP**.

### GLBP preemption

GLBP preemption is **disabled by default**.

Enable it when automatic recovery to the preferred AVG/AVF is required.

---

# 7. Election and Preemption

Do **not** treat HSRP, VRRP, and GLBP as having one identical election algorithm.

|Protocol|Main election concept|Default priority|Preempt default|
|---|---|--:|---|
|HSRP|Highest priority; IP address breaks a priority tie|100|**Off**|
|VRRP|Highest priority; priority 255 identifies address owner|100|**On**|
|GLBP|Highest priority determines AVG election|100|**Off**|

For Cisco FHRPs, configure preemption when you want the preferred device to  
automatically regain its role after recovering.

---

# 8. Failure Detection

|Protocol|Default behavior|
|---|---|
|HSRP|Hello 3s / Hold 10s|
|VRRP|Advertisement 1s; Master-down interval is calculated from the advertisement interval and priority|
|GLBP|Hello 3s / Hold 10s|

Faster failure detection can be achieved by using appropriate timer tuning and,  
where supported, **object tracking** or other tracking mechanisms.

> **Exam trap:** VRRP's failover calculation should not simply be memorized as  
> "3 × advertisement interval." Its Master-down interval includes a calculated  
> skew component based on priority.

# 9. Virtual MAC and Multicast — Memorization Table

|Protocol|IPv4 Multicast|Virtual MAC|
|---|---|---|
|HSRPv1|`224.0.0.2`|`0000.0c07.acXX`|
|HSRPv2|`224.0.0.102`|`0000.0c9f.fXXX`|
|VRRP|`224.0.0.18`|`0000.5e00.01XX`|
|GLBP|`224.0.0.102`|`0007.b400.XX01`–`XX04`|

### Easy memory pattern

```text
HSRPv1 → .2
VRRP   → .18
HSRPv2 → .102
GLBP   → .102
```

> **Important:** HSRPv2 and GLBP both use `224.0.0.102`, but their virtual MAC  
> formats and protocols are different.

# 10. Load-Sharing Comparison

|Protocol|One VIP + Multiple Active Forwarders?|Typical load-sharing method|
|---|---|---|
|HSRP|No|Multiple HSRP groups/VLANs|
|VRRP|No|Multiple VRRP groups/VRIDs|
|GLBP|**Yes**|AVG assigns multiple virtual MACs to AVFs|

### HSRP / VRRP

```text
VIP 1 → R1 Active
VIP 2 → R2 Active
```

Traffic can be distributed by designing multiple groups.

### GLBP

```text
             One VIP
                |
       +--------+--------+
       |        |        |
      AVF1     AVF2     AVF3
       |        |        |
      R1       R2       R3
```

The same virtual IP can use multiple virtual MAC addresses.

# 12. Object Tracking

Object tracking allows an FHRP device to react to the health of something  
beyond the local interface.

Examples of tracked conditions include:

- Interface state
    
- IP SLA reachability
    
- Route existence
    
- Other tracked objects
    

A common design is:

```text
Normal:

R1 → preferred gateway
R2 → backup gateway


Tracked upstream failure:

R1 tracking object fails
        ↓
FHRP priority/weight changes
        ↓
R2 becomes preferred gateway
```

This prevents a router from remaining the preferred gateway when its important  
upstream path has failed.

> **Important:** Object tracking is not itself an FHRP. It is a mechanism that  
> can be integrated with FHRP behavior.

# 13. Troubleshooting

|Symptom|Possible cause|Check|
|---|---|---|
|No FHRP neighbor|VLAN/subnet mismatch|Interface/VLAN configuration|
|Unexpected Active/Master/AVG|Priority/preemption configuration|FHRP status and priority|
|No failover|Peer cannot receive hellos/advertisements|VLAN, ACL, STP, interface state|
|Slow failover|Default timers|FHRP timers/tracking|
|Gateway unreachable|Incorrect VIP or subnet|IP addressing and FHRP configuration|
|GLBP traffic not distributed|GLBP load-balancing configuration or host ARP behavior|`show glbp`, ARP tables|
|Preferred router does not regain role|Preemption disabled|Configure appropriate preemption|
|Upstream failure not triggering gateway change|Tracking not configured/correctly applied|`show track` and FHRP status|

Useful commands:

```cisco
show standby brief
show standby

show vrrp brief
show vrrp

show glbp brief
show glbp

show track
show ip interface brief
show arp
```

# 14. Exam Traps

### Trap 1 — GLBP is the only one with built-in load balancing

Correct:

```text
HSRP → redundancy
VRRP → redundancy
GLBP → redundancy + built-in gateway load balancing
```

---

### Trap 2 — HSRPv1 and HSRPv2 use the same multicast address

False.

```text
HSRPv1 → 224.0.0.2
HSRPv2 → 224.0.0.102
```

---

### Trap 3 — All FHRPs have preemption enabled by default

False.

```text
HSRP → OFF
VRRP → ON
GLBP → OFF
```

---

### Trap 4 — GLBP has one Active router and several Standbys

Incorrect terminology.

GLBP uses:

```text
1 AVG
+
AVFs
```

The AVG performs the gateway-control role, while AVFs forward traffic.

---

### Trap 5 — HSRP load-balances one VIP across routers

False.

HSRP normally has one Active router per group.

Load sharing is achieved by using **multiple HSRP groups**, often across VLANs.

---

### Trap 6 — VRRP priority 255 is just a normal high priority

Not exactly.

Priority **255** identifies the **IP address owner** in VRRP.

---

### Trap 7 — FHRP failure detection is always 10 seconds

False.

The detection behavior depends on the protocol and configured timers.

For example:

```text
HSRP default → 3s hello / 10s hold
VRRP default → 1s advertisement + calculated Master-down interval
GLBP default → 3s hello / 10s hold
```

---

### Trap 8 — FHRP requires changing the host's default gateway during failover

False.

The host continues using the **same virtual IP**.

The FHRP changes which physical device provides that gateway.

---

### Trap 9 — FHRP is simply a Layer 2 protocol

Not a good description.

FHRPs provide a **redundant Layer 3 gateway function** while using Layer 2  
virtual MAC addressing and control-plane communication.

---

# 15. Choosing the FHRP

|Requirement|Preferred choice|
|---|---|
|Cisco proprietary environment + simple gateway redundancy|HSRP|
|Multi-vendor interoperability|VRRP|
|Cisco environment + built-in gateway load balancing|GLBP|
|Multiple VLANs with active/standby distribution|HSRP/VRRP|
|One VIP with multiple forwarding routers|**GLBP**|

Do not interpret this as "one protocol is always better." The correct choice  
depends on vendor interoperability, platform support, design requirements,  
and whether built-in gateway load balancing is required.
