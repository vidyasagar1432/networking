# Gateway (First Hop) Redundancy — Comparing FHRPs

> **Level 14 · First Hop Redundancy** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**First Hop Redundancy Protocols (FHRPs)** give hosts a **single virtual gateway** while
multiple routers provide it — one forwards, others stand by. The three candidates are
**HSRP** (Cisco, UDP), **VRRP** (open standard), and **GLBP** (Cisco, load-balancing).
This note compares them and frames the decision criteria the exam tests.

---

## 2. Core Concepts

### 2.1 The problem FHRPs solve

- A single default gateway = single point of failure.
- Changing host gateways manually is unmanageable.
- Solution: **VIP + virtual MAC** that hosts never change; routers elect a forwarder.

### 2.2 The three protocols side by side

| Feature | HSRP | VRRP | GLBP |
|---------|------|------|------|
| Vendor | Cisco | RFC 3768 | Cisco |
| Transport | UDP 1985 | IP 112 | UDP 3222 |
| Multicast | 224.0.0.2 | 224.0.0.18 | 224.0.0.102 |
| Virtual MAC | 0000.0c07.acXX | 0000.5e00.01XX | 0007.b400.XX01-04 |
| Active role | 1 Active | 1 Master | 1 AVG + up to 4 AVFs |
| Load balancing | via groups | via VRIDs | **built-in** |
| Preempt default | off | on | off |
| Timers | 3s / 10s | 1s / 3x | 3s / 10s |

- The **virtual MAC** and **multicast address** rows are the most-quizzed facts.

### 2.3 Election logic (all three)

| Criterion | Rule |
|-----------|------|
| Priority | default 100, highest wins |
| Tie-break | highest IP address |
| Preempt | HSRP off, VRRP on, GLBP off by default |

- Configure `preempt` where role recovery must be automatic.

### 2.4 Failover mechanics

| Protocol | Failure detection |
|----------|-------------------|
| HSRP | hold timer (10 s) / object tracking |
| VRRP | 3 × advert (3 s) / object tracking |
| GLBP | hello loss / weighting thresholds |

- All three react faster with **object tracking** (note 04) or tightened timers.

### 2.5 Load sharing strategies

| Protocol | Method |
|----------|--------|
| HSRP | multiple groups, one VIP each, rotate Active |
| VRRP | multiple VRIDs, one VIP each |
| GLBP | one VIP, ARP rotates virtual MACs |

- GLBP is the only one balancing **within a single group/VIP**.

### 2.6 Choosing the right one

| Need | Pick |
|------|------|
| Multi-vendor network | VRRP |
| Cisco-only + standard | HSRP |
| Single VIP + load sharing | GLBP |
| Sub-second failover | any + object tracking / timers |

## 3. Configuration / Commands

```text
interface Gi0/0
 standby 10 ip 10.0.0.1        ! HSRP
 vrrp 10 ip 10.0.0.1           ! VRRP
 glbp 10 ip 10.0.0.1           ! GLBP
show standby brief | vrrp brief | glbp brief
show track
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Two actives | hello blocked / VLAN split | show <proto> both ends |
| No failover | preempt missing | add preempt |
| Hosts unreachable | VIP wrong subnet | interface + VIP |
| Uneven load | only GLBP balances same VIP | group/VRID design |
| Slow failover | default timers | object tracking |

---

## 5. Exam Traps

- **Virtual MAC + multicast** per protocol is the memorization trap.
- **VRRP preempt is ON by default; HSRP/GLBP OFF**.
- VRRP allows the VIP to be the **real owner** address.
- GLBP: **1 AVG, 4 AVFs**, balancing built-in.
- FHRPs are **layer 2/3**; they need the same VLAN/subnet on all members.
- Hosts must run an **ARP cache** refresh to pick up new MAC on some designs.
