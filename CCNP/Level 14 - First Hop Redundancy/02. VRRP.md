# VRRP (Virtual Router Redundancy Protocol)

> **Level 14 · First Hop Redundancy** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**VRRP (Virtual Router Redundancy Protocol)** is an **IETF-standard First Hop Redundancy Protocol (FHRP)** that provides a redundant default gateway for hosts.

Multiple routers share a **Virtual IP Address (VIP)** and a **Virtual MAC address**. One router operates as the **Master**, while one or more routers operate as **Backup** routers.

- **Master** → forwards traffic for the VIP.
    
- **Backup** → monitors the Master and takes over when the Master fails.
    
- Hosts continue using the same default gateway.
    
- VRRP is designed for **multi-vendor interoperability**.
    
- VRRP does **not use UDP**.
    

For IPv4:

```text
IP Protocol       = 112
Multicast         = 224.0.0.18
Virtual MAC       = 0000.5e00.01XX
Default Priority  = 100
Advertisement     = 1 second
```

---

# 2. VRRP Versions

|Version|RFC|IPv4|IPv6|
|---|---|---|---|
|**VRRPv2**|RFC 3768|Yes|No|
|**VRRPv3**|RFC 5798|Yes|Yes|

### Important

**RFC 3768** defines VRRPv2.

**RFC 5798** defines VRRPv3 and adds support for both IPv4 and IPv6.

> **Exam trap:** Do not simply write "VRRP = RFC 3768." That is specifically **VRRPv2**.

# 3. VRRP Terminology

|Term|Meaning|
|---|---|
|**VRID**|Virtual Router Identifier; identifies a VRRP virtual router|
|**VIP**|Virtual IP address used as the default gateway|
|**Virtual MAC**|MAC address associated with the VRRP virtual router|
|**Master**|Router currently forwarding traffic for the VIP|
|**Backup**|Router monitoring the Master|
|**IP Address Owner**|Router whose real IP address is the VRRP VIP|
|**Advertisement**|VRRP message sent by the Master|
|**Priority**|Determines which router should become Master|
|**Preemption**|Allows a higher-priority router to become Master|

# 4. Master and Backup Roles

A VRRP group normally contains:

```text
1 Master
+
1 or more Backups
```

### Master

The Master:

- Owns the forwarding responsibility for the VIP.
    
- Responds to ARP for the virtual IPv4 address.
    
- Sends periodic VRRP advertisements.
    
- Forwards traffic destined to the virtual MAC.
    

### Backup

The Backup:

- Monitors VRRP advertisements.
    
- Does not normally forward traffic for the VIP.
    
- Takes over when the Master is considered unavailable.
    
- Participates in the Master election.
    

---

# 5. VRRP State Machine

VRRP has three primary states:

```text
Initialize
   |
   +----> Master
   |
   +----> Backup
```

### Initialize

Initial state when VRRP starts or the interface becomes unavailable.

### Master

The router:

- Owns the forwarding role.
    
- Sends advertisements.
    
- Responds to ARP/ND for the virtual address.
    
- Forwards traffic for the virtual router.
    

### Backup

The router:

- Listens for advertisements.
    
- Monitors the Master.
    
- Does not normally forward traffic for the virtual IP.
    
- Can transition to Master when the Master fails.
    

> **Exam note:** VRRP does not use HSRP's `Active`, `Standby`, `Speak`, and `Listen` terminology.

---

# 6. VRID

**VRID (Virtual Router Identifier)** identifies a VRRP virtual router.

For VRRP:

```text
VRID = 1–255
```

Example:

```text
VRID 10
```

The VRID is associated with:

- Virtual IP address
    
- Virtual MAC address
    
- Master
    
- Backup routers
    

Multiple VRIDs can exist on the same physical interface.

---

# 7. Virtual IP Address

The **Virtual IP Address (VIP)** is the gateway address configured on hosts.

Example:

```text
R1 real IP = 192.168.10.2
R2 real IP = 192.168.10.3

VRRP VIP   = 192.168.10.1
```

Hosts use:

```text
Default Gateway = 192.168.10.1
```

If R1 fails:

```text
R1 → Master
R1 → fails

R2 → Backup → Master
```

The host continues using:

```text
192.168.10.1
```

No default-gateway change is required.

---

# 8. IP Address Owner

VRRP has an important concept called the **IP Address Owner**.

The IP Address Owner is the router whose real interface IP address is the same as the VRRP virtual IP.

Example:

```text
R1 interface IP = 192.168.10.1
VRRP VIP        = 192.168.10.1
```

Therefore:

```text
R1 = IP Address Owner
```

The IP Address Owner has:

```text
Priority = 255
```

### Priority 255

Priority `255` is reserved for the IP Address Owner.

Normal VRRP routers generally use:

```text
Priority = 1–254
```

> **Exam trap:** VRRP priority `255` is special. It indicates the **IP Address Owner**.

---

# 9. VRRP Priority

Default priority:

```text
100
```

Higher priority wins the election.

Example:

```text
R1 = Priority 110
R2 = Priority 100
```

Result:

```text
R1 → Master
R2 → Backup
```

### Priority range

```text
1–255
```

But:

```text
255 = IP Address Owner
```

---

# 10. Election Tie-Breaker

If two routers have the same priority, the router with the **higher primary IPv4 address** wins.

Example:

```text
R1:
Priority = 100
IP       = 192.168.10.2

R2:
Priority = 100
IP       = 192.168.10.3
```

R2 wins:

```text
192.168.10.3 > 192.168.10.2
```

Therefore:

```text
R2 → Master
R1 → Backup
```

> **Exam rule:** Higher priority wins. If priority is equal, **higher primary IPv4 address wins**.

---

# 11. VRRP Advertisement

The Master periodically sends VRRP advertisements.

For IPv4:

```text
Source:
Master router

Destination:
224.0.0.18

IP Protocol:
112

TTL:
255
```

Default advertisement interval:

```text
1 second
```

Conceptually:

```text
Master
  |
  | VRRP Advertisement
  | every 1 second
  |
  +--------------------+
                       |
                       v
                    Backup
```

The Backup uses these advertisements to determine whether the Master is still operational.

---

# 12. Why TTL = 255 Matters

VRRP advertisements use:

```text
TTL = 255
```

A VRRP router receiving an advertisement expects the packet to have:

```text
TTL = 255
```

If the TTL is lower, the packet was routed through another Layer-3 hop and is not considered a valid directly connected VRRP advertisement.

This helps prevent VRRP packets from being accepted from off-link sources.

> **Exam trap:** Remember **VRRP IPv4 → protocol 112 → multicast 224.0.0.18 → TTL 255**.

---

# 13. VRRP Virtual MAC

For IPv4 VRRP:

```text
0000.5e00.01XX
```

Where:

```text
XX = VRID in hexadecimal
```

Example:

```text
VRID = 10

10 decimal = 0A hexadecimal

Virtual MAC:
0000.5e00.010A
```

The virtual MAC allows hosts to continue forwarding frames to the virtual router even when the physical Master changes.

---

# 14. ARP and VRRP

For IPv4, hosts use ARP to resolve the VIP.

Example:

```text
Host:
Who has 192.168.10.1?
```

The VRRP Master responds using the VRRP virtual MAC.

Conceptually:

```text
VIP:
192.168.10.1

        ↓ ARP

Virtual MAC:
0000.5e00.010A

        ↓

VRRP Master
```

After failover:

```text
Old Master → failed

New Master
     |
     +---- uses same VIP
     +---- uses same virtual MAC
```

The host's default gateway remains unchanged.

---

# 15. VRRP for IPv6

VRRPv3 supports IPv6.

IPv6 does not use ARP.

Instead, IPv6 uses:

```text
Neighbor Discovery (ND)
```

Therefore:

```text
IPv4 VRRP → ARP
IPv6 VRRP → Neighbor Discovery
```

VRRPv3 provides redundancy for IPv6 virtual routers while maintaining the same basic Master/Backup concept.

> **Exam note:** VRRPv3 is the version to associate with IPv6 support.

---

# 16. VRRP Timers

Default advertisement interval:

```text
1 second
```

VRRP does not simply use a fixed:

```text
3 × advertisement interval
```

for the exact Master Down Interval.

The calculation includes **Skew Time**.

```text
Skew_Time =
(256 - Priority) / 256
```

Then:

```text
Master_Down_Interval =
(3 × Advertisement_Interval) + Skew_Time
```

With the default advertisement interval:

```text
Advertisement = 1 second
```

the Master Down Interval is approximately:

```text
3 seconds + priority-based skew
```

---

# 17. Why Skew Time Exists

Skew time helps prevent multiple Backup routers from attempting to become Master simultaneously.

Higher-priority routers have a smaller skew.

Lower-priority routers have a larger skew.

Conceptually:

```text
Higher Priority
      ↓
Smaller Skew
      ↓
Earlier takeover
```

Therefore, the higher-priority Backup is favored during the Master election.

---

# 18. Preemption

VRRP supports **preemption**.

Preemption allows a higher-priority router to become Master when it is eligible.

Example:

```text
Normal:

R1 = Priority 110 → Master
R2 = Priority 100 → Backup
```

R1 fails:

```text
R1 → DOWN

R2 → Master
```

R1 returns:

```text
R1 = Priority 110
R2 = Priority 100
```

With preemption:

```text
R1 → Master
R2 → Backup
```

VRRP's default behavior allows higher-priority routers to preempt lower-priority Masters.

> **HSRP comparison:** Traditional HSRP requires `preempt` to be configured for priority-based role recovery; VRRP preemption is enabled by default.

---

# 19. Preemption Delay

Preemption can be delayed after a router becomes eligible.

A preemption delay can be useful when a router has just recovered and its routing interfaces or upstream paths are not yet fully operational.

Conceptually:

```text
Router returns
      ↓
Wait for preemption delay
      ↓
Routing converges
      ↓
Router becomes Master
```

This prevents an unstable or partially recovered router from immediately taking over gateway forwarding.

Exact CLI syntax is platform and IOS/IOS XE version dependent.

---

# 20. Priority 0

VRRP defines a special priority value:

```text
Priority = 0
```

A Master can use a priority-0 advertisement to indicate that it is **relinquishing the Master role**.

This allows Backup routers to react immediately rather than waiting for the normal Master Down Interval.

Conceptually:

```text
Current Master
      |
      | Priority 0 advertisement
      ↓
Backups
      |
      ↓
New Master election
```

> **Exam trap:** Priority `0` and priority `255` have special meanings.  
> `0` = Master is relinquishing the role.  
> `255` = IP Address Owner.

---

# 21. VRRP Tracking

VRRP implementations can track interfaces or objects and adjust the router's effective priority.

Example concept:

```text
Normal priority:
110

Tracked uplink fails:
110 - 20

Effective priority:
90
```

Another router may then have the higher effective priority and become Master.

Conceptually:

```text
Tracked uplink
      ↓
Failure
      ↓
Priority decrement
      ↓
Lower effective priority
      ↓
Another router may become Master
```

> **Exam point:** Tracking changes **priority/election preference**; it does not directly change the VIP.

---

# 22. Multiple VRIDs and Load Sharing

Multiple VRIDs can be used to distribute gateway forwarding responsibility.

Example:

```text
VRID 10:
R1 → Master
R2 → Backup

VRID 20:
R2 → Master
R1 → Backup
```

This provides gateway load sharing.

Example:

```text
VRID 10
VIP = 192.168.10.1
R1 preferred

VRID 20
VIP = 192.168.10.254
R2 preferred
```

Each VRID has its own:

- Virtual IP
    
- Virtual MAC
    
- Master
    
- Backup election
    
- Priority

# 24. VRRP Authentication

Older VRRPv2 specifications included authentication-related mechanisms.

VRRPv3 removed the VRRP authentication mechanism from the protocol specification.

Modern deployments should therefore not treat VRRP authentication as a core VRRPv3 feature.

> **Exam note:** If authentication appears in a VRRP question, determine which **VRRP version** the question is referring to.

# 25. Cisco Configuration Concept

Cisco VRRP configuration syntax is **platform and IOS/IOS XE version dependent**.

A common configuration concept is:

```cisco
interface GigabitEthernet0/0
 ip address 192.168.10.2 255.255.255.0
 vrrp 10 ip 192.168.10.1
 vrrp 10 priority 110
```

Another router:

```cisco
interface GigabitEthernet0/0
 ip address 192.168.10.3 255.255.255.0
 vrrp 10 ip 192.168.10.1
 vrrp 10 priority 100
```

Result:

```text
VRID 10
VIP = 192.168.10.1

R1 → Master
R2 → Backup
```

Always verify the exact command syntax on the Cisco platform being used:

```cisco
vrrp ?
```

VRRP can be inspected with packet-capture tools such as Wireshark.

For IPv4 VRRP, look for:

```text

112
```

```text
Destination:
```

```text
TTL:
255
```

Check:

```text
VRID
Priority
Advertisement Interval
Virtual IP
```

A useful troubleshooting flow is:

```text
1. Is the interface up?
        ↓
2. Are routers in the same Layer-2 segment?
        ↓
3. Is VRID correct?
        ↓
4. Is VIP correct?
        ↓
5. Are priorities correct?
        ↓
6. Are VRRP advertisements visible?
        ↓
7. Is multicast 224.0.0.18 reachable at L2?
        ↓
8. Is TTL 255?
        ↓
9. Is tracking changing priority?
        ↓
10. Is preemption affecting the election?
```

# 28. Common Failure Scenarios

### 28.1 Master Failure

```text
R1 → Master
R2 → Backup

R1 fails
   ↓
R2 stops receiving advertisements
   ↓
Master Down Interval
   ↓
R2 → Master
```

---

### 28.2 Backup Failure

```text
R1 → Master
R2 → Backup

R2 fails
   ↓
R1 remains Master
   ↓
No gateway outage
```

---

### 28.3 VLAN Partition

If the routers can no longer communicate at Layer 2:

```text
R1 → thinks it is Master
R2 → may think it is Master
```

This can result in:

```text
Two Masters
```

because each side may stop receiving the other's advertisements.

---

### 28.4 Tracking Failure

```text
R1 → Master
Priority = 110

Tracked uplink fails
       ↓
Priority decreases
       ↓
Effective priority = 90

R2 = Priority 100
       ↓
R2 becomes Master
```

---

### 28.5 Duplicate VRID/VIP

Incorrect configuration can cause unexpected elections or gateway behavior.

Check:

```text
VRID
VIP
Subnet
Interface
Priority
```

|Feature|HSRP|VRRP|
|---|---|---|
|Type|FHRP|FHRP|

|VRRPv2 RFC|—|RFC 3768|

|IPv4 Transport|UDP|IP protocol|
|Transport Number|UDP `1985`|IP `112`|
|IPv4 Multicast|`224.0.0.2` (HSRPv1)|`224.0.0.18`|
|Default Priority|`100`|`100`|
|Election|Highest priority|Highest priority|
|Tie-break|Highest IP|Highest primary IPv4 address|
|Main Role|Active|Master|
|Backup Role|Standby|Backup|
|HSRPv1 Virtual MAC|`0000.0c07.acXX`|—|
|VRRP IPv4 Virtual MAC|—|`0000.5e00.01XX`|
|Default Hello/Advert|`3 s`|`1 s`|

|Multi-vendor|Limited|Yes|

# 32. Exam Traps

- VRRP is an **IETF-standard FHRP**.
    
- VRRPv2 = **RFC 3768**.
    
- VRRPv3 = **RFC 5798**.
    
- VRRP IPv4 uses **IP protocol 112**.
    
- VRRP IPv4 multicast = **224.0.0.18**.
    
- VRRP IPv4 virtual MAC = **0000.5e00.01XX**.
    
- Default priority = **100**.
    
- Priority range = **1–255**.
    
- Priority `255` = **IP Address Owner**.
    
- Priority `0` = Master is **relinquishing the role**.
    
- Higher priority wins.
    
- Equal priority → **higher primary IPv4 address wins**.
    
- VRRP uses **Master / Backup** terminology.
    
- Default advertisement interval = **1 second**.
    
- Master Down Interval includes **Skew Time**.
    
- Skew Time = `(256 - Priority) / 256`.
    
- VRRP preemption is **enabled by default**.
    
- VRRPv3 supports **IPv6**.
    
- IPv4 uses **ARP**; IPv6 uses **Neighbor Discovery**.
    
- VRRP advertisements use **TTL 255**.
    
- VRRP does **not use UDP**.
    
- VRRP uses **224.0.0.18**, not HSRP's `224.0.0.2`.
    
- The VIP can be the **real IP address of the IP Address Owner**.
    
- Multiple VRIDs can provide **gateway load sharing**.
    
- Tracking changes **effective priority**.
    
- VRRPv3 does not use the VRRPv2 authentication mechanism.
