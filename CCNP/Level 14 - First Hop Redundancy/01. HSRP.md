# HSRP (Hot Standby Router Protocol)

> **Level 14 · First Hop Redundancy** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**HSRP** (Cisco-proprietary) provides a **virtual IP (VIP)** that the hosts use as their
default gateway, while a single **active** router forwards for it and a **standby** waits.
Hosts keep one gateway; the active router fails over to the standby with minimal downtime.
Protocol = **UDP 1985, multicast 224.0.0.2**.

---

## 2. Core Concepts

### 2.1 Roles and priorities

| Role | Priority | State |
|------|----------|-------|
| Active | highest (default 100) | forwards for VIP |
| Standby | second | monitors, takes over |
| Speaker | lower | learns, never forwards |
| Listen | any | watches |
| Initial/Disabled | boot | — |

- **Priority** decides Actives; tie-breaks go to the **highest IP**.
- `preempt` lets a higher-priority router reclaim the Active role after a comeback.

### 2.2 Virtual MAC and addressing

- Virtual MAC = `0000.0c07.acXX` where XX = **group number** (hex).
- Group 0–255; VIP must be on the same subnet as real interfaces.
- Hosts ARP the VIP → get the virtual MAC → traffic hits the Active.

### 2.3 Hello and hold timers

| Timer | Default |
|-------|---------|
| Hello | 3 s |
| Hold | 10 s |

- **3 x hello = hold** is the exam rule; hold must be ≥ 3× hello.
- Lowering both (`timers 1 3`) gives sub-second failover.

### 2.4 Configuration

```text
interface Gi0/0
 ip address 10.0.0.2 255.255.255.0
 standby 10 ip 10.0.0.1          ! VIP
 standby 10 priority 110
 standby 10 preempt
 standby 10 track Gi0/1 20       ! decrement on uplink loss
```

- `track` drops the priority by the decrement when the tracked object fails (note 04).

### 2.5 Multiple groups / load sharing

```text
interface Gi0/0
 standby 10 ip 10.0.0.1
 standby 10 priority 110
 standby 20 ip 10.0.1.1
 standby 20 priority 90
```

- Two groups on the same interfaces = two VIPs; each router is Active for one — **load
  sharing**.
- One MAC per group (00.0c.07.ac0a / ac14…).

### 2.6 States and failover

| Transition | Trigger |
|------------|---------|
| Active→standby | loss of hello (hold expiry) or preempt |
| Standby→active | hold expiry, preempt, or priority drop |
| Object failure | tracked interface up/down (priority decrement) |

- Failover time ≈ hold + convergence (usually < ~10 s with defaults).

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Two actives | no mutual hellos / VLAN split | show standby both sides |
| No failover | preempt missing | standby preempt |
| VIP unreachable | VIP not in subnet / wrong group | interface + group |
| Hosts stuck ARP | virtual MAC missing | show ip arp |
| Unexpected active drop | tracking | show standby track |
| Instant flap | timers too aggressive | restore 3:1 hold |

---

## 5. Exam Traps

- HSRP is **Cisco-proprietary** (UDP 1985, 224.0.0.2).
- Virtual MAC = `0000.0c07.acXX` (XX = group).
- Priority default **100**; tie = highest IP.
- **Hold ≥ 3× hello**.
- `preempt` needed for automatic role recovery.
- `track` decrements priority on object failure.
- Multiple groups = load sharing.
