# HSRP (Hot Standby Router Protocol)

> **Level 14 · First Hop Redundancy** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**HSRP (Hot Standby Router Protocol)** is a **Cisco-developed First Hop Redundancy Protocol (FHRP)** that provides a redundant default gateway for hosts.

Multiple routers participate in an HSRP group and share a **Virtual IP Address (VIP)** and **Virtual MAC address**.

One router becomes **Active** and forwards traffic for the virtual gateway. Another router becomes **Standby** and monitors the Active router.

If the Active router fails, the Standby router takes over the same virtual gateway.

```text
Hosts
  |
  | Default Gateway = Virtual IP
  |
  v
+-----------------------------+
|          HSRP Group         |
|                             |
|   R1                  R2    |
| Active              Standby |
|                             |
+-----------------------------+
```

For IPv4 HSRP:

```text
HSRPv1:
  UDP          = 1985
  Multicast    = 224.0.0.2
  Virtual MAC  = 0000.0c07.acXX
  Groups       = 0–255

HSRPv2:
  UDP          = 1985
  Multicast    = 224.0.0.102
  Virtual MAC  = 0000.0c9f.fXXX
  Groups       = 0–4095
```

---

# 2. HSRP Versions

HSRP has two commonly referenced versions.

|Feature|HSRPv1|HSRPv2|
|---|---|---|
|Version|1|2|
|Transport|UDP|UDP|
|UDP Port|`1985`|`1985`|
|Multicast|`224.0.0.2`|`224.0.0.102`|
|Virtual MAC|`0000.0c07.acXX`|`0000.0c9f.fXXX`|
|Group Range|`0–255`|`0–4095`|
|IPv6 Support|No|No native IPv6 gateway redundancy|

> **Exam trap:** `224.0.0.2` and `0000.0c07.acXX` are specifically **HSRPv1** values. HSRPv2 uses `224.0.0.102` and `0000.0c9f.fXXX`.

---

# 3. HSRP Terminology

|Term|Meaning|
|---|---|
|**HSRP Group**|Logical HSRP instance identified by a group number|
|**VIP**|Virtual IP address used as the host default gateway|
|**Active**|Router currently forwarding traffic for the VIP|
|**Standby**|Backup router for the Active router|
|**Speak**|Participates in HSRP election and sends hellos|
|**Listen**|Receives HSRP information but does not participate in election|
|**Learn**|Attempts to learn the VIP and Active router information|
|**Initial**|Initial HSRP state|
|**Priority**|Determines which router should become Active|
|**Preemption**|Allows a higher-priority router to reclaim Active|
|**Tracking**|Changes HSRP priority when a tracked object fails|
|**VIP**|Virtual gateway IP address|
|**Virtual MAC**|MAC address associated with the HSRP group|

---

# 4. HSRP States

HSRP uses the following states:

```text
Initial
   ↓
Learn
   ↓
Listen
   ↓
Speak
   ↓
Standby
   ↓
Active
```

## 4.1 Initial

The interface has started HSRP processing but has not yet entered normal operation.

---

## 4.2 Learn

The router does not yet know the virtual IP address and attempts to learn it from HSRP messages.

---

## 4.3 Listen

The router knows the virtual IP but is neither Active nor Standby.

It listens to HSRP messages.

---

## 4.4 Speak

The router participates in the HSRP election and sends hello messages.

---

## 4.5 Standby

The router is the primary backup for the Active router.

It monitors the Active router.

Normally:

```text
Active = forwarding
Standby = backup
```

---

## 4.6 Active

The router forwards traffic destined for the HSRP virtual MAC.

It also sends HSRP hello messages.

---

# 5. HSRP Election

HSRP uses **priority** to determine which router becomes Active.

Default priority:

```text
100
```

Higher priority wins.

Example:

```text
R1 = Priority 110
R2 = Priority 100
```

Result:

```text
R1 → Active
R2 → Standby
```

---

# 6. HSRP Priority

HSRP priority is normally configured between:

```text
1–255
```

Default:

```text
100
```

Example:

```cisco
interface GigabitEthernet0/0
 standby 10 priority 110
```

This gives the router:

```text
Priority = 110
```

### Important

Priority can be dynamically reduced through tracking.

Example:

```text
Normal:
110

Tracked object fails:
110 - 20

Effective priority:
90
```

---

# 7. Election Tie-Breaker

If two routers have the same priority, the router with the **higher IP address** wins.

Example:

```text
R1:
Priority = 100
IP       = 192.168.10.2

R2:
Priority = 100
IP       = 192.168.10.3
```

R2 wins:

```text
192.168.10.3 > 192.168.10.2
```

Therefore:

```text
R2 → Active
R1 → Standby
```

> **Exam rule:** Higher priority wins. If priority is equal, **higher IP address wins**.

---

# 8. Virtual IP Address

The **Virtual IP Address (VIP)** is the gateway address configured on hosts.

Example:

```text
R1 real IP = 192.168.10.2
R2 real IP = 192.168.10.3

HSRP VIP   = 192.168.10.1
```

Hosts use:

```text
Default Gateway = 192.168.10.1
```

The hosts do not need to know whether R1 or R2 is currently forwarding.

---

# 9. Virtual MAC Address

HSRP provides a virtual MAC address for the HSRP group.

## HSRPv1

```text
0000.0c07.acXX
```

Where:

```text
XX = HSRP group number in hexadecimal
```

Example:

```text
Group 10
10 decimal = 0A hexadecimal

Virtual MAC:
0000.0c07.ac0a
```

## HSRPv2

```text
0000.0c9f.fXXX
```

The HSRP group number is represented in the final portion.

Example:

```text
Group 10:

Virtual MAC:
0000.0c9f.f00a
```

> **Exam trap:** Know both HSRPv1 and HSRPv2 virtual MAC formats.

---

# 10. ARP and HSRP

Hosts use ARP to resolve the HSRP VIP to the virtual MAC.

Example:

```text
Host
 |
 | ARP:
 | Who has 192.168.10.1?
 |
 v
HSRP Active
 |
 | ARP response
 |
 v
Virtual MAC
0000.0c07.ac0a
```

The host then sends Ethernet frames toward the virtual MAC.

If the Active router fails:

```text
Old Active
    ↓
Fails
    ↓
Standby becomes Active
    ↓
Same VIP
    ↓
Same virtual MAC
```

The host does not need a new default gateway.

---

# 11. HSRP Hello Messages

HSRP routers exchange hello messages to maintain the HSRP relationship.

Default timers:

```text
Hello = 3 seconds
Hold  = 10 seconds
```

Conceptually:

```text
Active
  |
  | Hello
  | Hello
  | Hello
  v
Standby
```

The Standby uses the hold timer to determine whether the Active router is unavailable.

---

# 12. HSRP Timer Configuration

Example:

```cisco
interface GigabitEthernet0/0
 standby 10 timers 1 3
```

This configures:

```text
Hello = 1 second
Hold  = 3 seconds
```

Lower timers can reduce failure-detection time but can also increase sensitivity to packet loss and transient conditions.

> **Exam rule:** The hold timer should be at least **3× the hello timer**.

---

# 13. HSRP Failure Detection

With default timers:

```text
Hello = 3 seconds
Hold  = 10 seconds
```

The Standby can take up to approximately:

```text
10 seconds
```

to detect loss of the Active router through HSRP hello failure.

The actual application/network recovery time can be longer because additional convergence may be required.

---

# 14. HSRP Preemption

By default, HSRP does **not** allow a higher-priority router to automatically reclaim the Active role.

Enable preemption:

```cisco
interface GigabitEthernet0/0
 standby 10 preempt
```

Example:

```text
Initial:

R1 = Priority 110 → Active
R2 = Priority 100 → Standby
```

R1 fails:

```text
R1 → Down
R2 → Active
```

R1 returns:

```text
R1 = Priority 110
R2 = Priority 100
```

Without preemption:

```text
R2 → remains Active
R1 → remains Standby
```

With preemption:

```text
R1 → Active
R2 → Standby
```

> **Exam trap:** HSRP failover does not require preemption. **Preemption is required for priority-based role recovery.**

---

# 15. HSRP Preemption Delay

A recovering router can be configured to wait before reclaiming the Active role.

Conceptually:

```text
Router returns
     ↓
Wait
     ↓
Routing converges
     ↓
Preemption
     ↓
Router becomes Active
```

This is useful when the router's interfaces are up but its routing paths are not yet fully operational.

Example concept:

```cisco
interface GigabitEthernet0/0
 standby 10 preempt delay minimum 30
```

The exact available preemption-delay options are platform/version dependent.

---

# 16. HSRP Tracking

HSRP can track an interface or object.

If the tracked object fails, HSRP reduces the router's priority by the configured decrement.

Example:

```cisco
interface GigabitEthernet0/0
 standby 10 ip 192.168.10.1
 standby 10 priority 110
 standby 10 preempt
 standby 10 track GigabitEthernet0/1 20
```

Normal:

```text
Priority = 110
```

If Gi0/1 fails:

```text
110 - 20 = 90
```

If another router has priority 100:

```text
R1 = 90
R2 = 100
```

R2 can become Active.

---

# 17. Why Tracking Matters

Consider:

```text
R1 LAN interface = UP
R1 WAN interface = DOWN
```

Without tracking:

```text
R1 may remain Active
```

Even though its upstream path is broken.

With tracking:

```text
WAN failure
    ↓
Tracked object fails
    ↓
HSRP priority decreases
    ↓
Backup router becomes preferred
```

This makes HSRP respond to **path failure**, not just gateway-router failure.

---

# 18. Object Tracking and IP SLA

HSRP can work with object tracking.

A common advanced design is:

```text
IP SLA
   ↓
Object Tracking
   ↓
HSRP Priority
   ↓
Active/Standby Election
```

Example scenario:

```text
R1
 |
 | Internet
 X
```

The physical interface may remain:

```text
UP/UP
```

while Internet reachability is broken.

IP SLA can test a remote destination.

If the test fails:

```text
IP SLA fails
    ↓
Track object goes down
    ↓
HSRP priority decreases
    ↓
Other router becomes Active
```

This is more intelligent than simply tracking interface state.

---

# 19. HSRP Priority 0

HSRP supports a special priority value:

```text
0
```

A router can send an HSRP message with priority 0 to indicate that it is **relinquishing the Active role**.

Conceptually:

```text
Current Active
      |
      | Priority 0
      ↓
Standby
      |
      ↓
Becomes Active
```

This allows a transition to occur without waiting for the normal hold timer.

> **Exam trap:** Priority `0` can indicate that the current Active router is relinquishing its role.

---

# 20. HSRP Authentication

HSRP supports authentication mechanisms depending on HSRP version and platform.

Authentication can be used to help ensure that only correctly configured routers participate in the HSRP group.

A mismatch can prevent proper HSRP communication.

For troubleshooting:

```text
Check:
- HSRP version
- Authentication configuration
- Group number
- VIP
- Interface/VLAN
```

> **Exam note:** Authentication behavior differs between HSRPv1 and HSRPv2 and can be platform-dependent. Always verify the exact Cisco IOS/IOS XE implementation.

# 23. HSRPv1 vs HSRPv2 Multicast

### HSRPv1

```text
224.0.0.2
```

This multicast address is:

```text
All Routers
```

### HSRPv2

```text
224.0.0.102
```

This multicast address is used by HSRPv2.

> **Exam trap:** If a question gives `224.0.0.2`, think **HSRPv1**. If it gives `224.0.0.102`, think **HSRPv2**.

# 25. Multiple HSRP Groups

Multiple HSRP groups can be configured on the same LAN.

Each group has its own:

- Virtual IP
    
- Virtual MAC
    
- Active router
    
- Standby router
    
- Priority
    

Example:

```text
Group 10:
VIP = 192.168.10.1

Group 20:
VIP = 192.168.10.254
```

---

# 26. HSRP Gateway Load Sharing

Multiple groups can be used for gateway load sharing.

Example:

### R1

```text
Group 10 → Priority 110 → Active
Group 20 → Priority 90  → Standby
```

### R2

```text
Group 10 → Priority 90  → Standby
Group 20 → Priority 110 → Active
```

Result:

```text
Group 10:
R1 → Active
R2 → Standby

Group 20:
R2 → Active
R1 → Standby
```

This distributes gateway forwarding responsibility.

> **Important:** The VIPs must belong to the correct subnet associated with the LAN/VLAN.

# 27. HSRP Failover

Normal operation:

```text
                 HSRP Group
                     |
             +-------+-------+
             |               |
            R1              R2
         Active           Standby
       Priority 110     Priority 100
             |               |
             +-------+-------+
                     |
                 HSRP VIP
                     |
                   Hosts
```

If R1 fails:

```text
R1 Active
    ↓
R1 fails
    ↓
R2 stops receiving hellos
    ↓
Hold timer expires
    ↓
R2 becomes Active
    ↓
R2 forwards for same VIP/MAC
```

Hosts continue using the same gateway.

---

# 28. HSRP Split-Brain / Dual Active

If HSRP routers cannot receive each other's hellos, each router may believe that the other router is unavailable.

Possible causes:

```text
VLAN partition
Trunk failure
Layer-2 connectivity problem
Multicast filtering
Incorrect VLAN configuration
```

Possible result:

```text
R1 → Active
R2 → Active
```

This is often called a **dual-active** or split-brain condition.

Troubleshoot:

```text
show standby
show interfaces trunk
show vlan brief
show spanning-tree
```

Also verify that the routers are in the same Layer-2 broadcast domain.

# 29. HSRP Failure Scenarios

### Active failure

```text
Active fails
   ↓
Standby detects failure
   ↓
Standby becomes Active
```

### Standby failure

```text
Standby fails
   ↓
Active remains Active
   ↓
No gateway interruption
   ↓
Redundancy is temporarily lost
```

### VLAN failure

```text
HSRP hellos stop
   ↓
Routers may independently become Active
```

### Uplink failure

```text
Uplink fails
   ↓
Tracking detects failure
   ↓
Priority decreases
   ↓
Other router may become Active
```

|Symptom|Likely Cause|Check|
|---|---|---|
|Two Active routers|VLAN/L2 split, multicast problem|`show standby`, VLAN/trunk|

|Gateway path broken but Active remains|No tracking/IP SLA|Tracking configuration|

# 35. HSRP IP SLA + Tracking

A more advanced design can use IP SLA.

Concept:

```text
IP SLA
   ↓
Track Object
   ↓
HSRP Priority
   ↓
HSRP Election
```

Example conceptual configuration:

```cisco
ip sla 1
 icmp-echo 8.8.8.8 source-interface GigabitEthernet0/1
 frequency 5
ip sla schedule 1 life forever start-time now

track 1 ip sla 1 reachability

interface GigabitEthernet0/0
 standby 10 ip 192.168.10.1
 standby 10 priority 110
 standby 10 preempt
 standby 10 track 1 decrement 30
```

If the SLA test fails:

```text
IP SLA fails
     ↓
Track object DOWN
     ↓
HSRP priority:
110 - 30 = 80
     ↓
Other router may become Active
```

> **Note:** Exact IP SLA/HSRP syntax can vary by Cisco IOS/IOS XE release.

# 36. HSRP and Spanning Tree

HSRP and STP solve different problems.

### STP

Controls:

```text
Layer-2 loops
```

### HSRP

Provides:

```text
Default-gateway redundancy
```

Together:

```text
STP
 ↓
Layer-2 path selection

HSRP
 ↓
Default-gateway redundancy
```

A common campus design aligns STP root placement with HSRP gateway preference.

Example:

```text
VLAN 10:
SW1 → STP Root
R1  → HSRP Active

VLAN 20:
SW2 → STP Root
R2  → HSRP Active
```

This can reduce unnecessary Layer-2 traffic paths.

---

# 37. HSRP and ARP/CAM

Hosts learn:

```text
VIP → Virtual MAC
```

Switches learn:

```text
Virtual MAC → Active router's switchport
```

After failover:

```text
Old Active
    ↓
Fails

New Active
    ↓
Uses same virtual MAC
    ↓
Switch relearns MAC location
```

This allows traffic to move toward the new Active router.

> **Important:** HSRP provides the virtual gateway identity; Layer-2 switching still needs to learn where the virtual MAC is currently reachable.

# 39. HSRP vs VRRP

|Feature|HSRP|VRRP|
|---|---|---|
|Type|FHRP|FHRP|
|Standard|Cisco-developed|IETF standard|
|IPv4 Transport|UDP|IP protocol|
|Transport|UDP `1985`|IP `112`|
|HSRPv1 Multicast|`224.0.0.2`|—|
|HSRPv2 Multicast|`224.0.0.102`|—|
|VRRP Multicast|—|`224.0.0.18`|
|Default Priority|`100`|`100`|
|Main Role|Active|Master|
|Backup Role|Standby|Backup|
|HSRPv1 Virtual MAC|`0000.0c07.acXX`|—|
|HSRPv2 Virtual MAC|`0000.0c9f.fXXX`|—|
|VRRP Virtual MAC|—|`0000.5e00.01XX`|
|Default Hello/Advert|`3 s`|`1 s`|
|Default Hold/Down|`10 s`|~`3 s` + skew|
|Preemption|Disabled by default|Enabled by default|
|Tie-break|Higher IP|Higher primary IP|
|Multiple Groups|Yes|Multiple VRIDs|
|Multi-vendor|Limited|Yes|

# 41. Exam Traps

- HSRP is a **Cisco-developed FHRP**.
    
- HSRP uses **UDP port 1985**.
    
- HSRPv1 multicast = **224.0.0.2**.
    
- HSRPv2 multicast = **224.0.0.102**.
    
- HSRPv1 virtual MAC = **0000.0c07.acXX**.
    
- HSRPv2 virtual MAC = **0000.0c9f.fXXX**.
    
- HSRPv1 supports groups **0–255**.
    
- HSRPv2 supports groups **0–4095**.
    
- Default priority = **100**.
    
- Higher priority wins.
    
- Equal priority → **higher IP address wins**.
    
- HSRP uses **Active / Standby** terminology.
    
- Default hello = **3 seconds**.
    
- Default hold = **10 seconds**.
    
- Hold should be at least **3× hello**.
    
- `preempt` is **not required for basic failover**.
    
- `preempt` is required for automatic **priority-based role recovery**.
    
- Tracking **decrements priority**.
    
- IP SLA can feed object tracking.
    
- Multiple HSRP groups can provide **gateway load sharing**.
    
- HSRP uses the virtual IP as the host's default gateway.
    
- Hosts ARP for the VIP and learn the virtual MAC.
    
- HSRP packets use **UDP 1985**.
    
- HSRP authentication can affect peer formation.
    
- HSRP and STP solve different problems.
    
- HSRP split-brain can produce **dual Active** routers.
    
- HSRPv1 and HSRPv2 use different multicast addresses and virtual MAC formats.
    
- Priority `0` can indicate that an HSRP router is relinquishing its role.
    
- Actual network recovery can take longer than the HSRP hold timer because other convergence may be involved.

# 43. One-Minute Mental Model

```text
                         HSRP
                           |
                    Virtual Gateway
                           |
              +------------+------------+
              |                         |
             R1                        R2
          ACTIVE                    STANDBY
       Priority 110              Priority 100
              |                         |
              +------------+------------+
                           |
                       Virtual IP
                     192.168.10.1
                           |
                         Hosts
```

Normal:

```text
R1 = Active
R2 = Standby
VIP = 192.168.10.1
```

R1 fails:

```text
R1 Active
    ↓
R1 fails
    ↓
R2 stops receiving HSRP hellos
    ↓
Hold timer expires
    ↓
R2 becomes Active
    ↓
Same VIP
    ↓
Same virtual MAC
    ↓
Hosts continue using same gateway
```

> **Core idea:** **HSRP provides a Cisco-developed virtual default gateway. The Active router forwards traffic for the virtual IP/MAC, the Standby router monitors it, and the Standby takes over when the Active fails. Priority, preemption, tracking, and multiple HSRP groups control which router provides the gateway and how traffic is distributed.**
