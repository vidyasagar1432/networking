# Performance Analysis

> **Level 29 · Troubleshooting** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Performance analysis** isolates **latency, throughput, jitter, and loss** and ties
them to the network path. Tools: ping, traceroute, NetFlow, IP SLA, and protocol
analyzers. The exam tests interpreting metric patterns and root-causing performance.

---

## 2. Core Concepts

### 2.1 Key metrics

| Metric | Meaning |
|--------|---------|
| Latency | RTT delay |
| Throughput | bits/sec |
| Jitter | delay variation |
| Loss | dropped % |
| Utilization | capacity use |

- **Define the metric before measuring.**

### 2.2 Latency components

| Component | Where |
|-----------|-------|
| Serialization | link speed |
| Propagation | distance |
| Processing | router |
| Queueing | congestion |

- **Latency = serialization + propagation + processing + queueing.**

### 2.3 Tools

| Tool | Measures |
|------|----------|
| ping | RTT/loss |
| traceroute | hop latency |
| IP SLA | jitter/loss |
| NetFlow | throughput/apps |
| Wireshark | packet timing |
| SNMP | utilization |

- **IP SLA** gives jitter; **NetFlow** gives flows.

### 2.4 Interpreting patterns

| Pattern | Meaning |
|---------|---------|
| Constant high | serialization/distance |
| Spiking | queueing |
| Burst loss | congestion |
| One-way high | asymmetric |
| TTL cut | loop/hop |

- Match **pattern → cause**.

### 2.5 Throughput vs bandwidth

| Term | Detail |
|------|--------|
| Bandwidth | capacity |
| Throughput | delivered |
| TCP window | limits |
| Window scaling | helps |
| Drop | shrinks |

- **TCP behavior** often caps throughput before links do.

### 2.6 Analysis workflow

| Step | Action |
|------|--------|
| 1 | baseline |
| 2 | measure latency/loss |
| 3 | identify segment |
| 4 | capture |
| 5 | confirm fix |

- **Baseline → measure → isolate → capture → verify.**

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| High RTT | distance/queue | traceroute |
| Jitter | queue | ip sla |
| Loss | congestion | ping |
| Low TP | window | TCP |
| CPU | process | show processes |

---

## 5. Exam Traps

- Latency = **4 components** (serial/prop/process/queue).
- **Jitter ≠ latency** — variation not level.
- TCP window affects **throughput** independent of bandwidth.
- IP SLA = **active measurement** of SLA metrics.
- Baseline first; **isolate before fixing**.
