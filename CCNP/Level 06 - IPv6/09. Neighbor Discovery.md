# Neighbor Discovery (ND / NDP)

> **Level 06 · IPv6** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Neighbor Discovery (ND)** is IPv6's layer-2-to-3 bootstrap — the direct replacement
for **IPv4 ARP, ICMP redirects, and router discovery**, powered by **ICMPv6** messages.
It runs as part of every IPv6 link.

---

## 2. Core Concepts

### 2.1 The five ND messages (ICMPv6 types)

| Message | ICMPv6 Type | Use |
|---------|-------------|-----|
| **RS** Router Solicitation | 133 | "any router?" → sent to ff02::2 at boot |
| **RA** Router Advertisement | 134 | router responds (prefix, flags, lifetime, DNS) |
| **NS** Neighbor Solicitation | 135 | "who has this addressed by..." (like ARP) |
| **NA** Neighbor Advertisement | 136 | "I have it (my MAC)" / unsolicited too |
| **Redirect** | 137 | better next hop (like ICMPv4 redirect) |

### 2.2 Replaces ARP entirely

| IPv4 | IPv6 |
|------|------|
| ARP broadcast to ff:ff:ff... | **NS/NA** to **solicited-node multicast** |
| RARP (legacy) | ND |
| default gateway static/RA? | RA gives default route |
| duplicate IP check | **DAD** (NS/NA) |

**Solicited-node multicast** `ff02::1:ffXX:XXXX` — only ~1/65536 of the link gets the
request. Far more scalable than broadcast.

### 2.3 What ND achieves (summary of roles it plays)
1. **Address resolution** — LL → MAC (NS/NA), cached in neighbor cache.
2. **Router discovery** — default gateway(s) from RA.
3. **Address auto-config** — prefix from RA → SLAAC.
4. **DAD** — duplicate address detection.
5. **Neighbor unreachability detection (NUD)** — confirm reachability; detects
   link-down peers.
6. **Redirect** — on-link host told better route.
7. **Stateless DHCPv6 signaling** — M/O flags.

### 2.4 Neighbor cache & the reachability states

| State | Meaning |
|-------|---------|
| **INCOMPLETE** | NS sent, no NA yet |
| REACHABLE | confirmed reachable |
| STALE | no recent traffic; may be fine |
| DELAY | waiting a brief probe |
| PROBE | sending NS to confirm |
- `show ipv6 neighbors` on IOS = the cache.

### 2.5 ND security exposure
- **RA spoofing** — a rogue RA can become default gateway (MITM). Mitigate with
  **RA Guard** (per-port), SAVI, etc. — an exam security item (Level 17).
- **NA spoofing** — like ARP poisoning; **ND snooping/DAI analog** used.

## 3. Configuration / Commands

```text
# On interface, ND lives automatically; tune it:
interface GigabitEthernet0/1
 ipv6 nd ra-interval 30
 ipv6 nd ra-lifetime 1800
 ipv6 nd prefix 2001:db8:1:10::/64
 ipv6 nd managed-config-flag          # M=1

# View neighbor cache
show ipv6 neighbors
# View ND-related interface state
show ipv6 interface Gi0/1 | include Neighbor

# RA Guard (defender for ports toward users)
interface GigabitEthernet0/1
 ipv6 nd raguard policy-block-role?  (platform-specific)
```

## 4. Exam Traps

- **ND = ICMPv6-based**, not ARP — "IPv6 uses ARP" is always wrong.
- **NS target is solicited-node multicast**, not all-nodes.
- **RS/RA are router discovery; NS/NA are neighbors** — don't mix 133/134 vs 135/136.
- **ND replaces ARP, but also ICMP redirects and provides DAD/SLAAC.**
- **RA gives the default route** — even under DHCPv6, ND supplies it.
- **RA Guard** mitigates spoofed gateways (before cDAI in the story).
