# Multicast (IPv6)

> **Level 06 · IPv6** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

IPv6 multicast uses **`ff00::/8`** — richer than IPv4 (no separate class, flags/scopes
embedded). It replaces broadcast entirely: any-to-any neighbor and "all nodes" are
multicast groups.

---

## 2. Core Concepts

### 2.1 Format: `ff` + flags + scope + group ID
```
ff 0 T | scope (4 bits) | 112-bit group ID
```

| Field | Meaning | Detail |
|-------|---------|--------|
| `ff` | multicast | always |
| **flags** | T (transient vs permanent), P, R, etc. | T=0 well-known flag |
| **scope** | 1 interface, 2 link, 5 site, 8 org, E global | low bits |
| group ID | group within scope | 112 bits (last 32 derived from IPv4 mapping for SSM?) |

### 2.2 Scope values (memorize)

| Value | Scope | Group examples |
|-------|-------|----------------|
| 1 | interface-local | ff01::10 |
| 2 | **link-local** | `ff02::1` all nodes; `ff02::2` all routers; `ff02::5` OSPF |
| 5 | site-local | ff05::2 site routers |
| 8 | organization-local | ff08::… |
| E | global | ff0e::… |
| F | reserved | — |

### 2.3 Well-known groups you must know

| Group | Meaning |
|-------|---------|
| `ff02::1` | all nodes on link (replaces IPv4 broadcast's role) |
| `ff02::2` | all routers on link |
| `ff02::5` | OSPFv3 ALLSPFRouters |
| `ff02::6` | OSPFv3 DR/BDR |
| `ff02::9` | RIPv2 → eigrp? No: combined in tests v2 — eigrp uses ff02::A |
| `ff02::A` | EIGRP routers |
| `ff02::1:2` | ALL DHCPv6 (clients/servers) |
| `ff02::1:3` | LLMNR |
| `ff02::16` | MLDv2 |
| `ff02::FB` | mDNS |

### 2.4 MLD (Multicast Listener Discovery)
- IPv6's IGMP equivalent: **MLDv1** (like IGMPv2) / **MLDv2** (source filtering,
  supports SSM). Routers use it to learn who wants a group.
- Switches use **MLD snooping** to forward group traffic to only interested ports.

### 2.5 Multicast vs broadcast replacement
- No **IPv6 broadcast address** exists; jobs performed by:
  - ND (solicited-node multicast `ff02::1:ffxx:xxxx` / NS)
  - DHCPv6 relay → messages use `ff02::1:2`.
- Link-local multicast (ff02, TTL=1) sets the scoped range — never routed.

## 3. Configuration / Commands

```text
# Enable multicast + MLD on router
interface GigabitEthernet0/1
 ipv6 multicast routing
 ipv6 mld version 2              # MLDv2 default many platforms
# PIM for IPv6
ipv6 router pim
interface Gi0/1
 ipv6 pim sparse-mode

show ipv6 mroute
show ipv6 mld groups
```

---

## 4. Exam Traps

- **Scope in the address** — ff02 (link) vs ff05 (site) — determines routing boundary.
- **No broadcast in IPv6** — always say multicast/ND replaces it.
- **ff02::1 = all nodes (like IPv4 broadcast role), but multicast group, not broadcast.**
- **MLD is the IGMP analog; MLDv2 enables SSM with (S,G).**
- **Solicited-node multicast** `ff02::1:ff00:0/104` — used for ND; a favorite calcu.
- Well-known numbering in hex quirks (ff02::9 vs ::A) appear in protocol questions.
