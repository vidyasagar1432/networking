# Anycast

> **Level 06 · IPv6** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Anycast** = the **same unicast address assigned to multiple nodes**; a packet goes to
the **nearest** one (by routing metric). Available since IPv4 but first-class in IPv6
(addressed as ordinary global unicast). Powers DNS, cloud, CDNs.

---

## 2. Core Concepts

### 2.1 How it works
- Many distinct hosts hold the **same IPv6 address** (typically a GUA /32 or inside).
- They advertise the same prefix: routing picks the **topologically closest / best** path.
- In IPv4 you implement with BGP same prefix from many ASs; IPv6 does the same, but the
  address itself isn't distinguishable from unicast.

### 2.2 Anycast vs Unicast vs Multicast (the trio)

| | Unicast | Anycast | Multicast |
|--|---------|---------|-----------|
| Dest address | unique host | multiple identical | group |
| Who receives | one | **one** (nearest) | **all** members |
| Purpose | 1:1 | 1:nearest-of-N | 1:N |
| IPv6 form | GUA | GUA (shared) | ff00::/8 |
| Example | ssh to server | DNS root servers | video feeds |

### 2.3 Anycast address structure in IPv6
- No special prefix; any unicast prefix can be anycast.
- **Subnet-anycast /7 field** is reserved (RFC 2526): the last 128 bits with a
  specific pattern (`...:0:0` = subnet router anycast) — routers need not worry.
- Practical deployments: /128 anycast on loopbacks or /64+ subnet anycast.

### 2.4 Where you meet anycast in the real world / ENCOR
- **DNS root servers** (13 logical roots, hundreds of nodes behind anycast).
- **DNS resolvers** (e.g., 1.1.1.1, but in IPv6 form).
- **Cloud load balancing** (anycast reroutes to active PoP on failure).
- **VRRP/HSRP** gateways are "cfg-local"; **anycast gateway/VTEP** in VXLAN fabrics
  (Level 24) — same gateway IP/MAC on every leaf, traffic lands on nearest.

### 2.5 Caveats
- Sources can't bind to anycast as a *source* — must be the **destination**.
- Session state is per-interface; a failover to a different anycast member breaks
  stateful flows unless shared session (BGP keepalive → dropped; HTTP stateless OK).
- Anycast and unicast don't coexist in the same = policy/route-map needs to treat.

## 3. Configuration / Commands

```text
# Anycast = just assign the same address to multiple routers' loopbacks
interface Loopback0
 ipv6 address 2001:db8:100::10/128       # same on R1, R2, R3

# Usually accelerated by IGP — advertise the /128 means closest wins
router ospfv3 1
 address-family ipv6 unicast
  network 2001:db8:100::10/128 area 0

# VXLAN gateway example uses the same method (Level 24)
```

## 4. Exam Traps

- **Anycast answer is "nearest" — not "all" (that's multicast), not the unique (unicast).**
- **Anycast address indistinguishable from unicast** — the "which is anycast?" gotcha:
  you can't tell from the address; it's deployment.
- **Cannot use as source** — RFC 4291 rule.
- **Stateful failover caveat** — TCP to an anycast node that dies is not transparently
  taken over.
- **DNS/topology questions** → the mnemonic: nearest server = anycast, everyone = multicast.
