# Link-Local (fe80::/10)

> **Level 06 · IPv6** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Link-local addresses** (prefix **`fe80::/10`**) are automatically configured on every
IPv6 interface — mandatory, non-routable, and used for **ND, SLAAC signaling, neighbor
discovery, and routing protocol adjacencies** on the local segment.

---

## 2. Core Concepts

### 2.1 Fe, not global
- `fe80::/10` → shorthand `fe80::…` (first two hextets; actually /10 means fe80–febf, but
  familiar usage is `fe80::/64`).
- **Never forwarded by routers** (scope = link); not advertised into global routing.

### 2.2 Auto-generation
- EUI-64 from MAC (flip U/L bit, insert `fffe`) or random/stable (RFC 7217).
- Always present even if you never configure IPv6: `ipv6 enable` adds it.
- Multiple interfaces → unique link-local per interface.

### 2.3 The zone / `%` notation
- Because fe80:: is identical on every host, you must say **which interface**:
  - Linux/macOS: `ping6 fe80::1%eth0`
  - Windows: `ping fe80::1%5`
- Exam: "why does ping6 to fe80 need a zone?" → scope is per-link, must identify link.

### 2.4 Where link-local actually powers things

| Use | Why |
|-----|-----|
| **ND (NS/NA, RS/RA)** | one-hop neighbor operations (replaces ARP) |
| **SLAAC unicast** | routers use LL as next-hop |
| **Routing neighbors** | OSPFv3 and EIGRPv6 build adjacencies over fe80, use it as next hop |
| **Default gateways** | hosts learn the RA sender's link-local as default route |
| **Management reachability** | only IT can reach device via fe80 on connected segment |

### 2.5 Multiple IPv6 addresses per interface

| Type | Purpose | Removed? (age) |
|------|---------|-----------------|
| link-local (fe80) | mandatory local | never |
| GUA/ULA | global/unique routing | SLAAC (if no RA) / lifetime |
| temporary (privacy) | outbound, rotated | every few days |

## 3. Configuration / Commands

```text
# Router interface gains link-local automatically
interface GigabitEthernet0/1
 ipv6 enable                 # auto fe80::/64, no global
# Manual link-local (deterministic for OSPF next-hops)
 ipv6 address fe80::1 link-local

# Verify
show ipv6 interface Gi0/1 | include Link|fe80
ping6 fe80::1%0              # from itself with zone
```

---

## 4. Exam Traps

- **fe80::/10 ≠ "invalid"** — most common "why do I have this weird fe80 address" question.
- **Not routable** — never see fe80 in a global routing table; ping across routers with fe80 fails.
- **Zone id `%` is significant** — required to disambiguate interfaces.
- **Used as next-hop in routing tables** — next hop may display as fe80 address on point-to-point.
- **Not "IPv6 APIPA"** — fe80 is normal/deliberate, unlike IPv4's 169.254 fallback.
