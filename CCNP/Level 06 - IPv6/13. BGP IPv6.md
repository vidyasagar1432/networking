# BGP IPv6

> **Level 06 · IPv6** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

BGP carries IPv6 routes via **MP-BGP (Multiprotocol BGP)** — the same TCP 179 transport,
with the **MP_REACH/MP_UNREACH attributes** and **address families** (AFI 2/SAFI 1) to
tag NEXT-HOP and NLRI as IPv6. Whether peers speak IPv6 to each other or over IPv4 is a
separate knob (next-hop-unchanged, etc.).

---

## 2. Core Concepts

### 2.1 The MP-BGP address family

| Attribute | Carries |
|-----------|---------|
| **MP_REACH_NLRI** | AF + SAFI + next-hop (IPv6) + NLRI prefixes + labels |
| **MP_UNREACH_NLRI** | withdrawals |
- Format: AFI 2 (IPv6) / SAFI 1 (unicast), 4 = unicast-unicast? remember AFI/SAFI pair.

### 2.2 IPv6 eBGP/iBGP — transport question (the big trap)

| Mode | Peer address family (TCP source) | Config |
|------|----------------------------------|--------|
| **IPv6 peers** | neighbor uses global IPv6, transport IPv6 | `neighbor 2001:db8::peer remote-as` |
| **IPv4 transport, IPv6 NLRI** | peer over IPv4, exchange IPv6 routes | `neighbor X activate` under ipv6 unicast AF |
| Dual | both | — |
- To send IPv6 routes you **must `activate` the neighbor in the IPv6 AF**, even if the
  session is IPv4 (classic "forgot activate" failure).

### 2.3 Config sketch (dual stack)
```text
router bgp 65001
 bgp router-id 1.1.1.1
 neighbor 2001:db8:1::1 remote-as 65002

 address-family ipv6 unicast
  neighbor 2001:db8:1::1 activate
  neighbor 2001:db8:1::1 route-map V6IN in
```
If peer over IPv4 session:
```text
 neighbor 10.0.0.1 remote-as 65002
 address-family ipv6 unicast
  neighbor 10.0.0.1 activate
  network 2001:db8:1:10::/64
```

### 2.4 IPv6 BGP details (path selection still identical)
- **Next-hop** in MP_REACH for iBGP often needs `next-hop-self`/`next-hop-unchanged`
  depending on design.
- Prefixes: aggregate with `aggregate-address`; filters with prefix-list 6:
  `ipv6 prefix-list`.
- AS_PATH, local-pref, MED, communities work exactly as in IPv4 BGP.

### 2.5 BGP for IPv6 use cases
- ISP edge: advertise **GUA prefix** to peers (eBGP), accept customer /48s.
- Enterprise: dual-stack internet peering, or MP-BGP in **MPLS/VPNv6** (Level 20) and
  EVPN (Level 24).
- Anycast DNS/cloud: same prefix from multiple sites — multi-path via BGP.

## 4. Exam Traps

- **"Activate in AF" is mandatory** — neighbors not activated carry nothing, session may
  run, routes empty.
- **Transport ≠ NLRI** — IPv4 transport CAN still exchange IPv6 routes (via MP).
- **NEXT-HOP is carried in MP_REACH**, not the regular NEXT_HOP attr — a favor trap.
- **Same path selection** as IPv4 — don't invent IPv6-specific BGP best-path rules.
- **`network x/y` under the AF** advertises your local prefix; `aggregate` aggregates.
- **iBGP IPv6** still needs loopback peering + next-hop-self logic.
