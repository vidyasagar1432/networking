# OSPFv3

> **Level 06 · IPv6** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**OSPFv3** is OSPF re-engineered for IPv6 (RFC 5340): protocol logic and LSA structure
survive, but the protocol **no longer carries IPv4 addresses** inside LSAs; addressing
is stored in **separate LSA types (intra-area-prefix)**, and IPv6 **link-local** is the
neighbor/next-hop basis. Modern IOS-XE also runs **IPv4 unicast in OSPFv3**
(address-family style) — the exam tests that twist too.

---

## 2. Core Concepts

### 2.1 OSPFv3 vs OSPFv2 (the delta)

| Aspect | OSPFv2 (IPv4) | OSPFv3 (IPv6) |
|--------|---------------|---------------|
| Transport | IPv4, protocol 89 | IPv6, protocol 89 |
| Multicast | 224.0.0.5/6 | **ff02::5 / ff02::6** |
| Hello neighbor | IPv4 IPs in hello | **link-local** addresses |
| LSA addressing | inside Type-1/2 | moved to **Intra-Area-Prefix (Type 9)** |
| Router-ID | IPv4-derived | configured, or auto 0.0.0.x |
| AF support | IPv4 only | IPv6 (+IPv4 via AF) |
| Wildcards | `network` (IOS) | `area`-based addressing |

### 2.2 Two configuration flavors on IOS-XE
1. **Traditional**:
   ```
   interface Gi0/1
    ipv6 enable
    ipv6 ospf 1 area 0
   router ospf 1
    router-id 1.1.1.1
   ```
2. **Address-family style (modern, carries both protocols)**:
   ```
   router ospfv3 1
    address-family ipv6 unicast
      router-id 1.1.1.1
    interface Gi0/1
     ospfv3 1 ipv6 area 0
   ```
   (Can enable IPv4 unicast AF under ospfv3 too.)

### 2.3 LSA adjustments

| OSPFv3 LSA | Name | Note |
|-----------|------|------|
| 1 | Router | gives router's interfaces (IPv6) |
| 2 | Network | DR's segment |
| **8** | **Link-Local** | carries link-local info — new |
| **9** | **Intra-Area-Prefix** | *stores the actual IPv6 prefixes* for area |
| 3 | Inter-Area-Prefix | summarizes IPv6 |
| 4/5/7 | ASBR / AS-External / NSSA | external IPv6 |

### 2.4 Neighbor & next-hop detail
- **Neighbors are identified by link-local addresses** — the neighbor field in
  `show ipv6 ospf neighbor` is fe80::…
- Next-hop on transit links is **link-local**.
- Link loopbacks: remote neighbors reachable via GUA.
- CAUTION: if your fe80 changes on the link, adjacency may flap (use stable LL).

### 2.5 Areas, DR/BDR, metrics
- Same area mechanics; **interface cost default 1 for any speed** (unlike v2's 10^8/BW
  reference) — tune with `ipv6 ospf cost`.
- DR/BDR election same (router-id priority); protocol 89 both.

## 3. Configuration / Commands

```text
# Address-family (IPv6 on an interface)
interface GigabitEthernet0/1
 ipv6 address 2001:db8:1:10::1/64
 ospfv3 1 ipv6 area 0

router ospfv3 1
 router-id 1.1.1.1
 address-family ipv6 unicast

show ipv6 ospf
show ipv6 ospf neighbor
show ipv6 ospf database
show ospfv3 1 address-family ipv6 unicast interface Gi0/1
```

## 4. Exam Traps

- **LSAs no longer carry addresses; Type 9 intra-area-prefix does** — the deep fact.
- **Hello/neighbors are link-local** — don't expect real GUA in neighbor IDs.
- **Multicast groups**: IPv6 OSPF = ff02::5 / ff02::6 (not 224.0.0.x).
- **Router-ID default auto-select (highest loopback IPv4)** — or explicit; distinguish.
- **Cost default 1** — OSPFv3 doesn't auto-scale by bandwidth (like v2) unless configured.
- **The AF twist**: OSPFv3 can carry **IPv4** too — don't say "OSPFv3 is IPv6-only."
