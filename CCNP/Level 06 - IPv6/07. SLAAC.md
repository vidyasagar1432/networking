# SLAAC

> **Level 06 · IPv6** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**SLAAC (Stateless Address Autoconfiguration)** lets a host build its own **global
unicast (or /64) address** using a **Router Advertisement (RA)** — no DHCPv6 needed.
It's the default, natural IPv6 addressing model (RFC 4862).

---

## 2. Core Concepts

### 2.1 The steps a host runs
1. Generate **link-local** (fe80) from EUI-64/random + assign.
2. Send **Router Solicitation (RS)** to `ff02::2` (all routers) — optional; routers
   send **RA** periodically and on RS.
3. Receive **RA** from the default router with:
   - the on-link **/64 prefix**,
   - flags (A=auto-config, M=managed/DHCPv6, O=other config),
   - router lifetime → this LL becomes the **default route**.
4. Build GUA = prefix + interface ID.
5. **DAD (Duplicate Address Detection)** via NS to `ff02::1:ffxx:xxxx` before use.

### 2.2 RA flags — the three modes

| Flags | Meaning | Result |
|-------|---------|--------|
| **A=1, M=0, O=0** | SLAAC only | host self-addresses; RAR handles |
| **A/M/O varied** | classical "managed" (M=1) | client asks DHCPv6 for address too |
| **O=1** | other info (DNS etc.) | client uses DHCPv6-DaaS for everything but address |

Practical table:

| A | M | O | Addressing | DNS |
|---|---|----|-----------|-----|
| 1 | 0 | 0 | SLAAC | RA options (RDNSS) |
| 0 | 1 | 0 | DHCPv6 (stateful) | DHCPv6 |
| 1 | 1 | 0 | Both | RA or DHCPv6 |
| 0 | 0 | 1 | none auto → needs DHCPv6 | DHCPv6 |

### 2.3 SLAAC vs DHCPv6 (the choice)

| | SLAAC | DHCPv6 |
|--|-------|--------|
| Address config | automatic, RA-only | server-assigned (stateful) |
| Options (DNS, NTP) | RDNSS in RA (limited) | full options |
| Tracking/accounting | limited | per-lease |
| Server needed | no | yes |
| Best works with | broad Internet-like | enterprise policy |

Best hybrid used in production: **SLAAC for addressing + DHCPv6 for DNS/options**
(A=1 M=0 O=1).

### 2.4 The /64 requirement
- RA announces a /64; the interface ID fills the last 64 bits — **/64 is mandatory**.
- A /127 link in tests breaks SLAAC (you'd need DHCPv6/static).

### 2.5 DAD and privacy
- **DAD**: NS with tentative address → if an NA comes back, address is dropped
  (duplicate).
- **Privacy extensions (RFC 4941)**: temporary random interface IDs for outbound
  connections to avoid EUI-64 hostage tracking; SLAAC still works.

## 3. Configuration / Commands

```text
# Router: send RAs with a prefix, SLAAC on
interface GigabitEthernet0/1
 no ipv6 nd suppress-ra          # actually: enable RA (default when ipv6 address set)
 ipv6 nd ra-interval 30
 ipv6 nd prefix 2001:db8:1:10::/64

# If O=1 to also push RDNSS:
 ipv6 nd ra dns 2001:db8:53::1

# Host side verify
ip -6 addr show
ip -6 route show default
```

---

## 4. Exam Traps

- **SLAAC needs NO server** — the "stateless" word = no DHCP.
- **A=1 only addresses** — DNS still needs RDNSS (RA) or DHCPv6.
- **/64 mandatory** — SLAAC in a /60 or /127 = broken.
- **Router is required** — a segment with no IPv6 router = no global address (only fe80).
- **RS/RA are ND messages** (ICMPv6 Type 133/134). DAD uses NS/NA (ICMPv6 135/136).
