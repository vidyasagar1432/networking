# Secure Management

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Secure management** ensures admin traffic is **encrypted, authenticated, and
restricted** — SSH not Telnet, HTTPS not HTTP, management VLAN isolated, and **AAA**
enforced. The exam pairs **transport protocols** (SSH/HTTPS/SNMPv3) with **access
control** (ACLs / management plane protection) and the **management plane** concept.

---

## 2. Core Concepts

### 2.1 The management plane

| Plane | What | Protect with |
|-------|------|--------------|
| Data | transit traffic | ACLs (note 04) |
| Control | routing/protocols | CoPP (note 09) |
| **Management** | SSH/SNMP/syslog/NTP | secure mgmt practices |

- Management traffic is **admin-originated** — the plane you must lock down.

### 2.2 Transport decisions

| Service | Insecure | Secure |
|---------|----------|--------|
| CLI | Telnet (23) | **SSH (22)** |
| Web | HTTP (80) | **HTTPS (443)** |
| Monitor | SNMPv1/v2c | **SNMPv3** |
| File | TFTP/FTP | **SCP/SFTP** |

- The secure variants are the exam's "correct" answers.

### 2.3 Restricting management access

```text
access-list 99 permit 10.0.0.0 0.0.0.255
line vty 0 15
 transport input ssh
 access-class 99 in
 login authentication DEFAULT
!
ip http access-class 99 in
ip http secure-server
```

| Control | Effect |
|---------|--------|
| `access-class` | limit VTY sources |
| `transport input ssh` | force SSH |
| `login authentication` | AAA |
| `ip http access-class` | web source limit |
| `ip http secure-server` | HTTPS |

### 2.4 Management VLAN isolation

- Dedicated **management VLAN** keeps admin traffic off user subnets.
- Out-of-band (OOB) management = separate physical network — the strongest isolation.

### 2.5 AAA integration (note 01)

```text
aaa new-model
aaa authentication login DEFAULT group tacacs+ local
aaa authorization commands 15 DEFAULT group tacacs+ local
aaa accounting exec DEFAULT start-stop group tacacs+
```

- Every admin action **authenticated + authorized + logged**.

### 2.6 Verification

```text
show line
show ip ssh
show ip http server secure status
show snmp
show aaa sessions
show access-lists
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| SSH refused | transport input | line vty |
| Source blocked | access-class | access-lists |
| HTTP insecure | server on 80 | ip http secure-server |
| SNMP readable | v1/v2c community | use v3 |
| Lockout | ACL too narrow | add mgmt subnet |

---

## 5. Exam Traps

- **SSH / HTTPS / SNMPv3 / SCP** are the secure choices.
- `access-class` limits **who** reaches the VTYs.
- Isolated **management VLAN / OOB** separates admin traffic.
- AAA = authenticate + authorize + **account** every admin action.
- HTTP/SNMPv2c/Telnet remain legacy/insecure — never the secure answer.
