# Storm Control

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Storm control** caps the rate of **broadcast, multicast, and unknown-unicast**
traffic on a switchport. When the traffic level exceeds a threshold, the port stops
forwarding that flood class — protecting the switch and LAN from storms caused by loops,
misconfigurations, or attackers. Unlike STP, it stops floods at the **port level**.

---

## 2. Core Concepts

### 2.1 What it monitors

| Traffic type | Storm risk |
|--------------|-----------|
| broadcast | highest |
| multicast | high |
| unknown-unicast (dlf) | high after CAM loss |

- All three are **flooded** traffic — the ones that amplify in a loop.

### 2.2 Thresholds

| Method | Meaning |
|--------|---------|
| pps | packets per second |
| bps | bits per second |
| percent | % of interface bandwidth |

- Two-level (rising/falling) or single rising threshold.

### 2.3 Configuration

```text
interface Gi0/1
 storm-control broadcast level 50
 storm-control multicast level pps 500
 storm-control unicast level bps 20m
 storm-control action shutdown|trap
```

| Command | Effect |
|---------|--------|
| `level N` | threshold (rising) |
| `level pps N` | per-second rate |
| `action trap` | send SNMP trap |
| `action shutdown` | error-disable the port |
| `action shutdown trap` | both |

- Default action: **suppress** (drop above threshold) — no port shutdown.

### 2.4 Behavior above threshold

| Action | Behavior |
|--------|----------|
| (default) | drop the flood class; port stays up |
| trap | alert to NMS |
| shutdown | error-disable port (needs recovery) |

- Raising/lowering threshold hysteresis avoids flapping.

### 2.5 Storm control vs STP vs CoPP

| Feature | Storm control | STP | CoPP (09) |
|---------|---------------|-----|-----------|
| Scope | switchport floods | loop prevention | CPU-bound traffic |
| Layer | 2 | 2 | control plane |
| Protects | LAN flooding | loop topology | device CPU |

- They solve **different** storms: STP loops, storm control floods, CoPP CPU abuse.

### 2.6 Verification

```text
show storm-control
show storm-control broadcast
show storm-control multicast
show storm-control unicast
```

- Displays current vs configured thresholds and packet counts.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Traffic silently dropped | threshold hit | storm-control show |
| Port error-disabled | action shutdown | errdisable recovery |
| Alerts storm | threshold too low | raise / hysteresis |
| No protection | only broadcast configured | add mcast/unicast |
| Loop still hurts | STP not blocking | STP config |

---

## 5. Exam Traps

- Monitors **broadcast + multicast + unknown-unicast** flood traffic.
- Default action = **suppress** (no shutdown) — trap/shutdown are explicit.
- Thresholds in pps, bps, or percent.
- It's **port-level flood control** — distinct from STP loop prevention.
- `action shutdown` puts the port in error-disable.
