# CoPP (Control Plane Policing)

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**CoPP** rate-limits the traffic that the device **itself** must process — the control
plane (routing protocols, management, ICMP, BGP). It protects the CPU from **DoS
overload** by policing packets with QoS before they reach the CPU, while allowing
**legitimate** control traffic. It's the Cisco answer to "CPU-crushing floods".

---

## 2. Core Concepts

### 2.1 The three planes

| Plane | Traffic | Risk |
|-------|---------|------|
| Data | transit (CEF) | low CPU load |
| Control | protocol/management | CPU-critical |
| Management | SSH/SNMP/syslog | must survive |

- CoPP polices the **control + management** plane.

### 2.2 How CoPP works

```
ingress packet -> QoS classify (ACL) -> police -> drop/transmit to CPU
```

| Element | Meaning |
|---------|---------|
| ACL | match traffic class |
| class-map | group matches |
| policy-map | policing rates |
| control-plane | attach policy |

### 2.3 Building blocks

```text
ip access-list extended COPP-MGMT
 permit tcp any host 192.0.2.1 eq 22
 permit tcp any host 192.0.2.1 eq 179
!
class-map match-any COPP-CRIT
 match ip access-group COPP-MGMT
!
policy-map COPP-POLICY
 class COPP-CRIT
  police 512000 conform transmit exceed drop
 class class-default
  police 8000 conform transmit exceed drop
!
control-plane
 service-policy input COPP-POLICY
```

- **Critical traffic**: high-rate conform/transmit.
- **Default**: low-rate — drops bursts protecting the CPU.

### 2.4 Design rules (exam-critical)

| Rule | Why |
|------|-----|
| Permit routing/management first | never starve BGP/OSPF/SSH |
| Police, don't block | control must flow |
| Use CoPP on edge interfaces | where attacks arrive |
| Verify with `show policy-map control-plane` | confirm drops |

- **Locking yourself out** (no SSH rule) is the classic mistake.

### 2.5 CoPP vs ACL vs storm control

| Tool | Protects | Mechanism |
|------|----------|-----------|
| ACL (04) | data plane | drop/permit |
| Storm control (08) | LAN floods | port-level rate |
| CoPP | **device CPU** | QoS police |

- CoPP specifically guards the **control plane**.

### 2.6 Verification

```text
show policy-map control-plane
show control-plane
show policy-map control-plane class COPP-CRIT
```

- Counters show conform/exceed/drop per class.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| CPU pegged | no CoPP or too permissive | control-plane drops |
| Routing dies | BGP/OSPF policed too low | add critical class |
| Can't manage | SSH dropped | MGMT class |
| Everything dropped | default rate 0 | rate default |
| Log flooding | excessive drops | tune classes |

---

## 5. Exam Traps

- CoPP = **control-plane QoS**, `service-policy input` under `control-plane`.
- **Never police your own management/routing below need** — lockout trap.
- CoPP is a **police**, not a blanket ACL block.
- Applies at the **control plane**, separate from data-plane ACLs.
- Verify with `show policy-map control-plane`.
