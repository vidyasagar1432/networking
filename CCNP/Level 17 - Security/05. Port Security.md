# Port Security

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Port security** restricts which **source MAC addresses** are allowed on a switchport and limits the number of secure MAC addresses that can be learned on that port.

It is primarily used at the **access layer** to reduce the risk of:

- Unauthorized devices connecting to a switchport
    
- MAC address spoofing/substitution
    
- Excessive MAC-address learning and some forms of MAC/CAM table flooding
    

Port security operates on **Layer 2 source MAC addresses**. It is not a replacement for 802.1X, DHCP Snooping, Dynamic ARP Inspection (DAI), or other dedicated security features.

---

## 2. Core Concepts

### 2.1 Secure MAC Addresses

A port-security port maintains a maximum number of **secure MAC addresses**.

```text
interface Gi0/1
 switchport mode access
 switchport port-security
```

The default maximum is generally **1 secure MAC address** when port security is enabled.

A secure MAC can be configured or learned in several ways:

|Type|Description|Survives Reload?|
|---|---|---|
|**Static secure MAC**|Manually configured with `mac-address`|Yes|
|**Dynamic secure MAC**|Learned automatically|No, normally lost after reload|
|**Sticky secure MAC**|Dynamically learned and added to running-config|Yes, if configuration is saved|

### 2.2 Static Secure MAC

```text
interface Gi0/1
 switchport port-security
 switchport port-security mac-address aaaa.bbbb.cccc
```

Only the configured secure MAC is permitted, subject to the configured maximum.

### 2.3 Sticky MAC

```text
interface Gi0/1
 switchport port-security
 switchport port-security mac-address sticky
```

Sticky learning dynamically learns source MAC addresses and places them into the **running configuration** as sticky secure MAC entries.

Example:

```text
switchport port-security mac-address sticky aaaa.bbbb.cccc
```

To make sticky entries survive a reload, save the configuration:

```text
copy running-config startup-config
```

or:

```text
write memory
```

> **Important:** Sticky learning does not automatically mean permanent persistence. The learned entries must be saved to startup-config.

## 3. Basic Configuration

Example: allow up to two secure MAC addresses and use sticky learning.

```text
interface GigabitEthernet0/1
 switchport mode access
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation shutdown
```

Optional aging:

```text
interface GigabitEthernet0/1
 switchport port-security aging time 5
```

Depending on IOS/platform and desired behavior, aging can be configured as **absolute** or **inactivity** aging.

---

## 4. Maximum Secure MAC Addresses

```text
switchport port-security maximum 2
```

This limits the number of secure MAC addresses allowed on the port.

Example:

```text
interface Gi0/1
 switchport port-security
 switchport port-security maximum 2
```

If the port already has two secure MAC addresses and a frame arrives with another unauthorized source MAC, the configured **violation action** is triggered.

> The maximum applies to the total secure MAC addresses on the port, including statically configured and learned secure addresses.

---

## 5. Port-Security Violation Modes

Cisco IOS commonly provides three violation modes:

|Mode|Action|Notification/Counter|
|---|---|---|
|**shutdown**|Port is placed into err-disabled state|Yes|
|**restrict**|Violating frames are dropped|Yes|
|**protect**|Violating frames are dropped|No|

### 5.1 Shutdown

```text
switchport port-security violation shutdown
```

This is the **default violation mode** on Cisco IOS.

When a violation occurs, the port is placed into an **err-disabled** state.

Recovery can be performed manually:

```text
interface Gi0/1
 shutdown
 no shutdown
```

Or with supported errdisable recovery:

```text
errdisable recovery cause psecure-violation
errdisable recovery interval 60
```

### 5.2 Restrict

```text
switchport port-security violation restrict
```

Violating frames are dropped, while the switch records the violation and can generate logging/SNMP notifications.

The interface remains operational.

### 5.3 Protect

```text
switchport port-security violation protect
```

Violating frames are silently dropped.

The port remains operational, but protect provides less visibility than restrict.

### Severity/Impact

For exam purposes:

```text
shutdown  →  restrict  →  protect
most disruptive          least disruptive
```

This is an operational comparison, not a Cisco security ranking.

## 6. Port-Security Aging

Port-security aging removes secure MAC addresses according to an aging timer.

Example:

```text
interface Gi0/1
 switchport port-security aging time 5
```

Two important aging concepts are:

### Absolute Aging

The secure MAC address is removed after the configured aging period, regardless of activity.

### Inactivity Aging

The secure MAC address is removed if no traffic is received from that MAC for the configured period.

> Exact aging command syntax and supported behavior can vary by Cisco IOS/platform, so verify the available options with `?`.

Aging can be useful when devices are frequently replaced or when you do not want old learned MAC addresses to remain indefinitely.

## 7. Static vs Dynamic vs Sticky

|Type|How learned/configured|Running-config|Survives reload if saved?|
|---|---|---|---|
|**Static**|Administrator configures MAC|Yes|Yes|
|**Dynamic**|Switch learns MAC|No|No|
|**Sticky**|Switch learns MAC|Yes|Yes|

### Example

Dynamic:

```text
interface Gi0/1
 switchport port-security
```

Sticky:

```text
interface Gi0/1
 switchport port-security
 switchport port-security mac-address sticky
```

Static:

```text
interface Gi0/1
 switchport port-security
 switchport port-security mac-address aaaa.bbbb.cccc
```

## 8. Secure MAC Address Learning

Consider:

```text
interface Gi0/1
 switchport mode access
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
```

If two devices connect:

```text
PC1 → aaaa.bbbb.1111
PC2 → aaaa.bbbb.2222
```

The switch can learn:

```text
switchport port-security mac-address sticky aaaa.bbbb.1111
switchport port-security mac-address sticky aaaa.bbbb.2222
```

A third device:

```text
PC3 → aaaa.bbbb.3333
```

exceeds the maximum of two secure MAC addresses and triggers the configured violation action.

## 9. Configuration Example

### Access port for a single workstation

```text
interface GigabitEthernet0/1
 description USER-PC
 switchport mode access
 switchport access vlan 10
 switchport port-security
 switchport port-security maximum 1
 switchport port-security mac-address sticky
 switchport port-security violation shutdown
```

Save the configuration:

```text
copy running-config startup-config
```

### Multiple devices on an access port

For a port expected to have multiple legitimate devices:

```text
interface GigabitEthernet0/1
 description SHARED-ACCESS-PORT
 switchport mode access
 switchport access vlan 10
 switchport port-security
 switchport port-security maximum 3
 switchport port-security mac-address sticky
 switchport port-security violation restrict
```

## 11. Clearing Secure MAC Addresses

Dynamic secure MAC entries can be cleared with:

```text
clear port-security dynamic
```

Platform/IOS-specific variants may allow clearing entries for a particular interface or VLAN.

After clearing, verify:

```text
show port-security address
```

> Be careful when clearing sticky secure MACs because sticky entries are represented in the configuration. Removing a learned MAC from the running configuration may require configuration-specific cleanup depending on the platform and IOS version.

---

## 12. Err-Disabled Recovery

With the default **shutdown** violation mode, a port can enter err-disabled state after a security violation.

Check:

```text
show interfaces status err-disabled
```

Check recovery:

```text
show errdisable recovery
```

Enable automatic recovery for port-security violations:

```text
errdisable recovery cause psecure-violation
errdisable recovery interval 60
```

After the timer expires, the switch attempts to bring the port back up.

Manual recovery:

```text
interface Gi0/1
 shutdown
 no shutdown
```

> Automatic recovery should be used carefully. If the unauthorized device remains connected, the port may become err-disabled again.

## 13. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Port is err-disabled|Port-security violation|`show port-security interface Gi0/1`|
|New device cannot connect|Maximum secure MAC limit reached|Check secure MAC count|
|Legitimate device is blocked|Stale secure MAC|Check/clear secure MAC entries|
|Sticky MAC disappeared after reload|Running-config was not saved|`show startup-config`|
|Violating frames are dropped but port stays up|`restrict` or `protect` mode|Check violation mode|
|No visible violation logging|`protect` mode|Check violation mode|
|Port repeatedly becomes err-disabled|Unauthorized/stale device still connected|Check MAC address and recovery|
|Secure MAC not learned|Port-security or interface configuration issue|Check running config and interface state|

## 15. Port Security vs Other Security Features

Port security is only one part of Layer 2 security.

|Feature|Main Purpose|
|---|---|
|**Port Security**|Restrict source MAC addresses|
|**DHCP Snooping**|Build trusted DHCP bindings and block rogue DHCP servers|
|**Dynamic ARP Inspection**|Validate ARP using trusted bindings|
|**IP Source Guard**|Restrict source IP/MAC combinations using bindings|
|**802.1X**|Authenticate users/devices before network access|
|**Storm Control**|Limit excessive broadcast/multicast/unknown-unicast traffic|

A common secure-access design may combine several of these features.

---

## 16. Important Limitations

Port security should not be described as a complete defense against CAM-table attacks.

It primarily controls:

- **How many secure MAC addresses** can exist on a port
    
- **Which source MAC addresses** are allowed
    
- **What happens when a violation occurs**
    

For broader Layer 2 protection, Cisco networks commonly combine port security with features such as:

```text
802.1X
DHCP Snooping
Dynamic ARP Inspection
IP Source Guard
Storm Control
```

## 17. Exam Traps

- Default secure MAC **maximum is 1** on typical Cisco IOS port-security configuration.
    
- Default violation mode is **shutdown**.
    
- **Shutdown** places the port into an err-disabled state after a violation.
    
- **Restrict** drops violating traffic and provides violation visibility/counters.
    
- **Protect** drops violating traffic without the notifications/counters associated with restrict.
    
- **Sticky MACs are written to running-config** when learned.
    
- Sticky MACs survive a reload **only when the configuration containing them is saved**.
    
- Dynamic secure MACs normally do **not** survive a reload.
    
- Port security limits **source MAC addresses**, not IP addresses.
    
- `maximum` controls the number of secure MAC addresses allowed on the port.
    
- Aging can remove secure MAC entries according to the configured aging behavior.
    
- `errdisable recovery` can automate recovery from supported port-security violations.
    
- Port security is commonly deployed on **access ports**; support and behavior on trunks are platform/IOS dependent.
    
- Port security is **not a replacement for 802.1X**.
    
- Port security alone does not provide complete protection against every CAM/MAC-table attack.
    
- Always verify the actual platform/IOS syntax with `?` when commands differ between releases.

