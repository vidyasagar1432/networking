# IP Source Guard (IPSG)

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**IP Source Guard (IPSG)** is a Layer 2 security feature that prevents hosts from using **unauthorized source IP addresses** on an access port.

IPSG creates a source-address allowlist for an interface and filters traffic based on trusted **IP/MAC/VLAN/interface bindings**.

The most common source of these bindings is the **DHCP Snooping binding table**.

IPSG helps prevent:

- Source IP spoofing
    
- Unauthorized use of another host's IP address
    
- Some forms of Layer 3 impersonation on the access layer
    

IPSG works particularly well with:

```text
DHCP Snooping
      ↓
Trusted IP/MAC binding
      ↓
IP Source Guard
      ↓
Source IP/MAC filtering
```

---

# 2. The Threat: Source IP Spoofing

Without source validation, a host could transmit a packet using another device's IP address.

Example:

```text
Legitimate Host
IP: 192.168.10.20
MAC: aaaa.bbbb.2020
```

An attacker could attempt:

```text
Source IP: 192.168.10.20
Attacker MAC: aaaa.bbbb.evil
```

The attacker is pretending to be the legitimate host.

IPSG can reject the traffic when the source information does not match an authorized binding.

---

# 3. How IPSG Works

A typical deployment uses DHCP Snooping to learn:

```text
IP Address
    ↓
MAC Address
    ↓
VLAN
    ↓
Interface
```

Example binding:

```text
192.168.10.20
aaaa.bbbb.2020
VLAN 10
Gi0/2
```

IPSG then programs source filtering on the access interface.

If the host sends traffic with an unauthorized source IP:

```text
Source IP = 192.168.10.99
```

but the binding permits:

```text
192.168.10.20
```

the traffic can be dropped.

---

# 4. DHCP Snooping Relationship

DHCP Snooping is the most common source of IPSG bindings.

Example:

```text
ip dhcp snooping
ip dhcp snooping vlan 10
```

The switch learns legitimate DHCP client information and creates bindings.

Verify:

```text
show ip dhcp snooping binding
```

Example:

```text
MacAddress          IpAddress       Lease(sec)  Type      VLAN  Interface
------------------  --------------  ----------  --------  ----  ---------
aaaa.bbbb.2020      192.168.10.20   86400       dhcp-snoo 10    Gi0/2
```

IPSG can use this information to determine which source addresses are permitted on the interface.

---

# 5. Enabling IP Source Guard

Basic IPv4 IPSG:

```text
interface GigabitEthernet0/2
 switchport mode access
 ip verify source
```

This enables source IP filtering on the interface.

To additionally validate the source MAC:

```text
interface GigabitEthernet0/2
 ip verify source port-security
```

### Important

```text
ip verify source
```

provides **source IP filtering**.

```text
ip verify source port-security
```

provides **source IP + source MAC filtering**.

The `port-security` keyword here is part of the IPSG command and should not be confused with enabling the separate **switchport port-security** feature.

---

# 6. Source IP vs Source MAC Validation

## 6.1 IP-only filtering

```text
interface Gi0/2
 ip verify source
```

The switch filters traffic based on the authorized source IP information.

## 6.2 IP + MAC filtering

```text
interface Gi0/2
 ip verify source port-security
```

The switch also checks the source MAC against the authorized binding.

Conceptually:

```text
IP                 MAC
│                  │
▼                  ▼
192.168.10.20      aaaa.bbbb.2020
       \            /
        \          /
         ▼        ▼
        Authorized
          Binding
             │
             ▼
        IPSG allows
```

An unauthorized IP/MAC combination can be dropped.

---

# 7. Static-IP Hosts

Not every device uses DHCP.

Examples:

- Servers
    
- Printers
    
- Network appliances
    
- Cameras
    
- Management devices
    

These devices may not appear automatically in the DHCP Snooping binding table.

A static source binding can be configured manually.

Example:

```text
ip source binding aaaa.bbbb.5050 vlan 10 192.168.10.50 interface Gi0/3
```

This creates an explicit binding:

```text
IP:        192.168.10.50
MAC:       aaaa.bbbb.5050
VLAN:      10
Interface: Gi0/3
```

Now IPSG can use that binding for source validation.

---

# 8. Static Binding vs DHCP Snooping Binding

|Binding|Created By|Typical Use|
|---|---|---|
|**Dynamic**|DHCP Snooping|DHCP clients|
|**Static**|`ip source binding`|Static-IP devices|

Example dynamic binding:

```text
DHCP Client
    ↓
DHCP Snooping
    ↓
Dynamic Binding
    ↓
IPSG
```

Example static binding:

```text
Static-IP Device
       ↓
ip source binding
       ↓
Static Binding
       ↓
IPSG
```

---

# 9. IPSG on an Access Port

Typical user-port configuration:

```text
interface GigabitEthernet0/2
 description USER-PC
 switchport mode access
 switchport access vlan 10
 ip verify source
```

If the user receives:

```text
IP: 192.168.10.20
MAC: aaaa.bbbb.2020
```

DHCP Snooping can create the corresponding binding.

IPSG then allows the authorized source information.

---

# 10. IPSG + MAC Validation

For stronger source validation:

```text
interface GigabitEthernet0/2
 description USER-PC
 switchport mode access
 switchport access vlan 10
 ip verify source port-security
```

The intended binding is:

```text
192.168.10.20
aaaa.bbbb.2020
VLAN 10
Gi0/2
```

If the device attempts to send traffic using:

```text
IP: 192.168.10.20
MAC: aaaa.bbbb.9999
```

the source MAC does not match the authorized binding and the traffic can be rejected.

---

# 11. IPSG and Trusted Interfaces

IPSG is normally applied to **host-facing Layer 2 access interfaces**.

The common design is:

```text
                 Router
                   │
                   │
                Uplink
                   │
             +-----+-----+
             |  Switch   |
             +-----+-----+
                   │
              Access Port
                   │
                  PC
```

IPSG is normally configured on the **access/host-facing interface**.

Do not blindly apply source verification to infrastructure links. The correct configuration depends on the topology and platform.

> Unlike DAI, IPSG should not be reduced to a simple “trusted vs untrusted” model. The key concept is **where source filtering is applied**.

---

# 12. IPSG and Port Security

IPSG and Port Security solve different problems.

### Port Security

Controls:

```text
Source MAC addresses
```

Example:

```text
switchport port-security
switchport port-security maximum 1
```

### IPSG

Controls:

```text
Source IP
```

and optionally:

```text
Source IP + MAC
```

Example:

```text
ip verify source port-security
```

They can be combined:

```text
interface Gi0/2
 switchport mode access
 switchport port-security
 switchport port-security maximum 1
 switchport port-security mac-address sticky
 ip verify source port-security
```

This provides defense in depth.

---

# 13. IPSG and DAI

IPSG and DAI protect different things.

|Feature|Main Protection|
|---|---|
|**Port Security**|Unauthorized source MAC addresses|
|**DHCP Snooping**|DHCP protection + trusted bindings|
|**DAI**|ARP spoofing/poisoning|
|**IPSG**|Source IP/MAC spoofing|

Example:

```text
                DHCP Snooping
                      │
             IP/MAC Bindings
                ┌─────┴─────┐
                ▼           ▼
               DAI         IPSG
                │           │
                ▼           ▼
          ARP validation  Source validation
```

---

# 14. IPSG + DAI + Port Security

A secure access port can combine all three:

```text
Port Security
      │
      ├── Source MAC control
      │
DHCP Snooping
      │
      ├── Builds IP/MAC bindings
      │
      ├──────────────┐
      ▼              ▼
     DAI            IPSG
      │              │
      ▼              ▼
 ARP validation   Source validation
```

This is a common defense-in-depth design.

---

# 15. IPv6 Source Guard

IPv4 IPSG uses:

```text
ip verify source
```

IPv6 has a related source-guard feature:

```text
ipv6 verify source
```

The concepts are similar, but IPv6 source validation is a separate feature and should not be confused with IPv4 IPSG.

For ENCOR, understand the relationship, but keep IPv4 IPSG and IPv6 Source Guard conceptually separate.

# 17. Clearing IPSG Configuration

A commonly used command is:

```text
clear ip verify source interface Gi0/2
```

This is useful when troubleshooting or resetting source verification information.

> Exact command availability can vary by Cisco IOS/platform. Use `?` to verify the supported syntax.

# 18. Debugging

Where supported:

```text
debug ip verify source
```

Disable debugging afterward:

```text
undebug all
```

Use debugging carefully on production devices because debug output can be CPU-intensive and generate large amounts of traffic/output.

# 19. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Host traffic is dropped|No valid binding|`show ip source binding`|
|DHCP client cannot communicate|DHCP Snooping binding missing|`show ip dhcp snooping binding`|
|Static-IP host is blocked|No static source binding|`ip source binding`|
|Correct IP but wrong MAC|MAC validation enabled|`ip verify source port-security`|
|IPSG not filtering|`ip verify source` not configured|`show ip verify source`|
|Binding disappeared|DHCP lease/binding expired|Check DHCP Snooping|
|Device moved to another port|Binding still references old interface|Check source binding|
|Uplink/infrastructure traffic breaks|IPSG applied inappropriately|Check interface configuration|
|IPv6 traffic not protected|IPv4 IPSG only|`ipv6 verify source`|

# 20. Troubleshooting Workflow

### Step 1 — Check IPSG

```text
show ip verify source
```

Confirm the correct interface has source verification enabled.

### Step 2 — Check the source binding

```text
show ip source binding
```

Verify:

```text
IP
MAC
VLAN
Interface
```

### Step 3 — Check DHCP Snooping

```text
show ip dhcp snooping
```

### Step 4 — Check DHCP Snooping bindings

```text
show ip dhcp snooping binding
```

Confirm that the expected client appears.

### Step 5 — Check the interface

```text
show running-config interface Gi0/2
```

Look for:

```text
ip verify source
```

or:

```text
ip verify source port-security
```

### Step 6 — Check the physical/L2 state

```text
show interfaces Gi0/2
show interfaces status
```

### Step 7 — Check MAC learning

```text
show mac address-table interface Gi0/2
```

Compare the learned MAC with the expected binding.

# 21. Common Failure: Static-IP Device

Suppose:

```text
Server IP: 192.168.10.50
Server MAC: aaaa.bbbb.5050
Interface: Gi0/3
```

The server uses a static IP and therefore has no DHCP Snooping binding.

IPSG may reject its traffic.

Create the static binding:

```text
ip source binding aaaa.bbbb.5050 vlan 10 192.168.10.50 interface Gi0/3
```

Verify:

```text
show ip source binding
```

---

# 22. Common Failure: MAC Changed

Suppose the DHCP Snooping binding says:

```text
192.168.10.20
aaaa.bbbb.2020
Gi0/2
```

But the device now uses:

```text
192.168.10.20
aaaa.bbbb.3030
Gi0/2
```

With:

```text
ip verify source port-security
```

the source MAC does not match the authorized binding.

The traffic can therefore be rejected.

Troubleshoot with:

```text
show ip source binding
show mac address-table interface Gi0/2
```

---

# 23. Common Failure: Device Moved Ports

Binding:

```text
192.168.10.20
aaaa.bbbb.2020
Gi0/2
```

Device is physically moved to:

```text
Gi0/3
```

The binding may still identify `Gi0/2`.

IPSG can therefore reject traffic on the new interface until the binding is updated/renewed appropriately.

Check:

```text
show ip source binding
```

# 24. IPSG Limitations

IPSG is not a complete network security solution.

It primarily protects against **source address spoofing on the access layer**.

It does not replace:

- Port Security
    
- DHCP Snooping
    
- DAI
    
- 802.1X
    
- ACLs
    
- Authentication
    
- Firewall policies
    
- Other Layer 2/Layer 3 security controls
    

A secure campus normally uses multiple complementary mechanisms.

---

# 25. Exam Traps

- **IPSG protects against source IP spoofing.**
    
- `ip verify source` enables **source IP filtering**.
    
- `ip verify source port-security` adds **source MAC validation**.
    
- The `port-security` keyword in `ip verify source port-security` is not the same as enabling `switchport port-security`.
    
- DHCP Snooping is the **common source of dynamic IPSG bindings**.
    
- IPSG can also use **static IP source bindings**.
    
- Static-IP devices commonly require `ip source binding`.
    
- IPSG is normally deployed on **host-facing Layer 2 access ports**.
    
- Do not blindly apply IPSG to infrastructure links.
    
- `show ip source binding` is a key troubleshooting command.
    
- `show ip dhcp snooping binding` verifies the underlying DHCP Snooping information.
    
- IPSG protects **source addressing**; DAI protects **ARP**.
    
- Port Security controls **source MAC admission**, while IPSG controls **source IP/MAC authorization**.
    
- IPv4 IPSG and IPv6 Source Guard are related but separate features.
    
- A DHCP Snooping binding contains important information such as **IP, MAC, VLAN, and interface**.
    
- With `ip verify source port-security`, both source IP and source MAC information are checked against the authorized binding.
    
- IPSG is a **Layer 2 access-layer enforcement feature**, even though it validates Layer 3 source information.

# 28. One-Minute Exam Summary

**IPSG = prevent a host from using an unauthorized source IP/MAC on an access port.**

Remember:

```text
DHCP Snooping
      │
      ▼
IP/MAC/VLAN/Interface Binding
      │
      ▼
IP Source Guard
      │
      ├── ip verify source
      │       → Source IP filtering
      │
      └── ip verify source port-security
              → Source IP + MAC filtering
```

Core concepts:

```text
IPSG                  → Source IP spoofing protection
DHCP Snooping         → Common source of bindings
ip verify source      → IP filtering
port-security keyword → Adds source MAC validation
ip source binding     → Static binding
Access port           → Typical deployment
DAI                   → ARP protection
Port Security         → Source MAC admission/control
```

Most important commands:

```text
show ip verify source
show ip source binding
show ip dhcp snooping binding
show running-config interface Gi0/2
```

**DHCP Snooping creates trusted bindings → DAI validates ARP → IPSG validates source traffic.**
