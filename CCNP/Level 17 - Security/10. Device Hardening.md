# Device Hardening

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Device hardening** is the process of reducing a network device's attack surface and  
protecting its management and control functions.

For CCNP ENCOR, focus on:

- **AAA and secure authentication**
    
- **Strong password hashing**
    
- **SSH-only remote management**
    
- **Login brute-force protection**
    
- **Management-plane ACLs**
    
- **Secure console, VTY, and AUX lines**
    
- **Disabling unnecessary services**
    
- **Disabling unused interfaces**
    
- **Logging and time synchronization**
    
- **Secure SNMP configuration**
    
- **Legal warning banners**
    

The goal is to ensure that only authorized users and required protocols can access or  
consume device resources.

# 3. Secure Credentials

## 3.1 `enable secret`

Use `enable secret` instead of the legacy `enable password`.

```cisco
enable secret StrongEnablePassword
```

`enable secret` stores the enable credential using a cryptographic hash rather than  
the legacy clear-text-style `enable password` mechanism.

Avoid:

```cisco
enable password Cisco123
```

---

## 3.2 Local User Accounts

Create local users with `secret`:

```cisco
username admin privilege 15 secret StrongAdminPassword
```

Use `secret` rather than:

```cisco
username admin password Cisco123
```

Local users are especially useful as a fallback authentication method when AAA is  
configured.

---

## 3.3 Password Hash Types

|Type|Algorithm / Purpose|Security|
|---|---|---|
|Type 0|Clear text|Weak|
|Type 5|MD5-based|Legacy / weak by modern standards|
|Type 7|Reversible obfuscation|Weak|
|Type 8|PBKDF2-SHA-256|Strong|
|Type 9|scrypt|Stronger|

### Exam points

- **Type 7 is reversible**, not encryption suitable for protecting passwords.
    
- **Type 8 uses PBKDF2-SHA-256**.
    
- **Type 9 uses scrypt**.
    
- Prefer **type 8/9** when supported by the IOS/IOS XE release.
    
- The exact hash type generated by a `secret` command depends on the IOS/IOS XE  
    version and available syntax.
    

---

## 3.4 `service password-encryption`

```cisco
service password-encryption
```

This provides **Type 7 reversible obfuscation** for certain legacy plaintext  
passwords in the configuration.

Important:

> `service password-encryption` is **not strong password encryption** and does not  
> replace `secret`.

Use `secret` for credentials whenever possible.

# 4. AAA Hardening

AAA means:

- **Authentication** — Who are you?
    
- **Authorization** — What are you allowed to do?
    
- **Accounting** — What did you do?
    

Enable AAA:

```cisco
aaa new-model
```

A typical centralized AAA design uses:

- **TACACS+** for administrative device access
    
- **RADIUS** where appropriate, especially in environments using centralized  
    authentication infrastructure
    
- **Local users** as a controlled fallback
    

Example concept:

```cisco
aaa new-model

aaa authentication login default group tacacs+ local
aaa authorization exec default group tacacs+ local
```

The exact TACACS+/RADIUS server configuration depends on the platform and IOS XE  
release.

### Exam point

AAA should be considered a **core device-hardening mechanism**, not merely an  
optional fallback feature.

# 5. SSH Hardening

Remote CLI management should use **SSH**, not Telnet.

## 5.1 Configure SSH

Example:

```cisco
hostname R1
ip domain-name example.local

username admin privilege 15 secret StrongAdminPassword

crypto key generate rsa modulus 2048

ip ssh version 2
```

Verify:

```cisco
show ip ssh
show crypto key mypubkey rsa
```

---

## 5.2 Restrict VTY Lines to SSH

```cisco
line vty 0 15
 login local
 transport input ssh
 exec-timeout 5 0
```

This prevents Telnet access through the VTY lines.

Avoid:

```cisco
transport input all
```

when only SSH management is required.

### Exam point

**SSH-only management =**

```cisco
transport input ssh
```

---

# 6. Management-Plane ACL

Remote management should be restricted to trusted management networks.

Example:

```cisco
ip access-list standard MGMT
 permit 10.10.10.0 0.0.0.255
 deny any

line vty 0 15
 access-class MGMT in
 transport input ssh
 login local
 exec-timeout 5 0
```

This provides two layers:

1. **SSH** prevents Telnet.
    
2. **Access-class** limits which source addresses can reach the VTY lines.
    

> Use the ACL direction appropriate to the management access design. For VTY  
> access, `access-class ... in` filters incoming management connections.

---

# 7. Login Brute-Force Protection

Cisco IOS supports login blocking to reduce repeated failed login attempts.

Example:

```cisco
login block-for 120 attempts 3 within 60
```

Meaning:

- **3 failed attempts**
    
- within **60 seconds**
    
- causes login access to be blocked for **120 seconds**
    

Verify:

```cisco
show login
```

---

## 7.1 Quiet Mode

During a login quiet period, access can be restricted using an ACL:

```cisco
login quiet-mode access-class MGMT
```

The ACL defines which source addresses are permitted during quiet mode.

Do not interpret this as simply "legitimate admins are removed from the failed-login  
counter." It controls access during the quiet period.

---

## 7.2 Login Monitoring

```cisco
login on-failure log
login on-success log
```

These provide logging of failed and successful login attempts.

Verification:

```cisco
show login
```

---

# 8. Console Line Hardening

The console is a local management path and should also be protected.

Example:

```cisco
line console 0
 exec-timeout 5 0
 logging synchronous
```

If local console authentication is required:

```cisco
login local
```

Avoid unnecessarily long or unlimited console sessions.

---

# 9. VTY Line Hardening

Recommended baseline:

```cisco
line vty 0 15
 login local
 transport input ssh
 exec-timeout 5 0
```

With a management ACL:

```cisco
line vty 0 15
 access-class MGMT in
 login local
 transport input ssh
 exec-timeout 5 0
```

### Why?

|Setting|Purpose|
|---|---|
|`login local`|Uses local username database|
|`transport input ssh`|Allows SSH instead of Telnet|
|`access-class MGMT in`|Restricts management sources|
|`exec-timeout 5 0`|Disconnects idle sessions|

---

# 10. AUX Line Hardening

The AUX line is an additional management/access path and is often unnecessary.

If unused:

```cisco
line aux 0
 transport input none
 no exec
 exec-timeout 0 1
```

The exact available commands can vary by platform.

### Exam point

Do not leave an unnecessary AUX access path enabled.

---

# 11. Disable Unnecessary Services

Disable services that are not required.

## 11.1 HTTP / HTTPS Management

```cisco
no ip http server
no ip http secure-server
```

Verify:

```cisco
show ip http server status
```

If web-based device management is not required, disable it.

> Do not blindly disable HTTPS if the device is intentionally managed through a  
> required HTTPS-based management system.

---

## 11.2 TCP Small Servers

```cisco
no service tcp-small-servers
```

---

## 11.3 UDP Small Servers

```cisco
no service udp-small-servers
```

These legacy services can provide unnecessary attack surface.

---

## 11.4 PAD

```cisco
no service pad
```

PAD is associated with legacy X.25 environments and should be disabled when unused.

---

## 11.5 IP Source Routing

```cisco
no ip source-route
```

Source routing allows the sender to influence the path taken by an IP packet.

Disable it when not explicitly required.

---

# 12. Disable Unused Interfaces

Unused physical interfaces should normally be administratively shut down.

Example:

```cisco
interface GigabitEthernet1/0/10
 description UNUSED
 shutdown
```

This prevents an unused physical port from becoming an unintended entry point.

For switch environments, combine this with appropriate access-port security controls  
such as:

- Port security
    
- BPDU Guard
    
- DHCP Snooping
    
- Dynamic ARP Inspection
    
- IP Source Guard
    

These are related security mechanisms but are separate topics.

---

# 13. SNMP Hardening

Avoid insecure legacy SNMP configurations where possible.

Prefer:

> **SNMPv3**

because it supports authentication and privacy/security features.

Avoid exposing SNMP broadly to untrusted networks.

A management ACL can restrict SNMP sources where appropriate.

Example concept:

```cisco
ip access-list standard SNMP-MGMT
 permit 10.10.10.0 0.0.0.255
 deny any
```

SNMP configuration syntax varies by IOS/IOS XE release and SNMP deployment.

---

# 14. Logging and Time Synchronization

Security events are much more useful when timestamps are accurate.

Configure appropriate logging:

```cisco
service timestamps log datetime msec
```

Configure NTP as appropriate:

```cisco
ntp server 10.10.10.10
```

For security-sensitive environments, use authenticated NTP where supported and  
required.

Centralized syslog can also be used:

```cisco
logging host 10.10.10.20
```

Verify:

```cisco
show logging
show ntp status
```

---

# 15. Security Banner

A banner can provide a legal/security warning.

Example:

```cisco
banner motd ^
********************************************************
* WARNING: Authorized access only.                     *
* All activity may be monitored and recorded.          *
********************************************************
^
```

A banner does not technically prevent an attack, but it is commonly part of an  
organizational security baseline.

# 18. Troubleshooting

|Symptom|Likely Cause|Check / Fix|
|---|---|---|
|Telnet still works|VTY allows Telnet|`transport input ssh`|
|SSH fails|SSH/keys/domain not configured|`show ip ssh`|
|Management network cannot connect|VTY ACL blocking source|Check `access-class` ACL|
|Login temporarily blocked|`login block-for` triggered|`show login`|
|Weak password storage|Legacy password/type 7|Use `secret`|
|HTTP exposed|HTTP server enabled|`no ip http server`|
|HTTPS unexpectedly unavailable|HTTPS was disabled|Check whether HTTPS management is actually required|
|AUX accessible|AUX not hardened|`line aux 0`, `no exec`, `transport input none`|
|Idle sessions remain|Missing timeout|`exec-timeout`|
|Unused port is active|Interface not shut down|`shutdown`|
|Logs have incorrect time|NTP/time configuration problem|`show ntp status`|
|SNMP exposed broadly|Missing source restriction|Restrict SNMP management sources|

# 19. Exam Traps

### Trap 1 — `enable password` vs `enable secret`

Use:

```cisco
enable secret
```

rather than:

```cisco
enable password
```

---

### Trap 2 — Type 7 is not encryption

Type 7 is **reversible obfuscation**.

Do not confuse:

```cisco
service password-encryption
```

with strong cryptographic password protection.

---

### Trap 3 — Type 8 vs Type 9

Remember:

```text
Type 8 = PBKDF2-SHA-256
Type 9 = scrypt
```

---

### Trap 4 — Telnet

This:

```cisco
transport input ssh
```

is the important SSH-only VTY setting.

---

### Trap 5 — `login block-for`

```cisco
login block-for 120 attempts 3 within 60
```

means:

```text
3 failures
within 60 seconds
→ block logins for 120 seconds
```

---

### Trap 6 — HTTP management

```cisco
no ip http server
```

disables the HTTP server.

HTTPS is controlled separately:

```cisco
no ip http secure-server
```

---

### Trap 7 — AUX

An unused AUX line should not remain an unnecessary access path.

Common hardening:

```cisco
line aux 0
 no exec
 transport input none
```

---

### Trap 8 — `exec-timeout`

`exec-timeout` protects against abandoned interactive sessions.

Example:

```cisco
exec-timeout 5 0
```

means **5 minutes and 0 seconds**.

---

### Trap 9 — Management ACL vs data-plane ACL

A VTY `access-class` controls **management access to the line**.

It is not the same thing as an interface traffic-filtering ACL.
