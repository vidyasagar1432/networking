# Device Hardening

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Device hardening** is the set of baseline settings that shrink a device's attack
surface: **strong passwords (type 9), login blocking, banner, disable unused services,
banner, restrict AUX, and AAA fallback**. The exam tests the CLI security blocks —
`service password-encryption`, `login block-for`, and disabled auxiliary/legacy
protocols.

---

## 2. Core Concepts

### 2.1 The hardening checklist

| Area | Control |
|------|---------|
| Passwords | `secret` not `password`, type 9 |
| Encryption | `service password-encryption` |
| Login | `login block-for` (failed attempts) |
| Banner | legal/notice banner |
| Services | disable unused (http-server, small servers) |
| Lines | exec-timeout, transport input ssh |
| AUX | no aux-line access |

### 2.2 Strong secrets

```text
enable secret Cisco123          ! MD5 (type 5) / SHA (type 8/9)
username admin secret StrongPass
service password-encryption     ! obscures type-7 in config
```

| Type | Hash |
|------|------|
| 7 | reversible (weak) |
| 5 | MD5 |
| 8 | SHA-256 (best) |
| 9 | SCRYPT (strongest) |

- Prefer **type 8/9**; `secret` (not `password`).

### 2.3 Login throttling

```text
login block-for 120 attempts 3 within 60
login quiet-mode access-class MGMT
```

| Command | Effect |
|---------|--------|
| `login block-for` | lock login after N failed |
| `login delay` | delay between retries |
| `login on-failure` | log failures |
| `login on-success` | log successes |

- Throttles brute force without blocking legitimate admins (quiet-mode exempts MGMT).

### 2.4 Disabling risky services

```text
no ip http server
no ip http secure-server
no service tcp-small-servers
no service udp-small-servers
no service pad
no ip source-route
```

| Service | Risk |
|---------|------|
| HTTP server | unencrypted web mgmt |
| small servers | echo/chargen DoS |
| PAD | X.25 (legacy) |
| IP source-route | spoofed routing |

### 2.5 Line and AUX hardening

```text
line console 0
 exec-timeout 5 0
 password ...
line vty 0 15
 transport input ssh
 exec-timeout 5 0
line aux 0
 transport input none        ! or no exec
```

- **AUX** disabled (`transport input none`) removes the modem/aux access path.
- `exec-timeout` logs idle sessions off.

### 2.6 Baseline verification

```text
show running-config | include no service|transport|exec-timeout
show login
show ip http server status
show line
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Login blocked | block-for triggered | show login / quiet-mode |
| Weak hashes | type 7 used | change to secret |
| HTTP exposed | server on | no ip http server |
| AUX access | transport not none | line aux |
| Session hang | no exec-timeout | add timeout |

---

## 5. Exam Traps

- Use **`enable secret`** (hashed) not `enable password`.
- **Type 9 (SCRYPT)** is strongest; **type 7 is reversible** — never rely on it.
- `login block-for N attempts X within Y` throttles brute force.
- `no ip http server` disables web mgmt.
- **AUX line** must be disabled (`transport input none`).
