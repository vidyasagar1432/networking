# ACLs (Access Control Lists)

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Access Control Lists (ACLs)** are ordered sets of rules used to **match and permit or  
deny traffic**. ACLs can filter traffic based on addresses, protocols, ports, and other  
criteria.

ACLs are primarily used for:

- Traffic filtering
    
- Management access control
    
- NAT traffic selection
    
- Route-map matching
    
- QoS classification
    
- Control-plane protection
    
- Time-based access control
    

ACL processing follows three fundamental rules:

> **Top-to-bottom → First match wins → Implicit deny**

For IPv4, ACLs are commonly divided into **standard** and **extended** ACLs.

---

# 2. ACL Types

## 2.1 Standard ACL

A standard IPv4 ACL matches only the **source IPv4 address**.

```text
access-list 10 permit 192.168.10.0 0.0.0.255
```

It cannot directly match:

- Destination IP
    
- TCP/UDP ports
    
- Specific IP protocols
    

Numbered standard ACL ranges:

```text
1–99
1300–1999
```

---

## 2.2 Extended ACL

Extended IPv4 ACLs provide much more granular matching.

They can match:

- Source IPv4 address
    
- Destination IPv4 address
    
- IP protocol
    
- TCP source/destination ports
    
- UDP source/destination ports
    
- ICMP types
    
- TCP flags
    
- Other protocol-specific criteria
    

Numbered extended ACL ranges:

```text
100–199
2000–2699
```

Example:

```text
access-list 101 permit tcp 192.168.10.0 0.0.0.255 host 10.0.0.5 eq 443
```

This means:

```text
Source:      192.168.10.0/24
Protocol:    TCP
Destination: 10.0.0.5
Dest port:   443
Action:      Permit
```

---

# 3. Numbered vs Named ACLs

## Numbered ACL

Example:

```text
access-list 101 permit tcp any host 10.0.0.5 eq 443
```

The ACL is identified by its number.

## Named ACL

Example:

```text
ip access-list extended WEB-FILTER
 permit tcp any host 10.0.0.5 eq 443
 deny ip any any
```

Named ACLs are generally preferred because they provide:

- Meaningful names
    
- Easier administration
    
- Easier editing
    
- Sequence numbers
    
- Better documentation
    

---

# 4. Wildcard Masks

IPv4 ACLs use **wildcard masks** instead of subnet masks.

The rule is:

> **`0 = must match` · `1 = ignore`**

|Wildcard|Meaning|
|---|---|
|`0.0.0.0`|Exact host|
|`0.0.0.255`|Corresponding `/24` network|
|`0.0.255.255`|Corresponding `/16` network|
|`255.255.255.255`|Ignore all bits → any address|

### Example

```text
192.168.10.0 0.0.0.255
```

Matches:

```text
192.168.10.0/24
```

### Exact host

```text
host 192.168.10.10
```

Equivalent to:

```text
192.168.10.10 0.0.0.0
```

### Any address

```text
any
```

Equivalent to:

```text
0.0.0.0 255.255.255.255
```

---

# 5. Calculating Wildcard Masks

Wildcard mask = **inverse of subnet mask**

|Subnet Mask|Wildcard|
|---|---|
|`255.255.255.255`|`0.0.0.0`|
|`255.255.255.0`|`0.0.0.255`|
|`255.255.255.192`|`0.0.0.63`|
|`255.255.255.224`|`0.0.0.31`|
|`255.255.255.240`|`0.0.0.15`|
|`255.255.255.248`|`0.0.0.7`|
|`255.255.255.252`|`0.0.0.3`|
|`255.255.0.0`|`0.0.255.255`|
|`255.0.0.0`|`0.255.255.255`|
|`0.0.0.0`|`255.255.255.255`|

### Exam shortcut

```text
255 - subnet-mask-octet = wildcard-octet
```

Example:

```text
255.255.255.192
        ↓
255 - 192 = 63
        ↓
0.0.0.63
```

# 6. ACL Processing

ACL entries are processed **top-to-bottom**.

The first ACE that matches the packet determines the action.

```text
Packet
  |
  v
ACE 10
  |
  +-- Match --> PERMIT/DENY --> STOP
  |
  +-- No match
       |
       v
ACE 20
  |
  +-- Match --> PERMIT/DENY --> STOP
  |
  +-- No match
       |
       v
Implicit DENY
```

### Key rule

> **First match wins.**

The router does **not** continue searching for a more specific match.

---

# 7. Implicit Deny

Every ACL has an implicit deny at the end.

Conceptually:

```text
deny ip any any
```

Example:

```text
access-list 10 permit 192.168.10.0 0.0.0.255
```

Effectively means:

```text
permit 192.168.10.0/24
deny everything else
```

If all remaining IPv4 traffic should be permitted, add an explicit permit:

```text
access-list 10 permit 192.168.10.0 0.0.0.255
access-list 10 permit any
```

For an extended ACL:

```text
access-list 101 permit tcp any host 10.0.0.5 eq 443
access-list 101 permit ip any any
```

An explicit final deny can also be used for visibility and counters:

```text
deny ip any any
```

---

# 8. ACL Ordering

Because the first match wins, **order is critical**.

Bad:

```text
access-list 101 permit ip any any
access-list 101 deny tcp any host 10.0.0.5 eq 22
```

The SSH deny is never reached.

Correct:

```text
access-list 101 deny tcp any host 10.0.0.5 eq 22
access-list 101 permit ip any any
```

### Design principle

```text
Specific rules
     ↓
Specific denies
     ↓
Specific permits
     ↓
General rules
     ↓
Broad permit/deny
```

Always verify the exact policy because the correct order depends on the intended result.

---

# 9. ACL Placement

Recommended placement:

### Extended ACL

Place **close to the source** where practical.

Why?

Because extended ACLs can identify:

- Source
    
- Destination
    
- Protocol
    
- Port
    

Therefore, unwanted traffic can be stopped before crossing the network.

### Standard ACL

Place **close to the destination** where practical.

Why?

Because standard ACLs only know the source address. Placing one too close to the source  
could unintentionally block that source from reaching multiple destinations.

> These are **design guidelines**, not IOS restrictions.

---

# 10. Applying IPv4 ACLs

Use:

```text
ip access-group <ACL> in
```

or:

```text
ip access-group <ACL> out
```

Example:

```text
interface GigabitEthernet0/0
 ip access-group 101 in
```

### Direction

The direction is from the **router's perspective**.

```text
Host ---> Gi0/0 ---> Router
```

Traffic entering `Gi0/0`:

```text
ip access-group 101 in
```

Traffic leaving `Gi0/0`:

```text
ip access-group 101 out
```

---

# 11. Standard ACL Configuration

Example:

```text
access-list 10 permit 192.168.10.0 0.0.0.255

interface GigabitEthernet0/1
 ip access-group 10 out
```

The ACL matches only:

```text
Source IPv4 address
```

It cannot directly match:

```text
Destination
Protocol
TCP port
UDP port
```

---

# 12. Extended ACL Configuration

Example:

```text
access-list 101 permit tcp any host 10.0.0.5 eq 443
access-list 101 deny ip any any

interface GigabitEthernet0/0
 ip access-group 101 in
```

Meaning:

1. Permit TCP.
    
2. Source can be any IPv4 address.
    
3. Destination must be `10.0.0.5`.
    
4. Destination TCP port must be `443`.
    
5. Deny remaining IPv4 traffic.
    
6. Apply inbound on `Gi0/0`.

# 13. Extended ACL Protocol Matching

Extended ACLs can match IP protocols.

Common examples:

```text
tcp
udp
icmp
ip
```

### TCP

```text
access-list 101 permit tcp any host 10.0.0.10 eq 443
```

### UDP

```text
access-list 101 permit udp any host 10.0.0.20 eq 53
```

### ICMP

```text
access-list 101 permit icmp any host 10.0.0.1
```

### Any IPv4 protocol

```text
access-list 101 permit ip any any
```

`ip` means any IPv4 protocol carried by IPv4, subject to the other match criteria.

---

# 14. TCP/UDP Port Operators

Port operators are used with TCP/UDP matching.

|Operator|Meaning|
|---|---|
|`eq`|Equal to|
|`neq`|Not equal to|
|`gt`|Greater than|
|`lt`|Less than|
|`range`|Inclusive range|

Examples:

```text
eq 443
```

```text
range 20 21
```

```text
gt 1023
```

### Destination port example

```text
access-list 101 permit tcp any host 10.0.0.5 eq 443
```

Here `eq 443` matches the **destination TCP port**.

### Source port example

```text
access-list 101 permit tcp any eq 1024 host 10.0.0.5
```

Here `eq 1024` matches the **source TCP port**.

# 16. ICMP ACLs

Extended ACLs can match ICMP.

Example:

```text
access-list 101 permit icmp any host 10.0.0.1
```

More specific matching can identify ICMP types.

Example:

```text
access-list 101 permit icmp any host 10.0.0.1 echo
```

ICMP ACLs are useful when controlling:

- Ping
    
- Echo replies
    
- Destination unreachable
    
- Time exceeded
    
- Other ICMP message types
    

### Important

Do not blindly block all ICMP. Network troubleshooting, Path MTU Discovery,  
routing behavior, and IPv6 operation can depend on ICMP/ICMPv6.

---

# 17. TCP `established`

The `established` keyword can match TCP packets with:

- ACK set
    
- RST set
    

Example:

```text
access-list 101 permit tcp any any established
```

This is sometimes used to allow return TCP traffic.

### Important limitation

`established` is **not a stateful firewall**.

It does not maintain a full connection table and does not guarantee that traffic belongs  
to a legitimate session.

For modern security designs, use a proper stateful firewall when stateful inspection  
is required.

---

# 18. TCP Flags

Extended ACLs can match TCP flags.

Common flags include:

```text
ack
fin
psh
rst
syn
urg
```

TCP flags can be used to distinguish different types of TCP traffic.

Example concept:

```text
permit tcp any any syn
```

The exact flag syntax and available options should be verified against the IOS/IOS XE  
version being used.

### Exam concept

Know that ACLs can perform **TCP flag matching**, but ACL-based TCP filtering is not  
equivalent to stateful firewall inspection.

---

# 19. Named ACLs

Example:

```text
ip access-list extended WEB-FILTER
 permit tcp any host 10.0.0.5 eq 443
 deny tcp any host 10.0.0.5 eq 80
 permit ip any any
```

Named ACLs support sequence numbers:

```text
ip access-list extended WEB-FILTER
 10 permit tcp any host 10.0.0.5 eq 443
 20 deny tcp any host 10.0.0.5 eq 80
 30 permit ip any any
```

---

# 20. ACL Sequence Numbers

Sequence numbers allow entries to be inserted and modified more easily.

Example:

```text
ip access-list extended WEB-FILTER
 10 permit tcp any host 10.0.0.5 eq 443
 20 deny tcp any host 10.0.0.5 eq 80
 30 permit ip any any
```

Insert a new ACE:

```text
ip access-list extended WEB-FILTER
 15 deny tcp any host 10.0.0.5 eq 8080
```

### Resequence

For numbered ACLs:

```text
access-list resequence 101 10 10
```

Meaning:

```text
ACL number:       101
Starting number:  10
Increment:        10
```

---

# 21. ACL Remarks

Use remarks to document ACL purpose.

Example:

```text
ip access-list extended WEB-FILTER
 remark Allow HTTPS to web server
 permit tcp any host 10.0.0.5 eq 443
 remark Block HTTP
 deny tcp any host 10.0.0.5 eq 80
 permit ip any any
```

Good remarks make large ACLs easier to understand and troubleshoot.

---

# 22. Editing and Removing ACL Entries

Named ACLs can be entered and modified individually.

Example:

```text
ip access-list extended WEB-FILTER
 no 20
```

removes sequence `20`.

Remove the entire named ACL:

```text
no ip access-list extended WEB-FILTER
```

For a numbered ACL, individual ACE removal can be more cumbersome depending on the  
IOS version and configuration method.

---

# 23. Time-Based ACLs

A **time-based ACL** makes an ACE active only during a configured time period.

Create a time range:

```text
time-range BUSINESS-HOURS
 periodic weekdays 08:00 to 18:00
```

Use it in an ACL:

```text
ip access-list extended WEB-ACCESS
 permit tcp 192.168.10.0 0.0.0.255 host 10.0.0.5 eq 443 time-range BUSINESS-HOURS
 deny ip any any
```

The permit is active only during the configured time range.

### Uses

- Temporary access
    
- Business-hours access
    
- Scheduled maintenance
    
- Scheduled management access
    

---

# 24. Dynamic ACLs / Lock-and-Key

Dynamic ACLs can create temporary access after successful authentication.

Conceptually:

```text
User
  |
  v
Authentication
  |
  v
Temporary ACL entry
  |
  v
Permitted traffic
```

They are commonly associated with **lock-and-key security**.

Dynamic ACLs are more advanced than normal static ACLs and should not be confused  
with stateful firewall policies.

---

# 25. Reflexive ACLs

Reflexive ACLs can dynamically create temporary entries for return traffic.

Concepts include:

```text
reflect
evaluate
```

Example concept:

```text
permit tcp any any reflect OUTBOUND
```

and another ACL can evaluate the reflected entries.

Reflexive ACLs provide a limited form of dynamic return-traffic filtering, but they  
are not equivalent to a modern stateful firewall.

---

# 26. ACL Logging

ACL entries can use logging to report matches.

Example:

```text
access-list 101 deny ip any any log
```

or with named ACL syntax where supported:

```text
ip access-list extended FILTER
 deny ip any any log
```

Logging can help identify:

- Blocked sources
    
- Blocked destinations
    
- Unexpected traffic
    
- Policy violations
    

### Caution

Excessive ACL logging can generate large amounts of logging traffic and CPU work.  
Use it selectively, especially on high-volume deny entries.

---

# 27. ACLs and VTY Access

`access-class` is used to restrict VTY access.

Example:

```text
access-list 10 permit 192.168.10.0 0.0.0.255

line vty 0 4
 access-class 10 in
```

This controls which source addresses can connect to the VTY lines.

### Important distinction

```text
ip access-group
```

→ Interface traffic

```text
access-class
```

→ VTY access

---

# 28. ACLs and NAT

ACLs can identify traffic for NAT.

Example:

```text
access-list 10 permit 192.168.10.0 0.0.0.255

ip nat inside source list 10 interface GigabitEthernet0/1 overload
```

The ACL identifies which inside addresses should be translated.

### Important

An ACL used by NAT is functioning as a **traffic-selection mechanism**. It is not  
necessarily being applied as a packet filter on an interface.

---

# 29. ACLs and Route-Maps

ACLs can be used with route-maps.

Example:

```text
access-list 10 permit 192.168.10.0 0.0.0.255

route-map PBR permit 10
 match ip address 10
 set ip next-hop 10.0.0.1
```

The ACL identifies the traffic that the route-map should match.

This is commonly encountered with:

- Policy-Based Routing
    
- NAT
    
- Redistribution policies
    
- Other policy features
    

---

# 30. ACLs and QoS

ACLs can classify traffic for QoS.

Example:

```text
access-list 101 permit tcp any any eq 443
```

A QoS class-map can reference the ACL:

```text
class-map WEB
 match access-group 101
```

The ACL therefore identifies traffic that QoS can classify and treat differently.

---

# 31. ACLs and CoPP

**Control Plane Policing (CoPP)** protects the router's control plane.

ACLs can be used as part of the traffic classification process.

Conceptually:

```text
Incoming traffic
       |
       v
  ACL matching
       |
       v
   CoPP policy
       |
       v
Control plane
```

Do not confuse:

- **Data-plane/interface ACLs** → transit traffic
    
- **CoPP** → traffic destined for the device's control plane
    

---

# 32. IPv6 ACLs

IPv6 ACLs are important for ENCOR.

Create a named IPv6 ACL:

```text
ipv6 access-list WEB-V6
 permit tcp 2001:db8:10::/64 host 2001:db8:20::10 eq 443
 deny ipv6 any any
```

Apply it:

```text
interface GigabitEthernet0/0
 ipv6 traffic-filter WEB-V6 in
```

### IPv6 ACL differences

|Feature|IPv4 ACL|IPv6 ACL|
|---|---|---|
|Address|IPv4|IPv6|
|Wildcard mask|Yes|**No**|
|Named ACL|Yes|Yes|
|Interface command|`ip access-group`|`ipv6 traffic-filter`|
|ICMP|ICMP|**ICMPv6**|
|Implicit deny|Yes|Yes|

---

# 33. IPv6 and ICMPv6

ICMPv6 is especially important because IPv6 depends on ICMPv6 for functions such as:

- Neighbor Discovery
    
- Router Discovery
    
- Neighbor Solicitation
    
- Neighbor Advertisement
    
- Path MTU Discovery
    

Therefore:

> **Do not treat ICMPv6 like optional ping traffic.**

Blocking required ICMPv6 messages can break normal IPv6 operation.

---

# 34. IPv6 ACL Example

```text
ipv6 access-list USERS-V6
 permit tcp 2001:db8:10::/64 host 2001:db8:20::10 eq 443
 permit icmp any any
 deny ipv6 any any

interface GigabitEthernet0/0
 ipv6 traffic-filter USERS-V6 in
```

# 35. ACL Processing and Routing

For transit traffic, an interface ACL can affect whether the packet is allowed to  
continue through the router.

A simplified model is:

```text
Packet arrives
     |
     v
Ingress ACL
     |
     +-- Deny --> Drop
     |
     +-- Permit
          |
          v
      Routing/FIB
          |
          v
      Egress ACL
          |
          +-- Deny --> Drop
          |
          +-- Permit
                |
                v
              Send
```

The exact internal implementation depends on the platform and forwarding architecture,  
but the key operational idea is:

> **Ingress and egress ACLs control traffic at the corresponding interface boundaries.**

---

# 36. ACL vs Routing

An ACL does **not create a route**.

Routing answers:

> **Where should the packet go?**

ACL answers:

> **Is this packet allowed?**

Example:

```text
Routing table:
10.0.0.0/24 → Gi0/1
```

may correctly route traffic, but an ACL can still deny it.

Therefore, when troubleshooting connectivity:

```text
Routing problem?
       ↓
ACL problem?
       ↓
NAT problem?
       ↓
Layer-2 problem?
       ↓
Host/firewall problem?
```

Check each independently.

# 37. ACL Troubleshooting

### Step 1 — Check the ACL

```text
show ip access-lists
```

### Step 2 — Check counters

Look for:

```text
matches
```

If the expected ACE has no matches, the packet may not be reaching that ACL or may  
not match the ACE.

### Step 3 — Check interface application

```text
show ip interface GigabitEthernet0/0
```

### Step 4 — Check direction

```text
in
out
```

Remember that direction is from the router's perspective.

### Step 5 — Check ACE order

A previous broad ACE may be matching first.

### Step 6 — Check source and destination

Verify:

```text
source IP
destination IP
```

### Step 7 — Check protocol and port

Verify:

```text
TCP
UDP
ICMP
source port
destination port
```

### Step 8 — Check routing

```text
show ip route
```

### Step 9 — Check IPv6 separately

```text
show ipv6 access-list
show ipv6 route
```

# 39. ACL Counters

Example:

```text
show ip access-lists
```

Possible output:

```text
Extended IP access list WEB-FILTER
    10 permit tcp any host 10.0.0.5 eq 443 (25 matches)
    20 deny ip any any (7 matches)
```

Counters help determine whether traffic is hitting a particular ACE.

If a deny entry has increasing counters:

```text
deny ip any any (100 matches)
```

then unmatched traffic is reaching the implicit/explicit deny.

---

# 40. Clearing ACL Counters

ACL counters can be cleared when troubleshooting or measuring a new traffic test.

Example:

```text
clear access-list counters
```

After clearing:

1. Generate test traffic.
    
2. Check ACL counters.
    
3. Identify which ACE matched.
    

This can make troubleshooting much easier.

# 41. Common ACL Mistakes

|Mistake|Result|
|---|---|
|Wrong wildcard|Unexpected matches|
|Wrong direction|ACL appears ineffective|
|Wrong interface|Traffic bypasses ACL|
|Broad permit first|Later denies never match|
|Missing final permit|Traffic hits implicit deny|
|Wrong destination|Intended traffic does not match|
|Wrong port|Application fails|
|Blocking ICMP|Troubleshooting/PMTUD issues|
|Blocking required ICMPv6|IPv6 functionality may break|
|Confusing `access-class` and `access-group`|Management filtering does not work as expected|
|Forgetting ACL counters|Harder troubleshooting|
|Excessive logging|High logging/CPU overhead|

# 44. Exam Traps

## Trap 1 — First match wins

```text
permit ip any any
deny tcp any host 10.0.0.5 eq 22
```

The deny is never reached.

---

## Trap 2 — Implicit deny

If nothing matches:

```text
DENY
```

---

## Trap 3 — Wildcard logic

Remember:

```text
0 = MATCH
1 = IGNORE
```

---

## Trap 4 — Standard ACL

Standard ACLs match:

```text
SOURCE ONLY
```

---

## Trap 5 — Extended ACL

Extended ACLs can match:

```text
SOURCE
DESTINATION
PROTOCOL
PORTS
OTHER EXTENDED CRITERIA
```

---

## Trap 6 — `eq 443`

```text
permit tcp any host 10.0.0.5 eq 443
```

means destination TCP port `443`.

---

## Trap 7 — `access-group` vs `access-class`

```text
ip access-group
```

→ interface traffic

```text
access-class
```

→ VTY access

---

## Trap 8 — IPv6 wildcard masks

IPv6 ACLs do **not** use IPv4 wildcard masks.

---

## Trap 9 — ACL vs firewall

An ACL is primarily a **stateless packet-filtering/matching mechanism**.

It is not equivalent to a full stateful firewall.

---

## Trap 10 — ACL does not replace routing

A permit in an ACL does not create a route.

Routing and ACL filtering are separate functions.
