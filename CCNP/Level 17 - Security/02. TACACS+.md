# TACACS+

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**TACACS+ (Terminal Access Controller Access-Control System Plus)** is a Cisco-developed AAA protocol commonly used for **centralized network-device administration**.

It provides:

- **Authentication** — verifies administrator identity
    
- **Authorization** — controls what an authenticated administrator can do
    
- **Accounting** — records administrator activity
    
- **TCP transport** on port **49**
    
- Strong separation of authentication, authorization, and accounting
    
- **Granular command authorization**
    
- Encryption of the **TACACS+ packet body**
    

TACACS+ is commonly preferred for **network-device administrative AAA**, while RADIUS is widely used for **network-access AAA** such as 802.1X, wireless, and VPN services.

---

## 2. TACACS+ Architecture

A typical deployment looks like:

```text
              +----------------------+
              |   TACACS+ Server     |
              |  Authentication      |
              |  Authorization       |
              |  Accounting          |
              +----------+-----------+
                         |
                    TCP 49
                         |
              +----------+-----------+
              |   Cisco Router/SW    |
              |      AAA Client       |
              +----------+-----------+
                         |
                   Administrator
```

The network device acts as the **TACACS+ client**.

The TACACS+ server performs centralized AAA functions.

## 3. Transport

|Property|TACACS+|
|---|---|
|Transport|TCP|
|Port|TCP 49|
|Connection|Reliable TCP session|
|Common use|Network-device administration|
|Authentication|Supported|
|Authorization|Supported|
|Accounting|Supported|

### Key exam fact

```text
TACACS+ → TCP 49
```

Do not confuse this with RADIUS:

```text
RADIUS authentication → UDP 1812
RADIUS accounting     → UDP 1813
```

---

## 4. Encryption

TACACS+ protects the **packet body** using a shared secret between the client and server.

The shared secret is configured on both sides:

```cisco
tacacs server TAC1
 address ipv4 10.0.0.5
 key SharedSecret
```

### Important terminology

Do not memorize:

> "TACACS+ encrypts the entire packet including the header."

A more accurate statement is:

> **TACACS+ encrypts the TACACS+ packet body; selected header information remains visible.**

For CCNP-level comparison, remember:

```text
TACACS+ → packet body encrypted
RADIUS  → traditionally protects the password field rather than the entire packet
```

---

## 5. Shared Secret

The TACACS+ key must match between the network device and TACACS+ server.

Cisco configuration:

```cisco
tacacs server TAC1
 address ipv4 10.0.0.5
 key MySecretKey
```

If the key does not match:

```text
Client → TACACS+ Server
          |
          X
      authentication/
      integrity failure
```

Typical symptoms include:

- Authentication failures
    
- Authentication timeouts/failures
    
- Server communication problems

## 6. TACACS+ and AAA

TACACS+ integrates directly with Cisco AAA.

Basic framework:

```cisco
aaa new-model
```

Authentication:

```cisco
aaa authentication login default group tacacs+ local
```

EXEC authorization:

```cisco
aaa authorization exec default group tacacs+ local
```

Command authorization:

```cisco
aaa authorization commands 15 default group tacacs+ local
```

EXEC accounting:

```cisco
aaa accounting exec default start-stop group tacacs+
```

Command accounting:

```cisco
aaa accounting commands 15 default start-stop group tacacs+
```

---

## 7. TACACS+ Authentication

Authentication answers:

> **Who are you?**

Example:

```cisco
aaa authentication login VTY-AUTH group tacacs+ local
```

Apply the method list:

```cisco
line vty 0 15
 login authentication VTY-AUTH
```

The device sends the administrator's authentication request to the TACACS+ server.

The server can:

```text
ACCEPT
REJECT
or become UNAVAILABLE
```

These responses matter when AAA method-list fallback is configured.

---

## 8. TACACS+ Authorization

Authorization answers:

> **What are you allowed to do?**

TACACS+ is particularly useful for network-device administration because authorization can be granular.

Examples:

```cisco
aaa authorization exec default group tacacs+
```

and:

```cisco
aaa authorization commands 15 default group tacacs+
```

---

## 9. EXEC Authorization

EXEC authorization controls whether the user can obtain an authorized EXEC session and what authorization information is associated with that session.

Example:

```cisco
aaa authorization exec default group tacacs+ local
```

Conceptually:

```text
Authentication
      ↓
Identity verified
      ↓
EXEC authorization
      ↓
Authorized EXEC session
```

Authentication success does **not automatically guarantee authorization success**.

---

## 10. Command Authorization

Command authorization is one of TACACS+'s major advantages for network-device administration.

Example:

```cisco
aaa authorization commands 15 default group tacacs+
```

The number `15` represents the **IOS privilege level**, not the number of commands.

Examples:

```cisco
aaa authorization commands 1 default group tacacs+
aaa authorization commands 5 default group tacacs+
aaa authorization commands 15 default group tacacs+
```

### Example

An administrator may authenticate successfully but receive:

```text
show commands → permitted
configure terminal → denied
```

The TACACS+ server can make authorization decisions based on configured policies/attributes.

---

## 11. TACACS+ Authorization Attributes

TACACS+ can return authorization information using **attribute-value pairs (AV pairs)**.

These can provide information such as:

- Privilege level
    
- Shell/EXEC authorization
    
- Command authorization
    
- Service-specific authorization
    

Conceptually:

```text
Administrator
     |
     v
TACACS+ Authentication
     |
     v
Server returns authorization attributes
     |
     v
Cisco IOS applies authorization policy
```

This is one reason TACACS+ is valuable for centralized network-device administration.

---

## 12. Accounting

Accounting answers:

> **What did the administrator do?**

TACACS+ accounting can record activities such as:

- EXEC sessions
    
- Commands
    
- Other supported connection/service events
    

### EXEC accounting

```cisco
aaa accounting exec default start-stop group tacacs+
```

Records the beginning and end of an EXEC session.

### Command accounting

```cisco
aaa accounting commands 15 default start-stop group tacacs+
```

Records commands executed at privilege level 15.

Accounting is useful for:

- Auditing
    
- Security investigations
    
- Compliance
    
- Operational tracking
    

---

## 13. Authentication vs Authorization vs Accounting

|Function|TACACS+ Role|
|---|---|
|Authentication|Verify administrator identity|
|Authorization|Determine permitted actions|
|Accounting|Record activity|

Remember:

```text
Authentication → WHO?
Authorization  → WHAT?
Accounting     → WHAT DID THEY DO?
```

## 14. TACACS+ Server Configuration

Modern IOS-style configuration:

```cisco
tacacs server TAC1
 address ipv4 10.0.0.5
 key MyTacacsKey
```

Multiple servers can be configured:

```cisco
tacacs server TAC1
 address ipv4 10.0.0.5
 key MyTacacsKey

tacacs server TAC2
 address ipv4 10.0.0.6
 key MyTacacsKey
```

---

## 15. TACACS+ Server Groups

A server group lets AAA reference a logical group of TACACS+ servers.

Example:

```cisco
aaa group server tacacs+ TACACS-GROUP
 server name TAC1
 server name TAC2
```

Then:

```cisco
aaa authentication login default group TACACS-GROUP local
```

Advantages:

- Multiple TACACS+ servers
    
- Centralized server selection
    
- Better redundancy
    
- Different groups can be used for different AAA policies
    

---

Example:

```cisco
!
aaa new-model
!

!

!

!
```

## 17. TACACS+ with SSH

A common enterprise design is:

```text
Administrator
      |
      | SSH
      v
Cisco Router/Switch
      |
      | TCP 49
      v
TACACS+ Server
```

Configuration:

```cisco
aaa new-model

aaa authentication login VTY-AUTH group tacacs+ local
aaa authorization exec VTY-EXEC group tacacs+ local

line vty 0 15
 login authentication VTY-AUTH
 authorization exec VTY-EXEC
 transport input ssh
```

### Security principle

Use:

```cisco
transport input ssh
```

rather than allowing insecure Telnet management where possible.

## 18. Local Fallback

A common configuration is:

```cisco
aaa authentication login default group tacacs+ local
```

This provides a local method after TACACS+ when the earlier method is unavailable according to AAA fallback rules.

The local database must contain a usable account:

```cisco
username admin privilege 15 secret LocalPassword
```

### Important

Do not interpret this as:

```text
TACACS+ rejects password
        ↓
always try local
```

That is incorrect.

AAA distinguishes between:

- Server unavailable/timeout
    
- Explicit authentication rejection
    
- Other method responses
    

An explicit TACACS+ rejection generally should **not** be bypassed by automatically trying the local database.

---

## 19. Why Local Fallback Matters

Without an appropriate fallback:

```text
Administrator
      |
      v
Cisco Device
      |
      v
TACACS+ Server
      |
      X
   UNREACHABLE
      |
      v
Login may fail
```

With an appropriate local fallback:

```text
Administrator
      |
      v
Cisco Device
      |
      v
TACACS+ Server
      |
      X
   UNREACHABLE
      |
      v
Local AAA
      |
      v
Access
```

This is especially important for remote devices.

---

## 20. `none` Is Not the Same as `local`

Do not confuse:

```cisco
local
```

with:

```cisco
none
```

### `local`

Uses the device's local username database:

```cisco
username admin privilege 15 secret Password
```

### `none`

Means no authentication/authorization method is required for the relevant AAA service where `none` is supported.

It should **not** be used as a normal substitute for secure local fallback.

## 21. TACACS+ vs RADIUS

|Feature|TACACS+|RADIUS|
|---|---|---|
|Origin|Cisco-developed|IETF standard|
|Transport|TCP|UDP|
|Ports|TCP 49|UDP 1812/1813|
|Common use|Device administration|Network access AAA|
|Authentication|Separate AAA function|Authentication/access control|
|Authorization|Granular|Attribute-based, generally less granular for CLI commands|
|Command authorization|Strong support|Not equivalent to TACACS+ command authorization|
|Encryption|TACACS+ body|Traditionally password field protection|
|Transport reliability|TCP|UDP|
|Accounting|Yes|Yes|

### Remember

```text
Device administration
        ↓
     TACACS+

Network access
        ↓
      RADIUS
```

This is a **use-case rule**, not an absolute restriction.

RADIUS can also be used for administrative access, and TACACS+ is not limited exclusively to device administration.

## 22. TACACS+ vs RADIUS — Ports

```text
TACACS+
TCP 49
```

```text
RADIUS
UDP 1812 → Authentication
UDP 1813 → Accounting
```

Legacy RADIUS deployments may use:

```text
UDP 1645 → Authentication
UDP 1646 → Accounting
```

Modern RADIUS deployments normally use:

```text
UDP 1812
UDP 1813
```

---

## 23. TACACS+ vs RADIUS — Transport

### TACACS+

```text
Administrator
     |
     v
Cisco Device
     |
   TCP 49
     |
     v
TACACS+ Server
```

TCP provides connection-oriented, reliable transport.

### RADIUS

```text
Client
  |
 UDP
  |
  v
RADIUS Server
```

RADIUS uses UDP and therefore handles reliability at the application protocol level rather than relying on TCP.

## 24. TACACS+ Server Selection

When multiple TACACS+ servers are configured, IOS can use the configured server group and server-selection mechanisms to select an available server.

Example:

```cisco
aaa group server tacacs+ TACACS-GROUP
 server name TAC1
 server name TAC2
```

If one server becomes unavailable, another server can be used according to IOS AAA server-selection behavior.

This provides redundancy.

---

## 25. TACACS+ Deadtime

IOS can temporarily avoid repeatedly attempting to contact a server that has been determined to be unavailable.

Example syntax varies by IOS/platform, so verify the exact supported command before deployment.

Conceptually:

```text
TACACS+ Server
      |
      X
  unavailable
      |
      v
Temporarily treated as dead
      |
      v
Try another server
```

This improves failover behavior in multi-server deployments.

---

## 26. TACACS+ Source Interface

The source IP used for TACACS+ communication can matter when:

- The TACACS+ server uses an ACL
    
- Routing is asymmetric
    
- Management traffic must use a dedicated interface
    
- The server expects a specific client IP
    

Example platform-dependent configuration:

```cisco
ip tacacs source-interface Loopback0
```

Then the TACACS+ server identifies the device using the expected source address.

Always ensure that the chosen source IP is reachable from the TACACS+ server.

---

## 27. VRF Considerations

In enterprise networks, management traffic may exist in a dedicated VRF.

Conceptually:

```text
Management VRF
      |
      v
Loopback / Mgmt Interface
      |
      v
TACACS+ Server
```

If TACACS+ is configured for a management VRF, verify that:

- The VRF exists
    
- The TACACS+ server is reachable in that VRF
    
- The correct source interface/address is used
    
- The platform supports the required TACACS+ VRF syntax
    

Exact commands are IOS/platform dependent.

## 28. Troubleshooting TACACS+

Use a structured approach.

### Step 1 — Verify AAA configuration

```cisco
show running-config | section aaa
```

Check:

- `aaa new-model`
    
- Authentication method lists
    
- Authorization method lists
    
- Accounting lists
    
- Server groups
    

---

### Step 2 — Verify TACACS+ server configuration

```cisco
show running-config | section tacacs
```

Check:

- Server IP
    
- Server group
    
- Shared secret
    
- Source interface if configured
    

---

### Step 3 — Test IP reachability

```cisco
ping 10.0.0.5
```

Verify:

- Routing
    
- Interface status
    
- ACLs
    
- VRF
    
- Return path
    

---

### Step 4 — Verify TCP 49

The server must be reachable using:

```text
TCP/49
```

A successful ping does **not** prove that TACACS+ is working.

```text
Ping works
     ≠
TCP 49 works
```

---

### Step 5 — Verify the shared secret

The key must match:

```text
Cisco Device
    |
    | MySecretKey
    |
TACACS+ Server
```

A mismatch causes TACACS+ communication/authentication problems.

---

### Step 6 — Verify authentication

Check:

```cisco
debug aaa authentication
debug tacacs
```

---

### Step 7 — Verify authorization

If authentication succeeds but commands fail:

```cisco
debug aaa authorization
```

Check:

```cisco
aaa authorization exec ...
aaa authorization commands ...
```

---

### Step 8 — Verify accounting

If users can log in but accounting records are missing:

```cisco
debug aaa accounting
```

Check:

```cisco
aaa accounting exec ...
aaa accounting commands ...
```

|Symptom|Possible Cause|What to Check|
|---|---|---|
|TACACS+ timeout|Server unreachable|Routing / ACL / TCP 49|

## 32. TACACS+ Security Best Practices

Use:

```text
SSH
+
TACACS+
+
Strong shared secret
+
Local emergency account
+
Command authorization
+
Accounting
+
Redundant TACACS+ servers
```

Additional practices:

- Restrict TCP 49 to authorized TACACS+ servers.
    
- Protect the TACACS+ shared secret.
    
- Use dedicated management networks where appropriate.
    
- Use redundant AAA servers.
    
- Use local emergency access carefully.
    
- Enable accounting for administrative auditing.
    
- Restrict administrative privileges.
    
- Test AAA changes before closing the existing management session.
    
- Maintain console or out-of-band access.
    

---

## 33. TACACS+ Configuration Safety

AAA changes can lock administrators out.

Before applying major AAA changes:

```text
1. Keep console/OOB access available.
2. Keep an existing administrative session open.
3. Configure TACACS+.
4. Configure local fallback.
5. Test authentication.
6. Test EXEC authorization.
7. Test command authorization.
8. Test accounting.
9. Open a second SSH session.
10. Only then close the original session.
```

Never test a major AAA change on a remote production device without a recovery path.

## 34. TACACS+ Exam Traps

### Trap 1 — TCP 49

```text
TACACS+ → TCP 49
```

Not UDP.

---

### Trap 2 — RADIUS ports

```text
RADIUS authentication → UDP 1812
RADIUS accounting     → UDP 1813
```

---

### Trap 3 — TACACS+ body encryption

Do not say:

> "The entire IP packet is encrypted."

More accurate:

> **The TACACS+ packet body is encrypted using the shared secret; header information remains visible.**

---

### Trap 4 — Per-command authorization

TACACS+ is strongly associated with:

```text
Per-command authorization
```

This is a major reason it is commonly selected for network-device administration.

---

### Trap 5 — Authentication ≠ authorization

A user can:

```text
Authenticate successfully
        ↓
Fail authorization
```

Always troubleshoot the two separately.

---

### Trap 6 — `commands 15`

```cisco
aaa authorization commands 15 ...
```

means:

> Commands at privilege level 15.

It does not mean:

> 15 commands.

---

### Trap 7 — Local fallback

```cisco
group tacacs+ local
```

does not mean:

> Every TACACS+ rejection automatically falls back to local.

Fallback depends on the AAA method response.

---

### Trap 8 — `none` ≠ `local`

```text
local → use local username database
none  → no authentication/authorization method
```

Do not confuse them.

---

### Trap 9 — Ping is not enough

```text
ping TACACS+ server
```

proves IP reachability, not that:

```text
TCP 49
```

is permitted or that the shared secret is correct.

---

### Trap 10 — Device admin ≠ only use case

TACACS+ is commonly associated with device administration, but RADIUS is not exclusively a wireless/VPN protocol and TACACS+ is not technically limited to one use case.

## 39. Final Takeaway

For CCNP Enterprise, remember TACACS+ as:

> **Centralized AAA for network-device administration, using TCP 49, with strong separation of authentication, authorization, and accounting and granular command authorization.**

The most important exam facts are:

1. **TACACS+ uses TCP port 49.**
    
2. **TACACS+ is Cisco-developed.**
    
3. **TACACS+ encrypts the TACACS+ packet body.**
    
4. **TACACS+ supports granular command authorization.**
    
5. **Authentication, authorization, and accounting are separate AAA functions.**
    
6. **`commands N` refers to an IOS privilege level.**
    
7. **The TACACS+ shared secret must match.**
    
8. **`group tacacs+ local` provides fallback only according to AAA method behavior.**
    
9. **TACACS+ server groups provide redundancy and logical grouping.**
    
10. **Ping success does not prove TCP/49 or TACACS+ authentication is working.**
    
11. **TACACS+ is commonly used for device administration; RADIUS is commonly used for network access.**
    
12. **Always maintain a console/OOB recovery path when modifying AAA.**
