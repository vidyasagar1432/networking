# AAA

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**AAA** = **Authentication, Authorization, and Accounting**.

It controls:

- **Authentication** — Who are you?
    
- **Authorization** — What are you allowed to do?
    
- **Accounting** — What did you do?
    

Cisco IOS can use **local databases** or centralized **TACACS+ / RADIUS** servers.

AAA is built around three major components:

1. `aaa new-model`
    
2. **AAA method lists**
    
3. **AAA services** such as authentication, authorization, and accounting
    

---

## 2. The Three A's

|AAA Function|Question|Example|
|---|---|---|
|**Authentication**|Who are you?|Verify username/password|
|**Authorization**|What can you do?|Permit privilege level 15|
|**Accounting**|What did you do?|Record login/session/command activity|

### Authentication

Authentication verifies the user's identity.

Example:

```cisco
aaa authentication login default group tacacs+ local
```

The device attempts TACACS+ authentication and can use the local database as a fallback when the TACACS+ method is unavailable.

### Authorization

Authorization determines what an authenticated user is permitted to do.

Examples:

```cisco
aaa authorization exec default group tacacs+ local
aaa authorization commands 15 default group tacacs+ local
```

Authorization can control:

- EXEC access
    
- Commands
    
- Network services
    
- Privilege levels
    
- Other supported IOS services
    

### Accounting

Accounting records activity for auditing and tracking.

Example:

```cisco
aaa accounting exec default start-stop group tacacs+
aaa accounting commands 15 default start-stop group tacacs+
```

Accounting **does not grant or deny access**. It records activity.

---

## 3. `aaa new-model`

AAA must be enabled before configuring IOS AAA services:

```cisco
aaa new-model
```

This changes the device's authentication/authorization behavior to use the AAA framework.

### Important

After enabling `aaa new-model`, existing line authentication behavior can change.

Do **not** assume that an existing:

```cisco
line vty 0 15
 login local
```

configuration automatically replaces a newly configured AAA method list.

Always verify the effective AAA configuration and ensure a valid management-access fallback exists before testing remote access.

---

## 4. Local User Database

A local fallback requires local usernames:

```cisco
username admin privilege 15 secret StrongPassword
```

Verify:

```cisco
show running-config | include username
```

Local authentication can then be referenced by:

```cisco
aaa authentication login default group tacacs+ local
```

## 5. AAA Method Lists

A **method list** defines how IOS performs a particular AAA operation.

General structure:

```text
aaa <service> <type> <list-name> <methods>
```

Examples:

```cisco
aaa authentication login default group tacacs+ local
aaa authorization exec default group tacacs+ local
aaa authorization commands 15 default group tacacs+ local
aaa accounting exec default start-stop group tacacs+
```

### Components

|Component|Meaning|
|---|---|
|`aaa`|Enable AAA command framework|
|`authentication`|Authentication service|
|`authorization`|Authorization service|
|`accounting`|Accounting service|
|`login`|Login authentication|
|`exec`|EXEC authorization/accounting|
|`commands 15`|Commands at privilege level 15|
|`default`|Default method list|
|`group tacacs+`|Use TACACS+ server group|
|`local`|Use local username database|
|`none`|Permit without authentication/authorization where supported|
|`start-stop`|Start and stop accounting records|

---

## 6. Default vs Named Method Lists

### Default method list

The `default` list is automatically used when no named method list is explicitly applied.

Example:

```cisco
aaa authentication login default group tacacs+ local
```

### Named method list

A named list allows different AAA behavior for different lines or services.

Example:

```cisco
aaa authentication login VTY-AUTH group tacacs+ local
```

Apply it:

```cisco
line vty 0 15
 login authentication VTY-AUTH
```

### Key point

A **named method list must be explicitly applied**.

The `default` method list is used automatically when no named list is specified for that service.

---

## 7. AAA Method Order and Fallback

Example:

```cisco
aaa authentication login default group tacacs+ local
```

The order is:

1. Try the TACACS+ method.
    
2. If the TACACS+ method is unavailable according to AAA's fallback rules, try `local`.
    

### Critical exam point

Do **not** memorize this as simply:

> "First method fails → second method always runs."

AAA distinguishes between different types of responses.

A **server timeout/unavailability** can permit fallback to another method.

A **definitive authentication rejection** from the server generally does **not** mean IOS should ignore that rejection and authenticate locally.

This prevents a central AAA server's explicit denial from being bypassed accidentally.

---

## 8. TACACS+ vs RADIUS

|Feature|TACACS+|RADIUS|
|---|---|---|
|Vendor|Cisco-originated / widely implemented|IETF standard|
|Transport|TCP|UDP|
|Default authentication port|TCP 49|UDP 1812|
|Accounting|TCP 49|UDP 1813|
|Encryption|Encrypts the AAA packet body|Traditionally encrypts password field|
|Command authorization|Strong support|More limited for device administration|
|AAA separation|Authentication, authorization, accounting separated|More tightly coupled|
|Common use|Network-device administration|Network access / AAA|

### CCNP exam preference

For **network-device administrative access**, TACACS+ is commonly preferred because it provides strong separation of authentication and authorization and supports granular command authorization.

## 9. TACACS+ Server Configuration

Example:

```cisco
tacacs server TAC1
 address ipv4 10.0.0.5
 key MyTacacsKey
```

Create a server group:

```cisco
aaa group server tacacs+ TACACS-GROUP
 server name TAC1
```

Use the group:

```cisco
aaa authentication login default group TACACS-GROUP local
```

### Older syntax

Some IOS versions/labs may use:

```cisco
tacacs-server host 10.0.0.5
tacacs-server key MyTacacsKey
```

The exact syntax depends on the IOS platform and release.

## 11. Authentication for VTY / SSH

A common secure management configuration is:

```cisco
aaa new-model

username admin privilege 15 secret LocalPassword

aaa authentication login VTY-AUTH group tacacs+ local
aaa authorization exec VTY-EXEC group tacacs+ local

line vty 0 15
 login authentication VTY-AUTH
 authorization exec VTY-EXEC
 transport input ssh
```

This provides:

- TACACS+ authentication
    
- Local fallback when appropriate
    
- EXEC authorization
    
- SSH-only remote access
    

---

## 12. EXEC Authorization

Authentication answers:

> **Who are you?**

EXEC authorization answers:

> **Are you allowed to obtain an EXEC shell, and with what authorization information?**

Example:

```cisco
aaa authorization exec default group tacacs+ local
```

This is different from command authorization.

---

## 13. Command Authorization

Command authorization controls commands based on privilege level.

Example:

```cisco
aaa authorization commands 15 default group tacacs+ local
```

The number represents the IOS privilege level:

```text
commands 1
commands 5
commands 15
```

For example:

```cisco
aaa authorization commands 15 default group tacacs+
```

controls commands executed at **privilege level 15**.

### Important

`commands N` does **not** mean "allow N commands."

It refers to the **privilege level**.

---

## 14. Privilege Levels

Cisco IOS traditionally uses privilege levels from:

```text
0–15
```

Common levels:

|Level|Typical use|
|---|---|
|0|Very limited commands|
|1|User EXEC|
|15|Privileged EXEC|

Example:

```cisco
username admin privilege 15 secret Password
```

This assigns the local user privilege level 15.

AAA authorization can override or influence what the user is permitted to do based on server-provided authorization attributes.

---

## 15. Accounting

### EXEC accounting

Records EXEC session activity:

```cisco
aaa accounting exec default start-stop group tacacs+
```

### Command accounting

Records commands at a specified privilege level:

```cisco
aaa accounting commands 15 default start-stop group tacacs+
```

### Common accounting keywords

|Keyword|Meaning|
|---|---|
|`start-stop`|Send start and stop records|
|`stop-only`|Send only stop records|
|`none`|No accounting|

### Example

```cisco
aaa accounting exec default start-stop group tacacs+
aaa accounting commands 15 default start-stop group tacacs+
```

This provides auditing of:

- EXEC sessions
    
- Privilege-level command activity
    

---

## 16. AAA Network Authorization

AAA authorization is not limited to CLI access.

IOS supports different authorization services, including:

```cisco
aaa authorization exec ...
aaa authorization commands ...
aaa authorization network ...
```

For example:

```cisco
aaa authorization network default group radius local
```

`network` authorization is relevant to network-access services such as supported PPP/VPN-related AAA functions.

## 17. Complete TACACS+ Example

```cisco
!
aaa new-model
!
username admin privilege 15 secret LocalFallbackPassword
!
tacacs server TAC1
 address ipv4 10.0.0.5
 key MyTacacsKey
!
aaa group server tacacs+ TACACS-GROUP
 server name TAC1
!
aaa authentication login VTY-AUTH group TACACS-GROUP local
aaa authorization exec VTY-EXEC group TACACS-GROUP local
aaa authorization commands 15 CMD-AUTH group TACACS-GROUP local
!
aaa accounting exec EXEC-ACCT start-stop group TACACS-GROUP
aaa accounting commands 15 CMD-ACCT start-stop group TACACS-GROUP
!
line vty 0 15
 login authentication VTY-AUTH
 authorization exec VTY-EXEC
 authorization commands 15 CMD-AUTH
 transport input ssh
!
```

### What happens?

```text
SSH connection
      |
      v
Authentication
      |
      +---- TACACS+
      |
      +---- local fallback if appropriate
      |
      v
EXEC authorization
      |
      v
Command authorization
      |
      v
Accounting records
```

## 18. Local-Only AAA

AAA does not require TACACS+ or RADIUS.

A device can use its local database:

```cisco
aaa new-model

username admin privilege 15 secret LocalPassword

aaa authentication login default local
aaa authorization exec default local
```

This is useful for:

- Small environments
    
- Lab environments
    
- Emergency access
    
- AAA-server outage fallback
    

However, centralized AAA is generally preferred in enterprise networks.

---

## 19. AAA vs Line Passwords

Traditional line authentication:

```cisco
line vty 0 15
 password Cisco123
 login
```

uses the line password.

Local authentication:

```cisco
line vty 0 15
 login local
```

uses the local username database.

AAA authentication:

```cisco
line vty 0 15
 login authentication VTY-AUTH
```

uses the specified AAA method list.

### Key distinction

Do not treat:

```cisco
login
login local
login authentication <method-list>
```

as interchangeable.

They represent different authentication mechanisms.

## 22. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Login fails|Incorrect method list|`show run \| section aaa`|
|Local fallback fails|No local username|`show run \| include username`|
|TACACS+ timeout|Server unreachable|Routing, ACL, server|
|TACACS+ rejects login|Wrong credentials/policy|TACACS+ server|
|EXEC denied|EXEC authorization problem|`aaa authorization exec`|
|Commands denied|Command authorization problem|`aaa authorization commands`|
|No accounting records|Accounting not configured/reachable|`aaa accounting`|
|Wrong AAA server used|Incorrect server group|`aaa group server`|
|SSH works but authorization fails|Authz configuration/server attributes|EXEC/command authorization|
|Device becomes inaccessible|AAA misconfiguration|Console/OOB access|

## 23. AAA Lockout Prevention

AAA changes should be performed carefully.

A common safe strategy is:

```cisco
aaa authentication login default group tacacs+ local
```

This gives the device a local fallback when the centralized server is unavailable and fallback conditions are met.

Maintain a known working local emergency account:

```cisco
username emergency privilege 15 secret EmergencyPassword
```

### Best practice

Before changing AAA on a remote device:

1. Keep an existing administrative session open.
    
2. Configure the new AAA method.
    
3. Open a second test session.
    
4. Test authentication.
    
5. Test authorization.
    
6. Test accounting.
    
7. Only then close the original session.
    

Out-of-band/console access is especially important for AAA changes.

## 26. Common Exam Traps

### Trap 1 — Authentication ≠ Authorization

Authentication:

> **Who are you?**

Authorization:

> **What are you allowed to do?**

---

### Trap 2 — Accounting does not authorize

Accounting records activity.

It does not grant access.

---

### Trap 3 — `commands 15`

```cisco
aaa authorization commands 15 default ...
```

The `15` means:

> **Privilege level 15**

It does not mean 15 commands.

---

### Trap 4 — Default vs named lists

```cisco
aaa authentication login default ...
```

is a default method list.

```cisco
aaa authentication login VTY-AUTH ...
```

is a named method list.

Named lists must be explicitly applied.

---

### Trap 5 — Fallback is not "any failure"

With:

```cisco
group tacacs+ local
```

a TACACS+ server being unreachable/unavailable can allow the next method to be tried.

A definitive authentication rejection generally does not mean IOS should silently bypass the rejection and try local authentication.

---

### Trap 6 — `local` requires local users

This:

```cisco
aaa authentication login default group tacacs+ local
```

is not useful as a local fallback unless a local user exists:

```cisco
username admin privilege 15 secret Password
```

---

### Trap 7 — Authentication and authorization are separate

A user can successfully authenticate but still fail authorization.

Example:

```text
Authentication → SUCCESS
Authorization  → DENIED
```

Therefore, troubleshooting must check both.

---

### Trap 8 — TACACS+ vs RADIUS

Remember the high-level distinction:

```text
TACACS+ → TCP 49 + stronger separation + command authorization
RADIUS  → UDP 1812/1813 + common network-access AAA
```

## 27. Troubleshooting Workflow

When AAA fails, troubleshoot in this order:

```text
1. Is the AAA configuration correct?
        |
        v
2. Can the router reach the AAA server?
        |
        v
3. Is the correct server group being used?
        |
        v
4. Is the shared secret/key correct?
        |
        v
5. Is authentication working?
        |
        v
6. Is EXEC authorization working?
        |
        v
7. Is command authorization working?
        |
        v
8. Is accounting working?
```

Useful commands:

```cisco
show running-config | section aaa
show aaa servers
show aaa sessions
debug aaa authentication
debug aaa authorization
debug aaa accounting
```

## 31. Final Takeaway

For CCNP ENCOR, understand AAA as a **policy framework**, not just a collection of commands:

```text
aaa new-model
      ↓
Method Lists
      ↓
Authentication
      ↓
Authorization
      ↓
Accounting
```

The most important concepts to master are:

1. **Authentication vs authorization vs accounting**
    
2. **Default vs named method lists**
    
3. **TACACS+ vs RADIUS**
    
4. **Local fallback**
    
5. **EXEC vs command authorization**
    
6. **Privilege-level-based command authorization**
    
7. **Accounting start/stop records**
    
8. **AAA troubleshooting**
    
9. **AAA lockout prevention**
    
10. **Method-list fallback behavior**
