# Infrastructure Security

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Infrastructure security** protects the **network itself** — not the data flowing through
it. It defends against spoofing, protocol attacks, and resource exhaustion at the edge.
Core techniques: **anti-spoofing ACLs (uRPF)**, **BGP/OSPF protections**, **DHCP
snooping/DAI/IPSG** (notes 16/17), and **CPP/CoPP**. The exam mixes these into
"infrastructure protection" scenarios.

---

## 2. Core Concepts

### 2.1 What we protect

| Asset | Threat | Defense |
|-------|--------|---------|
| Edge routers | spoofed sources | uRPF / ACLs |
| Routing protocols | forged updates | MD5 / auth |
| Switches | MAC/IP/ARP attacks | snooping/DAI/IPSG |
| Device CPU | floods | CoPP |
| Mgmt plane | unauthorized | secure mgmt (11) |

### 2.2 Anti-spoofing with uRPF

```text
interface Gi0/0
 ip verify unicast source reachable-via rx
```

| Mode | Check |
|------|-------|
| strict (rx) | source must be reachable via that interface |
| loose | source reachable via **any** interface |

- **Strict** on edge toward customer; **loose** where asymmetric routing exists.

### 2.3 Routing-protocol protection

| Protocol | Auth |
|----------|------|
| OSPF | `ip ospf authentication message-digest` |
| EIGRP | key chain / HMAC-SHA |
| BGP | MD5 (TCP MD5) / BGP TTL security |
| IS-IS | HMAC-MD5 |

```text
router bgp 65001
 neighbor 192.0.2.2 password BgpSecret
 neighbor 192.0.2.2 ttl-security hops 1
```

- BGP **TTL security** (GTSM) drops spoofed packets far from the peer.
- eBGP has its own AS_PATH loop prevention (L12 note 04).

### 2.4 Filtering at the edge (anti-spoofing ACL)

| Filter | Rule |
|--------|------|
| Private/bogons | deny in from internet |
| Own prefixes | deny as source from internet |
| RFC1918 | deny as transit source |
| Directed broadcast | disable (`no ip directed-broadcast`) |

- ACLs applied inbound on WAN/uplink interfaces.

### 2.5 Access-layer stack (summary)

| Defense | Attack | Note |
|---------|--------|------|
| DHCP snooping | rogue server/starve | 16·02 |
| DAI | ARP spoof | 17·06 |
| IPSG | IP spoof | 17·07 |
| Port security | MAC flood | 17·05 |
| Storm control | floods | 17·08 |

- All rely on the **snooping binding table** where applicable.

### 2.6 Device-level protections

| Control | Purpose |
|---------|---------|
| CoPP | CPU DoS |
| CEF/uRPF | source validation |
| `no service` hardening | attack surface |
| AAA + SSH | management |
| BPDU guard / root guard | STP attacks |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Legit traffic dropped | uRPF strict w/ asymmetric | switch to loose |
| BGP flapping | MD5 mismatch | neighbor password |
| Spoofed source passes | missing edge ACL | inbound filter |
| Protocol flap | no protocol auth | add auth |
| CPU overload | no CoPP | control-plane |

---

## 5. Exam Traps

- **uRPF strict vs loose** — the routing-asymmetry trap.
- BGP **TTL security + MD5** both protect the session.
- Anti-spoofing ACLs go **inbound on edge**.
- Access-layer stack feeds off **DHCP snooping**.
- Infrastructure security ≠ data security — it guards the **network fabric**.
