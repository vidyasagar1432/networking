# Dynamic ARP Inspection (DAI)

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Dynamic ARP Inspection (DAI)** is a Layer 2 security feature that protects against **ARP spoofing and ARP poisoning**.

DAI intercepts ARP packets received on **untrusted switchports** and validates their contents before allowing them through.

The most common source of trusted IP-to-MAC information is the **DHCP Snooping binding database**.

DAI can also use **ARP ACLs** for devices that do not obtain their addresses through DHCP, such as servers with statically configured IP addresses.

### DAI relationship

```text
DHCP Snooping
      │
      │ creates IP ↔ MAC bindings
      ▼
DHCP Snooping Binding Table
      │
      ▼
Dynamic ARP Inspection
      │
      ├── Valid ARP → Forward
      └── Invalid ARP → Drop
```

> **Important:** DHCP Snooping is the normal source of DAI bindings, but DAI can also validate using configured **ARP ACLs**.

---

# 2. The Threat: ARP Spoofing / Poisoning

ARP has no built-in authentication.

An attacker can send a forged ARP message such as:

```text
192.168.1.1 is at aaaa.bbbb.cccc
```

where `192.168.1.1` is actually the gateway but `aaaa.bbbb.cccc` belongs to the attacker.

Victims may then associate:

```text
Gateway IP → Attacker MAC
```

This can allow:

- Traffic interception
    
- Man-in-the-middle attacks
    
- Traffic redirection
    
- Network disruption
    

DAI helps prevent this by validating ARP information before forwarding it.

---

# 3. Trusted vs Untrusted Ports

By default, interfaces are **untrusted** for DAI.

|Port|DAI Behavior|Typical Use|
|---|---|---|
|**Untrusted**|ARP packets are inspected|End-user/device ports|
|**Trusted**|ARP inspection is bypassed|Uplinks, infrastructure/gateway-facing ports|

Example:

```text
                Router
                  │
                  │ Trusted
                  │
             +----+----+
             | Switch  |
             +----+----+
                  │
            Untrusted
                  │
                 PC
```

Configure a trusted interface:

```text
interface GigabitEthernet0/1
 ip arp inspection trust
```

### Important

Do **not** blindly trust user-facing ports.

A trusted interface bypasses DAI inspection, so it should normally face a legitimate network device such as:

- Router
    
- Layer 3 switch
    
- Trusted distribution switch
    
- Other controlled infrastructure
    

---

# 4. Basic DAI Configuration

DAI is enabled per VLAN.

Typical configuration:

```text
ip dhcp snooping
ip dhcp snooping vlan 10
!
ip arp inspection vlan 10
!
interface GigabitEthernet0/1
 ip arp inspection trust
```

The logical sequence is:

```text
1. Enable DHCP Snooping
2. Enable DHCP Snooping for the VLAN
3. Configure DHCP Snooping trusted interfaces
4. Enable DAI for the VLAN
5. Trust appropriate infrastructure interfaces
6. Leave endpoint ports untrusted
```

# 5. DHCP Snooping Binding Table

When DHCP Snooping observes legitimate DHCP exchanges, it can build bindings containing information such as:

```text
MAC address
IP address
VLAN
Interface
Lease information
```

Example:

```text
IP Address      MAC Address       VLAN    Interface
192.168.10.20   aaaa.bbbb.1111   10      Gi0/2
192.168.10.21   aaaa.bbbb.2222   10      Gi0/3
```

DAI can use these bindings to determine whether an ARP packet is legitimate.

Verification:

```text
show ip dhcp snooping binding
```

---

# 6. How DAI Validates ARP

DAI examines ARP packets received on untrusted interfaces.

The switch can validate information such as:

- Sender IP address
    
- Sender MAC address
    
- Target MAC address
    
- Relationship between IP and MAC information
    

The exact validation behavior depends on the configured DAI validation options.

Common validation checks include:

```text
src-mac
dst-mac
ip
```

---

## 6.1 Source MAC Validation

```text
ip arp inspection validate src-mac
```

Checks whether the **source MAC in the Ethernet frame** matches the **sender MAC address in the ARP packet**.

Example:

```text
Ethernet Source MAC
        │
        ▼
aaaa.bbbb.1111
        │
        │ must match
        ▼
ARP Sender MAC
aaaa.bbbb.1111
```

A mismatch can indicate a forged ARP packet.

---

## 6.2 Destination MAC Validation

```text
ip arp inspection validate dst-mac
```

Checks the destination MAC information between the Ethernet frame and ARP packet where applicable.

---

## 6.3 IP Validation

```text
ip arp inspection validate ip
```

Checks ARP IP information for invalid or inconsistent addresses, including checks involving the ARP sender/target IP fields.

---

## 6.4 Multiple Validation Checks

Multiple validation options can be configured:

```text
ip arp inspection validate src-mac dst-mac ip
```

> The exact supported syntax and behavior can vary by Cisco IOS/platform. Use `?` to verify available options.

---

# 7. DHCP Snooping + DAI

A common design looks like this:

```text
                    Router
                      │
                Trusted Gi0/1
                      │
               +------+------+
               |   Switch    |
               +------+------+
                      │
             Untrusted Gi0/2
                      │
                     PC
```

The DHCP Snooping binding table might contain:

```text
192.168.10.50
      │
      ▼
aaaa.bbbb.5050
```

The PC sends:

```text
ARP:
192.168.10.1 is at aaaa.bbbb.5050
```

DAI can validate the ARP information against the available trusted information.

If an attacker sends:

```text
ARP:
192.168.10.1 is at aaaa.bbbb.evil
```

and the information fails validation, DAI can drop the packet.

---

# 8. Static-IP Devices

A common problem occurs with devices that use **static IP addresses**.

Examples:

- Servers
    
- Printers
    
- Network appliances
    
- Cameras
    
- Management devices
    

These devices may not appear in the DHCP Snooping binding table.

Therefore, DAI can use an **ARP ACL** to define legitimate IP-to-MAC mappings.

---

# 9. ARP ACL

Create an ARP access list:

```text
arp access-list STATIC-ARP
 permit ip host 192.168.10.50 mac host aaaa.bbbb.5050
```

Apply it to the VLAN:

```text
ip arp inspection filter STATIC-ARP vlan 10
```

Conceptually:

```text
192.168.10.50
      │
      ▼
aaaa.bbbb.5050
```

is explicitly permitted.

### Why ARP ACLs matter

Without an appropriate trusted binding or ARP ACL, a legitimate statically addressed device can have its ARP packets rejected by DAI.

---

# 10. DHCP Bindings vs ARP ACLs

DAI can obtain validation information from:

```text
DHCP Snooping Binding Table
          OR
ARP ACL
```

In practical deployments, both can be used.

|Device|Typical Source of Validation|
|---|---|
|DHCP client|DHCP Snooping binding|
|Static-IP server|ARP ACL|
|Static-IP appliance|ARP ACL|
|Trusted infrastructure|DAI trusted interface|

---

# 11. DAI Rate Limiting

DAI can limit the rate of ARP packets received on an interface.

This helps protect against excessive ARP traffic.

Example:

```text
interface GigabitEthernet0/2
 ip arp inspection limit rate 15 burst interval 1
```

This configuration limits ARP traffic on the interface according to the configured rate/burst parameters.

### Why rate limiting matters

An attacker could generate a large number of ARP packets.

Without protection:

```text
Attacker
   │
   │ ARP flood
   ▼
Switch
```

Rate limiting helps control excessive ARP traffic.

> Rate-limit settings must be chosen carefully. A legitimate host or environment with high ARP activity can otherwise trigger the limit.

---

# 12. Rate-Limit Violations and Err-Disabled State

Depending on the Cisco IOS/platform and configuration, exceeding the DAI rate limit can cause the interface to be placed into an **err-disabled** state.

Check:

```text
show errdisable recovery
```

If supported, automatic recovery can be configured:

```text
errdisable recovery cause arp-inspection
errdisable recovery interval 60
```

> The exact errdisable cause name and support can vary by Cisco IOS/platform. Always verify with `errdisable recovery cause ?`.

---

# 13. DAI Configuration Example

Complete example:

```text
ip dhcp snooping
ip dhcp snooping vlan 10
!
ip arp inspection vlan 10
!
interface GigabitEthernet0/1
 description UPLINK-TO-ROUTER
 ip dhcp snooping trust
 ip arp inspection trust
!
interface GigabitEthernet0/2
 description USER-PC
 switchport mode access
 switchport access vlan 10
```

The design is:

```text
Gi0/1 → Trusted infrastructure
Gi0/2 → Untrusted endpoint
```

The endpoint port remains subject to DAI inspection.

# 14. Static-IP Example

Suppose a server has:

```text
IP: 192.168.10.50
MAC: aaaa.bbbb.5050
```

Create the ARP ACL:

```text
arp access-list STATIC-ARP
 permit ip host 192.168.10.50 mac host aaaa.bbbb.5050
```

Apply it:

```text
ip arp inspection filter STATIC-ARP vlan 10
```

Enable DAI:

```text
ip arp inspection vlan 10
```

Now DAI has a static source of truth for that server.

# 17. Troubleshooting

|Symptom|Likely Cause|Check|
|---|---|---|
|Legitimate ARP is dropped|Missing DHCP binding|`show ip dhcp snooping binding`|
|Static-IP host cannot communicate|Missing ARP ACL|Check ARP ACL|
|Gateway ARP fails|Uplink/infrastructure port is untrusted|`ip arp inspection trust`|
|ARP validation failures|Incorrect IP/MAC information|DAI statistics|
|Port becomes err-disabled|ARP rate limit exceeded|`show errdisable recovery`|
|DAI appears inactive|DAI not enabled for VLAN|`show ip arp inspection`|
|DHCP clients fail DAI|DHCP Snooping not configured correctly|Check snooping configuration/bindings|
|ARP works intermittently|Binding/aging or rate-limit issue|Check bindings and statistics|
|Legitimate device repeatedly drops|Incorrect binding/ARP ACL|Compare IP/MAC/interface|

# 20. DAI vs DHCP Snooping

These features work together but solve different problems.

|Feature|Main Purpose|
|---|---|
|**DHCP Snooping**|Protects DHCP and builds trusted IP/MAC bindings|
|**DAI**|Validates ARP using trusted information|
|**ARP ACL**|Provides static ARP validation information|
|**IP Source Guard**|Restricts source IP/MAC traffic using bindings|

Typical relationship:

```text
DHCP Snooping
     │
     ├──────────────┐
     ▼              ▼
DAI          IP Source Guard
     │
     ▼
ARP Protection
```

---

# 21. DAI vs Port Security

These features protect different aspects of Layer 2 access.

|Feature|Protects Against|
|---|---|
|**Port Security**|Unauthorized source MAC addresses|
|**DAI**|ARP spoofing/poisoning|
|**DHCP Snooping**|Rogue DHCP servers / untrusted DHCP messages|
|**IP Source Guard**|Unauthorized source IP/MAC traffic|

They can be deployed together.

Example access-layer security:

```text
Port Security
      +
DHCP Snooping
      +
Dynamic ARP Inspection
      +
IP Source Guard
```

---

# 22. Important Limitations

DAI is specifically designed to protect **ARP**.

It does not automatically protect against every Layer 2 or Layer 3 attack.

For example:

- Port Security → source MAC control
    
- DHCP Snooping → DHCP protection/binding creation
    
- DAI → ARP protection
    
- IP Source Guard → source IP/MAC enforcement
    
- 802.1X → identity/authentication
    
- Storm Control → excessive Layer 2 traffic
    

DAI should therefore be viewed as **one component of a broader access-layer security strategy**.

# 23. Exam Traps

- **DAI protects against ARP spoofing/poisoning.**
    
- DAI is enabled **per VLAN** with `ip arp inspection vlan`.
    
- Interfaces are **untrusted by default** for DAI.
    
- Trusted interfaces bypass DAI validation.
    
- Typically trust **infrastructure/uplink interfaces**, not endpoint ports.
    
- DHCP Snooping commonly provides the **IP-to-MAC binding information** used by DAI.
    
- DAI can also use **ARP ACLs**, so DHCP Snooping is not the only possible source of validation information.
    
- Static-IP devices commonly require an **ARP ACL** when no DHCP Snooping binding exists.
    
- DAI can inspect **ARP requests and replies**, not merely ARP replies.
    
- DAI can perform configurable **MAC and IP validation checks**.
    
- `src-mac` compares the Ethernet source MAC with the ARP sender MAC.
    
- `dst-mac` validates destination MAC information.
    
- `ip` validates ARP IP information.
    
- DAI rate limiting is configured **per interface**.
    
- Excessive ARP traffic can trigger rate-limit protection and, depending on platform/configuration, err-disable the interface.
    
- Always check the **DHCP Snooping binding table** when legitimate ARP traffic is being dropped.
    
- Do not confuse **DHCP Snooping** with **DAI**: snooping creates/maintains bindings; DAI uses trusted information to validate ARP.
    
- Do not blindly trust every trunk. Trust only interfaces where ARP traffic is expected and controlled.

# 26. One-Minute Exam Summary

**DAI = inspect ARP and reject forged IP/MAC information.**

Remember:

```text
DHCP Snooping
      │
      ▼
IP ↔ MAC Binding
      │
      ▼
DAI
      │
      ├── Valid ARP   → Forward
      └── Invalid ARP → Drop
```

Core concepts:

```text
DAI                 → Protects against ARP spoofing
VLAN                → DAI is enabled per VLAN
Untrusted           → ARP is inspected
Trusted             → ARP inspection bypassed
DHCP Snooping       → Common source of bindings
ARP ACL             → Static validation source
src-mac             → Ethernet source MAC vs ARP sender MAC
dst-mac             → Destination MAC validation
ip                  → ARP IP validation
Rate limit          → Controls excessive ARP traffic
Statistics          → Troubleshoot dropped ARP
```

Most important commands:

```text
show ip arp inspection
show ip arp inspection interfaces
show ip arp inspection statistics
show ip dhcp snooping binding
```

**Port Security controls who can use a port by MAC address; DHCP Snooping builds trusted bindings; DAI uses those bindings to protect ARP.**
