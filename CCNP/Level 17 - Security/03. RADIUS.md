# RADIUS

> **Level 17 · Security** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**RADIUS (Remote Authentication Dial-In User Service)** is an open-standard AAA protocol widely used for **network-access authentication, authorization, and accounting**.

Common enterprise use cases include:

- **802.1X**
    
- Enterprise Wi-Fi
    
- VPN access
    
- Network access control
    
- Remote-access services
    
- Centralized user authentication
    

RADIUS uses **UDP** and commonly uses:

```text
UDP 1812 → Authentication / authorization
UDP 1813 → Accounting
```

RADIUS uses **attributes** to carry authentication and authorization information between the network-access device and the RADIUS server.

---

## 2. RADIUS Architecture

A typical network-access deployment is:

```text
                         +----------------------+
                         |    RADIUS Server     |
                         | Authentication       |
                         | Authorization        |
                         | Accounting           |
                         +----------+-----------+
                                    |
                              UDP 1812/1813
                                    |
                         +----------+-----------+
                         |       NAS            |
                         | AP / Switch / VPN    |
                         | Firewall / Gateway   |
                         +----------+-----------+
                                    |
                              Network Client
```

### Important terminology

|Component|Meaning|
|---|---|
|**Supplicant**|End device requesting network access|
|**Authenticator / NAS**|Device controlling network access|
|**RADIUS Client**|Usually the NAS sending RADIUS requests|
|**RADIUS Server**|Performs centralized AAA|
|**RADIUS Proxy**|Forwards requests between RADIUS realms/servers|

### Critical exam point

The **switch, wireless controller/AP, VPN gateway, or other NAS is the RADIUS client**.

The end user's laptop is generally the **supplicant**, not the RADIUS client.

---

## 3. RADIUS Ports

|Function|Port|
|---|--:|
|Authentication / authorization|**UDP 1812**|
|Accounting|**UDP 1813**|

Legacy deployments may use:

```text
UDP 1645 → Authentication
UDP 1646 → Accounting
```

Modern RADIUS deployments normally use:

```text
UDP 1812
UDP 1813
```

### Exam memory

```text
RADIUS
1812 → Authentication
1813 → Accounting
```

---

## 4. RADIUS Transport

RADIUS traditionally uses **UDP** rather than TCP.

Therefore, RADIUS itself must handle things such as:

- Request retransmission
    
- Response timeouts
    
- Server selection
    
- Failover
    

Conceptually:

```text
NAS
 |
 | UDP
 |
 +-------> RADIUS Server
 |
 | timeout
 |
 +-------> retransmit / try another server
```

### Important

Do not conclude:

> "UDP means RADIUS cannot be reliable."

Instead:

> RADIUS uses UDP and implements its own request/response and retransmission behavior.

---

## 5. RADIUS Security and Encryption

Traditional RADIUS security is based on a **shared secret** between the RADIUS client and server.

Example:

```cisco
radius server RAD1
 address ipv4 10.0.0.5 auth-port 1812 acct-port 1813
 key SharedSecret
```

### Important CCNP distinction

The traditional RADIUS protocol does **not provide whole-packet encryption in the same way TACACS+ does**.

The commonly taught comparison is:

```text
RADIUS
→ traditionally protects the user password field

TACACS+
→ encrypts the TACACS+ packet body
```

However, do not oversimplify modern RADIUS security to:

> "Everything except the password is completely unsecured."

Actual security depends on the RADIUS version, authentication method, attributes, transport protection, and deployment.

---

## 6. RADIUS Shared Secret

The shared secret must match on both sides.

```text
RADIUS Client
     |
     | SharedSecret
     |
RADIUS Server
```

Example:

```cisco
radius server RAD1
 address ipv4 10.0.0.5 auth-port 1812 acct-port 1813
 key MyRadiusSecret
```

If the secret is incorrect, RADIUS authentication or accounting can fail.

### Security best practice

Use a strong shared secret and protect it like any other credential.

---

## 7. RADIUS Packet Types

The most important RADIUS packet types are:

|Packet|Purpose|
|---|---|
|**Access-Request**|Client asks server to authenticate/authorize|
|**Access-Accept**|Server accepts request|
|**Access-Reject**|Server rejects request|
|**Access-Challenge**|Server requests additional authentication information|
|**Accounting-Request**|Client sends accounting information|
|**Accounting-Response**|Server acknowledges accounting request|

---

## 8. Basic Authentication Flow

A simplified authentication exchange:

```text
RADIUS Client / NAS
        |
        | Access-Request
        v
RADIUS Server
        |
        | Access-Accept
        v
RADIUS Client
        |
        v
   Network Access
```

If rejected:

```text
RADIUS Client
        |
        | Access-Request
        v
RADIUS Server
        |
        | Access-Reject
        v
RADIUS Client
        |
        v
      DENIED
```

The server can also return:

```text
Access-Challenge
```

when additional authentication steps are required.

---

## 9. Access-Request

The NAS sends an **Access-Request** to request authentication/authorization.

It can contain attributes such as:

- User identity
    
- Authentication information
    
- NAS identity
    
- NAS IP address
    
- NAS port
    
- Service type
    
- Calling/called station information
    
- EAP-related information
    
- Other policy attributes
    

Conceptually:

```text
Supplicant
    |
    v
NAS
    |
    | Access-Request
    | + attributes
    v
RADIUS Server
```

---

## 10. Access-Accept

If the user is accepted:

```text
RADIUS Server
      |
      | Access-Accept
      | + authorization attributes
      v
NAS
```

The server can return authorization/policy information.

Examples include:

- VLAN assignment
    
- Session timeout
    
- Filter/ACL-related policy
    
- Privilege-related attributes
    
- Vendor-Specific Attributes
    
- Other network-access parameters
    

---

## 11. Access-Reject

If authentication or authorization is rejected:

```text
RADIUS Server
      |
      | Access-Reject
      v
NAS
      |
      v
Access denied
```

### Important AAA fallback trap

If an AAA method list contains:

```cisco
group radius local
```

do **not** assume that every RADIUS `Access-Reject` causes IOS to try the local database.

A definitive rejection is normally treated differently from a server being unavailable or timing out.

---

## 12. Access-Challenge

The RADIUS server can return:

```text
Access-Challenge
```

when additional authentication information is required.

This is important for authentication methods involving multiple exchanges.

Conceptually:

```text
NAS
 |
 | Access-Request
 v
Server
 |
 | Access-Challenge
 v
NAS
 |
 | Additional authentication information
 v
Server
 |
 +---- Access-Accept
 |
 +---- Access-Reject
```

---

## 13. RADIUS Attributes

RADIUS uses **attributes** to transport authentication, authorization, and session information.

Examples include:

```text
User-Name
NAS-IP-Address
Service-Type
Session-Timeout
Idle-Timeout
Framed-IP-Address
Calling-Station-Id
Called-Station-Id
```

Attributes allow the RADIUS server to return policy to the NAS.

---

## 14. Vendor-Specific Attributes (VSAs)

RADIUS supports **Vendor-Specific Attributes (VSAs)**.

VSAs allow vendors to define additional attributes for vendor-specific functionality.

Cisco environments can therefore use Cisco-specific RADIUS attributes for supported authorization and policy features.

Conceptually:

```text
RADIUS
  |
  +-- Standard Attributes
  |
  +-- Vendor-Specific Attributes
           |
           +-- Cisco-specific policy
```

### Exam point

RADIUS is not limited to a tiny set of authorization decisions.

It can return extensive policy information through standard attributes and VSAs.

---

## 15. RADIUS Authorization

RADIUS authorization is generally **attribute-based**.

For example, the RADIUS server may return policy that causes a NAS to:

- Place a user into a particular VLAN
    
- Apply session restrictions
    
- Assign an IP address
    
- Apply access policy
    
- Enforce session timeouts
    
- Apply vendor-specific policy
    

This differs from TACACS+'s strong association with **per-command authorization for network-device administration**.

---

## 16. RADIUS Accounting

Accounting records network-access activity.

Typical events include:

- Session start
    
- Session stop
    
- Interim updates
    
- Session duration
    
- Data usage
    
- NAS information
    
- User identity
    

Accounting uses:

```text
UDP 1813
```

Typical packet:

```text
Accounting-Request
```

followed by:

```text
Accounting-Response
```

---

## 17. Accounting Flow

```text
User connects
      |
      v
NAS
      |
      | Accounting-Request
      | Start
      v
RADIUS Server
      |
      | Accounting-Response
      v
NAS
```

At session termination:

```text
NAS
 |
 | Accounting-Request
 | Stop
 v
RADIUS Server
 |
 | Accounting-Response
 v
NAS
```

Interim accounting updates can also be sent during a session.

## 18. 802.1X and RADIUS

RADIUS is extremely important for **802.1X network access control**.

The three major roles are:

|Role|Example|
|---|---|
|**Supplicant**|Laptop / phone|
|**Authenticator**|Switch / wireless infrastructure|
|**Authentication Server**|RADIUS server|

Architecture:

```text
Supplicant
    |
    | EAP
    v
Authenticator / NAS
    |
    | RADIUS carrying EAP information
    v
RADIUS Server
```

### Important

The switch or wireless infrastructure is the **authenticator** and typically the **RADIUS client/NAS**.

The endpoint is the **supplicant**.

The RADIUS server performs centralized authentication.

---

## 19. EAP and RADIUS

RADIUS is commonly used to transport **EAP-related information** between the authenticator/NAS and authentication server in 802.1X deployments.

Example:

```text
Laptop
  |
  | EAP
  v
Switch
  |
  | RADIUS + EAP attributes
  v
RADIUS Server
```

This allows authentication methods such as:

- EAP-TLS
    
- PEAP
    
- Other supported EAP methods
    

to be integrated into centralized network-access authentication.

---

## 20. WPA2/WPA3-Enterprise

Enterprise Wi-Fi commonly uses:

```text
802.1X
+
EAP
+
RADIUS
```

Simplified architecture:

```text
Wireless Client
      |
      | 802.1X / EAP
      v
AP / WLC
      |
      | RADIUS
      v
RADIUS Server
```

The RADIUS server validates the user's/device's authentication according to the configured EAP method.

RADIUS can also provide centralized authentication for supported VPN/network-access systems.

Conceptually:

```text
VPN User
   |
   v
VPN Gateway / NAS
   |
   | RADIUS

RADIUS Server
```

## 22. RADIUS Server Groups

Cisco IOS can organize RADIUS servers into server groups.

Example:

```cisco
radius server RAD1
 address ipv4 10.0.0.5 auth-port 1812 acct-port 1813
 key Secret1

radius server RAD2
 address ipv4 10.0.0.6 auth-port 1812 acct-port 1813
 key Secret2

aaa group server radius RADIUS-GROUP
 server name RAD1
 server name RAD2
```

Then use:

```cisco
aaa authentication login default group RADIUS-GROUP local
```

This provides a logical group of RADIUS servers.

## 23. Basic Cisco RADIUS Configuration

Example:

```cisco
aaa new-model

radius server RAD1
 address ipv4 10.0.0.5 auth-port 1812 acct-port 1813
 key MyRadiusSecret

aaa group server radius RADIUS-GROUP
 server name RAD1

aaa authentication login default group RADIUS-GROUP local
```

For accounting:

```cisco
aaa accounting network default start-stop group RADIUS-GROUP
```

Exact AAA service configuration depends on what service is being secured.

---

## 24. RADIUS for Device Login

RADIUS can also be used for administrator login.

Example:

```cisco
aaa authentication login VTY-AUTH group radius local

line vty 0 15
 login authentication VTY-AUTH
 transport input ssh
```

However, for **granular network-device command authorization**, TACACS+ is generally the more appropriate Cisco AAA choice.

### Remember

```text
RADIUS
→ can authenticate device administrators

TACACS+
→ commonly preferred for granular device administration
```

Do not incorrectly state that RADIUS is incapable of device administration.

---

## 25. RADIUS Failover

Multiple RADIUS servers can provide redundancy:

```text
             +------------+
             | RADIUS 1   |
             +------+-----+
                    |
                    |
NAS ----------------+
                    |
             +------+-----+
             | RADIUS 2   |
             +------------+
```

If a configured server becomes unavailable, the NAS can retransmit and/or try another configured server according to its RADIUS/AAA server-selection behavior.

---

## 26. Local Fallback

Example:

```cisco
aaa authentication login default group radius local
```

This can provide local fallback when the RADIUS method is unavailable according to AAA fallback rules.

Local users must exist:

```cisco
username admin privilege 15 secret LocalPassword
```

### Important

Do not interpret:

```cisco
group radius local
```

as:

```text
Any RADIUS rejection
        ↓
Try local
```

An explicit `Access-Reject` is normally not treated as simple server unavailability.

---

## 27. RADIUS Source Interface

The RADIUS server identifies the client using the source IP and configured client definition.

In environments with multiple interfaces, a consistent source interface can be useful.

Example:

```cisco
ip radius source-interface Loopback0
```

Platform and IOS release support may vary.

Ensure the source address:

- Is configured on the device
    
- Is reachable by the RADIUS server
    
- Is configured as an authorized RADIUS client on the server
    

---

## 28. RADIUS and VRFs

Enterprise management networks may place RADIUS traffic in a dedicated VRF.

Conceptually:

```text
Management VRF
      |
      v
Management Interface / Loopback
      |
      v
RADIUS Server
```

Verify:

- Correct VRF
    
- Correct routing table
    
- Correct source interface
    
- Server reachability
    
- RADIUS client configuration
    

Exact commands vary by IOS/platform.

---

## 29. RADIUS Server Identification

A RADIUS server normally needs to know which network device is allowed to act as a client.

The server configuration commonly contains:

```text
Client IP address
Shared secret
Client name
```

Example conceptual configuration:

```text
RADIUS Client:
    IP = 10.0.0.10
    Secret = MySharedSecret
```

If the NAS uses a different source IP than expected, the server may reject or ignore the request.


- Source-interface configuration

## 32. Common RADIUS Failures

|Symptom|Likely Cause|Check|
|---|---|---|
|Authentication timeout|Server unreachable|Routing / UDP 1812|
|Authentication rejected|Invalid credentials/policy|RADIUS server|
|Shared-secret error|Key mismatch|Client/server configuration|
|Accounting missing|UDP 1813/configuration|Accounting configuration|
|Wrong VLAN|Incorrect returned attribute|Server policy|
|User not recognized|Incorrect identity source|RADIUS/identity system|
|Server ignores request|Unknown NAS/source IP|RADIUS client configuration|
|802.1X fails|EAP/NAS/server configuration|EAP + RADIUS|
|Works from one interface only|Source/VRF issue|Source interface / routing|
|Local fallback doesn't occur|Server response is rejection|AAA method behavior|

## 33. RADIUS vs TACACS+

|Feature|RADIUS|TACACS+|
|---|---|---|
|Standard|Open standard|Cisco-developed|
|Transport|UDP|TCP|
|Authentication port|UDP 1812|TCP 49|
|Accounting port|UDP 1813|TCP 49|
|Common use|Network access|Device administration|
|Encryption|Traditionally password protection|TACACS+ packet body|
|Authorization|Attribute-based|Granular command authorization|
|802.1X|Very common|Not the typical choice|
|Enterprise Wi-Fi|Very common|Not typical|
|VPN access|Very common|Less typical|
|Device administration|Possible|Common choice|
|Per-command CLI authorization|Not equivalent to TACACS+|Strong support|

### Exam memory

```text
Network Access
    ↓
RADIUS

Device Administration
    ↓
TACACS+
```

Again, this is a **common-use guideline**, not an absolute protocol limitation.

## 35. RADIUS Security Best Practices

Use:

- Strong RADIUS shared secrets
    
- Dedicated management/access-control networks where appropriate
    
- Redundant RADIUS servers
    
- Correct source-interface configuration
    
- ACLs restricting RADIUS traffic
    
- Secure transport/protection mechanisms supported by the deployment
    
- Accurate time synchronization where authentication systems depend on it
    
- Proper certificate validation for certificate-based EAP methods
    
- Accounting for auditing where required
    

For 802.1X/EAP environments, certificate validation and EAP-method security are particularly important.

## 36. RADIUS Exam Traps

### Trap 1 — UDP 1812/1813

```text
1812 → Authentication
1813 → Accounting
```

---

### Trap 2 — RADIUS client

The:

```text
Switch / AP / WLC / VPN Gateway
```

is normally the RADIUS client/NAS.

Not the user's laptop.

---

### Trap 3 — RADIUS vs TACACS+

Remember:

```text
RADIUS
→ network access

TACACS+
→ network-device administration
```

But neither protocol is absolutely restricted to only one use case.

---

### Trap 4 — Password-only encryption

For traditional RADIUS comparisons:

```text
RADIUS
→ password protection

TACACS+
→ TACACS+ packet body encryption
```

Do not turn this into an absolute statement about every modern RADIUS deployment.

---

### Trap 5 — RADIUS authorization

RADIUS is not simply:

> "Authentication only."

It can return extensive authorization/policy information through attributes and VSAs.

---

### Trap 6 — EAP

For 802.1X:

```text
Supplicant
    ↓
Authenticator
    ↓
RADIUS
    ↓
Authentication Server
```

EAP is used between the supplicant/authenticator and is transported between the NAS and RADIUS server using RADIUS EAP attributes.

---

### Trap 7 — Ping

```text
ping RADIUS-server
```

does not prove:

```text
UDP 1812
UDP 1813
```

are working.

---

### Trap 8 — Access-Reject

```text
Access-Reject
```

is not the same as:

```text
Server unreachable
```

This distinction matters for AAA method-list fallback.

---

### Trap 9 — Accounting

RADIUS accounting normally uses:

```text
UDP 1813
```

It is separate from authentication.

---

### Trap 10 — Shared secret

The RADIUS shared secret must match between:

```text
NAS ↔ RADIUS Server
```

## 43. Final Takeaway

For CCNP Enterprise, remember RADIUS as:

> **An open-standard, UDP-based AAA protocol widely used for centralized network-access authentication, authorization, and accounting, especially with 802.1X, enterprise wireless, VPN, and NAC environments.**

The highest-value exam facts are:

1. **RADIUS uses UDP.**
    
2. **UDP 1812 is the standard authentication port.**
    
3. **UDP 1813 is the standard accounting port.**
    
4. **The NAS is normally the RADIUS client.**
    
5. **The endpoint is normally the 802.1X supplicant.**
    
6. **The RADIUS server provides centralized authentication and policy.**
    
7. **RADIUS uses attributes and VSAs for authorization information.**
    
8. **Access-Request, Access-Accept, Access-Reject, and Access-Challenge are key packet types.**
    
9. **RADIUS accounting uses Accounting-Request/Response.**
    
10. **RADIUS is heavily associated with 802.1X, EAP, enterprise Wi-Fi, and VPN access.**
    
11. **The shared secret must match between the NAS and RADIUS server.**
    
12. **Traditional RADIUS protects the password field rather than encrypting the entire protocol body like TACACS+.**
    
13. **RADIUS can perform device authentication, but TACACS+ is commonly preferred for granular device administration and per-command authorization.**
    
14. **`group radius local` does not mean every RADIUS rejection automatically falls back to local authentication.**
    
15. **Ping success does not prove UDP 1812/1813 communication is working.**
